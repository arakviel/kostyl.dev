## Змінна: ім'я, тип і значення

**Змінна** (*variable*) — іменована ділянка пам'яті, в якій лежить значення одного наперед визначеного типу. C#, як і C++, — мова зі статичною типізацією (*static typing*): тип кожної змінної відомий під час компіляції і не змінюється, поки програма працює. Компілятор перевіряє кожне присвоєння і кожну операцію на відповідність типу ще до запуску.

Синтаксис оголошення такий самий, як у C++: спочатку тип, потім ім'я, потім необов'язковий ініціалізатор. Відмінності в правилах навколо нього, і вони — основний зміст лекції:

- прочитати змінну, якій ще нічого не присвоєно, не можна: це помилка компіляції, а не випадкове значення;
- змінна вкладеного блоку не може мати ім'я змінної із зовнішнього блоку;
- розміри типів однакові на всіх платформах: `long` — завжди 8 байтів.

![Анатомія оголошення: явний тип int age = 19, var title = "Звіт" з типом, який виводить компілятор, і const int MaxScore = 100 зі значенням, відомим під час компіляції](/images/csharp/fundamentals/variables-types-literals/01-declaration-anatomy.png){.diagram-img}

### Усі способи оголосити змінну

Одна програма, в якій зібрано всі форми оголошення локальної змінної:

```csharp [declare.cs]
int count;                 // лише оголошення: значення ще немає
count = 3;                 // перше присвоєння
int total = 10;            // оголошення з ініціалізацією
int width = 4, height = 3; // кілька змінних одного типу
var title = "Звіт";        // тип виводить компілятор: string
const int MaxScore = 100;  // константа: значення відоме під час компіляції
int empty = default;       // значення за замовчуванням для int: 0

Console.WriteLine($"{count} {total} {width}x{height} {title} {MaxScore} {empty}");
```

::terminal-preview{title="dotnet run declare.cs"}
```text
3 10 4x3 Звіт 100 0
```
::

::field-group

::field{name="int count;" type="оголошення"}
Змінна існує, але значення в неї немає. Читати її можна лише після першого присвоєння.
::

::field{name="int total = 10;" type="оголошення з ініціалізацією"}
Ініціалізація (*initialization*) — присвоєння значення в момент оголошення. Найчастіша форма.
::

::field{name="int width = 4, height = 3;" type="кілька змінних"}
Через кому оголошуються змінні одного типу. Ініціалізатор у кожної свій.
::

::field{name='var title = "Звіт";' type="виведення типу"}
Тип визначає компілятор за ініціалізатором. Без ініціалізатора `var` не працює.
::

::field{name="const int MaxScore = 100;" type="константа"}
Значення задається один раз, відоме під час компіляції і не змінюється.
::

::field{name="int empty = default;" type="значення за замовчуванням"}
`default` дає значення, в якому всі біти нульові: `0` для чисел, `false` для `bool`, `null` для посилальних типів.
::

::

::callout{icon="i-lucide-lightbulb"}
**Коли який спосіб**

- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **Ініціалізація при оголошенні** — за замовчуванням: змінна одразу має осмислене значення.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **Оголошення без значення** — коли значення залежить від розгалуження і присвоюється в кожній гілці (приклад у наступному розділі).
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **Кілька змінних в одному рядку** — лише для тісно пов'язаних значень на кшталт `width` і `height`.
- :icon{name="i-lucide-circle-x" class="inline-block text-red-500"} **Не оголошуйте всі змінні на початку методу**, як у старому C: оголошуйте поруч із першим використанням, тоді область видимості змінної мінімальна.

::

### Читання до присвоєння — помилка компіляції

У C++ локальна змінна без ініціалізатора містить те, що лишилося в пам'яті стеку, і її читання — невизначена поведінка (*undefined behavior*). C# такий код не компілює:

```csharp [errors/unassigned.cs]
int x;
Console.WriteLine(x);
```

::terminal-preview{title="dotnet build errors/unassigned.cs"}
```text
unassigned.cs(2,19): error CS0165: Use of unassigned local variable 'x'
```
::

Правило називається **definite assignment** («точно присвоєно»): у кожному місці, де змінну читають, вона має бути присвоєна на **кожному** шляху виконання від оголошення до цього місця. Компілятор перевіряє шляхи, а не значення. Якщо змінна присвоюється в обох гілках `if`, читати її після `if` можна:

```csharp [definite.cs]
int score = 75;
string grade;
if (score >= 60)
{
    grade = "зараховано";
}
else
{
    grade = "не зараховано";
}
Console.WriteLine(grade);
```

::terminal-preview{title="dotnet run definite.cs"}
```text
зараховано
```
::

Без гілки `else` той самий код не компілюється, хоча `score` дорівнює 75 і умова на практиці завжди істинна. Компілятор не обчислює значення змінних: для нього `score >= 60` може бути і `true`, і `false`, а на шляху «ні» змінній `grade` нічого не присвоєно.

::terminal-preview{title="dotnet build errors/one-branch.cs (той самий код без else)"}
```text
one-branch.cs(7,19): error CS0165: Use of unassigned local variable 'grade'
```
::

![Дві схеми if: зліва змінна grade присвоюється в обох гілках і програма компілюється, справа на гілці «ні» присвоєння немає і компілятор видає CS0165](/images/csharp/fundamentals/variables-types-literals/02-definite-assignment.png){.diagram-img}

У лекції про декомпілятори в IL кожного методу був рядок `.locals init`. Слово `init` наказує runtime обнулити всі локальні змінні на початку методу, тож випадкового «сміття», як у C++, у .NET не буває навіть технічно. Компілятор однаково вимагає присвоєння, бо нуль, який програміст не записував, — теж помилка логіки: правило ловить забуту гілку `else` чи пропущений `case` ще до запуску.

::note
Правило definite assignment стосується локальних змінних. Елементи масиву і поля класів отримують значення за замовчуванням автоматично: `new int[3]` — це три нулі. Масиви розглядає лекція 11, класи — модуль ООП.
::

### Як runtime обнуляє локальні змінні

Програма з двома змінними, зібрана в Debug, і її IL:

```csharp [var-il.cs]
var a = 10;
int b = 20;
Console.WriteLine(a + b);
```

::code-group

```text [IL: звичайна збірка]
.locals init (
	[0] int32,
	[1] int32
)
IL_0000: ldc.i4.s 10
IL_0002: stloc.0
IL_0003: ldc.i4.s 20
IL_0005: stloc.1
```

```text [IL: з атрибутом SkipLocalsInit]
.locals (
	[0] int32,
	[1] int32
)
IL_0000: ldc.i4.s 10
IL_0002: stloc.0
IL_0003: ldc.i4.s 20
IL_0005: stloc.1
```

::

Друга версія — файл `skip-init.cs`, у якому перед кодом стоять директива `#:property AllowUnsafeBlocks=true` і атрибут `[module: System.Runtime.CompilerServices.SkipLocalsInit]`. Атрибут прибирає з IL слово `init`, і JIT перестає обнуляти пам'ять під локальні змінні.

Навіщо це потрібно. Обнулення кількох змінних `int` нічого не коштує, але метод може виділити на стеку буфер на кілька кілобайтів (`stackalloc`, лекція 11), і тоді обнулення займає помітний час при кожному виклику. Атрибут застосовують у бібліотеках, де важить кожна наносекунда, зокрема в самому .NET. Звичайні змінні від цього не стають небезпечними: правило definite assignment однаково не дасть їх прочитати, а змінні з посиланнями на об'єкти JIT обнуляє завжди, бо збирачу сміття потрібно, щоб там був або `null`, або справжній об'єкт.

## var: тип виводить компілятор

Ключове слово `var` замість типу означає «візьми тип з ініціалізатора». Це аналог `auto` у C++. Який тип отримає змінна, залежить від форми літерала:

```csharp [var-types.cs]
var a = 42;
var b = 42L;
var c = 3_000_000_000;
var d = 4.5;
var e = 4.5f;
var f = 4.5m;
var g = 'Ї';
var h = "Ї";
var i = true;
// далі для кожної змінної друкується a.GetType() тощо
```

::terminal-preview{title="dotnet run var-types.cs"}
```text
var a = 42;            System.Int32
var b = 42L;           System.Int64
var c = 3_000_000_000; System.UInt32
var d = 4.5;           System.Double
var e = 4.5f;          System.Single
var f = 4.5m;          System.Decimal
var g = 'Ї';           System.Char
var h = "Ї";           System.String
var i = true;          System.Boolean
```
::

`GetType()` повертає тип значення, а виводиться він повним іменем .NET: `System.Int32` — це `int`. Число `3_000_000_000` отримало тип `uint`, а не `long`: воно не влазить в `int`, і компілятор узяв наступний тип за правилом, яке розбирає розділ про літерали. Дробове `4.5` без суфікса — завжди `double`.

### var — це не динамічна типізація

Тип змінної з `var` визначається один раз, під час компіляції. Далі вона поводиться так само, як змінна з явним типом:

```csharp [errors/var-string.cs]
var n = 10;
n = "text";
```

::terminal-preview{title="dotnet build errors/var-string.cs"}
```text
var-string.cs(2,5): error CS0029: Cannot implicitly convert type 'string' to 'int'
```
::

У IL між `var a = 10;` і `int b = 20;` різниці немає: обидві змінні — слоти `int32` у `.locals init`. `var` існує лише в коді C#.

### Обмеження var

Компілятору потрібен ініціалізатор, з якого видно тип. Звідси три помилки:

| Код | Помилка | Причина |
|---|---|---|
| `var x;` | CS0818: Implicitly-typed variables must be initialized | немає з чого вивести тип |
| `var x = null;` | CS0815: Cannot assign &lt;null&gt; to an implicitly-typed variable | `null` не має власного типу |
| `var a = 1, b = 2;` | CS0819: Implicitly-typed variables cannot have multiple declarators | `var` оголошує одну змінну |

Ще одне обмеження: `var` працює лише для локальних змінних. Поля класів і параметри методів завжди мають явний тип.

::callout{icon="i-lucide-lightbulb"}
**Коли var, а коли явний тип**

- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **var** — коли тип видно з правої частини: `var title = "Звіт";`, `var students = new List<string>();`, `var sw = Stopwatch.StartNew();`. Повторювати тип двічі немає сенсу.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **Явний тип** — коли тип не очевидний з виклику: `int count = GetCount();` читається без підказок IDE.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **Явний тип** — коли потрібен інший тип, ніж у літерала: `long big = 5;`, `double ratio = 1;`.
- :icon{name="i-lucide-circle-x" class="inline-block text-red-500"} **Не пишіть `var price = 19.99;` для грошей**: це `double`. Або `decimal price = 19.99m;`, або `var price = 19.99m;`.

::

У командах правило записують у `.editorconfig` (опції `csharp_style_var_for_built_in_types`, `csharp_style_var_when_type_is_apparent`, `csharp_style_var_elsewhere`), і IDE підсвічує порушення як IDE0007 («використайте var») чи IDE0008 («використайте явний тип»).

## const: значення, відоме під час компіляції

`const` оголошує константу: значення задається при оголошенні, обчислюється компілятором і не змінюється. Константу можна обчислити з інших констант:

```csharp [const-fold.cs]
const int SecondsPerMinute = 60;
const int MinutesPerHour = 60;
const int SecondsPerHour = SecondsPerMinute * MinutesPerHour;

int hours = 3;
Console.WriteLine(hours * SecondsPerHour);
```

::terminal-preview{title="dotnet run const-fold.cs"}
```text
10800
```
::

Змінних для констант у програмі немає зовсім. Компілятор підставив обчислене значення прямо в код:

::terminal-preview{title="ilspycmd -il (Release, метод <Main>$)"}
```text

IL_0006: mul
IL_0007: call void [System.Console]System.Console::WriteLine(int32)
IL_000c: ret
```

Інструкція `ldc.i4 3600` кладе на стек готове число: `60 * 60` обчислено під час компіляції. Звідси правила для `const`:

| Код | Помилка | Правило |
|---|---|---|
| `const int Max = Math.Max(1, 2);` | CS0133: The expression being assigned to 'Max' must be constant | праворуч — лише літерали, інші константи та операції над ними; виклик методу виконується лише під час роботи програми |
| `Max = 20;` | CS0131: The left-hand side of an assignment must be a variable, property or indexer | константа — не змінна, присвоїти їй нічого не можна |
| `const DateTime Start = new DateTime(2026, 9, 1);` | CS0283: The type 'DateTime' cannot be declared const | константами бувають лише вбудовані числові типи, `char`, `bool`, `string` і перелічення |

Рядкову константу можна зібрати інтерполяцією з інших рядкових констант (з C# 10): `const string Title = $"Курс {Course}";`, де `Course` — теж `const string`.

Константи іменують у PascalCase: `MaxScore`, `SecondsPerHour`. Стиль `MAX_SCORE` прийшов з макросів C і в .NET не використовується.

::note
Для полів класу є ще модифікатор `readonly`: значення задається один раз, але під час роботи програми, тож його можна обчислити викликом методу. Це тема класів.

## Імена змінних

### Правила мови

Ідентифікатор (*identifier*) — ім'я змінної, методу чи типу. Правила C#:

- складається з літер, цифр і `_`, починається з літери або `_`;
- літери — будь-якого алфавіту Unicode, тож `ціна` — допустиме ім'я;
- регістр має значення: `count` і `Count` — різні імена;
- ключове слово (`class`, `int`, `if`) не може бути ім'ям, якщо перед ним немає `@`.

| Ім'я | Результат | Чому |
|---|---|---|
| `userName` | компілюється | camelCase, рекомендований стиль |
| `_temp` | компілюється | `_` на початку дозволено |
| `ціна` | компілюється | кирилиця — літери Unicode; але за конвенцією імена англійські |
| `2nd` | CS1001: Identifier expected | починається з цифри |
| `user-name` | CS1003: Syntax error, '=' expected | `-` — оператор віднімання, компілятор бачить `user - name` |
| `class` | CS1001: Identifier expected | ключове слово |
| `@class` | компілюється | `@` дозволяє взяти ключове слово як ім'я |
| `var` | компілюється | контекстне ключове слово |

**Префікс `@`** (*verbatim identifier*) не входить до імені. У метаданих змінна чи метод називаються `class`:

```csharp [names.cs]
int @class = 11;
int вік = 19;
int _count = 2;

Console.WriteLine(@class + вік + _count);
Console.WriteLine(nameof(@class));
```

::terminal-preview{title="dotnet run names.cs"}
```text
32
class
```
::

Навіщо це потрібно. У лекції про платформу .NET було показано, що бібліотеку, написану однією мовою .NET, використовують з інших. Те, що в F# чи VB — звичайне ім'я, в C# може виявитися ключовим словом. `@` дає змогу звернутися до такого члена. Ще `@` трапляється в згенерованому коді, де ім'я береться з даних. У власному коді `@`-імен не створюють.

**Контекстні ключові слова** (`var`, `value`, `nameof`, `record`, `async`, `await`, `when`) мають особливе значення лише в певних конструкціях, тому як імена змінних їх компілятор приймає. Користуватися цим не варто: `int var = 5;` збиває з пантелику кожного, хто читає код.

### Конвенції .NET

Правила мови дозволяють багато чого, а конвенції визначають, як пишуть насправді. Їх дотримується вся бібліотека .NET (`Console.WriteLine`, `string.IsNullOrEmpty`, `int.MaxValue`), тож код, написаний за ними, читається так само, як BCL.

| Що | Стиль | Приклад |
|---|---|---|
| локальні змінні, параметри методів | camelCase | `totalScore`, `fileName` |
| константи | PascalCase | `MaxScore`, `DefaultTimeout` |
| методи, типи, властивості | PascalCase | `CalculateTotal`, `Student` |
| приватні поля класу | `_camelCase` | `_count`, `_logger` |
| інтерфейси | `I` + PascalCase | `IComparable`, `IDisposable` |
| змінні `bool` | питання «так чи ні» | `isValid`, `hasAccess`, `canRetry` |

Ще кілька правил з настанов Microsoft:

- **Абревіатури з двох літер** пишуться великими (`IO`, як у `System.IO`), довші — як слово: `Xml`, `Html`, `Json` (`XmlDocument`, `JsonSerializer`). `Id` — скорочення, а не абревіатура, тому `userId`, а не `userID`.
- **Без угорської нотації**: тип не дописують до імені (`iCount`, `strName`). IDE і так показує тип при наведенні курсору.
- **Без незрозумілих скорочень**: `customerAddress`, а не `custAddr`. Загальновідомі `id`, `url`, `max` — допустимі.

::callout{icon="i-lucide-lightbulb"}
**Добрі й погані імена**

- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`studentCount`, `averageGrade`, `isPaid`** — ім'я каже, що лежить у змінній.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`i`, `j` для лічильників циклів** — загальноприйнята домовленість, коротке ім'я тут доречне.
- :icon{name="i-lucide-circle-x" class="inline-block text-red-500"} **`a`, `temp`, `data2`, `x1`** — щоб зрозуміти, що в змінній, доводиться читати весь код навколо.
- :icon{name="i-lucide-circle-x" class="inline-block text-red-500"} **`MAX_SCORE`, `strName`** — звички з C і C++, у .NET так не пишуть.

::

Rider, Visual Studio і VS Code підсвічують порушення конвенцій, якщо правила іменування записано в `.editorconfig` (діагностика IDE1006).

## Область видимості

### Блок визначає, де існує змінна

**Область видимості** (*scope*) локальної змінної — блок `{ }`, в якому її оголошено. Змінну можна використати від місця оголошення до кінця блоку. Змінна з заголовка `for` належить циклу. Програма з циклом і окремим блоком:

```csharp [scopes.cs]
int total = 0;
for (int i = 1; i <= 2; i++)
{
    int square = i * i;
    total += square;
}
{
    int square = 100;
    Console.WriteLine(square);
}
Console.WriteLine(total);
```

::terminal-preview{title="dotnet run scopes.cs"}
```text
100
5
```
::

Дві змінні `square` — різні змінні з однаковим іменем. Це дозволено, бо їхні блоки стоять поруч, а не один в одному. Покрокове виконання тієї самої програми: які змінні існують після кожного рядка.

Звернення до змінної поза її блоком — помилка:

::code-group

```csharp [errors/for-scope.cs]

```

```csharp [errors/before-decl.cs]

```

Повідомлення різні. Для `i` компілятор пише, що такого імені тут немає взагалі. Для `y` — що змінну не можна використати **до оголошення**: ім'я `y` вже належить блоку, хоча оголошено нижче. В C# область видимості локальної змінної — **увесь** блок, а не частина від оголошення до кінця. Використати змінну можна лише після оголошення, але ім'я зайняте в усьому блоці. Наслідок цього видно в наступному розділі.

### Shadowing заборонено

**Shadowing** — оголошення у вкладеному блоці змінної з тим самим іменем, що й у зовнішньому. У C++ це дозволено: внутрішня змінна ховає зовнішню до кінця свого блоку.

```cpp [cpp/shadow.cpp]
#include <iostream>

int main() {
    int count = 10;
    {
        int count = 0;   // нова змінна з тим самим іменем
        count += 5;      // змінюється внутрішня
    }
    std::cout << count << "\n";
}
```

::terminal-preview{title="clang++ -Wall -Wextra shadow.cpp && ./a.out"}
```text
10
```
::

Програма компілюється і друкує `10`. Якщо автор хотів додати 5 до зовнішньої `count`, помилку доведеться шукати в дебагері: clang і GCC попереджають про shadowing лише з окремою опцією `-Wshadow`, якої немає навіть у `-Wall -Wextra`. У C# такий код не компілюється:

```csharp [errors/shadow.cs]
int x = 1;
{
    int x = 2;
}
```

::terminal-preview{title="dotnet build errors/shadow.cs"}
```text
shadow.cs(3,9): error CS0136: A local or parameter named 'x' cannot be declared in this scope because that name is used in an enclosing local scope to define a local or parameter
```
::

Те саме для змінної циклу: `int x = 1; for (int x = 0; x < 3; x++) { }` дає CS0136. І навіть порядок не рятує:

```csharp [errors/shadow-after.cs]
{
    int x = 1;
}
int x = 2;
Console.WriteLine(x);
```

::terminal-preview{title="dotnet build errors/shadow-after.cs"}
```text
shadow-after.cs(2,9): error CS0136: A local or parameter named 'x' cannot be declared in this scope because that name is used in an enclosing local scope to define a local or parameter
```
::

Зовнішня `x` оголошена після блоку, але її ім'я займає весь зовнішній блок, включно з вкладеним. Помилку компілятор показує на внутрішньому оголошенні.

**Чому так зроблено.** Дизайнери C# поставили правило: в межах блоку просте ім'я має означати одне й те саме. Читаючи будь-який рядок методу, не треба з'ясовувати, яку з кількох змінних `count` він змінює. Shadowing дає помилки, які компілятор C++ пропускає, а заборона нічого не коштує: внутрішній змінній достатньо дати інше ім'я.

::note
Виняток — локальні функції (лекція 14). З C# 8 змінна чи параметр усередині локальної функції може мати ім'я змінної з навколишнього методу: файл `errors/local-func-shadow-ok.cs` компілюється. Функція — окремий шматок коду зі своїми параметрами, і там такий збіг імен трапляється часто.
::

## Вбудовані типи

### Ключові слова — псевдоніми типів .NET

У першій лекції було показано, що `int` — псевдонім типу `System.Int32` з CTS, а `sizeof` повертає розмір значення в байтах. Усі вбудовані типи C# влаштовані так само: ключове слово мови відповідає структурі з namespace `System`.

![Лінійка вбудованих типів: кожен рядок — тип C#, його ім'я в .NET, клітинки за кількістю байтів (від 1 до 16) і діапазон значень](/images/csharp/fundamentals/variables-types-literals/04-type-ruler.png){.wide-img}

| C# | .NET | Байти | Значення за замовчуванням | Літерал |
|---|---|---|---|---|
| `bool` | `System.Boolean` | 1 | `false` | `true` |
| `sbyte` | `System.SByte` | 1 | `0` | `(sbyte)-5` або `sbyte s = -5;` |
| `byte` | `System.Byte` | 1 | `0` | `byte b = 255;` |
| `short` / `ushort` | `System.Int16` / `System.UInt16` | 2 | `0` | `short s = 1000;` |
| `char` | `System.Char` | 2 | `'\0'` | `'A'` |
| `int` / `uint` | `System.Int32` / `System.UInt32` | 4 | `0` | `42`, `42U` |
| `long` / `ulong` | `System.Int64` / `System.UInt64` | 8 | `0` | `42L`, `42UL` |
| `nint` / `nuint` | `System.IntPtr` / `System.UIntPtr` | 4 або 8 | `0` | `nint n = 42;` |
| `float` | `System.Single` | 4 | `0` | `4.5f` |
| `double` | `System.Double` | 8 | `0` | `4.5`, `4.5d` |
| `decimal` | `System.Decimal` | 16 | `0` | `4.5m` |
| `string` | `System.String` | посилання | `null` | `"текст"` |
| `object` | `System.Object` | посилання | `null` | — |

Головна відмінність від C++: **розміри зафіксовано специфікацією CTS**, а не платформою. У C++ стандарт гарантує лише мінімальні розміри, і `long` займає 4 байти в Windows і 8 байтів у 64-бітних Linux і macOS. У C# `long` — 8 байтів скрізь, `int` — 4. Від платформи залежать лише `nint` і `nuint`: вони мають розмір покажчика.

Усі типи таблиці, крім `string` і `object`, — **значущі** (*value types*): змінна містить саме значення. `string` і `object` — **посилальні** (*reference types*): змінна містить посилання на об'єкт у керованій купі. Різницю між ними розбирає наступна лекція.

Діапазони всіх цілих типів, отримані з `MinValue` і `MaxValue`:

```csharp [ranges.cs (фрагмент)]
Console.WriteLine($"nint    {nint.Size,5} {nint.MinValue,21} {nint.MaxValue,22}");
```

```csharp [errors/byte-sum.cs]
byte a = 1, b = 2;
```

Сума двох `byte` має тип `int`, бо `200 + 100` уже не влазить у байт. Компілятор не обрізає значення мовчки: результат треба або зберегти в `int`, або явно привести до `byte`:

```csharp [byte-sum.cs]
byte a = 200, b = 100;
int sum = a + b;               // byte + byte -> int
byte cut = (byte)(a + b);      // явне приведення: лишаються молодші 8 біт
Console.WriteLine(sum);
Console.WriteLine(cut);
```

```text

```
::

Короткі типи потрібні там, де значень мільйони або де формат даних задано ззовні: пікселі зображення (байт на канал кольору), бінарні файли, мережеві протоколи. Для окремої змінної економія кількох байтів нічого не дає, а приведення ускладнюють код, тому лічильники, індекси й кількості — `int`.

**Беззнакові типи** (`uint`, `ulong`, `ushort`, `sbyte`) не входять у CLS: їх підтримують не всі мови .NET. Тому публічні API бібліотеки .NET повертають `int` навіть там, де від'ємне значення неможливе: `string.Length`, `Array.Length`, `List<T>.Count` — усі `int`.

**`nint` і `nuint`** мають розмір покажчика: 8 байтів у 64-бітному процесі, 4 — у 32-бітному. Вони потрібні для роботи з нативним кодом (бібліотеки на C, виклики ОС) і в низькорівневих оптимізаціях.

**`Int128` і `UInt128`** (з .NET 7) — 16-байтні цілі. Ключових слів для них немає, ім'я типу пишеться повністю. Застосовуються для 128-бітних ідентифікаторів і хешів та обчислень, які виходять за межі `long`.

### Арифметика коротких типів в IL

Чому `byte + byte` дає `int`, видно в IL програми `byte-sum.cs`, зібраної в Debug:

::terminal-preview{title="ilspycmd -il (Debug, метод <Main>$, фрагмент)"}
```text

	[1] uint8,
	[2] int32,
	[3] uint8
)
IL_0009: ldloc.0
IL_000a: ldloc.1
IL_000b: add
IL_000c: stloc.2
IL_000d: ldloc.0
IL_000e: ldloc.1
IL_000f: add
IL_0010: conv.u1
IL_0011: stloc.3
```
::

Слоти змінних мають типи `uint8` (це `byte`) і `int32`, але стек обчислень IL працює лише з кількома типами: `int32`, `int64`, `native int`, числа з рухомою точкою і посилання. Інструкція `ldloc.0` читає байт і кладе на стек 32-бітне значення, `add` додає два `int32`. Щоб записати результат у слот `uint8`, потрібна інструкція `conv.u1`, яка відкидає старші біти. Це і є явне приведення `(byte)` з коду C#.

Мова повторює правило стекової машини: результат арифметики над короткими типами — `int`, бо таким він є на стеку. Звужувати його назад компілятор дозволяє лише явно, щоб відкидання бітів було видно в коді.

### Дробові числа: float, double, decimal

Три дробові типи відрізняються розміром, точністю і способом зберігання:

```csharp [real-types.cs]
Console.WriteLine($"float   {sizeof(float),2} Б  max {float.MaxValue}");
Console.WriteLine($"double  {sizeof(double),2} Б  max {double.MaxValue}");
Console.WriteLine($"decimal {sizeof(decimal),2} Б  max {decimal.MaxValue}");
Console.WriteLine();

float f = 16_777_217;
Console.WriteLine($"float f = 16_777_217  ->  {f}");

double d = 0.1 + 0.2;
Console.WriteLine($"double:  0.1 + 0.2 = {d}, дорівнює 0.3? {d == 0.3}");

decimal m = 0.1m + 0.2m;
Console.WriteLine($"decimal: 0.1 + 0.2 = {m}, дорівнює 0.3? {m == 0.3m}");
```

::terminal-preview{title="dotnet run real-types.cs"}
```text
float    4 Б  max 3.4028235E+38
double   8 Б  max 1.7976931348623157E+308
decimal 16 Б  max 79228162514264337593543950335

float f = 16_777_217  ->  16777216
double:  0.1 + 0.2 = 0.30000000000000004, дорівнює 0.3? False
decimal: 0.1 + 0.2 = 0.3, дорівнює 0.3? True
```
::

- **`float` і `double`** — двійкові числа з рухомою точкою (*floating-point*) за стандартом IEEE 754, ті самі, що в C++. `float` тримає 6–9 значущих цифр, тому ціле 16 777 217 (2²⁴ + 1) в нього вже не влазить і округлюється до сусіднього 16 777 216. `double` тримає 15–17 цифр.
- **Десяткові дроби у двійковому записі неточні.** `0.1` у двійковій системі — нескінченний дріб, як ⅓ у десятковій, тому `0.1 + 0.2` у `double` дає не рівно `0.3`.
- **`decimal`** зберігає число в десятковій системі: 96-бітне ціле і кількість знаків після коми. `0.1m` записано точно, і сума дорівнює `0.3m`. Точність — 28–29 цифр, але діапазон менший, ніж у `double`, а операції повільніші: процесор не має інструкцій для `decimal`, і вони виконуються програмно.

Будову IEEE 754, порівняння з допуском, `NaN` і нескінченності розбирає лекція 06.

::note
Виводи в лекції отримано на macOS з регіональними налаштуваннями en-NZ, тому дробова частина відокремлена крапкою. На комп'ютері з українськими налаштуваннями та сама програма надрукує кому: `0,30000000000000004`. Як це контролювати — теж у лекції 06.
::

::callout{icon="i-lucide-lightbulb"}
**Коли який дробовий тип**

- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`double`** — за замовчуванням для вимірювань і розрахунків: фізика, статистика, координати, відсотки.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`decimal`** — гроші та все, де результат має збігатися з розрахунком «на папері» до копійки.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`float`** — великі масиви чисел, де важить пам'ять: графіка, ігри, нейромережі.
- :icon{name="i-lucide-circle-x" class="inline-block text-red-500"} **Не рахуйте гроші в `double`**: копійки накопичують похибку, і сума рахунку розійдеться з сумою позицій.

### char і bool

`char` у C# — 16-бітний код символу UTF-16 (*code unit*), а не байт, як `char` у C++. Кирилиця, латиниця і більшість символів світових писемностей займають один `char`.

```csharp [chars.cs]
char letter = 'A';
Console.WriteLine(letter + 1);          // char + int -> int
Console.WriteLine((char)(letter + 1));  // назад у char

char yi = 'Ї';
Console.WriteLine((int)yi);
Console.WriteLine('\u0407');
Console.WriteLine(sizeof(char));

bool passed = true;
Console.WriteLine(passed);
Console.WriteLine(sizeof(bool));
```

::terminal-preview{title="dotnet run chars.cs"}
```text
66
B
1031
Ї
2
True
1
```
::

- `letter + 1` дає `int` 66: в арифметиці `char` перетворюється на свій код. Щоб отримати символ, результат приводять назад: `(char)(letter + 1)`.
- Код `Ї` — 1031, у шістнадцятковому записі `0407`, тому `'\u0407'` — та сама літера.
- Зворотного неявного перетворення немає: `char c = 65;` — помилка CS0266 «Cannot implicitly convert type 'int' to 'char'», так само `string s = 'a';` — CS0029. Символ і рядок — різні типи.
- Деякі символи (частина ієрогліфів, нотні знаки, емодзі) не влазять у 16 бітів і займають два `char`. Їх розбирає лекція про рядки.

`bool` має лише два значення, `true` і `false`, і займає 1 байт. На відміну від C++, число не перетворюється на `bool` ні неявно, ні в умові:

```csharp [errors/if-assign.cs]
int x = 5;
if (x = 5) { }
```

::terminal-preview{title="dotnet build errors/if-assign.cs"}
```text
if-assign.cs(2,5): error CS0029: Cannot implicitly convert type 'int' to 'bool'
```
::

Класична помилка C++ `if (x = 5)` замість `if (x == 5)` у C# не компілюється: присвоєння дає `int`, а умова вимагає `bool`. З тієї ж причини не компілюються `if (1)` і `bool b = 0;`.

### string, object і значення за замовчуванням

`string` (`System.String`) — текст у кодуванні UTF-16, послідовність `char`. Рядок у .NET незмінний (*immutable*): операції на кшталт `Replace` створюють новий рядок. `object` (`System.Object`) — базовий тип усіх типів .NET: у змінну `object` можна записати значення будь-якого типу. Обидва — посилальні типи, тож `sizeof` до них не застосовується: `sizeof(string)` дає помилку CS0233 «'string' does not have a predefined size». Детально їх розбирають лекції 05 (значущі й посилальні типи) і 12 (рядки).

Ще одне ключове слово, `dynamic`, вимикає перевірку типів під час компіляції і переносить її на час виконання. У цьому курсі воно не використовується.

**Значення за замовчуванням** (*default value*) кожного типу — значення, в якому всі біти нульові. Його дає вираз `default(T)` або літерал `default`, якщо тип відомий з контексту:

```csharp [defaults.cs]
Console.WriteLine(default(int));
Console.WriteLine(default(double));
Console.WriteLine(default(bool));
Console.WriteLine((int)default(char));

int counter = default;   // тип береться з лівої частини
string? text = default;
Console.WriteLine(counter);
Console.WriteLine(text == null);
```

::terminal-preview{title="dotnet run defaults.cs"}
```text
0
0
False
0
0
True
```
::

`default(char)` — символ з кодом 0, на екрані він невидимий, тому програма друкує його код. Для `string` значення за замовчуванням — `null`, «посилання в нікуди». Знак `?` у `string?` позначає, що змінна може містити `null`; це тема наступної лекції.

## Літерали

**Літерал** (*literal*) — значення, записане прямо в коді: `42`, `3.14`, `'A'`, `"текст"`, `true`, `null`. У кожного літерала є тип, і компілятор визначає його за формою запису.

### Цілі літерали

Ціле число можна записати в трьох системах числення і розбити на групи цифр:

```csharp [int-literals.cs (фрагмент)]
int dec = 255;
int hex = 0xFF;
int bin = 0b1111_1111;
int million = 1_000_000;
int notOctal = 010;
Console.WriteLine($"{dec} {hex} {bin} {million} {notOctal}");
```

::terminal-preview{title="dotnet run int-literals.cs (перший рядок)"}
```text
255 255 255 1000000 10
```
::

::field-group

::field{name="255" type="десятковий"}
Звичайний запис.
::

::field{name="0xFF" type="шістнадцятковий"}
Префікс `0x` або `0X`. Зручний для бітових масок, кольорів (`0xFF8800`), кодів символів.
::

::field{name="0b1111_1111" type="двійковий, з C# 7"}
Префікс `0b` або `0B`. Видно кожен біт: прапорці, маски.
::

::field{name="1_000_000" type="роздільник розрядів, з C# 7"}
`_` між цифрами компілятор ігнорує. Ставиться де завгодно між цифрами і одразу після `0x` чи `0b` (`0x_FF`), але не на початку чи в кінці числа.
::

::field{name="010" type="десяткове 10"}
Вісімкових літералів у C# немає. У C++ `010` — це 8, у C# — 10.
::

::

### Тип цілого літерала

Літерал без суфікса отримує перший тип зі списку `int`, `uint`, `long`, `ulong`, в який влазить значення:

![Ланцюжок вибору типу цілого літерала без суфікса: влізе в int — int, інакше uint, інакше long, інакше ulong, інакше помилка CS1021; суфікси U, L, UL звужують вибір](/images/csharp/fundamentals/variables-types-literals/05-literal-type.png){.diagram-img}

::terminal-preview{title="dotnet run int-literals.cs (продовження)"}
```text

4_294_967_296             System.Int64
```

| Суфікс | Тип | Приклад |
|---|---|---|
| немає | `int`, `uint`, `long`, `ulong` — перший, в який влазить | `42` |
| `U` або `u` | `uint`, `ulong` | `42U` |
| `L` або `l` | `long`, `ulong` | `42L` |
| `UL`, `LU` у будь-якому регістрі | `ulong` | `42UL` |

Суфікс `l` (мала літера) компілятор приймає з попередженням CS0078 «The 'l' suffix is easily confused with the digit '1' -- use 'L' for clarity»: у `5l` легко побачити `51`.

Правило пояснює дві типові помилки:

- `int big = 3_000_000_000;` — помилка CS0266 «Cannot implicitly convert type 'uint' to 'int'». Літерал має тип `uint`, бо в `int` не влазить. Потрібен `long big = 3_000_000_000;`.
- `var x = 18_446_744_073_709_551_616;` — помилка CS1021 «Integral constant is too large»: число більше за `ulong.MaxValue`. Для таких значень є `Int128`, `UInt128` і `System.Numerics.BigInteger`.

При цьому `byte b = 200;` компілюється, хоча `200` має тип `int`: константу, яка влазить у цільовий тип, компілятор звужує сам (міні-завдання «Чи влізе значення» вище).

### Дробові літерали

Дробовий літерал без суфікса — `double`. Суфікс змінює тип:

| Запис | Тип |
|---|---|
| `1.5`, `1.5d`, `1.5D` | `double` |
| `1.5f`, `1.5F` | `float` |
| `1.5m`, `1.5M` | `decimal` |
| `5e3`, `1.496e11`, `2.5E-3` | `double` в експоненційному записі: 5·10³, 1,496·10¹¹, 2,5·10⁻³ |

Неявно звузити `double` до `float` чи перетворити на `decimal` компілятор не дає навіть для літерала:

::terminal-preview{title="dotnet build float m = 1.5; і decimal m = 1.5;"}
```text
error CS0664: Literal of type double cannot be implicitly converted to type 'float'; use an 'F' suffix to create a literal of this type
error CS0664: Literal of type double cannot be implicitly converted to type 'decimal'; use an 'M' suffix to create a literal of this type
```
::

Компілятор прямо підказує суфікс. Для `float` причина — можлива втрата точності. Для `decimal` інша: `1.5` вже є двійковим числом `double`, і `decimal`, створений з нього, міг би успадкувати двійкову неточність, якої `decimal` якраз мав позбутися.

### Символьні літерали і escape-послідовності

Символьний літерал записується в одинарних лапках. Той самий символ можна задати чотирма способами:

::field-group

::field{name="'A'" type="сам символ"}
Найчитабельніший запис.
::

::field{name="'\u0041'" type="код Unicode, 4 шістнадцяткові цифри"}
Для символів, яких немає на клавіатурі або які невидимі.
::

::field{name="'\x41'" type="код, від 1 до 4 шістнадцяткових цифр"}
Те саме, але кількість цифр змінна. У рядках через це виникає пастка (нижче).
::

::field{name="(char)65" type="приведення числа"}
Не літерал, а перетворення `int` у `char`: зручно, коли код обчислюється.
::

::

**Escape-послідовність** (*escape sequence*) — `\` і один або кілька символів, які разом позначають символ, який неможливо або незручно записати напряму. Вони працюють у символьних і звичайних рядкових літералах:

| Послідовність | Символ |
|---|---|
| `\'` `\"` `\\` | апостроф, лапки, зворотна скісна риска |
| `\n` | новий рядок (LF) |
| `\r` | повернення каретки (CR); у Windows рядки в файлах закінчуються `\r\n` |
| `\t` | табуляція |
| `\0` | символ з кодом 0 |
| `\a` `\b` `\f` `\v` | сигнал, крок назад, нова сторінка, вертикальна табуляція — для старих терміналів і принтерів |
| `\e` | ESC (код 27), з C# 13; початок керівних послідовностей терміналу |
| `\uXXXX` | символ з кодом із 4 шістнадцяткових цифр |
| `\xH`…`\xHHHH` | символ з кодом з 1–4 шістнадцяткових цифр |
| `\UXXXXXXXX` | символ з кодом із 8 шістнадцяткових цифр, для символів за межами U+FFFF; лише в рядках |

```csharp [escapes.cs]
Console.WriteLine("Ім'я\tОцінка");
Console.WriteLine("Рядок 1\nРядок 2");
Console.WriteLine("Лапки: \"так\", апостроф: \'");
Console.WriteLine("Шлях: C:\\Users\\student");
Console.WriteLine("\u0406\u0422 = ІТ");
Console.WriteLine("\e[32mзелений\e[0m і звичайний");
```

::terminal-preview{title="dotnet run escapes.cs"}

<div class="line">Ім'я    Оцінка</div>
<div class="line">Рядок 1</div>
<div class="line">Рядок 2</div>
<div class="line">Лапки: "так", апостроф: '</div>
<div class="line">Шлях: C:\Users\student</div>
<div class="line">ІТ = ІТ</div>
<div class="line"><span class="text-green-400">зелений</span> і звичайний</div>
::

`\e[32m` — керівна послідовність ANSI: термінал не друкує її, а вмикає зелений колір, `\e[0m` скидає колір. Їх розуміють Windows Terminal і термінали macOS та Linux. Апостроф у рядку можна писати без `\`: екранувати його обов'язково лише в символьному літералі `'\''`.

::warning
`\x` бере від 1 до 4 шістнадцяткових цифр — скільки знайде. Якщо одразу після коду йдуть літери `A`–`F` чи цифри, вони теж стають частиною коду: `"\x41BC"` — це не `"ABC"`, а один символ U+41BC (китайський ієрогліф). Програма `escapes.cs` перевіряє це: довжина `"\x41BC"` — 1, а `"\x0041BC"` — 3 символи `ABC`. Використовуйте `\u` з рівно чотирма цифрами.
::

### Рядкові літерали

Рядок можна записати трьома видами літералів. Один і той самий шлях до файлу:

```csharp [strings.cs]
string path1 = "C:\\Users\\student\\notes.txt";
string path2 = @"C:\Users\student\notes.txt";
string path3 = """C:\Users\student\notes.txt""";
Console.WriteLine(path1);
Console.WriteLine(path1 == path2 && path2 == path3);

string quote = @"Він сказав: ""Привіт""";
Console.WriteLine(quote);

string json = """
    {
      "name": "Олена",
      "age": 19
    }
    """;
Console.WriteLine(json);

string name = "Олена";
int age = 19;
Console.WriteLine($"{name}: {age} років, через рік буде {age + 1}");
```

::terminal-preview{title="dotnet run strings.cs"}
```text
C:\Users\student\notes.txt
True
Він сказав: "Привіт"
{
  "name": "Олена",
  "age": 19
}
Олена: 19 років, через рік буде 20
```
::

::field-group

::field{name='"..."' type="звичайний рядок"}
Escape-послідовності працюють, `\` треба подвоювати, лапки — писати як `\"`. Лише в один рядок коду.
::

::field{name='@"..."' type="verbatim-рядок"}
`\` — звичайний символ, escape-послідовності не працюють. Лапки подвоюються: `""`. Може займати кілька рядків коду.
::

::field{name='"""..."""' type="raw-рядок, з C# 11"}
Нічого не екранується: ні `\`, ні лапки. Може займати кілька рядків, а спільний відступ прибирається. Якщо в тексті трапляються три лапки поспіль, літерал відкривають і закривають чотирма: `""""...""""`.
::

::field{name='$"..."' type="інтерполяція"}
Вирази у `{ }` обчислюються і вставляються в рядок. Поєднується з іншими видами: `$@"..."`, `$"""..."""`. Формат і вирівнювання (`{x,10:F2}`) розбирає лекція про консольне введення й виведення.
::

::

Багаторядковий raw-рядок має правила відступів: вміст починається з рядка після відкривальних `"""`, а позиція закривальних `"""` задає відступ, який компілятор прибирає з кожного рядка. Тому JSON у коді вирівняно разом з кодом, а у значенні рядка відступу немає:

![Raw-рядок з JSON: перші 4 пробіли кожного рядка позначені червоним — компілятор їх прибирає, бо закривальні лапки стоять після 4 пробілів; праворуч — значення рядка без відступу](/images/csharp/fundamentals/variables-types-literals/06-raw-string.png){.diagram-img}

::callout{icon="i-lucide-lightbulb"}
**Коли який рядковий літерал**

- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **Звичайний** — короткі рядки без `\` і лапок, а також рядки, де потрібні `\n`, `\t`, `\e`.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **Verbatim `@`** — шляхи Windows і регулярні вирази в коді, написаному до C# 11.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **Raw `"""`** — JSON, SQL, XML, багаторядковий текст і все, де багато лапок чи `\`.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **Інтерполяція `$`** — коли рядок складається зі значень змінних.
- :icon{name="i-lucide-circle-x" class="inline-block text-red-500"} **Не збирайте рядок з частин через `+`**, якщо можна інтерполяцією: `"Ім'я: " + name + ", вік: " + age` читається гірше за `$"Ім'я: {name}, вік: {age}"`.

::

### UTF-8 літерали і raw-рядки з фігурними дужками

Рядок `string` зберігається в UTF-16. Мережеві протоколи і файли найчастіше використовують UTF-8, і перетворення коштує часу. Суфікс `u8` (з C# 11) створює літерал одразу в байтах UTF-8: його тип — `ReadOnlySpan<byte>`, «вікно» на масив байтів, вбудований в assembly.

Друга проблема — інтерполяція тексту, в якому самі фігурні дужки є вмістом, як у JSON. Кількість знаків `$` перед raw-рядком задає, скільки дужок відкривають вираз: при `$$` вираз пишеться `{{name}}`, а одинарні `{` і `}` — звичайний текст.

```csharp [utf8-raw.cs]
string text = "Привіт";
ReadOnlySpan<byte> bytes = "Привіт"u8;
Console.WriteLine($"символів UTF-16: {text.Length}, байтів UTF-8: {bytes.Length}");

string name = "Олена";
string json = $$"""
    {
      "name": "{{name}}",
      "tags": {}
    }
    """;
Console.WriteLine(json);
```

::terminal-preview{title="dotnet run utf8-raw.cs"}
```text
символів UTF-16: 6, байтів UTF-8: 12
{
  "name": "Олена",
  "tags": {}
}
```
::

Кожна кирилична літера займає один `char` у UTF-16 і два байти в UTF-8. У `$$`-рядку не можна ставити поспіль стільки закривальних дужок, скільки знаків `$`: `{}}` у кінці однорядкового літерала дає помилку CS9007, бо `}}` компілятор вважає кінцем виразу. Тому JSON записано в кілька рядків.

### true, false, null, default

Решта літералів:

- `true` і `false` — два значення типу `bool`;
- `null` — «немає об'єкта», значення для посилальних типів: `string? name = null;`. Звертання до члена через `null` (`name.Length`) кидає виняток під час роботи, і компілятор попереджає про це (CS8602). Як працювати з `null` безпечно — наступна лекція;
- `default` — значення за замовчуванням для типу, який відомий з контексту (розділ про `default` вище).

## nameof

Оператор `nameof` повертає ім'я змінної, типу чи методу як рядок. Рядок обчислюється під час компіляції:

```csharp [nameof.cs]
int userAge = -5;
if (userAge < 0)
{
    Console.WriteLine($"Помилка: {nameof(userAge)} = {userAge}, очікується число >= 0");
}

Console.WriteLine(nameof(Console.WriteLine));
Console.WriteLine(nameof(System.Int32));
Console.WriteLine(nameof(userAge.ToString));
```

::terminal-preview{title="dotnet run nameof.cs"}
```text
Помилка: userAge = -5, очікується число >= 0
WriteLine
Int32
ToString
```
::

`nameof` повертає лише останню частину імені: `WriteLine`, а не `Console.WriteLine`. Виклику під час роботи програми немає. В IL на місці `nameof` стоять звичайні рядкові літерали:

::terminal-preview{title="ilspycmd -il (Release, фрагмент)"}
```text
IL_001f: ldstr "userAge"
...
IL_0055: ldstr "WriteLine"
IL_005f: ldstr "Int32"
IL_0069: ldstr "ToString"
```
::

Навіщо `nameof`, якщо можна написати `"userAge"` у лапках:

- **Перейменування.** Команда Rename в IDE змінює ім'я змінної в усіх місцях, де воно є іменем, і `nameof(userAge)` оновиться разом з ними. Рядок `"userAge"` IDE не чіпає: повідомлення почне брехати.
- **Перевірка компілятором.** Опечатка в рядку не помітна до запуску, а в `nameof` — помилка компіляції:

::terminal-preview{title="dotnet build errors/nameof-typo.cs"}
```text
nameof-typo.cs(2,26): error CS0103: The name 'userAgee' does not exist in the current context
```
::

`nameof` приймає ім'я, а не ключове слово: `nameof(int)` дає CS1525 «Invalid expression term 'int'», треба писати `nameof(Int32)`. З C# 14 `nameof` приймає і узагальнений тип без аргументів: `nameof(List<>)` повертає `"List"`.

Найчастіше `nameof` трапляється в повідомленнях про помилки і у винятках: `throw new ArgumentOutOfRangeException(nameof(age))`. Винятки — тема окремого модуля, але такий рядок ви побачите в коді бібліотек вже зараз.

::::accordion

:::accordion-item{label="Спробуйте: що поверне nameof" icon="i-lucide-clipboard-list"}

1. Не запускаючи програму, запишіть, що вона надрукує:

```csharp [nameof-task.cs]
int maxSpeed = 90;
Console.WriteLine(nameof(maxSpeed));
Console.WriteLine(nameof(Math.Max));
Console.WriteLine(nameof(System.Console));
Console.WriteLine(nameof(args));
Console.WriteLine(nameof(List<>));
```

## Питання для самоперевірки

::::accordion

:::accordion-item{label="Runtime обнуляє локальні змінні. Чому ж компілятор не дає прочитати змінну без присвоєння?" icon="i-lucide-help-circle"}

Нуль, який з'явився через обнулення, програміст не записував: читання такої змінної майже завжди означає забуту гілку `else`, пропущений `case` або логічну помилку. Правило definite assignment знаходить такі місця під час компіляції. Компілятор перевіряє всі шляхи виконання від оголошення до читання і не обчислює значень, тому шлях вважається можливим, навіть якщо на практиці він не трапляється.

:::

:::accordion-item{label="Чим var відрізняється від динамічної типізації?" icon="i-lucide-help-circle"}

`var` лише просить компілятор визначити тип з ініціалізатора. Тип визначається один раз, під час компіляції, і далі не змінюється: присвоїти рядок змінній, оголошеній як `var n = 10`, не можна (CS0029). В IL змінна з `var` має той самий тип, що й з явним оголошенням. Динамічна типізація, коли тип перевіряється під час роботи, в C# є лише через `dynamic`.

:::

:::accordion-item{label="Чому праворуч від const не можна викликати метод, але можна Math.PI?" icon="i-lucide-help-circle"}

Значення `const` обчислює компілятор і підставляє його в код як готове число. Виклик методу, наприклад `Math.Sqrt(2)`, виконується лише під час роботи програми, тому компілятор не знає результату (CS0133). `Math.PI` — сама константа (`const double` у класі `Math`), її значення відоме під час компіляції.

:::

:::accordion-item{label="Чому C# не дає оголосити x у вкладеному блоці, якщо x уже є в зовнішньому?" icon="i-lucide-help-circle"}

Область видимості локальної змінної — весь блок, в якому вона оголошена, включно з вкладеними блоками і навіть рядками до оголошення. Внутрішня `x` потрапила б в область видимості зовнішньої, і ім'я `x` у вкладеному блоці означало б іншу змінну, ніж у решті методу. C# вимагає, щоб у межах блоку ім'я означало одне й те саме, тому shadowing — помилка CS0136. У C++ такий код компілюється, і зміна «не тієї» змінної стає помилкою, яку шукають у дебагері.

:::

:::accordion-item{label="Чому byte c = a + b; для двох змінних byte не компілюється?" icon="i-lucide-help-circle"}

Арифметика над `byte`, `sbyte`, `short` і `ushort` виконується в `int`: сума має тип `int` і може не влізти в байт (`200 + 100 = 300`). Неявно звузити `int` до `byte` компілятор не дає, бо старші біти загубилися б непомітно (CS0266). Треба або зберегти результат в `int`, або написати явне приведення `(byte)(a + b)`.

:::

:::accordion-item{label="Який тип має літерал 3_000_000_000 і чому int big = 3_000_000_000; не компілюється?" icon="i-lucide-help-circle"}

Ціле без суфікса отримує перший тип зі списку `int`, `uint`, `long`, `ulong`, в який влазить. Три мільярди більші за `int.MaxValue` (2 147 483 647), але менші за `uint.MaxValue`, тому літерал має тип `uint`. Неявного перетворення `uint` в `int` немає, бо діапазони не збігаються (CS0266). Для такого значення потрібен `long`.

:::

:::accordion-item{label="Коли брати decimal, а коли double?" icon="i-lucide-help-circle"}

`decimal` зберігає число в десятковій системі, тому `0.1m + 0.2m` дорівнює `0.3m` точно. Це потрібно для грошей і всього, що має збігатися з розрахунком на папері. `double` зберігає число в двійковій системі: десяткові дроби в ньому неточні, зате діапазон більший, а операції виконує процесор, тому вони значно швидші. Для вимірювань і наукових розрахунків — `double`.

:::

:::accordion-item{label="Чим verbatim-рядок відрізняється від raw-рядка?" icon="i-lucide-help-circle"}

В обох `\` — звичайний символ і обидва можуть займати кілька рядків коду. У verbatim-рядку (`@"..."`) лапки треба подвоювати (`""`), а відступи коду потрапляють у значення рядка. У raw-рядку (`"""..."""`) лапки пишуться як є, а спільний відступ, заданий позицією закривальних `"""`, компілятор прибирає. Raw-рядки з'явилися в C# 11 і зручніші для JSON, SQL і будь-якого тексту з лапками.

:::

:::accordion-item{label="Навіщо nameof, якщо ім'я можна написати в лапках?" icon="i-lucide-help-circle"}

Рядок у лапках компілятор не перевіряє: опечатку не видно до запуску, а після перейменування змінної повідомлення лишається зі старим іменем. `nameof` перевіряється компілятором (опечатка дає CS0103) і оновлюється командою Rename в IDE. Під час роботи програми `nameof` нічого не коштує: в IL на його місці звичайний рядковий літерал.

:::

| Поняття / запис | Що це | Приклад або де побачити |

| `var` | тип виводить компілятор з ініціалізатора | `var title = "Звіт";` |
| `const` | значення, обчислене під час компіляції | `const int MaxScore = 100;`, в IL — `ldc.i4 100` |

5. Поясніть письмово: чому одне повідомлення змінилося, а інше — ні? Що станеться, якщо в IDE увімкнути перейменування й у рядках?

:::accordion-item{label="Розв'язок завдання 4" icon="i-lucide-check-circle"}

До перейменування обидва рядки однакові:

::terminal-preview{title="dotnet run rename.cs"}
```text
Помилка: studentCount має бути >= 0
Помилка: studentCount має бути >= 0
```
::

Після перейменування з налаштуваннями за замовчуванням:

::terminal-preview{title="dotnet run rename.cs (після Rename)"}
```text
Помилка: studentCount має бути >= 0
Помилка: groupSize має бути >= 0
```
::

- Rename змінює ім'я там, де воно є **ім'ям** у коді: в оголошенні, в умові, всередині `nameof`. Текст у лапках для компілятора — просто символи, зв'язку зі змінною в ньому немає, тому перше повідомлення стало неправдивим.
- Деякі IDE пропонують у вікні перейменування замінити ім'я ще й у рядках і коментарях (у Visual Studio — опція Include strings). З нею IDE замінить і текст у лапках, але це звичайний пошук тексту: він зачепить і рядки, де `studentCount` — просто слово, не пов'язане зі змінною. `nameof` розв'язує задачу точно, без пошуку.
