# Значущі та посилальні типи, null

::card-group

::card{title="Навчальні цілі" icon="i-lucide-graduation-cap"}

- Відрізняти значущі й посилальні типи і пояснювати, що копіюється при присвоєнні.
- Передбачати результат `==` для чисел, масивів, рядків і об'єктів.
- Пояснювати, що лежить у стеку, а що в керованій купі, і чому твердження «значущі типи живуть на стеку» неточне.
- Пояснювати boxing і вимірювати виділену пам'ять через `GC.GetAllocatedBytesForCurrentThread`.
- Пояснювати, чому `string` — посилальний тип, який поводиться як значення.
- Створювати анонімні типи, знати, що генерує для них компілятор і де їх не можна використати.
- Безпечно працювати з `null` через `?.`, `?[]`, `??` і `??=`.

## Дві категорії типів

У лекції 04 таблиця вбудованих типів закінчувалася двома рядками, `string` і `object`, у яких замість розміру стояло «посилання». Усі типи .NET діляться на дві категорії за тим, що зберігає змінна:

- **значущий тип** (*value type*) — змінна містить саме значення: число, символ, дату;
- **посилальний тип** (*reference type*) — змінна містить посилання на об'єкт, а сам об'єкт лежить в окремій ділянці пам'яті, **керованій купі** (*managed heap*).

Найближча аналогія з C++: значущий тип поводиться як звичайна змінна `int` чи структура, передана за значенням, а посилальний — як покажчик на об'єкт, створений через `new`. Відмінності від покажчика суттєві: арифметики над посиланнями немає, `delete` писати не треба (пам'ять звільняє збирач сміття), а посилання не може вказувати на вже звільнений об'єкт.

Перевірити, до якої категорії належить тип, можна властивістю `Type.IsValueType`:

```csharp [type-kinds.cs]
using System.Text;

Show("int", typeof(int));
Show("double", typeof(double));
Show("decimal", typeof(decimal));
Show("bool", typeof(bool));
Show("char", typeof(char));
Show("DateTime", typeof(DateTime));
Show("(int, int)", typeof((int, int)));
Show("string", typeof(string));
Show("object", typeof(object));
Show("int[]", typeof(int[]));
Show("StringBuilder", typeof(StringBuilder));
Show("List<int>", typeof(List<int>));

static void Show(string name, Type type) =>
    Console.WriteLine($"{name,-14} {(type.IsValueType ? "значущий" : "посилальний")}");
```

::terminal-preview{title="dotnet run type-kinds.cs"}
```text

double         значущий
decimal        значущий
bool           значущий
char           значущий
DateTime       значущий
(int, int)     значущий
string         посилальний
object         посилальний
int[]          посилальний
StringBuilder  посилальний
List<int>      посилальний
```
::

| Категорія | Які типи | Приклади з BCL |
|---|---|---|
| значущі | усі числові типи, `char`, `bool`, `decimal`, перелічення (`enum`), структури (`struct`), кортежі | `int`, `DateTime`, `TimeSpan`, `Guid`, `(int, int)` |
| посилальні | `string`, `object`, усі масиви (навіть `int[]`), класи, делегати, анонімні типи | `StringBuilder`, `List<T>`, `Random`, `Exception` |

Масив `int[]` — посилальний тип, хоча його елементи значущі: змінна містить посилання на масив, а масив разом з усіма числами лежить у купі. Власні структури й класи оголошують у модулі ООП, а тут вистачить типів з бібліотеки .NET. `StringBuilder` з namespace `System.Text` — змінюваний рядок, з яким працюють як з об'єктом: `Append` дописує текст у той самий об'єкт.

### Присвоєння: копія значення чи копія посилання

Присвоєння завжди копіює вміст змінної. Різниця в тому, що саме лежить у змінній:

```csharp [copy.cs]
using System.Text;

int a = 5;
int b = a;          // копія значення
b = 10;
Console.WriteLine($"a = {a}, b = {b}");

int[] x = [1, 2, 3];
int[] y = x;        // копія посилання: обидві змінні ведуть до одного масиву
y[0] = 99;
Console.WriteLine($"x[0] = {x[0]}, y[0] = {y[0]}");

StringBuilder first = new("Привіт");
StringBuilder second = first;
second.Append(", світе");
Console.WriteLine($"first = {first}, second = {second}");

y = [7, 8, 9];      // y тепер веде до нового масиву, x — до старого
Console.WriteLine($"x[0] = {x[0]}, y[0] = {y[0]}");
```

::terminal-preview{title="dotnet run copy.cs"}
```text
a = 5, b = 10
x[0] = 99, y[0] = 99
first = Привіт, світе, second = Привіт, світе
x[0] = 99, y[0] = 7
```
::

- `int b = a` копіює число 5. Далі `a` і `b` — дві незалежні комірки, і `b = 10` на `a` не впливає.
- `int[] y = x` копіює посилання. Масив один, змінних, які до нього ведуть, дві, тому зміну `y[0]` видно і через `x`.
- `StringBuilder` поводиться так само: `Append` змінює об'єкт, до якого ведуть обидві змінні.
- `y = [7, 8, 9]` змінює **змінну**, а не об'єкт: у `y` записується посилання на новий масив, а `x` і далі веде до старого. Ця різниця — «змінити об'єкт через посилання» проти «записати в змінну інше посилання» — головна в цій лекції.

Запис `[1, 2, 3]` — вираз колекції (*collection expression*, C# 12), який створює масив; масиви докладно розбирає лекція 11. `new("Привіт")` — скорочення від `new StringBuilder("Привіт")`: тип береться з лівої частини.

### Що порівнює ==

Для значущих типів `==` порівнює значення. Для посилальних — за замовчуванням посилання: чи ведуть обидві змінні до **того самого** об'єкта. Тип може змінити цю поведінку, як це зробив `string`:

```csharp [equality.cs]
using System.Text;

int a = 5, b = 5;
Console.WriteLine($"int            a == b                   {a == b}");

int[] x = [1, 2, 3];
int[] y = [1, 2, 3];
int[] z = x;
Console.WriteLine($"int[]          x == y                   {x == y}");
Console.WriteLine($"int[]          x == z                   {x == z}");
Console.WriteLine($"int[]          x.SequenceEqual(y)       {x.SequenceEqual(y)}");

var sb1 = new StringBuilder("Hi");
var sb2 = new StringBuilder("Hi");
Console.WriteLine($"StringBuilder  sb1 == sb2               {sb1 == sb2}");
Console.WriteLine($"StringBuilder  sb1.Equals(sb2)          {sb1.Equals(sb2)}");

string s1 = "Hi";
string s2 = "H";
s2 += "i";
Console.WriteLine($"string         s1 == s2                 {s1 == s2}");
Console.WriteLine($"string         ReferenceEquals(s1, s2)  {object.ReferenceEquals(s1, s2)}");
```

::terminal-preview{title="dotnet run equality.cs"}
```text
int            a == b                   True
int[]          x == y                   False
int[]          x == z                   True
int[]          x.SequenceEqual(y)       True
StringBuilder  sb1 == sb2               False
StringBuilder  sb1.Equals(sb2)          True
string         s1 == s2                 True
string         ReferenceEquals(s1, s2)  False
```
::

| Вираз | Що порівнює |
|---|---|
| `==` для значущих типів | значення |
| `==` для масивів і більшості класів | посилання: той самий об'єкт чи ні |
| `==` для `string` | вміст: `string` перевизначає оператор `==` |
| `a.Equals(b)` | те, що вирішив автор типу: `StringBuilder` і `string` порівнюють вміст, масив — посилання |
| `object.ReferenceEquals(a, b)` | завжди посилання |
| `x.SequenceEqual(y)` | елементи двох послідовностей по черзі (LINQ) |

Два масиви `x` і `y` з однаковими числами — різні об'єкти, тому `x == y` дає `False`. Рядки `s1` і `s2` — теж різні об'єкти (`ReferenceEquals` дає `False`), але `==` для `string` порівнює символи.

::callout{icon="i-lucide-lightbulb"}
**Як порівнювати**

- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **Числа, `char`, `bool`, рядки** — через `==`.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **Вміст двох масивів** — `SequenceEqual`, а не `==`.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **«Це той самий об'єкт?»** — `object.ReferenceEquals`: так видно намір, навіть якщо тип колись перевизначить `==`.
- :icon{name="i-lucide-circle-x" class="inline-block text-red-500"} **Не покладайтеся на `==` для типу, якого не знаєте**: для одних класів він порівнює вміст, для інших — посилання. Подивіться документацію або декомпілюйте тип.

## Стек і керована купа

Змінні методу і об'єкти програми живуть у двох різних ділянках пам'яті.

- **Стек** (*stack*). Кожен виклик методу отримує кадр (*stack frame*), у якому лежать його локальні змінні. Коли метод повертає керування, кадр звільняється одразу, разом з усіма змінними. Збирач сміття тут не потрібен.
- **Керована купа** (*managed heap*). Тут лежать об'єкти: масиви, рядки, екземпляри класів. Об'єкт існує, поки на нього є посилання; коли посилань не лишилося, пам'ять звільняє збирач сміття.

Часто кажуть: «значущі типи живуть на стеку, посилальні — у купі». Друга половина правильна, перша — ні. Точне правило таке: **значення значущого типу лежить там, де оголошена змінна чи поле, яке його містить**. Локальна змінна `int` — у кадрі методу. Елемент масиву `int[]` — у купі, всередині масиву. Поле об'єкта — у купі, всередині об'єкта. Для посилального типу там, де оголошена змінна, лежить лише посилання, а сам об'єкт — завжди в купі.

![Код з чотирма змінними: int a = 5 лежить у кадрі стеку; object boxed, int[] three і string text містять посилання на об'єкти в купі — boxing з копією 5 (24 Б), масив int[3] з довжиною і трьома нулями (40 Б) і рядок](/images/csharp/fundamentals/value-and-reference-types/02-stack-heap.png){.diagram-img}

Перевірити, що створює об'єкт у купі, можна вимірюванням: метод `GC.GetAllocatedBytesForCurrentThread()` повертає, скільки байтів поточний потік виділив у купі від початку роботи. Різниця до і після операції — розмір того, що вона виділила:

```csharp [allocations.cs (фрагмент)]
int a = 5;
long start;

start = GC.GetAllocatedBytesForCurrentThread();
int b = a;
long copyInt = GC.GetAllocatedBytesForCurrentThread() - start;

start = GC.GetAllocatedBytesForCurrentThread();
object boxed = a;
long boxing = GC.GetAllocatedBytesForCurrentThread() - start;
// так само для new int[3], new int[1000], копії посилання і склеювання рядків
```

::terminal-preview{title="dotnet run allocations.cs"}
```text
int b = a;                        0 Б
object boxed = a;                24 Б
new int[3]                       40 Б
new int[1000]                  4024 Б
int[] alias = thousand;           0 Б
text + "!" (7 символів)          40 Б
```
::

- Копія `int` і копія посилання не виділяють у купі нічого: змінюються лише комірки в кадрі методу.
- `new int[1000]` — це 4000 байтів чисел і ще 24 службових. Тисяча значень `int` лежить у купі, а не на стеку.
- `object boxed = a` виділяє 24 байти: значення 5 скопійовано в новий об'єкт у купі. Це **boxing**, наступний розділ.
- Склеювання рядків створює новий рядок у купі.

На 64-бітних Windows, Linux і macOS ці числа однакові: розміри задає runtime, а не ОС.

### Що займає місце в купі

Кожен об'єкт у купі починається зі службової частини з двох слів по 8 байтів (у 64-бітному процесі):

- **заголовок** (*object header*) — місце для блокування (`lock`), хеш-коду та службових прапорців runtime;
- **покажчик на тип** (*method table pointer*) — звідки runtime знає, що це за об'єкт: `Int32`, `Int32[]`, `String`. Саме тому `GetType()` працює для будь-якого об'єкта.

Далі йдуть дані, а загальний розмір вирівнюється до 8 байтів; найменший об'єкт займає 24 байти. Звідси виміряні числа:

| Об'єкт | Розрахунок | Виміряно |
|---|---|---|
| упакований `int` | 16 службових + 4 дані → вирівнювання | 24 Б |
| упакований `double` | 16 + 8 | 24 Б |
| упакований `decimal` | 16 + 16 | 32 Б |
| `new int[0]` | 16 + 8 (довжина з вирівнюванням) | 24 Б |
| `new int[3]` | 24 + 3 · 4 = 36 → вирівнювання | 40 Б |
| `new int[10]` | 24 + 10 · 4 | 64 Б |
| `new int[1000]` | 24 + 1000 · 4 | 4024 Б |
| рядок з 7 символів | 16 + 4 (довжина) + 7 · 2 + 2 (завершальний `\0`) = 36 → вирівнювання | 40 Б |

Масив і рядок зберігають довжину всередині себе, тому `Length` не обчислюється, а читається. Завершальний символ `\0` у рядку .NET потрібен для передачі рядка в нативний код без копіювання.

Об'єкти від 85 000 байтів runtime кладе в окрему ділянку, купу великих об'єктів (*Large Object Heap*), бо переміщувати їх під час збирання сміття дорого. Будову купи й поколінь розбирає модуль про керування пам'яттю.

### Boxing: значення в об'єкті

Змінна типу `object` може містити будь-яке значення, але `object` — посилальний тип: у змінній лежить посилання. Коли туди записують значення значущого типу, runtime створює в купі новий об'єкт і копіює в нього значення. Це **boxing** (упаковка). Зворотна операція, приведення `(int)boxed`, копіює значення з об'єкта назад — **unboxing**.

```csharp [boxing.cs]
int a = 5;
object boxed = a;      // boxing: копія a в купі
a = 10;
Console.WriteLine($"a = {a}, boxed = {boxed}");

int back = (int)boxed; // unboxing: копія значення з об'єкта
Console.WriteLine(back);

object o1 = 5;
object o2 = 5;
Console.WriteLine($"o1 == o2: {o1 == o2}");
Console.WriteLine($"o1.Equals(o2): {o1.Equals(o2)}");
```

::terminal-preview{title="dotnet run boxing.cs"}
```text
a = 10, boxed = 5
5
o1 == o2: False
o1.Equals(o2): True
```
::

- `boxed` зберігає копію, зроблену в момент boxing: зміна `a` її не зачіпає.
- Кожен boxing створює **новий** об'єкт. `o1` і `o2` — два різні об'єкти з однаковим числом, тому `==` (порівняння посилань для `object`) дає `False`, а `Equals`, який `Int32` перевизначає для порівняння значень, — `True`.
- Unboxing можливий лише в той самий тип, який упакували. Об'єкт з `int` всередині не розпаковується в `long`:

::terminal-preview{title="dotnet run unbox-wrong.cs"}
```text
5

```
::

Правильно — спочатку розпакувати в `int`, потім перетворити: `long ok = (int)boxed;`.

Кожен такий випадок — виділення пам'яті в купі і зайва робота для збирача сміття. Узагальнені колекції (`List<int>`) і узагальнені методи, які розглядає модуль про generics, створені насамперед для того, щоб boxing не був потрібен.

### Збирач сміття

Об'єкти в купі ніхто не видаляє вручну. **Збирач сміття** (*garbage collector*, GC) періодично з'ясовує, до яких об'єктів ще можна дістатися від «коренів» — локальних змінних методів, що виконуються зараз, і статичних полів, — і звільняє пам'ять решти. Нові об'єкти потрапляють у покоління 0, і більшість із них стає непотрібною дуже швидко, тому GC найчастіше перевіряє саме молоді об'єкти. Під час збирання об'єкти, що вижили, можуть переміщуватися в пам'яті, а всі посилання на них runtime оновлює сам. Через це в C# немає арифметики над посиланнями і немає «висячих» посилань на звільнену пам'ять. Ціна — паузи на збирання сміття, тому зайві виділення в купі (наприклад, boxing у циклі) впливають на швидкість. Детально GC розбирає модуль про керування пам'яттю.

## string: посилальний тип, що поводиться як значення

`string` — посилальний тип: рядок лежить у купі, змінна містить посилання. Але змінити рядок неможливо: жоден метод `string` не змінює наявний об'єкт. `ToUpper`, `Replace`, `Trim` повертають **новий** рядок, а `s += "!"` означає `s = s + "!"`: склеєний рядок — новий об'єкт, посилання на який записується в `s`.

```csharp [strings.cs]
string s1 = "Привіт";
string s2 = s1;
s2 += "!";
Console.WriteLine($"s1 = {s1}, s2 = {s2}");

string upper = s1.ToUpper();
Console.WriteLine($"s1 = {s1}, upper = {upper}");

string a = "Hi";
string b = "Hi";
string c = "H";
c += "i";
Console.WriteLine($"a == c                      {a == c}");
Console.WriteLine($"ReferenceEquals(a, b)       {object.ReferenceEquals(a, b)}");
Console.WriteLine($"ReferenceEquals(a, c)       {object.ReferenceEquals(a, c)}");
Console.WriteLine($"ReferenceEquals(a, Intern)  {object.ReferenceEquals(a, string.Intern(c))}");
```

::terminal-preview{title="dotnet run strings.cs"}
```text
s1 = Привіт, s2 = Привіт!
s1 = Привіт, upper = ПРИВІТ
a == c                      True
ReferenceEquals(a, b)       True
ReferenceEquals(a, c)       False
ReferenceEquals(a, Intern)  True
```
::

![До: s1 і s2 ведуть до одного рядка «Привіт». Після s2 += "!": s1 веде до старого рядка, s2 — до нового об'єкта «Привіт!»](/images/csharp/fundamentals/value-and-reference-types/03-string-immutable.png){.diagram-img}

- Після `s2 += "!"` змінна `s1` не змінилася, хоча до того обидві змінні вели до одного об'єкта. Порівняйте зі `StringBuilder` у `copy.cs`: там `Append` змінював спільний об'єкт.
- **Інтернування** (*interning*). Однакові рядкові літерали в програмі — один об'єкт: `a` і `b` ведуть до того самого `"Hi"`. Рядок, зібраний під час роботи (`c`), — окремий об'єкт з тим самим вмістом. `string.Intern(c)` повертає посилання на спільний екземпляр з таблиці інтернованих рядків.

**Чому рядок зроблено незмінним.** Незмінний об'єкт можна безпечно ділити між змінними: передали рядок у метод — і метод не зіпсує ваш текст. З тієї ж причини рядок безпечно читати з кількох потоків одночасно, використовувати як ключ словника (хеш-код не зміниться) і інтернувати. У результаті `string` поводиться як значення: присвоєння і передача «копіюють» текст, хоча насправді копіюється лише посилання. Ціна — нові об'єкти при кожній зміні: склеювання рядка в циклі на тисячі ітерацій створює тисячі проміжних рядків. Для цього є `StringBuilder`, і лекція про рядки вимірює різницю.

## Анонімні типи

Іноді кілька значень треба на хвилину зібрати в один об'єкт, не оголошуючи для цього класу. Для цього є **анонімні типи** (*anonymous types*): `new { ... }` без імені типу.

```csharp [anonymous.cs]
var student = new { Name = "Олена", Age = 19 };
Console.WriteLine(student);
Console.WriteLine(student.Name);

string city = "Львів";
int year = 2026;
var info = new { city, year };            // імена властивостей беруться з імен змінних
Console.WriteLine(info);

var older = student with { Age = 20 };    // нова копія зі зміненою властивістю
Console.WriteLine($"{student} -> {older}");

var same = new { Name = "Олена", Age = 19 };
Console.WriteLine($"Equals:   {student.Equals(same)}");
Console.WriteLine($"==:       {student == same}");
Console.WriteLine($"один тип: {student.GetType() == same.GetType()}");
Console.WriteLine($"ім'я типу: {student.GetType().Name}");
Console.WriteLine($"значущий: {student.GetType().IsValueType}");
```

::terminal-preview{title="dotnet run anonymous.cs"}
```text
{ Name = Олена, Age = 19 }
Олена
{ city = Львів, year = 2026 }
{ Name = Олена, Age = 19 } -> { Name = Олена, Age = 20 }
Equals:   True
==:       False
один тип: True
ім'я типу: <>f__AnonymousType0`2
значущий: False
```
::

- **Властивості** задаються як `Ім'я = значення`. Якщо значенням є змінна, ім'я можна не писати: `new { city, year }` створює властивості `city` і `year`.
- **Тип виводить компілятор**, тому змінна оголошується лише через `var`: імені, яке можна написати в коді, у типу немає.
- **`ToString`** друкує всі властивості, що зручно для налагодження.
- **Властивості лише для читання.** Змінити значення після створення не можна:

::terminal-preview{title="dotnet build errors/anon-readonly.cs"}
```text
anon-readonly.cs(2,1): error CS0200: Property or indexer '<anonymous type: string Name, int Age>.Age' cannot be assigned to -- it is read only
```
::

- **`with`** (з C# 10) створює новий об'єкт — копію зі зміненими властивостями. Оригінал лишається незмінним.
- **Рівність.** `Equals` порівнює всі властивості, а `==` — посилання, бо анонімний тип — клас, посилальний тип.
- **Один тип на одну форму.** Два анонімні об'єкти з однаковими іменами, типами і **порядком** властивостей в одній assembly мають один і той самий тип.

### Що генерує компілятор

Ім'я ``<>f__AnonymousType0`2`` підказує, що за анонімним типом стоїть звичайний клас, згенерований компілятором. Його видно в декомпіляторі. Опція `-lv CSharp1` з лекції 03 показує клас без синтаксичного цукру:

::terminal-preview{title="ilspycmd -lv CSharp1 anonymous.dll (фрагмент)"}
```text
[CompilerGenerated]
internal sealed class <>f__AnonymousType0<<Name>j__TPar, <Age>j__TPar>
{
	private readonly <Name>j__TPar <Name>i__Field;
	private readonly <Age>j__TPar <Age>i__Field;

	public <Name>j__TPar Name { get { return <Name>i__Field; } }
	public <Age>j__TPar Age { get { return <Age>i__Field; } }

	public <>f__AnonymousType0(<Name>j__TPar Name, <Age>j__TPar Age)
	{
		<Name>i__Field = Name;
		<Age>i__Field = Age;
	}

	public override bool Equals(object value)
	{
		<>f__AnonymousType0<<Name>j__TPar, <Age>j__TPar> anon = value as <>f__AnonymousType0<<Name>j__TPar, <Age>j__TPar>;
		if (this != anon)
		{
			if (anon != null && EqualityComparer<<Name>j__TPar>.Default.Equals(<Name>i__Field, anon.<Name>i__Field))
			{
				return EqualityComparer<<Age>j__TPar>.Default.Equals(<Age>i__Field, anon.<Age>i__Field);
			}
			return false;
		}
		return true;
	}

	public override int GetHashCode() { ... }

	public override string ToString()
	{
		...
		return string.Format(null, "{{ Name = {0}, Age = {1} }}", array);
	}

```
::

Атрибути `DebuggerBrowsable` і `DebuggerHidden` та тіла `GetHashCode` і `ToString` у фрагменті пропущено.

- Клас `sealed` (від нього не можна наслідуватися) і `internal` (видно лише в цій assembly).
- Поля `readonly` і властивості лише з `get` — звідси помилка CS0200.
- `Equals` порівнює поля по черзі, а `GetHashCode` обчислюється з усіх полів. Оператора `==` компілятор не генерує, тому `==` лишається порівнянням посилань.
- Типи властивостей — параметри узагальненого класу (`<Name>j__TPar`). Один згенерований клас обслуговує всі анонімні об'єкти з властивостями `Name` і `Age`, незалежно від їхніх типів.
- Імена з `<` і `>` недопустимі в C#, як і `<Main>$`: звернутися до цього класу з коду неможливо.

### Обмеження

Оскільки імені типу немає, його не можна написати як тип параметра чи результат методу. Анонімний об'єкт можна передати в метод лише як `object`, і тоді властивості `Name` і `Age` недоступні без рефлексії. Тому анонімні типи використовують у межах одного методу: зібрати кілька значень разом, вивести, порівняти. Головне їхнє застосування — запити LINQ, де `select new { ... }` вибирає з даних лише потрібні поля (модуль про колекції і LINQ). Коли значення треба повернути з методу, беруть кортеж `(string Name, int Age)` (лекція 15) або оголошують клас чи `record` (модуль ООП).

## null

### null і посилальні типи

`null` — значення посилальної змінної, яка не веде до жодного об'єкта. Це значення за замовчуванням для всіх посилальних типів. Звертання до члена через `null` компілюється, але під час роботи кидає виняток:

```csharp [null-ref.cs]
string? name = null;
Console.WriteLine("до звернення");
Console.WriteLine(name.Length);
Console.WriteLine("після звернення");
```

::terminal-preview{title="dotnet run null-ref.cs"}
```text
null-ref.cs(4,19): warning CS8602: Dereference of a possibly null reference.
до звернення
Unhandled exception. System.NullReferenceException: Object reference not set to an instance of an object.
   at Program.<Main>$(String[] args) in null-ref.cs:line 4
```
::

Значущий тип `null` містити не може: у змінній `int` завжди лежить число.

::terminal-preview{title="dotnet build errors/int-null.cs"}
```text
int-null.cs(1,9): error CS0037: Cannot convert null to 'int' because it is a non-nullable value type
```
::

Для значущих типів, яким потрібне «немає значення», є `int?` — скорочення від `Nullable<int>`, структури з числом і прапорцем «чи є значення». Її розбирає модуль 4; у цій лекції `int?` з'являється лише як результат оператора `?.`.

У лекції 02 розглядалося, як компілятор допомагає уникати `NullReferenceException`. У проєкті з `<Nullable>enable</Nullable>` (і у file-based програмах за замовчуванням) `string` означає «тут `null` бути не повинно», а `string?` — «тут може бути `null`». Компілятор відстежує кожну змінну і попереджає, а після перевірки на `null` попередження зникає:

```csharp [errors/nrt-warnings.cs]
string name = null;
string? maybe = Console.ReadLine();
Console.WriteLine(maybe.Length);
if (maybe != null)
{
    Console.WriteLine(maybe.Length);
}
```

::terminal-preview{title="dotnet build errors/nrt-warnings.cs"}
```text
nrt-warnings.cs(1,15): warning CS8600: Converting null literal or possible null value to non-nullable type.
nrt-warnings.cs(3,19): warning CS8602: Dereference of a possibly null reference.
```
::

Попередження для рядка 6 немає: всередині `if (maybe != null)` компілятор знає, що `maybe` не `null`. Це попередження, а не помилки: програма компілюється, і виняток станеться під час роботи. Опція `TreatWarningsAsErrors` з лекції 02 перетворює їх на помилки.

### Оператори ?. ?[] ?? ??=

Перевірки `if (x != null)` перед кожним зверненням роздувають код. Для типових випадків є чотири оператори:

::field-group

::field{name="x?.Member" type="null-conditional, умовний доступ"}
Якщо `x` — `null`, результат — `null` і `Member` не читається. Інакше — звичайне `x.Member`.
::

::field{name="x?[i]" type="умовний доступ за індексом"}
Те саме для індексу: якщо масив `null`, елемент не читається.
::

::field{name="a ?? b" type="null-coalescing"}
Якщо `a` не `null` — результат `a`, інакше `b`. `b` обчислюється лише тоді, коли воно потрібне.
::

::field{name="a ??= b" type="присвоєння, якщо null"}
Записує `b` в `a`, лише якщо `a` дорівнює `null`.
::

```csharp [null-ops.cs]
string? name = null;

int[]? scores = null;

Console.WriteLine($"[{name?.Length}]");
Console.WriteLine($"[{city?.Length}]");

int length = name?.Length ?? 0;
Console.WriteLine(length);

Console.WriteLine(scores?[0] ?? -1);

string display = name ?? "гість";
Console.WriteLine(display);

name ??= "Петро";
Console.WriteLine(name);

Console.WriteLine(city?.ToUpper().Length);
```

- `name?.Length` при `name == null` дає `null`, і інтерполяція друкує порожнє місце між дужками.
- `name?.Length ?? 0` — типова пара: `?.` обриває звернення, `??` підставляє запасне значення.
- `scores?[0] ?? -1` — те саме для масиву, якого немає.
- Перший `??=` записав `"Олена"`, бо `name` було `null`. Другий нічого не зробив: `name` уже не `null`.
- `city?.ToUpper().Length` — якщо `city` дорівнює `null`, обривається **весь** ланцюжок: не викликається ні `ToUpper`, ні `Length`. Писати `?.` перед кожною крапкою не потрібно.

Результат `?.` для значущої властивості може бути `null`, тому має тип `int?`, а не `int`. Записати його в `int` без `??` не вийде:

::callout{icon="i-lucide-lightbulb"}
**Коли який оператор**

- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`?.`** — коли `null` є нормальним станом: необов'язкове поле, порожнє введення, ще не створений об'єкт.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`??`** — значення за замовчуванням: `input ?? "гість"`, `name?.Length ?? 0`.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`??=`** — «створити, якщо ще не створено»: `cache ??= new StringBuilder();`.
- :icon{name="i-lucide-circle-x" class="inline-block text-red-500"} **Не ховайте помилку за `?.`**: якщо `null` тут бути не може, `?.` лише відкладе проблему — програма мовчки отримає `null` замість результату. Краще впасти одразу з `NullReferenceException` у місці, де помилка сталася.

::

### Умовне присвоєння в C# 14

До C# 14 оператори `?.` і `?[]` працювали лише для читання. З C# 14 через них можна й присвоювати: присвоєння виконується, лише якщо зліва не `null`.

```csharp [null-assign.cs]
using System.Text;

int[]? scores = null;
scores?[0] = 100;
Console.WriteLine(scores is null);

scores = new int[3];
scores?[0] = 100;
Console.WriteLine(scores?[0]);

StringBuilder? log = null;
log?.Length = 0;
log = new StringBuilder("старий запис");
log?.Length = 0;
Console.WriteLine($"[{log}]");
```

```text
[]
```

`scores?[0] = 100` для `null` не робить нічого і не кидає виняток. Раніше те саме писали як `if (scores != null) scores[0] = 100;`. Права частина присвоєння теж не обчислюється, якщо зліва `null`: у прикладі `assign-rhs.cs` метод `Next()` у `scores?[0] = Next()` викликається лише тоді, коли масив існує, і програма друкує «Next() викликано» один раз, а не два. `StringBuilder.Length` — властивість, яку можна записувати: `log?.Length = 0` очищує текст, якщо `log` існує.

### Як влаштовані nullable reference types

`string` і `string?` — той самий тип .NET `System.String`. Знак `?` існує лише для компілятора: під час роботи програми різниці немає, і `typeof(string?)` не компілюється (CS8639 «The typeof operator cannot be used on a nullable reference type»). У assembly позначка зберігається атрибутом. IL локальної функції `static string Describe(string? name)` з `nrt-flow.cs`:

::terminal-preview{title="ilspycmd -il nrt-flow.dll (фрагмент)"}
```text
string '<<Main>$>g__Describe|0_0' (
	string name
) cil managed
{
	.custom instance void [System.Runtime]System.Runtime.CompilerServices.NullableContextAttribute::.ctor(uint8) = (
		01 00 01 00 00
	)
	.param [1]
		.custom instance void [System.Runtime]System.Runtime.CompilerServices.NullableAttribute::.ctor(uint8) = (
			01 00 02 00 00
		)
```
::

Параметр у сигнатурі — звичайний `string`. Атрибут `NullableContext(1)` каже «у цьому методі типи за замовчуванням не допускають null», а `Nullable(2)` на параметрі 1 — «цей параметр може бути null». Компілятор іншої програми, яка викликає метод, читає ці атрибути і видає попередження.

Ще три інструменти аналізу:

- **Оператор `!`** (*null-forgiving*) вимикає попередження: `string sure = maybe!;` означає «я знаю, що тут не `null`». Перевірки під час роботи він не додає: у `nrt-flow.cs` змінна `sure` після `maybe!` однаково дорівнює `null`, і програма друкує `True`. Застосовується там, де компілятор не може довести те, що відомо програмісту.
- **Атрибути на методах бібліотеки.** У лекції 03 декомпільований `string.IsNullOrWhiteSpace` мав параметр `[NotNullWhen(false)] string? value`. Атрибут каже: «якщо метод повернув `false`, аргумент не `null`». Тому після `if (!string.IsNullOrWhiteSpace(input))` звертання `input.Trim()` не дає попередження, хоча явної перевірки `input != null` немає.
- **Директиви `#nullable enable` і `#nullable disable`** вмикають і вимикають аналіз для частини файлу — це потрібно під час поступового переведення старого коду на nullable reference types.

## Питання для самоперевірки

::::accordion

:::accordion-item{label="Що саме копіюється при присвоєнні int[] y = x і чому зміна y[0] видна через x?" icon="i-lucide-help-circle"}

Масив — посилальний тип: у змінній `x` лежить посилання на об'єкт у купі. Присвоєння копіює вміст змінної, тобто посилання. Після нього `x` і `y` ведуть до одного масиву, тому зміну його елемента видно через обидві змінні. Якщо ж записати в `y` інший масив (`y = [7, 8, 9]`), змінюється лише змінна `y`, а `x` веде до старого масиву.

:::

:::accordion-item{label="Чому твердження «значущі типи живуть на стеку» неточне?" icon="i-lucide-help-circle"}

Значення значущого типу лежить там, де оголошена змінна чи поле, яке його містить. Локальна змінна `int` — у кадрі методу на стеку. Але елементи масиву `int[]` лежать у купі всередині масиву, поле об'єкта — у купі всередині об'єкта, а упакований `int` — окремий об'єкт у купі. Вимірювання показує це: `new int[1000]` виділяє в купі 4024 байти.

:::

:::accordion-item{label="Чому два однакові масиви не рівні через ==, а два однакові рядки — рівні?" icon="i-lucide-help-circle"}

Для посилальних типів `==` за замовчуванням порівнює посилання: чи це той самий об'єкт. Масиви цю поведінку не змінюють, тому два масиви з однаковими числами — різні об'єкти і `==` дає `False`; для вмісту є `SequenceEqual`. `string` перевизначає оператор `==` так, щоб він порівнював символи, тому два різні об'єкти з однаковим текстом рівні.

:::

:::accordion-item{label="Що таке boxing і чому object o1 = 5, o2 = 5 дає o1 == o2 рівне False?" icon="i-lucide-help-circle"}

Boxing — копіювання значення значущого типу в новий об'єкт у купі, коли його записують у змінну типу `object`. Кожен boxing створює окремий об'єкт. `o1` і `o2` — два різні об'єкти, а `==` для `object` порівнює посилання. `o1.Equals(o2)` дає `True`, бо `Int32` перевизначає `Equals` для порівняння значень.

:::

:::accordion-item{label="Хто і коли звільняє пам'ять об'єкта в купі?" icon="i-lucide-help-circle"}

Збирач сміття. Він знаходить об'єкти, до яких можна дістатися від коренів (локальних змінних методів, що виконуються, і статичних полів), і звільняє пам'ять решти. Програміст нічого не видаляє вручну. Кадр методу на стеку звільняється інакше: одразу, коли метод повертає керування.

:::

:::accordion-item{label="Чому після s2 += текст змінна s1, що вела до того самого рядка, не змінилася?" icon="i-lucide-help-circle"}

Рядок незмінний: `s2 += "!"` — це `s2 = s2 + "!"`, і склеєний рядок — новий об'єкт. Змінюється лише вміст змінної `s2`: тепер у ній посилання на новий рядок. Старий рядок, до якого веде `s1`, лишився таким самим.

:::

:::accordion-item{label="Чому анонімний тип не можна повернути з методу?" icon="i-lucide-help-circle"}

Тип має ім'я, згенероване компілятором (``<>f__AnonymousType0`2``), яке недопустиме в C#, тому написати його як тип результату чи параметра неможливо. Повернути об'єкт можна лише як `object`, і тоді властивості недоступні. Для повернення кількох значень використовують кортежі або оголошують клас чи `record`.

:::

:::accordion-item{label="Який тип має вираз name?.Length, якщо name типу string?" icon="i-lucide-help-circle"}

`int?`. Якщо `name` дорівнює `null`, `?.` не читає `Length` і повертає `null`, а звичайний `int` містити `null` не може. Тому результат записують або в `int?`, або доповнюють запасним значенням: `int length = name?.Length ?? 0;`.

:::

:::accordion-item{label="Чим відрізняються ?? і ??=?" icon="i-lucide-help-circle"}

`a ?? b` — вираз: дає `a`, якщо воно не `null`, інакше `b`. Змінна `a` не змінюється. `a ??= b` — присвоєння: записує `b` в `a`, лише якщо `a` дорівнює `null`. Повторний `??=` для вже не-null змінної нічого не робить.

:::

:::accordion-item{label="Розв'язок завдання 4" icon="i-lucide-check-circle"}

```csharp [safe-input.cs]
Console.Write("Ім'я: ");
string? name = Console.ReadLine()?.Trim();

Console.Write("Місто: ");
string? city = Console.ReadLine()?.Trim();

if (string.IsNullOrEmpty(name))
{
    name = null;
}
name ??= "гість";
city ??= "невідоме місто";

Console.WriteLine($"Літер в імені: {name.Length}, у місті: {city?.Length ?? 0}");
```

::terminal-preview{title="три запуски, лише рядки результату: «Олена» і «Львів», порожнє ім'я і «Одеса», кінець введення"}

```text
гість, невідоме місто
Літер в імені: 5, у місті: 14
```
::

`Console.ReadLine()?.Trim()` не викликає `Trim` для `null`. Порожній рядок не `null`, тому його окремо перетворено на `null`, а `??=` замінює обидва випадки на `гість`. Без `?` у типі імені:

::terminal-preview{title="dotnet build safe-input.cs (string name без ?)"}
```text
safe-input.cs(3,15): warning CS8600: Converting null literal or possible null value to non-nullable type.
safe-input.cs(10,12): warning CS8600: Converting null literal or possible null value to non-nullable type.
```
::

- Рядок 3: `Console.ReadLine()?.Trim()` може повернути `null`, а змінна оголошена як «без null».
- Рядок 10: явне присвоєння `null` змінній, яка `null` не допускає.

Тип `string?` чесно описує, що в змінній буває `null`, а `??=` гарантує, що після нього `null` уже немає, — тому `name.Length` в останньому рядку попередження не дає.
