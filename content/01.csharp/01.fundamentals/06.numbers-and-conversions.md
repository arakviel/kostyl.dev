## Як записано ціле число

### Доповняльний код

Цілі числа зі знаком у C# записуються в **доповняльному коді** (*two's complement*), як і в C++ (там його зробив обов'язковим стандарт C++20, а на практиці його використовують усі сучасні процесори). У C# це закріплено специфікацією мови, тож поведінка однакова на будь-якому процесорі.

Правило доповняльного коду: старший біт має **від'ємну** вагу. У `sbyte` біти мають ваги −128, 64, 32, 16, 8, 4, 2, 1. Ті самі 8 бітів у `byte` мають ваги 128, 64, …, 1. Тому один і той самий набір бітів означає різні числа залежно від типу:

```csharp [twos.cs]
sbyte[] values = [0, 1, 127, -1, -2, -128];
foreach (sbyte v in values)
{
    Console.WriteLine($"{v,5}  {v:B8}  ті самі біти як byte: {(byte)v,3}");
}
Console.WriteLine();
Console.WriteLine($"int -1:           {-1:B32}");
Console.WriteLine($"int.MinValue:     {int.MinValue:B32}");
Console.WriteLine($"int.MaxValue:     {int.MaxValue:B32}");
```

::terminal-preview{title="dotnet run twos.cs"}
```text
    0  00000000  ті самі біти як byte:   0
    1  00000001  ті самі біти як byte:   1
  127  01111111  ті самі біти як byte: 127
   -1  11111111  ті самі біти як byte: 255
   -2  11111110  ті самі біти як byte: 254
 -128  10000000  ті самі біти як byte: 128

int -1:           11111111111111111111111111111111
int.MinValue:     10000000000000000000000000000000
int.MaxValue:     01111111111111111111111111111111
```
::

Формат `B8` (з .NET 8) друкує число у двійковому записі з 8 цифрами, `B32` — з 32. `(byte)v` перетворює `sbyte` на `byte`, зберігаючи біти.

![Шість наборів по 8 бітів і їхні значення як byte і як sbyte: 0000_0000 — 0 і 0, 0111_1111 — 127 і 127, 1000_0000 — 128 і −128, 1111_1111 — 255 і −1; старший біт — знаковий](/images/csharp/fundamentals/numbers-and-conversions/01-twos-complement.png){.diagram-img}

- **Від'ємне число** отримують з додатного так: інвертувати всі біти і додати 1. `1` = `0000_0001` → `1111_1110` → `1111_1111` = −1.
- **Діапазон несиметричний.** Від'ємних значень на одне більше: `sbyte` — від −128 до 127, `int` — від −2 147 483 648 до 2 147 483 647. Для найменшого числа немає додатної пари, тому `-int.MinValue` дорівнює `int.MinValue`, а `Math.Abs(int.MinValue)` кидає виняток, як показав декомпілятор у лекції 03.
- **Додавання і віднімання** процесор виконує однаково для знакових і беззнакових чисел: різниця лише в тому, як прочитати результат.

### Переповнення

Що станеться, якщо до `int.MaxValue` додати 1? Результат не влазить у 32 біти, і за замовчуванням C# залишає молодші 32 біти без жодної помилки:

```csharp [overflow.cs]
int max = int.MaxValue;
int next = max + 1;
Console.WriteLine($"{max} + 1 = {next}");
Console.WriteLine($"{max:B32}");
Console.WriteLine($"{next:B32}");

byte b = 255;
b++;
Console.WriteLine($"byte 255 + 1 = {b}");

long big = long.MaxValue;
big++;
Console.WriteLine($"long.MaxValue + 1 = {big}");

int min = int.MinValue;
Console.WriteLine($"-int.MinValue = {-min}");

int a = 2_000_000_000, c = 2_000_000_000;
long total = a + c;          // додавання в int, переповнення ще до запису в long
long right = (long)a + c;    // додавання в long
Console.WriteLine($"long total = a + c: {total}; (long)a + c: {right}");
```

::terminal-preview{title="dotnet run overflow.cs"}
```text
2147483647 + 1 = -2147483648
01111111111111111111111111111111
10000000000000000000000000000000
byte 255 + 1 = 0
long.MaxValue + 1 = -9223372036854775808
-int.MinValue = -2147483648
long total = a + c: -294967296; (long)a + c: 4000000000
```
::

Перенос з молодших бітів дійшов до знакового, і найбільше додатне число стало найменшим від'ємним. Значення рухаються по колу: після максимуму йде мінімум. Для беззнакового `byte` межа інша: після 255 іде 0.

![Коло 8-бітних значень: усередині — значення як sbyte (0, 32, 64, 96, 127, −128, −96, −64, −32, −1), ззовні — ті самі біти як byte (0…255); переповнення sbyte відбувається внизу (127 + 1 = −128), byte — вгорі (255 + 1 = 0)](/images/csharp/fundamentals/numbers-and-conversions/02-overflow-wheel.png){.diagram-img}

Лічильник `sbyte` крок за кроком проходить через межу:

Останній рядок `overflow.cs` показує найпідступніший випадок. `long total = a + c` виглядає безпечно, бо результат записується в `long`. Але тип виразу `a + c` визначають операнди, а не змінна зліва: обидва `int`, тому додавання виконується в `int` і переповнюється, а в `long` записується вже неправильне число. Правильно — перетворити один з операндів до додавання: `(long)a + c`.

::note
У C++ переповнення знакового цілого — невизначена поведінка: компілятор має право вважати, що воно ніколи не стається, і оптимізувати код з цього припущення. У C# поведінка визначена: без перевірки результат обертається по колу, з перевіркою — кидається виняток.
::

::::accordion

:::accordion-item{label="Спробуйте: що надрукує програма" icon="i-lucide-clipboard-list"}

2. Запустіть і перевірте. Для останнього рядка поясніть, чому зміна знака не змінила число.

:::

- `byte` після 255 повертається до 0.
- `short.MaxValue` = 32 767; наступне значення по колу — найменше, −32 768.
- Віднімання від мінімуму переходить на максимум: коло працює в обидва боки.
- `-s` для −128 дає `int` 128 (арифметика над `sbyte` — у `int`, лекція 04). Приведення `(sbyte)` залишає молодші 8 бітів `1000_0000`, тобто знову −128. Додатної пари для найменшого числа немає.

## checked і unchecked

Тихе переповнення небезпечне в розрахунках: сума замовлення, кількість на складі, лічильник — неправильне число йде далі, і помилку видно лише за наслідками. Ключове слово **`checked`** вмикає перевірку: при переповненні кидається виняток `OverflowException`, і програма зупиняється в місці помилки.

```csharp [checked.cs]
int max = int.MaxValue;

int wrapped = unchecked(max + 1);
Console.WriteLine($"unchecked(max + 1) = {wrapped}");

long total;
checked
{
    int a = 2_000_000_000, c = 2_000_000_000;
    Console.WriteLine("рахуємо a + c у блоці checked...");
    total = a + c;
}
Console.WriteLine(total);
```

::terminal-preview{title="dotnet run checked.cs"}
```text
unchecked(max + 1) = -2147483648
рахуємо a + c у блоці checked...
Unhandled exception. System.OverflowException: Arithmetic operation resulted in an overflow.
   at Program.<Main>$(String[] args) in checked.cs:line 12
```
::

::field-group

::field{name="checked(вираз)" type="вираз"}
Перевірка діє лише всередині дужок.
::

::field{name="checked { … }" type="блок"}
Перевірка діє для всіх операторів блоку.
::

::field{name="unchecked(вираз), unchecked { … }" type="вимкнути"}
Явно дозволяє переповнення, навіть якщо перевірку ввімкнено для всієї програми.
::

::field{name="<CheckForOverflowUnderflow>true</CheckForOverflowUnderflow>" type="уся програма"}
Властивість у `.csproj` або `#:property CheckForOverflowUnderflow=true` у file-based програмі: перевірка за замовчуванням для всього коду.
::

::

Перевірку для всієї програми можна точково вимкнути:

```csharp [checked-project.cs]
#:property CheckForOverflowUnderflow=true
int max = int.MaxValue;
Console.WriteLine($"unchecked(max + 1) = {unchecked(max + 1)}");
Console.WriteLine("max + 1 без unchecked...");
Console.WriteLine(max + 1);
```

::terminal-preview{title="dotnet run checked-project.cs"}
```text
unchecked(max + 1) = -2147483648
max + 1 без unchecked...
Unhandled exception. System.OverflowException: Arithmetic operation resulted in an overflow.
```
::

### Що саме перевіряє checked

- **Перевіряє:** цілочисельні `+`, `-`, `*`, `/`, `++`, `--`, унарний `-` і явні перетворення між цілими типами та з дробових типів у цілі.
- **Не стосується `double` і `float`**: їхнє переповнення дає нескінченність, а не виняток, навіть у `checked`.
- **Не потрібен `decimal`**: він перевіряє переповнення завжди, навіть в `unchecked`.
- **Діє лише на код усередині.** Методи, які викликаються з блоку `checked`, працюють у своєму власному контексті.

```csharp [floating-overflow.cs]
double d = double.MaxValue;
double dd = checked(d * 2);
Console.WriteLine($"checked(double.MaxValue * 2) = {dd}");

decimal m = decimal.MaxValue;
Console.WriteLine("unchecked(decimal.MaxValue + 1)...");
decimal mm = unchecked(m + 1);
Console.WriteLine(mm);
```

::terminal-preview{title="dotnet run floating-overflow.cs"}
```text
checked(double.MaxValue * 2) = ∞
unchecked(decimal.MaxValue + 1)...
Unhandled exception. System.OverflowException: Value was either too large or too small for a Decimal.
```
::

**Константи компілятор перевіряє завжди.** Якщо переповнення видно ще під час компіляції, це помилка, а не тихе обертання:

::terminal-preview{title="dotnet build errors/const-overflow.cs і errors/const-cast.cs"}
```text
const-overflow.cs(1,9): error CS0220: The operation overflows at compile time in checked mode
const-cast.cs(1,10): error CS0221: Constant value '300' cannot be converted to a 'byte' (use 'unchecked' syntax to override)
```
::

Перший рядок — `int x = int.MaxValue + 1;`, другий — `byte b = (byte)300;`. Компілятор сам підказує: щоб навмисно отримати обернене значення константи, потрібен `unchecked(...)`.

### checked в IL

Різницю видно в декомпіляторі. Чотири локальні функції з `checked-il.cs` — додавання і приведення `long` до `int`, без перевірки і з нею:

::code-group

```csharp [checked-il.cs]
static int Add(int a, int b) => a + b;
static int AddChecked(int a, int b) => checked(a + b);
static int ToInt(long value) => (int)value;
static int ToIntChecked(long value) => checked((int)value);
```

```text [IL (ilspycmd -il, Release)]
// Add
IL_0002: add
// AddChecked
IL_0002: add.ovf
// ToInt
IL_0001: conv.i4
// ToIntChecked
IL_0001: conv.ovf.i4
```

::

`checked` не додає в код `if`: він замінює інструкцію на її версію з перевіркою (`.ovf` — *overflow*), а перевірку виконує процесор разом з операцією. Ціна невелика, але в обчислювальних циклах помітна, тому за замовчуванням перевірку вимкнено.

**Чому за замовчуванням unchecked.** Так поводяться C, C++ і процесор: арифметика по колу — найшвидша. Хеш-функції, генератори випадкових чисел і контрольні суми покладаються саме на обертання. А для бізнес-розрахунків (гроші, кількості, лічильники) розумно вмикати перевірку: виняток у місці помилки кращий за неправильне число в звіті.

::callout{icon="i-lucide-lightbulb"}
**Коли вмикати перевірку**

- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`checked` для виразу чи блоку** — у розрахунках, де переповнення означає помилку: суми, кількості, розміри.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`CheckForOverflowUnderflow` для всієї програми** — у навчальних і бізнесових проєктах, де швидкість обчислень не критична.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`unchecked`** — явно там, де обертання потрібне: хеші, контрольні суми.
- :icon{name="i-lucide-circle-x" class="inline-block text-red-500"} **Не покладайтеся на `checked` для `double`**: перевіряйте результат через `double.IsInfinity`, або беріть `decimal`.

## Перетворення між числовими типами

### Неявні перетворення

**Неявне перетворення** (*implicit conversion*) компілятор виконує сам, без запису в коді. C# дозволяє його лише тоді, коли будь-яке значення вихідного типу влазить у діапазон цільового: з `int` у `long`, з `float` у `double`, з `char` у `int`.

![Граф неявних числових перетворень: sbyte → short → int → long, byte → ushort → uint → ulong, byte → short, ushort → int, uint → long, char → ushort, float → double, int → double; пунктиром (можлива втрата точності) — int → float, long → double, ulong → double; long і ulong → decimal](/images/csharp/fundamentals/numbers-and-conversions/03-implicit-graph.png){.wide-img}

«Влазить у діапазон» не означає «зберігає всі цифри». Перетворення цілого в `float` чи `long` у `double` компілятор дозволяє неявно, хоча частина цифр може загубитися:

```csharp [implicit.cs]
int i = 123_456_789;
long l = i;          // без втрат
double d = i;        // без втрат: double точно зберігає будь-який int
float f = i;         // дозволено неявно, але float має лише 24 біти мантиси
Console.WriteLine($"int {i} -> long {l}, double {d}, float {f:F0}");

long big = 9_007_199_254_740_993;
double bd = big;     // double має 53 біти мантиси
Console.WriteLine($"long {big} -> double {bd:F0}");

char c = 'A';
int code = c;
decimal money = i;
Console.WriteLine($"char 'A' -> int {code}; int -> decimal {money}");
```

::terminal-preview{title="dotnet run implicit.cs"}
```text
int 123456789 -> long 123456789, double 123456789, float 123456792
long 9007199254740993 -> double 9007199254740992
char 'A' -> int 65; int -> decimal 123456789
```
::

`float` зберігає 24 значущі двійкові цифри, тобто точно — лише цілі до 16 777 216. Число 123 456 789 більше, і найближче, яке можна записати, — 123 456 792. `double` має 53 двійкові цифри: будь-який `int` він зберігає точно, а `long` — лише до 2⁵³ = 9 007 199 254 740 992.

У зворотному напрямку компілятор вимагає явного приведення, навіть якщо конкретне значення влазить:

::terminal-preview{title="dotnet build errors/conversions.cs"}
```text
conversions.cs(2,9): error CS0266: Cannot implicitly convert type 'long' to 'int'. An explicit conversion exists (are you missing a cast?)
conversions.cs(5,12): error CS0266: Cannot implicitly convert type 'double' to 'float'. An explicit conversion exists (are you missing a cast?)
conversions.cs(6,13): error CS0266: Cannot implicitly convert type 'double' to 'decimal'. An explicit conversion exists (are you missing a cast?)
conversions.cs(8,10): error CS0266: Cannot implicitly convert type 'int' to 'char'. An explicit conversion exists (are you missing a cast?)
conversions.cs(9,10): error CS0266: Cannot implicitly convert type 'int' to 'uint'. An explicit conversion exists (are you missing a cast?)
```
::

У C++ звуження `int x = someLong;` компілюється, у кращому разі з попередженням. C# вимагає записати приведення явно, щоб місце можливої втрати даних було видно в коді. Між `double` і `decimal` неявного перетворення немає в жодному напрямку: `decimal` точніший, а `double` має більший діапазон, тож втрати можливі в обидва боки.

### Явні перетворення

**Явне перетворення** (*explicit conversion*, приведення, *cast*) записується як `(тип)вираз`. Ним програміст підтверджує, що втрата даних можлива і передбачена:

```csharp [explicit.cs]
double price = 3.99;
double negative = -3.99;
Console.WriteLine($"(int)3.99 = {(int)price}, (int)-3.99 = {(int)negative}");

int big = 300;
Console.WriteLine($"(byte)300 = {(byte)big}");

long three = 3_000_000_000;
Console.WriteLine($"(int)3_000_000_000L = {(int)three}");

double huge = 1e10;
double nan = double.NaN;
Console.WriteLine($"(int)1e10 = {(int)huge}, (int)NaN = {(int)nan}");

double tenth = 0.1;
float tenthF = (float)tenth;
Console.WriteLine($"(float)0.1 = {tenthF}, назад у double: {(double)tenthF}");

decimal money = 19.99m;
Console.WriteLine($"(double)19.99m = {(double)money}, (int)19.99m = {(int)money}");
```

::terminal-preview{title="dotnet run explicit.cs"}
```text
(int)3.99 = 3, (int)-3.99 = -3
(byte)300 = 44
(int)3_000_000_000L = -1294967296
(int)1e10 = 2147483647, (int)NaN = 0
(float)0.1 = 0.1, назад у double: 0.10000000149011612
(double)19.99m = 19.99, (int)19.99m = 19
```
::

- **Дробове → ціле** відкидає дробову частину, тобто округлює в бік нуля: 3.99 → 3, −3.99 → −3. Це не округлення до найближчого.
- **Широке ціле → вузьке** залишає молодші біти: 300 → 44, 3 000 000 000 → −1 294 967 296. Те саме обертання по колу, що й при переповненні.
- **Дробове, яке не влазить у ціле.** У .NET 10 результат насичений (*saturating*): найближча межа типу, а `NaN` дає 0. Старіші версії .NET на процесорах x64 давали інший результат (`int.MinValue`), тому на це покладатися не варто. Надійно — перевірити діапазон або написати `checked((int)huge)`, і тоді програма кине `OverflowException`.
- **`double` → `float`** округлює до найближчого `float`. `0.1f` друкується як 0.1, бо `ToString` показує найкоротший запис, який читається назад у те саме `float`, але в `double` видно справжнє значення 0.10000000149011612.

### Округлення

Приведення `(int)x` — лише один зі способів отримати ціле з дробового. Решта — методи класу `Math` і `Convert.ToInt32`:

```csharp [rounding.cs]
double[] values = [2.4, 2.5, 2.6, 3.5, -2.5, -2.7];
Console.WriteLine("    x  (int)x  Round  AwayFromZero  Floor  Ceiling  Convert.ToInt32");
foreach (double x in values)
{
    Console.WriteLine($"{x,5}  {(int)x,6}  {Math.Round(x),5}  {Math.Round(x, MidpointRounding.AwayFromZero),12}  " +
                      $"{Math.Floor(x),5}  {Math.Ceiling(x),7}  {Convert.ToInt32(x),15}");
}
Console.WriteLine();
Console.WriteLine($"Math.Round(2.665m, 2)               = {Math.Round(2.665m, 2)}");
Console.WriteLine($"Math.Round(2.665m, 2, AwayFromZero) = {Math.Round(2.665m, 2, MidpointRounding.AwayFromZero)}");
```

::terminal-preview{title="dotnet run rounding.cs"}
```text
    x  (int)x  Round  AwayFromZero  Floor  Ceiling  Convert.ToInt32
  2.4       2      2             2      2        3                2
  2.5       2      2             3      2        3                2
  2.6       2      3             3      2        3                3
  3.5       3      4             4      3        4                4
 -2.5      -2     -2            -3     -3       -2               -2
 -2.7      -2     -3            -3     -3       -2               -3

Math.Round(2.665m, 2)               = 2.66
Math.Round(2.665m, 2, AwayFromZero) = 2.67
```
::

![П'ять способів округлення для 2.5 і −2.7 на числовій осі: (int)x — 2 і −2, Floor — 2 і −3, Ceiling — 3 і −2, Round — 2 і −3, Round з AwayFromZero — 3 і −3](/images/csharp/fundamentals/numbers-and-conversions/04-rounding.png){.diagram-img}

`Math.Round(2.5)` дорівнює **2**, а не 3. За замовчуванням `Math.Round` округлює половину до найближчого **парного** числа (*banker's rounding*, `MidpointRounding.ToEven`): 2.5 → 2, 3.5 → 4, −2.5 → −2. Так само працює `Convert.ToInt32`. Причина — накопичення похибки. «Шкільне» правило завжди округлює половину вгору, і сума великої кількості округлених значень систематично виходить більшою за точну. Округлення до парного в половині випадків іде вгору, у половині — вниз, і похибки компенсуються. Тому його використовують у статистиці й фінансах, а правило «від нуля» вмикають явно: `MidpointRounding.AwayFromZero`.

::callout{icon="i-lucide-lightbulb"}
**Який спосіб округлення обрати**

- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`(int)x`** — коли потрібна ціла частина: скільки повних годин у 7.9 години.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`Math.Ceiling`** — «скільки потрібно, щоб вистачило»: кількість сторінок для 41 запису по 10 на сторінку — `Math.Ceiling(41 / 10.0)` = 5.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`Math.Floor`** — округлення вниз і для від'ємних чисел: −2.7 → −3, тоді як `(int)` дає −2.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`Math.Round(x, digits, MidpointRounding.…)`** — гроші й оцінки: правило округлення половини задається явно, щоб воно було видно в коді.
- :icon{name="i-lucide-circle-x" class="inline-block text-red-500"} **Не чекайте від `Math.Round(2.5)` результату 3**: за замовчуванням це 2.

::

## Рядок у число і число в рядок

Приведення працює лише між числовими типами. Рядок — не число, і `(int)"42"` не компілюється:

::terminal-preview{title="dotnet build errors/cast-string.cs"}
```text
cast-string.cs(2,13): error CS0030: Cannot convert type 'string' to 'int'
```
::

Для перетворення тексту на число є три способи:

::field-group

::field{name="int.Parse(s)" type="рядок → число"}
Розбирає рядок. Якщо рядок не є числом потрібного типу — кидає виняток: `FormatException` для неправильного формату, `OverflowException` для числа поза діапазоном, `ArgumentNullException` для `null`.
::

::field{name="int.TryParse(s, out int n)" type="рядок → число без винятку"}
Повертає `true` і записує число в `n`, або повертає `false`, і тоді `n` дорівнює 0. Для введення користувача — основний спосіб.
::

::field{name="Convert.ToInt32(x)" type="з будь-якого типу"}
Приймає рядок, `double`, `bool`, `null` та інші типи. `null` перетворює на 0, дробові числа округлює до парного.
::

::field{name="number.ToString()" type="число → рядок"}
Зворотний напрямок. Формат задається аргументом або в інтерполяції: `x.ToString("F2")`, `$"{x:F2}"` — лекція про консольне введення й виведення.
::

::

```csharp [convert-parse.cs]
string text = "42";
int a = int.Parse(text);
int b = Convert.ToInt32(text);
Console.WriteLine($"int.Parse(\"42\") = {a}, Convert.ToInt32(\"42\") = {b}");

string? missing = null;
Console.WriteLine($"Convert.ToInt32(null) = {Convert.ToInt32(missing)}");

double x = 12.6;
Console.WriteLine($"(int)12.6 = {(int)x}, Convert.ToInt32(12.6) = {Convert.ToInt32(x)}");
Console.WriteLine($"Convert.ToInt32(true) = {Convert.ToInt32(true)}, Convert.ToBoolean(0) = {Convert.ToBoolean(0)}");
Console.WriteLine($"Convert.ToString(42, 2) = {Convert.ToString(42, 2)}, Convert.ToInt32(\"101010\", 2) = {Convert.ToInt32("101010", 2)}");

if (int.TryParse("abc", out int number))
{
    Console.WriteLine($"число: {number}");
}
else
{
    Console.WriteLine($"\"abc\" — не число, number = {number}");
}
```

::terminal-preview{title="dotnet run convert-parse.cs"}
```text
int.Parse("42") = 42, Convert.ToInt32("42") = 42
Convert.ToInt32(null) = 0
(int)12.6 = 12, Convert.ToInt32(12.6) = 13
Convert.ToInt32(true) = 1, Convert.ToBoolean(0) = False
Convert.ToString(42, 2) = 101010, Convert.ToInt32("101010", 2) = 42
"abc" — не число, number = 0
```
::

Запис `out int number` оголошує змінну, в яку метод запише результат. Параметри `out` докладно розбирає лекція 15, а зараз достатньо шаблону `if (int.TryParse(рядок, out int змінна))`. `Convert.ToString(42, 2)` і `Convert.ToInt32("101010", 2)` перетворюють між рядком і числом у системах числення з основою 2, 8, 10 і 16.

`Parse` для неправильного рядка зупиняє програму:

::terminal-preview{title="dotnet run parse-errors.cs -- abc / -- 3000000000 / -- 4.5"}
```text
Unhandled exception. System.FormatException: The input string 'abc' was not in a correct format.
Unhandled exception. System.OverflowException: Value was either too large or too small for an Int32.
Unhandled exception. System.FormatException: The input string '4.5' was not in a correct format.
```
::

`TryParse` для тих самих і ще кількох рядків:

```csharp [tryparse.cs]
string?[] inputs = ["42", " 42 ", "+42", "-0", "4 2", "42.0", "1_000", "", "3000000000", null];
Console.WriteLine("рядок          успіх  результат");
foreach (string? s in inputs)
{
    bool ok = int.TryParse(s, out int n);
    Console.WriteLine($"{Show(s),-14} {ok,-6} {n}");
}

static string Show(string? s) => s is null ? "null" : $"\"{s}\"";
```

::terminal-preview{title="dotnet run tryparse.cs"}
```text
рядок          успіх  результат
"42"           True   42
" 42 "         True   42
"+42"          True   42
"-0"           True   0
"4 2"          False  0
"42.0"         False  0
"1_000"        False  0
""             False  0
"3000000000"   False  0
null           False  0
```
::

Пробіли на початку й у кінці допускаються, знак `+` — теж. Роздільник `_` існує лише в літералах коду, а не в тексті, який розбирає `Parse`. `"42.0"` — не ціле число, хоча значення ціле: для нього потрібен `double.TryParse`.

::warning
`double.Parse` і `double.TryParse` розбирають рядок за регіональними налаштуваннями ОС. На комп'ютері з українськими налаштуваннями роздільник дробової частини — кома, і `double.Parse("3.14")` кине `FormatException`. Для даних з файлів, мережі чи конфігурації передавайте `CultureInfo.InvariantCulture` (namespace `System.Globalization`): `double.Parse(text, CultureInfo.InvariantCulture)`. Докладніше — у рамці про регіональні налаштування нижче.
::

**Коли який спосіб**

- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`TryParse`** — введення користувача, рядки з файлів і мережі: усе, що може бути неправильним.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`Parse`** — коли неправильний рядок означає помилку в програмі, і зупинка з винятком — правильна реакція.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **Приведення `(int)x`** — між числовими типами, коли відкидання дробової частини потрібне.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`Convert`** — перетворення між системами числення і з `bool`.
- :icon{name="i-lucide-circle-x" class="inline-block text-red-500"} **Не перетворюйте введення через `Convert.ToInt32`**: для `null` він мовчки поверне 0, а для неправильного тексту кине виняток — гірше з обох варіантів.

- `"7,5"` як `double` дає **75**: в InvariantCulture кома — роздільник тисяч, а не дробової частини, і `TryParse` його пропускає. Помилки немає — є неправильне число.
- `"1e400"` більше за `double.MaxValue`, і `double.TryParse` повертає нескінченність, а не `false`.
- `"-7.5e2"` — експоненційний запис: −7.5·10² = −750. `int.TryParse` його не приймає.

### Будова double: IEEE 754

У лекції 04 `0.1 + 0.2` дало `0.30000000000000004`. Причина — у тому, як `double` зберігає число. За стандартом IEEE 754 64 біти поділено на три частини: знак, порядок (*exponent*) і мантису (*mantissa*). Число дорівнює ±1.мантиса × 2^порядок, як науковий запис, тільки в двійковій системі:

![64 біти числа 0.1: знак 0 (плюс), порядок 01111111011 = 1019, тобто 1019 − 1023 = −4, мантиса 1001100110011…1010 — дробова частина числа ≈ 1.6; значення = 1.6000000000000000888 × 2⁻⁴ = 0.1000000000000000055511151](/images/csharp/fundamentals/numbers-and-conversions/05-double-bits.png){.wide-img}

Десятковий дріб 0.1 у двійковій системі нескінченний (0.000110011001100…₂), як ⅓ = 0.333… у десятковій. 52 біти мантиси вміщають лише початок, тому в `double` лежить найближче число, трохи більше за 0.1. Програма `ieee.cs` показує біти, точне значення і наслідки:

```csharp [ieee.cs (фрагмент)]
double x = 0.1;
long bits = BitConverter.DoubleToInt64Bits(x);
Console.WriteLine($"біти 0.1: {bits:B64}");
Console.WriteLine($"0.1 насправді: {x:F25}");

double sum = 0;
for (int i = 0; i < 10; i++)
{
    sum += 0.1;
}
Console.WriteLine($"0.1 десять разів: {sum}, == 1.0? {sum == 1.0}");
Console.WriteLine($"з допуском 1e-9: {Math.Abs(sum - 1.0) < 1e-9}");
```

```text
біти 0.1: 0011111110111001100110011001100110011001100110011001100110011010
0.1 насправді: 0.1000000000000000055511151
0.1 десять разів: 0.9999999999999999, == 1.0? False
різниця: 1.1102230246251565E-16

NaN == NaN: False, double.IsNaN(NaN): True

```
::

- **Порівняння з допуском.** Похибки окремих операцій накопичуються, тому дробові числа порівнюють не через `==`, а через різницю: `Math.Abs(a - b) < 1e-9`. Розмір допуску залежить від задачі й масштабу чисел.
- **Нескінченність.** Ділення `double` на нуль не кидає виняток, а дає `∞` чи `-∞` (`double.PositiveInfinity`, `double.NegativeInfinity`). Ціле `int` на нуль — інакше: `DivideByZeroException` (приклад `int-divide.cs`).
- **NaN** (*Not a Number*) — результат невизначених операцій: 0.0 / 0, корінь з від'ємного. `NaN` не дорівнює нічому, навіть собі, тому перевірка — лише `double.IsNaN(x)`. На `nan == nan` компілятор навіть попереджає (CS1718: порівняння змінної з самою собою).
- **Від'ємний нуль.** −0.0 дорівнює 0.0 при порівнянні, але `1 / -0.0` дає `-∞`: знак зберігається в окремому біті.
- **`double.Epsilon`** — найменше додатне число, близько 5·10⁻³²⁴. Як допуск для порівняння воно не годиться: це не «точність double», а межа біля нуля.

Символи `∞` і `-∞` у виводі залежать від регіональних налаштувань: InvariantCulture друкує `Infinity`.

### BigInteger: ціле без меж

Коли ціле число не влазить навіть у `decimal`, є `System.Numerics.BigInteger`. Його розмір обмежений лише пам'яттю, а переповнення немає:

```csharp [bigint.cs]
using System.Numerics;

BigInteger factorial = 1;
for (int i = 2; i <= 30; i++)
{
    factorial *= i;
}
Console.WriteLine($"30! = {factorial}");
Console.WriteLine($"2^128 = {BigInteger.Pow(2, 128)}");
Console.WriteLine($"long.MaxValue + 1 = {(BigInteger)long.MaxValue + 1}");
```

### Регіональні налаштування і розбір чисел

Кожна культура (*culture*) — набір правил для мови й регіону: роздільник дробової частини, роздільник тисяч, формат дати. Методи `ToString`, `Parse`, `TryParse` та інтерполяція за замовчуванням використовують поточну культуру ОС — `CultureInfo.CurrentCulture`. Одне й те саме число в різних культурах:

```csharp [culture.cs]
using System.Globalization;

Console.WriteLine($"поточна культура: {CultureInfo.CurrentCulture.Name}");
string[] names = ["uk-UA", "en-US", "de-DE", ""];
foreach (string name in names)
{
    CultureInfo culture = CultureInfo.GetCultureInfo(name);
    string label = name == "" ? "Invariant" : name;
    string shown = 1234.5.ToString("N2", culture).Replace(' ', '_').Replace(' ', '_');
    string dot = double.TryParse("3.14", culture, out double a) ? a.ToString(CultureInfo.InvariantCulture) : "помилка";
    string comma = double.TryParse("3,14", culture, out double b) ? b.ToString(CultureInfo.InvariantCulture) : "помилка";
    Console.WriteLine($"{label,-10} 1234.5 -> {shown,-10} \"3.14\" -> {dot,-8} \"3,14\" -> {comma}");
}
```

::terminal-preview{title="dotnet run culture.cs"}
```text
поточна культура: en-NZ
uk-UA      1234.5 -> 1_234,50   "3.14" -> помилка  "3,14" -> 3.14
en-US      1234.5 -> 1,234.50   "3.14" -> 3.14     "3,14" -> 314
de-DE      1234.5 -> 1.234,50   "3.14" -> 314      "3,14" -> 3.14
Invariant  1234.5 -> 1,234.50   "3.14" -> 3.14     "3,14" -> 314
```
::

Роздільник тисяч в українській культурі — нерозривний пробіл, у виводі його замінено на `_`, щоб було видно. Його конкретний символ залежить від бібліотеки культур ОС (ICU в Linux і macOS, NLS у Windows), тому на Windows вивід може трохи відрізнятися.

- **uk-UA:** `"3.14"` не розбирається зовсім — і це найкращий варіант, бо помилку видно.
- **en-US і Invariant:** `"3,14"` дає 314. Кома — роздільник тисяч, `TryParse` повертає `true`, і програма працює з числом, у сто разів більшим.
- **de-DE:** навпаки, `"3.14"` дає 314, бо крапка — роздільник тисяч.

Правило: **текст для людини** (вивід на екран, введення з клавіатури) — у поточній культурі; **дані для програм** (файли, CSV, JSON, мережа, конфігурація) — в `CultureInfo.InvariantCulture`, і для читання, і для запису: `x.ToString(CultureInfo.InvariantCulture)`, `double.Parse(text, CultureInfo.InvariantCulture)`. Інакше файл, записаний на одному комп'ютері, неправильно прочитається на іншому.

## Питання для самоперевірки

::::accordion

:::accordion-item{label="Чому int.MaxValue + 1 дорівнює int.MinValue і чому немає помилки?" icon="i-lucide-help-circle"}

`int.MaxValue` у двійковому записі — нуль у знаковому біті й одиниці в решті. Додавання одиниці переносить розряд у знаковий біт, і виходить `1000…0`, що в доповняльному коді є найменшим від'ємним числом. За замовчуванням C# не перевіряє переповнення (контекст `unchecked`), бо так швидше і так поводиться процесор. Перевірку вмикає `checked`.

:::

:::accordion-item{label="Чому long total = a + c для двох великих int дає від'ємне число?" icon="i-lucide-help-circle"}

Тип виразу `a + c` визначають операнди, а не змінна, в яку записується результат. Обидва операнди `int`, тому додавання виконується в `int` і переповнюється. У `long` записується вже неправильний результат. Треба перетворити один з операндів до операції: `(long)a + c`.

:::

:::accordion-item{label="Що робить checked і на які операції не впливає?" icon="i-lucide-help-circle"}

`checked` змушує цілочисельну арифметику і явні перетворення до цілих типів кидати `OverflowException` замість обертання по колу; в IL це інструкції з суфіксом `.ovf`. На `double` і `float` він не впливає (переповнення дає нескінченність), `decimal` перевіряє переповнення завжди, а методи, викликані з блоку `checked`, працюють у своєму контексті.

:::

:::accordion-item{label="Чому int → float — неявне перетворення, хоча воно може втратити точність?" icon="i-lucide-help-circle"}

Неявні перетворення C# дозволяє, коли діапазон цільового типу вміщає весь діапазон вихідного. Діапазон `float` (до 3.4·10³⁸) значно більший за діапазон `int`, тому перетворення не дає переповнення. Але `float` має лише 24 двійкові цифри точності, і цілі більше 16 777 216 зберігаються наближено: 123 456 789 стає 123 456 792.

:::

:::accordion-item{label="Чим (int)x відрізняється від Math.Round(x) і Convert.ToInt32(x)?" icon="i-lucide-help-circle"}

`(int)x` відкидає дробову частину, тобто округлює в бік нуля: 2.6 → 2, −2.7 → −2. `Math.Round(x)` округлює до найближчого цілого, а половину — до парного: 2.6 → 3, 2.5 → 2. `Convert.ToInt32(x)` округлює так само, як `Math.Round`.

:::

:::accordion-item{label="Чому Math.Round(2.5) дає 2 і навіщо таке правило?" icon="i-lucide-help-circle"}

За замовчуванням використовується банківське округлення: половина округлюється до найближчого парного числа. Округлення половини завжди вгору систематично збільшує суму великої кількості округлених значень. Округлення до парного в половині випадків іде вгору, в половині — вниз, і похибки взаємно компенсуються. Звичне правило вмикається явно: `MidpointRounding.AwayFromZero`.

:::

:::accordion-item{label="Чому для введення користувача краще TryParse, а не Parse чи Convert?" icon="i-lucide-help-circle"}

Користувач може ввести будь-що, і неправильне введення — нормальна ситуація, а не помилка програми. `Parse` для неправильного рядка кидає виняток і зупиняє програму. `Convert.ToInt32` теж кидає виняток для неправильного тексту, а для `null` мовчки повертає 0. `TryParse` повертає `false`, і програма сама вирішує, що робити: попросити ввести знову чи взяти значення за замовчуванням.

:::

:::accordion-item{label="Чому (int)1e10 краще не писати без перевірки діапазону?" icon="i-lucide-help-circle"}

10¹⁰ не влазить в `int`. У .NET 10 результат насичується до `int.MaxValue`, але старіші версії .NET на x64 давали інше число, тож поведінка залежить від версії і платформи. Надійно — перевірити діапазон перед приведенням або написати `checked((int)x)`, щоб отримати `OverflowException`.

:::

   - для сум 12.345, 12.355, 0.125, 0.135, 7.005, 7.015 (у `decimal`) друкує округлення до копійок двома способами: `Math.Round(x, 2)` і `Math.Round(x, 2, MidpointRounding.AwayFromZero)`;
   - друкує три підсумки: точну суму, суму округлених першим способом і суму округлених другим.
2. Письмово поясніть:
   - чому сума в `double` не дорівнює 1;
   - який спосіб округлення дав підсумок, ближчий до точного, і чому.

Додайте скріншот виводу.

- 0.10 у `double` — найближче двійкове число, трохи менше або більше за 0.1. Десять додавань накопичують похибку, і сума виходить 0.9999999999999999. `decimal` зберігає 0.10 точно.
- Банківське округлення (`ToEven`) дало 38.98 — рівно точну суму: три половини округлено вниз (12.34, 0.12, 7.00), три — вгору. «Від нуля» округлило вгору всі шість половин, і підсумок виріс на 3 копійки. На тисячах операцій така похибка стає помітною.

:::accordion-item{label="Розв'язок завдання 4" icon="i-lucide-check-circle"}

```csharp [age-input.cs]
Console.Write("Вік: ");
string? input = Console.ReadLine();

if (!int.TryParse(input, out int age))
{
    Console.WriteLine($"\"{input}\" — не ціле число");
}
else if (age < 0 || age > 150)
{
    Console.WriteLine($"{age} — поза діапазоном 0–150");
}
else
{
    Console.WriteLine($"Вік: {age}, через 10 років: {age + 10}");
}
```

| Введення | Вивід |
|---|---|
| `25` | Вік: 25, через 10 років: 35 |
| `abc` | "abc" — не ціле число |
| порожній рядок | "" — не ціле число |
| `  30 ` | Вік: 30, через 10 років: 40 |
| `200` | 200 — поза діапазоном 0–150 |
| `-5` | -5 — поза діапазоном 0–150 |
| `25.5` | "25.5" — не ціле число |

- Пробіли по краях `TryParse` пропускає, тому `  30 ` розібрано.
- `25.5` — не ціле число, хоча це число: `int.TryParse` повертає `false`.
- З `int.Parse` введення `abc` зупинило б програму: `Unhandled exception. System.FormatException: The input string 'abc' was not in a correct format.`
- Якщо введення закінчилося (Ctrl+Z, Ctrl+D), `ReadLine` повертає `null`, `TryParse` повертає `false`, і програма друкує `"" — не ціле число`: інтерполяція друкує `null` як порожній рядок.
