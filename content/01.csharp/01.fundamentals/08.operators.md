## Вираз і оператор

### Будова виразу

Змінні з лекцій 04–06 зберігають значення. Щоб із них щось обчислити, значення поєднують операторами у вирази.

**Вираз** (*expression*) — частина коду, яка обчислюється в значення певного типу: `2 + 3`, `age >= 18`, `name.Length`, `Math.Max(a, b)`. **Оператор** (*operator*) — символ чи слово, яке виконує дію над значеннями: `+`, `>=`, `&&`. Значення, над якими працює оператор, — **операнди** (*operands*): змінні, літерали, виклики методів або інші вирази.

![Анатомія виразу int total = price * count - discount: total отримує значення виразу, = — оператор присвоєння, price, count і discount — операнди, * і - — бінарні оператори; price * count — підвираз з власним значенням; увесь вираз праворуч від = має тип int; унарні оператори мають один операнд, бінарні — два, тернарний — три](/images/csharp/fundamentals/operators/01-expression-anatomy.png){.diagram-img}

- **Вираз складається з підвиразів.** `price * count` — теж вираз зі своїм значенням, і саме воно стає лівим операндом для `-`. Будь-який вираз можна взяти в дужки і використати як операнд.
- **Кожен вираз має тип**, і компілятор знає його до запуску: `price * count` для двох `int` має тип `int`, `age >= 18` — `bool`. Від типу операндів залежить, що робить оператор: `/` для `int` ділить націло, для `double` — дробово.
- **Присвоєння — теж оператор.** `=` має найнижчий пріоритет серед звичайних операторів, тому виконується після всього, що стоїть праворуч.

За кількістю операндів оператори бувають **унарні** (один операнд: `-x`, `!done`, `i++`), **бінарні** (два: `a + b`, `x < y`) і один **тернарний** (три: `умова ? a : b`). Унарний оператор стоїть перед операндом (префіксна форма: `-x`, `++i`) або після нього (постфіксна: `i++`), бінарний — між операндами.

### Групи операторів

Оператори лекції, по одному прикладу на групу:

```csharp [overview.cs]
int x = 10;
bool done = false;
Console.WriteLine($"арифметичні:  7 / 2 = {7 / 2}, 7 % 2 = {7 % 2}, -x = {-x}");
Console.WriteLine($"порівняння:   3 < 5 = {3 < 5}, 3 == 5 = {3 == 5}");
Console.WriteLine($"логічні:      true && false = {true && false}, !done = {!done}");
Console.WriteLine($"бітові:       6 & 3 = {6 & 3}, 1 << 4 = {1 << 4}");
x += 5;
Console.WriteLine($"присвоєння:   x += 5 -> x = {x}");
Console.WriteLine($"умовний:      x > 0 ? \"+\" : \"-\" = {(x > 0 ? "+" : "-")}");
```

::terminal-preview{title="dotnet run overview.cs"}
```text
арифметичні:  7 / 2 = 3, 7 % 2 = 1, -x = -10
порівняння:   3 < 5 = True, 3 == 5 = False
логічні:      true && false = False, !done = True
бітові:       6 & 3 = 2, 1 << 4 = 16
присвоєння:   x += 5 -> x = 15
умовний:      x > 0 ? "+" : "-" = +
```
::

| Група | Оператори | Тип результату | Розділ |
|---|---|---|---|
| арифметичні | `+` `-` `*` `/` `%`, унарні `+x` `-x`, `++` `--` | числовий | [Арифметичні оператори](#арифметичні-оператори) |
| порівняння | `==` `!=` `<` `>` `<=` `>=` | `bool` | [Оператори порівняння](#оператори-порівняння) |
| логічні | `!` `&&` `\|\|`, а також `&` `\|` `^` для `bool` | `bool` | [Логічні оператори](#логічні-оператори) |
| бітові | `~` `&` `\|` `^` `<<` `>>` `>>>` | цілий | [Бітові оператори](#бітові-оператори) |
| присвоєння | `=` і складені `+=` `-=` `*=` … `??=` | тип змінної | [Присвоєння](#присвоєння) |
| умовний | `?:` | тип гілок | лекція 09 |

Синтаксис і більшість правил — такі самі, як у C++. Відмінності, через які код, перенесений з C++, поводиться інакше або не компілюється:

- **порядок обчислення операндів визначений**: зліва направо, тому `i++ + i++` — не невизначена поведінка;
- **цілі числа не перетворюються на `bool`**: `if (x & 1)` не компілюється;
- **ланцюжок порівнянь `1 < x < 10` і `x & 1 == 0` — помилки компіляції**, а не тиха помилка логіки;
- **рядки не порівнюються через `<` і `>`**, лише через `==` і `!=`;
- **кількість зсуву маскується**: `1 << 33` для `int` дорівнює 2;
- **у мові є `>>>`** — логічний зсув вправо для знакових типів (з C# 11);
- **оператора степеня немає**, а `^` — це XOR.

## Арифметичні оператори

### Усі арифметичні оператори

Арифметичні оператори працюють з усіма числовими типами: цілими, `double`, `float`, `decimal`. Програма з усіма формами:

```csharp [arith-all.cs]
int a = 17, b = 5;
Console.WriteLine($"a + b = {a + b}");
Console.WriteLine($"a - b = {a - b}");
Console.WriteLine($"a * b = {a * b}");
Console.WriteLine($"a / b = {a / b}");
Console.WriteLine($"a % b = {a % b}");
Console.WriteLine($"-a = {-a}, +a = {+a}");
Console.WriteLine();

double x = 17, y = 5;
Console.WriteLine($"x / y = {x / y}");
Console.WriteLine($"x % y = {x % y}");
Console.WriteLine();

int i = 5;
i++;
Console.WriteLine($"після i++: i = {i}");
i--;
i--;
Console.WriteLine($"після двох i--: i = {i}");
```

::terminal-preview{title="dotnet run arith-all.cs"}
```text
a + b = 22
a - b = 12
a * b = 85
a / b = 3
a % b = 2
-a = -17, +a = 17

x / y = 3.4
x % y = 2

після i++: i = 6
після двох i--: i = 4
```
::

::field-group

::field{name="a + b" type="додавання"}
Для чисел — сума. Якщо хоча б один операнд — рядок, `+` склеює рядки (нижче).
::

::field{name="a - b, a * b" type="віднімання, множення"}
Для цілих типів можливе переповнення (лекція 06).
::

::field{name="a / b" type="ділення"}
Для двох цілих — ціле ділення: `17 / 5 = 3`. Якщо хоча б один операнд дробовий — звичайне: `3.4`.
::

::field{name="a % b" type="остача від ділення"}
`17 % 5 = 2`, бо 17 = 3 · 5 + 2. Працює і для дробових типів.
::

::field{name="-a, +a" type="унарні мінус і плюс"}
`-a` змінює знак. `+a` значення не змінює; для `byte` чи `short` він, як і будь-яка арифметика, дає `int` (лекція 04).
::

::field{name="i++, i--, ++i, --i" type="інкремент, декремент"}
Збільшують чи зменшують змінну на 1. Префіксна і постфіксна форми відрізняються значенням виразу (розділ нижче).
::

::

Результат має тип ширшого з операндів (лекція 06): `int` і `int` дають `int`, `int` і `double` — `double`. Звідси головні особливості ділення.

### Ділення і остача

Ділення двох `int` — цілочисельне, а знак остачі має свої правила:

```csharp [arith.cs]
int a = 7, b = 2;
Console.WriteLine($" 7 / 2 = {a / b},   7 % 2 = {a % b}");
Console.WriteLine($"-7 / 2 = {-a / b},  -7 % 2 = {-a % b}");
Console.WriteLine($" 7 / -2 = {a / -b},  7 % -2 = {a % -b}");
Console.WriteLine($" 7 / 2.0 = {a / 2.0}, (double)7 / 2 = {(double)a / b}");
Console.WriteLine($" 5.5 % 2 = {5.5 % 2},  -5.5 % 2 = {-5.5 % 2}");
Console.WriteLine($" (7 / 2) * 2 + 7 % 2 = {(a / b) * b + a % b}");
Console.WriteLine();

int sum = 18, count = 4;
double wrong = sum / count;
double right = (double)sum / count;
Console.WriteLine($"середнє: sum / count = {wrong}, (double)sum / count = {right}");
Console.WriteLine();

Console.WriteLine("1" + 2 + 3);
Console.WriteLine(1 + 2 + "3");
Console.WriteLine($"2 ^ 3 = {2 ^ 3}, Math.Pow(2, 3) = {Math.Pow(2, 3)}");
```

::terminal-preview{title="dotnet run arith.cs"}
```text
 7 / 2 = 3,   7 % 2 = 1
-7 / 2 = -3,  -7 % 2 = -1
 7 / -2 = -3,  7 % -2 = 1
 7 / 2.0 = 3.5, (double)7 / 2 = 3.5
 5.5 % 2 = 1.5,  -5.5 % 2 = -1.5
 (7 / 2) * 2 + 7 % 2 = 7

середнє: sum / count = 4, (double)sum / count = 4.5

123
33
2 ^ 3 = 1, Math.Pow(2, 3) = 8
```
::

- **Ціле ділення відкидає дробову частину** в бік нуля: `7 / 2 = 3`, `-7 / 2 = -3`.
- **Знак остачі — як у діленого**, знак дільника не впливає: `-7 % 2 = -1`, `7 % -2 = 1`. Завжди виконується тотожність `(a / b) * b + a % b == a`.
- **`%` працює і для дробових чисел**: `5.5 % 2 = 1.5`.
- **`double wrong = sum / count`** дає 4, а не 4,5: ділення виконалося в `int`, і лише результат перетворено на `double`. Тип виразу визначають операнди, а не змінна зліва (та сама пастка, що з переповненням у лекції 06). Достатньо перетворити один операнд: `(double)sum / count`.
- **`+` з рядком склеює.** Вираз обчислюється зліва направо: `"1" + 2` — уже рядок `"12"`, до нього додається `"3"`. А `1 + 2` — спочатку число 3, і лише потім склеювання з `"3"`.
- **Оператора степеня немає.** `^` — побітове виключне АБО (розділ про бітові оператори), тому `2 ^ 3` дорівнює 1. Степінь — `Math.Pow(2, 3)` (повертає `double`), а степінь двійки для цілих — зсув `1 << n`.

Ділення цілого на нуль кидає `DivideByZeroException`, а дробового — дає нескінченність (лекція 06). Ще один особливий випадок — `int.MinValue / -1`: результат 2 147 483 648 не влазить в `int`, і операція кидає виняток навіть без `checked`:

::terminal-preview{title="dotnet run min-div.cs"}
```text
Unhandled exception. System.OverflowException: Arithmetic operation resulted in an overflow.
```

### Інкремент і декремент

`++` і `--` змінюють змінну на 1 і самі є виразами, які мають значення. Префіксна форма (`++i`) спочатку змінює змінну, а потім дає нове значення; постфіксна (`i++`) дає старе значення, а змінну змінює після цього:

```csharp [increment.cs]
int i = 5;
int post = i++;   // спочатку значення 5, потім i стає 6
Console.WriteLine($"post = {post}, i = {i}");

int j = 5;
int pre = ++j;    // спочатку j стає 6, потім значення 6
Console.WriteLine($"pre = {pre}, j = {j}");

int k = 5;
int r = k++ + ++k;   // 5 (k стає 6) + 7 (k стає 7)
Console.WriteLine($"k++ + ++k = {r}, k = {k}");

int m = 1;
m = m++;             // значення виразу m++ — 1, і воно записується назад у m
Console.WriteLine($"m = m++  ->  m = {m}");
```

::terminal-preview{title="dotnet run increment.cs"}
```text
post = 5, i = 6
pre = 6, j = 6
k++ + ++k = 12, k = 7
m = m++  ->  m = 1
```

У C++ вираз `k++ + ++k` змінює одну змінну двічі без точки послідовності, і результат не визначений. У C# він визначений: операнди обчислюються зліва направо, кожен — повністю, разом із побічним ефектом. `m = m++` теж визначений і нічого не змінює: `m++` повертає 1 і збільшує `m` до 2, а присвоєння записує повернуте 1 назад.

::callout{icon="i-lucide-lightbulb"}
**Як використовувати ++ і --**

- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **Окремим оператором**: `count++;`, `i--;` — тут префіксна і постфіксна форми однакові.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **У заголовку циклу** `for (int i = 0; i < n; i++)`.
- :icon{name="i-lucide-circle-x" class="inline-block text-red-500"} **Не змінюйте змінну кілька разів в одному виразі**: `k++ + ++k` компілюється і має визначений результат, але читач мусить відтворювати порядок обчислення в голові.

- `b = a++ * 2`: значення `a++` — 10, `b = 20`, `a` стає 11.

## Порівняння і логічні оператори

### Оператори порівняння

Оператор порівняння приймає два значення і повертає `bool`: `true`, якщо співвідношення виконується, і `false` — якщо ні. Цей `bool` стає умовою в `if` і циклах або зберігається в змінну:

```csharp [compare.cs]
int a = 3, b = 5;
Console.WriteLine($"a == b: {a == b}");
Console.WriteLine($"a != b: {a != b}");
Console.WriteLine($"a <  b: {a < b}");
Console.WriteLine($"a >  b: {a > b}");
Console.WriteLine($"a <= 3: {a <= 3}");
Console.WriteLine($"a >= 4: {a >= 4}");
Console.WriteLine();

bool less = a < b;   // результат порівняння можна зберегти в змінну
Console.WriteLine($"less = {less}");

char c = 'k';
Console.WriteLine($"'k' < 'z': {c < 'z'} (коди {(int)c} і {(int)'z'})");

string s1 = "кіт";
string s2 = "кі" + "т";
Console.WriteLine($"s1 == s2: {s1 == s2}");

double sum = 0.1 + 0.2;
Console.WriteLine($"0.1 + 0.2 == 0.3: {sum == 0.3}");
```

::terminal-preview{title="dotnet run compare.cs"}
```text

a != b: True
a <  b: True
a >  b: False
a <= 3: True
a >= 4: False

less = True
'k' < 'z': True (коди 107 і 122)

0.1 + 0.2 == 0.3: False
```

::

::field-group

::field{name="a == b, a != b" type="рівність, нерівність"}
Працюють для всіх вбудованих типів. Для `string` порівнюють вміст, а не посилання (лекція 05).
::

::field{name="a < b, a > b" type="менше, більше"}
Лише для числових типів і `char`. `char` порівнюється за кодом символу: `'k'` (107) менше за `'z'` (122).
::

::field{name="a <= b, a >= b" type="не більше, не менше"}
Те саме, включно з рівністю. Знак `=` завжди другий: `=<` і `=>` не є операторами порівняння.
::

::

Що відрізняється від C++:

- **Рядки не порівнюються через `<` і `>`.** `"apple" < "banana"` не компілюється (CS0019 «Operator '<' cannot be applied to operands of type 'string' and 'string'»). Порядок рядків визначає `string.Compare` з урахуванням мови і регістру (лекція 12).
- **Ланцюжок `1 < x < 10` не компілюється.** `1 < x` дає `bool`, а порівнювати `bool` з числом не можна (CS0019 «Operator '<' cannot be applied to operands of type 'bool' and 'int'»). У C++ `bool` перетворюється на 0 або 1, і вираз тихо дає неправильний результат. Правильно: `1 < x && x < 10` або шаблон `x is > 1 and < 10` (лекція 09).
- **Дробові числа порівнюють з допуском.** `0.1 + 0.2 == 0.3` — `False`, бо обидва значення записані в `double` наближено (лекція 06).

### Логічні оператори

Логічні оператори працюють лише з `bool`:

::field-group

::field{name="!x" type="логічне НЕ"}
`true`, якщо `x` хибне.
::

::field{name="a && b" type="логічне І, скорочене"}
Якщо `a` хибне, результат `false`, і `b` **не обчислюється**.
::

::field{name="a || b" type="логічне АБО, скорочене"}
Якщо `a` істинне, результат `true`, і `b` **не обчислюється**.
::

::field{name="a & b, a | b" type="І та АБО без скорочення"}
Для `bool` дають той самий результат, але обчислюють обидва операнди завжди.
::

::field{name="a ^ b" type="виключне АБО"}
`true`, якщо рівно один з операндів істинний.
::

::

Різницю видно, якщо правий операнд щось робить — тут друкує повідомлення:

```csharp [logical.cs]
Console.WriteLine("false && Check(1):");
bool r1 = false && Check(1);
Console.WriteLine("false & Check(2):");
bool r2 = false & Check(2);
Console.WriteLine("true || Check(3):");
bool r3 = true || Check(3);
Console.WriteLine("true | Check(4):");
bool r4 = true | Check(4);
Console.WriteLine($"результати: {r1} {r2} {r3} {r4}");
Console.WriteLine($"true ^ true = {true ^ true}, true ^ false = {true ^ false}");

string? name = null;
bool ok = name != null && name.Length > 0;   // без && тут був би NullReferenceException
Console.WriteLine($"ім'я задане: {ok}");

static bool Check(int id)
{
    Console.WriteLine($"  Check({id}) викликано");
    return true;
}
```

::terminal-preview{title="dotnet run logical.cs"}
```text
false && Check(1):
false & Check(2):
  Check(2) викликано
true || Check(3):
true | Check(4):
  Check(4) викликано
результати: False False True True
true ^ true = False, true ^ false = True
ім'я задане: False
```
::

Скорочене обчислення (*short-circuit evaluation*) — не лише оптимізація. На ньому побудовані перевірки, де права частина має сенс лише тоді, коли ліва пройшла: `name != null && name.Length > 0` не звертається до `Length`, якщо `name` дорівнює `null`.

На відміну від C++, число не перетворюється на `bool`, тому звична для C++ перевірка біта в умові не компілюється:

::terminal-preview{title="dotnet build errors/if-int.cs: if (x & 1)"}
```text
if-int.cs(2,5): error CS0029: Cannot implicitly convert type 'int' to 'bool'
```
::

Правильно: `if ((x & 1) != 0)`.

::callout{icon="i-lucide-lightbulb"}
**Які логічні оператори обирати**

- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`&&` і `||`** — завжди для умов: швидше і безпечніше.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **Перевірка, потім звернення**: `x != null && x.Length > 0`, `count > 0 && sum / count > 10`.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`^`** — «рівно одна з двох умов».
- :icon{name="i-lucide-circle-x" class="inline-block text-red-500"} **Не покладайтеся на `&` і `|`, щоб «точно викликати» метод у правій частині**: виклик, потрібний сам по собі, пишуть окремим рядком.

::

::::accordion

:::accordion-item{label="Спробуйте: які виклики відбудуться" icon="i-lucide-clipboard-list"}

1. Метод `Log` друкує своє ім'я і повертає задане значення. Не запускаючи, запишіть, які літери надрукує програма і які значення матимуть `r1`–`r4`:

```csharp [short-circuit.cs]
bool r1 = Log("A", false) && Log("B", true);
bool r2 = Log("C", true) || Log("D", false);
bool r3 = Log("E", false) | Log("F", true);
bool r4 = Log("G", true) && Log("H", false) || Log("I", true);
Console.WriteLine($"{r1} {r2} {r3} {r4}");

static bool Log(string name, bool value)
{
    Console.Write(name + " ");
    return value;
}
```

2. Запустіть і перевірте.

:::

:::accordion-item{label="Розв'язок" icon="i-lucide-check-circle"}

::terminal-preview{title="dotnet run short-circuit.cs"}
```text
A C E F G H I False True True True
```
::

- `A` хибне — `&&` не викликає `B`.
- `C` істинне — `||` не викликає `D`.
- `|` викликає обидва: `E` і `F`.
- `&&` має вищий пріоритет за `||`, тому `r4` — це `(G && H) || I`. `G` істинне, тому викликається `H`; `H` хибне, тому ліва частина `||` хибна і викликається `I`.

### Скорочене обчислення в IL

Як `&&` пропускає правий операнд, видно в IL. Три методи з `il-logic.cs`:

```csharp [il-logic.cs (фрагмент)]
static bool BothSimple(bool a, bool b) => a && b;
static bool BothShort(bool a) => a && IsReady();
static bool BothFull(bool a) => a & IsReady();
```

::terminal-preview{title="ilspycmd -il (Release, тіла трьох методів)"}
```text
BothSimple:
IL_0000: ldarg.0
IL_0001: ldarg.1
IL_0002: and
IL_0003: ret

BothShort:
IL_0000: ldarg.0
IL_0001: brfalse.s IL_0009
IL_0003: call bool Program::'<<Main>$>g__IsReady|0_3'()
IL_0008: ret
IL_0009: ldc.i4.0
IL_000a: ret

BothFull:
IL_0000: ldarg.0
IL_0001: call bool Program::'<<Main>$>g__IsReady|0_3'()
IL_0006: and
IL_0007: ret
```
::

- **`BothShort`**: `brfalse.s` перевіряє `a` і, якщо воно хибне, переходить одразу на `ldc.i4.0` — повернення `false`. Виклик `IsReady` опиняється в гілці, яку перехід оминає. Скорочене обчислення — це звичайний умовний перехід.
- **`BothFull`**: `IsReady` викликається завжди, а результати поєднує інструкція `and`.
- **`BothSimple`**: компілятор замінив `&&` на `and` без переходу. Правий операнд — просто параметр, його читання нічого не змінює і не може кинути виняток, тому пропускати його немає сенсу, а код без переходу виконується швидше. Програма поводиться так само, як написано: оптимізація не змінює видимого результату.

## Бітові оператори

### Побітові І, АБО, XOR і НЕ

Для цілих чисел `&`, `|`, `^` і `~` працюють з кожним бітом окремо:

```csharp [bitwise.cs]
byte a = 0b1100_1010;   // 202
byte b = 0b1010_0110;   // 166

Console.WriteLine($"a      = {a:B8}  {a,4}");
Console.WriteLine($"b      = {b:B8}  {b,4}");
Console.WriteLine($"a & b  = {a & b:B8}  {a & b,4}");
Console.WriteLine($"a | b  = {a | b:B8}  {a | b,4}");
Console.WriteLine($"a ^ b  = {a ^ b:B8}  {a ^ b,4}");
Console.WriteLine($"~a     = {(byte)~a:B8}  {(byte)~a,4}");
Console.WriteLine();
Console.WriteLine($"~a без приведення: {~a} (тип {(~a).GetType().Name})");
Console.WriteLine($"a ^ b ^ b = {a ^ b ^ b}");
```

::terminal-preview{title="dotnet run bitwise.cs"}
```text

b      = 10100110   166
a & b  = 10000010   130
a | b  = 11101110   238
a ^ b  = 01101100   108
~a     = 00110101    53

~a без приведення: -203 (тип Int32)
a ^ b ^ b = 202
```
::

![Бітові операції по стовпчиках для a = 202 і b = 166: a & b = 130 (1, якщо обидва біти 1), a | b = 238 (1, якщо хоч один 1), a ^ b = 108 (1, якщо біти різні), ~a = 53 (інверсія кожного біта)](/images/csharp/fundamentals/operators/02-bitwise-columns.png){.diagram-img}

- Кожен стовпчик обчислюється незалежно від інших: перенесень між розрядами, як у додаванні, немає.
- `byte` в арифметиці стає `int` (лекція 04), тому `~a` інвертує всі 32 біти і дає −203. Щоб отримати 8-бітний результат, потрібне приведення `(byte)~a`.
- `a ^ b ^ b` повертає `a`: XOR з тим самим значенням двічі скасовує себе. На цьому побудовані прості шифри (так Obfuscar ховав рядки в лекції 03) і контрольні суми.

### Зсуви

`x << n` зсуває біти вліво на `n` позицій і заповнює звільнені праві розряди нулями — це множення на 2ⁿ. `x >> n` зсуває вправо, і для зсуву вправо важливо, чим заповнюються ліві розряди:

```csharp [shifts.cs]
int x = 13;
Console.WriteLine($"13 << 2   = {x << 2}");
Console.WriteLine($"13 >> 2   = {x >> 2}");

int neg = -16;
Console.WriteLine($"-16       = {neg:B32}");
Console.WriteLine($"-16 >> 2  = {neg >> 2:B32}  {neg >> 2}");
Console.WriteLine($"-16 >>> 2 = {neg >>> 2:B32}  {neg >>> 2}");

uint u = 0xF000_0000;
Console.WriteLine($"uint 0xF0000000 >> 4 = 0x{u >> 4:X8}");

int one = 1;
int shift = 33;
Console.WriteLine($"1 << 33 (int)  = {one << shift}");
Console.WriteLine($"1L << 33 (long) = {1L << shift}");
```

::terminal-preview{title="dotnet run shifts.cs"}
```text

13 >> 2   = 3
-16       = 11111111111111111111111111110000
-16 >> 2  = 11111111111111111111111111111100  -4
-16 >>> 2 = 00111111111111111111111111111100  1073741820
uint 0xF0000000 >> 4 = 0x0F000000
1 << 33 (int)  = 2
1L << 33 (long) = 8589934592
```
::

![Зсув −16 вправо на 2 у 32 бітах: >> заповнює два нові ліві біти знаковим бітом (1) і дає −4, >>> заповнює їх нулями і дає 1073741820; два молодші біти зникають](/images/csharp/fundamentals/operators/03-shifts.png){.wide-img}

- **`>>` для знакових типів — арифметичний зсув**: ліві розряди заповнюються знаковим бітом, тому від'ємне число лишається від'ємним, а `-16 >> 2` = −4 — ділення на 4.
- **`>>` для беззнакових типів — логічний**: ліві розряди заповнюються нулями.
- **`>>>`** (з C# 11) — логічний зсув і для знакових типів: −16 стає великим додатним числом. Раніше для цього число доводилося приводити до `uint`.
- **Кількість зсуву маскується**: для `int` береться лише 5 молодших бітів (`n & 31`), для `long` — 6 (`n & 63`). Тому `1 << 33` для `int` — це `1 << 1` = 2. У C++ зсув на кількість, не меншу за розрядність, — невизначена поведінка, у C# результат визначений, але навряд чи той, на який розраховували.

Бітові оператори використовують для прапорців (набору «так / ні» в одному числі), масок, бінарних форматів файлів і мережевих протоколів, хеш-функцій. Замінювати ними множення й ділення «для швидкості» не потрібно: JIT сам перетворює `x * 4` на зсув, де це вигідно.

### Біти на практиці: прапорці і BitOperations

Кілька логічних ознак зручно зберігати в одному числі — по біту на ознаку. Так задані права доступу до файлів, налаштування в API операційних систем, стани в мережевих протоколах. Чотири операції над прапорцями:

```csharp [flags.cs]
using System.Numerics;

const int Read = 1 << 0;      // 001
const int Write = 1 << 1;     // 010
const int Execute = 1 << 2;   // 100

int access = 0;
access |= Read | Write;               // встановити два біти
Console.WriteLine($"після |= Read | Write  {access:B3}");
access &= ~Write;                     // скинути біт Write
Console.WriteLine($"після &= ~Write        {access:B3}");
access ^= Execute;                    // перемкнути біт Execute
Console.WriteLine($"після ^= Execute       {access:B3}");
Console.WriteLine($"є Read?    {(access & Read) != 0}");
Console.WriteLine($"є Write?   {(access & Write) != 0}");
Console.WriteLine();

uint value = 0b1100_1010;
Console.WriteLine($"PopCount({value})          = {BitOperations.PopCount(value)}");
Console.WriteLine($"LeadingZeroCount({value})  = {BitOperations.LeadingZeroCount(value)}");
Console.WriteLine($"TrailingZeroCount({value}) = {BitOperations.TrailingZeroCount(value)}");
Console.WriteLine($"IsPow2(64) = {BitOperations.IsPow2(64)}, IsPow2(65) = {BitOperations.IsPow2(65)}");
Console.WriteLine($"RotateLeft(0x80000001, 1) = 0x{BitOperations.RotateLeft(0x8000_0001u, 1):X8}");
```

::terminal-preview{title="dotnet run flags.cs"}
```text
після |= Read | Write  011
після &= ~Write        001
після ^= Execute       101
є Read?    True
є Write?   False

PopCount(202)          = 4
LeadingZeroCount(202)  = 24
TrailingZeroCount(202) = 1
IsPow2(64) = True, IsPow2(65) = False
RotateLeft(0x80000001, 1) = 0x00000003
```
::

| Дія | Запис |
|---|---|
| встановити біт | `flags \|= Mask` |
| скинути біт | `flags &= ~Mask` |
| перемкнути біт | `flags ^= Mask` |
| перевірити біт | `(flags & Mask) != 0` |

Клас `System.Numerics.BitOperations` дає операції, для яких у процесорів є окремі інструкції: `PopCount` рахує одиничні біти, `LeadingZeroCount` і `TrailingZeroCount` — нулі зліва й справа, `IsPow2` перевіряє степінь двійки, `RotateLeft` і `RotateRight` — циклічний зсув, у якому біт, що виходить з одного краю, повертається з іншого. У C# для прапорців зазвичай оголошують перелічення з атрибутом `[Flags]` — його розглядає модуль про типи.

## Присвоєння

### Просте і складене присвоєння

`змінна = вираз;` спочатку обчислює вираз праворуч, потім записує його значення у змінну ліворуч. Ліворуч може стояти лише те, що зберігає значення: змінна, елемент масиву, властивість. Літерал чи вираз туди не підходить:

::terminal-preview{title="dotnet build errors/assign-literal.cs: 5 = x;"}
```text
assign-literal.cs(2,1): error CS0131: The left-hand side of an assignment must be a variable, property or indexer
```
::

Коли нове значення змінної обчислюється зі старого (`total = total + 5`), ту саму змінну доводиться писати двічі. Складений оператор (*compound assignment*) записує це коротше:

| Запис | Рівнозначно | Приклад для `x = 12` |
|---|---|---|
| `x = y` | — | `x = 3` — 3 |
| `x += y` | `x = x + y` | `x += 3` — 15 |
| `x -= y` | `x = x - y` | `x -= 3` — 9 |
| `x *= y` | `x = x * y` | `x *= 3` — 36 |
| `x /= y` | `x = x / y` | `x /= 5` — 2 |
| `x %= y` | `x = x % y` | `x %= 5` — 2 |
| `x &= y`, `x \|= y`, `x ^= y` | `x = x & y` і т. д. | `x \|= 1` — 13 |
| `x <<= y`, `x >>= y`, `x >>>= y` | `x = x << y` і т. д. | `x <<= 1` — 24 |
| `x ??= y` | `x = x ?? y` | присвоює, лише якщо `x` дорівнює `null` (лекція 05) |

Присвоєння в C#, як і в C++, — вираз: його значення — присвоєне значення. Тому присвоєння можна ланцюжити, і обчислюється ланцюжок справа наліво:

```csharp [compound.cs]
int a, b, c;
a = b = c = 5;
Console.WriteLine($"a = {a}, b = {b}, c = {c}");

int total = 10;
total += 5;
total *= 2;
total -= 3;
total /= 4;
total %= 4;
Console.WriteLine($"total = {total}");

byte level = 250;
level += 5;          // компілюється: це (byte)(level + 5)
Console.WriteLine($"level += 5   -> {level}");
level += 10;         // 255 + 10 = 265 не влазить у byte: лишаються молодші 8 біт
Console.WriteLine($"level += 10  -> {level}");

int flags = 0b0001;
```

## Пріоритет, асоціативність і порядок обчислення

### Пріоритет і асоціативність

**Пріоритет** (*precedence*) визначає, як оператори групуються, коли дужок немає: у `2 + 3 * 4` множення групується першим. **Асоціативність** визначає групування операторів одного рівня: `10 - 4 - 3` — це `(10 - 4) - 3`. Більшість бінарних операторів лівоасоціативні; присвоєння, `??` і `?:` — правоасоціативні: `a = b = 5` — це `a = (b = 5)`.

![Пріоритет операторів C# від вищого до нижчого: первинні, унарні, мультиплікативні, адитивні, зсуви, відношення і перевірка типу, рівність, &, ^, |, &&, ||, ??, ?:, присвоєння; останні три групи правоасоціативні](/images/csharp/fundamentals/operators/04-precedence.png){.diagram-img}

```csharp [precedence.cs]
Console.WriteLine($"2 + 3 * 4      = {2 + 3 * 4}");
Console.WriteLine($"(2 + 3) * 4    = {(2 + 3) * 4}");
Console.WriteLine($"10 - 4 - 3     = {10 - 4 - 3}");
Console.WriteLine($"2 * 3 % 4      = {2 * 3 % 4}");
Console.WriteLine($"1 + 2 << 1     = {1 + 2 << 1}");
Console.WriteLine($"5 > 3 == true  = {5 > 3 == true}");
Console.WriteLine($"6 & 3 | 8      = {(6 & 3 | 8)}");

int x = 6;
bool isEven = (x & 1) == 0;
Console.WriteLine($"(x & 1) == 0   = {isEven}");
```

::terminal-preview{title="dotnet run precedence.cs"}
```text

(2 + 3) * 4    = 20
10 - 4 - 3     = 3
2 * 3 % 4      = 2
1 + 2 << 1     = 6
5 > 3 == true  = True
6 & 3 | 8      = 10
(x & 1) == 0   = True
```
::

- `*`, `/` і `%` мають однаковий пріоритет і групуються зліва направо: `2 * 3 % 4` = `6 % 4` = 2.
- Зсуви мають нижчий пріоритет за додавання: `1 + 2 << 1` = `3 << 1` = 6. Звідси правило: вирази зі зсувами беруть у дужки.
- Порівняння `>` вище за рівність `==`: `5 > 3 == true` = `(5 > 3) == true`.

Найчастіша пастка, перенесена з C, — перевірка біта без дужок. `==` має вищий пріоритет за `&`, тому `x & 1 == 0` групується як `x & (1 == 0)`. У C++ це компілюється (`1 == 0` стає нулем), у C# — ні, бо `int & bool` не має сенсу:

::terminal-preview{title="dotnet build errors/and-equals.cs: bool even = x & 1 == 0;"}
```text
and-equals.cs(2,13): error CS0019: Operator '&' cannot be applied to operands of type 'int' and 'bool'
```
::

### Порядок обчислення операндів

Пріоритет визначає, як вираз **групується**, але не те, у якому порядку **обчислюються** операнди. У C# правило просте: операнди обчислюються **зліва направо**, кожен повністю, а лише потім виконується оператор.

```csharp [eval-order.cs]
int result = F(1) + F(2) * F(3);
Console.WriteLine($"F(1) + F(2) * F(3) = {result}");

int[] data = [10, 20, 30];
int i = 0;
data[i] = i = 2;      // індекс обчислено першим (0), потім i = 2, потім data[0] = 2
Console.WriteLine($"data = [{string.Join(", ", data)}], i = {i}");

static int F(int n)
{
    Console.WriteLine($"  обчислюю F({n})");
    return n;
}
```

::terminal-preview{title="dotnet run eval-order.cs"}
```text
  обчислюю F(1)
  обчислюю F(2)
  обчислюю F(3)
F(1) + F(2) * F(3) = 7
data = [2, 20, 30], i = 2
```
::

Множення групується першим, але `F(1)` викликається раніше за `F(2)` і `F(3)`. У виразі `data[i] = i = 2` індекс `data[i]` обчислюється до присвоєння `i = 2`, тому змінюється `data[0]`. У C++ порядок обчислення операндів здебільшого не визначений, і такі вирази поводяться по-різному в різних компіляторах. C# закріпив порядок у специфікації, щоб результат програми не залежав від компілятора.

![Дерево розбору a + b * c > d && !done: внизу — вищий пріоритет (*), вгорі — нижчий (&&); операнди a, b, c, d, done обчислюються в порядку 1–5 зліва направо; значення вузлів для a = 1, b = 2, c = 3, d = 5, done = false](/images/csharp/fundamentals/operators/05-expression-tree.png){.diagram-img}

**Дужки і читабельність**

- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **Дужки навколо бітових операцій і зсувів**: `(flags & Mask) != 0`, `(a + b) << 1`.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **Дужки, коли поєднуються `&&` і `||`**: `(a && b) || c` читається однозначно, навіть якщо пріоритет і так дає це групування.
- :icon{name="i-lucide-circle-x" class="inline-block text-red-500"} **Не будуйте вирази, результат яких залежить від порядку обчислення**: `data[i] = i = 2` має визначений результат, але кожен читач перевірятиме його вручну.

## Питання для самоперевірки

::::accordion

:::accordion-item{label="Чому -7 / 2 дає -3, а -7 % 2 дає -1?" icon="i-lucide-help-circle"}

Ціле ділення в C# відкидає дробову частину в бік нуля: −3,5 стає −3. Остача має знак діленого і узгоджена з діленням так, щоб `(a / b) * b + a % b == a`: (−3) · 2 + (−1) = −7. Звідси пастка перевірки непарності `n % 2 == 1`, яка не спрацьовує для від'ємних чисел.

:::

:::accordion-item{label="Чому double avg = sum / count дає ціле число для int sum і count?" icon="i-lucide-help-circle"}

Тип виразу визначають операнди: обидва `int`, тому ділення цілочисельне, і дробова частина зникає ще до присвоєння. Перетворення на `double` застосовується вже до цілого результату. Виправлення — перетворити хоча б один операнд: `(double)sum / count`.

:::

:::accordion-item{label="Чим відрізняються i++ і ++i?" icon="i-lucide-help-circle"}

Обидва збільшують змінну на 1, але значення виразу різне: `i++` повертає старе значення, `++i` — нове. Окремим оператором (`i++;`) вони рівнозначні. Різниця має значення лише тоді, коли результат використовується в іншому виразі.

:::

:::accordion-item{label="Чим a && b відрізняється від a & b для bool?" icon="i-lucide-help-circle"}

Результат однаковий, але `&&` не обчислює `b`, якщо `a` хибне, а `&` обчислює обидва операнди завжди. Це важливо, коли правий операнд має побічний ефект або може кинути виняток: `name != null && name.Length > 0` безпечне, а з `&` дало б `NullReferenceException`.

:::

:::accordion-item{label="Чому if (x & 1) не компілюється в C#, а в C++ працює?" icon="i-lucide-help-circle"}

`x & 1` — вираз типу `int`, а умова в C# має бути `bool`. Неявного перетворення числа на `bool` у C# немає, тому компілятор видає CS0029. Правильно: `if ((x & 1) != 0)`.

:::

:::accordion-item{label="Чим >> відрізняється від >>>?" icon="i-lucide-help-circle"}

Для знакових типів `>>` — арифметичний зсув: ліві розряди заповнюються знаковим бітом, і від'ємне число лишається від'ємним (−16 >> 2 = −4). `>>>` — логічний зсув: ліві розряди заповнюються нулями (−16 >>> 2 = 1073741820). Для беззнакових типів обидва оператори дають однаковий результат.

:::

:::accordion-item{label="Чому byte level += 5 компілюється, а level = level + 5 — ні?" icon="i-lucide-help-circle"}

`level + 5` має тип `int`, і неявно звузити його до `byte` компілятор не дає. Складений оператор `+=` за специфікацією містить приховане приведення до типу змінної: `level += 5` — це `level = (byte)(level + 5)`. Тому він компілюється, але й так само мовчки відкидає старші біти при переповненні.

:::

:::accordion-item{label="Чому x & 1 == 0 не компілюється?" icon="i-lucide-help-circle"}

`==` має вищий пріоритет за `&`, тому вираз групується як `x & (1 == 0)` — `int & bool`, і такого оператора немає (CS0019). У C++ це компілюється і тихо дає неправильний результат. Правильно: `(x & 1) == 0`.

:::

:::accordion-item{label="Пріоритет і порядок обчислення — це одне й те саме?" icon="i-lucide-help-circle"}

Ні. Пріоритет визначає групування: у `F(1) + F(2) * F(3)` множення виконується над `F(2)` і `F(3)`. Порядок обчислення визначає, коли обчислюються операнди: у C# завжди зліва направо, тому `F(1)` викликається першим. У C++ порядок обчислення операндів здебільшого не визначений.

:::

## Шпаргалка

| Запис | Що робить | Приклад |
|---|---|---|
| `a / b` для цілих | ціле ділення, в бік нуля | `-7 / 2` = −3 |
| `a % b` | остача зі знаком діленого | `-7 % 2` = −1 |
| `(double)a / b` | дробове ділення двох цілих | `(double)7 / 2` = 3.5 |
| `Math.Pow(x, y)` | степінь (`double`) | `^` — не степінь, а XOR |
| `i++` / `++i` | старе / нове значення, змінна +1 | `k++ + ++k` = 12 для `k = 5` |
| `&&`, `\|\|` | логічні І / АБО зі скороченим обчисленням | `s != null && s.Length > 0` |
| `&`, `\|`, `^` для `bool` | без скорочення / виключне АБО | `true ^ true` = false |
| `&`, `\|`, `^`, `~` для цілих | побітові операції | `(x & 1) != 0` — непарне |
| `<<`, `>>`, `>>>` | зсуви: вліво, арифметичний, логічний вправо | `-16 >>> 2` = 1073741820 |
| `x op= y` | `x = (T)(x op y)` | `byte b += 5` компілюється |
| `a = b = 5` | присвоєння — вираз, справа наліво | |
| пріоритет | `*` вище `+`, `+` вище `<<`, `<<` вище `<`, `==` вище `&`, `&&` вище `\|\|` | дужки для бітових операцій |
| порядок обчислення | операнди — зліва направо | `F(1) + F(2) * F(3)` викликає 1, 2, 3 |

   - чим `-17 / 5` відрізняється від `Math.Floor(-17 / 5.0)` і коли потрібне саме округлення вниз (наприклад, номер тижня для від'ємного зміщення днів).

Додайте скріншот таблиці.

:::

```text
  17    5       3       2                    17   (3, 2)
  17   -5      -3       2                    17   (-3, 2)

 -17   -5       3      -2                   -17   (3, -2)
```

- Знак частки — «мінус», якщо знаки операндів різні; знак остачі — завжди як у діленого.
- Остачу визначено так, щоб тотожність виконувалася: ділення відкидає дробову частину в бік нуля, а остача «добирає» решту.
- `-17 / 5` = −3 (в бік нуля), `Math.Floor(-17 / 5.0)` = −4 (вниз). Для календарних обчислень з від'ємним зміщенням потрібне саме округлення вниз, інакше дні −1…−6 потраплять у той самий тиждень, що й 0…6.
- `Math.DivRem` повертає частку й остачу разом, а запис `(int q, int r) = …` розкладає їх у дві змінні (кортежі — лекція 15).

:::accordion-item{label="Завдання 3. Права доступу rwx" icon="i-lucide-clipboard-list"}

1. У Linux і macOS права на файл записують трьома бітами: r (читання) = 4, w (запис) = 2, x (виконання) = 1. Напишіть програму, яка для кожного числа від 0 до 7 друкує його двійковий запис і рядок прав, наприклад `5 = 101 -> r-x`. Кожен біт перевіряйте через `&`.
2. Права `754` — це три такі групи для власника, групи й інших. Запишіть це число двійковим літералом (`0b111_101_100`) і виділіть кожну групу зсувом і маскою `& 7`.
3. Перевірте на своїй машині: у macOS чи Linux виконайте `ls -l` у будь-якій папці; у Windows — `wsl ls -l`, якщо встановлено WSL. Знайдіть файл з правами `rw-r--r--` і запишіть відповідне число.
4. Письмово: чому для групи власника потрібен зсув на 6, а для групи — на 3?

:::

:::accordion-item{label="Розв'язок завдання 3" icon="i-lucide-check-circle"}

```csharp [rwx.cs]
for (int mode = 0; mode <= 7; mode++)
{
    char r = (mode & 0b100) != 0 ? 'r' : '-';
    char w = (mode & 0b010) != 0 ? 'w' : '-';
    char x = (mode & 0b001) != 0 ? 'x' : '-';
    Console.WriteLine($"{mode} = {mode:B3} -> {r}{w}{x}");
}

int chmod = 0b111_101_100;   // 754 у вісімковій: власник rwx, група r-x, інші r--
Console.WriteLine($"754: власник {(chmod >> 6) & 7}, група {(chmod >> 3) & 7}, інші {chmod & 7}");
```

::terminal-preview{title="dotnet run rwx.cs"}
```text
0 = 000 -> ---
1 = 001 -> --x
2 = 010 -> -w-
3 = 011 -> -wx
4 = 100 -> r--
5 = 101 -> r-x
6 = 110 -> rw-
7 = 111 -> rwx
754: власник 7, група 5, інші 4
```
::

- Кожна група займає три біти: інші — біти 0–2, група — 3–5, власник — 6–8. Зсув на 6 переносить біти власника в позиції 0–2, а `& 7` (`0b111`) відкидає все, що вище.
- `rw-r--r--` — це 6, 4, 4, тобто права 644: так зазвичай виглядають звичайні файли.
- Вісімкових літералів у C# немає (лекція 04), тому права записано двійковим літералом з роздільниками по три біти.

```csharp [trace.cs]
int result = T("a", 2) + T("b", 3) * T("c", 4) - T("d", 5) / T("e", 1);
Console.WriteLine();

bool flag = T("f", 0) > 1 && T("g", 2) > 1 || T("h", 3) > 1;

static int T(string name, int value)
{
    Console.Write($"{name}={value} ");
    return value;
}
```

- Другий вираз групується як `((f > 1) && (g > 1)) || (h > 1)`. `f > 1` хибне, тому `&&` не викликає `g`; ліва частина `||` хибна, тому викликається `h`.
