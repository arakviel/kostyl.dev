## Що в C# інакше, ніж у C++

Синтаксис `if`, `else`, `?:` і `switch` у C# такий самий, як у C++. Кожен розділ лекції починається з будови конструкції і всіх форм її запису, а потім переходить до відмінностей — правил, які перевіряє компілятор:

- **умова — лише `bool`**: `if (x = 5)`, `if (count)` чи `if (ptr)` не компілюються;
- **у `switch` немає провалювання** (*fall-through*): кожна секція завершується явно, інакше — помилка компіляції;
- **`switch` працює з рядками** і з будь-яким типом, для якого можна записати шаблон;
- **є switch expression** — `switch`, який повертає значення;
- **є шаблони** (*patterns*): `x is >= 0 and < 10`, `s is null`, `(a, b) switch { (0, 0) => … }`;
- **`?:` бере тип зі змінної зліва**, якщо гілки не зводяться до спільного типу самі.

## if і else

### Будова if

Оператор `if` виконує інструкцію лише тоді, коли умова істинна. Необов'язкова частина `else` задає інструкцію, яка виконується, коли умова хибна:

![Анатомія if / else: ключове слово if, умова в круглих дужках типу bool, блок гілки «так» у фігурних дужках, необов'язковий else і блок гілки «ні»](/images/csharp/fundamentals/branching-and-switch/01-if-anatomy.png){.diagram-img}

- **Умова** — будь-який вираз типу `bool`: порівняння, логічна змінна, виклик методу, що повертає `bool`, комбінація через `&&`, `||` і `!` (лекція 08). Круглі дужки навколо умови — частина синтаксису, без них код не компілюється.
- **Гілка** — одна інструкція або блок у фігурних дужках. Блок `{ … }` об'єднує кілька інструкцій в одну і задає область видимості: змінна, оголошена всередині гілки, існує лише в ній (лекція 04).
- **Виконується рівно одна гілка** або жодна, якщо `else` немає. Після цього програма продовжується з інструкції, що стоїть після всього `if`.

### Усі форми запису if

Одна програма, в якій зібрано всі форми `if`:

```csharp [if-forms.cs]
int temperature = 18;
bool raining = true;

// 1. if без else: гілка виконується або пропускається
if (temperature < 0)
{
    Console.WriteLine("1: мороз");
}

// 2. if з else: виконується рівно одна з двох гілок
if (raining)
{
    Console.WriteLine("2: беріть парасольку");
}
else
{
    Console.WriteLine("2: парасолька не потрібна");
}

// 3. ланцюжок else if: перша гілка з істинною умовою
if (temperature < 0)
{
    Console.WriteLine("3: мороз");
}
else if (temperature < 15)
{
    Console.WriteLine("3: холодно");
}
else
{
    Console.WriteLine("3: тепло");
}

// 4. вкладений if: друга умова перевіряється лише всередині першої гілки
if (temperature > 10)
{
    if (raining)
    {
        Console.WriteLine("4: тепло, але дощ");
    }
    else
    {
        Console.WriteLine("4: тепло і сухо");
    }
}

// 5. одна інструкція без фігурних дужок
if (temperature > 15)
    Console.WriteLine("5: можна без куртки");

// 6. складена умова з логічних операторів
if (temperature > 10 && !raining || temperature > 25)
{
    Console.WriteLine("6: гарна погода для прогулянки");
}
else
{
    Console.WriteLine("6: краще лишитися вдома");
}
```

::terminal-preview{title="dotnet run if-forms.cs"}
```text
2: беріть парасольку
3: тепло
4: тепло, але дощ
5: можна без куртки
6: краще лишитися вдома
```
::

::field-group

::field{name="if (умова) { … }" type="без else"}
Гілка виконується, якщо умова істинна, інакше пропускається. Рядка з номером 1 у виводі немає: 18 не менше за 0.
::

::field{name="if (умова) { … } else { … }" type="дві гілки"}
Виконується рівно одна з двох гілок.
::

::field{name="if … else if … else" type="ланцюжок"}
Умови перевіряються згори вниз, виконується перша гілка з істинною умовою. Завершальний `else` спрацьовує, якщо не підійшла жодна.
::

::field{name="if усередині гілки" type="вкладений if"}
Внутрішня умова перевіряється лише тоді, коли виконується зовнішня гілка.
::

::field{name="if (умова) інструкція;" type="без фігурних дужок"}
Гілка з однієї інструкції може обходитися без блоку. Друга інструкція з тим самим відступом до гілки вже не належить.
::

::field{name="if (a && !b || c)" type="складена умова"}
Умова збирається з логічних операторів за правилами пріоритету лекції 08: тут `(a && !b) || c`. Для 18° з дощем обидві частини хибні, тому виконується `else`.

### Висячий else і зайва крапка з комою

Дві пастки, які C# успадкував від C++. Перша — висячий `else` (*dangling else*): `else` завжди належить найближчому `if` без власного `else`, а відступи на це не впливають:

```csharp [dangling-else.cs]
int a = 5, b = -1;
if (a > 0)
    if (b > 0)
        Console.WriteLine("обидва додатні");
else
    Console.WriteLine("a не додатне?");
```

::terminal-preview{title="dotnet run dangling-else.cs"}
```text
a не додатне?
```
::

За відступами `else` належить до `if (a > 0)`, але компілятор прив'язує його до `if (b > 0)`. `a` додатне, `b` — ні, тому друкується повідомлення, яке за змістом хибне. Попередження компілятор не видає. Фігурні дужки навколо гілок прибирають двозначність.

Друга — крапка з комою одразу після умови. `;` — порожня інструкція, і саме вона стає гілкою `if`, а блок у фігурних дужках виконується завжди:

```csharp [errors/empty-if.cs]
int x = -5;
if (x > 0);
{
    Console.WriteLine("додатне");
}
```

::terminal-preview{title="dotnet run errors/empty-if.cs"}
```text
empty-if.cs(2,11): warning CS0642: Possible mistaken empty statement
додатне
```
::

Тут компілятор попереджає (CS0642), але програма компілюється і друкує «додатне» для −5.

::::accordion

:::accordion-item{label="Спробуйте: прив'язати else до зовнішнього if" icon="i-lucide-clipboard-list"}

1. Візьміть код з `dangling-else.cs` і розставте фігурні дужки так, щоб `else` належав до `if (a > 0)`, як підказують відступи.
2. Замість друку записуйте повідомлення в змінну `message` з початковим значенням `"нічого не надруковано"` і друкуйте її після `if`.
3. Перевірте на парах `(5, -1)`, `(5, 3)`, `(-2, -1)`. Для якої пари не виконується жодна гілка і чому?

:::

:::accordion-item{label="Розв'язок" icon="i-lucide-check-circle"}

```csharp [dangling-fix.cs]
(int a, int b)[] pairs = [(5, -1), (5, 3), (-2, -1)];
foreach (var (a, b) in pairs)
{
    string message = "нічого не надруковано";
    if (a > 0)
    {
        if (b > 0)
            message = "обидва додатні";
    }
    else
        message = "a не додатне";
    Console.WriteLine($"a = {a,2}, b = {b,2}: {message}");
}
```

::terminal-preview{title="dotnet run dangling-fix.cs"}
```text
a =  5, b = -1: нічого не надруковано
a =  5, b =  3: обидва додатні
a = -2, b = -1: a не додатне
```
::

Блок `{ … }` закриває внутрішній `if`, тому `else` після блоку належить зовнішньому. Для `(5, -1)` зовнішня умова істинна, внутрішня — хибна, а `else` у внутрішнього `if` тепер немає: не виконується нічого. Масив пар і `var (a, b)` — кортежі (лекція 15).

:::

### Ланцюжок else if

Ланцюжок `else if` перевіряє умови згори вниз і виконує першу гілку, умова якої істинна. Решта умов після неї не обчислюються:

```csharp [if-else.cs (перша частина)]
int[] scores = [95, 74, 60, 12];
foreach (int score in scores)
{
    string grade;
    if (score >= 90)
        grade = "відмінно";
    else if (score >= 75)
        grade = "добре";
    else if (score >= 60)
        grade = "задовільно";
    else
        grade = "незадовільно";
    Console.WriteLine($"{score,3}: {grade}");
}
```

::terminal-preview{title="dotnet run if-else.cs (перша частина виводу)"}
```text
 95: відмінно
 74: задовільно
 60: задовільно
 12: незадовільно
```
::

![Ланцюжок if / else if / else для score = 74: умови score >= 90 і score >= 75 хибні, score >= 60 істинна, тому grade = задовільно; else не перевіряється](/images/csharp/fundamentals/branching-and-switch/02-if-chain.png){.diagram-img}

- **`else if` — це звичайний `if` усередині `else`**, окремого ключового слова немає. Тому порядок умов важливий: перевіряти треба від найсуворішої (`>= 90`) до найслабшої (`>= 60`). Якби першою стояла `score >= 60`, усі оцінки від 60 і вище стали б «задовільно».
- **`string grade;` без початкового значення** — компілятор перевіряє, що кожна гілка присвоює `grade`. Якби `else` не було, рядок `Console.WriteLine` не скомпілювався б: змінна могла б лишитися неприсвоєною (лекція 04).

Умова в C# має тип `bool`, тому звична помилка C++ — присвоєння замість порівняння — не компілюється:

::terminal-preview{title="dotnet build errors/if-assign.cs: if (x = 5)"}
```text
if-assign.cs(2,5): error CS0029: Cannot implicitly convert type 'int' to 'bool'
```
::

Виняток — змінна типу `bool`: `if (done = true)` компілюється, бо результат присвоєння теж `bool`. Компілятор лише попереджає, а гілка виконується завжди:

::terminal-preview{title="dotnet build errors/if-assign-bool.cs: if (done = true)"}
```text
if-assign-bool.cs(2,5): warning CS0665: Assignment in conditional expression is always constant; did you mean to use == instead of = ?
```
::

Для `bool` порівняння `== true` зайве: пишуть `if (done)` і `if (!done)`.

### Guard clause і змінні з умови

Коли перевірок кілька і кожна може завершити роботу, вкладені `if` замінюють ранніми `return` — guard clause («сторожовими» перевірками). Кожна перевірка відсікає один поганий випадок, і основна логіка лишається на верхньому рівні:

```csharp [if-else.cs (друга частина)]
string[] inputs = ["42", "abc", "-5"];
foreach (string input in inputs)
{
    Console.WriteLine($"{input}: {Describe(input)}");
}

static string Describe(string text)
{
    if (!int.TryParse(text, out int value))
        return "не число";
    if (value < 0)
        return "від'ємне число";
    // value оголошено в умові першого if, але воно видиме й тут
    return $"число {value}, квадрат {value * value}";
}
```

::terminal-preview{title="dotnet run if-else.cs (друга частина виводу)"}
```text
42: число 42, квадрат 1764
abc: не число
-5: від'ємне число
```
::

Змінна `value` оголошена прямо в умові (`out int value`, лекція 06), а використовується після `if`. У C# змінна, оголошена у виразі умови `if`, належить блоку, у якому стоїть сам `if`, а не лише його гілці. Компілятор дозволяє читати її там, де вона точно присвоєна: після `if (!int.TryParse(...)) return …;` до наступного рядка доходить лише та програма, у якої розбір вдався. Так само працюють змінні з шаблонів (`if (obj is int n)`), про які далі.

::callout{icon="i-lucide-lightbulb"}
**Як писати if**

- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **Guard clause замість вкладеності**: спочатку відсічіть некоректні випадки ранніми `return`, потім пишіть основну логіку.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **Ланцюжок `else if` — від найсуворішої умови до найслабшої**, і завершальний `else` для решти.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **Фігурні дужки, якщо гілка довша за один рядок** або якщо поруч вкладені `if`.
- :icon{name="i-lucide-circle-x" class="inline-block text-red-500"} **Не порівнюйте `bool` з `true` чи `false`**: `if (done)`, а не `if (done == true)`.

::

```csharp [guard.cs]
string[] inputs = ["17", "abc", "-3", "130", "45"];
foreach (string input in inputs)
{
    Console.WriteLine($"{input,4}: {Check(input)}");
}

static string Check(string text)
{
    if (!int.TryParse(text, out int age))
        return "не число";
    if (age < 0 || age > 120)
        return "неможливий вік";
    if (age < 18)
        return $"неповнолітній, до 18 лишилось {18 - age}";
    return $"повнолітній, {age} років";
}
```

```text

```
::

`else` не потрібен: якщо `if` спрацював, `return` завершив метод, і наступна перевірка виконується лише для решти випадків. `age` оголошено в першій умові, а використовується в наступних.

## Умовний оператор ?:

### Будова умовного оператора

Умовний оператор (*conditional operator*) — єдиний оператор C# з трьома операндами, тому його ще називають тернарним. `умова ? a : b` — вираз: він має значення `a`, якщо умова істинна, і `b` — якщо хибна. Обчислюється лише одна з гілок.

![Анатомія ?: — string text = t < 0 ? "мороз" : "не мороз"; умова t < 0 типу bool, знак ? після умови, значення для true, двокрапка, значення для false; результат присвоюється змінній](/images/csharp/fundamentals/branching-and-switch/03-ternary-anatomy.png){.diagram-img}

На відміну від `if`, `?:` не виконує інструкції, а дає значення. Тому він стоїть там, де очікується значення:

```csharp [ternary-forms.cs]
int count = 1;
string word = count == 1 ? "файл" : "файли";
Console.WriteLine(word);
Console.WriteLine(count > 0 ? "є файли" : "порожньо");
Console.WriteLine($"знайдено {count} {(count == 1 ? "файл" : "файли")}");
Console.WriteLine(Sign(-7));

static string Sign(int n)
{
    return n < 0 ? "мінус" : "плюс";
}
```

::terminal-preview{title="dotnet run ternary-forms.cs"}
```text
файл
є файли
знайдено 1 файл
мінус
```
::

::field{name="T x = умова ? a : b;" type="присвоєння"}

::

::field{name="Method(умова ? a : b)" type="аргумент методу"}

::

::field{name="return умова ? a : b;" type="результат методу"}
Метод повертає одне з двох значень без `if` і двох `return`.
::

::field{name="{(умова ? a : b)}" type="в інтерполяції"}
Усередині `{}` інтерполяції `?:` береться в дужки, бо двокрапка інакше починає формат ([лекція 07](/csharp/fundamentals/console-io#фігурні-дужки-й-умовний-вираз-в-інтерполяції)).
::

::field{name="a ? x : b ? y : z" type="ланцюжок"}
`?:` правоасоціативний: це `a ? x : (b ? y : z)`. Працює, але три і більше варіантів читаються краще у switch expression.
::

### Тип результату

Обидві гілки мають дати значення одного типу, бо в результату `?:` тип лише один. Що стається, коли типи гілок різні:

```csharp [ternary.cs]
int n = 7;
string parity = n % 2 == 0 ? "парне" : "непарне";
Console.WriteLine($"{n} — {parity}");

int a = 3, b = 8;
int max = a > b ? a : b;
Console.WriteLine($"max = {max}");

double ratio = n > 5 ? 1 : 0.5;   // int і double: тип результату double
Console.WriteLine($"ratio = {ratio} ({ratio.GetType().Name})");

int? maybe = n > 5 ? n : null;    // target-typed: тип бере зі змінної зліва
Console.WriteLine($"maybe = {maybe}");

object any = n > 5 ? n : "мало";  // теж target-typed: int і string зводяться до object
Console.WriteLine($"any = {any} ({any.GetType().Name})");

int t = 25;
string weather = t < 0 ? "мороз" : t < 15 ? "холодно" : t < 25 ? "тепло" : "спека";
Console.WriteLine($"{t}° — {weather}");
```

::terminal-preview{title="dotnet run ternary.cs"}
```text
7 — непарне
max = 8
ratio = 1 (Double)
maybe = 7
any = 7 (Int32)
25° — спека
```
::

Правила такі:

- **Якщо одна гілка неявно перетворюється в тип іншої**, результат має тип ширшої: `1` і `0.5` дають `double`, тому `ratio` — це `1` типу `Double`.
- **Якщо спільного типу немає, тип береться з місця призначення** (*target-typed conditional*, з C# 9): `int? maybe = … ? n : null` компілюється, бо і `int`, і `null` перетворюються в `int?`. `object any = … ? n : "мало"` — так само, через `object`.
- **Якщо місця призначення немає** (`var`, аргумент без певного типу), компілятор не має звідки взяти тип:

::terminal-preview{title='dotnet build errors/ternary-types.cs: var result = n > 5 ? n : "мало";'}
```text
ternary-types.cs(2,14): error CS0173: Type of conditional expression cannot be determined because there is no implicit conversion between 'int' and 'string'
```
::

Останній рядок `ternary.cs` — ланцюжок: `t < 0 ? "мороз" : t < 15 ? "холодно" : …` групується як `t < 0 ? "мороз" : (t < 15 ? "холодно" : (…))` (правоасоціативність, лекція 08). Той самий вибір switch expression записує таблицею, без вкладення.

::callout{icon="i-lucide-lightbulb"}
**Коли ?:, а коли if**

- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`?:` — вибір одного з двох значень**: `max = a > b ? a : b`, текст для виводу, значення за замовчуванням.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`if` — коли гілки виконують дії**, а не повертають значення.
- :icon{name="i-lucide-circle-x" class="inline-block text-red-500"} **Не вкладайте `?:` один в одного**: три і більше варіантів записуйте через switch expression.

::

## switch statement

### Будова switch

`switch` вибирає одну з кількох гілок за значенням одного виразу. Вираз обчислюється один раз, його значення порівнюється з мітками, і виконання переходить у секцію з міткою, що збіглася:

![Анатомія switch statement: ключове слово switch, вираз у дужках, мітки case 6 і case 7 з двокрапкою ведуть в одну секцію, секція з інструкціями завершується break, default — для решти значень, остання секція теж закінчується break](/images/csharp/fundamentals/branching-and-switch/04-switch-anatomy.png){.diagram-img}

- **Вираз** у круглих дужках після `switch` — значення, за яким іде вибір: число, `char`, `string`, `bool`, перелічення або значення будь-якого типу, якщо мітки записані шаблонами (наступні розділи).
- **Мітка** — `case`, константа того самого типу і двокрапка. Константа має бути відома під час компіляції: літерал або `const`.
- **Секція** — інструкції після однієї чи кількох міток. Секція закінчується явно, найчастіше `break`.
- **`default:`** — мітка для всіх значень, яких немає серед `case`. Вона необов'язкова: без неї для такого значення не виконується нічого.

Ланцюжок `if (day == 6 || day == 7) … else …` робить те саме, але повторює `day` у кожній умові. `switch` записує вибір за одним значенням як таблицю.

### Усі форми секцій

```csharp [switch-forms.cs]
int[] codes = [1, 2, 3, 4, 5, 9];
foreach (int code in codes)
{
    Console.Write($"{code}: ");
    switch (code)
    {
        case 1:
            Console.WriteLine("один");
            break;
        case 2:
        case 3:
            Console.WriteLine("два або три");
            break;
        case 4:
        {
            int square = code * code;
            Console.WriteLine($"чотири, квадрат {square}");
            break;
        }
        case 5:
            Console.Write("п'ять -> ");
            goto case 1;
        default:
            Console.WriteLine("інше");
            break;
    }
}
Console.WriteLine(DayName(3));

static string DayName(int day)
{
    switch (day)
    {
        case 1: return "понеділок";
        case 2: return "вівторок";
        case 3: return "середа";
        default: return "інший день";
    }
}
```

::terminal-preview{title="dotnet run switch-forms.cs"}
```text

2: два або три
3: два або три
4: чотири, квадрат 16
5: п'ять -> один
9: інше
середа
```
::

::field-group

::field{name="case 1: … break;" type="одна мітка"}
Основна форма: мітка, інструкції секції і `break`.
::

::field{name="case 2: case 3: …" type="кілька міток"}
Мітки підряд без інструкцій між ними ведуть в одну секцію.
::

::field{name="case 4: { … }" type="секція з блоком"}
Фігурні дужки дають секції власну область видимості для змінних, як `square`.
::

::field{name="case 5: … goto case 1;" type="перехід в іншу секцію"}
Після своїх інструкцій секція продовжується секцією `case 1`. Звідси вивід «п'ять -> один».
::

::field{name="default: … break;" type="усі інші значення"}
Значення 9 не збіглося з жодною міткою.
::

::field{name="case 1: return …;" type="секція з return"}
Секція завершує метод, тому `break` не потрібен. Коротку секцію пишуть в один рядок з міткою.
::

::

### Числа і рядки в мітках

Мітками бувають константи будь-якого з цих типів. Два приклади — дні тижня (числа) і команди (рядки):

```csharp [switch-statement.cs]
for (int day = 1; day <= 8; day++)
{
    switch (day)
    {
        case 1:
        case 2:
        case 3:
        case 4:
        case 5:
            Console.WriteLine($"{day}: робочий день");
            break;
        case 6:
        case 7:
            Console.WriteLine($"{day}: вихідний");
            break;
        default:
            Console.WriteLine($"{day}: такого дня немає");
            break;
    }
}
Console.WriteLine();

string[] commands = ["start", "restart", "STOP", "help"];
foreach (string command in commands)
{
    Console.Write($"{command}: ");
    switch (command)
    {
        case "restart":
            Console.Write("зупиняю... ");
            goto case "start";
        case "start":
            Console.WriteLine("запускаю");
            break;
        case "stop":
            Console.WriteLine("зупиняю");
            break;
        default:
            Console.WriteLine("невідома команда");
            break;
    }
}
```

::terminal-preview{title="dotnet run switch-statement.cs"}
```text
1: робочий день
2: робочий день
3: робочий день
4: робочий день
5: робочий день
6: вихідний
7: вихідний
8: такого дня немає

start: запускаю
restart: зупиняю... запускаю
STOP: невідома команда
help: невідома команда
```
::

- **`default`** виконується, якщо не підійшла жодна мітка. Його можна поставити будь-де, але за домовленістю він останній.
- **Рядки порівнюються з урахуванням регістру**: `"STOP"` не дорівнює `"stop"`, тому потрапляє в `default`. Без урахування регістру порівнюють `command.ToLowerInvariant()` (лекція 12).
- **Дві однакові мітки** — помилка CS0152 («The switch statement contains multiple cases with the label value '1'»).

### Без провалювання

У C++ секція без `break` продовжується наступною. У C# це помилка компіляції: кожна секція, у якій є інструкції, мусить явно передати керування кудись іще.

![switch у C++ і C#: у C++ case 1 без break провалюється в case 2 і друкує обидва дні; у C# той самий код — помилка CS0163; секцію завершують break, return, goto case або кілька міток на одну секцію](/images/csharp/fundamentals/branching-and-switch/05-no-fallthrough.png){.wide-img}

::terminal-preview{title="dotnet build errors/fallthrough.cs"}
```text
fallthrough.cs(4,5): error CS0163: Control cannot fall through from one case label ('case 1:') to another
```
::

Правило поширюється і на останню секцію: `default` без `break` теж не компілюється (CS8070 «Control cannot fall out of switch from final case label ('default:')»). Секцію завершують:

::field-group

::field{name="break;" type="вихід зі switch"}
Найчастіший варіант. Виконання продовжується після `switch`.
::

::field{name="return …;" type="вихід з методу"}
Зручно, коли кожна секція обчислює результат методу.
::

::field{name="goto case мітка;" type="явний перехід"}
Перехід в іншу секцію, як `restart` → `start` у прикладі. Те, що в C++ робить провалювання, у C# записано явно. `goto default;` переходить у `default`.
::

::field{name="throw …;" type="виняток"}
Секція завершується винятком (модуль 3).
::

::

Порожня мітка, за якою одразу йде інша мітка (`case 1: case 2:`), — не провалювання: це одна секція з кількома мітками.

Навіщо така суворість: забутий `break` — одна з найчастіших помилок у C і C++, і випадкове провалювання виглядає так само, як навмисне. У C# навмисний перехід завжди видно в коді (`goto case`), а випадковий не компілюється.

### Область видимості в секціях

Усі секції `switch` — один блок. Змінна, оголошена в одній секції, видима в інших, тому однакові імена конфліктують:

::terminal-preview{title="dotnet build errors/case-scope.cs: string text у двох секціях"}

## switch expression

### Вибір значення

Більшість `switch` у реальному коді не виконують дій, а вибирають значення: назву дня, ціну, текст повідомлення. Для цього в C# 8 з'явився switch expression — `switch`, який сам є виразом:

```csharp [switch-expression.cs]
for (int day = 1; day <= 8; day++)
{
    string kind = day switch
    {
        1 or 2 or 3 or 4 or 5 => "робочий день",
        6 or 7 => "вихідний",
        _ => "такого дня немає",
    };
    Console.WriteLine($"{day}: {kind}");
}
Console.WriteLine();

string[] commands = ["start", "stop", "STOP", "help"];
foreach (string command in commands)
{
    Console.WriteLine($"{command}: {Reply(command)}");
}

static string Reply(string command) => command.ToLowerInvariant() switch
{
    "start" => "запускаю",
    "stop" => "зупиняю",
    _ => "невідома команда",
};
```

::terminal-preview{title="dotnet run switch-expression.cs"}
```text
1: робочий день
2: робочий день
3: робочий день
4: робочий день
5: робочий день
6: вихідний
7: вихідний
8: такого дня немає

start: запускаю
stop: зупиняю
STOP: зупиняю
help: невідома команда
```
::

Ті самі вісім рядків, що в `switch` statement, займають п'ять, і в них немає `break`, `case` і повторного присвоєння `kind`.

![Анатомія switch expression: вхідний вираз t, ключове слово switch після нього, гілки з шаблоном, стрілкою => і результатом, кома після кожної гілки, _ для решти значень і крапка з комою після закритої дужки](/images/csharp/fundamentals/branching-and-switch/06-switch-expression-anatomy.png){.diagram-img}

- **Вираз пишеться перед `switch`**, а не в дужках після нього: `day switch { … }`.
- **Гілка** (*arm*) — `шаблон => результат`. Гілки розділяються комами; кома після останньої гілки дозволена і зручна, коли гілки додають.
- **`_`** (*discard*) підходить до будь-якого значення: це аналог `default`.
- **Результати всіх гілок зводяться до одного типу**, як дві гілки `?:`.
- **Після `}` стоїть `;`**, бо весь `switch` — частина оператора присвоєння. Метод `Reply` записаний через `=>` (*expression-bodied*): його тіло — один вираз (методи — лекція 14).
- **`1 or 2 or 3`** — логічний шаблон, про нього в наступному розділі.

Гілки перевіряються згори вниз, і результат дає перша, шаблон якої підійшов:

  <source src="/videos/csharp/fundamentals/branching-and-switch/anim-01-first-match.webm" type="video/webm">

Тому гілку, яку вже повністю перекривають попередні, компілятор вважає помилкою. Якщо поставити `_` першим, жодна наступна гілка не виконається:

::terminal-preview{title="dotnet build errors/unreachable-arm.cs: _ перед < 0"}

### Повнота перевірки

Switch expression мусить повернути значення для будь-якого входу. Якщо компілятор знаходить значення, яке не підходить до жодної гілки, він попереджає і наводить приклад такого значення. Під час роботи програми таке значення кидає виняток:

```csharp [non-exhaustive.cs]
int[] values = [1, 2, 3];
foreach (int v in values)
{
    string name = v switch
    {
        1 => "один",
        2 => "два",
    };
    Console.WriteLine(name);
}
```

::terminal-preview{title="dotnet run non-exhaustive.cs"}
```text
non-exhaustive.cs(5,21): warning CS8509: The switch expression does not handle all possible values of its input type (it is not exhaustive). For example, the pattern '0' is not covered.
один
два
Unhandled exception. System.Runtime.CompilerServices.SwitchExpressionException: Non-exhaustive switch expression failed to match its input.
Unmatched value was 3.
```
::

`_` наприкінці не обов'язковий, якщо гілки вже покривають усі значення. Компілятор аналізує шаблони, а не лише їх кількість:

```csharp [exhaustive.cs]
int[] values = [-3, 0, 8];
foreach (int v in values)
{
    string sign = v switch
    {
        < 0 => "від'ємне",
        0 => "нуль",
        > 0 => "додатне",
    };
    Console.WriteLine($"{v}: {sign}");
}

bool ready = true;
string state = ready switch
{
    true => "готово",
    false => "ще ні",
};
Console.WriteLine(state);
```

Для `int` шаблони `< 0`, `0` і `> 0` покривають усі значення, для `bool` — `true` і `false`. А ті самі три шаблони для `double` вже неповні: у `double` є значення `NaN` («не число», результат `0.0 / 0`), яке не менше, не більше і не дорівнює жодному числу. Компілятор знає це і називає його:


Попередження CS8509 варто сприймати як помилку: воно означає, що програма може впасти з `SwitchExpressionException`. Виправлення — додати гілку для пропущеного значення або `_`.

::callout{icon="i-lucide-lightbulb"}
**switch statement чи switch expression**

- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **switch expression — коли кожна гілка дає значення**: назва, ціна, текст, результат методу.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **switch statement — коли гілки виконують дії**: друк, кілька інструкцій, зміна кількох змінних.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **Ланцюжок `if` — коли умови перевіряють різні змінні** і не зводяться до шаблонів одного значення.
- :icon{name="i-lucide-circle-x" class="inline-block text-red-500"} **Не ігноруйте CS8509**: неповний switch expression кидає виняток на першому непокритому значенні.

## Шаблони

### Що таке шаблон

Шаблон (*pattern*) — перевірка того, чи підходить значення під певну форму: дорівнює константі, лежить у діапазоні, не є `null`. Шаблони записуються в трьох місцях: у гілках switch expression, у мітках `case` і після оператора `is`:

```csharp [patterns-is.cs]
char[] chars = ['q', 'Q', '7', ' ', 'ї'];
foreach (char c in chars)
{
    bool latin = c is >= 'a' and <= 'z' or >= 'A' and <= 'Z';
    bool digit = c is >= '0' and <= '9';
    bool notSpace = c is not ' ';
    Console.WriteLine($"'{c}': латинська {latin,-5}  цифра {digit,-5}  не пробіл {notSpace}");
}
Console.WriteLine();

int code = 404;
Console.WriteLine($"{code} is 404: {code is 404}");
Console.WriteLine($"{code} is >= 400 and < 500: {code is >= 400 and < 500}");
Console.WriteLine($"{code} is 200 or 201 or 204: {code is 200 or 201 or 204}");

string? name = null;
Console.WriteLine($"name is null: {name is null}, name is not null: {name is not null}");
name = "Олена";
Console.WriteLine($"name is null: {name is null}, name is not null: {name is not null}");
```

::terminal-preview{title="dotnet run patterns-is.cs"}
```text
'q': латинська True   цифра False  не пробіл True
'Q': латинська True   цифра False  не пробіл True
'7': латинська False  цифра True   не пробіл True
' ': латинська False  цифра False  не пробіл False
'ї': латинська False  цифра False  не пробіл True

404 is 404: True
404 is >= 400 and < 500: True
404 is 200 or 201 or 204: False
name is null: True, name is not null: False
name is null: False, name is not null: True
```
::

`x is шаблон` — вираз типу `bool`. Значення `x` обчислюється один раз, а шаблон перевіряє його кілька разів: `c is >= 'a' and <= 'z'` коротше за `c >= 'a' && c <= 'z'` і не повторює `c`. Види шаблонів:

::field-group

::field{name="константний" type="5, 'a', null, рядок у лапках"}
Значення дорівнює константі.
::

::field{name="відношення" type="< 0, >= 'a', <= 100"}
Порівняння з константою: `<`, `<=`, `>`, `>=` (з C# 9).
::

::field{name="логічні" type="and, or, not, (…)"}
Поєднання шаблонів. Пріоритет: `not`, потім `and`, потім `or`; дужки змінюють порядок.
::

::field{name="discard" type="_"}
Підходить до будь-якого значення.
::

::field{name="var" type="var x"}
Підходить до будь-якого значення і записує його в нову змінну `x`.
::

::field{name="кортежний" type="(0, _), (> 0, < 0)"}
Перевіряє кілька значень одночасно, кожне — своїм шаблоном.
::

::

`is null` і `is not null` — стандартний спосіб перевірки на `null`. На відміну від `== null`, їх не можна змінити перевантаженням оператора `==` у власному класі (перевантаження операторів — модуль ООП), тому вони завжди перевіряють саме посилання.

### Обмеження і пастки

**Справа в шаблоні — лише константа.** Шаблон перевіряється компілятором, тому змінна там не допускається:

::terminal-preview{title="dotnet build errors/relational-var.cs: amount is > limit"}
```text
relational-var.cs(3,25): error CS9135: A constant value of type 'int' is expected
```
::

Для порівняння зі змінною пишуть звичайне `amount > limit` або `when` (наступний підрозділ).

**`not` стосується лише найближчого шаблону.** `code is not 1 or 2` читається як «не 1 і не 2», але групується як `(not 1) or 2` — і це істинно для будь-якого значення, крім 1. Компілятор .NET 10 помічає такі шаблони:

::terminal-preview{title="dotnet build errors/is-not-or.cs: code is not 1 or 2"}
```text
is-not-or.cs(2,29): warning CS9336: The pattern is redundant.
```
::

Правильно: `code is not (1 or 2)`.

### Діапазони

Шаблони відношення в switch expression записують діапазони без повторення змінної. Оскільки гілки перевіряються згори вниз, кожна наступна гілка отримує лише ті значення, які не забрали попередні:

```csharp [relational.cs]
double[] temps = [-12, 0, 7.5, 18, 24.9, 25, 33];
foreach (double t in temps)
{
    string kind = t switch
    {
        < 0 => "мороз",
        < 10 => "холодно",
        >= 10 and < 25 => "тепло",
        >= 25 => "спека",
        _ => "немає даних",
    };
    Console.WriteLine($"{t,6}°: {kind}");
}
Console.WriteLine($"{double.NaN,6}°: {Classify(double.NaN)}");

static string Classify(double t) => t switch
{
    < 0 => "мороз",
    < 10 => "холодно",
    >= 10 and < 25 => "тепло",
    >= 25 => "спека",
    _ => "немає даних",
};
```

::terminal-preview{title="dotnet run relational.cs"}
```text

     0°: холодно
   7.5°: холодно
    18°: тепло
  24.9°: тепло
    25°: спека
    33°: спека
   NaN°: немає даних
```

- `< 10` стоїть після `< 0`, тому фактично охоплює лише проміжок від 0 до 10. Від'ємні значення сюди не доходять.
- `>= 10 and < 25` можна було б записати як `< 25`: нижню межу вже відсікли попередні гілки. Повна форма довша, але не залежить від порядку гілок.
- Межі: 0 — уже «холодно», 25 — уже «спека». Для меж вибирають `<` чи `<=` так само уважно, як в `if`.

### when

Шаблон перевіряє значення лише проти констант. Коли потрібна умова зі змінною чи обчисленням, до гілки додають `when`:

```csharp [when.cs]
int limit = 100;
int[] amounts = [-5, 0, 42, 100, 250];
foreach (int amount in amounts)
{
    string verdict = amount switch
    {
        < 0 => "помилка: від'ємна сума",
        0 => "нічого не списано",
        _ when amount > limit => $"перевищено ліміт {limit}",
        var x when x % 2 == 0 => $"парна сума {x}",
        _ => $"сума {amount}",
    };
    Console.WriteLine($"{amount,4}: {verdict}");
}
```

::terminal-preview{title="dotnet run when.cs"}
```text
  -5: помилка: від'ємна сума
   0: нічого не списано
  42: парна сума 42
 100: парна сума 100
 250: перевищено ліміт 100
```
::

- Гілка спрацьовує, якщо підійшов шаблон **і** умова після `when` істинна. Інакше перевірка йде до наступної гілки.
- `_ when amount > limit` — шаблон підходить до будь-якого значення, а відбір робить `when` зі змінною `limit`.
- `var x when x % 2 == 0` — `var x` записує значення в нову змінну, яку можна використати і в `when`, і в результаті гілки.
- Компілятор не аналізує умови `when`, тому гілки з `when` не роблять switch повним: остання гілка `_` потрібна.

Шаблони і `when` працюють і в мітках `switch` statement:

```csharp [case-patterns.cs]
int[] amounts = [-5, 0, 42, 7, 250];
foreach (int amount in amounts)
{
    switch (amount)
    {
        case < 0:
            Console.WriteLine($"{amount}: помилка");
            break;
        case 0:
            Console.WriteLine($"{amount}: нуль");
            break;
        case > 100:
            Console.WriteLine($"{amount}: велика сума");
            break;
        case var x when x % 2 == 0:
            Console.WriteLine($"{amount}: парна");
            break;
        default:
            Console.WriteLine($"{amount}: непарна");
            break;
    }
}
```

```text

0: нуль
42: парна
7: непарна
250: велика сума
```

### Кортежні шаблони

Коли результат залежить від кількох значень, їх беруть у дужки — `(a, b)` створює кортеж (*tuple*), набір значень без окремого типу (докладно — лекція 15). Кортежний шаблон перевіряє кожну позицію своїм шаблоном:

```csharp [tuple-patterns.cs]
for (int n = 1; n <= 15; n++)
{
    string text = (n % 3, n % 5) switch
    {
        (0, 0) => "FizzBuzz",
        (0, _) => "Fizz",
        (_, 0) => "Buzz",
        _ => n.ToString(),
    };
    Console.Write(text + " ");
}
Console.WriteLine();
Console.WriteLine();

(int x, int y)[] points = [(3, 4), (-2, 5), (0, 7), (0, 0), (6, -1)];
foreach (var (x, y) in points)
{
    string where = (x, y) switch
    {
        (0, 0) => "початок координат",
        (0, _) => "на осі Y",
        (_, 0) => "на осі X",
        (> 0, > 0) => "I чверть",
        (< 0, > 0) => "II чверть",
        (< 0, < 0) => "III чверть",
        (> 0, < 0) => "IV чверть",
    };
    Console.WriteLine($"({x,2}, {y,2}): {where}");
}
```

```text

(-2,  5): II чверть

( 0,  0): початок координат

```

![Кортежні шаблони на координатній площині: (> 0, > 0) — I чверть, (< 0, > 0) — II, (< 0, < 0) — III, (> 0, < 0) — IV, (_, 0) — вісь X, (0, _) — вісь Y, (0, 0) — початок; точки (3, 4), (−2, 5), (0, 7), (0, 0), (6, −1) з виводу](/images/csharp/fundamentals/branching-and-switch/08-quadrants.png){.diagram-img}

- **FizzBuzz**: замість ланцюжка `if` з комбінаціями `n % 3 == 0 && n % 5 == 0` — таблиця з чотирьох рядків. `(0, 0)` стоїть першим, бо `(0, _)` теж підходить до цього значення.
- **Чверті**: у другому switch немає `_`, і попередження CS8509 немає. Компілятор перевірив, що сім гілок покривають усі пари `int`: обидві координати нульові, одна нульова, обидві ненульові з чотирма комбінаціями знаків.
- `foreach (var (x, y) in points)` розкладає кожен кортеж масиву на дві змінні (лекція 15).

Інші види шаблонів — шаблон типу (`obj is int n`), шаблон властивостей (`s is { Length: > 5 }`) і шаблон списку (`arr is [1, .., 9]`) — розглядає лекція [Pattern Matching](/csharp/advanced-core/pattern-matching) модуля про розширені можливості мови: вони потрібні разом із класами.

### Як компілюється switch

Switch expression і `switch` statement описують, **що** вибрати. **Як** перевіряти значення, вирішує компілятор, і результат залежить від міток. Чотири методи з `switch-il.cs`, зібрані в Release:

```csharp [switch-il.cs (фрагменти)]
static string Dense(int day)
{
    switch (day)
    {
        case 1: return "пн";
        case 2: return "вт";
        // … до case 5
        default: return "?";
    }
}

static string Sparse(int code)   // мітки 1, 1000, 1000000

static int ByName(string command) // мітки "start", "stop", "pause", "resume", "status", "help", "exit"

static string Range(int score) => score switch
{
    < 0 => "помилка",
    < 60 => "F",
    < 75 => "C",
    < 90 => "B",
    <= 100 => "A",
    _ => "помилка",
};
```

**Щільні мітки — таблиця переходів.** Для `case 1`–`case 5` компілятор віднімає 1 і використовує інструкцію `switch`: вона бере адресу переходу з таблиці за індексом, без жодного порівняння:

## Питання для самоперевірки

::::accordion

:::accordion-item{label="Чому if (x = 5) не компілюється в C#, а if (done = true) компілюється?" icon="i-lucide-help-circle"}

Умова `if` має бути типу `bool`. `x = 5` для `int x` — вираз типу `int`, і неявного перетворення `int` у `bool` немає (CS0029). `done = true` для `bool done` — вираз типу `bool`, тому він компілюється, і компілятор лише попереджає (CS0665), що умова завжди істинна.

:::

:::accordion-item{label="Чому змінна з out int value в умові if доступна після цього if?" icon="i-lucide-help-circle"}

Змінні, оголошені у виразі умови `if` (через `out` або шаблон), належать блоку, у якому стоїть `if`. Компілятор дозволяє їх читати там, де вони точно присвоєні. Після `if (!int.TryParse(text, out int value)) return …;` виконання доходить лише при успішному розборі, тому `value` можна використовувати далі. На цьому побудований guard clause.

:::

:::accordion-item{label="Від чого залежить тип результату виразу ?:?" icon="i-lucide-help-circle"}

Якщо одна гілка неявно перетворюється в тип іншої, результат має тип ширшої (`int` і `double` — `double`). Якщо ні, тип береться з місця призначення: `int? r = … ? n : null` компілюється. Якщо місця призначення немає (`var`), а гілки несумісні, — помилка CS0173.

:::

:::accordion-item{label="Що таке провалювання в switch і як C# його замінює?" icon="i-lucide-help-circle"}

Провалювання — продовження виконання в наступній секції, якщо поточна не завершилась `break`. У C# воно заборонене (CS0163): кожна непорожня секція завершується `break`, `return`, `throw` або `goto case`. Кілька міток підряд без інструкцій між ними — не провалювання, а одна секція. Навмисний перехід записується явно через `goto case`.

:::

:::accordion-item{label="Чим switch expression відрізняється від switch statement?" icon="i-lucide-help-circle"}

Switch expression — вираз: кожна гілка дає значення, і весь `switch` можна присвоїти змінній чи повернути з методу. У ньому немає `case`, `break` і `default` — замість них `шаблон => результат` і `_`. Switch statement — інструкція, його секції виконують дії. Для вибору значення switch expression коротший і перевіряється на повноту.

:::

:::accordion-item{label="Чому для double гілок < 0, 0, > 0 недостатньо, а для int — достатньо?" icon="i-lucide-help-circle"}

`double` має значення `NaN`, яке не менше, не більше і не дорівнює нулю, тому не підходить до жодного з трьох шаблонів. Компілятор попереджає CS8509 і називає `double.NaN`. У `int` такого значення немає: кожне число або менше нуля, або нуль, або більше.

:::

:::accordion-item{label="Чому шаблон amount is > limit не компілюється і як записати таку перевірку?" icon="i-lucide-help-circle"}

У шаблоні відношення справа може стояти лише константа: компілятор аналізує шаблони під час компіляції (повнота, недосяжні гілки), а значення змінної на той момент невідоме (CS9135). Порівняння зі змінною записують звичайним `amount > limit` або в гілці `_ when amount > limit => …`.

:::

:::accordion-item{label="Що означає code is not 1 or 2?" icon="i-lucide-help-circle"}

`not` має вищий пріоритет за `or`, тому вираз групується як `(not 1) or 2`: істинно для будь-якого значення, крім 1. У .NET 10 компілятор попереджає CS9336 «The pattern is redundant». Перевірка «ні 1, ні 2» записується як `code is not (1 or 2)`.

:::

:::accordion-item{label="Чому порядок гілок у switch expression важливий?" icon="i-lucide-help-circle"}

Результат дає перша гілка, шаблон якої підійшов. Загальніший шаблон, поставлений вище за окремий, забирає його значення: `(0, _)` перед `(0, 0)` робить другу гілку недосяжною, і компілятор видає помилку CS8510. Тому гілки впорядковують від окремих випадків до загальних, а `_` ставлять останнім.

:::

## Шпаргалка

| Запис | Що робить | Приклад |
|---|---|---|
| `if / else if / else` | перша гілка з істинною умовою | `if (s >= 90) … else if (s >= 75) …` |
| guard clause | ранній `return` для поганих випадків | `if (!int.TryParse(t, out int v)) return "не число";` |
| `c ? a : b` | вибір одного з двох значень | `int max = a > b ? a : b;` |
| target-typed `?:` | тип зі змінної зліва | `int? r = ok ? n : null;` |
| `case 1: case 2:` | кілька міток на одну секцію | |
| `break`, `return`, `goto case` | завершення секції `switch` | без них — CS0163 |
| `x switch { … }` | switch expression | `day switch { 6 or 7 => "вихідний", _ => "робочий" }` |
| `_` | будь-яке значення (discard) | остання гілка |
| `x is 5`, `x is null` | константний шаблон | `s is not null` |
| `< 0`, `>= 'a'` | шаблон відношення, лише з константою | `t is >= 10 and < 25` |
| `and`, `or`, `not` | логічні шаблони; пріоритет `not` > `and` > `or` | `code is not (1 or 2)` |
| `when` | додаткова умова гілки | `_ when x > limit => …` |
| `var x` | будь-яке значення в нову змінну | `var x when x % 2 == 0 => …` |
| `(a, b) switch` | кортежний шаблон | `(0, _) => "Fizz"` |
| CS8509 | switch expression неповний | додати гілку або `_` |
| CS8510 | гілка недосяжна | переставити гілки |

::

Switch expression повторює таблицю тарифу: один рядок — одна клітинка. У вкладених `?:` ту саму відповідність треба відновлювати, розставляючи дужки в голові. До того ж для switch компілятор перевіряє повноту і недосяжні гілки, а для `?:` — ні. `_` у кінці не потрібен: `(_, false)` і `(_, true)` покривають решту значень, разом із `NaN`.

:::

:::accordion-item{label="Завдання 4. Дні в місяці і високосний рік" icon="i-lucide-clipboard-list"}

1. Напишіть метод `DaysIn(int month, bool leap)` як switch expression: лютий — 28 або 29 (через `?:`), квітень, червень, вересень, листопад — 30 (одна гілка з `or`), інші місяці 1–12 — 31; для неправильного номера — `throw new ArgumentOutOfRangeException(nameof(month))`.
2. Високосний рік: `year % 4 == 0 && year % 100 != 0 || year % 400 == 0`. Для років 2024, 2025, 1900, 2000 і **вашого року народження** надрукуйте, чи рік високосний, кількість днів у лютому за вашим методом і `DateTime.DaysInMonth(year, 2)`.
3. Надрукуйте кількість днів для всіх 12 місяців невисокосного року.
4. Письмово:
   - як групується формула високосного року без дужок (пріоритет `&&` і `||`, лекція 08);
   - чому 1900 — не високосний, а 2000 — високосний;
   - чому гілка з `throw` не порушує правило «кожна гілка повертає `int`».

:::

:::accordion-item{label="Розв'язок завдання 4" icon="i-lucide-check-circle"}

```csharp [days-in-month.cs]
int[] years = [2024, 2025, 1900, 2000];
foreach (int year in years)
{
    bool leap = year % 4 == 0 && year % 100 != 0 || year % 400 == 0;
    int february = DaysIn(2, leap);
    Console.WriteLine($"{year}: високосний {leap,-5}  лютий {february}  DateTime: {DateTime.DaysInMonth(year, 2)}");
}
Console.WriteLine();
for (int month = 1; month <= 12; month++)
{
    Console.Write($"{month}:{DaysIn(month, false)} ");
}
Console.WriteLine();

static int DaysIn(int month, bool leap) => month switch
{
    2 => leap ? 29 : 28,
    4 or 6 or 9 or 11 => 30,
    >= 1 and <= 12 => 31,
    _ => throw new ArgumentOutOfRangeException(nameof(month)),
};
```

- `&&` має вищий пріоритет за `||`, тому формула — `(year % 4 == 0 && year % 100 != 0) || year % 400 == 0`: рік ділиться на 4, але не на 100, або ділиться на 400.
- 1900 ділиться на 100, але не на 400 — не високосний. 2000 ділиться на 400 — високосний.
- `throw` у гілці — вираз, який не повертає значення, а завершує обчислення винятком, тому він сумісний з будь-яким типом результату. Гілка `>= 1 and <= 12` стоїть після окремих місяців і забирає решту правильних номерів.
