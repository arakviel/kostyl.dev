## Що в C# інакше, ніж у C++

Масив — це послідовність елементів одного типу, до яких звертаються за номером (індексом) від 0. Так само, як у C++. Кожен розділ лекції починається з будови і всіх форм запису, а потім переходить до відмінностей, головні з яких такі:

- **масив — завжди об'єкт у купі**: змінна `int[] a` містить посилання (лекція 05), масивів на стеку на зразок `int a[10];` немає;
- **дужки стоять після типу**: `int[] a`, а не `int a[]`, і розмір не входить у тип: `int[]` — масив будь-якої довжини;
- **масив знає свою довжину**: `a.Length` замість `sizeof(a) / sizeof(a[0])`, і в метод масив передається разом з нею;
- **елементи завжди ініціалізовані**: `new int[5]` — п'ять нулів, а не сміття з пам'яті;
- **кожен індекс перевіряється**: вихід за межі дає виняток `IndexOutOfRangeException`, а не читання чужої пам'яті;
- **багатовимірних масивів два види**: прямокутний `int[,]` (один блок) і рваний `int[][]` (масив масивів);
- **клас `Array`** дає готові `Sort`, `Reverse`, `IndexOf`, `BinarySearch`, `Fill`, `Resize`.

## Одновимірний масив

### Будова масиву

Оголошення масиву складається з типу елемента, порожніх квадратних дужок і імені. Сам масив створюється окремо — оператором `new` або виразом колекції:

![Анатомія масиву: тип елемента int, квадратні дужки після типу, змінна scores з посиланням, new int[5] створює масив з п'яти нулів у купі; другий рядок — вираз колекції [2, 3, 5, 7]; третій — запис за індексом scores[0] = 90](/images/csharp/fundamentals/arrays/01-array-anatomy.png){.diagram-img}

- **`int[]`** — тип «масив `int`». Довжина в тип не входить: у змінну `int[]` можна записати масив з трьох чи з тисячі елементів.
- **Змінна** містить посилання на масив, а не самі елементи. Масив з усіма числами лежить у купі (лекція 05).
- **`new int[5]`** створює масив з п'яти елементів, кожен дорівнює 0. Розмір можна задати будь-яким виразом типу `int`, зокрема змінною: він потрібен лише під час створення.
- **Індекс** — номер елемента від 0 до `Length - 1`. Після створення довжина масиву не змінюється.

### Усі способи створити масив

Одна програма, в якій зібрано всі способи:

```csharp [array-forms.cs]
// 1. new з розміром: елементи отримують значення за замовчуванням
int[] zeros = new int[3];

// 2. new з ініціалізатором: розмір рахує компілятор
int[] primes = new int[] { 2, 3, 5, 7 };

// 3. new з розміром і ініціалізатором: кількості мають збігатися
int[] three = new int[3] { 10, 20, 30 };

// 4. скорочений ініціалізатор: лише в оголошенні змінної
string[] days = { "пн", "вт", "ср" };

// 5. вираз колекції (C# 12)
int[] odds = [1, 3, 5, 7, 9];

// 6. new[]: тип елементів виводить компілятор
var letters = new[] { 'a', 'b', 'c' };

// 7. порожній масив
int[] empty = [];

// 8. розмір зі змінної: відомий лише під час роботи програми
int n = 4;
int[] squares = new int[n];
for (int i = 0; i < n; i++)
{
    squares[i] = i * i;
}

Console.WriteLine($"1: Length {zeros.Length}: {string.Join(", ", zeros)}");
Console.WriteLine($"2: Length {primes.Length}: {string.Join(", ", primes)}");
Console.WriteLine($"3: Length {three.Length}: {string.Join(", ", three)}");
Console.WriteLine($"4: Length {days.Length}: {string.Join(", ", days)}");
Console.WriteLine($"5: Length {odds.Length}: {string.Join(", ", odds)}");
Console.WriteLine($"6: {letters.GetType().Name}, Length {letters.Length}: {string.Join(", ", letters)}");
Console.WriteLine($"7: Length {empty.Length}");
Console.WriteLine($"8: Length {squares.Length}: {string.Join(", ", squares)}");
```

::terminal-preview{title="dotnet run array-forms.cs"}
```text
1: Length 3: 0, 0, 0
2: Length 4: 2, 3, 5, 7
3: Length 3: 10, 20, 30
4: Length 3: пн, вт, ср
5: Length 5: 1, 3, 5, 7, 9
6: Char[], Length 3: a, b, c
7: Length 0
8: Length 4: 0, 1, 4, 9
```
::

`string.Join(", ", масив)` збирає елементи в один рядок через кому — так масив друкується одним рядком.

::field-group

::field{name="new int[3]" type="розмір"}
Масив заданої довжини, усі елементи мають значення за замовчуванням. Розмір — будь-який вираз `int`, як у способі 8.
::

::field{name="new int[] { 2, 3, 5, 7 }" type="ініціалізатор"}
Елементи перелічено у фігурних дужках, довжину рахує компілятор. Такий запис працює будь-де, де потрібен масив: у присвоєнні, аргументі методу, `return`.
::

::field{name="new int[3] { 10, 20, 30 }" type="розмір і ініціалізатор"}
Розмір і кількість елементів мають збігатися, інакше помилка компіляції. Розмір тут нічого не додає, тому так пишуть рідко.
::

::field{name='{ "пн", "вт", "ср" }' type="скорочений ініціалізатор"}
Лише в оголошенні змінної з явним типом: тип масиву компілятор бере зі змінної. Присвоїти `{ … }` уже оголошеній змінній не можна.
::

::field{name="[1, 3, 5, 7, 9]" type="вираз колекції"}
Запис з C# 12. Працює в оголошенні, присвоєнні, аргументі і `return`, а також для `List<T>` і інших колекцій. Тип береться зі змінної зліва, тому з `var` не працює.
::

::field{name="new[] { 'a', 'b', 'c' }" type="виведений тип"}
Тип елементів компілятор виводить з ініціалізатора: тут `char`, тому `var letters` має тип `char[]` (у .NET — `Char[]`). Усі елементи мають зводитися до одного типу.
::

::field{name="[] або new int[0]" type="порожній масив"}
Масив довжиною 0 — не те саме, що `null`: у нього є `Length`, його можна перебрати циклом, і цикл не виконається жодного разу.
::

::field{name="new int[n]" type="розмір зі змінної"}
Розмір обчислюється під час роботи програми, наприклад з введення користувача. Значення елементів заповнюють окремо, зазвичай циклом.
::

::

::callout{icon="i-lucide-lightbulb"}
**Коли який спосіб**

- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **Вираз колекції `[…]`** — елементи відомі під час написання коду. Найкоротший запис, і той самий для масивів і списків.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`new int[n]`** — відомий лише розмір, а значення обчислюються чи вводяться далі.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`new[] { … }` або `new int[] { … }`** — потрібна змінна `var` або код має компілюватися старішими версіями C#, ніж 12.
- :icon{name="i-lucide-circle-x" class="inline-block text-red-500"} **Не пишіть `new int[3] { … }`** з розміром: він дублює кількість елементів і ламає компіляцію, коли елемент додають, а розмір забувають змінити.

### Значення за замовчуванням

Що лежить в елементах масиву, створеного через `new int[n]`, до першого присвоєння?

```csharp [defaults.cs]
int[] ints = new int[2];
double[] doubles = new double[2];
bool[] flags = new bool[2];
char[] chars = new char[2];
string[] names = new string[2];

Console.WriteLine($"int[]:    {ints[0]}, {ints[1]}");
Console.WriteLine($"double[]: {doubles[0]}, {doubles[1]}");
Console.WriteLine($"bool[]:   {flags[0]}, {flags[1]}");
Console.WriteLine($"char[]:   код {(int)chars[0]}, код {(int)chars[1]}");
Console.WriteLine($"string[]: {names[0] is null}, {names[1] is null}");
```

::terminal-preview{title="dotnet run defaults.cs"}
```text
int[]:    0, 0
double[]: 0, 0
bool[]:   False, False
char[]:   код 0, код 0
string[]: True, True
```
::

Runtime виділяє пам'ять для нового об'єкта вже заповненою нулями. Нульові байти — це 0 для чисел, `false` для `bool`, символ з кодом 0 для `char` і `null` для посилальних типів. Тому елементи масиву, на відміну від локальних змінних, компілятор не вимагає ініціалізувати (лекція 04). У C++ `int a[3];` усередині функції містить те, що лишилося в пам'яті від попереднього коду.

Масив рядків, створений через `new string[2]`, містить два `null`, а не два порожні рядки: звертання `names[0].Length` дасть `NullReferenceException` (лекція 05).

### Індекс, довжина і межі

Масив зберігає свою довжину всередині об'єкта, і `Length` її лише читає. Індекс елемента — від 0 до `Length - 1`:

```csharp [index.cs]
int[] temps = [12, 15, 9, 21, 18];
Console.WriteLine($"Length: {temps.Length}");
Console.WriteLine($"перший: temps[0] = {temps[0]}");
Console.WriteLine($"останній: temps[temps.Length - 1] = {temps[temps.Length - 1]}");

temps[2] = 10;
Console.WriteLine($"після temps[2] = 10: {string.Join(", ", temps)}");

int day = 5;
Console.WriteLine($"temps[{day}] = {temps[day]}");
```

::terminal-preview{title="dotnet run index.cs (шлях до файлу скорочено)"}
```text
Length: 5
перший: temps[0] = 12
останній: temps[temps.Length - 1] = 18
після temps[2] = 10: 12, 15, 10, 21, 18
Unhandled exception. System.IndexOutOfRangeException: Index was outside the bounds of the array.
   at Program.<Main>$(String[] args) in …/11-arrays/index.cs:line 10
```
::

![Масив у пам'яті: змінна scores у кадрі методу містить посилання на об'єкт у купі; об'єкт складається зі службової частини (заголовок, тип int[], Length = 5) і п'яти елементів int з індексами від 0 до 4; комірки з індексом 5 немає — звертання до неї дає IndexOutOfRangeException](/images/csharp/fundamentals/arrays/02-array-in-heap.png){.diagram-img}

Перед кожним звертанням за індексом runtime порівнює індекс з довжиною. Індекс 5 у масиві з п'яти елементів, як і −1, не проходить перевірку, і програма зупиняється з винятком. У C++ `temps[5]` прочитав би 4 байти, що лежать за масивом, без жодного повідомлення. Поглиблений розділ [Як runtime звертається до елементів](#як-runtime-звертається-до-елементів) показує, у що перетворюється ця перевірка і коли JIT-компілятор її прибирає.

### Типові алгоритми над масивом

Більшість задач з масивами зводиться до кількох шаблонів: накопичити суму, знайти максимум, знайти елемент, порахувати елементи за умовою, переставити елементи. Усі п'ять в одній програмі:

```csharp [algorithms.cs]
int[] temps = [12, 15, 9, 21, 18, 9, 14];

// 1. сума і середнє
int sum = 0;
foreach (int t in temps)
{
    sum += t;
}
double average = (double)sum / temps.Length;
Console.WriteLine($"1: сума {sum}, середнє {average}");

// 2. максимум та його індекс
int maxIndex = 0;
for (int i = 1; i < temps.Length; i++)
{
    if (temps[i] > temps[maxIndex])
        maxIndex = i;
}
Console.WriteLine($"2: максимум {temps[maxIndex]} у день {maxIndex}");

// 3. лінійний пошук: перший індекс значення
int target = 9;
int found = -1;
for (int i = 0; i < temps.Length; i++)
{
    if (temps[i] == target)
    {
        found = i;
        break;
    }
}
Console.WriteLine($"3: перше {target} на індексі {found}");

// 4. підрахунок за умовою
int warm = 0;
foreach (int t in temps)
{
    if (t > average)
        warm++;
}
Console.WriteLine($"4: днів тепліше за середнє: {warm}");

// 5. розворот на місці: обмін симетричних елементів
for (int i = 0, j = temps.Length - 1; i < j; i++, j--)
{
    int tmp = temps[i];
    temps[i] = temps[j];
    temps[j] = tmp;
}
Console.WriteLine($"5: навпаки: {string.Join(", ", temps)}");
```

::field{name="сума і середнє" type="foreach"}
Індекс не потрібен, тому `foreach`. Приведення `(double)sum` перед діленням дає дробове середнє: `int / int` — ціле ділення (лекція 08).

::field{name="максимум та його індекс" type="for"}

::field{name="підрахунок за умовою" type="foreach"}

::field{name="розворот на місці" type="for з двома індексами"}

## Масив — посилальний тип

Лекція 05 показала, що `int[] b = a` копіює посилання, а не елементи: обидві змінні ведуть до одного масиву, і `==` порівнює посилання. Звідси три наслідки, які в C# трапляються щодня: як масив передається в метод, як отримати справжню копію і що робить `Array.Resize`.

### Масив як параметр методу

У метод передається копія посилання. Метод бачить той самий масив, що й викликач:

```csharp [parameter.cs]
int[] prices = [100, 200, 300];

Discount(prices);
Console.WriteLine($"після Discount: {string.Join(", ", prices)}");

Replace(prices);
Console.WriteLine($"після Replace:  {string.Join(", ", prices)}");

// метод отримує копію посилання на той самий масив
static void Discount(int[] items)
{
    for (int i = 0; i < items.Length; i++)
    {
        items[i] = items[i] * 9 / 10;
    }
}

// присвоєння параметру змінює лише параметр, а не змінну викликача
static void Replace(int[] items)
{
    items = [1, 2, 3];
    items[0] = 999;
}
```

::terminal-preview{title="dotnet run parameter.cs"}
```text
після Discount: 90, 180, 270
після Replace:  90, 180, 270
```
::

- **`Discount`** змінює елементи через `items[i]`, а `items` веде до масиву `prices`. Знижку видно після виклику.
- **`Replace`** записує в параметр `items` посилання на новий масив. Змінна `prices` викликача і далі веде до старого масиву, тому `999` потрапляє в новий масив, який після виходу з методу нікому не потрібен.

У C++ масив передається у функцію як покажчик на перший елемент, і довжину доводиться передавати окремим параметром. У C# метод отримує масив разом з `Length`. Щоб метод міг замінити сам масив у змінній викликача, параметр позначають `ref` (лекція 15).

### Усі способи скопіювати масив

Незалежна копія — це новий масив з тими самими елементами. Способів кілька:

```csharp [copy.cs]
int[] source = [1, 2, 3, 4, 5];

int[] alias = source;                        // не копія: те саме посилання
int[] clone = (int[])source.Clone();         // 1. Clone
int[] copied = new int[5];
Array.Copy(source, copied, source.Length);   // 2. Array.Copy: увесь масив
int[] part = new int[3];
Array.Copy(source, 1, part, 0, 3);           // 3. Array.Copy: 3 елементи з індексу 1
int[] bigger = new int[7];
source.CopyTo(bigger, 2);                    // 4. CopyTo: у більший масив з позиції 2
int[] spread = [.. source];                  // 5. розгортання у виразі колекції
int[] linq = source.ToArray();               // 6. ToArray

source[0] = 100;

Console.WriteLine($"source: {string.Join(", ", source)}");
Console.WriteLine($"alias:  {string.Join(", ", alias)}");
Console.WriteLine($"clone:  {string.Join(", ", clone)}");
Console.WriteLine($"copied: {string.Join(", ", copied)}");
Console.WriteLine($"part:   {string.Join(", ", part)}");
Console.WriteLine($"bigger: {string.Join(", ", bigger)}");
Console.WriteLine($"spread: {string.Join(", ", spread)}");
Console.WriteLine($"linq:   {string.Join(", ", linq)}");
```

::terminal-preview{title="dotnet run copy.cs"}
```text
source: 100, 2, 3, 4, 5
alias:  100, 2, 3, 4, 5
clone:  1, 2, 3, 4, 5
copied: 1, 2, 3, 4, 5
part:   2, 3, 4
bigger: 0, 0, 1, 2, 3, 4, 5
spread: 1, 2, 3, 4, 5
linq:   1, 2, 3, 4, 5
```
::

Зміну `source[0] = 100` видно лише через `alias`: решта змінних ведуть до нових масивів.

::field-group

::field{name="(int[])source.Clone()" type="Clone"}
Новий масив того самого типу і довжини. `Clone` оголошено в класі `Array` з типом результату `object`, тому потрібне приведення `(int[])`.
::

::field{name="Array.Copy(src, dst, n)" type="Array.Copy"}
Копіює `n` елементів у вже створений масив. Масив-приймач створюють заздалегідь, і він має бути достатньо довгим.
::

::field{name="Array.Copy(src, 1, dst, 0, 3)" type="частина масиву"}
Повна форма: звідки, з якого індексу, куди, з якого індексу, скільки. Так копіюють частину масиву або зсувають елементи.
::

::field{name="src.CopyTo(dst, 2)" type="CopyTo"}
Копіює весь масив у інший, починаючи з вказаного індексу приймача. Решта елементів приймача не змінюється.
::

::field{name="[.. source]" type="розгортання"}
Оператор `..` у виразі колекції вставляє всі елементи іншої колекції. Так само склеюють кілька масивів: `[.. a, .. b, 0]`.
::

::field{name="source.ToArray()" type="ToArray"}
Метод LINQ: створює масив з будь-якої послідовності, не лише з масиву. Для масиву результат той самий, що в `Clone`, але без приведення.
::

::

Усі способи створюють **поверхневу копію** (*shallow copy*): копіюються елементи, і якщо елемент — посилання, копіюється посилання, а не об'єкт, на який воно веде. Для `int[]` різниці немає, для масиву масивів вона важлива — див. розділ [Рваний масив](#рваний-масив).

### Array.Resize створює новий масив

Довжина масиву після створення не змінюється. Метод `Array.Resize` лише називається «змінити розмір»:

```csharp [resize.cs]
int[] a = [1, 2, 3];
int[] b = a;

Array.Resize(ref a, 5);
a[0] = 100;

Console.WriteLine($"a: {string.Join(", ", a)} (Length {a.Length})");
Console.WriteLine($"b: {string.Join(", ", b)} (Length {b.Length})");
Console.WriteLine($"a і b ведуть до одного масиву: {ReferenceEquals(a, b)}");
```

::terminal-preview{title="dotnet run resize.cs"}
```text
a: 100, 2, 3, 0, 0 (Length 5)
b: 1, 2, 3 (Length 3)
a і b ведуть до одного масиву: False
```
::

![До Array.Resize змінні a і b ведуть до одного масиву 1, 2, 3; після Array.Resize(ref a, 5) і a[0] = 100 змінна a веде до нового масиву 100, 2, 3, 0, 0, а b — до старого 1, 2, 3](/images/csharp/fundamentals/arrays/03-resize.png){.diagram-img}

`Resize` створює новий масив потрібної довжини, копіює в нього старі елементи і записує посилання на новий масив у змінну `a`. Тому параметр позначено `ref`: методу потрібно змінити саму змінну викликача (лекція 15). Змінна `b` про це не знає і веде до старого масиву. Коли кількість елементів наперед невідома і змінюється часто, замість масиву і `Resize` беруть `List<T>` (лекція 10), який робить те саме всередині себе.

### Пошук, сортування, заповнення

Типові дії над масивом уже реалізовано статичними методами класу `Array`:

```csharp [array-methods.cs]
int[] scores = [74, 92, 58, 92, 81];
```


::field-group

::field{name="Array.IndexOf(a, x)" type="пошук"}
Індекс першого елемента, рівного `x`, або −1. Це той самий лінійний пошук, що в `algorithms.cs`. `LastIndexOf` шукає з кінця.
::

::field{name="a.Contains(x)" type="наявність"}
`true`, якщо елемент є. Метод розширення: викликається через крапку на самому масиві, хоча масив такого методу не оголошує.
::

::field{name="Array.Sort(a)" type="сортування"}
Сортує масив на місці за зростанням: змінюється сам масив, нового не створюється.
::

::field{name="Array.Reverse(a)" type="розворот"}
Переставляє елементи у зворотному порядку на місці. Після `Sort` дає сортування за спаданням.
::

::field{name="Array.Fill(a, x)" type="заповнення"}
Записує `x` у кожен елемент. Так створюють масив, де початкове значення не нуль.
::

::field{name="Array.Clear(a, start, count)" type="очищення"}
Записує значення за замовчуванням у `count` елементів, починаючи з `start`. Довжина масиву не змінюється.
::

::field{name="a.Min(), a.Max(), a.Sum()" type="LINQ"}
Методи [LINQ](/csharp/standard-library/linq) для будь-яких послідовностей. Для порожнього масиву `Min` і `Max` кидають виняток, бо найменшого елемента немає.
::

::

`Array.Sort` для рядків порівнює їх за правилами поточної культури, а не за кодами символів. Для українських слів різниця помітна:

```csharp [sort-strings.cs]
using System.Globalization;

string[] byCulture = (string[])words.Clone();
Array.Sort(byCulture);
Console.WriteLine($"за культурою uk-UA: {string.Join(", ", byCulture)}");

string[] byCode = (string[])words.Clone();
Array.Sort(byCode, StringComparer.Ordinal);
Console.WriteLine($"за кодами символів: {string.Join(", ", byCode)}");
```

::terminal-preview{title="dotnet run sort-strings.cs"}
```text

```
::

У таблиці Unicode 32 літери від `а` до `я` йдуть підряд, а `є`, `і`, `ї` і `ґ` мають більші коди і стоять після `я`. Порівняння за кодами (`StringComparer.Ordinal`) ставить їх у кінець, порівняння за культурою uk-UA — на місце за українською абеткою. Порівняння рядків детально розбирає лекція 12.

### Бінарний пошук

`Array.IndexOf` перевіряє елементи по черзі: для мільйона елементів — до мільйона порівнянь. `Array.BinarySearch` ділить діапазон пошуку навпіл на кожному кроці і обходиться приблизно двадцятьма порівняннями. Але працює він лише на відсортованому масиві:

```csharp [binary-search.cs]
int[] sorted = [3, 8, 15, 21, 34, 42, 57, 66];
Console.WriteLine($"BinarySearch(42): {Array.BinarySearch(sorted, 42)}");
Console.WriteLine($"BinarySearch(40): {Array.BinarySearch(sorted, 40)}");

int[] unsorted = [42, 3, 66, 15, 8, 57, 21, 34];
Console.WriteLine($"невідсортований, BinarySearch(42): {Array.BinarySearch(unsorted, 42)}");
Console.WriteLine($"невідсортований, IndexOf(42):      {Array.IndexOf(unsorted, 42)}");
```

::terminal-preview{title="dotnet run binary-search.cs"}
```text
BinarySearch(42): 5
BinarySearch(40): -6
невідсортований, BinarySearch(42): -6
невідсортований, IndexOf(42):      0
```
::

<video controls autoplay loop muted playsinline poster="/videos/csharp/fundamentals/arrays/anim-01-binary-search.png" class="diagram-img rounded-xl shadow-lg w-full my-6">
  <source src="/videos/csharp/fundamentals/arrays/anim-01-binary-search.mp4" type="video/mp4">
  <source src="/videos/csharp/fundamentals/arrays/anim-01-binary-search.webm" type="video/webm">
</video>

- **Кожен крок** порівнює шукане з елементом посередині діапазону. Якщо середній менший, шукане може бути лише правіше, і ліва половина відкидається. Для 42 у відсортованому масиві вистачає двох порівнянь.
- **Від'ємний результат** означає «не знайдено». Його побітове заперечення (`~`, лекція 08) — індекс, куди число треба вставити, щоб масив лишився відсортованим: `~(-6) = 5`, тобто 40 стало б між 34 і 42.
- **На невідсортованому масиві** перший же крок відкидає ліву половину разом з 42, і пошук повертає «не знайдено». Ні помилки, ні винятку немає: метод не перевіряє порядок, бо перевірка коштувала б стільки ж, скільки лінійний пошук.

## Багатовимірні масиви

### Прямокутний масив

Таблицю з рядків і стовпців однакової довжини зберігають у прямокутному (*rectangular*) масиві. Кількість вимірів задає кількість ком у квадратних дужках:

![Анатомія int[,]: тип елемента int, дужки з комою — два виміри, Rank = 2; new int[2, 3] — 2 рядки по 3 стовпці, GetLength(0) = 2, GetLength(1) = 3, Length = 6; grid[1, 2] — індекс рядка і стовпця через кому в одних дужках](/images/csharp/fundamentals/arrays/04-rectangular-anatomy.png){.diagram-img}

```csharp [rectangular.cs]
// 1. new з розмірами: 2 рядки по 3 стовпці, усі елементи — нулі
int[,] grid = new int[2, 3];
grid[0, 0] = 1;
grid[1, 2] = 6;

// 2. new з ініціалізатором: розміри рахує компілятор
int[,] table = new int[,] { { 1, 2, 3 }, { 4, 5, 6 } };

// 3. скорочений ініціалізатор: лише в оголошенні змінної
int[,] same = { { 1, 2, 3 }, { 4, 5, 6 } };

Console.WriteLine($"grid[0, 0] = {grid[0, 0]}, grid[1, 2] = {grid[1, 2]}, grid[1, 0] = {grid[1, 0]}");
Console.WriteLine($"Rank = {table.Rank}, Length = {table.Length}");
Console.WriteLine($"GetLength(0) = {table.GetLength(0)}, GetLength(1) = {table.GetLength(1)}");

for (int row = 0; row < table.GetLength(0); row++)
{
    for (int col = 0; col < table.GetLength(1); col++)
    {
        Console.Write($"{table[row, col],3}");
    }
    Console.WriteLine();

```

### Рваний масив

Коли рядки мають різну довжину — оцінки студентів, уроки за днями тижня, — використовують рваний (*jagged*) масив: масив, елементи якого — інші масиви:

![Анатомія int[][]: тип елемента рядка int, дві пари дужок — масив масивів, кожен елемент якого — int[]; new int[3][] створює 3 рядки, довжини рядків не задано, тому всі три — null; rows[1] = [2, 3] створює рядок окремо; rows[1][0] — номер рядка і номер елемента в рядку в окремих дужках](/images/csharp/fundamentals/arrays/06-jagged-anatomy.png){.diagram-img}

```csharp [jagged.cs]
// 1. зовнішній масив з трьох посилань, кожен рядок створюється окремо
int[][] rows = new int[3][];
rows[0] = [1];
rows[1] = [2, 3];
rows[2] = new int[4];

Console.WriteLine($"rows.Length = {rows.Length}");
for (int i = 0; i < rows.Length; i++)
{
    Console.Write($"рядок {i}, Length {rows[i].Length}:");
    for (int j = 0; j < rows[i].Length; j++)
    {
        Console.Write($" {rows[i][j]}");
    }
    Console.WriteLine();
}

// 2. вираз колекції з вкладеними виразами колекцій
int[][] triangle = [[1], [1, 1], [1, 2, 1]];

// 3. new з ініціалізатором: кожен рядок — окремий new
int[][] pairs = new int[][] { new int[] { 1, 2 }, new[] { 3, 4 } };

Console.Write("triangle:");
foreach (int[] row in triangle)
{
    Console.Write($" [{string.Join(" ", row)}]");
}
Console.WriteLine();
Console.WriteLine($"pairs[1][0] = {pairs[1][0]}");
```

```text

рядок 2, Length 4: 0 0 0 0

```

::field-group

::field{name="new int[3][]" type="зовнішній масив"}
Створює лише масив з трьох посилань на рядки, кожне дорівнює `null`. Довжину рядків тут не задають.
::

::field{name="rows[i] = [ … ]" type="рядок"}
Кожен рядок — звичайний одновимірний масив, створений будь-яким способом з першого розділу, і має власну довжину.
::

::field{name="[[1], [1, 1], [1, 2, 1]]" type="вираз колекції"}
Вкладені вирази колекцій створюють і зовнішній масив, і всі рядки одразу. Для рваних масивів, на відміну від прямокутних, вирази колекцій працюють.
::

::field{name="rows[i][j]" type="індекс"}
Кожен індекс — в окремих дужках: `rows[i]` — рядок (`int[]`), `[j]` — елемент у ньому.
::

::field{name="rows.Length і rows[i].Length" type="довжини"}
`rows.Length` — кількість рядків, `rows[i].Length` — довжина рядка `i`. Внутрішній цикл бере межу з поточного рядка.
::

::field{name="foreach (int[] row in rows)" type="перебір"}
Змінна `foreach` — цілий рядок типу `int[]`, з яким далі працюють як зі звичайним масивом.
::

Рваний масив — це кілька незалежних об'єктів у купі: зовнішній масив з посилань і окремий масив на кожен рядок:

```csharp [jagged-clone.cs]
copy[1] = [7, 7];   // новий рядок лише в копії
```

### int[,] чи int[][]

Прямокутний масив — один об'єкт з елементами одним блоком, рваний — кілька об'єктів, пов'язаних посиланнями. Звідси й вибір:

::callout{icon="i-lucide-lightbulb"}
**Коли який масив**

- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`int[,]`** — таблиця, де всі рядки однакової довжини: матриця, ігрове поле, розклад «дні × уроки». Один об'єкт, без `null`-рядків, розміри відомі з `GetLength`.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`int[][]`** — рядки різної довжини або рядки, які треба замінювати цілком: оцінки студентів, трикутні таблиці, рядки тексту. Кожен рядок можна передати в метод як звичайний `int[]`.
- :icon{name="i-lucide-circle-x" class="inline-block text-red-500"} **Не беріть `int[][]`** для таблиці з рядками однакової довжини: кожен рядок доведеться створювати окремо, і забутий рядок дасть `NullReferenceException`.
- :icon{name="i-lucide-circle-x" class="inline-block text-red-500"} **Не беріть `int[,]`** для рядків різної довжини: доведеться резервувати місце під найдовший рядок і окремо пам'ятати справжню довжину кожного.

### Індекси з кінця і діапазони

З C# 8 індекс можна рахувати з кінця масиву, а частину масиву — задавати діапазоном:

```csharp [index-range.cs]
// Поглиблений розділ: індекси з кінця і діапазони.
int[] a = [10, 20, 30, 40, 50];

Console.WriteLine($"a[^1] = {a[^1]}, a[^2] = {a[^2]}");
Console.WriteLine($"a[1..3]  = {string.Join(", ", a[1..3])}");
Console.WriteLine($"a[..2]   = {string.Join(", ", a[..2])}");
Console.WriteLine($"a[3..]   = {string.Join(", ", a[3..])}");
Console.WriteLine($"a[1..^1] = {string.Join(", ", a[1..^1])}");

// діапазон над масивом створює новий масив
int[] middle = a[1..^1];
middle[0] = 999;
Console.WriteLine($"middle = {string.Join(", ", middle)}; a = {string.Join(", ", a)}");

// Index і Range — звичайні значення, їх можна зберігати в змінних
Index last = ^1;
Range firstTwo = ..2;
Console.WriteLine($"a[last] = {a[last]}, a[firstTwo] = {string.Join(", ", a[firstTwo])}");
```

::terminal-preview{title="dotnet run index-range.cs"}
```text
a[^1] = 50, a[^2] = 40
a[1..3]  = 20, 30
a[..2]   = 10, 20
a[3..]   = 40, 50
a[1..^1] = 20, 30, 40
middle = 999, 30, 40; a = 10, 20, 30, 40, 50
a[last] = 50, a[firstTwo] = 10, 20
```
::

- **`^n`** — індекс з кінця: `a[^1]` — останній елемент, те саме, що `a[a.Length - 1]`. `^0` вказує за останній елемент і як індекс елемента дає виняток.
- **`start..end`** — діапазон від `start` включно до `end` не включно: `a[1..3]` — елементи з індексами 1 і 2. Будь-яку межу можна пропустити: `..2` — від початку, `3..` — до кінця.
- **Діапазон над масивом копіює елементи** в новий масив: зміна `middle` не зачіпає `a`. Для великих масивів у циклі ця копія коштує пам'яті й часу.
- **`Index` і `Range`** — типи з простору імен `System`, значення яких можна передавати в методи й зберігати в змінних.

### Span: вікно в масив

`Span<T>` — «вікно» на частину масиву: він зберігає, звідки почати і скільки елементів, але не копіює їх. Звертання через вікно змінює сам масив:

```csharp [span.cs]
// Поглиблений розділ: Span<T> — вікно в масив без копіювання.
int[] a = [10, 20, 30, 40, 50];

Span<int> window = a.AsSpan(1, 3);   // елементи з індексами 1, 2, 3
window[0] = 999;                     // змінюється сам масив
Console.WriteLine($"window.Length = {window.Length}, a = {string.Join(", ", a)}");

Span<int> tail = a.AsSpan()[3..];    // діапазон над Span — теж вікно, не копія
tail.Fill(0);
Console.WriteLine($"після tail.Fill(0): a = {string.Join(", ", a)}");

Console.WriteLine($"Sum(a) = {Sum(a)}");                   // int[] → ReadOnlySpan<int>
Console.WriteLine($"Sum(a.AsSpan(1, 2)) = {Sum(a.AsSpan(1, 2))}");

static int Sum(ReadOnlySpan<int> items)
{
    int sum = 0;
    foreach (int item in items)
        sum += item;
    return sum;
}
```

::terminal-preview{title="dotnet run span.cs"}

- **`a.AsSpan(start, length)`** створює вікно без копіювання. Діапазон над `Span` (`[3..]`) теж дає вікно, а не новий масив, на відміну від діапазону над масивом.
- **`ReadOnlySpan<T>`** — вікно лише для читання. Метод з таким параметром приймає і цілий масив, і будь-яку його частину без копіювання, а компілятор гарантує, що метод не змінить елементи.

```csharp [span-extension.cs]
{
    public static int CountPositive(this ReadOnlySpan<int> items)
    {
        int count = 0;

        return count;
    }
}
```

Методи `SumLength` і `SumTen` відрізняються лише умовою циклу: `i < items.Length` проти `i < 10`. Фрагменти машинного коду з Apple M4 Pro (arm64, на x64 команди інші), коментарі дописано вручну:

::code-group

```text [SumLength: i < items.Length]
ldr     w2, [x0, #0x08]          // Length: зсув 8 від адреси в посиланні
cmp     w2, #0
ble     G_M000_IG05              // порожній масив — одразу вихід
add     x0, x0, #16              // елементи: зсув 16
G_M000_IG04:
ldr     w3, [x0], #0x04          // елемент, перехід до наступного
add     w1, w3, w1               // sum += елемент
sub     w2, w2, #1
cbnz    w2, G_M000_IG04          // перевірки меж у циклі немає
```

```text [SumTen: i < 10]
cbz     x0, G_M000_IG06          // null — повільна версія
ldr     w3, [x0, #0x08]
cmp     w3, #10
blt     G_M000_IG06              // Length < 10 — повільна версія
...                              // швидкий цикл без перевірок, як у SumLength
G_M000_IG06:                     // повільна версія циклу:
ldr     w3, [x0, #0x08]
cmp     w2, w3                   // індекс < Length?
bhs     G_M000_IG07              // ні — виняток
...
G_M000_IG07:
bl      CORINFO_HELP_RNGCHKFAIL  // кидає IndexOutOfRangeException
```

```text [Rect: g[1, 0]]
ldp     w2, w3, [x0, #0x10]      // довжини обох вимірів
...                              // дві перевірки меж
madd    w1, w1, w3, w2           // позиція = рядок · стовпці + стовпець
ldr     w0, [x0, x1]             // елемент
```

::

- **`SumLength`**: умова `i < items.Length` гарантує, що індекс у межах, тому JIT прибирає перевірку з циклу повністю. Цикл — чотири інструкції на елемент.
- **`SumTen`**: про довжину масиву умова `i < 10` нічого не каже. JIT створює дві копії циклу (*loop cloning*): якщо перед циклом `Length >= 10`, виконується швидка копія без перевірок, інакше — повільна з перевіркою на кожній ітерації, яка й кидає `IndexOutOfRangeException`.
- **`Rect`**: виклик `Get` з IL JIT замінює кількома інструкціями. Позицію обчислює одна інструкція `madd` за формулою зі схеми прямокутного масиву: `рядок · стовпці + стовпець`.

Звідси практичне правило: у циклі за масивом пишіть умову через `Length` того самого масиву. Перевірку меж JIT прибере сам, а код лишиться безпечним.

## Питання для самоперевірки

::::accordion

:::accordion-item{label="Чим int[] a у C# відрізняється від int a[10] у C++?" icon="i-lucide-help-circle"}

У C# `int[] a` — змінна з посиланням на масив у купі, розмір у тип не входить і задається під час створення: `new int[10]`. Масив знає свою довжину (`a.Length`), його елементи ініціалізовано нулями, кожен індекс перевіряється. У C++ `int a[10]` усередині функції — десять неініціалізованих чисел на стеку, розмір — частина типу, перевірки меж немає.

:::

:::accordion-item{label="Які значення мають елементи нового масиву і чому?" icon="i-lucide-help-circle"}

Значення за замовчуванням: 0 для чисел, `false` для `bool`, символ з кодом 0 для `char`, `null` для посилальних типів, зокрема `string` і `int[]`. Runtime виділяє пам'ять для нового об'єкта вже заповненою нулями, а нульові байти означають саме ці значення.

:::

:::accordion-item{label="Що станеться при звертанні за індексом, що дорівнює Length?" icon="i-lucide-help-circle"}

Runtime перевіряє кожен індекс перед звертанням. Індекс `Length` (як і −1) виходить за межі `0 … Length − 1`, тому програма зупиняється з `IndexOutOfRangeException`. Пам'ять за масивом не читається і не змінюється.

:::

:::accordion-item{label="Чому метод може змінити елементи масиву викликача, але не може замінити сам масив?" icon="i-lucide-help-circle"}

У метод передається копія посилання на той самий масив, тому `items[i] = …` змінює масив викликача. Присвоєння `items = новий масив` змінює лише параметр — копію посилання, змінна викликача веде до старого масиву. Щоб замінити масив у змінній викликача, параметр позначають `ref`, як в `Array.Resize(ref a, 5)`.

:::

:::accordion-item{label="Чим поверхнева копія відрізняється від повної і коли це помітно?" icon="i-lucide-help-circle"}

Поверхнева копія (`Clone`, `Array.Copy`, `[.. a]`) копіює елементи як є. Для `int[]` це повна копія. Для масиву посилань, наприклад рваного масиву `int[][]`, копіюються посилання, і рядки лишаються спільними: зміна `copy[0][0]` видна в оригіналі. Повну копію отримують, копіюючи кожен рядок окремо.

:::

:::accordion-item{label="Чому Array.Resize не змінює масив, на який веде інша змінна?" icon="i-lucide-help-circle"}

Довжина масиву після створення не змінюється. `Resize` створює новий масив, копіює в нього елементи і записує посилання на нього в змінну, передану через `ref`. Інші змінні ведуть до старого масиву і бачать стару довжину.

:::

:::accordion-item{label="Чому BinarySearch на невідсортованому масиві може не знайти наявний елемент?" icon="i-lucide-help-circle"}

Бінарний пошук на кожному кроці відкидає половину діапазону, спираючись на порядок: якщо середній елемент менший за шуканий, шуканий може бути лише правіше. У невідсортованому масиві це припущення хибне, і половина з шуканим елементом відкидається. Метод не перевіряє порядок і повертає від'ємне число «не знайдено» без помилки.

:::

:::accordion-item{label="Чим відрізняються Length і GetLength для прямокутного масиву?" icon="i-lucide-help-circle"}

`Length` — загальна кількість елементів, добуток розмірів усіх вимірів: для `int[2, 3]` це 6. `GetLength(d)` — довжина одного виміру: `GetLength(0)` = 2 рядки, `GetLength(1)` = 3 стовпці. Межі вкладених циклів беруть з `GetLength`.

:::

:::accordion-item{label="Чому в рваному масиві після new int[3][] звертання до елемента дає виняток?" icon="i-lucide-help-circle"}

`new int[3][]` створює лише зовнішній масив з трьох посилань на рядки, і кожне дорівнює `null`, бо це значення за замовчуванням для посилального типу `int[]`. Звертання `rows[0][0]` бере `null` замість рядка і кидає `NullReferenceException`. Кожен рядок треба створити окремо.

:::

```csharp [copy-predict.cs]
int[] a = [1, 2, 3];
int[] b = a;
int[] c = (int[])a.Clone();

b[0] = 10;

static void Twice(int[] items)
{
    for (int i = 0; i < items.Length; i++)
        items[i] *= 2;
}
```

Письмово: для кожного рядка програми після оголошень вкажіть, скільки масивів існує в купі в цей момент і до якого з них веде кожна змінна. Додайте скріншот виводу і свої передбачення поруч.

```csharp [week-temps.cs]
string[] days = ["пн", "вт", "ср", "чт", "пт", "сб", "нд"];
// 7 днів (рядки) × 3 заміри: ранок, день, вечір
int[,] temps =
{
    { 4, 11, 7 },
    { 3, 12, 8 },
    { 6, 14, 12 },
    { 8, 9, 5 },
    { 5, 13, 10 },
    { 7, 16, 11 },
    { 6, 15, 9 },
};

Console.WriteLine($"Length = {temps.Length}, GetLength(0) = {temps.GetLength(0)}, GetLength(1) = {temps.GetLength(1)}");

for (int day = 0; day < temps.GetLength(0); day++)
{
    int sum = 0;
    for (int m = 0; m < temps.GetLength(1); m++)
        sum += temps[day, m];
    Console.WriteLine($"{days[day]}: середня {sum / temps.GetLength(1)}");
}

string[] names = ["ранок", "день", "вечір"];
for (int m = 0; m < temps.GetLength(1); m++)
{
    int maxDay = 0;
    for (int day = 1; day < temps.GetLength(0); day++)
        if (temps[day, m] > temps[maxDay, m])
            maxDay = day;
    Console.WriteLine($"{names[m]}: максимум {temps[maxDay, m]} ({days[maxDay]})");
}
```

`Length` — загальна кількість елементів, 21, а рядків лише 7. Цикл до `temps.Length` на восьмій ітерації звернувся б до `temps[7, 0]` і `days[7]`, і програма зупинилася б з `IndexOutOfRangeException` після семи правильних рядків. Неправильних чисел не буде: runtime перевіряє індекси кожного виміру окремо.
