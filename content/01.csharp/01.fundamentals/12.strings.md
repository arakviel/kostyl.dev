## Що в C# інакше, ніж у C++

Рядок у C# — це `string` (`System.String`), послідовність символів `char`. Літерали (звичайні, verbatim, raw) розбирала лекція 04, незмінність і порівняння через `==` — лекція 05, інтерполяцію і форматування — лекція 07. Ця лекція розбирає операції над рядками: як рядок влаштований, як у ньому шукати, вирізати, розбивати, порівнювати і як швидко збирати великий текст. Порівняно з `std::string` у C++:

- **рядок незмінний**: `ToUpper`, `Replace`, `Trim` повертають новий рядок, а не змінюють наявний;
- **індексатор лише читає**: `s[0] = 'x'` не компілюється;
- **довжина зберігається в об'єкті**: `s.Length` не шукає завершальний `'\0'`, і `'\0'` може стояти всередині рядка;
- **`char` — 16 бітів UTF-16**, тому `Length` рахує одиниці UTF-16, а не байти і не завжди літери;
- **пошук повертає −1**, а не `npos`;
- **частина методів порівнює рядки за правилами культури**, якщо не вказати `StringComparison`;
- **склеювання в циклі через `+=` повільне**, для цього є `StringBuilder`.

## Рядок як послідовність символів

### Будова рядка

Рядок зберігає символи підряд, як масив `char`, і так само дає `Length` і доступ за індексом:

![Рядок Чернігів як 8 клітинок char з індексами від 0 до 7: city[0] = Ч, city[city.Length - 1] = в, city.Length = 8; кожна клітинка — char у UTF-16, індексатор лише читає, запис city[0] дає помилку CS0200](/images/csharp/fundamentals/strings/01-string-indexes.png){.diagram-img}

```csharp [basics.cs]
string city = "Чернігів";

Console.WriteLine($"Length: {city.Length}");
Console.WriteLine($"перший символ: {city[0]}, останній: {city[city.Length - 1]}");

// перебір символів за індексом
for (int i = 0; i < city.Length; i++)
{
    Console.Write($"{i}:{city[i]} ");
}
Console.WriteLine();

// перебір через foreach і підрахунок
int count = 0;
foreach (char c in city)
{
    if (c == 'і')
        count++;
}
Console.WriteLine($"літера і трапляється {count} рази");

// рядок у масив символів і назад
char[] letters = city.ToCharArray();
Array.Reverse(letters);
string reversed = new string(letters);
Console.WriteLine($"навпаки: {reversed}");
```

::terminal-preview{title="dotnet run basics.cs"}
```text
Length: 8
перший символ: Ч, останній: в
0:Ч 1:е 2:р 3:н 4:і 5:г 6:і 7:в 
літера і трапляється 2 рази
навпаки: вігінреЧ
```
::

- **`Length`** — кількість `char` у рядку. Для кирилиці й латиниці це кількість літер, винятки розбирає поглиблений розділ про Unicode.
- **`city[i]`** повертає `char`. Індекси — від 0 до `Length - 1`, вихід за межі дає `IndexOutOfRangeException`, як у масиві (лекція 11).
- **`foreach`** перебирає символи без індексу (лекція 10).
- **`ToCharArray()`** копіює символи в новий масив `char[]`, який уже можна змінювати. `new string(letters)` створює з масиву новий рядок.

Записати символ за індексом не можна:

::terminal-preview{title="dotnet build errors/index-assign.cs: city[0] = 'к';"}
```text
index-assign.cs(2,1): error CS0200: Property or indexer 'string.this[int]' cannot be assigned to -- it is read only
```
::

Індексатор `string` має лише `get`. Щоб отримати рядок з іншою літерою, створюють новий: через `ToCharArray` і `new string`, через `Replace` або через `StringBuilder`.

### Усі способи створити рядок

Одна програма, в якій зібрано всі способи:

```csharp [string-forms.cs]
// 1. літерал (звичайний, verbatim, raw — лекція 04)
string literal = "Київ";
string path = @"C:\Docs\звіт.txt";
string raw = """Він сказав: "Так".""";

// 2. інтерполяція (лекція 07)
int year = 2026;
string interpolated = $"Рік {year}";

// 3. повторення символу
string line = new string('-', 12);

// 4. з масиву символів: увесь масив або частина
char[] chars = ['р', 'я', 'д', 'о', 'к'];
string fromChars = new string(chars);
string fromPart = new string(chars, 1, 3);

// 5. склеювання елементів масиву через роздільник
string[] parts = ["Київ", "Львів", "Одеса"];
string joined = string.Join(" | ", parts);

// 6. склеювання без роздільника
string concat = string.Concat("ab", "cd", "ef");

// 7. з іншого значення
string fromNumber = 3.ToString() + 14.ToString();

// 8. порожній рядок
string empty = string.Empty;

Console.WriteLine(literal);
Console.WriteLine(path);
Console.WriteLine(raw);
Console.WriteLine(interpolated);
Console.WriteLine(line);
Console.WriteLine($"{fromChars}, {fromPart}");
Console.WriteLine(joined);
Console.WriteLine(concat);
Console.WriteLine(fromNumber);
Console.WriteLine($"empty: Length {empty.Length}, empty == \"\": {empty == ""}");
```

::terminal-preview{title="dotnet run string-forms.cs"}
```text
Київ
C:\Docs\звіт.txt
Він сказав: "Так".
Рік 2026
------------
рядок, ядо
Київ | Львів | Одеса
abcdef
314
empty: Length 0, empty == "": True
```
::

::field-group

::field{name='"…", @"…", """…"""' type="літерали"}
Текст, записаний у коді. Звичайний рядок з escape-послідовностями, verbatim без них, raw без екранування лапок — лекція 04.
::

::field{name='$"Рік {year}"' type="інтерполяція"}
Рядок зі вставленими значеннями виразів, з шириною і форматом — лекція 07.
::

::field{name="new string('-', 12)" type="повторення"}
Рядок з одного символу, повтореного задану кількість разів. Так малюють лінії й рамки потрібної довжини.
::

::field{name="new string(chars) / new string(chars, 1, 3)" type="з масиву char"}
Увесь масив символів або його частина: з якого індексу і скільки символів. Масив копіюється, і подальші зміни масиву рядок не зачіпають.
::

::field{name='string.Join(" | ", parts)' type="Join"}
Елементи масиву (або будь-якої послідовності) через роздільник. Роздільник ставиться лише між елементами, не в кінці.
::

::field{name='string.Concat("ab", "cd")' type="Concat"}
Склеювання без роздільника. Оператор `+` для рядків компілюється саме у виклик `string.Concat`.
::

::field{name="3.ToString()" type="з іншого значення"}
`ToString()` є в кожного типу. Для чисел він враховує культуру: `2.5.ToString()` в uk-UA дає `2,5` (лекція 06).
::

::field{name='string.Empty або ""' type="порожній рядок"}
Рядок довжиною 0. Обидва записи дають той самий об'єкт. Порожній рядок — не `null`: у нього є `Length` і всі методи.
::

::

::callout{icon="i-lucide-lightbulb"}
**Коли який спосіб**

- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **Інтерполяція** — рядок з кількох значень і тексту: найкраще читається.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`string.Join`** — елементи масиву чи списку через роздільник: не треба думати про зайву кому в кінці.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`new string(c, n)`** — повторення символу: лінії, відступи, рамки.
- :icon{name="i-lucide-circle-x" class="inline-block text-red-500"} **Не склеюйте `+=` у циклі** на тисячі ітерацій: розділ [StringBuilder](#stringbuilder) вимірює, чому.

::

## Пошук і перевірки

### Методи пошуку

Знайти символ чи підрядок, перевірити, з чого рядок починається і чим закінчується, — це методи пошуку. Усі вони не змінюють рядок:

```csharp [search.cs]
string text = "мама мила раму, а Марко мив вікно";

Console.WriteLine($"IndexOf('м'):         {text.IndexOf('м')}");
Console.WriteLine($"IndexOf('м', 1):      {text.IndexOf('м', 1)}");
Console.WriteLine($"IndexOf(\"ми\"):        {text.IndexOf("ми")}");
Console.WriteLine($"LastIndexOf('м'):     {text.LastIndexOf('м')}");
Console.WriteLine($"IndexOf('ж'):         {text.IndexOf('ж')}");
Console.WriteLine($"IndexOfAny([',', '.']): {text.IndexOfAny([',', '.'])}");
Console.WriteLine($"Contains(\"раму\"):     {text.Contains("раму")}");
Console.WriteLine($"StartsWith(\"мама\"):   {text.StartsWith("мама")}");
Console.WriteLine($"EndsWith(\"вікно\"):    {text.EndsWith("вікно")}");
Console.WriteLine($"Contains(\"марко\"):    {text.Contains("марко")}");

// усі входження: пошук з позиції після попереднього
Console.Write("усі 'м':");
int pos = text.IndexOf('м');
while (pos != -1)
{
    Console.Write($" {pos}");
    pos = text.IndexOf('м', pos + 1);
}
Console.WriteLine();

string? nothing = null;
Console.WriteLine($"IsNullOrEmpty(null): {string.IsNullOrEmpty(nothing)}, IsNullOrWhiteSpace(\"  \"): {string.IsNullOrWhiteSpace("  ")}");
```

```text

IndexOf('м', 1):      2
IndexOf("ми"):        5
LastIndexOf('м'):     24
IndexOf('ж'):         -1
IndexOfAny([',', '.']): 14
Contains("раму"):     True
StartsWith("мама"):   True
EndsWith("вікно"):    True
Contains("марко"):    False
усі 'м': 0 2 5 12 24
IsNullOrEmpty(null): True, IsNullOrWhiteSpace("  "): True
```
::

::field-group

::field{name="IndexOf(c) / IndexOf(c, start)" type="перший індекс"}
Індекс першого входження символу чи підрядка, або −1. Друга форма починає пошук з позиції `start` — так шукають усі входження циклом `while`, як у кінці програми.
::

::field{name="LastIndexOf(c)" type="останній індекс"}
Те саме, але шукає з кінця. `М` у слові «Марко» на індексі 18 не знайдено: регістр має значення.
::

::field{name="IndexOfAny(['…'])" type="будь-який з символів"}
Індекс першого символу з набору. Зручно для пошуку першого роздільника, коли їх кілька.
::

::field{name='Contains("…")' type="чи є підрядок"}
`true` або `false` без індексу. З урахуванням регістру: «марко» з маленької літери не знайдено.
::

::field{name='StartsWith("…") / EndsWith("…")' type="початок і кінець"}
Перевірка префікса і суфікса: розширення файлу, код країни в телефоні, протокол в адресі.
::

::field{name="string.IsNullOrEmpty / IsNullOrWhiteSpace" type="порожнеча"}
Статичні методи, які безпечно приймають `null`. Другий вважає порожнім і рядок з самих пробілів — так перевіряють введення користувача (лекція 07).
::

::

Регістр враховують усі методи пошуку, якщо не передати `StringComparison` — розділ [Порівняння рядків](#порівняння-рядків).

2. Після знахідки продовжуйте пошук з позиції `pos + target.Length`, щоб входження не перекривалися.
3. Порахуйте вдруге без урахування регістру: передайте в `IndexOf` третім аргументом `StringComparison.OrdinalIgnoreCase`.

Очікуваний вивід:

::terminal-preview{title="dotnet run count-word.cs"}

:::accordion-item{label="Розв'язок" icon="i-lucide-check-circle"}

```csharp [count-word.cs]
string text = "Мама мила раму, а мама Марка мила вікно";
string target = "ма";

int count = 0;
int pos = text.IndexOf(target, StringComparison.Ordinal);
while (pos != -1)
{
    count++;
    pos = text.IndexOf(target, pos + target.Length, StringComparison.Ordinal);
}
Console.WriteLine($"\"{target}\" з урахуванням регістру: {count}");

count = 0;
pos = text.IndexOf(target, StringComparison.OrdinalIgnoreCase);
while (pos != -1)
{
    count++;
    pos = text.IndexOf(target, pos + target.Length, StringComparison.OrdinalIgnoreCase);
}
Console.WriteLine($"\"{target}\" без урахування регістру: {count}");
```

З урахуванням регістру: одне «ма» у «Мама» і два в «мама». Без урахування додаються «Ма» на початку «Мама» і в «Марка». Склад «ма» у «мила» немає: там «ми».

## Вирізання і розбиття

### Substring, Split і Trim

Текст із зовнішніх джерел — дата, рядок CSV, список міст через кому — розбирають на частини трьома групами методів: вирізати частину за позицією, розбити за роздільником, прибрати зайве з країв:

```csharp [slicing.cs]
string date = "2026-11-26";
Console.WriteLine($"Substring(0, 4): {date.Substring(0, 4)}");
Console.WriteLine($"Substring(5, 2): {date.Substring(5, 2)}");
Console.WriteLine($"Substring(8):    {date.Substring(8)}");

string[] pieces = date.Split('-');
Console.WriteLine($"Split('-'): {pieces.Length} частини: {string.Join(" / ", pieces)}");

string messy = " Київ, Львів ,,Одеса ";
string[] raw = messy.Split(',');
Console.WriteLine($"Split(','): {raw.Length}: [{string.Join("][", raw)}]");
string[] clean = messy.Split(',', StringSplitOptions.RemoveEmptyEntries | StringSplitOptions.TrimEntries);
Console.WriteLine($"з опціями:  {clean.Length}: [{string.Join("][", clean)}]");

string sentence = "один два  три";
string[] words = sentence.Split([' '], StringSplitOptions.RemoveEmptyEntries);
Console.WriteLine($"слів: {words.Length}");

string padded = "   **Київ**   ";
Console.WriteLine($"Trim():          [{padded.Trim()}]");
Console.WriteLine($"TrimStart():     [{padded.TrimStart()}]");
Console.WriteLine($"Trim(' ', '*'):  [{padded.Trim(' ', '*')}]");
```

::terminal-preview{title="dotnet run slicing.cs"}

```text
Split('-'): 3 частини: 2026 / 11 / 26

з опціями:  3: [Київ][Львів][Одеса]
слів: 3
```

::field-group

::field{name="Substring(start, length)" type="частина"}
`length` символів, починаючи з індексу `start`. Другий аргумент — **довжина**, а не кінцевий індекс: `Substring(5, 2)` — символи 5 і 6.
::

::field{name="Substring(start)" type="до кінця"}
Від `start` до кінця рядка.
::

::field{name="Split(c)" type="розбиття"}
Масив частин між роздільниками. Роздільники в результат не потрапляють. Два роздільники поспіль дають порожній рядок між ними.
::

::field{name="Split(c, RemoveEmptyEntries | TrimEntries)" type="розбиття з опціями"}
`RemoveEmptyEntries` відкидає порожні частини, `TrimEntries` прибирає пробіли з країв кожної частини. Опції поєднуються оператором `|` (лекція 08).
::

::field{name="Split([' ', ','], …)" type="кілька роздільників"}
Масив роздільників: частина закінчується на будь-якому з них.
::

::field{name="Trim() / TrimStart() / TrimEnd()" type="краї"}
Прибирають пробільні символи (пробіл, табуляцію, перенесення рядка) з обох країв, з початку або з кінця. Пробіли всередині лишаються.
::

::field{name="Trim(' ', '*')" type="задані символи"}
Прибирає з країв будь-які з переданих символів, у будь-якій кількості й порядку.
::

::

Розбиття рядка з пробілами і подвійним роздільником:

## Методи, що повертають новий рядок

### Replace, Insert, Remove, регістр, вирівнювання

Лекція 05 показала, що рядок змінити неможливо, і `title.Replace(…)` без присвоєння нічого не робить. Методи «зміни» повертають новий рядок:

```csharp [modify.cs]
string phone = "050-123-45-67";
Console.WriteLine($"Replace('-', ' '):     {phone.Replace('-', ' ')}");
Console.WriteLine($"Replace(\"-\", \"\"):      {phone.Replace("-", "")}");
Console.WriteLine($"Insert(0, \"+38\"):      {phone.Insert(0, "+38")}");
Console.WriteLine($"Remove(3):             {phone.Remove(3)}");
Console.WriteLine($"Remove(3, 4):          {phone.Remove(3, 4)}");

string name = "Олена Коваль";
Console.WriteLine($"ToUpper():             {name.ToUpper()}");
Console.WriteLine($"ToLower():             {name.ToLower()}");

Console.WriteLine($"[{"7".PadLeft(3, '0')}] [{"кава".PadRight(8)}] [{"кава".PadLeft(8, '.')}]");

// ланцюжок: кожен метод повертає новий рядок, і наступний викликається на ньому
string input = "  НОВИЙ   звіт  ";
string result = input.Trim().ToLower().Replace("  ", " ").Replace("  ", " ");
Console.WriteLine($"ланцюжок: [{result}]");
Console.WriteLine($"input не змінився: [{input}]");
```

```text

Insert(0, "+38"):      +38050-123-45-67
Remove(3):             050
Remove(3, 4):          050-45-67
```

::field-group

::field{name="Replace(old, new)" type="заміна"}
Замінює **всі** входження символу чи підрядка. Заміна на `""` видаляє їх.
::

::field{name="Insert(index, text)" type="вставка"}
Вставляє текст перед символом з індексом `index`.
::

::field{name="Remove(start) / Remove(start, count)" type="видалення"}
Видаляє все від `start` до кінця або `count` символів, починаючи з `start`.
::

::field{name="ToUpper() / ToLower()" type="регістр"}
Усі літери у верхньому чи нижньому регістрі за правилами поточної культури. Для порівнянь регістр так не вирівнюють — для цього є `StringComparison`.
::

::field{name="PadLeft(n, c) / PadRight(n)" type="доповнення"}
Доповнює рядок символом (за замовчуванням пробілом) до довжини `n` зліва чи справа. Довший рядок не обрізається.
::

::field{name="a.Trim().ToLower().Replace(…)" type="ланцюжок"}
Кожен метод повертає рядок, тому наступний викликається одразу на результаті. Читається зліва направо як послідовність кроків.
::

::

Ланцюжок з чотирьох викликів створює чотири нові рядки. Початковий лишається незмінним, проміжні стають непотрібними одразу після наступного кроку:

Для коротких рядків і кількох викликів це непомітно. Для тисяч операцій у циклі проміжні рядки стають помітною роботою для збирача сміття — тоді рядок збирають у `StringBuilder`.

## Порівняння рядків

### ==, Equals і StringComparison

`==` для рядків порівнює вміст посимвольно, з урахуванням регістру (лекція 05). Для інших правил порівняння використовують методи з параметром `StringComparison`:

```csharp [compare.cs]
string a = "Київ";
string b = "КИЇВ";

Console.WriteLine($"a == b:                             {a == b}");
Console.WriteLine($"a.Equals(b, OrdinalIgnoreCase):     {a.Equals(b, StringComparison.OrdinalIgnoreCase)}");
Console.WriteLine($"string.Equals(a, b, CurrentCultureIgnoreCase): {string.Equals(a, b, StringComparison.CurrentCultureIgnoreCase)}");

// порядок: від'ємне — a раніше, 0 — рівні, додатне — a пізніше
Console.WriteLine($"Compare(\"груша\", \"яблуко\", Ordinal):   {string.Compare("груша", "яблуко", StringComparison.Ordinal)}");
Console.WriteLine($"Compare(\"яблуко\", \"їжак\", Ordinal):    {string.Compare("яблуко", "їжак", StringComparison.Ordinal)}");
Console.WriteLine($"Compare(\"a\", \"B\", Ordinal):            {string.Compare("a", "B", StringComparison.Ordinal)}");
Console.WriteLine($"Compare(\"a\", \"B\", InvariantCulture):   {string.Compare("a", "B", StringComparison.InvariantCulture)}");

// пошук з урахуванням регістру і без
string command = "Save File";
Console.WriteLine($"Contains(\"file\"):                     {command.Contains("file")}");
Console.WriteLine($"Contains(\"file\", OrdinalIgnoreCase):  {command.Contains("file", StringComparison.OrdinalIgnoreCase)}");
Console.WriteLine($"StartsWith(\"save\", OrdinalIgnoreCase): {command.StartsWith("save", StringComparison.OrdinalIgnoreCase)}");
```

::terminal-preview{title="dotnet run compare.cs"}
```text
a == b:                             False
a.Equals(b, OrdinalIgnoreCase):     True
string.Equals(a, b, CurrentCultureIgnoreCase): True
Compare("груша", "яблуко", Ordinal):   -28
Compare("яблуко", "їжак", Ordinal):    -8
Compare("a", "B", Ordinal):            31
Compare("a", "B", InvariantCulture):   -1
Contains("file"):                     False
Contains("file", OrdinalIgnoreCase):  True
StartsWith("save", OrdinalIgnoreCase): True
```
::

`string.Compare` повертає число, у якого має значення лише знак: від'ємне — перший рядок іде раніше, нуль — рядки рівні, додатне — пізніше. Саме значення залежить від способу порівняння: −28 — це різниця кодів `г` і `я`.

::field-group

::field{name="Ordinal" type="за кодами символів"}
Посимвольне порівняння кодів UTF-16. Найшвидше і передбачуване: результат не залежить від машини. `a` (код 97) іде після `B` (код 66), а `ї` — після `я`.
::

::field{name="OrdinalIgnoreCase" type="за кодами, без регістру"}
Те саме, але `К` і `к` вважаються рівними. Для ідентифікаторів, команд, ключів налаштувань, імен файлів і розширень.
::

::field{name="CurrentCulture" type="за правилами культури"}
Порядок, яким його бачить людина з мовою поточної культури: `a` перед `B`, `ґ` після `г`, `є` після `е`. Для сортування і порівняння тексту, який читає користувач.
::

::field{name="CurrentCultureIgnoreCase" type="культура, без регістру"}
Порівняння тексту для людини без урахування регістру.
::

::field{name="InvariantCulture" type="незмінна культура"}
Правила культури, які не залежать від налаштувань машини. Для даних, які мають сортуватися однаково всюди.
::

::

### Порівняння за замовчуванням

Не всі методи `string` порівнюють однаково, якщо `StringComparison` не передано. Частина порівнює за кодами, частина — за правилами культури, а культура по-різному обробляє «невидимі» символи. Приклад — м'який перенос (U+00AD), який часто приходить разом з текстом, скопійованим із сайту:

```csharp [culture-search.cs]
using System.Globalization;

CultureInfo.CurrentCulture = CultureInfo.GetCultureInfo("uk-UA");

// м'який перенос U+00AD: невидимий символ, який часто приходить разом з текстом, скопійованим із сайту
string pasted = "інфор\u00ADмація";
string word = "інформація";

Console.WriteLine($"Length: {pasted.Length} і {word.Length}");
Console.WriteLine($"pasted == word:                   {pasted == word}");
Console.WriteLine($"Contains(word):                   {pasted.Contains(word)}");
Console.WriteLine($"IndexOf(word):                    {pasted.IndexOf(word)}");
Console.WriteLine($"IndexOf(word, Ordinal):           {pasted.IndexOf(word, StringComparison.Ordinal)}");
Console.WriteLine($"StartsWith(word):                 {pasted.StartsWith(word)}");
Console.WriteLine($"StartsWith(word, Ordinal):        {pasted.StartsWith(word, StringComparison.Ordinal)}");
Console.WriteLine($"string.Compare(pasted, word):     {string.Compare(pasted, word)}");
```

::terminal-preview{title="dotnet run culture-search.cs"}
```text
Length: 11 і 10
pasted == word:                   False
Contains(word):                   False
IndexOf(word):                    0
IndexOf(word, Ordinal):           -1
StartsWith(word):                 True
StartsWith(word, Ordinal):        False
string.Compare(pasted, word):     0
```
::

Рядки відрізняються одним невидимим символом. `==` і `Contains` порівнюють коди і бачать різницю. `IndexOf(string)`, `StartsWith(string)` і `string.Compare` без `StringComparison` порівнюють за культурою, а культура м'який перенос ігнорує: для неї рядки однакові. У програмі, яка в одному місці перевіряє `Contains`, а в іншому `IndexOf`, такі розбіжності дають помилки, які важко знайти.

| Порівнюють за кодами (ordinal) | Порівнюють за культурою |
|---|---|
| `==`, `Equals(string)` | `IndexOf(string)`, `LastIndexOf(string)` |
| `Contains(string)` | `StartsWith(string)`, `EndsWith(string)` |
| `Replace(string, string)` | `string.Compare`, `CompareTo` |
| `IndexOf(char)`, `Split` | `ToUpper()`, `ToLower()`, `Array.Sort(string[])` |

::callout{icon="i-lucide-lightbulb"}
**Як порівнювати рядки**

- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **Передавайте `StringComparison` явно** в `IndexOf`, `StartsWith`, `EndsWith`, `Equals`, `Compare`: тоді правило порівняння видно в коді, а не залежить від методу.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`Ordinal` / `OrdinalIgnoreCase`** — команди, ключі, ідентифікатори, шляхи, розширення файлів, усе, що читає програма.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **`CurrentCulture`** — сортування і пошук у тексті, який читає людина: імена, назви, слова.
- :icon{name="i-lucide-circle-x" class="inline-block text-red-500"} **Не порівнюйте через `a.ToLower() == b.ToLower()`**: створюються два нові рядки, а результат залежить від культури (поглиблений розділ про турецьку I).

::

::::accordion

:::accordion-item{label="Спробуйте: команди без урахування регістру" icon="i-lucide-clipboard-list"}

1. Для введень `"EXIT"`, `"Help"`, `"save"`, `"  help  "` визначте команду: `help` — «довідка», `exit` — «вихід», інше — «невідома команда».
2. Пробіли з країв прибирайте `Trim`, регістр ігноруйте через `Equals` з `StringComparison.OrdinalIgnoreCase`, без `ToLower`.

Очікуваний вивід:

## StringBuilder

### Чому += у циклі повільно

`s += "x"` створює новий рядок довжиною `s.Length + 1` і копіює в нього весь старий рядок. На кожному кроці циклу копіюється все, що вже накопичено. `StringBuilder` з простору імен `System.Text` тримає символи в буфері з запасом місця і дописує новий символ у вільну клітинку:

  <source src="/videos/csharp/fundamentals/strings/anim-01-append.mp4" type="video/mp4">
  <source src="/videos/csharp/fundamentals/strings/anim-01-append.webm" type="video/webm">
</video>

Скільки це коштує насправді, вимірює програма: `n` разів дописати `"x"` двома способами, заміряти час (`Stopwatch`, лекція 10) і кількість виділених байтів (`GC.GetAllocatedBytesForCurrentThread`):

```csharp [concat-vs-builder.cs]
// Замір: склеювання += проти StringBuilder. Запускати з -c Release.
using System.Diagnostics;
using System.Text;

int[] sizes = [5_000, 10_000, 20_000, 40_000];
Concat(100);    // прогрів: перший виклик включає роботу JIT
Builder(100);

foreach (int n in sizes)
{
    long before = GC.GetAllocatedBytesForCurrentThread();
    var sw = Stopwatch.StartNew();
    string s1 = Concat(n);
    sw.Stop();
    long concatBytes = GC.GetAllocatedBytesForCurrentThread() - before;
    double concatMs = sw.Elapsed.TotalMilliseconds;

    before = GC.GetAllocatedBytesForCurrentThread();
    sw.Restart();
    string s2 = Builder(n);
    sw.Stop();
    long builderBytes = GC.GetAllocatedBytesForCurrentThread() - before;
    double builderMs = sw.Elapsed.TotalMilliseconds;

    Console.WriteLine($"n = {n,6}: += {concatMs,7:F1} мс, {concatBytes / 1_000_000.0,7:F1} МБ | " +
                      $"StringBuilder {builderMs,4:F2} мс, {builderBytes / 1_000_000.0,4:F2} МБ | однакові: {s1 == s2}");
}

static string Concat(int n)
{
    string result = "";
    for (int i = 0; i < n; i++)
        result += "x";
    return result;
}

static string Builder(int n)
{
    var sb = new StringBuilder();
    for (int i = 0; i < n; i++)
        sb.Append("x");
    return sb.ToString();
}
```

```text
n =  10000: +=     4.0 мс,   100.3 МБ | StringBuilder 0.31 мс, 0.05 МБ | однакові: True
n =  20000: +=    13.2 мс,   400.5 МБ | StringBuilder 0.05 мс, 0.09 МБ | однакові: True
n =  40000: +=    49.6 мс,  1601.0 МБ | StringBuilder 0.07 мс, 0.16 МБ | однакові: True
```
::

![Два графіки для n від 5 000 до 40 000: час += росте від 1,4 до 49,6 мс, виділена пам'ять — від 25 до 1601 МБ; StringBuilder лишається біля нуля: 0,07 мс і 0,16 МБ для n = 40 000](/images/csharp/fundamentals/strings/05-concat-vs-builder.png){.wide-img}

- **Пам'ять `+=` зростає вчетверо, коли `n` подвоюється**: 25 → 100 → 400 → 1601 МБ. На кроці `i` створюється рядок з `i` символів, разом 1 + 2 + … + n = n(n + 1)/2 символів по 2 байти. Для n = 10 000 це 100 мільйонів байтів — саме стільки й виміряно.
- **Час `+=` росте приблизно так само**: копіювання і збирання сміття пропорційні кількості виділених байтів.
- **`StringBuilder` виділяє кілобайти і працює за десяті частки мілісекунди**. Його часи нижче мілісекунди — на рівні похибки `Stopwatch`, тому 0,31 мс для n = 10 000 більше за 0,05 мс для n = 20 000 — це шум, а не закономірність.

Чому компілятор сам не замінює `+=` у циклі на `StringBuilder`? Він не знає, скільки ітерацій буде і чи використовується проміжний рядок десь іще. Склеювання в одному виразі (`a + b + c + d`) він оптимізує сам — в один виклик `string.Concat`.

### Методи StringBuilder

```csharp [builder.cs]
using System.Text;

var sb = new StringBuilder();
sb.Append("Звіт");
sb.Append(' ');
sb.Append(2026);
sb.AppendLine();
sb.AppendLine("рядок 1");
sb.Append($"рядок {1 + 1}");
Console.WriteLine(sb.ToString());
Console.WriteLine($"Length: {sb.Length}");

sb.Clear();
sb.Append("кіт");
sb.Insert(0, "сірий ");
sb.Replace("кіт", "пес");
sb[0] = 'С';                  // StringBuilder можна змінювати за індексом
Console.WriteLine(sb);

// кома між елементами: прибрати останню після циклу
int[] scores = [90, 75, 60];
var csv = new StringBuilder();
foreach (int s in scores)
{
    csv.Append(s).Append(',');
}
csv.Length--;                 // відкинути останній символ
Console.WriteLine(csv);
```

::terminal-preview{title="dotnet run builder.cs"}
```text
Звіт 2026
рядок 1
рядок 2
Length: 25
Сірий пес
90,75,60
```

`Length: 25` виміряно на macOS, де `AppendLine` дописує один символ `\n`. На Windows перенесення рядка — два символи `\r\n`, і `Length` буде 27.

::field-group

::field{name="Append(x)" type="дописати"}
Дописує рядок, символ, число чи будь-яке інше значення в кінець. Повертає той самий `StringBuilder`, тому виклики можна ланцюжити: `csv.Append(s).Append(',')`.
::

::field{name="AppendLine() / AppendLine(text)" type="рядок"}
Дописує текст і перенесення рядка `Environment.NewLine`.
::

::field{name='Append($"…")' type="інтерполяція"}
Інтерполяція в `Append` записується прямо в буфер, без проміжного рядка.
::

::field{name="Insert, Remove, Replace" type="зміна на місці"}
Ті самі операції, що в `string`, але змінюють сам буфер, а не створюють новий об'єкт.
::

::field{name="sb[i] = c" type="індексатор"}
На відміну від `string`, індексатор `StringBuilder` дозволяє запис.
::

::field{name="Length, Clear()" type="довжина"}
`Length` можна зменшити: `Length--` відкидає останній символ. `Clear()` робить довжину нульовою, і буфер використовується знову.
::

::field{name="ToString()" type="результат"}
Створює звичайний рядок з поточного вмісту. `Console.WriteLine(sb)` викликає його сам.
::

Буфер росте сам. Програма дописує символи по одному і друкує ємність (*capacity*) щоразу, коли вона змінюється:

```csharp [capacity.cs]
using System.Text;

var sb = new StringBuilder();
int capacity = sb.Capacity;
Console.Write($"Capacity: {capacity}");
for (int i = 0; i < 200; i++)
{
    sb.Append('x');
    if (sb.Capacity != capacity)
    {
        capacity = sb.Capacity;
        Console.Write($" → {capacity} (Length {sb.Length})");
    }
}
Console.WriteLine();
```

::terminal-preview{title="dotnet run capacity.cs"}
```text
Capacity: 16 → 32 (Length 17) → 64 (Length 33) → 128 (Length 65) → 256 (Length 129)
```

Ємність подвоюється щоразу, коли місце закінчується. Тому на 200 дописаних символів припадає лише чотири розширення, а не 200 нових об'єктів, як у `+=`. Якщо розмір результату відомий заздалегідь, його передають у конструктор: `new StringBuilder(1000)`.

::callout{icon="i-lucide-lightbulb"}
**Коли StringBuilder**

- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **Текст збирається в циклі** з невідомою або великою кількістю частин: звіти, CSV, HTML, лог.
- :icon{name="i-lucide-circle-check" class="inline-block text-green-500"} **Текст змінюється багато разів**: вставки, заміни, видалення в одному буфері.
- :icon{name="i-lucide-circle-x" class="inline-block text-red-500"} **Не потрібен** для кількох частин в одному виразі: інтерполяція чи `a + b + c` коротші й не повільніші.
- :icon{name="i-lucide-circle-x" class="inline-block text-red-500"} **Не потрібен** для склеювання масиву через роздільник: `string.Join` зробить це сам.

### Unicode: сурогатні пари і комбіновані символи

`char` — 16 бітів, а кодових точок у Unicode понад мільйон. Символи з кодом більшим за U+FFFF (частина ієрогліфів, математичні й нотні знаки, емодзі) займають два `char` — сурогатну пару (*surrogate pair*). Деякі літери можна записати і одним символом, і базовою літерою з комбінованим знаком:

```csharp [unicode.cs]
// Поглиблений розділ: char — одиниця UTF-16, а не «літера».
using System.Globalization;
using System.Text;

string clef = "\U0001D11E";               // скрипковий ключ, U+1D11E
Console.WriteLine($"{clef}: Length {clef.Length}, char: {(int)clef[0]:X4} {(int)clef[1]:X4}");
Console.WriteLine($"IsSurrogate(clef[0]): {char.IsSurrogate(clef[0])}");

Rune rune = Rune.GetRuneAt(clef, 0);
Console.WriteLine($"Rune: U+{rune.Value:X}, Utf16SequenceLength {rune.Utf16SequenceLength}");

string composed = "й";                     // одна кодова точка U+0439
string decomposed = "и\u0306";             // и + комбінований знак бреве U+0306
Console.WriteLine($"composed: Length {composed.Length}, decomposed: Length {decomposed.Length}");
Console.WriteLine($"composed == decomposed: {composed == decomposed}");
Console.WriteLine($"після Normalize(): {composed == decomposed.Normalize()}");
Console.WriteLine($"StringInfo: {new StringInfo(decomposed).LengthInTextElements} текстовий елемент");

string word = "Андріи\u0306" + clef;   // «Андрій» з розкладеною й і ключ
Console.WriteLine($"{word}: Length {word.Length}, Runes {word.EnumerateRunes().Count()}, " +
                  $"текстових елементів {new StringInfo(word).LengthInTextElements}");
```

::terminal-preview{title="dotnet run unicode.cs"}
```text
𝄞: Length 2, char: D834 DD1E
IsSurrogate(clef[0]): True
Rune: U+1D11E, Utf16SequenceLength 2
composed: Length 1, decomposed: Length 2
composed == decomposed: False
після Normalize(): True
StringInfo: 1 текстовий елемент
Андрій𝄞: Length 9, Runes 8, текстових елементів 7
```
::

![Як символи лежать у рядку UTF-16: К (U+041A) — один char 041A; скрипковий ключ U+1D11E — сурогатна пара D834 DD1E, Length 2, одна Rune; й складена U+0439 — один char; й розкладена U+0438 + U+0306 — два char, один текстовий елемент](/images/csharp/fundamentals/strings/06-utf16.png){.diagram-img}

- **`Length` рахує `char`**, а не літери: скрипковий ключ — 2, розкладена `й` — 2.
- **`Rune`** (`System.Text`) — одна кодова точка Unicode. `EnumerateRunes()` перебирає рядок по кодових точках і правильно складає сурогатні пари.
- **Текстовий елемент** — те, що людина бачить як один символ. `StringInfo.LengthInTextElements` рахує саме їх: «Андрій» з розкладеною `й` і ключ — 7.
- **`Normalize()`** приводить рядок до складеної форми (NFC): після неї розкладена `й` дорівнює складеній. Текст з різних джерел (файли, буфер обміну, веб-форми) перед порівнянням нормалізують.

Наслідок для коду з цієї лекції: розворот рядка через `ToCharArray` і `Array.Reverse` розриває сурогатні пари і відриває комбіновані знаки від літер. Для тексту людською мовою перебирають текстові елементи (`StringInfo.GetTextElementEnumerator`), а не `char`.

### ToUpper, ToLower і турецька I

Зміна регістру — теж операція культури. У турецькій мові є дві різні літери i: з крапкою (`i` / `İ`) і без (`ı` / `I`):

```csharp [turkish.cs]
// Поглиблений розділ: ToUpper і ToLower залежать від культури.
using System.Globalization;

CultureInfo tr = CultureInfo.GetCultureInfo("tr-TR");
CultureInfo uk = CultureInfo.GetCultureInfo("uk-UA");

Console.WriteLine($"\"file\".ToUpper(uk):  {"file".ToUpper(uk)}");
Console.WriteLine($"\"file\".ToUpper(tr):  {"file".ToUpper(tr)}");
Console.WriteLine($"\"FILE\".ToLower(tr):  {"FILE".ToLower(tr)}");
Console.WriteLine($"ToUpperInvariant:    {"file".ToUpperInvariant()}");

CultureInfo.CurrentCulture = tr;
string command = "file";
Console.WriteLine($"tr-TR: command.ToUpper() == \"FILE\": {command.ToUpper() == "FILE"}");
Console.WriteLine($"tr-TR: Equals(\"FILE\", OrdinalIgnoreCase): {command.Equals("FILE", StringComparison.OrdinalIgnoreCase)}");
```

::terminal-preview{title="dotnet run turkish.cs"}
```text
"file".ToUpper(uk):  FILE
"file".ToUpper(tr):  FİLE
"FILE".ToLower(tr):  fıle
ToUpperInvariant:    FILE
tr-TR: command.ToUpper() == "FILE": False
tr-TR: Equals("FILE", OrdinalIgnoreCase): True
```
::

Програма, яка перевіряє команду через `command.ToUpper() == "FILE"`, на комп'ютері з турецькою культурою не впізнає команду `file`: `ToUpper()` дає `FİLE` з крапкою над I. `Equals` з `OrdinalIgnoreCase` від культури не залежить. Для ідентифікаторів регістр змінюють `ToUpperInvariant()` / `ToLowerInvariant()`, а порівнюють — через `StringComparison`.

### Розбір без проміжних рядків

`Substring` створює новий рядок у купі. Для розбору дати `"2026-11-26"` на три числа це три зайві об'єкти, які потрібні лише на мить. `ReadOnlySpan<char>` — вікно в той самий рядок, як `Span<T>` для масиву (лекція 11), а `int.Parse` уміє читати число прямо з нього:

```csharp [span-parse.cs]
// Поглиблений розділ: розбір дати без проміжних рядків через ReadOnlySpan<char>.
string date = "2026-11-26";
Parse(date);    // прогрів
ParseSpan(date);

long before = GC.GetAllocatedBytesForCurrentThread();
for (int i = 0; i < 1000; i++)
    Parse(date);
long substringBytes = GC.GetAllocatedBytesForCurrentThread() - before;

before = GC.GetAllocatedBytesForCurrentThread();
for (int i = 0; i < 1000; i++)
    ParseSpan(date);
long spanBytes = GC.GetAllocatedBytesForCurrentThread() - before;

Console.WriteLine($"Parse:     {Parse(date)}, 1000 разів: {substringBytes} Б");
Console.WriteLine($"ParseSpan: {ParseSpan(date)}, 1000 разів: {spanBytes} Б");

static (int, int, int) Parse(string s)
{
    int year = int.Parse(s.Substring(0, 4));     // Substring створює новий рядок
    int month = int.Parse(s.Substring(5, 2));
    int day = int.Parse(s.Substring(8, 2));
    return (year, month, day);
}

static (int, int, int) ParseSpan(string s)
{
    ReadOnlySpan<char> span = s.AsSpan();
    int year = int.Parse(span[..4]);              // вікно в той самий рядок
    int month = int.Parse(span.Slice(5, 2));
    int day = int.Parse(span[8..]);
    return (year, month, day);
}
```

::terminal-preview{title="dotnet run span-parse.cs"}
```text
Parse:     (2026, 11, 26), 1000 разів: 96000 Б
ParseSpan: (2026, 11, 26), 1000 разів: 0 Б
```
::

Кожен виклик `Parse` виділяє 96 байтів: три маленькі рядки по 32 байти (16 службових, 4 на довжину, символи і завершальний `\0` з вирівнюванням — лекція 05). `ParseSpan` не виділяє нічого: діапазони `[..4]` і `[8..]` над span дають вікна, а не копії. На одній даті різниця непомітна, на мільйонах рядків лог-файлу — це мегабайти, які не доведеться прибирати збирачу сміття.

## Питання для самоперевірки

::::accordion

:::accordion-item{label="Чому s[0] = 'x' не компілюється і як отримати рядок з іншою першою літерою?" icon="i-lucide-help-circle"}

Рядок незмінний, тому індексатор `string` має лише `get` (CS0200). Новий рядок створюють: `char[] a = s.ToCharArray(); a[0] = 'x'; s = new string(a);`, або `s = "x" + s.Substring(1);`, або через `StringBuilder`, індексатор якого дозволяє запис.

:::

:::accordion-item{label="Чим Substring(5, 2) відрізняється від запису діапазону з початком і кінцем?" icon="i-lucide-help-circle"}

Другий аргумент `Substring` — довжина: `Substring(5, 2)` — два символи з індексами 5 і 6. Якщо `start + length` виходить за межі рядка, кидається `ArgumentOutOfRangeException`, а не обрізається до кінця, як у `substr` з C++.

:::

:::accordion-item{label="Що дає Split на рядку з двома роздільниками поспіль і як цього уникнути?" icon="i-lucide-help-circle"}

Між двома роздільниками — порожня частина, тому в масиві з'являється `""`. Опція `StringSplitOptions.RemoveEmptyEntries` відкидає порожні частини, а `TrimEntries` прибирає пробіли з країв кожної частини.

:::

:::accordion-item{label="Чому title.Replace без присвоєння нічого не змінює?" icon="i-lucide-help-circle"}

`Replace`, як і `ToUpper`, `Trim`, `Insert`, `Remove`, повертає новий рядок і не змінює наявний. Якщо результат не записати в змінну, він губиться, а `title` веде до старого рядка. Правильно: `title = title.Replace(…)`.

:::

:::accordion-item{label="Чому Contains і IndexOf можуть дати різні відповіді для тих самих рядків?" icon="i-lucide-help-circle"}

Без `StringComparison` `Contains(string)` порівнює за кодами символів, а `IndexOf(string)` — за правилами поточної культури. Культура ігнорує деякі невидимі символи, наприклад м'який перенос, тому `IndexOf` знаходить слово, а `Contains` — ні. Явний `StringComparison` прибирає розбіжність.

:::

:::accordion-item{label="Коли порівнювати рядки Ordinal, а коли CurrentCulture?" icon="i-lucide-help-circle"}

`Ordinal` і `OrdinalIgnoreCase` — для всього, що читає програма: команди, ключі, ідентифікатори, шляхи, розширення файлів. Порівняння швидке і не залежить від машини. `CurrentCulture` — для тексту, який читає людина: сортування імен і слів, пошук у тексті. Тоді `ґ` стоїть після `г`, а не після `я`.

:::

:::accordion-item{label="Чому пам'ять += у циклі зростає вчетверо при подвоєнні кількості ітерацій?" icon="i-lucide-help-circle"}

Рядок незмінний, тому на кроці `i` створюється новий рядок з `i` символів і в нього копіюється весь попередній. Разом 1 + 2 + … + n = n(n + 1)/2 символів, тобто квадратична залежність: удвічі більше `n` — учетверо більше пам'яті. `StringBuilder` дописує в буфер з запасом, і пам'ять росте лінійно.

:::

:::accordion-item{label="Як росте буфер StringBuilder?" icon="i-lucide-help-circle"}

Початкова ємність — 16 символів. Коли місце закінчується, ємність подвоюється: 16 → 32 → 64 → 128 → 256. Тому на 200 символів буфер розширюється лише чотири рази. Якщо розмір результату відомий, його передають у конструктор.

:::

:::accordion-item{label="Чому Length рядка не завжди дорівнює кількості літер?" icon="i-lucide-help-circle"}

`Length` рахує одиниці UTF-16 (`char`). Кирилиця й латиниця займають по одному `char`, але символи з кодом понад U+FFFF займають два (сурогатна пара), а літера з комбінованим знаком, наприклад розкладена `й`, — два `char` на одну видиму літеру. Видимі символи рахує `StringInfo.LengthInTextElements`.

:::

## Шпаргалка

| Запис | Що робить | Приклад |
|---|---|---|
| `s.Length`, `s[i]` | довжина в `char`, символ за індексом (лише читання) | `s[s.Length - 1]` |
| `new string(c, n)` | `n` повторень символу | `new string('-', 12)` |
| `string.Join(sep, items)` | елементи через роздільник | `string.Join(", ", parts)` |
| `IndexOf`, `LastIndexOf` | індекс входження або −1 | `s.IndexOf('-', start)` |
| `Contains`, `StartsWith`, `EndsWith` | перевірка підрядка, початку, кінця | `name.EndsWith(".cs", StringComparison.OrdinalIgnoreCase)` |
| `Substring(start, length)` | частина рядка, другий аргумент — довжина | `date.Substring(5, 2)` |
| `Split(sep, options)` | масив частин | `RemoveEmptyEntries \| TrimEntries` |
| `Trim`, `TrimStart`, `TrimEnd` | прибрати символи з країв | `s.Trim(' ', '*')` |
| `Replace`, `Insert`, `Remove` | новий рядок зі зміною | `phone.Replace("-", "")` |
| `PadLeft`, `PadRight` | доповнити до довжини | `"7".PadLeft(3, '0')` |
| `string.IsNullOrWhiteSpace` | `null`, порожній або з пробілів | перевірка введення |
| `StringComparison.Ordinal(IgnoreCase)` | порівняння за кодами | команди, ключі, шляхи |
| `StringComparison.CurrentCulture` | порівняння за правилами мови | сортування імен |
| `StringBuilder` | змінюваний буфер для збирання тексту | `sb.Append(x).AppendLine()` |
| CS0200 | запис у `s[i]` | новий рядок або `StringBuilder` |

4. Письмово: чому розв'язок з двома індексами краще, ніж `ToLower()`, `Replace(" ", "")` і порівняння з розвернутою копією? Скільки рядків створив би другий спосіб для однієї фрази?

:::accordion-item{label="Розв'язок завдання 1" icon="i-lucide-check-circle"}

```csharp [palindrome.cs]
string[] phrases = ["Я несу гусеня", "Козак з казок!", "Київ — столиця", "А"];
foreach (string phrase in phrases)
{
    Console.WriteLine($"{phrase,-16} → {IsPalindrome(phrase)}");
}

static bool IsPalindrome(string text)
{
    int left = 0;
    int right = text.Length - 1;
    while (left < right)
    {
        if (!char.IsLetter(text[left]))
        {
            left++;
            continue;
        }
        if (!char.IsLetter(text[right]))
        {
            right--;
            continue;
        }
        if (char.ToLowerInvariant(text[left]) != char.ToLowerInvariant(text[right]))
            return false;
        left++;
        right--;
    }
    return true;
}
```

::terminal-preview{title="dotnet run palindrome.cs"}
```text
Я несу гусеня    → True
Козак з казок!   → True
Київ — столиця   → False
А                → True
```
::

Індекси сходяться до середини, і кожна пара літер порівнюється один раз. Нових рядків не створюється, а на першій розбіжності метод одразу повертає `false`. Спосіб з копіями створив би щонайменше три нові рядки: після `ToLower`, після кожного `Replace` для пробілів і знаків, і розвернуту копію. Для однієї фрази це непомітно, для мільйона рядків — мільйони зайвих об'єктів. `continue` для пропущеного символу повертає до умови `while` і не чіпає другий індекс (лекція 10).

4. Письмово: чому в цьому форматі поля розділено `;`, а не `,`? Що станеться з розбором, якщо в середині прізвища трапиться `;`?

```csharp [grades-csv.cs]
using System.Globalization;

CultureInfo.CurrentCulture = CultureInfo.GetCultureInfo("uk-UA");

string[] lines =
[
    "Коваль;Олена;10,12,11",
    "Шевчук;Тарас;8,9",
    "Бондар;Ірина;12,10,11,12",
];

Console.WriteLine($"{"Прізвище",-10}{"Ім'я",-8}{"Оцінок",7}{"Середня",9}");
Console.WriteLine(new string('-', 34));
foreach (string line in lines)
{
    string[] fields = line.Split(';');
    string[] marks = fields[2].Split(',');
    int sum = 0;
    foreach (string mark in marks)
        sum += int.Parse(mark);
    double average = (double)sum / marks.Length;
    Console.WriteLine($"{fields[0],-10}{fields[1],-8}{marks.Length,7}{average,9:F2}");
}
```

:::accordion-item{label="Розв'язок завдання 3" icon="i-lucide-check-circle"}

```csharp [initials.cs]
string[] inputs = ["  олена   петрівна   КОВАЛЬ ", "тарас григорович шевченко", "Ірина Бондар"];
foreach (string input in inputs)
{
    string[] parts = input.Split(' ', StringSplitOptions.RemoveEmptyEntries);
    string surname = Capitalize(parts[^1]);
    string initials = "";
    for (int i = 0; i < parts.Length - 1; i++)
    {
        initials += $" {char.ToUpper(parts[i][0])}.";
    }
    Console.WriteLine($"[{input}] → {surname}{initials}");
}

static string Capitalize(string word) => char.ToUpper(word[0]) + word.Substring(1).ToLower();
```

::terminal-preview{title="dotnet run initials.cs"}
```text
[  олена   петрівна   КОВАЛЬ ] → Коваль О. П.
[тарас григорович шевченко] → Шевченко Т. Г.
[Ірина Бондар] → Бондар І.
```

`parts[^1]` — останній елемент масиву (лекція 11), `parts[i][0]` — перший символ слова. Для одного слова цикл не виконається, і результатом буде лише прізвище. Для порожнього рядка або рядка з пробілів `parts` — порожній масив, і `parts[^1]` кине `IndexOutOfRangeException`. Перед розбором перевіряють `string.IsNullOrWhiteSpace(input)`. `+=` тут допустимий: частин дві-три, а не тисячі.
