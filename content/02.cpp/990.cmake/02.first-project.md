# Перший проєкт з CMake: конфігурація, збірка, запуск

::card-group

::card{title="🎯 Мета лекції" icon="i-lucide-target"}

- Створити мінімальний CMake-проєкт із одним файлом і зібрати його.
- Розрізняти етапи конфігурації та збірки й знати, яка команда за що відповідає.
- Розуміти, чому збірка виконується в окремій папці `build/`, і що в ній лежить.
- Вибирати генератор за допомогою прапорця `-G`.

::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Out-of-source build:** збірка, при якій згенеровані файли лежать окремо від вихідного коду.
- **Конфігурація (*configure*):** етап, на якому CMake читає `CMakeLists.txt` і генерує файли збірки.
- **Ціль (*target*):** результат збірки (виконуваний файл або бібліотека), який описується в `CMakeLists.txt`.
- **Кеш CMake:** файл `CMakeCache.txt` із запам'ятованими налаштуваннями.

::

::

У попередній лекції з'ясували, що CMake генерує файли для системи збірки. Тепер ця схема перевіряється на найменшому можливому проєкті: одна програма в одному файлі.

## Структура проєкту

Проєкт складається з двох файлів. У `main.cpp` лежить код програми, у `CMakeLists.txt` — опис того, як із нього зробити виконуваний файл.

::code-tree

```cpp [main.cpp]
#include <iostream>

int main() {
    std::cout << "Привіт, CMake!" << std::endl;
    std::cout << "Моя перша програма з CMake" << std::endl;
    return 0;
}
```

```cmake [CMakeLists.txt]
# Мінімальна версія CMake
cmake_minimum_required(VERSION 3.10)

# Назва проєкту
project(HelloCMake)

# Вказуємо стандарт C++
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED True)

# Створюємо виконуваний файл
add_executable(HelloCMake main.cpp)
```

::

Файл `CMakeLists.txt` має саме таку назву, з урахуванням регістру. CMake шукає його в папці, яку ви вказали як початкову.

## Розбір CMakeLists.txt рядок за рядком

Файл складається з чотирьох команд. Кожна команда CMake має вигляд `ім'я(аргументи)`.

```cmake
cmake_minimum_required(VERSION 3.10)
```

Задає найнижчу версію CMake, з якою проєкт гарантовано збереться. Якщо у користувача CMake старіший, він побачить зрозуміле повідомлення замість незрозумілих помилок про невідомі команди.

```cmake
project(HelloCMake)
```

Оголошує назву проєкту. Вона потрапляє в змінну `${PROJECT_NAME}` і в назви згенерованих файлів (наприклад, `HelloCMake.sln` у Visual Studio). Саме під час виклику `project()` CMake шукає компілятор.

```cmake
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED True)
```

Перша змінна вибирає стандарт C++ (допустимі значення: 11, 14, 17, 20, 23). Друга змінна забороняє «тихо» знижувати стандарт. Без неї старий компілятор мовчки збере проєкт зі старішим стандартом, і помилки з'являться лише в коді.

```cmake
add_executable(HelloCMake main.cpp)
```

Створює ціль: виконуваний файл `HelloCMake` (на Windows `HelloCMake.exe`), який збирається з `main.cpp`. Перший аргумент — ім'я цілі, далі йдуть джерела.

::note
Ім'я цілі й назва проєкту — різні речі. Тут вони збігаються для простоти, але `project(Shop)` може містити цілі `shop-server` і `shop-client`.
::

## Збірка проєкту

CMake рекомендує збирати проєкт в окремій папці, а не поруч з вихідними файлами. Такий підхід називають **out-of-source build**. Повний цикл складається з трьох кроків:

![Три кроки: конфігурація, збірка, запуск](/images/cpp/cmake/first-project/01-three-steps.png){.diagram-img}

::tabs

::tabs-item{label="Linux / macOS"}

```bash
# 1. Перейдіть у папку проєкту
cd HelloCMake

# 2. Згенеруйте файли збірки в папку build
cmake -S . -B build

# 3. Скомпілюйте
cmake --build build

# 4. Запустіть
./build/HelloCMake
```

::

::tabs-item{label="Windows"}

```bash
cd HelloCMake
cmake -S . -B build
cmake --build build --config Debug
.\build\Debug\HelloCMake.exe
```

З Visual Studio виконуваний файл лежить у підпапці конфігурації (`Debug` або `Release`). Причину пояснимо нижче, у розділі про multi-config генератори.

### Що робить кожна команда

1. **`cmake -S . -B build`** читає `CMakeLists.txt` із папки `.` (прапорець `-S`, source), визначає компілятор і створює файли збірки в папці `build` (прапорець `-B`, binary). Це етап **конфігурації**.
2. **`cmake --build build`** запускає ту систему збірки, для якої CMake згенерував файли (`make`, Ninja, MSBuild). Система компілює `.cpp` в об'єктні файли `.o` і лінкує їх у програму.
3. **`./build/HelloCMake`** запускає результат. Це вже звичайна програма, CMake у цьому не бере участі.

### Класичний варіант із `cd build`

Прапорці `-S` і `-B` з'явилися у CMake 3.13. У старіших матеріалах і на старих системах зустрінете такий запис:

```bash
mkdir build
cd build
cmake ..
make
```

Команда `cmake ..` робить те саме, що `cmake -S .. -B .`: джерела беруться з батьківської папки, а поточна папка стає папкою збірки. Обидва варіанти еквівалентні.

::tip
Команда `cmake --build` працює однаково з будь-яким генератором. Тому у скриптах і документації краще писати її замість `make` або `msbuild`: інструкція не залежить від платформи.
::

## Що лежить у папці build

Після конфігурації та збірки в `build/` з'являється таке:

| Об'єкт | Призначення |
|--------|-------------|
| `CMakeCache.txt` | Кеш налаштувань: шлях до компілятора, значення опцій, `CMAKE_BUILD_TYPE` |
| `CMakeFiles/` | Внутрішні службові файли CMake, об'єктні файли (`.o`) |
| `cmake_install.cmake` | Скрипт для команди `cmake --install` |
| `Makefile` | Згенерований файл для `make` (Linux, macOS) |
| `HelloCMake.sln` | Рішення Visual Studio (Windows, якщо обрано цей генератор) |
| `HelloCMake` | Готова програма |

Реальний склад залежить від генератора: з Visual Studio замість `Makefile` будуть `.sln` і `.vcxproj`, а з Ninja з'явиться `build.ninja`.

### Чому збірка виконується в окремій папці

- **Чисте дерево вихідного коду.** Файли збірки не змішуються з `.cpp` і `.h`, тому `git status` не засмічується.
- **Чиста збірка за секунду.** Папку `build/` можна видалити повністю, і наступна конфігурація почнеться з нуля. Видалення окремих згенерованих файлів серед вихідних було б ризикованим.
- **Кілька збірок одночасно.** Поруч можуть лежати `build-debug/` і `build-release/` з різними налаштуваннями, і вони не заважають одна одній.

::warning
Команда `cmake .` без `-B` виконує збірку **в самому дереві джерел** (*in-source build*). Усе згенероване змішується з кодом, а видалити його без `git clean` складно. Користуйтеся `-S` і `-B`.
::

## Одна команда замість кількох

Конфігурацію і збірку можна запустити в один рядок:

```bash
cmake -S . -B build && cmake --build build && ./build/HelloCMake
```

Оператор `&&` виконує наступну команду лише тоді, коли попередня завершилась успішно. Якщо конфігурація впала з помилкою, збірка не стартує.

## Вибір генератора

Якщо генератор не вказано, CMake обирає його сам: `Unix Makefiles` на Linux і macOS, найновіший Visual Studio на Windows. Явно вибрати можна прапорцем `-G`:

```bash
cmake -S . -B build -G "Ninja"
cmake -S . -B build -G "Unix Makefiles"
cmake -S . -B build -G "Visual Studio 17 2022"
cmake -S . -B build -G "Xcode"
```

Список доступних генераторів виводить команда `cmake --help` в її кінці.

### Генератори з однією і кількома конфігураціями

Генератори поділяються на два типи:

| Тип | Приклади | Де задається Debug/Release |
|-----|----------|----------------------------|
| Single-config | Makefiles, Ninja | На етапі конфігурації: `-DCMAKE_BUILD_TYPE=Release` |
| Multi-config | Visual Studio, Xcode, Ninja Multi-Config | На етапі збірки: `--config Release` |

Через це на Windows виконуваний файл лежить у `build/Debug/`, а на Linux прямо в `build/`. Детальніше про типи збірки йдеться в окремій лекції.

::warning
Якщо змінити генератор для вже існуючої папки `build`, CMake видасть помилку: «Does not match the generator used previously». Видаліть `build/` або вкажіть іншу папку.
::

## Типові помилки на першому проєкті

::::accordion

:::accordion-item{label="❓ CMake Error: The source directory does not appear to contain CMakeLists.txt" icon="i-lucide-help-circle"}

CMake не знайшов `CMakeLists.txt` у папці, яку ви вказали через `-S` (або в `..`). Перевірте, чи ви запускаєте команду з правильної папки і чи файл названий саме `CMakeLists.txt`: з великих літер, у множині, без зайвого розширення `.txt.txt`.

:::

:::accordion-item{label="❓ No CMAKE_CXX_COMPILER could be found" icon="i-lucide-help-circle"}

У системі немає компілятора C++ або він не доступний у `PATH`. Встановіть компілятор (див. першу лекцію розділу), а потім видаліть `build/` і повторіть конфігурацію, бо CMake запам'ятав невдалий результат пошуку в кеші.

:::

:::accordion-item{label="❓ Я змінив CMakeLists.txt. Треба знову викликати cmake -S . -B build?" icon="i-lucide-help-circle"}

Ні. Достатньо `cmake --build build`: система збірки помітить, що `CMakeLists.txt` змінився, і сама повторно запустить конфігурацію. Окремий виклик `cmake -S . -B build` потрібен, коли ви хочете передати нові опції (`-D...`) або змінити генератор.

:::

:::accordion-item{label="❓ Чому на Windows немає файлу build/HelloCMake.exe?" icon="i-lucide-help-circle"}

Visual Studio є multi-config генератором, тому файл лежить у підпапці конфігурації: `build\Debug\HelloCMake.exe`. Щоб зібрати Release, виконайте `cmake --build build --config Release`, і файл з'явиться в `build\Release\`.

:::

## Практичне завдання

::::accordion

:::accordion-item{label="📋 Завдання: перша збірка" icon="i-lucide-clipboard-list"}

1. Створіть папку `HelloCMake` із двома файлами: `main.cpp` і `CMakeLists.txt` з цієї лекції.
2. Змініть повідомлення в `main.cpp` на власне.
3. Збудуйте проєкт у папці `build`, запустіть програму.
4. Видаліть папку `build` і повторіть збірку однією командою.
5. Змініть стандарт C++ на 20 і знову зберіть проєкт. Переконайтеся, що збірка проходить.

:::

:::accordion-item{label="✅ Перевірка" icon="i-lucide-check-circle"}

Після кроку 4 усе повинно збиратися з нуля без помилок, і це доводить, що в `build/` немає нічого, що не можна відтворити. Якщо компілятор у вас старий і не підтримує C++20, завдяки `CMAKE_CXX_STANDARD_REQUIRED` CMake зупиниться з помилкою замість мовчазного пониження стандарту.

:::

## Резюме

::card-group

::card{title="📄 Мінімальний проєкт" icon="i-lucide-file-code"}
Чотири команди в `CMakeLists.txt`: `cmake_minimum_required`, `project`, стандарт C++ і `add_executable`.
::

::card{title="🔁 Два етапи" icon="i-lucide-repeat"}
`cmake -S . -B build` генерує файли, `cmake --build build` компілює. Запуск програми від CMake не залежить.
::

::card{title="🗂️ Окрема папка" icon="i-lucide-folder"}
Out-of-source збірка тримає код чистим, дозволяє видалити `build/` і мати кілька збірок поруч.
::

::card{title="🧰 Генератори" icon="i-lucide-wrench"}
Прапорець `-G` вибирає систему збірки. Single-config і multi-config генератори по-різному задають Debug і Release.
::

::

::note
У наступній лекції розглянемо синтаксис `CMakeLists.txt` докладніше: команди `project`, `set`, `message`, вбудовані змінні, списки і коментарі.
::
