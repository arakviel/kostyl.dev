# Бібліотеки в CMake: STATIC, SHARED, INTERFACE та видимість PUBLIC/PRIVATE

::card-group

::card{title="🎯 Мета лекції" icon="i-lucide-target"}

- Розрізняти статичні, динамічні та header-only бібліотеки і знати їхні розширення на різних ОС.
- Винести спільний код у власну бібліотеку і підключити її до програми.
- Пояснити, що означають `PUBLIC`, `PRIVATE`, `INTERFACE` у командах `target_*`.
- Перемикати тип бібліотеки через `BUILD_SHARED_LIBS` без зміни коду.

::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Статична бібліотека (*static library*):** архів `.a` або `.lib`, код якого копіюється у виконуваний файл при лінкуванні.
- **Динамічна бібліотека (*shared library*):** `.so`, `.dylib` або `.dll`, яка завантажується під час запуску.
- **Видимість (*visibility*):** правило, чи передається налаштування цілі тим, хто її використовує.
- **Транзитивна залежність (*transitive dependency*):** налаштування, що проходять через ланцюжок цілей.

::

::

Минулого разу всі `.cpp` потрапляли в одну програму. Якщо той самий код потрібен кільком програмам (наприклад, основній і тестовій), його виносять у **бібліотеку**: це збірка функцій і класів, яку підключають до різних програм.

## Типи бібліотек

CMake підтримує три основні види бібліотек, які створюються командою `add_library`:

| Тип | Результат | Коли код потрапляє в програму | Розмір програми | Файли потрібні при запуску |
|-----|-----------|-------------------------------|-----------------|----------------------------|
| `STATIC` | `.a` (Linux, macOS), `.lib` (Windows) | Під час лінкування, копіюється | Більший | Ні |
| `SHARED` | `.so` (Linux), `.dylib` (macOS), `.dll` (Windows) | Під час запуску програми | Менший | Так, поруч або в системному шляху |
| `INTERFACE` | Файлів не створює | Не потрапляє: лише заголовки | Залежить від коду заголовків | Ні |

- **Статична бібліотека** вбудовується в програму цілком. Програма самодостатня, але якщо бібліотеку використовують десять програм, її код дублюється десять разів.
- **Динамічна бібліотека** існує окремим файлом. Кілька програм можуть ділити одну копію, а оновлення бібліотеки не вимагає перекомпіляції програм. Платимо тим, що файл потрібно доставити разом із програмою.
- **INTERFACE** призначена для header-only бібліотек: у них весь код у `.h` (типовий приклад — шаблонні бібліотеки), тому компілювати нічого. Ціль потрібна, щоб передати іншим цілям шляхи до заголовків і прапорці.

## Власна бібліотека: проєкт

Винесемо математичні й рядкові функції в бібліотеку, а `main.cpp` залишимо програмою, яка їх викликає. Функції згруповані в просторах імен `MathUtils` та `StringUtils`, щоб не конфліктувати з іншим кодом.

::code-tree

```cpp [mylib/math_utils.h]
#ifndef MATH_UTILS_H
#define MATH_UTILS_H

namespace MathUtils {
    int add(int a, int b);
    int multiply(int a, int b);
    double power(double base, int exp);
}

#endif
```

```cpp [mylib/math_utils.cpp]
#include "math_utils.h"

namespace MathUtils {
    int add(int a, int b) {
        return a + b;
    }

    int multiply(int a, int b) {
        return a * b;
    }

    double power(double base, int exp) {
        double result = 1.0;
        for (int i = 0; i < exp; i++) {
            result *= base;
        }
        return result;
    }
}
```

```cpp [mylib/string_utils.h]
#ifndef STRING_UTILS_H
#define STRING_UTILS_H

#include <string>
#include <vector>

namespace StringUtils {
    std::string toUpperCase(const std::string& str);
    std::string toLowerCase(const std::string& str);
    std::vector<std::string> split(const std::string& str, char delimiter);
}

#endif
```

```cpp [mylib/string_utils.cpp]
#include "string_utils.h"
#include <algorithm>
#include <sstream>

namespace StringUtils {
    std::string toUpperCase(const std::string& str) {
        std::string result = str;
        std::transform(result.begin(), result.end(), result.begin(), ::toupper);
        return result;
    }

    std::string toLowerCase(const std::string& str) {
        std::string result = str;
        std::transform(result.begin(), result.end(), result.begin(), ::tolower);
        return result;
    }

    std::vector<std::string> split(const std::string& str, char delimiter) {
        std::vector<std::string> tokens;
        std::stringstream ss(str);
        std::string token;

        while (std::getline(ss, token, delimiter)) {
            tokens.push_back(token);
        }

        return tokens;
    }
}
```

```cpp [main.cpp]
#include <iostream>
#include "mylib/math_utils.h"
#include "mylib/string_utils.h"

int main() {
    std::cout << "=== Math Utils ===" << std::endl;
    std::cout << "5 + 3 = " << MathUtils::add(5, 3) << std::endl;
    std::cout << "10 * 2 = " << MathUtils::multiply(10, 2) << std::endl;
    std::cout << "2^10 = " << MathUtils::power(2, 10) << std::endl;

    std::cout << "\n=== String Utils ===" << std::endl;
    std::string text = "Hello World";
    std::cout << "Original: " << text << std::endl;
    std::cout << "Upper: " << StringUtils::toUpperCase(text) << std::endl;
    std::cout << "Lower: " << StringUtils::toLowerCase(text) << std::endl;

    std::string csv = "apple,banana,cherry,date";
    auto fruits = StringUtils::split(csv, ',');
    std::cout << "Split: ";
    for (const auto& fruit : fruits) {
        std::cout << fruit << " ";
    }
    std::cout << std::endl;

    return 0;
}
```

### CMakeLists.txt зі статичною бібліотекою

```cmake
cmake_minimum_required(VERSION 3.10)
project(MyProject VERSION 1.0.0)

set(CMAKE_CXX_STANDARD 17)

# Створюємо статичну бібліотеку
add_library(MyUtils STATIC
    mylib/math_utils.cpp
    mylib/math_utils.h
    mylib/string_utils.cpp
    mylib/string_utils.h
)

# Де шукати заголовкові файли бібліотеки
target_include_directories(MyUtils PUBLIC ${CMAKE_CURRENT_SOURCE_DIR})

# Створюємо виконуваний файл
add_executable(MyProject main.cpp)

# Зв'язуємо програму з бібліотекою
target_link_libraries(MyProject MyUtils)
```

Збірка показує порядок: спершу бібліотека, потім програма, яка від неї залежить. CMake визначив цей порядок сам з рядка `target_link_libraries`.

### Розбір команд

```cmake
add_library(MyUtils STATIC ...)
```

Створює ціль-бібліотеку з іменем `MyUtils`. Ключове слово `STATIC` задає тип. На диску з'явиться `libMyUtils.a` (на Windows `MyUtils.lib`).

```cmake
target_include_directories(MyUtils PUBLIC ${CMAKE_CURRENT_SOURCE_DIR})
```

Додає папку до шляхів пошуку заголовків. Слово `PUBLIC` означає, що її матимуть не лише файли самої бібліотеки, а й усі, хто з нею лінкується. Завдяки цьому в `main.cpp` працює `#include "mylib/math_utils.h"`.

```cmake
target_link_libraries(MyProject MyUtils)
```

Каже, що `MyProject` залежить від `MyUtils`. Крім лінкування, команда **передає програмі всі `PUBLIC` та `INTERFACE` налаштування бібліотеки**. Нижче цей механізм розібрано докладно.

## Динамічна бібліотека

Перехід на динамічну бібліотеку на рівні `CMakeLists.txt` зводиться до заміни одного слова:

```cmake
cmake_minimum_required(VERSION 3.10)
project(MyProject VERSION 1.0.0)

set(CMAKE_CXX_STANDARD 17)

# SHARED: динамічна бібліотека
add_library(MyUtils SHARED
    mylib/math_utils.cpp
    mylib/math_utils.h
    mylib/string_utils.cpp
    mylib/string_utils.h
)

target_include_directories(MyUtils PUBLIC ${CMAKE_CURRENT_SOURCE_DIR})

add_executable(MyProject main.cpp)
target_link_libraries(MyProject MyUtils)

# На Windows .dll має лежати поруч з .exe
if(WIN32)
    add_custom_command(TARGET MyProject POST_BUILD
        COMMAND ${CMAKE_COMMAND} -E copy_if_different
        $<TARGET_FILE:MyUtils>
        $<TARGET_FILE_DIR:MyProject>
    )
endif()
```

На macOS та Linux цей файл збереться без змін, а `otool -L` (на Linux `ldd`) покаже залежність програми від динамічної бібліотеки:

### Особливості Windows

На Windows `.dll` має додаткові обмеження:

1. **Експорт символів.** У Linux та macOS усі функції бібліотеки видимі за замовчуванням. У Windows DLL нічого не експортує, доки функції явно не позначені `__declspec(dllexport)`. Без експорту лінкер програми не знайде жодної функції бібліотеки.
2. **Розташування `.dll`.** Windows шукає DLL у папці виконуваного файла та в `PATH`. Тому вище команда `POST_BUILD` копіює `.dll` поряд із `.exe`. Вираз `$<TARGET_FILE:MyUtils>` — це *generator expression*: CMake підставляє на його місце реальний шлях до файлу бібліотеки на етапі генерації.

Для навчальних проєктів експорт можна автоматизувати однією змінною, яку слід встановити **до** `add_library`:

```cmake
set(CMAKE_WINDOWS_EXPORT_ALL_SYMBOLS ON)
```

CMake сам згенерує список експортів для всіх функцій і методів. Обмеження: глобальні змінні так не експортуються. Для промислових бібліотек використовують модуль `GenerateExportHeader`: він створює заголовок із макросом `MYUTILS_EXPORT`, який розмічає тільки публічний API.

::note
У старих матеріалах зустрічається рядок `target_compile_definitions(MyUtils PRIVATE BUILDING_DLL)`. Він працює лише тоді, коли у заголовках є макрос, що перетворює `BUILDING_DLL` на `dllexport`. Сам по собі такий рядок нічого не експортує.
::

## Вибір типу бібліотеки через опцію

Якщо в `add_library` не вказати тип, CMake обере його за змінною `BUILD_SHARED_LIBS`. Це дозволяє перемикати тип із командного рядка без правок `CMakeLists.txt`:

```cmake
cmake_minimum_required(VERSION 3.10)
project(MyProject)

set(CMAKE_CXX_STANDARD 17)

# Опція для вибору типу бібліотеки
option(BUILD_SHARED_LIBS "Build shared libraries" OFF)

# Тип не вказано: CMake вибере сам
add_library(MyUtils
    mylib/math_utils.cpp
    mylib/string_utils.cpp
)

target_include_directories(MyUtils PUBLIC ${CMAKE_CURRENT_SOURCE_DIR})

add_executable(MyProject main.cpp)
target_link_libraries(MyProject MyUtils)
```

::tabs

::tabs-item{label="Статична (за замовчуванням)"}

```bash
cmake -S . -B build
cmake --build build
```

::

::tabs-item{label="Динамічна"}

```bash
cmake -S . -B build -DBUILD_SHARED_LIBS=ON
cmake --build build
```

::

::

Результат на macOS: у першому випадку в папці збірки створюється `libMyUtils.a`, у другому `libMyUtils.dylib`. Обидві програми виводять однакові результати.

::tip
Змінна `BUILD_SHARED_LIBS` працює і для сторонніх бібліотек, підключених через `add_subdirectory` або `FetchContent`: вони також зберуться як SHARED, якщо їхні `CMakeLists.txt` не вказують тип явно. Тому змінюйте її на рівні командного рядка, а не всередині проєкту.
::

## Видимість: PUBLIC, PRIVATE, INTERFACE

Команди `target_include_directories`, `target_compile_definitions`, `target_compile_options` та `target_link_libraries` приймають слово, яке визначає, **хто побачить налаштування**.

```cmake
add_library(MyLib source.cpp)

# PUBLIC: потрібно і самій MyLib, і тим, хто її використовує
target_include_directories(MyLib PUBLIC include/)
target_compile_definitions(MyLib PUBLIC USE_FEATURE=1)

# PRIVATE: потрібно тільки всередині MyLib
target_include_directories(MyLib PRIVATE internal/)
target_compile_definitions(MyLib PRIVATE INTERNAL_DEBUG=1)

# INTERFACE: самій MyLib не потрібно, але потрібно користувачам
target_include_directories(MyLib INTERFACE external/)
```

![PRIVATE бачить лише бібліотека, PUBLIC її користувачі теж, INTERFACE тільки користувачі](/images/cpp/cmake/libraries/01-visibility.png){.diagram-img}

| Слово | Бачить сама бібліотека | Бачать ті, хто її використовує |
|-------|------------------------|--------------------------------|
| `PRIVATE` | Так | Ні |
| `PUBLIC` | Так | Так |
| `INTERFACE` | Ні | Так |

### Практична перевірка: що буде, якщо помилитися

Теорію легко забути, тому подивимось на реальні помилки. Бібліотека `greet` має заголовок у власній папці `include/`, а програма включає його через `<greet/greet.h>`:

::code-tree

```cmake [CMakeLists.txt]
cmake_minimum_required(VERSION 3.15)
project(Visibility CXX)
set(CMAKE_CXX_STANDARD 17)

add_library(greet greet/src/greet.cpp)
target_include_directories(greet PUBLIC greet/include)

add_executable(app app/main.cpp)
target_link_libraries(app PRIVATE greet)
```

```cpp [greet/include/greet/greet.h]
#pragma once
#include <string>

std::string greet(const std::string& name);
```

```cpp [greet/src/greet.cpp]
#include <greet/greet.h>

std::string greet(const std::string& name) {
    return "Hello, " + name + "!";
}
```

```cpp [app/main.cpp]
#include <iostream>
#include <greet/greet.h>

int main() {
    std::cout << greet("CMake") << std::endl;
}
```

::

Заголовок потрібен і самій бібліотеці (`greet.cpp`), і програмі (`main.cpp`). Тому правильний варіант — `PUBLIC`. Подивимось, що буде з двома іншими словами:

::terminal-preview{title="три варіанти target_include_directories"}

<div class="line"><span class="text-blue-400 font-bold">PRIVATE</span>   app/main.cpp:2:10: <span class="text-red-400 font-bold">fatal error</span>: 'greet/greet.h' file not found</div>
<div class="line"><span class="text-green-400 font-bold">PUBLIC</span>    [100%] Built target app    →  Hello, CMake!</div>
<div class="line"><span class="text-blue-400 font-bold">INTERFACE</span> greet/src/greet.cpp:1:10: <span class="text-red-400 font-bold">fatal error</span>: 'greet/greet.h' file not found</div>

::

- **`PRIVATE`.** Бібліотека знайшла свій заголовок, але програма — ні, бо налаштування їй не передалося.
- **`INTERFACE`.** Навпаки: програма отримала шлях, а самій бібліотеці `greet.cpp` шлях не потрібен за правилом `INTERFACE`, і вона не зібралася.
- **`PUBLIC`.** Шлях діє в обох місцях.

::warning
Правило вибору таке. Якщо шлях чи прапорець фігурує в публічних заголовках бібліотеки (тобто користувач бібліотеки їх бачить через `#include`), потрібен `PUBLIC`. Якщо він потрібен лише для `.cpp` самої бібліотеки, потрібен `PRIVATE`. `INTERFACE` застосовують для бібліотек без власного коду (header-only) та для налаштувань, які бібліотека лише передає.
::

### Транзитивність

Видимість діє ланцюжком. Якщо `app` лінкується з `greet` через `PRIVATE`, а `greet` лінкується з `fmt` через `PUBLIC`, то `app` теж отримає `fmt`. Якби `greet` лінкувала `fmt` через `PRIVATE`, то `fmt` залишився б прихованою деталлю реалізації, і `app` про нього б не знала.

## Header-only бібліотеки

Бібліотека без `.cpp` описується як `INTERFACE`:

```cmake
add_library(MathLib INTERFACE)
target_include_directories(MathLib INTERFACE include/)
target_compile_features(MathLib INTERFACE cxx_std_17)

add_executable(MyApp main.cpp)
target_link_libraries(MyApp PRIVATE MathLib)
```

Усі налаштування для такої цілі позначаються `INTERFACE`, бо в самої цілі немає коду, який би їх використовував. `target_compile_features(... cxx_std_17)` вимагає стандарт C++17 від усіх, хто підключить бібліотеку.

## Псевдоніми цілей

Рекомендується створювати псевдонім із простором імен у стилі `Проєкт::Ціль`:

```cmake
add_library(MyProject_MyUtils STATIC mylib/math_utils.cpp)
add_library(MyProject::MyUtils ALIAS MyProject_MyUtils)

target_link_libraries(MyApp PRIVATE MyProject::MyUtils)
```

Переваги: запис однаковий для власних і зовнішніх бібліотек (`fmt::fmt`, `Boost::filesystem`), а CMake розрізняє ціль і звичайну бібліотеку: якщо ви помилитесь в імені цілі з `::`, CMake видасть помилку замість того, щоб мовчки шукати файл бібліотеки з такою назвою.

## Питання для самоперевірки

::::accordion

:::accordion-item{label="❓ Коли обрати статичну бібліотеку, а коли динамічну?" icon="i-lucide-help-circle"}

Статична підходить, коли потрібна одна самодостатня програма без додаткових файлів. Динамічна — коли бібліотеку використовує кілька програм або її потрібно оновлювати окремо. У навчальних проєктах і невеликих утилітах частіше беруть статичні.

:::

:::accordion-item{label="❓ Чому target_link_libraries підтягує не лише бібліотеку, а й шляхи до заголовків?" icon="i-lucide-help-circle"}

Тому що ціль у сучасному CMake несе з собою свої `PUBLIC` та `INTERFACE` налаштування. Коли ви лінкуєте програму з такою ціллю, CMake передає їх програмі автоматично. Саме тому в `main.cpp` не довелося окремо викликати `target_include_directories`.

:::

:::accordion-item{label="❓ Що станеться на Windows із SHARED бібліотекою без dllexport?" icon="i-lucide-help-circle"}

Збірка DLL пройде, але разом з нею не з'явиться імпортна бібліотека `.lib` із функціями, і лінкер програми повідомить про нерозв'язані символи. Вирішення: позначити API макросом `dllexport` через `GenerateExportHeader` або тимчасово ввімкнути `CMAKE_WINDOWS_EXPORT_ALL_SYMBOLS`.

:::

:::accordion-item{label="❓ Чи можна лінкувати PRIVATE і PUBLIC в одній команді?" icon="i-lucide-help-circle"}

Так. Слова-ключі діють на всі аргументи після них, поки не зустрінеться наступне слово:

```cmake
target_link_libraries(MyLib
    PUBLIC  fmt::fmt
    PRIVATE Threads::Threads
)
```

:::

## Резюме

::card-group

::card{title="📚 Типи" icon="i-lucide-library"}
`STATIC` вбудовується в програму, `SHARED` завантажується під час запуску, `INTERFACE` описує бібліотеки лише із заголовків.
::

::card{title="🔗 target_link_libraries" icon="i-lucide-link"}
Задає залежність і передає користувачеві `PUBLIC` та `INTERFACE` налаштування бібліотеки: шляхи, макроси, прапорці.
::

::card{title="👁️ Видимість" icon="i-lucide-eye"}
`PRIVATE` лише для бібліотеки, `INTERFACE` лише для користувачів, `PUBLIC` для обох. Помилка у виборі проявляється як «file not found».
::

::card{title="🎛️ BUILD_SHARED_LIBS" icon="i-lucide-toggle-left"}
Керує типом бібліотеки без явного слова `STATIC` або `SHARED`. Змінюється командою `-DBUILD_SHARED_LIBS=ON`.
::

::

::note
Власну бібліотеку підключати вміємо. Наступний крок: як підключити чужу бібліотеку через `find_package`, `add_subdirectory`, `FetchContent` або `pkg-config`.
::
