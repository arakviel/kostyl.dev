# Умови, опції, цикли та функції в CMake

::card-group

::card{title="🎯 Мета лекції" icon="i-lucide-target"}

- Писати умови `if`/`elseif`/`else` та правильно перевіряти змінні, рядки, числа й файли.
- Підлаштовувати збірку під платформу та компілятор.
- Додавати налаштовувані опції `option()` і передавати їх через `-D`.
- Користуватися циклами, функціями й макросами та знати різницю між останніми двома.
- Передавати інформацію з CMake в код C++ через `configure_file`.

::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Опція (*option*):** булева змінна в кеші, яку користувач може перемкнути командою `-D`.
- **Область видимості (*scope*):** місце, у якому діє змінна.
- **Функція та макрос:** користувацькі команди, що відрізняються областю видимості змінних.
- **`configure_file`:** команда, що підставляє значення змінних CMake у шаблон файлу.

::

::

`CMakeLists.txt` — програма, тому в ній є розгалуження, цикли і підпрограми. Вони потрібні, щоб один файл збирав проєкт і на Windows, і на Linux, а також щоб користувач міг увімкнути або вимкнути частини проєкту.

## Умовні конструкції

### if, elseif, else

```cmake
# Проста умова
if(WIN32)
    message("Це Windows")
endif()

# if-else
if(UNIX)
    message("Це Unix-подібна система (Linux/macOS)")
else()
    message("Це Windows")
endif()

# if-elseif-else
if(WIN32)
    message("Windows")
elseif(APPLE)
    message("macOS")
elseif(UNIX)
    message("Linux")
else()
    message("Невідома система")
endif()
```

Кожний `if` закривається `endif()`. Змінні `WIN32`, `APPLE`, `UNIX` визначає сам CMake. Зверніть увагу, що `UNIX` істинна також на macOS, тому перевірку `APPLE` слід розташовувати **перед** `UNIX`, якщо різниця важлива.

### Перевірка змінних

```cmake
# Чи змінна визначена
if(DEFINED MY_VARIABLE)
    message("Змінна MY_VARIABLE визначена")
endif()

# Булеве значення
set(ENABLE_FEATURE ON)
if(ENABLE_FEATURE)
    message("Feature увімкнена")
endif()

# Порівняння рядків
set(BUILD_TYPE "Debug")
if(BUILD_TYPE STREQUAL "Debug")
    message("Debug режим")
endif()

# Заперечення
if(NOT BUILD_TYPE STREQUAL "Release")
    message("Це не Release збірка")
endif()
```

Як CMake трактує значення в `if(ЗМІННА)`, визначають окремі правила. Реальний запуск підтверджує їх:

::terminal-preview{title="cmake -P conditions.cmake"}

<div class="line">Debug режим</div>
<div class="line">NOPE не визначена</div>
<div class="line">FLAG ON -> істина         <span class="opacity-40"># set(FLAG ON)</span></div>
<div class="line">FLAG NO -> хиба           <span class="opacity-40"># set(FLAG "NO"), перевірка if(NOT FLAG)</span></div>

::

Значення вважаються **істинними**: `1`, `ON`, `YES`, `TRUE`, `Y`, а також будь-яке ненульове число. **Хибними**: `0`, `OFF`, `NO`, `FALSE`, `N`, `IGNORE`, `NOTFOUND`, порожній рядок і рядки, що закінчуються на `-NOTFOUND`.

::warning
Команда `if(ЗМІННА)` **автоматично розіменовує** змінну: якщо в `ЗМІННА` лежить рядок, що збігається з іменем іншої змінної, CMake піде за нею. Це джерело неочевидних помилок. Для порівняння з конкретним рядком завжди використовуйте `STREQUAL`, а не голе `if(...)`. Для перевірки, чи змінна взагалі існує, є `DEFINED`.
::

### Логічні оператори

```cmake
# AND
if(WIN32 AND CMAKE_CXX_COMPILER_ID STREQUAL "MSVC")
    message("Windows з компілятором MSVC")
endif()

# OR
if(APPLE OR UNIX)
    message("Unix-подібна система")
endif()

# NOT
if(NOT WIN32)
    message("Не Windows")
endif()

# Комбінація з дужками
if((WIN32 OR APPLE) AND CMAKE_BUILD_TYPE STREQUAL "Debug")
    message("Debug збірка на Windows або macOS")
endif()
```

### Порівняння чисел

```cmake
set(VERSION 15)

if(VERSION GREATER 10)
    message("Версія більша за 10")
endif()

if(VERSION LESS 20)
    message("Версія менша за 20")
endif()

if(VERSION EQUAL 15)
    message("Версія дорівнює 15")
endif()

if(VERSION GREATER_EQUAL 15)
    message("Версія >= 15")
endif()
```

Операторам `GREATER`, `LESS`, `EQUAL` потрібні числа. Для версій у форматі `3.10.2` призначені окремі оператори `VERSION_GREATER`, `VERSION_LESS`, `VERSION_EQUAL`: рядкове порівняння `"3.9"` та `"3.10"` дало б хибний результат.

::terminal-preview{title="числове і рядкове порівняння"}

<div class="line">9 LESS 10: числове                                  <span class="opacity-40"># if("9" LESS "10")</span></div>
<div class="line">9 STRLESS 10: хибно (рядкове: '9' > '1')           <span class="opacity-40"># if("9" STRLESS "10")</span></div>

::

Рядки порівнюються посимвольно: символ `9` у таблиці кодів більший за `1`, тому `"9"` вважається «більшим» за `"10"`. Це типова причина помилок у версіях, тому використовуйте числові або `VERSION_*` оператори.

### Перевірка файлів

```cmake
# Чи існує файл
if(EXISTS "${CMAKE_SOURCE_DIR}/config.txt")
    message("Конфігураційний файл знайдено")
endif()

# Чи це папка
if(IS_DIRECTORY "${CMAKE_SOURCE_DIR}/external")
    message("Папка external існує")
endif()
```

Перевірка `EXISTS` корисна для необов'язкових компонентів: наприклад, підключати папку `tests`, лише якщо вона є, або використати локальний конфіг, якщо його створив розробник.

### Приклад: налаштування під платформу

```cmake
cmake_minimum_required(VERSION 3.10)
project(CrossPlatformApp)

set(CMAKE_CXX_STANDARD 17)

# Загальні вихідні файли
set(SOURCES
    main.cpp
    app.cpp
)

# Платформо-специфічні файли
if(WIN32)
    list(APPEND SOURCES windows_specific.cpp)
    message(STATUS "Adding Windows-specific files")
elseif(APPLE)
    list(APPEND SOURCES macos_specific.cpp)
    message(STATUS "Adding macOS-specific files")
elseif(UNIX)
    list(APPEND SOURCES linux_specific.cpp)
    message(STATUS "Adding Linux-specific files")
endif()

add_executable(${PROJECT_NAME} ${SOURCES})

# Платформо-специфічні бібліотеки
if(WIN32)
    target_link_libraries(${PROJECT_NAME} ws2_32)  # Windows sockets
elseif(UNIX)
    find_package(Threads REQUIRED)
    target_link_libraries(${PROJECT_NAME} Threads::Threads)
endif()

# Платформо-специфічні прапорці компіляції
if(MSVC)
    target_compile_options(${PROJECT_NAME} PRIVATE /W4 /WX)
else()
    target_compile_options(${PROJECT_NAME} PRIVATE -Wall -Wextra -Werror)
endif()
```

Загальні файли зібрані в `SOURCES`, а специфічні додаються до списку залежно від платформи. У джерелі для POSIX-потоків написано `pthread`. Надійніше підключати `Threads::Threads` через `find_package(Threads)`: ця ціль сама підбирає правильний прапорець або бібліотеку (на macOS окремої `pthread` не потрібно).

::caution
Прапорець `-Werror` перетворює будь-яке попередження компілятора на помилку. Його зручно вмикати у вашій CI-збірці, але небезпечно залишати за замовчуванням: нова версія компілятора з новими попередженнями «зламає» збірку у користувачів, хоча код правильний. Для бібліотек, які ставлять інші люди, його краще не вмикати.
::

## Опції

Опція — це булева змінна в кеші, яку користувач може перемикати, не змінюючи `CMakeLists.txt`.

```cmake
cmake_minimum_required(VERSION 3.10)
project(ConfigurableApp)

# Опції, які користувач може змінити
option(ENABLE_TESTS "Build tests" OFF)
option(ENABLE_LOGGING "Enable logging" ON)
option(USE_STATIC_LIBS "Use static libraries" OFF)

# Стан опцій
message(STATUS "ENABLE_TESTS: ${ENABLE_TESTS}")
message(STATUS "ENABLE_LOGGING: ${ENABLE_LOGGING}")
message(STATUS "USE_STATIC_LIBS: ${USE_STATIC_LIBS}")

add_executable(MyApp main.cpp)

# Використання опцій
if(ENABLE_LOGGING)
    target_compile_definitions(MyApp PRIVATE LOGGING_ENABLED)
    message(STATUS "Logging is enabled")
endif()

# Тести додаємо тільки на вимогу
if(ENABLE_TESTS)
    enable_testing()
    add_subdirectory(tests)
endif()
```

Синтаксис: `option(ІМ'Я "опис" значення_за_замовчуванням)`. Опис видно в GUI та у виводі `cmake -LH`.

### Передача опцій із командного рядка

```bash
# Увімкнути тести
cmake -S . -B build -DENABLE_TESTS=ON

# Кілька опцій
cmake -S . -B build -DENABLE_LOGGING=OFF -DUSE_STATIC_LIBS=ON

# Графічний інтерфейс
cmake-gui .
```

Реальний вивід двох конфігурацій одного проєкту:

::terminal-preview{title="опції за замовчуванням і з -D"}

<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">cmake -S . -B build</strong></div>
<div class="line">-- ENABLE_TESTS: OFF</div>
<div class="line">-- ENABLE_LOGGING: ON</div>
<div class="line">-- Logging is enabled</div>
<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">cmake -S . -B build -DENABLE_TESTS=ON -DENABLE_LOGGING=OFF</strong></div>
<div class="line">-- ENABLE_TESTS: ON</div>
<div class="line">-- ENABLE_LOGGING: OFF</div>
<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">cmake -L -N build | grep ENABLE</strong></div>
<div class="line">ENABLE_LOGGING:BOOL=OFF</div>
<div class="line">ENABLE_TESTS:BOOL=ON</div>

::

Після другого запуску значення залишилися в кеші `CMakeCache.txt`. Наступна конфігурація без `-D` **збереже** їх, і це поширена причина здивування: «я ж не вмикав тести, а вони збираються». Скинути все можна, видаливши `build/`.

::note
Команда `cmake -L -N build` виводить закешовані змінні без повторної конфігурації. Варіанти `-LA` (разом із розширеними) та `-LH` (з описом) зручні для діагностики.
::

### Пастка порядку: BUILD_SHARED_LIBS

Опція `BUILD_SHARED_LIBS` впливає на бібліотеки, **створені після** її встановлення. Типова помилка зі старих прикладів:

```cmake
add_library(MyLib lib.cpp)   # створена тут...

if(USE_STATIC_LIBS)
    set(BUILD_SHARED_LIBS OFF)  # ...а змінну ставимо пізніше: ефекту не буде
endif()
```

Правильно: спершу встановити `BUILD_SHARED_LIBS`, потім викликати `add_library`. Або, ще краще, не змінювати її всередині проєкту, а передавати через `-DBUILD_SHARED_LIBS=ON` з командного рядка.

## Цикли

### foreach

```cmake
# Перебір списку
set(FRUITS apple banana cherry)
foreach(FRUIT ${FRUITS})
    message("Фрукт: ${FRUIT}")
endforeach()

# Діапазон від 0 до 3 включно
foreach(I RANGE 3)
    message("Ітерація ${I}")
endforeach()

# Діапазон із кроком
foreach(I RANGE 0 10 2)
    message("${I}")
endforeach()

# Перебір знайдених файлів
file(GLOB CPP_FILES "src/*.cpp")
foreach(FILE ${CPP_FILES})
    message("Знайдено файл: ${FILE}")
endforeach()
```

<div class="line">Фрукт: cherry</div>
<div class="line">Ітерація 0</div>
<div class="line">Ітерація 1</div>
<div class="line">Ітерація 2</div>
<div class="line">Ітерація 3</div>
<div class="line">0 2 4 6 8 10      <span class="opacity-40"># кожне число окремим рядком</span></div>

Діапазон `RANGE 3` дає числа 0, 1, 2, 3: кінець включається, на відміну від C++-циклів. Типове застосування `foreach` — створити однакові цілі за списком, наприклад по одному тестовому виконуваному файлу на кожен `.cpp`:

```cmake
foreach(NAME test_math test_strings test_io)
    add_executable(${NAME} ${NAME}.cpp)
    target_link_libraries(${NAME} PRIVATE MyLib)
    add_test(NAME ${NAME} COMMAND ${NAME})
endforeach()
```

### while

```cmake
set(COUNT 0)
while(COUNT LESS 5)
    message("Лічильник: ${COUNT}")
    math(EXPR COUNT "${COUNT} + 1")  # COUNT = COUNT + 1
endwhile()
```

Для арифметики використовується команда `math(EXPR ...)`, оскільки в CMake значення є рядками і `COUNT + 1` не обчислюється саме по собі. Цикл `while` у `CMakeLists.txt` трапляється рідко, але потрібен, коли кількість повторів невідома наперед.

## Функції та макроси

### Функція

```cmake
# Оголошення
function(print_message TEXT)
    message("=== ${TEXT} ===")
endfunction()

# Виклик
print_message("Hello CMake")

# Функція з кількома параметрами та поверненням значення
function(add_numbers RESULT A B)
    math(EXPR SUM "${A} + ${B}")
    set(${RESULT} ${SUM} PARENT_SCOPE)
endfunction()

add_numbers(MY_RESULT 5 3)
message("Результат: ${MY_RESULT}")  # 8
```

CMake не має операції `return` зі значенням. Щоб «повернути» результат, функція отримує **ім'я** змінної як перший параметр (`RESULT`) і записує в неї значення командою `set(${RESULT} ... PARENT_SCOPE)`. Слово `PARENT_SCOPE` обов'язкове, бо без нього змінна існуватиме тільки всередині функції.

### Макрос

```cmake
# Макроси схожі на функції, але працюють в тій самій області видимості
macro(set_default_compiler_flags)
    if(MSVC)
        add_compile_options(/W4)
    else()
        add_compile_options(-Wall -Wextra)
    endif()
endmacro()

set_default_compiler_flags()
```

### Функція чи макрос

Принципова різниця — область видимості змінних. Функція працює у **власній** області: змінні, створені або змінені всередині, зовні не видно. Макрос підставляє свій текст у місце виклику, тому змінює змінні **викликача**. Перевірка:

```cmake
function(f_scope)
    set(X "змінено у функції")
endfunction()

macro(m_scope)
    set(X "змінено в макросі")
endmacro()

set(X "початкове")
f_scope()
message("після функції: ${X}")
m_scope()
message("після макросу: ${X}")
```

::terminal-preview{title="cmake -P scope.cmake"}

<div class="line">після функції: початкове</div>
<div class="line">після макросу: змінено в макросі</div>

::

::tip
За замовчуванням пишіть функції: вони не псують змінні викликача. Макрос варто брати лише тоді, коли дія свідомо має змінити область, з якої її викликали, наприклад задати набір загальних прапорців.
::

## Генерація заголовка з версією: configure_file

Команда `configure_file` читає шаблон, підставляє в нього значення змінних CMake та записує результат у потрібну папку. Так версія проєкту з `project(... VERSION ...)` потрапляє у код C++ без дублювання.

::code-tree

```cmake [CMakeLists.txt]
cmake_minimum_required(VERSION 3.10)
project(VersionedApp VERSION 2.5.1)

# Створюємо config.h із версією
configure_file(
    "${CMAKE_SOURCE_DIR}/config.h.in"
    "${CMAKE_BINARY_DIR}/config.h"
)

add_executable(MyApp main.cpp)

# Підключаємо папку зі згенерованим файлом
target_include_directories(MyApp PRIVATE ${CMAKE_BINARY_DIR})
```

```cpp [config.h.in]
#ifndef CONFIG_H
#define CONFIG_H

#define VERSION_MAJOR @PROJECT_VERSION_MAJOR@
#define VERSION_MINOR @PROJECT_VERSION_MINOR@
#define VERSION_PATCH @PROJECT_VERSION_PATCH@
#define VERSION_STRING "@PROJECT_VERSION@"

#endif
```

```cpp [main.cpp]
#include <iostream>
#include "config.h"

int main() {
    std::cout << "Version: " << VERSION_STRING << std::endl;
    std::cout << "Major: " << VERSION_MAJOR << std::endl;
    std::cout << "Minor: " << VERSION_MINOR << std::endl;
    std::cout << "Patch: " << VERSION_PATCH << std::endl;
    return 0;
}
```

::

Шаблон `config.h.in` містить місця для підстановки у форматі `@ІМ'Я@`. Під час конфігурації CMake замінює їх значеннями змінних і створює `build/config.h`. Готовий файл лежить у **папці збірки**, не в джерелах, тому `target_include_directories` вказує на `CMAKE_BINARY_DIR`.

::terminal-preview{title="результат"}

<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">./build/MyApp</strong></div>
<div class="line">Version: 2.5.1</div>
<div class="line">Major: 2</div>
<div class="line">Minor: 5</div>
<div class="line">Patch: 1</div>

::

Зміна версії в `project()` оновить заголовок автоматично. У шаблоні також підтримується запис `#cmakedefine ІМ'Я`: рядок перетворюється на `#define ІМ'Я`, якщо змінна істинна, і на закоментований, якщо хибна. Так опції CMake перетворюють на макроси C++.

## Питання для самоперевірки

::::accordion

:::accordion-item{label="❓ Чому if(UNIX) істинне на macOS і що з цим робити?" icon="i-lucide-help-circle"}

macOS є Unix-системою, тому CMake встановлює `UNIX` разом з `APPLE`. Якщо потрібно відокремити Linux від macOS, перевіряйте `APPLE` першим або пишіть `if(UNIX AND NOT APPLE)`.

:::

:::accordion-item{label="❓ Чому після повторної конфігурації без -D опція зберегла старе значення?" icon="i-lucide-help-circle"}

`option()` записує значення в кеш `CMakeCache.txt` і наступні конфігурації його не перезаписують. Змінити значення можна новим `-D...`, а повністю скинути — видаленням папки `build/`.

:::

:::accordion-item{label="❓ Як повернути значення з функції CMake?" icon="i-lucide-help-circle"}

Передати ім'я змінної як параметр і записати в неї значення з `PARENT_SCOPE`: `set(${RESULT} ${VALUE} PARENT_SCOPE)`. Без `PARENT_SCOPE` змінна залишиться локальною.

:::

:::accordion-item{label="❓ Чому version 3.9 «більша» за 3.10 у рядковому порівнянні?" icon="i-lucide-help-circle"}

Рядки порівнюються символ за символом. Перші символи однакові (`3.`), далі `9` порівнюється з `1`, а `9` має більший код. Для версій користуйтеся операторами `VERSION_GREATER`, `VERSION_LESS` та `VERSION_EQUAL`.

:::

## Практичне завдання

::::accordion

:::accordion-item{label="📋 Завдання: налаштовуваний проєкт" icon="i-lucide-clipboard-list"}

Створіть проєкт `Configurable` з `main.cpp`, який виводить версію проєкту та повідомляє, чи ввімкнено логування. Потрібно:

1. Версія `1.4.0` задається в `project()` і потрапляє у код через `configure_file`.
2. Опція `ENABLE_LOGGING` (за замовчуванням `ON`) визначає макрос `LOGGING_ENABLED`.
3. Опція `BUILD_EXAMPLES` (за замовчуванням `OFF`) за увімкнення виводить `message(STATUS ...)` про те, що приклади будуть зібрані.
4. Перевірте, що `cmake -DENABLE_LOGGING=OFF` змінює вивід програми.

:::

:::accordion-item{label="✅ Розв'язок" icon="i-lucide-check-circle"}

```cmake
cmake_minimum_required(VERSION 3.10)
project(Configurable VERSION 1.4.0)

option(ENABLE_LOGGING "Enable logging" ON)
option(BUILD_EXAMPLES "Build examples" OFF)

configure_file(
    "${CMAKE_SOURCE_DIR}/config.h.in"
    "${CMAKE_BINARY_DIR}/config.h"
)

add_executable(Configurable main.cpp)
target_include_directories(Configurable PRIVATE ${CMAKE_BINARY_DIR})

if(ENABLE_LOGGING)
    target_compile_definitions(Configurable PRIVATE LOGGING_ENABLED)
endif()

if(BUILD_EXAMPLES)
    message(STATUS "Examples will be built")
endif()
```

```cpp
#include <iostream>
#include "config.h"

int main() {
    std::cout << "Version " << VERSION_STRING << std::endl;
#ifdef LOGGING_ENABLED
    std::cout << "Logging: on" << std::endl;
#else
    std::cout << "Logging: off" << std::endl;
#endif
}
```

Файл `config.h.in` такий самий, як у прикладі вище.

:::

## Резюме

::card-group

::card{title="🔀 Умови" icon="i-lucide-git-branch"}
`if` перевіряє змінні, рядки, числа, файли та платформу. Для рядків використовуйте `STREQUAL`, для версій `VERSION_*` оператори.
::

::card{title="🎚️ Опції" icon="i-lucide-toggle-right"}
`option()` створює булеву змінну в кеші. Передається через `-DІМ'Я=ON`, зберігається між запусками.
::

::card{title="🔁 Цикли" icon="i-lucide-repeat"}
`foreach` перебирає списки й діапазони, `while` повторює до виконання умови. Арифметика через `math(EXPR ...)`.
::

::card{title="🧱 Функції й макроси" icon="i-lucide-box"}
Функція має власну область видимості, макрос працює в області викликача. Результат повертається через `PARENT_SCOPE`.
::

::card{title="📄 configure_file" icon="i-lucide-file-cog"}
Підставляє значення CMake у шаблон `.in` і створює заголовок, наприклад з версією проєкту.
::

::

::note
Наступна тема: типи збірки Debug і Release, прапорці для кожного з них, вирази-генератори `$<...>` та відмінність між single-config і multi-config генераторами.
::
