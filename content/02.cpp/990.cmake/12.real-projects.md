# Практичні проєкти: калькулятор, Qt-застосунок і кросплатформна збірка

::card-group

::card{title="🎯 Мета лекції" icon="i-lucide-target"}

- Зібрати повний проєкт із бібліотекою, програмою та тестами за усталеною структурою.
- Підключити великий фреймворк (Qt6) через `find_package` і налаштувати автоматичні генератори коду.
- Налаштувати кросплатформну збірку для іншої архітектури через toolchain-файл.

::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Toolchain-файл:** файл CMake, який описує, яким компілятором і для якої системи збирати.
- **Кросплатформна збірка (*cross-compilation*):** збірка на одній платформі програми для іншої.
- **AUTOMOC/AUTOUIC/AUTORCC:** вбудовані в CMake генератори коду для Qt.
- **Цільова платформа (*target platform*):** система, на якій програма запускатиметься.

У попередніх лекціях кожна можливість CMake розглядалася окремо. Нижче вони зібрані у трьох проєктах, які відображають типові сценарії: консольна програма з бібліотекою й тестами, застосунок із графічним фреймворком і збірка для іншого типу процесора.

## Проєкт 1: консольний калькулятор

Калькулятор складається з бібліотеки `calculator_lib` (арифметика та движок із історією обчислень), програми з меню та двох тестових програм. Бібліотека відокремлена від `main.cpp`, тому тести працюють із нею напряму, без діалогу з користувачем.

### Структура

::code-tree

```cmake [CMakeLists.txt]
cmake_minimum_required(VERSION 3.15)
project(Calculator VERSION 1.0.0 LANGUAGES CXX)

# Налаштування
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

# Опції
option(BUILD_TESTS "Build tests" ON)
option(ENABLE_WARNINGS "Enable compiler warnings" ON)

# Виведення інформації
message(STATUS "========================================")
message(STATUS "  ${PROJECT_NAME} v${PROJECT_VERSION}")
message(STATUS "========================================")
message(STATUS "Build type: ${CMAKE_BUILD_TYPE}")
message(STATUS "Build tests: ${BUILD_TESTS}")
message(STATUS "========================================")

# Бібліотека calculator
add_library(calculator_lib
    src/calculator.cpp
    src/operations.cpp
)

target_include_directories(calculator_lib
    PUBLIC
        $<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}/include>
        $<INSTALL_INTERFACE:include>
)

# Попередження компілятора
if(ENABLE_WARNINGS)
    if(MSVC)
        target_compile_options(calculator_lib PRIVATE /W4)
    else()
        target_compile_options(calculator_lib PRIVATE -Wall -Wextra -Wpedantic)
    endif()
endif()

# Виконуваний файл
add_executable(calculator src/main.cpp)
target_link_libraries(calculator PRIVATE calculator_lib)

# Тести
if(BUILD_TESTS)
    enable_testing()
    add_subdirectory(tests)
endif()
```

```cpp [src/operations.cpp]
#include "calculator/operations.h"
#include <cmath>

namespace Calculator {

double add(double a, double b) { return a + b; }
double subtract(double a, double b) { return a - b; }
double multiply(double a, double b) { return a * b; }
double divide(double a, double b) { return a / b; }

}
```

```cpp [src/calculator.cpp]
#include "calculator/calculator.h"
#include "calculator/operations.h"
#include <sstream>

namespace Calculator {

bool Engine::apply(char op, double a, double b, double& result) {
    switch (op) {
        case '+': result = add(a, b); break;
        case '-': result = subtract(a, b); break;
        case '*': result = multiply(a, b); break;
        case '/':
            if (b == 0) return false;
            result = divide(a, b);
            break;
        case '^': result = power(a, b); break;
        default: return false;
    }

    std::ostringstream line;
    line << a << " " << op << " " << b << " = " << result;
    history_.push_back(line.str());
    return true;
}

}
```

```cpp [src/main.cpp]
#include <iostream>
#include <limits>
#include "calculator/operations.h"

using namespace Calculator;

void showMenu() {
    std::cout << "\n=== Калькулятор ===" << std::endl;
    std::cout << "1. Додавання (+)" << std::endl;
    std::cout << "2. Віднімання (-)" << std::endl;
    std::cout << "3. Множення (*)" << std::endl;
    std::cout << "4. Ділення (/)" << std::endl;
    std::cout << "5. Степінь (^)" << std::endl;
    std::cout << "6. Квадратний корінь" << std::endl;
    std::cout << "0. Вихід" << std::endl;
    std::cout << "Виберіть операцію: ";
}

int main() {
    int choice;
    double a = 0, b = 0, result;

    while (true) {
        showMenu();
        std::cin >> choice;

        if (std::cin.fail()) {
            std::cin.clear();
            std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
            std::cout << "Невірний ввід!" << std::endl;
            continue;
        }

        if (choice == 0) {
            std::cout << "До побачення!" << std::endl;
            break;
        }

        if (choice >= 1 && choice <= 5) {
            std::cout << "Введіть перше число: ";
            std::cin >> a;
            std::cout << "Введіть друге число: ";
            std::cin >> b;
        } else if (choice == 6) {
            std::cout << "Введіть число: ";
            std::cin >> a;
        } else {
            std::cout << "Невірний вибір!" << std::endl;
            continue;
        }

        switch (choice) {
            case 1:
                result = add(a, b);
                std::cout << "Результат: " << a << " + " << b << " = " << result << std::endl;
                break;
            case 2:
                result = subtract(a, b);
                std::cout << "Результат: " << a << " - " << b << " = " << result << std::endl;
                break;
            case 3:
                result = multiply(a, b);
                std::cout << "Результат: " << a << " * " << b << " = " << result << std::endl;
                break;
            case 4:
                if (b == 0) {
                    std::cout << "Помилка: ділення на нуль!" << std::endl;
                } else {
                    result = divide(a, b);
                    std::cout << "Результат: " << a << " / " << b << " = " << result << std::endl;
                }
                break;
            case 5:
                result = power(a, b);
                std::cout << "Результат: " << a << " ^ " << b << " = " << result << std::endl;
                break;
            case 6:
                if (a < 0) {
                    std::cout << "Помилка: від'ємне число!" << std::endl;
                } else {
                    result = squareRoot(a);
                    std::cout << "Результат: √" << a << " = " << result << std::endl;
                }
                break;
        }
    }

    return 0;
}
```

### Як влаштовано проєкт

1. **Бібліотека `calculator_lib`** містить усю логіку: функції арифметики та клас `Engine`. Заголовки лежать у `include/calculator/`, тому в коді пишемо `#include "calculator/operations.h"`, і папка `calculator/` працює як простір імен для файлів.
2. **`target_include_directories(... PUBLIC ...)`** з `BUILD_INTERFACE` і `INSTALL_INTERFACE` передає шлях до заголовків програмі й тестам автоматично.
3. **Програма `calculator`** лінкується з бібліотекою через `PRIVATE`: користувачів у програми немає, тому передавати залежність далі немає сенсу.
4. **Тести** створюються циклом `foreach`: кожен файл стає окремою програмою і окремим тестом CTest.
5. **Перевірки `CHECK`** написані власним макросом, а не через `assert`. Як з'ясували в лекції про тестування, `assert` у Release-збірці зникає, а `CHECK` працює завжди.

## Проєкт 2: застосунок із графічним інтерфейсом (Qt)

Qt — найпоширеніший C++-фреймворк для графічних програм, що працює на Windows, Linux і macOS. Він має власні інструменти генерації коду, і CMake вміє запускати їх автоматично. Це приклад проєкту із великою зовнішньою залежністю, яка підключається через `find_package`.

::note
Qt встановлюється окремо: офіційним інсталятором Qt, через `brew install qt` на macOS або `apt install qt6-base-dev` на Ubuntu. Також доступний пакет `qtbase` у vcpkg, але його збірка триває дуже довго. Після встановлення CMake має знайти Qt: якщо ні, вкажіть `-DCMAKE_PREFIX_PATH=/шлях/до/Qt/6.x/платформа`.
::

### CMakeLists.txt

```cmake
cmake_minimum_required(VERSION 3.16)
project(QtApp VERSION 1.0.0 LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

# Автоматичні генератори коду Qt
set(CMAKE_AUTOMOC ON)  # Meta-Object Compiler: сигнали та слоти
set(CMAKE_AUTORCC ON)  # Resource Compiler: файли ресурсів .qrc
set(CMAKE_AUTOUIC ON)  # UI Compiler: файли форм .ui

# Знайти Qt
find_package(Qt6 REQUIRED COMPONENTS Widgets)

# Вихідні файли
set(SOURCES
    src/main.cpp
    src/mainwindow.cpp
    src/mainwindow.h
)

# Створення виконуваного файлу з урахуванням платформи
if(WIN32)
    add_executable(${PROJECT_NAME} WIN32 ${SOURCES})
elseif(APPLE)
    add_executable(${PROJECT_NAME} MACOSX_BUNDLE ${SOURCES})
else()
    add_executable(${PROJECT_NAME} ${SOURCES})
endif()

# Зв'язати з Qt
target_link_libraries(${PROJECT_NAME} PRIVATE Qt6::Widgets)

# Встановлення
install(TARGETS ${PROJECT_NAME}
    BUNDLE DESTINATION .
    RUNTIME DESTINATION bin
)
```

### Що тут нового

- **`CMAKE_AUTOMOC`.** Механізм сигналів і слотів Qt потребує додаткового коду, який створює спеціальний компілятор `moc`. З цією змінною CMake сам знаходить класи з макросом `Q_OBJECT` у заголовках і запускає `moc` перед компіляцією.
- **`CMAKE_AUTOUIC`** перетворює файли форм `.ui` (створені в Qt Designer) на C++-заголовки, **`CMAKE_AUTORCC`** вбудовує ресурси `.qrc` (зображення, переклади) у виконуваний файл.
- **`find_package(Qt6 REQUIRED COMPONENTS Widgets)`** знаходить лише потрібну частину Qt. Ціль `Qt6::Widgets` уже залежить від `Qt6::Gui` та `Qt6::Core`, тому перелічувати їх окремо не потрібно.
- **`WIN32` та `MACOSX_BUNDLE`** — прапорці `add_executable`. Перший прибирає консольне вікно на Windows, другий створює на macOS пакет `.app` замість звичайного виконуваного файлу.

### Розгортання на Windows

Програма Qt на Windows не запуститься на чужому комп'ютері без бібліотек Qt (`Qt6Core.dll`, `Qt6Widgets.dll` і плагінів платформи). Збирати їх вручну не потрібно: Qt постачає утиліту `windeployqt`, яку можна запустити після збірки:

```cmake
if(WIN32)
    find_program(WINDEPLOYQT windeployqt HINTS "${Qt6_DIR}/../../../bin")

    if(WINDEPLOYQT)
        add_custom_command(TARGET ${PROJECT_NAME} POST_BUILD
            COMMAND ${WINDEPLOYQT} --no-translations
                    $<TARGET_FILE:${PROJECT_NAME}>
            COMMENT "Копіювання бібліотек Qt поруч з виконуваним файлом"
        )
    endif()
endif()
```

`windeployqt` аналізує виконуваний файл, визначає потрібні DLL і плагіни та копіює їх поруч. Подібні утиліти є й на інших платформах: `macdeployqt` для macOS і `linuxdeploy` для Linux.

::warning
У старих прикладах для цієї мети DLL копіюють вручну командою `copy_if_different`, пошук `Qt6::qmake` використовують, щоб отримати папку Qt. Такий підхід ламається, коли змінюється склад компонентів або встановлюється нова версія Qt. `windeployqt` відстежує залежності автоматично.
::

## Проєкт 3: кросплатформна збірка для Raspberry Pi

До цього часу збірка виконувалась на тій же системі, на якій програма запускається. Часто це неможливо: мікроконтролер або Raspberry Pi надто слабкі для компіляції, і програму збирають на потужному ПК. Така збірка називається **кросплатформною** (*cross-compilation*). Компілятор працює на **хост-системі** (ваш комп'ютер), а результат призначений для **цільової системи** (Raspberry Pi).

Щоб CMake знав, що збирати потрібно для іншої системи, її описують у файлі **toolchain**.

### Toolchain-файл

```cmake
# toolchain-raspberry.cmake

# Цільова система: Linux на процесорі ARM
set(CMAKE_SYSTEM_NAME Linux)
set(CMAKE_SYSTEM_PROCESSOR arm)

# Компілятори для ARM
set(CMAKE_C_COMPILER arm-linux-gnueabihf-gcc)
set(CMAKE_CXX_COMPILER arm-linux-gnueabihf-g++)

# Де шукати бібліотеки та заголовки цільової системи
set(CMAKE_FIND_ROOT_PATH /usr/arm-linux-gnueabihf)

# Програми (cmake, python) шукати на хості, бібліотеки й заголовки в цільовому sysroot
set(CMAKE_FIND_ROOT_PATH_MODE_PROGRAM NEVER)
set(CMAKE_FIND_ROOT_PATH_MODE_LIBRARY ONLY)
set(CMAKE_FIND_ROOT_PATH_MODE_INCLUDE ONLY)
```

Рядки по порядку:

- **`CMAKE_SYSTEM_NAME`** переводить CMake в режим кросплатформної збірки. Після цього змінна `CMAKE_CROSSCOMPILING` стає істинною.
- **`CMAKE_SYSTEM_PROCESSOR`** описує архітектуру процесора. У прикладі `arm` відповідає 32-бітній Raspberry Pi OS. Для 64-бітної системи використовують `aarch64` і компілятор `aarch64-linux-gnu-g++`.
- **`CMAKE_C_COMPILER`, `CMAKE_CXX_COMPILER`** вказують кросплатформні компілятори. Їх ставлять на хості: наприклад, `sudo apt install g++-arm-linux-gnueabihf` на Ubuntu.
- **`CMAKE_FIND_ROOT_PATH`** — корінь файлової системи цільової платформи (*sysroot*). `find_package`, `find_library` шукають бібліотеки саме там, а не серед бібліотек хоста.
- **Режими `MODE_PROGRAM/LIBRARY/INCLUDE`.** Програми (наприклад, `python` або `protoc`) виконуються на хості, тому їх шукають у системі хоста (`NEVER`). А бібліотеки й заголовки потрібні для цільової платформи, тому їх шукають тільки в sysroot (`ONLY`).

### Використання

```bash
cmake -S . -B build-rpi -DCMAKE_TOOLCHAIN_FILE=toolchain-raspberry.cmake
cmake --build build-rpi
```

Перевірити, що результат справді призначений для ARM, можна командою `file`:

```bash
file build-rpi/MyApp
# build-rpi/MyApp: ELF 32-bit LSB executable, ARM, EABI5 ...
```

Запускати цей файл на ПК не вийде. Його копіюють на Raspberry Pi (наприклад, `scp build-rpi/MyApp pi@raspberrypi:~`) й запускають там. Для швидкої перевірки без пристрою CMake підтримує емулятор: якщо вказати `-DCMAKE_CROSSCOMPILING_EMULATOR=qemu-arm`, команди `add_test` і CTest запускатимуть тести через `qemu-arm`.

::note
Toolchain-файл читається на самому початку конфігурації, до команди `project()`. Тому параметр `-DCMAKE_TOOLCHAIN_FILE` задається при першому запуску `cmake` для папки збірки. Змінити його в уже налаштованій папці не вийде: створіть нову.
::

::tip
Менеджер vcpkg також вміє збирати бібліотеки для іншої платформи: для цього використовується власний `triplet` (наприклад, `arm-linux`), а його toolchain `vcpkg.cmake` підключає ваш toolchain-файл через змінну `VCPKG_CHAINLOAD_TOOLCHAIN_FILE`. Це детально розглянуто у розділі про vcpkg.
::

## Шаблон нового проєкту

Щоб не повторювати кожного разу структуру з нуля, використовуйте перевірений скрипт створення мінімального проєкту:

```bash
# Створити папку проєкту
mkdir MyNewProject && cd MyNewProject

# Базова структура
mkdir -p src include tests docs scripts

# Головний CMakeLists.txt
cat > CMakeLists.txt << 'EOF'
cmake_minimum_required(VERSION 3.15)
project(MyNewProject VERSION 1.0.0)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

option(BUILD_TESTS "Build tests" ON)

add_executable(${PROJECT_NAME} src/main.cpp)

if(BUILD_TESTS)
    enable_testing()
    add_subdirectory(tests)
endif()
EOF

# Файл тестів (без нього add_subdirectory(tests) завершиться помилкою)
echo "# Тести проєкту додаються тут" > tests/CMakeLists.txt

# Головний файл
cat > src/main.cpp << 'EOF'
#include <iostream>

int main() {
    std::cout << "Hello from MyNewProject!" << std::endl;
    return 0;
}
EOF

# .gitignore
cat > .gitignore << 'EOF'
build/
build-*/
*.user
.vs/
.vscode/
.idea/
EOF

# Готово! Збираємо
cmake -S . -B build
cmake --build build
./build/MyNewProject
```

::warning
У поширених версіях цього шаблону немає рядка зі створенням `tests/CMakeLists.txt`, але опція `BUILD_TESTS` увімкнена за замовчуванням. Тоді `add_subdirectory(tests)` падає з помилкою «The source directory ... does not contain a CMakeLists.txt». Саме цей рядок тут додано, а наслідки його відсутності можна побачити нижче.
::

::terminal-preview{title="шаблон без tests/CMakeLists.txt"}

<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">cmake -S . -B build</strong></div>
<div class="line"><span class="text-red-400 font-bold">CMake Error</span> at CMakeLists.txt:13 (add_subdirectory):</div>
<div class="line">  The source directory</div>
<div class="line">    /.../MyNewProject/tests</div>
<div class="line">  does not contain a CMakeLists.txt file.</div>

::

Після створення `tests/CMakeLists.txt` конфігурація проходить і програма друкує `Hello from MyNewProject!`.

## Питання для самоперевірки

::::accordion

:::accordion-item{label="❓ Чому тестову логіку калькулятора винесено в бібліотеку, а не залишено в main.cpp?" icon="i-lucide-help-circle"}

Тести не можуть підключити `main.cpp` як бібліотеку: у ньому вже є функція `main`, яка вступила б у конфлікт із тестовим `main`. Бібліотека без `main` лінкується і з програмою, і з тестами. Ще одна перевага: логіку можна тестувати без введення даних із клавіатури.

:::

:::accordion-item{label="❓ Для чого Qt потрібен moc, і що робить CMAKE_AUTOMOC?" icon="i-lucide-help-circle"}

Сигнали й слоти Qt реалізовані через додатковий код, який створює утиліта `moc` (*Meta-Object Compiler*) для класів із макросом `Q_OBJECT`. Без `CMAKE_AUTOMOC` довелося б запускати `moc` вручну для кожного такого заголовка. З нею CMake знаходить потрібні класи й підключає згенерований код автоматично.

:::

:::accordion-item{label="❓ Чому в toolchain-файлі програми шукаються на хості, а бібліотеки в sysroot?" icon="i-lucide-help-circle"}

Програми, як-от `python` чи `protoc`, виконуються під час збірки, на вашому комп'ютері, тож потрібні версії для хоста. Бібліотеки й заголовки лінкуються в результуючий файл, який запуститься на Raspberry Pi, тому вони мають бути саме для ARM. Якщо їх сплутати, зберуться бінарні файли для неправильної архітектури.

:::

:::accordion-item{label="❓ Чи можна запустити кросплатформно зібрану програму на комп'ютері розробника?" icon="i-lucide-help-circle"}

Напряму ні: це файл для іншої архітектури, і ОС відмовиться його виконувати. Є два способи: скопіювати на цільовий пристрій або запускати через емулятор (`qemu-arm`), який можна передати CMake через `CMAKE_CROSSCOMPILING_EMULATOR`.

:::

## Практичне завдання

::::accordion

:::accordion-item{label="📋 Завдання: розширення калькулятора" icon="i-lucide-clipboard-list"}

1. Додайте в `Engine` метод `clearHistory()` та тест для нього.
2. Виведіть історію обчислень у `main.cpp` перед виходом, використовуючи `Engine` замість безпосередніх викликів `add`, `subtract` тощо.
3. Додайте опцію `BUILD_SHARED_LIBS` і перевірте, що проєкт збирається і як статична, і як динамічна бібліотека.
4. Додайте команду `install` для програми, бібліотеки та заголовків, виконайте `cmake --install build --prefix out` і подивіться на вміст папки `out`.

:::

:::accordion-item{label="✅ Підказка до пункту 2" icon="i-lucide-check-circle"}

У `main.cpp` створіть один екземпляр `Calculator::Engine engine;`, замість окремих `add(a, b)` викликайте `engine.apply('+', a, b, result)`, а перед виходом пройдіться по `engine.history()` циклом `for (const auto& line : engine.history())`. Залежність програми від `calculator_lib` не змінюється: `Engine` вже у бібліотеці.
