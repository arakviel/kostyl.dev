::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Фреймворк (*framework*):** бібліотека, яка задає каркас застосунку й викликає ваш код.
- **Маршрут (*route*):** відповідність «шлях → обробник».
- **Обробник (*handler*):** функція, що формує відповідь на запит.
- **vcpkg manifest:** файл `vcpkg.json` із переліком залежностей проєкту.
- **Header-only:** бібліотека, що підключається заголовками без окремого компілювання.

::

::

У попередній лекції сервер на сокетах приймав одне з'єднання за раз, читав запит одним викликом `recv` і не вмів нічого, окрім метода й шляху. Фреймворк вирішує ці задачі готовими компонентами.

## Що таке Crow

**Crow** — мікрофреймворк для C++, у якому маршрутизація, розбір HTTP, JSON, шаблони та middleware зібрані в одній бібліотеці. Синтаксис нагадує Flask (Python) і Express (Node.js): маршрут описується однією макрокомандою із лямбдою. Бібліотека побудована на Asio для мережевого введення-виведення, обробляє запити в пулі потоків і працює на Windows, Linux та macOS із GCC, Clang і MSVC.

![Сервер на сокетах проти сервера на Crow](/images/cpp/crow-web/hello-crow/01-sockets-vs-crow.png){.diagram-img}

Crow не змушує розбиратися в сокетах, але й не ховає HTTP: заголовки, статус-коди й тіло залишаються в коді. Це зручно для навчання, бо вивчене переноситься на інші фреймворки.

::note
Серед альтернатив для C++: Drogon (швидший, більше можливостей, складніший), Oat++ (суворіша типізація), Pistache, cpp-httplib (один заголовок, простіший за Crow). Для лекційної серії Crow обрано за читабельний API й вбудовані JSON, шаблони та middleware.
::

## Підключення через vcpkg

Менеджер пакетів **vcpkg** завантажує й збирає залежності. У режимі *manifest* перелік залежностей лежить у файлі `vcpkg.json` поряд із кодом. Тоді CMake під час конфігурації сам викликає vcpkg, і ручна команда `vcpkg install` не потрібна. Докладно це розглянуто в модулі про CMake та vcpkg.

::code-tree

```json [vcpkg.json]
{
  "name": "crow-demos",
  "version": "1.0.0",
  "dependencies": ["crow"]
}
```

```cmake [CMakeLists.txt]
cmake_minimum_required(VERSION 3.20)
project(CrowDemos LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

find_package(Crow CONFIG REQUIRED)

add_executable(hello_crow src/main.cpp)
target_link_libraries(hello_crow PRIVATE Crow::Crow)
```

```cpp [src/main.cpp]
#include "crow.h"

int main() {
    crow::SimpleApp app;

    CROW_ROUTE(app, "/")([] {
        return "Hello, Crow! Привіт, світ!";
    });

    app.port(8080).multithreaded().run();
}
```

::

Рядок `find_package(Crow CONFIG REQUIRED)` знаходить пакет, а `Crow::Crow` — імпортована ціль: разом із лінкуванням вона додає шляхи до заголовків, потрібну версію стандарту й залежність від Asio та потоків.

![Від vcpkg.json до запущеного сервера](/images/cpp/crow-web/hello-crow/02-toolchain.png){.diagram-img}

Конфігурація й збірка:

::tabs
::tabs-item{label="macOS / Linux"}
```bash
cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE=$VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake
cmake --build build
./build/02-hello-crow/hello_crow
```
::
::tabs-item{label="Windows (PowerShell)"}
```powershell
cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE="$env:VCPKG_ROOT\scripts\buildsystems\vcpkg.cmake"
cmake --build build --config Debug
.\build\02-hello-crow\Debug\hello_crow.exe
```
::
::

Файл toolchain повідомляє CMake, де шукати пакети vcpkg. Змінна `VCPKG_ROOT` має вказувати на папку, у якій клоновано vcpkg.

::warning
Перша конфігурація завантажує й збирає Crow та Asio, тому триває довше. Наступні запуски беруть результат із кешу vcpkg.
::

## Розбір коду

Програма складається з чотирьох елементів.

- `crow::SimpleApp app;` створює застосунок без middleware. Версія з middleware (`crow::App<...>`) з'являється в лекції 09.
- `CROW_ROUTE(app, "/")` реєструє маршрут для шляху `/`. Макрос повертає об'єкт, якому у виклику передається обробник.
- Лямбда `[] { return "..."; }` — обробник. Рядок, який вона повертає, Crow загортає у відповідь зі статусом 200.
- `app.port(8080).multithreaded().run()` задає порт, вмикає пул потоків (за кількістю ядер) і запускає цикл прийому з'єднань. Виклик `run()` блокує потік до зупинки сервера.

Журнал запуску показує адресу й кількість потоків:

::terminal-preview{title="./hello_crow 8082"}

<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">./hello_crow 8082</strong></div>
<div class="line">(2026-11-18 13:10:20) [INFO    ] Crow/master server is running at http://0.0.0.0:8082 using 12 threads</div>
<div class="line">(2026-11-18 13:10:20) [INFO    ] Call `app.loglevel(crow::LogLevel::Warning)` to hide Info level logs.</div>
::

Адреса `0.0.0.0` означає, що сервер приймає з'єднання на всіх мережевих інтерфейсах, а не лише з локальної машини. Це зручно для перевірки з телефону в тій самій мережі, але небезпечно на ненадійній мережі.

## Три види відповіді

Повернення рядка дає текстову відповідь. Якщо потрібен інший статус чи тип вмісту, обробник повертає `crow::response`.

```cpp
CROW_ROUTE(app, "/about")([] {
    crow::response res(200, "<h1>Про сервер</h1><p>Працює на Crow.</p>");
    res.set_header("Content-Type", "text/html; charset=utf-8");
    return res;
});

CROW_ROUTE(app, "/health")([] {
    crow::json::wvalue body;
    body["status"] = "ok";
    body["framework"] = "Crow";
    return body;
});
```

Перший маршрут явно задає тип `text/html`. Без заголовка `Content-Type` браузер не знає, чи показувати рядок як HTML, чи як текст. Другий повертає об'єкт `crow::json::wvalue`; Crow серіалізує його й сам ставить `Content-Type: application/json`.

Перевірка:

::terminal-preview{title="curl -i http://localhost:8082/health"}

<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">curl -i http://localhost:8082/health</strong></div>
<div class="line">HTTP/1.1 200 OK</div>
<div class="line">Content-Type: application/json</div>
<div class="line">Content-Length: 34</div>
<div class="line">Server: Crow/master</div>
<div class="line">Connection: Keep-Alive</div>
<div class="line"></div>
<div class="line">{"framework":"Crow","status":"ok"}</div>
::

Заголовки `Server` і `Connection: Keep-Alive` додав Crow. Порядок ключів у відповіді не збігається з порядком присвоєння і не гарантований: JSON-об'єкт за специфікацією — невпорядкований набір пар, тому клієнт не повинен на порядок покладатися.

## Порт із командного рядка

Порт, зашитий у код, незручний: якщо він зайнятий, потрібно перекомпілювати. Демо читає його з аргументу.

```cpp
int main(int argc, char* argv[]) {
    const int port = argc > 1 ? std::atoi(argv[1]) : 8080;
    crow::SimpleApp app;
    // ...
    app.port(static_cast<uint16_t>(port)).multithreaded().run();
}
```

::caution
Якщо порт зайнятий іншою програмою (наприклад, сервером розробки сайту), запит дійде не до вашого сервера, і відповідь буде чужою. Тому, перш ніж шукати помилку в коді, перевірте, хто слухає порт: `lsof -i :8080` на macOS і Linux, `netstat -ano | findstr :8080` на Windows.
::

## Запитання

::::accordion

:::accordion-item{label="❓ Чому без multithreaded() сервер працює повільніше?" icon="i-lucide-help-circle"}

Без цього виклику всі запити обробляє один потік. Довгий запит блокує решту. Із `multithreaded()` Crow створює пул потоків за кількістю ядер. Обробники при цьому можуть виконуватися одночасно, тому спільні дані між ними потребують синхронізації (див. лекцію про JSON-сховище).

:::

:::accordion-item{label="❓ Що буде, якщо два маршрути мають однаковий шлях?" icon="i-lucide-help-circle"}

Друга реєстрація того самого шляху кидає виняток `std::runtime_error` із текстом `handler already exists for /a`, і програма завершується ще до початку прийому запитів. Помилка проявляється на старті, а не під час першого запиту.

:::

:::accordion-item{label="❓ Чи обов'язково використовувати vcpkg?" icon="i-lucide-help-circle"}

Ні. Crow доступний також через `FetchContent` у CMake або як набір заголовків, скопійований у проєкт. vcpkg вибрано, бо він однаково працює на трьох системах і фіксує версії залежностей у `vcpkg.json`.

:::

## Підсумок

- Crow бере на себе сокети, розбір HTTP і пул потоків. Маршрут описується однією макрокомандою.
- `vcpkg.json` + `find_package(Crow)` + `Crow::Crow` — мінімальний набір для підключення.
- Обробник може повернути рядок, `crow::response` або `crow::json::wvalue`.
- Порт краще брати з аргументу командного рядка, а зайнятий порт перевіряти системною командою.
