# Маршрути й параметри: шляхи, path- і query-параметри

::card-group

::card{title="🎯 Мета лекції" icon="i-lucide-target"}

- Описувати статичні й вкладені маршрути та розуміти, як Crow обирає обробник.
- Використовувати типізовані параметри шляху `<int>`, `<uint>`, `<double>`, `<string>`, `<path>`.
- Читати query-параметри, у тому числі необов'язкові та списки.
- Розрізняти, коли дані кладуть у шлях, а коли в рядок запиту.
- Знати пастки: кодування кирилиці, переповнення `<int>`, слеш наприкінці шляху.

::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Маршрутизація (*routing*):** вибір обробника за методом і шляхом запиту.
- **Path-параметр:** частина шляху, яка передається в обробник як змінна (`/users/<int>`).
- **Query-параметр:** пара `ключ=значення` після `?` (`/search?q=Марія`).
- **Відсоткове кодування (*percent-encoding*):** запис небезпечних символів URL у вигляді `%XX`.

::

::

Попередня лекція завершилась маршрутами, у яких шлях фіксований: `/`, `/about`, `/health`. Реальні API мають ресурси з ідентифікаторами: користувач номер 2, файл за іменем. Описувати окремий маршрут на кожен із них неможливо, тому шлях містить параметри.

## Статичні й вкладені маршрути

Статичний маршрут відповідає одному точному шляху. Вкладеність нічим не відрізняється від звичайного шляху з кількома сегментами.

```cpp
CROW_ROUTE(app, "/")([] { return "Головна"; });
CROW_ROUTE(app, "/api/v1/status")([] { return "API v1 працює"; });
```

Першою частиною шляху часто роблять префікс `/api` і номер версії: коли формат відповіді зміниться, старі клієнти продовжать працювати з `/api/v1`, а нові перейдуть на `/api/v2`.

::note
Crow зіставляє шлях запиту з шаблонами в точності. Шлях `/t/` не збігається з маршрутом `/t` і дає 404. Якщо маршрут оголошено зі слешем наприкінці (`/slash/`), запит на `/slash` отримує перенаправлення 301 на `/slash/`.
::

## Параметри шляху

Якщо в шаблоні маршруту вказано `<тип>`, Crow виділяє цей сегмент зі шляху, перетворює на потрібний тип і передає в обробник аргументом. Кількість і порядок параметрів лямбди відповідають шаблону зліва направо.

```cpp
CROW_ROUTE(app, "/users/<int>")([&users](int id) {
    auto it = users.find(id);
    if (it == users.end()) return crow::response(404, "Користувача не знайдено");
    return crow::response(200, "Користувач: " + it->second);
});
```

| Шаблон | Що приймає | Тип аргумента |
| ------ | ---------- | ------------- |
| `<int>` | ціле зі знаком: `-5`, `42` | `int` |
| `<uint>` | ціле без знака: `7` | `unsigned` |
| `<double>` | число з крапкою або ціле: `2.5`, `5` | `double` |
| `<string>` | один сегмент без слешів | `std::string` |
| `<path>` | решта шляху разом зі слешами | `std::string` |

![Як шаблони маршрутів зіставляються з запитаними шляхами](/images/cpp/crow-web/routes-parameters/02-route-matching.png){.diagram-img}

Тип виконує функцію першої перевірки. Запит `/users/abc` не відповідає шаблону `/users/<int>`, тому обробник не викликається, а Crow повертає 404. Код перевірки «чи це число» писати не потрібно.

::terminal-preview{title="Запити до демо 03-routes"}

<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">curl -s -w ' [%{http_code}]\n' localhost:8083/users/2</strong></div>
<div class="line">Користувач: Марія Коваленко [200]</div>
<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">curl -s -w ' [%{http_code}]\n' localhost:8083/users/9</strong></div>
<div class="line">Користувача не знайдено [404]</div>
<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">curl -s -w ' [%{http_code}]\n' localhost:8083/users/abc</strong></div>
<div class="line">404 Not Found [404]</div>
<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">curl -s localhost:8083/calc/add/2/3</strong></div>
<div class="line">5</div>
<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">curl -s localhost:8083/files/a/b/c.txt</strong></div>
<div class="line">Запитано файл: a/b/c.txt</div>
::

Відповіді 404 тут мають різне походження: на `/users/9` її повернув наш код (маршрут збігся, а користувача немає), а на `/users/abc` — Crow (маршрут не збігся). Клієнту обидві виглядають однаково, але відрізняти їх у голові корисно під час налагодження.

### Кілька параметрів і `<path>`

Параметрів у шляху може бути кілька.

```cpp
CROW_ROUTE(app, "/calc/add/<int>/<int>")([](int a, int b) {
    return std::to_string(a + b);
});
```

Тип `<string>` зупиняється на першому слеші, тому `/s/a/b` не відповідає `/s/<string>`. Для шляхів із вкладеністю, наприклад імен файлів, потрібен `<path>`: він захоплює все до кінця шляху, включно зі слешами.

```cpp
CROW_ROUTE(app, "/files/<path>")([](const std::string& p) {
    return "Запитано файл: " + p;
});
```

::warning
Значення `<path>` приходить від клієнта, і воно може містити `../`. Якщо цей рядок використати як ім'я файлу на диску, запит `/files/../../etc/passwd` прочитає файл поза робочою папкою. Перед відкриттям файлу шлях потрібно перевіряти. Обслуговування файлів розглядається в лекції про статику.
::

## Пастки параметрів шляху

Кожна з них перевірена на демо й проявляється в реальних проєктах.

::::accordion

:::accordion-item{label="⚠️ Переповнення <int> проходить мовчки" icon="i-lucide-alert-triangle"}

Crow розбирає ціле як 64-бітне, а в обробник передає `int`. Якщо число не вміщається, воно просто обрізається:

::terminal-preview{title="curl localhost:8091/i/99999999999"}
<div class="line">int:1215752191</div>
::

Помилки немає, обробник отримав чуже число. Якщо діапазон важливий (ідентифікатори, суми), приймайте `<uint>` або `<string>` і перетворюйте самі з перевіркою діапазону.

:::

:::accordion-item{label="⚠️ <string> не декодує відсоткове кодування" icon="i-lucide-alert-triangle"}

Для запиту `/s/%D0%9C%D0%B0` обробник отримує рядок `%D0%9C%D0%B0`, а не `Ма`. Query-параметри Crow декодує сам, а параметри шляху ні. Якщо ім'я може містити кирилицю чи пробіли, його треба декодувати вручну або передавати в query-параметрі.

:::

:::accordion-item{label="⚠️ Від'ємні числа і <uint>" icon="i-lucide-alert-triangle"}

Запит `/u/-1` не збігається з `/u/<uint>` і дає 404, а не помилку 400 із поясненням. Якщо потрібна інформативна відповідь, приймайте `<string>` і перевіряйте вручну.

:::

::::

## Query-параметри

Параметри після знака `?` не входять до шаблону маршруту. Обробник отримує весь запит і витягує потрібні пари з `req.url_params`.

```cpp
CROW_ROUTE(app, "/search")([&users](const crow::request& req) {
    const char* q = req.url_params.get("q");
    if (!q) return crow::response(400, "Параметр q обов'язковий");

    int limit = 10;
    if (const char* l = req.url_params.get("limit")) limit = std::atoi(l);
    // ... пошук серед користувачів
});
```

Метод `get` повертає `const char*`: вказівник на значення або `nullptr`, якщо параметра немає. Це дає змогу відрізнити обов'язкові параметри від необов'язкових: для обов'язкового відсутність означає 400, для необов'язкового підставляється значення за замовчуванням (тут `limit = 10`).

Значення завжди приходить текстом. Функція `std::atoi` повертає 0 на нечисловому вході, тому для користувацьких даних надійніше `std::stoi` у `try`/`catch` або `std::from_chars`.

::terminal-preview{title="Запити з query-параметрами"}

<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">curl -s --get --data-urlencode "q=Марія" localhost:8083/search</strong></div>
<div class="line">2. Марія Коваленко</div>
<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">curl -s -w ' [%{http_code}]\n' localhost:8083/search</strong></div>
<div class="line">Параметр q обов'язковий [400]</div>
<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">curl -s -w ' [%{http_code}]\n' "localhost:8083/search?q=x"</strong></div>
<div class="line">Нічого не знайдено [404]</div>
::

### Кирилиця в URL

Якщо в адресу вписати кирилицю прямо (`/search?q=Марія`), `curl` надішле сирі байти UTF-8, а Crow закриє з'єднання без відповіді: символи поза ASCII в запиті недопустимі. Браузер кодує їх сам, а в `curl` для цього є `--data-urlencode` разом із `--get`. Закодований запит має вигляд `/search?q=%D0%9C%D0%B0%D1%80`, і значення, яке бачить обробник, уже декодоване.

### Списки значень

Один параметр може повторюватися. Crow читає такі списки за ключем із квадратними дужками.

```cpp
CROW_ROUTE(app, "/tags")([](const crow::request& req) {
    std::ostringstream out;
    for (const auto& t : req.url_params.get_list("t")) out << t << "\n";
    return out.str();
});
```

::terminal-preview{title="Список значень"}

<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">curl "localhost:8083/tags?t[]=cpp&t[]=web"</strong></div>
<div class="line">cpp</div>
<div class="line">web</div>
::

Запит `/tags?t=cpp&t=web` (без дужок) поверне порожню відповідь: метод `get_list("t")` шукає ключ `t[]`.

## Параметр у шляху чи в запиті

Обидва способи передають дані, але мають різне призначення.

| Критерій | Path-параметр | Query-параметр |
| -------- | ------------- | -------------- |
| Що описує | ідентифікує конкретний ресурс | уточнює вибірку чи відображення |
| Обов'язковість | завжди присутній | зазвичай необов'язковий |
| Приклад | `/users/2` | `/users?role=admin&page=2` |
| Типізація в Crow | є (`<int>`, `<double>`) | немає, значення — рядок |
| Кирилиця | не декодується | декодується |

Правило вибору: те, без чого ресурс не існує (id), кладуть у шлях; фільтри, сортування, пагінацію та пошук — у query.

## Запитання

::::accordion

:::accordion-item{label="❓ Що буде, якщо два шаблони підходять до одного шляху?" icon="i-lucide-help-circle"}

Наприклад, `/users/me` і `/users/<string>`. Перевірка показала, що пріоритету «статичний над параметричним» немає: виграє маршрут, зареєстрований раніше. Якщо спочатку оголосити `/users/<string>`, запит `/users/me` потрапить у нього. Тому конкретні шляхи реєструють до загальних.

:::

:::accordion-item{label="❓ Чому 404 від Crow і 404 від мого коду мають різний текст?" icon="i-lucide-help-circle"}

Тіло відповіді формує той, хто повертає статус. Для власних помилок повертають структурований JSON (лекція 04), а для невідомих маршрутів налаштовують єдиний обробник `CROW_CATCHALL_ROUTE`.

:::

:::accordion-item{label="❓ Чи безпечно класти пароль чи токен у query-параметр?" icon="i-lucide-help-circle"}

Ні. URL потрапляє в журнали сервера, історію браузера й заголовок `Referer`. Секрети передають у заголовку `Authorization` або в тілі запиту.

:::

## Практика

::::accordion

:::accordion-item{label="📋 Завдання 1: калькулятор" icon="i-lucide-clipboard-list"}

Реалізуйте `/calc/add/<double>/<double>`, `/calc/sub/...`, `/calc/mul/...`, `/calc/div/...`. Для ділення на нуль поверніть 400 із поясненням.

:::

:::accordion-item{label="✅ Розв'язок завдання 1 (ділення)" icon="i-lucide-check-circle"}

```cpp
CROW_ROUTE(app, "/calc/div/<double>/<double>")([](double a, double b) {
    if (b == 0) return crow::response(400, "Ділення на нуль");
    return crow::response(std::to_string(a / b));
});
```

:::

:::accordion-item{label="📋 Завдання 2: конвертер" icon="i-lucide-clipboard-list"}

Створіть `/convert/km-to-miles/<double>` та `/convert/celsius-to-fahrenheit/<double>`. Додайте query-параметр `precision` (кількість знаків після коми, за замовчуванням 2).

:::

:::accordion-item{label="📋 Завдання 3: пошук із пагінацією" icon="i-lucide-clipboard-list"}

Розширте `/search` параметрами `page` і `limit`. Для 25 записів і `limit=10` сторінка 3 має містити 5 записів, а сторінка 4 — повертати порожній список, а не помилку.

:::

:::accordion-item{label="📋 Завдання 4: захист від переповнення" icon="i-lucide-clipboard-list"}

Перепишіть `/users/<int>` на `<string>` із власним перетворенням. Для рядків, що не є числом чи не вміщаються в `int`, поверніть 400 із текстом помилки.

## Підсумок

- Маршрут зіставляється зі шляхом точно; тип параметра у шаблоні відсікає непідходящі запити ще до виклику обробника.
- `<int>` може обрізати надто велике число, `<string>` не декодує `%XX`, `<path>` потребує перевірки на `../`.
- Query-параметри читаються через `req.url_params.get`, який повертає `nullptr` для відсутнього ключа. Списки читаються за ключем `t[]`.
- Ідентифікатор ресурсу кладуть у шлях, фільтри й пагінацію в query.
