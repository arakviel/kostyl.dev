# Шаблони Mustache: MVC, контекст, цикли й екранування

::card-group

::card{title="🎯 Мета лекції" icon="i-lucide-target"}

- Пояснити, навіщо відокремлювати HTML від C++ коду, і описати схему MVC.
- Використовувати синтаксис Mustache: змінні, цикли, умови, інвертовані секції, partials.
- Передавати дані в шаблон через `crow::mustache::context`.
- Збирати сторінку з макета та вмісту.
- Розуміти екранування HTML і чому `{{{ }}}` небезпечні.
- Налаштувати папку шаблонів і знати, що буде, коли шаблон не знайдено.

::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Шаблон (*template*):** HTML із позначками, замість яких підставляються дані.
- **Контекст (*context*):** дані, які передають шаблону під час рендерингу.
- **Рендеринг (*rendering*):** підстановка контексту в шаблон і отримання готового HTML.
- **MVC:** розділення на модель (дані), вигляд (відображення) й контролер (зв'язок).
- **Екранування (*escaping*):** заміна спецсимволів `<`, `>`, `&`, `'` на безпечні послідовності.

::

::

До цього часу сервер повертав JSON, який споживає інша програма. Для людини потрібні сторінки. Формувати HTML рядками в C++ (`"<ul>" + ... + "</ul>"`) швидко перетворюється на нечитабельний код, де верстальник не може змінити розмітку без програміста.

## Розділення відповідальності: MVC

Шаблонізатор дозволяє тримати розмітку в окремих файлах, а в C++ залишати лише логіку. Таке розділення описує схема **MVC** (*Model — View — Controller*).

![Модель, контролер і вигляд у веб-застосунку на Crow](/images/cpp/crow-web/templates-mustache/01-mvc.png){.diagram-img}

- **Модель** містить дані та правила: структури користувачів, репозиторій (лекції 13–15).
- **Контролер** — обробник маршруту: приймає запит, бере дані з моделі, готує контекст.
- **Вигляд** — шаблон: описує розмітку й місця підстановки.

Перевага практична: дизайнер змінює `.html` без перекомпіляції сервера й без доступу до коду, а програміст змінює логіку, не зачіпаючи верстки.

## Mustache

**Mustache** («логіка без логіки») — мінімалістичний шаблонізатор, вбудований у Crow. Він навмисно не має виразів, `if` з умовами чи арифметики: шаблон лише підставляє підготовлені дані. Складну логіку виконує контролер, а шаблон вирішує тільки «показати чи ні» та «повторити для кожного».

![П'ять основних тегів Mustache](/images/cpp/crow-web/templates-mustache/02-tags.png){.diagram-img}

### Змінні й екранування

Тег `{{name}}` підставляє значення з контексту. Спеціальні символи HTML автоматично замінюються на безпечні.

Шаблон `user.html`:

```html
<h1>{{name}}</h1>
<p>Email: {{email}}</p>
<p>Біо (екрановано): {{bio}}</p>
<p>Біо (без екранування): {{{bio}}}</p>
```

Для користувача, у якого `bio` дорівнює `<script>alert('xss')</script>`, результат такий:

::terminal-preview{title="GET /users/2"}

<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">curl -s localhost:8091/users/2</strong></div>
<div class="line">&lt;h1&gt;Марія Коваленко&lt;/h1&gt;</div>
<div class="line">&lt;p&gt;Email: maria@example.com&lt;/p&gt;</div>
<div class="line">&lt;p&gt;Біо (екрановано): &amp;lt;script&amp;gt;alert(&amp;#39;xss&amp;#39;)&amp;lt;&amp;#x2F;script&amp;gt;&lt;/p&gt;</div>
<div class="line">&lt;p&gt;Біо (без екранування): &lt;script&gt;alert('xss')&lt;/script&gt;&lt;/p&gt;</div>
::

Подвійні дужки перетворили `<script>` на текст, який браузер покаже буквально. Потрійні дужки вставили тег як є: браузер виконає скрипт. Це міжсайтове виконання скриптів (**XSS**, *cross-site scripting*): якщо `bio` вводить користувач, зловмисник отримує змогу запускати свій код у браузерах інших відвідувачів.

::warning
Використовуйте `{{{ }}}` лише для HTML, який згенерував сам сервер (наприклад, готовий фрагмент сторінки в макеті). Будь-які дані користувача виводьте тільки через `{{ }}`.
::

Те саме правило захищає й від ін'єкції через query-параметри:

::terminal-preview{title="GET /greet?name=<b>Ivan</b>"}

<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">curl -s -G --data-urlencode "name=&lt;b&gt;Ivan&lt;/b&gt;" localhost:8091/greet | grep Привіт</strong></div>
<div class="line">&lt;p&gt;Привіт, &amp;lt;b&amp;gt;Ivan&amp;lt;&amp;#x2F;b&amp;gt;!&lt;/p&gt;</div>
::

Це виправлення помилки з лекції 04, де `req.url` потрапляв у HTML без екранування.

### Цикли й умови: секції

Секція `{{#ключ}}...{{/ключ}}` має різну поведінку залежно від типу значення:

- для **масиву** вміст повторюється для кожного елемента, і всередині доступні його поля;
- для **булевого `true`** (або непорожнього значення) вміст показується один раз;
- для **`false`**, порожнього масиву чи відсутнього ключа вміст не показується.

**Інвертована секція** `{{^ключ}}...{{/ключ}}` працює навпаки: показується, коли значення «порожнє». Разом вони замінюють `if/else`.

Шаблон `users.html`:

```html
<h1>Користувачі</h1>
{{#has_users}}
<ul>
  {{#users}}
  <li><a href="/users/{{id}}">{{name}}</a>{{#admin}} (адміністратор){{/admin}}</li>
  {{/users}}
</ul>
{{/has_users}}
{{^has_users}}
<p>Користувачів немає.</p>
{{/has_users}}
```

Обробник готує контекст. Вкладені ключі й індекси створюються звичайним присвоєнням:

```cpp
CROW_ROUTE(app, "/users")([](const crow::request& req) {
    const bool empty = req.url_params.get("empty") != nullptr;
    crow::mustache::context ctx;
    ctx["has_users"] = !empty;
    if (!empty) {
        for (size_t i = 0; i < kUsers.size(); ++i) {
            ctx["users"][i]["id"] = kUsers[i].id;
            ctx["users"][i]["name"] = kUsers[i].name;
            ctx["users"][i]["admin"] = kUsers[i].admin;
        }
    }
    return render_page("users.html", ctx, "Користувачі");
});
```

Прапорець `has_users` вводиться окремо, бо в Mustache немає виразу «довжина масиву більше нуля». Контролер обчислює його сам, а шаблон лише читає готове значення. Для `/users?empty=1` показується інвертована секція:

::terminal-preview{title="GET /users?empty=1"}

<div class="line">&lt;main&gt;</div>
<div class="line">    &lt;h1&gt;Користувачі&lt;/h1&gt;</div>
<div class="line">    &lt;p&gt;Користувачів немає.&lt;/p&gt;</div>
<div class="line">&lt;/main&gt;</div>
::

## Макет сторінки

Повторювана частина сторінок (шапка, меню, підвал) виноситься в **макет**. У Crow макет збирають у два кроки: спочатку рендериться вміст сторінки, а потім його HTML передається в макет як змінна.

```cpp
static crow::response render_page(const std::string& page, crow::mustache::context& ctx,
                                  const std::string& title) {
    std::string content = crow::mustache::load(page).render_string(ctx);

    crow::mustache::context layout_ctx;
    layout_ctx["title"] = title;
    layout_ctx["content"] = content;

    crow::response res(crow::mustache::load("layout.html").render_string(layout_ctx));
    res.set_header("Content-Type", "text/html; charset=utf-8");
    return res;
}
```

Макет `layout.html` вставляє вміст через потрійні дужки (це готовий HTML сервера, тому екранувати його не треба) і підключає частину меню:

```html
<!DOCTYPE html>
<html lang="uk">
<head>
  <meta charset="utf-8">
  <title>{{title}} — Демо шаблонів</title>
</head>
<body>
  {{>nav.html}}
  <main>
{{{content}}}
  </main>
  <footer>Сторінку згенеровано сервером на Crow</footer>
</body>
</html>
```

Тег `{{>nav.html}}` — **partial**: Crow завантажує файл `nav.html` із папки шаблонів і вставляє його на місце тега. Партіали зручні для частин, що повторюються: меню, картка товару, форма.

Структура проєкту:

::code-tree

```html [templates/layout.html]
<!DOCTYPE html>
<html lang="uk">
<head><meta charset="utf-8"><title>{{title}}</title></head>
<body>
  {{>nav.html}}
  <main>{{{content}}}</main>
</body>
</html>
```

```html [templates/nav.html]
<nav><a href="/">Головна</a> | <a href="/users">Користувачі</a></nav>
```

```html [templates/users.html]
<h1>Користувачі</h1>
{{#users}}<li>{{name}}</li>{{/users}}
```

```cpp [src/main.cpp]
crow::mustache::set_global_base(TEMPLATES_DIR);
// ... маршрути з render_page(...)
```

::

Результат для `/users`:

::terminal-preview{title="GET /users"}

<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">curl -si localhost:8091/users</strong></div>
<div class="line">HTTP/1.1 200 OK</div>
<div class="line">Content-Type: text/html; charset=utf-8</div>
<div class="line">&lt;title&gt;Користувачі — Демо шаблонів&lt;/title&gt;</div>
<div class="line">&lt;nav&gt;&lt;a href="/"&gt;Головна&lt;/a&gt; | &lt;a href="/users"&gt;Користувачі&lt;/a&gt;&lt;/nav&gt;</div>
<div class="line">&lt;li&gt;&lt;a href="/users/1"&gt;Іван Петренко&lt;/a&gt; (адміністратор)&lt;/li&gt;</div>
<div class="line">&lt;li&gt;&lt;a href="/users/2"&gt;Марія Коваленко&lt;/a&gt;&lt;/li&gt;</div>

## Папка шаблонів і пастки

За замовчуванням Crow шукає шаблони в папці `templates/` **відносно поточної робочої папки**. Це означає, що сервер, запущений з іншої папки, шаблонів не знайде. Є два способи це виправити: запускати з кореня проєкту або зашити шлях під час збірки.

Демо використовує другий. CMake передає абсолютний шлях макросом:

```cmake
target_compile_definitions(templates PRIVATE
    TEMPLATES_DIR="${CMAKE_CURRENT_SOURCE_DIR}/templates")
```

У коді шлях задається функцією `set_global_base`:

```cpp
crow::mustache::set_global_base(TEMPLATES_DIR);
```

::caution
Існує схожа функція `crow::mustache::set_base`, але вона діє «на рівні маршруту» і скидається перед кожним обробником. Перша версія демо використовувала саме її. Сервер запускався без помилок, проте всі шаблони виявлялися «не знайденими», коли його запускали не з кореня проєкту. Для шляху на весь застосунок потрібен `set_global_base`.
::

Друга пастка: **відсутній шаблон не дає помилки**. Crow пише в журнал попередження й рендерить порожній рядок, тому клієнт отримує відповідь 200 із порожнім тілом:

::terminal-preview{title="Шаблон не знайдено"}

<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">curl -si localhost:8091/users</strong></div>
<div class="line">HTTP/1.1 200 OK</div>
<div class="line">Content-Type: text/html; charset=utf-8</div>
<div class="line">Content-Length: 0</div>
<div class="line">[WARNING ] Template "users.html" not found.</div>
::

Помилку видно лише в журналі сервера. Перевіряйте журнал після зміни шляхів, а в тестах дивіться на наявність очікуваного тексту, а не лише на код відповіді.

## Запитання

::::accordion

:::accordion-item{label="❓ Чому Mustache не має умов на кшталт if (age > 18)?" icon="i-lucide-help-circle"}

Така логіка виконується в C++, а в шаблон передається готовий результат (`adult: true`). Це тримає шаблони простими й безпечними: у них неможливо випадково виконати довільний код.

:::

:::accordion-item{label="❓ Чи кешує Crow шаблони?" icon="i-lucide-help-circle"}

Функція `crow::mustache::load` читає файл із диска при кожному виклику. Для навчального сервера це зручно: правка `.html` видна після оновлення сторінки без перекомпіляції. У виробництві шаблон завантажують один раз і зберігають `crow::mustache::template_t` у змінній, щоб не читати диск на кожен запит.

:::

:::accordion-item{label="❓ Коли краще повертати JSON, а коли HTML?" icon="i-lucide-help-circle"}

JSON потрібен, коли дані споживає програма: фронтенд на JavaScript, мобільний застосунок, інший сервіс. HTML підходить для сторінок, які бачить людина, і для застосунків, де фронтенд не відокремлюють. Один сервер може віддавати обидва формати на різних маршрутах.

:::

:::accordion-item{label="❓ Чому HTML екранується навіть у атрибутах?" icon="i-lucide-help-circle"}

Лапки `"` і `'` також екрануються, тому значення в `href="{{url}}"` не вирветься з атрибута. Але `{{ }}` не робить безпечним саме посилання: `javascript:alert(1)` залишиться допустимим значенням `href`. Адреси від користувачів перевіряють окремо (дозволена схема `http` або `https`).

:::

## Домашнє завдання

Створіть веб-сторінки для застосунку «Каталог»: головна зі списком, сторінка деталей, форма пошуку (`GET /search?q=`), сторінка 404, спільний макет із меню. Дані зберігаються у `std::vector` або JSON-файлі. Користувацький ввід виводиться лише через `{{ }}`.

Критерії: спільний макет, хоча б один partial, цикл і інвертована секція, пошук без XSS, шаблони знаходяться незалежно від робочої папки.

## Підсумок

- MVC розділяє дані, логіку й відображення: HTML живе в `.html` файлах, а контролер лише готує контекст.
- Mustache має змінні, секції (цикли й умови), інвертовані секції та partials. Логіки в шаблонах немає.
- `{{ }}` екранує HTML і захищає від XSS. `{{{ }}}` застосовують лише до HTML, який створив сервер.
- Папку шаблонів задають `set_global_base`. Відсутній шаблон не дає помилки: лише попередження в журналі й порожня відповідь.
