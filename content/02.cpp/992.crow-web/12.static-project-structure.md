# Статичні файли, MIME-типи й структура проєкту

::card-group

::card{title="🎯 Мета лекції" icon="i-lucide-target"}

- Відрізняти динамічний і статичний вміст та розуміти, чому їх обслуговують по-різному.
- Налаштувати вбудований маршрут `/static/<path>` і папку статики.
- Пояснити, що таке MIME-тип і яку роль відіграє `Content-Type`.
- Написати власну видачу файлів і захистити її від виходу за межі папки.
- Організувати структуру проєкту: шари, ресурси, конфігурація.

::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Статичний файл:** файл, який віддається без змін (CSS, JS, зображення, PDF).
- **MIME-тип (*media type*):** позначка формату вмісту на кшталт `text/css`.
- **Path traversal:** атака, яка за допомогою `../` читає файли поза дозволеною папкою.
- **Кешування:** повторне використання вже отриманого файлу без нового завантаження.
- **Канонічний шлях:** абсолютний шлях без `.`, `..` і символічних посилань.

::

::

Лекція 11 генерує HTML сторінок. Але сторінці потрібні стилі, скрипти, зображення. Це файли, які на сервері не змінюються й не потребують обчислень. Їх просто читають із диска й віддають.

## Статичні й динамічні ресурси

| Критерій | Динамічний | Статичний |
| -------- | ---------- | --------- |
| Приклад | `/users` (HTML або JSON) | `/static/css/style.css` |
| Вміст | залежить від запиту й даних | однаковий для всіх |
| Хто формує | обробник маршруту | файл на диску |
| Кешування | зазвичай заборонене або коротке | довге |

Для статики не потрібен C++ код обробника: достатньо відповідності «URL → файл» і правильних заголовків. Тому веб-сервери мають вбудовану видачу файлів, а на великих проєктах її виносять на окремий сервер чи CDN.

## Вбудований маршрут `/static`

Crow автоматично реєструє маршрут `/static/<path>`, який віддає файли з папки `static/`. Окремий код для цього писати не потрібно.

```text
static/
├── css/style.css
├── js/app.js
├── images/logo.svg
└── index.html
```

::terminal-preview{title="Запити до статики"}

<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">curl -i localhost:8092/static/css/style.css</strong></div>
<div class="line">HTTP/1.1 200 OK</div>
<div class="line">Content-Type: text/css</div>
<div class="line">Content-Length: 55</div>
<div class="line"></div>
<div class="line">body { font-family: sans-serif; background: #f8fafc; }</div>
<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">curl -i localhost:8092/static/images/logo.svg | head -2</strong></div>
<div class="line">HTTP/1.1 200 OK</div>
<div class="line">Content-Type: image/svg+xml</div>
<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">curl -i localhost:8092/static/nope.css | head -1</strong></div>
<div class="line">HTTP/1.1 404 Not Found</div>
::

Папка `static/` за замовчуванням шукається відносно робочої папки, як і `templates/`. Щоб не залежати від місця запуску, її задають макросом `CROW_STATIC_DIRECTORY` під час збірки (з обов'язковим кінцевим слешем):

```cmake
target_compile_definitions(static_files PRIVATE
    CROW_STATIC_DIRECTORY="${CMAKE_CURRENT_SOURCE_DIR}/static/"
    DOWNLOADS_DIR="${CMAKE_CURRENT_SOURCE_DIR}/downloads")
```

Для одного файлу (головної сторінки) використовується `set_static_file_info`. Нюанс: ця функція лише очищає ім'я файлу й шукає його відносно робочої папки, тому для абсолютного шляху, який складає сам сервер, потрібна версія `_unsafe`. Її застосовують тільки до шляхів, у які не потрапляє клієнтський ввід.

```cpp
CROW_ROUTE(app, "/")([](crow::response& res) {
    res.set_static_file_info_unsafe(std::string(CROW_STATIC_DIRECTORY) + "index.html");
    res.end();
});
```

Перша версія демо передавала в безпечну функцію абсолютний шлях і отримувала 404. Саме тому її варіант `_unsafe` існує: він не змінює шлях.

## MIME-типи

Браузер вирішує, що робити з відповіддю, за заголовком `Content-Type`, а не за розширенням у адресі. Значення цього заголовка називають **MIME-типом**: `тип/підтип`.

![Розширення, Content-Type і поведінка браузера](/images/cpp/crow-web/static-project-structure/02-mime.png){.diagram-img}

Помилка в типі має наслідки:

- CSS із типом `text/plain` браузер не застосує до сторінки;
- JavaScript з неправильним типом може бути заблокований політикою безпеки;
- файл невідомого типу (`application/octet-stream`) браузер запропонує зберегти.

Вбудований маршрут Crow визначає тип за розширенням, як видно у виводі вище. Зверніть увагу, що для `text/css` він не додає `charset=utf-8`. Для CSS і JS без кирилиці це неважливо, а для текстових файлів з українською краще керувати типом самому.

## Власна видача файлів

Коли потрібен контроль над типами, кешуванням чи правами, файли віддають власним маршрутом. Приклад: завантаження звітів із папки `downloads/`.

```cpp
CROW_ROUTE(app, "/files/<path>")([&downloads](const std::string& relative) {
    fs::path requested = fs::weakly_canonical(downloads / relative);
    if (!is_inside(downloads, requested))
        return crow::response(403, "Вихід за межі папки заборонено");
    if (!fs::is_regular_file(requested))
        return crow::response(404, "Файл не знайдено");

    std::ifstream in(requested, std::ios::binary);
    std::string body((std::istreambuf_iterator<char>(in)), std::istreambuf_iterator<char>());

    crow::response res(200, body);
    res.set_header("Content-Type", mime_type(requested));
    res.set_header("Cache-Control", "public, max-age=3600");
    return res;
});
```

Тип визначається таблицею розширень:

```cpp
static std::string mime_type(const fs::path& path) {
    static const std::map<std::string, std::string> types = {
        {".html", "text/html; charset=utf-8"}, {".css", "text/css; charset=utf-8"},
        {".js", "application/javascript; charset=utf-8"}, {".json", "application/json"},
        {".txt", "text/plain; charset=utf-8"}, {".csv", "text/csv; charset=utf-8"},
        {".svg", "image/svg+xml"}, {".png", "image/png"}, {".jpg", "image/jpeg"},
    };
    auto it = types.find(path.extension().string());
    return it == types.end() ? "application/octet-stream" : it->second;
}
```

Для невідомого розширення повертається найбезпечніший тип `application/octet-stream`: браузер не намагається інтерпретувати вміст.

::terminal-preview{title="Видача з нашими заголовками"}

<div class="line">HTTP/1.1 200 OK</div>
<div class="line">Content-Type: text/csv; charset=utf-8</div>
<div class="line">Cache-Control: public, max-age=3600</div>
<div class="line">Content-Length: 32</div>

## Path traversal

Маршрут із `<path>` віддає файл за ім'ям, яке надіслав клієнт. Без перевірки запит `/files/../src/main.cpp` вийшов би за межі папки `downloads/` і віддав би файл із вихідним кодом, а `/files/../../../../etc/hosts` — системні файли. Це атака **path traversal**.

![Дозволена папка й заборонені файли поза нею](/images/cpp/crow-web/static-project-structure/01-path-traversal.png){.diagram-img}

Захист складається з двох кроків:

1. **Нормалізувати шлях.** `fs::weakly_canonical(downloads / relative)` перетворює результат на абсолютний шлях, усуваючи `.` і `..`.
2. **Перевірити префікс.** Нормалізований шлях має починатися з шляху дозволеної папки. Функція `is_inside` порівнює шляхи по компонентах, а не як рядки: рядкове порівняння прийняло б сусідню папку `downloads_secret` через спільний префікс.

```cpp
static bool is_inside(const fs::path& base, const fs::path& file) {
    auto b = base.begin();
    auto f = file.begin();
    for (; b != base.end(); ++b, ++f) {
        if (f == file.end() || *f != *b) return false;
    }
    return true;
}
```

Перевірка на практиці:

::terminal-preview{title="Спроби вийти за межі папки"}

<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">curl -i --path-as-is "localhost:8092/files/../src/main.cpp"</strong></div>
<div class="line">HTTP/1.1 403 Forbidden</div>
<div class="line">Вихід за межі папки заборонено</div>
<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">curl -i --path-as-is "localhost:8092/files/../../../../etc/hosts"</strong></div>
<div class="line">HTTP/1.1 403 Forbidden</div>
<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">curl -i "localhost:8092/files/..%2Fsrc%2Fmain.cpp"</strong></div>
<div class="line">HTTP/1.1 404 Not Found</div>
<div class="line">Файл не знайдено</div>
::

Прапорець `--path-as-is` потрібен, бо без нього `curl` сам прибирає `../` з адреси до відправки. Закодована форма `..%2F` отримує 404: параметр `<path>` не декодує `%2F` (лекція 03), тому шукається файл із дивною назвою, якого немає.

Вбудований маршрут `/static` на такі спроби теж відповідає 404:

::terminal-preview{title="Вбудований /static"}

<div class="line"><span class="opacity-40">$</span> <strong class="font-bold">curl -i --path-as-is "localhost:8092/static/../../src/main.cpp" | head -1</strong></div>
<div class="line">HTTP/1.1 404 Not Found</div>
::

::warning
Перевірка `weakly_canonical` + префікс не враховує символічні посилання всередині дозволеної папки, якщо вони ведуть назовні: `weakly_canonical` розкриває їх, тож цей випадок теж буде відхилено, але права файлової системи все одно мають бути мінімальними. Папку з публічними файлами не змішують із конфігурацією, ключами й базами даних.
::

## Кешування

Заголовок `Cache-Control: public, max-age=3600` дозволяє браузеру й проксі зберігати файл годину без нових запитів. Для статики, яка змінюється рідко, це прискорює сторінки й розвантажує сервер.

Проблема: після оновлення `style.css` користувачі ще годину бачать стару версію. Стандартне рішення — додавати до імені версію або хеш (`style.4f2a9c.css`, `/static/css/style.css?v=2`): для браузера це новий ресурс.

Вбудований `/static` Crow у перевірці **не додавав заголовків кешування** (`Cache-Control`, `ETag`, `Last-Modified`). Для політики кешування потрібен або власний маршрут, як вище, або проксі перед сервером.

::note
Для великих файлів (відео, архіви) читання всього файлу в рядок, як у цьому демо, марнує пам'ять. Вбудований `set_static_file_info` віддає файл потоково. Власний маршрут для таких випадків можна побудувати на `set_static_file_info_unsafe` після перевірки шляху.
::

## Структура проєкту

Із застосунком, який складається з маршрутів, шаблонів, статики й даних, потрібна зрозуміла структура папок. Типовий розподіл за відповідальністю:

::code-tree

```cpp [src/main.cpp]
// Точка входу: складання застосунку, реєстрація маршрутів, запуск
#include "routes/user_routes.hpp"
int main() { /* ... */ }
```

```cpp [src/routes/user_routes.hpp]
// Контролери: приймають запит, повертають відповідь
```

```cpp [src/middleware/access_log.hpp]
// Наскрізна логіка: журнал, обмеження частоти, автентифікація
```

```cpp [src/models/user.hpp]
// Моделі даних і правила
```

```cpp [src/data/user_repository.hpp]
// Доступ до даних (лекції 13–15)
```

```html [templates/layout.html]
<!-- Вигляд: HTML-шаблони -->
```

```css [static/css/style.css]
/* Статичні ресурси: стилі, скрипти, зображення */
```

```json [config/settings.json]
{ "port": 8080 }
```

::

Принципи структури:

- **Один шар — одна папка.** Контролери не містять SQL, а моделі не знають про HTTP.
- **Ресурси окремо від коду.** `templates/` і `static/` не змішують із `src/`: їх змінюють інші люди й в іншому ритмі.
- **Конфігурація поза кодом.** Порт, шляхи, ключі — у файлі чи змінних оточення, щоб змінювати їх без перекомпіляції.
- **Шлях до ресурсів не залежить від місця запуску.** Абсолютні шляхи через макроси CMake або обчислення від розташування виконуваного файлу.

Організація маршрутів: коли їх більше десятка, їх групують у функції `register_user_routes(app)`, `register_admin_routes(app)`, які викликає `main`. У Crow для цього також є *blueprints* (`crow::Blueprint`) із префіксом шляху й власними папками шаблонів та статики.

## Запитання

::::accordion

:::accordion-item{label="❓ Чому не можна віддавати файли за повним шляхом, який надіслав клієнт?" icon="i-lucide-help-circle"}

Клієнт може запросити будь-який файл, доступний процесу сервера, включно з ключами й конфігурацією. Тому клієнтський шлях завжди розглядають як відносний до однієї дозволеної папки й перевіряють після нормалізації.

:::

:::accordion-item{label="❓ Чи достатньо перевірити, що в шляху немає рядка ../ ?" icon="i-lucide-help-circle"}

Ні. Обхід можна записати закодовано, з подвійним кодуванням, з різними роздільниками або через символічні посилання. Надійна перевірка виконується над нормалізованим абсолютним шляхом, а не над текстом запиту.

:::

:::accordion-item{label="❓ Чому статику виносять на окремий сервер?" icon="i-lucide-help-circle"}

Nginx чи CDN віддають файли швидше й ближче до користувача, підтримують кешування та стиснення. Сервер застосунку при цьому займається лише динамічними запитами.

:::

:::accordion-item{label="❓ Що буде, якщо віддати HTML-файл користувача з типом text/html?" icon="i-lucide-help-circle"}

Скрипти в такому файлі виконаються в контексті вашого сайту: це знову XSS. Файли, які завантажили користувачі, віддають або як `application/octet-stream`/`attachment`, або з окремого домену.

:::

## Практика

::::accordion

:::accordion-item{label="📋 Завдання 1: сторінка із зображенням" icon="i-lucide-clipboard-list"}

Додайте до шаблонів лекції 11 тег `<link rel="stylesheet" href="/static/css/style.css">` і логотип. Об'єднайте демо: шаблони й статика в одному застосунку.

:::

:::accordion-item{label="📋 Завдання 2: Content-Disposition" icon="i-lucide-clipboard-list"}

Додайте до `/files/<path>` параметр `?download=1`: тоді відповідь має заголовок `Content-Disposition: attachment; filename="..."`, і браузер зберігає файл, а не відкриває.

:::

:::accordion-item{label="✅ Підказка до завдання 2" icon="i-lucide-check-circle"}

```cpp
if (req.url_params.get("download"))
    res.set_header("Content-Disposition",
                   "attachment; filename=\"" + requested.filename().string() + "\"");
```

Обробнику потрібен параметр `const crow::request& req` першим аргументом.

:::

:::accordion-item{label="📋 Завдання 3: ETag" icon="i-lucide-clipboard-list"}

Додайте заголовок `ETag` (наприклад, розмір і час зміни файлу) та обробку `If-None-Match`: якщо значення збігається, повертайте 304 без тіла.

:::

:::accordion-item{label="📋 Завдання 4: список файлів" icon="i-lucide-clipboard-list"}

Створіть `GET /files` у JSON: імена, розміри й типи файлів із `downloads/`. Підпапки пропускайте.

:::

## Домашнє завдання

Збудуйте невеликий сайт «Фотоальбом»: сторінка зі списком зображень із папки (динамічно, шаблон із циклом), перегляд окремого зображення, завантаження файлу (`?download=1`). Власна видача має перевіряти шлях, визначати MIME-тип і ставити `Cache-Control`.

Критерії: захист від path traversal (покажіть `curl --path-as-is` із запитом поза папкою), коректні типи для jpg, png й svg, структура проєкту за шарами, шляхи незалежні від робочої папки.

## Підсумок

- Статичні файли не потребують обробника: Crow віддає їх маршрутом `/static/<path>` з папки, яку задає `CROW_STATIC_DIRECTORY`.
- `Content-Type` визначає, що з файлом зробить браузер. Невідомий тип позначають `application/octet-stream`.
- Шлях від клієнта нормалізують (`weakly_canonical`) і перевіряють, що він лежить усередині дозволеної папки, інакше `../` відкриває весь диск.
- Проєкт розділяють на шари, а шляхи до ресурсів і конфігурацію не прив'язують до місця запуску.
