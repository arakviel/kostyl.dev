# Посилання та зображення в HTML

## Навіщо гіперпосилання змінили світ

1989 рік. Тім Бернерс-Лі пише пропозицію для CERN і формулює концепцію, яка перевернула спосіб поширення знань. Ключова ідея проста і геніальна: **документи повинні посилатися один на одного**. Не копіювати інформацію — а посилатися на неї.

Цей принцип, який ми сьогодні сприймаємо як даність — клікабельне посилання в тексті — лежить в основі Всесвітньої павутини. Без тегу `<a>` інтернет був би набором ізольованих сторінок-островів.

Тег `<img>` з'явився пізніше — у 1993 році в браузері Mosaic. Марк Андрессен запропонував елемент, що дозволяв вбудовувати зображення безпосередньо в текст. До цього в «мережі» були лише слова.

Сьогодні ми розберемо обидва елементи так, як їх визначає **HTML Living Standard** (WHATWG) — актуальна жива специфікація, яку підтримують всі сучасні браузери.

---

## Тег `<a>` — Гіперпосилання

### Що каже специфікація

За визначенням HTML Living Standard, елемент `<a>` (_anchor_ — якір) **представляє гіперпосилання або заповнювач для нього**. Якщо присутній атрибут `href` — це гіперпосилання. Якщо `href` відсутній — це заповнювач (placeholder), де посилання могло бути.

::note
**Content model (модель вмісту за специфікацією):** `<a>` є _transparent_ (прозорим) елементом — він успадковує модель вмісту від свого батьківського елемента. Це означає, що всередині `<a>` дозволено те ж саме, що дозволено в батьку, **за винятком** інтерактивного вмісту.

::

```html
<!-- <a> всередині <p> (flow content) → може містити фразований вміст -->
<p>Відвідайте <a href="https://example.com">наш сайт</a>.</p>

<!-- <a> всередині <ul> (list context) → НЕ може містити <li> -->
<!-- ❌ Це неправильно: -->
<a href="/"><li>Головна</li></a>

<!-- ✅ Правильно: -->
<li><a href="/">Головна</a></li>
```

### Атрибут `href` — адреса посилання

**`href`** (_Hypertext Reference_ — гіпертекстове посилання) визначає URL, на який веде посилання.

::::tabs

:::tabs-item{label="Зовнішні URL"}

Абсолютна адреса — повна URL із протоколом:

::html-preview

```html
<p><a href="https://developer.mozilla.org" target="_blank" rel="noopener noreferrer">MDN Web Docs</a></p>
<p><a href="https://www.youtube.com/watch?v=dQw4w9WgXcQ" target="_blank" rel="noopener noreferrer">YouTube відео</a></p>
```

```css
a { color: #2563eb; text-decoration: underline; }
a:hover { color: #1d4ed8; }
```

::

Зверніть увагу: завжди використовуйте `https://` — не `http://`. Сучасні браузери блокують mixed-content (змішаний вміст).

:::

:::tabs-item{label="Відносні шляхи"}

Відносна адреса — відносно поточного документа або кореня сайту:

```html
<!-- Відносно поточної директорії -->
<a href="about.html">Про нас</a>
<a href="contacts/index.html">Контакти</a>

<!-- Відносно кореня сайту (починається з /) -->
<a href="/products">Каталог</a>
<a href="/blog/2024/my-article">Стаття</a>

<!-- На рівень вище (../) -->
<a href="../index.html">Повернутися до головної</a>
```

Структура папок для цього прикладу:

::html-preview

```html
<pre style="line-height:1.6; font-size:14px;">
site/                       ← корінь сайту ( / )
├── index.html
├── about.html              ← href="about.html"
├── products/
│   └── index.html          ← href="/products"
└── contacts/
    ├── index.html          ← href="contacts/index.html"
    └── map.html            ← з нього: href="../index.html" веде до contacts/index.html
</pre>
```

::

::note
У прев'ю немає файлової системи сайту, тому самі відносні посилання тут не працюють — натомість показано структуру, від якої вони відраховуються.

::

:::

:::tabs-item{label="Якірні (#id)"}

Посилання на конкретний елемент на **поточній або іншій** сторінці:

```html
<!-- Посилання на елемент з id="contacts" на ПОТОЧНІЙ сторінці -->
<a href="#contacts">Перейти до контактів</a>

<!-- Посилання на елемент на ІНШІЙ сторінці -->
<a href="/about#team">Наша команда</a>

<!-- Прокрутка до початку сторінки -->
<a href="#">Вгору ↑</a>
<!-- Краще: -->
<a href="#top">Вгору ↑</a>

<!-- Мета-визначення якоря: -->
<section id="contacts">
    <h2>Контакти</h2>
    <!-- ... -->
</section>
```

Живий приклад: натисніть посилання у верхньому меню та прокрутіть сторінку всередині вікна.

::html-preview

```html
<nav id="top" class="nav">
    <a href="#intro">Вступ</a>
    <a href="#team">Команда</a>
    <a href="#contacts">Контакти</a>
</nav>

<section id="intro" class="block">
    <h2>Вступ</h2>
    <p>Перша секція.</p>
    <a href="#contacts">Перейти до контактів</a>
</section>

<section id="team" class="block">
    <h2>Команда</h2>
    <p>Друга секція.</p>
</section>

<section id="contacts" class="block">
    <h2>Контакти</h2>
    <p>Остання секція.</p>
    <a href="#top">Вгору ↑</a>
</section>
```

```css
a { color: #2563eb; text-decoration: underline; }
a:hover { color: #1d4ed8; }
html { scroll-behavior: smooth; }
h2 { font-size: 1.2rem; font-weight: 700; margin: 0 0 8px; }
.nav { display: flex; gap: 16px; }
.block { min-height: 260px; margin-top: 16px; padding: 16px; border: 1px dashed #94a3b8; border-radius: 12px; }
```

:::tabs-item{label="download"}

Атрибут `download` змушує браузер завантажити файл замість відображення:

```html
<!-- Завантаження файлу з його оригінальною назвою -->
<a href="/files/report-2024.pdf" download>Завантажити звіт</a>

<!-- Завантаження з перейменуванням -->
<a href="/api/export/users.csv" download="список-користувачів.csv"> Експортувати CSV </a>

<!-- Завантаження зображення -->
<a href="/images/logo.svg" download="logo-brand.svg"> Завантажити логотип </a>
```

Працюючий приклад: файл генерується з `data:`-URL, тому клік справді завантажить `.txt`:

::html-preview

```html
<p><a href="data:text/plain;charset=utf-8,Привіт%20від%20kostyl.dev!" download>Завантажити з оригінальною назвою</a></p>

<p><a href="data:text/csv;charset=utf-8,name,score%0AAlice,95%0ABob,88" download="список-користувачів.csv">Експортувати CSV (з перейменуванням)</a></p>
```

```css
a { color: #2563eb; text-decoration: underline; }
a:hover { color: #1d4ed8; }
```

::

Атрибут `download` працює лише для посилань на **той самий origin** (той самий домен + протокол + порт). Для зовнішніх URL браузер ігнорує `download` з міркувань безпеки.

### Атрибут `target` — де відкрити посилання

- `target="_blank"` — відкриває посилання в **новій вкладці або вікні**. Найпоширеніше значення для зовнішніх посилань.
- `target="_self"` — відкриває в **поточній вкладці** (поведінка за замовчуванням).
- `target="_parent"` — відкриває в **батьківському фреймі**. Якщо фрейму немає — поводиться як `_self`.
- `target="_top"` — відкриває в **найвищому контексті перегляду** (весь браузер). Використовується для виходу з iframe-вкладення.

### Безпека: `rel="noopener noreferrer"`

::caution
Відкриваючи посилання з `target="_blank"` **без** `rel`, ви надаєте новій вкладці доступ до батьківської сторінки через `window.opener`. Це класична вразливість — **Tab Napping**: шкідливий сайт може непомітно переадресувати вашу вкладку.

::

::html-preview

```html
<!-- ❌ Небезпечно: нова вкладка має доступ window.opener -->
<p><a href="https://example.com" target="_blank">Сторонній сайт</a></p>

<!-- ✅ Безпечно: window.opener = null -->
<p><a href="https://example.com" target="_blank" rel="noopener noreferrer">Сторонній сайт</a></p>
```

```css
a { color: #2563eb; text-decoration: underline; }
a:hover { color: #1d4ed8; }
```

::

**Розшифровка `rel` для посилань:**

| Значення        | Що означає                                                                               |
| --------------- | ---------------------------------------------------------------------------------------- |
| `noopener`      | Нова вкладка не має доступу до `window.opener`                                           |
| `noreferrer`    | Не передавати заголовок `Referer` (не показувати звідки прийшов користувач)              |
| `nofollow`      | Пошукові роботи не мають слідувати цьому посиланню (для платних чи недовірених посилань) |
| `external`      | Семантична мітка: це посилання веде на зовнішній ресурс                                  |
| `prev` / `next` | Попередня/наступна сторінка в серії (для пагінації)                                      |
| `author`        | Посилання на автора                                                                      |
| `license`       | Посилання на ліцензію контенту                                                           |

::tip
Сучасні браузери (Chrome 88+, Safari 12.1+) автоматично встановлюють `noopener` для `target="_blank"`. Але явне зазначення `rel="noopener noreferrer"` — це **найкраща практика** для сумісності з усіма браузерами.

::

### Атрибут `title` — підказка

::html-preview

```html
<a href="https://www.w3.org/TR/html52/" title="HTML 5.2 — специфікація W3C" target="_blank" rel="noopener noreferrer">
    Специфікація HTML5
</a>
<!-- При наведенні курсора браузер показує підказку з title -->
```

```css
a { color: #2563eb; text-decoration: underline; }
a:hover { color: #1d4ed8; }
```

::

::note
`title` на посиланні не є заміною для доступного тексту. Скринрідери поводяться з ним по-різному — одні зачитують, інші ігнорують. Основний текст посилання має бути зрозумілим без підказки.

## Доступний текст посилання

Це один із найважливіших аспектів якісного HTML. Скринрідери зчитують список усіх посилань на сторінці, і людина з вадами зору має розуміти кожне посилання **без контексту навколишнього тексту**.

::card-group

::card{title="❌ Погано" icon="i-heroicons-x-circle"}

```html
<p>Прочитайте нашу статтю <a href="/article">тут</a>.</p>

<a href="/download">Натисніть тут</a>
<a href="/more">Детальніше</a>
```

Скринрідер оголосить: _"тут", "Натисніть тут", "Детальніше"_ — без жодного контексту.

::

::card{title="✅ Добре" icon="i-heroicons-check-circle"}

```html
<p>Прочитайте нашу статтю <a href="/article">Вступ до HTML5</a>.</p>

<a href="/download">Завантажити PDF-звіт (2.3 МБ)</a>
<a href="/products/camera">Детальніше про Canon EOS R6</a>
```

Скринрідер розуміє кожне посилання окремо.

### Посилання із зображенням

Коли посилання містить тільки зображення (без тексту), атрибут `alt` у `<img>` виконує роль тексту посилання:

::html-preview

```html
<!-- alt зображення = текст посилання -->
<a href="#home">
    <img src="https://picsum.photos/seed/acme-logo/160/60" alt="Головна сторінка компанії Acme" />
</a>

<!-- Порожній alt = посилання без тексту для скринрідера -->
<a href="#home">
    <img src="https://picsum.photos/seed/acme-logo2/160/60" alt="" />
</a>
```

```css
a { display: inline-block; margin-right: 12px; }
img { display: block; border-radius: 8px; }
```

## Тег `<img>` — Зображення

### Що каже специфікація

`<img>` (_image_ — зображення) — **void element** (порожній елемент): він не має закриваючого тегу і не може містити вміст. За специфікацією WHATWG, `<img>` є **embedded content** (вбудований вміст) та **phrasing content** (фрагментний контент).

**Обов'язкові атрибути:**

```html
<!-- src і alt є обов'язковими за специфікацією -->
<img src="photo.jpg" alt="Опис зображення" />
```

Живий приклад:

::html-preview

```html
<!-- src і alt є обов'язковими за специфікацією -->
<img src="https://picsum.photos/seed/minimal/500/300" alt="Опис зображення" />
```

```css
img { max-width: 100%; height: auto; display: block; }
```

::

::caution
Відсутність атрибута `alt` є **порушенням специфікації HTML** і помилкою доступності. Валідатор W3C позначить це як помилку.

::

### Атрибут `alt` — альтернативний текст

`alt` (_alternative text_) — це **текстова альтернатива** для зображення. Він використовується:

- Скринрідерами для озвучення зображення
- Браузером, якщо зображення не завантажилось
- Пошуковими системами для індексування

**Три сценарії використання `alt`:**

::::tabs

:::tabs-item{label="Значуще зображення"}

Зображення несе інформацію — опишіть її:

::html-preview

```html
<!-- Описуйте зміст, а не вигляд -->
<img src="https://picsum.photos/seed/evacuation/400/200" alt="Схема евакуації: вихід ліворуч від ліфта, сходи в кінці коридору" />

<!-- Для зображення з текстом — передайте текст -->
<img src="https://picsum.photos/seed/sale-banner/400/200" alt="Знижки до 50% на всі товари. Тільки до 31 грудня!" />

<!-- Фотографія людини -->
<img src="https://picsum.photos/seed/ceo/200/200" alt="Марія Коваленко, генеральний директор компанії TechUA" />
```

```css
img { max-width: 100%; height: auto; display: block; }
img { margin-bottom: 8px; }
```

::

Наведіть курсор або вимкніть зображення в DevTools: якщо картинка не завантажиться, замість неї з'явиться текст `alt`.

:::

:::tabs-item{label="Декоративне зображення"}

Зображення не несе інформації — `alt` залишаємо **порожнім** (`alt=""`). Скринрідери пропускають такі зображення:

::html-preview

```html
<!-- Декоративна смужка-роздільник -->
<img src="https://picsum.photos/seed/divider/600/40" alt="" />

<!-- Іконка-прикраса поруч з текстом -->
<p>
    <img src="https://picsum.photos/seed/star-icon/24/24" alt="" />
    Рейтинг: 4.8 з 5
</p>

<!-- Фотографія-ілюстрація, яку повністю описує підпис figure -->
<figure>
    <img src="https://picsum.photos/seed/office/600/300" alt="" />
    <figcaption>Офіс компанії TechUA у Києві</figcaption>
</figure>
```

```css
img { max-width: 100%; height: auto; display: block; }
figure { margin: 0; }
figcaption { font-size: 14px; color: #475569; margin-top: 4px; }
p img { display: inline-block; vertical-align: middle; }
```

::

:::

:::tabs-item{label="Функціональне (в <a>)"}

Коли зображення є єдиним вмістом посилання або кнопки — `alt` описує дію:

::html-preview

```html
<!-- alt = те, що робить посилання/кнопка -->
<a href="#top"><img src="https://picsum.photos/seed/logo-fn/120/40" alt="Повернутися на головну" /></a>

<button type="submit">
    <img src="https://picsum.photos/seed/search-ic/20/20" alt="Пошук" />
</button>

<!-- Кнопка закрити -->
<button type="button">
    <img src="https://picsum.photos/seed/close-ic/20/20" alt="Закрити діалог" />
</button>
```

```css
a, button { display: inline-block; margin: 0 8px 8px 0; }
button { border: 1px solid #cbd5e1; border-radius: 8px; padding: 6px 10px; background: #f8fafc; cursor: pointer; }
img { display: block; }
```

### Атрибути розміру: `width` та `height`

Завжди вказуйте `width` і `height` у пікселях. Це критично для **запобігання зміщенню вмісту** (CLS — Cumulative Layout Shift):

::html-preview

```html
<!-- ✅ Браузер резервує місце для зображення до його завантаження -->
<img src="https://picsum.photos/seed/headphones/800/600" alt="Навушники у чорному кольорі" width="800" height="600" />

<!-- Без розмірів: сторінка «стрибає» при завантаженні -->
<img src="https://picsum.photos/seed/headphones2/400/300" alt="Навушники" />
```

```css
img { max-width: 100%; height: auto; display: block; }
img { margin-bottom: 8px; }
```

::

::tip

### Атрибут `loading` — завантаження зображень

::html-preview

```html
<!-- eager (за замовчуванням): завантажити негайно -->
<img src="https://picsum.photos/seed/hero-eager/600/250" alt="Герой-банер" loading="eager" />

<!-- lazy: відкласти завантаження до наближення до viewport -->
<img src="https://picsum.photos/seed/below-fold/600/250" alt="Фото нижче відгину" loading="lazy" />
```

```css
img { max-width: 100%; height: auto; display: block; }
img { margin-bottom: 8px; }
```

::

**Правило використання:**

- `loading="lazy"` — для всіх зображень **нижче лінії відгину** (below the fold)
- `loading="eager"` — для зображень у **верхній частині** сторінки (hero, логотип)

::note
`loading="lazy"` — нативна реалізація без JavaScript. Браузер сам вирішує, коли завантажити зображення. Підтримка: Chrome 76+, Firefox 75+, Safari 15.4+.

::

### Атрибут `decoding` — декодування

::html-preview

```html
<!-- async: декодувати асинхронно (не блокувати рендеринг) -->

<!-- auto: браузер вирішує (за замовчуванням) -->
<img src="https://picsum.photos/seed/dec3/600/300" alt="Фото" decoding="auto" />
```

```css
img { max-width: 100%; height: auto; display: block; }
img { margin-bottom: 8px; }
```

## `<picture>` — адаптивні зображення

Елемент `<picture>` (_picture_) дозволяє браузеру обрати **найбільш відповідне зображення** з набору варіантів. Це відповідь на дві проблеми:

1. **Art direction** — різні зображення для різних розмірів екрана (обрізка, інша композиція)
2. **Format switching** — сучасний формат для тих, хто підтримує, з fallback для решти

### За специфікацією

`<picture>` — **container element** (контейнер). Він містить:

- Нуль або більше елементів `<source>`
- Рівно один елемент `<img>` (обов'язковий, у кінці)

Браузер перевіряє `<source>` **по порядку** і використовує перший, що підходить. `<img>` — fallback, якщо жодна `<source>` не підійшла.

![Алгоритм вибору зображення браузером: source, srcset, sizes та fallback img](/images/html-css/html-links-images/03.png){.diagram-img}

<video controls preload="metadata" playsinline poster="/images/html-css/html-links-images/srcset-file-choice-poster.jpg" class="diagram-img rounded-xl shadow-lg w-full my-6">
  <source src="/videos/html-css/html-links-images/srcset-file-choice.mp4" type="video/mp4">
</video>

### Art direction — різна композиція

::html-preview

```html
<picture>
    <!-- Мобільний: квадратний кадр -->
    <source media="(max-width: 767px)" srcset="https://picsum.photos/seed/speaker/500/500" />
    <!-- Планшет: середній план -->
    <source media="(max-width: 1199px)" srcset="https://picsum.photos/seed/speaker/800/500" />
    <!-- Десктоп: широкий план -->
    <img
        src="https://picsum.photos/seed/speaker/1200/500"
        alt="Доповідач на сцені конференції"
        width="1200"
        height="500"
    />
</picture>
```

```css
img { max-width: 100%; height: auto; display: block; }
```

::

Змінюйте ширину вікна: на вузькому екрані кадр стає квадратним, на широкому — панорамним. Прев'ю-вікно має власну ширину, тож результат найкраще видно, відкривши сторінку у вужчому вікні браузера.

### Format switching — сучасні формати з fallback

::html-preview

```html
<picture>
    <!-- AVIF та WebP — сучасні формати. Браузер бере перший, який підтримує -->
    <!-- <source srcset="/images/hero.avif" type="image/avif" /> -->
    <source srcset="https://picsum.photos/seed/city-hero/900/450.webp" type="image/webp" />
    <!-- JPEG — універсальний fallback -->
    <img
        src="https://picsum.photos/seed/city-hero/900/450.jpg"
        alt="Панорама міста"
        width="900"
        height="450"
        loading="eager"
        decoding="async"
    />
</picture>
```

```css
img { max-width: 100%; height: auto; display: block; }
```

::

::note
У прев'ю використано WebP + JPEG. Джерело AVIF підключається так само: окремий `<source type="image/avif">` **перед** WebP.

::

### `srcset` та `sizes` — ретина та адаптивні розміри

Атрибут `srcset` у `<img>` дозволяє вказати набір зображень для **різної щільності пікселів** або **різних ширин вікна**:

::html-preview

```html
<!-- 1. Дескриптор щільності (x) — для фіксованих розмірів -->
<img
    src="https://picsum.photos/seed/logo-x/200/60"
    srcset="https://picsum.photos/seed/logo-x/400/120 2x, https://picsum.photos/seed/logo-x/600/180 3x"
    alt="Логотип"
    width="200"
    height="60"
/>

<!-- 2. Дескриптор ширини (w) + sizes — для адаптивних зображень -->
<img
    src="https://picsum.photos/seed/mountains/800/450"
    srcset="
        https://picsum.photos/seed/mountains/400/225   400w,
        https://picsum.photos/seed/mountains/800/450   800w,
        https://picsum.photos/seed/mountains/1200/675 1200w,
        https://picsum.photos/seed/mountains/1600/900 1600w
    "
    sizes="
        (max-width: 600px) 100vw,
        (max-width: 1200px) 50vw,
        800px
    "
    alt="Гірський краєвид"
    width="1600"
    height="900"
    loading="lazy"
/>
```

```css
img { max-width: 100%; height: auto; display: block; }
```

::

Змінюйте ширину вікна браузера та відкрийте DevTools → Network: браузер обирає різні файли з `srcset` залежно від ширини та щільності екрана.

**Як читати `sizes`:**

```
sizes="
  (max-width: 600px) 100vw,   ← якщо вікно ≤600px: зображення займає 100% ширини
  (max-width: 1200px) 50vw,   ← якщо вікно ≤1200px: зображення займає 50% ширини
  800px                        ← в іншому разі: фіксована ширина 800px
"
```

Браузер читає `sizes` ліворуч направо і застосовує **перше відповідне** умові значення.

## `<figure>` та `<figcaption>` — Семантичні підписи

Елемент `<figure>` (_figure_) представляє **незалежний вміст**, на який є посилання в основному тексті, але який може бути відокремлений від нього (як малюнок у книзі).

`<figcaption>` (_figure caption_ — підпис до рисунка) — опціональний підпис. Може бути першим або останнім дочірнім елементом `<figure>`.

::html-preview

```html
<!-- Зображення з підписом -->
<figure>
    <img
        src="https://picsum.photos/seed/network/800/400"
        alt="Абстрактне зображення для ілюстрації схеми"
        width="800"
        height="400"
    />
    <figcaption>
        Рис. 1. Архітектура тришарової нейронної мережі для класифікації зображень.
        <cite>Джерело: Deep Learning Book, Goodfellow et al., 2016</cite>
    </figcaption>
</figure>

<!-- Блок коду як figure -->
<figure>
    <figcaption>Лістинг 1: Функція обчислення факторіалу</figcaption>
    <pre><code>function factorial(n) {
    if (n === 0) return 1;
    return n * factorial(n - 1);
}</code></pre>
</figure>

<!-- Цитата як figure -->
<figure>
    <blockquote>
        <p>Будь-який досить просунутий код невідрізнений від магії.</p>
    </blockquote>
    <figcaption>— Артур Кларк (перефраз)</figcaption>
</figure>
```

```css
img { max-width: 100%; height: auto; display: block; }
figure { margin: 0 0 24px; padding: 12px; border: 1px solid #e2e8f0; border-radius: 12px; }
figcaption { margin-top: 8px; font-size: 14px; color: #475569; }
pre { background: #0f172a; color: #e2e8f0; padding: 12px; border-radius: 8px; overflow-x: auto; }
blockquote { margin: 0; padding-left: 12px; border-left: 4px solid #3b82f6; font-style: italic; }
cite { display: block; font-size: 12px; opacity: .7; }
```

::

::note
`<figure>` — для вмісту, на який посилаються в основному тексті («як показано на рисунку 1...»). Якщо вміст є лише декоративним — `<figure>` не потрібен.

::

## Карти зображень — `<map>` та `<area>`

Карта зображення (_image map_) дозволяє визначити **клікабельні зони** поверх зображення. Кожна зона — самостійне посилання.

::html-preview

```html
<!-- Атрибут usemap пов'язує <img> з <map> через # + name -->
<img src="https://picsum.photos/seed/region-map/800/600" alt="Карта регіонів" width="800" height="600" usemap="#regions" />

<map name="regions">
    <!-- shape="rect": прямокутна зона: x1,y1,x2,y2 -->
    <area shape="rect" coords="120,80,280,180" href="#kyiv" alt="Прямокутна зона" />

    <!-- shape="circle": кругла зона: cx,cy,radius -->
    <area shape="circle" coords="350,300,50" href="#poltava" alt="Кругла зона" />

    <!-- shape="poly": довільний многокутник -->
    <area shape="poly" coords="200,100,300,120,320,200,220,210,180,150" href="#cherkasy" alt="Зона-многокутник" />

    <!-- shape="default": решта зображення -->
    <area shape="default" href="#all" alt="Решта карти" />
</map>
```

```css
img { max-width: 100%; height: auto; display: block; }
```

::

Наведіть курсор на зображення: у зонах `<area>` курсор змінюється на «руку». У прев'ю адреси замінено на якорі `#...`, щоб клік не ламав вікно.

::warning
Карти зображень мають низьку доступність і не є адаптивними (координати фіксовані в пікселях). Для сучасних проєктів краще використовуйте **SVG із посиланнями** або **CSS + HTML** замість image maps.

::

## Підсумкова таблиця: атрибути `<a>` та `<img>`

### Атрибути `<a>`

::field-group
::field{name="href" type="string" required}
URL посилання. Без `href` елемент є заповнювачем.

::
::field{name="target" type="string"}
Контекст відкриття: `_blank`, `_self`, `_parent`, `_top` або назва фрейму.

::
::field{name="rel" type="string"}
Відношення між документами. Важливі значення: `noopener`, `noreferrer`, `nofollow`, `external`, `author`, `license`.

::
::field{name="download" type="string"}
Якщо присутній — браузер завантажує файл. Значення атрибуту = ім'я файлу.

::
::field{name="title" type="string"}
Підказка при наведенні. Не замінює доступний текст.

::
::field{name="hreflang" type="string"}
Мова цільового документа (наприклад, `uk`, `en-US`). Підказка для браузера.

::
::field{name="type" type="string"}
MIME-тип цільового ресурсу (наприклад, `application/pdf`). Підказка.

::
::field{name="ping" type="string"}
Список URL, яким браузер надсилає POST-запит при кліку. Використовується для аналітики.

::

::

### Атрибути `<img>`

::field-group
::field{name="src" type="string" required}
URL зображення. Обов'язковий.

::
::field{name="alt" type="string" required}
Альтернативний текст. Обов'язковий (може бути порожнім для декоративних зображень).

::
::field{name="width" type="number"}
Ширина в пікселях. Рекомендовано вказувати для уникнення CLS.

::
::field{name="height" type="number"}
Висота в пікселях. Рекомендовано вказувати разом з `width`.

::
::field{name="loading" type="string"}
`eager` (за замовч.) або `lazy` — відкладене завантаження.

::
::field{name="decoding" type="string"}
`async`, `sync`, `auto` — стратегія декодування зображення.

::
::field{name="srcset" type="string"}
Набір варіантів зображення для різних щільностей (`2x`) або ширин (`800w`).

::
::field{name="sizes" type="string"}
Оголошення відображуваної ширини для кожного media condition. Використовується з `srcset`.

::
::field{name="crossorigin" type="string"}
CORS-налаштування: `anonymous` або `use-credentials`. Для зображень на Canvas або з `fetchpriority`.

::
::field{name="fetchpriority" type="string"}
`high`, `low`, `auto` — пріоритет завантаження. `high` для LCP-зображень (hero).

::
::field{name="usemap" type="string"}
Прив'язка до карти зображення: `#map-name`.

::
::field{name="ismap" type="boolean"}
Серверна карта зображення (застаріла техніка).

::

::

## Практичні завдання

::accordion

::accordion-item{label="🟢 Рівень 1: Базовий — Навігаційне меню" icon="i-lucide-circle"}

Створіть навігаційне меню для сайту університету. Вимоги:

::accordion-item{label="🟡 Рівень 2: Логіка — Галерея з підписами" icon="i-lucide-circle"}

Створіть галерею із 4 фотографій. Кожна фотографія:

1. Загорнута в `<figure>` з `<figcaption>`
2. Посилання на збільшену версію (`/gallery/photo-N-large.jpg`) з `download`
3. Адаптивна версія через `<picture>`: WebP + JPEG fallback
4. Атрибути `width`, `height`, `loading="lazy"`, `decoding="async"`
5. Семантичний `alt` (не «Фото 1», а конкретний опис)

::

::accordion-item{label="🔴 Рівень 3: Архітектура — Картка товару" icon="i-lucide-circle"}

Створіть HTML картки товару (наприклад, ноутбука) з такими елементами:

1. **Зображення товару** — `<picture>` з AVIF + WebP + JPEG, `srcset` з 3 розмірами (`400w`, `800w`, `1200w`), `sizes` для адаптивного відображення, `fetchpriority="high"` (товар вгорі сторінки)
2. **Посилання на товар** — з `<a>` навколо зображення та назви, правильний `title`
3. **Завантаження брошури** — посилання з `download` та зазначеним іменем файлу
4. **Зовнішні посилання** — на офіційний сайт виробника з повним набором `rel`
5. **Карта магазинів** — `<map>` з `<area>` для 3 різних зон схеми торгового центру

**Що демонструє цей приклад:**

::card-group

::card{title="🔗 Посилання" icon="i-heroicons-link"}

Всі типи: зовнішні з `rel="noopener noreferrer external"`, якірні (`#contacts`, `#pricing`), `mailto:`, `tel:`, `download`, з `rel="license"` та `rel="next"`, посилання-зображення

::

::card{title="🖼️ Зображення" icon="i-heroicons-photo"}

Hero з `fetchpriority="high"`, lazy-завантаження галереї, `srcset` + `sizes`, `decoding="async"`, декоративні з `alt=""`

::

::card{title="🎨 `<picture>`" icon="i-heroicons-squares-2x2"}

Art direction (mobile vs desktop), format switching (AVIF → WebP → JPEG), комбіновані `<source>` з `media` та `type`

::

::card{title="📝 Семантика" icon="i-heroicons-document-text"}

`<figure>` + `<figcaption>` для зображень та коду, `<address>` для контактів, `<map>` + `<area>` для схеми
