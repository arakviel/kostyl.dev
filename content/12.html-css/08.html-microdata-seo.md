# Мікророзмітка та SEO в HTML

## Чому пошуковці не розуміють «звичайний» HTML

Уявіть, що ви шукаєте рецепт борщу. Google показує картку з фото, рейтингом 4.7 ⭐, часом приготування «55 хв» та калорійністю — ще до того, як ви перейшли на сайт. Звідки Google знає, що це рецепт? Що «4.7» — це рейтинг, а не ціна? Що «55 хв» — це приготування, а не доставка?

Відповідь — **структуровані дані** (Structured Data). Розробник явно описав вміст своєї сторінки машиночитабельною мовою, і Google її зрозумів.

Без структурованих даних пошуковий робот бачить:

```
"Борщ 4.7 55 хв 312 ккал"
```

З ними — розуміє:

```
Рецепт: "Борщ"
Рейтинг: 4.7/5 (87 відгуків)
Час готування: 55 хвилин
Калорійність: 312 ккал на порцію
```

## `<meta>` для SEO та соцмереж

Базові мета-теги — перший крок до видимості у пошуку.

### Стандартні SEO-теги

```html
<head>
    <!-- Кодування — ЗАВЖДИ першим у <head> -->
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />

    <!-- Заголовок: 50–60 символів, унікальний для кожної сторінки -->
    <title>Курс HTML для початківців — TechUA Academy</title>

    <!-- Опис: 120–160 символів. Відображається у видачі. -->
    <meta
        name="description"
        content="Вивчіть HTML з нуля за 4 тижні. Практичні завдання, живі приклади, сертифікат. Старт щопонеділка. Підходить для тих, хто ніколи не писав код."
    />

    <!-- Роботи: дозволяємо або забороняємо індексацію -->
    <meta name="robots" content="index, follow" />
    <!-- Для сторінок, які не мають бути в пошуку: -->
    <!-- <meta name="robots" content="noindex, nofollow"> -->

    <!-- Іконка сайту (favicon): показується у вкладці браузера та поряд зі сніпетом у видачі.
         Google вимагає розмір кратний 48 px (48×48, 96×96…) або SVG; адреса має бути стабільною -->
    <link rel="icon" href="/favicon.ico" sizes="48x48" />
    <link rel="icon" href="/favicon.svg" type="image/svg+xml" />
    <link rel="apple-touch-icon" href="/apple-touch-icon.png" />

    <!-- Канонічна адреса: яку версію сторінки показувати у видачі -->
    <link rel="canonical" href="https://techua.com/courses/html" />

    <!-- Автор сторінки -->
    <meta name="author" content="Іван Коваленко" />

    <!-- Колір панелі браузера на мобільних -->
    <meta name="theme-color" content="#4f46e5" />
    <meta name="theme-color" content="#312e81" media="(prefers-color-scheme: dark)" />
</head>
```

Змінюйте `<title>` та `description`, щоб побачити, як вони потрапляють у сніпет: довгі значення обрізаються (приблизно до 60 символів для заголовка й 160 для опису; на телефоні менше), а `noindex` прибирає сторінку з видачі зовсім. Меж у символах Google не гарантує: насправді обрізання залежить від ширини тексту в пікселях.

### Open Graph — для соцмереж і месенджерів

Open Graph Protocol (розроблений Facebook) визначає вигляд посилання при поширенні у Facebook, Telegram, WhatsApp, Slack, Discord:

📐 **Специфікація:** [Open Graph Protocol](https://ogp.me/) · [усі `og:` властивості](https://ogp.me/#metadata)

::warning
Open Graph-теги використовують атрибут **`property`**, а не `name`: `<meta property="og:title" …>`. Запис `<meta name="og:title" …>` часто працює випадково, але формально хибний, і частина парсерів його ігнорує. Навпаки, **Twitter Cards використовують `name`**: `<meta name="twitter:card" …>`.
::

```html
<head>
    <!-- Обов'язкові OG-теги -->
    <meta property="og:title" content="Курс HTML для початківців — TechUA Academy" />
    <meta property="og:description" content="Практичний курс: від першого тега до готового сайту. Старт щопонеділка." />
    <meta property="og:image" content="https://techua.com/images/og-course-html.jpg" />
    <!-- Зображення: рекомендований розмір 1200×630 px, мінімум 600×315 -->
    <meta property="og:url" content="https://techua.com/courses/html" />

    <!-- Тип: website, article, product, video.movie, book, profile -->
    <meta property="og:type" content="website" />
    <meta property="og:site_name" content="TechUA Academy" />
    <meta property="og:locale" content="uk_UA" />

    <!-- Для статті (og:type="article") -->
    <meta property="article:author" content="https://techua.com/authors/ivan" />
    <meta property="article:published_time" content="2024-11-20T09:00:00+02:00" />
    <meta property="article:modified_time" content="2024-11-25T14:30:00+02:00" />
    <meta property="article:section" content="HTML" />
    <meta property="article:tag" content="HTML" />
    <meta property="article:tag" content="Веб-розробка" />
</head>
```

Так це посилання виглядає в різних месенджерах. Перемикайте платформу та вимикайте OG-теги, щоб побачити різницю: без них залишається лише голе посилання.

### Twitter Cards

Twitter (X) підтримує власний формат. Якщо OG-теги вже є — Twitter використає їх як резервні:

📐 **Документація:** [Twitter Cards — огляд](https://developer.x.com/en/docs/x-for-websites/cards/overview/abouts-cards)

```html
<head>
    <!-- summary: маленька кнопочка; summary_large_image: велике зображення вгорі -->
    <meta name="twitter:card" content="summary_large_image" />
    <meta name="twitter:site" content="@TechUA_Academy" />
    <meta name="twitter:creator" content="@ivan_koval" />
    <meta name="twitter:title" content="Курс HTML для початківців — TechUA Academy" />
    <meta name="twitter:description" content="Від першого тега до готового сайту. Практично." />
    <meta name="twitter:image" content="https://techua.com/images/og-course-html.jpg" />
    <meta name="twitter:image:alt" content="Скріншот курсу: код HTML в редакторі та результат у браузері" />
</head>
```

Twitter (X) має два основні формати карток. Перемикайте їх і вимикайте `twitter:card`, щоб побачити різницю.

## Schema.org: словник для машин

[Schema.org](https://schema.org) — спільно розроблений Google, Microsoft, Yahoo та Яндексом словник для опису будь-яких сутностей: організацій, людей, товарів, подій, рецептів тощо.

::tip
Кожна розмітка в цій лекції починається зі сторінки типу на schema.org: там видно всі властивості, що дозволені для типу, їхні очікувані значення та батьківські типи. Посилання **📐 Схема** під заголовками ведуть саме туди. Для перевірки власної розмітки — [Schema Markup Validator](https://validator.schema.org/).
::

Реалізується трьома способами:

::card-group

::card{title="JSON-LD" icon="i-heroicons-code-bracket"}
**Рекомендовано Google.** JSON у тегу `<script type="application/ld+json">`. Не пов'язаний з HTML-розміткою — легко генерується на сервері.

::

::card{title="Microdata" icon="i-heroicons-tag"}
Атрибути `itemscope`, `itemtype`, `itemprop` прямо в HTML-тегах. Розмітка злита з версткою — складніше підтримувати.

::

::card{title="RDFa" icon="i-heroicons-document-text"}
Атрибути `typeof`, `property` у форматі RDF. Використовується рідко, здебільшого у наукових/академічних сайтах.

::

## JSON-LD — Детальний розбір

### Синтаксис

Вставляється у `<head>` або перед `</body>`. На одній сторінці може бути **кілька** `<script type="application/ld+json">`:

```html
<script type="application/ld+json">
    {
        "@context": "https://schema.org",
        "@type": "Тип",
        "властивість": "значення"
    }
</script>
```

::note
**`@context` обов'язковий.** Без `"@context": "https://schema.org"` Google не знає, що `@type` і властивості належать до словника Schema.org, і розмітка ігнорується. `@type` задає тип сутності, решта ключів — її властивості.

**Де розміщувати.** `<script type="application/ld+json">` можна вставляти в `<head>` або в `<body>`, а також додавати динамічно через JavaScript (Google виконує JS при індексації, але статична розмітка надійніша). Вставляти JSON-LD у CSS-файл або підключати зовнішнім файлом через `<link>` не можна.
::

📐 **Схема:** [`Organization`](https://schema.org/Organization) · [вимоги Google](https://developers.google.com/search/docs/appearance/structured-data/organization)

## Google Search Features (Rich Results)

Google використовує структуровані дані для створення **розширених результатів** — карток з додатковою інформацією прямо у видачі.

::note
У прикладах нижче показано лише JSON, щоб працювала підсвітка синтаксису. На сторінці його завжди потрібно обгортати в `<script type="application/ld+json"> … </script>`, як у розділі «JSON-LD — Детальний розбір».
::

::warning
**Розмітка не гарантує розширений результат.** Google лише *може* показати rich result: це залежить від якості сторінки, запиту та політик. Без розмітки розширений сніпет майже напевно не з'явиться, але з розміткою він не з'явиться автоматично.

**Розмітка має збігатися з видимим вмістом.** Не можна описувати у JSON-LD те, чого користувач не бачить на сторінці: вигадані відгуки, приховані ціни, неіснуючий рейтинг. За це Google накладає **ручні санкції** (manual action) і знімає розширені результати з усього сайту.
::

Спершу порівняйте звичайний результат і результат із розміткою. Контент сторінки однаковий, відрізняється лише наявність структурованих даних.

## Семантичні теги і сніпети

Окрім JSON-LD, на вигляд сніпета впливає й **звичайна семантична розмітка**. Google будує **featured snippets** («відповідь над видачею»), посилання «Перейти до розділу» та дати безпосередньо з HTML сторінки. Жодна з цих функцій не вмикається тегом автоматично, але **без правильних тегів вони майже не з'являються**.

::note
Google не публікує офіційного списку «тег → сніпет». Нижче поєднано те, що описано в документації Search Central (заголовки, `alt`, `<time>`, `<title>`), і практичні спостереження SEO-спільноти (таблиці, списки, `<dl>`). Результат у видачі залежить від запиту й може змінюватися.
::

## Microdata — Розмітка в HTML

Microdata вбудовується безпосередньо в теги через атрибути. Корисна коли JSON-LD недоступний або контент генерується старим CMS.

### Ключові атрибути

| Атрибут     | Де                | Призначення                 |
| ----------- | ----------------- | --------------------------- |
| `itemscope` | Будь-який елемент | Оголошує початок сутності   |
| `itemtype`  | Де `itemscope`    | URL типу зі schema.org      |
| `itemprop`  | Дочірній елемент  | Ім'я властивості            |
| `itemid`    | Де `itemscope`    | Унікальний URL для сутності |

### Person — Сторінка автора

📐 **Схема:** [`Person`](https://schema.org/Person) · [вимоги Google](https://developers.google.com/search/docs/appearance/structured-data/profile-page)

**Властивості:** [`name`](https://schema.org/name), [`image`](https://schema.org/image), [`jobTitle`](https://schema.org/jobTitle), [`worksFor`](https://schema.org/worksFor), [`sameAs`](https://schema.org/sameAs)

```html
<article itemscope itemtype="https://schema.org/Person">
    <header>
```

## `canonical`, `hreflang` та пагінація

Технічне SEO через `<link>` у `<head>`:

```html
<head>
    <!-- Canonical: яка з дублікатів сторінок є «головною» -->
    <!-- Захищає від duplicate content penalty -->
    <link rel="canonical" href="https://techua.com/courses/html-css" />

    <!-- hreflang: мовні версії сторінки -->
    <link rel="alternate" hreflang="uk" href="https://techua.com/uk/courses/html-css" />
    <link rel="alternate" hreflang="en" href="https://techua.com/en/courses/html-css" />
    <!-- x-default: версія за замовчуванням для інших мов/регіонів -->
    <link rel="alternate" hreflang="x-default" href="https://techua.com/courses/html-css" />

    <!-- Пагінація: для правильної індексації сторінок блогу -->
    <link rel="prev" href="https://techua.com/blog?page=3" />
    <link rel="next" href="https://techua.com/blog?page=5" />
</head>
```

::warning
Помилка з `canonical` — одна з найпоширеніших SEO-проблем. Якщо сторінка доступна через HTTP та HTTPS, www та без www, з `/` та без — Google вважає їх дублікатами. `canonical` вирішує цю проблему.

::

## `robots.txt` та `<meta name="robots">`

Два рівні контролю над індексацією:

```html
<!-- У <head> кожної сторінки -->

<!-- Повний доступ (за замовчуванням) -->
<meta name="robots" content="index, follow" />

<!-- Не індексувати, але переходити по посиланнях -->
<meta name="robots" content="noindex, follow" />

<!-- Індексувати, але не переходити по посиланнях -->
<meta name="robots" content="index, nofollow" />

<!-- Повна заборона -->
<meta name="robots" content="noindex, nofollow" />

<!-- Специфічно для Googlebot -->
<meta name="googlebot" content="noindex, nofollow" />

<!-- Не показувати сніппет (опис) у видачі -->
<meta name="robots" content="nosnippet" />

<!-- Не показувати кешовану версію -->
<meta name="robots" content="noarchive" />

<!-- Максимальна довжина сніппету — 150 символів -->
<meta name="robots" content="max-snippet:150" />

<!-- Поєднання директив -->
<meta name="robots" content="index, follow, max-snippet:160, max-image-preview:large" />
```

## Інструменти перевірки

Два головні валідатори відповідають на різні питання:

| Інструмент | Що перевіряє | Коли використовувати |
|---|---|---|
| **Rich Results Test** (Google) | Чи **придатна** розмітка для розширеного результату Google і яких властивостей бракує | Перед публікацією, щоб побачити, чи отримаєте сніпет |
| **Schema Markup Validator** (schema.org) | Чи **синтаксично та семантично коректна** розмітка за словником Schema.org, незалежно від Google | Для будь-яких типів, зокрема тих, що Google не показує як rich result |

Після публікації результат у видачі відстежують у **Search Console** (розділ «Покращення»).

::card{title="Google Search Console" icon="i-heroicons-chart-bar"}
[search.google.com/search-console](https://search.google.com/search-console) — після публікації: показує, скільки сторінок проіндексовано та які помилки виявлено.

::accordion-item{label="🟡 Рівень 2: Логіка — Сторінка товару з Microdata" icon="i-lucide-circle"}

Реалізуйте HTML-сторінку комп'ютерного магазину за допомогою **Microdata**:

1. `<section itemscope itemtype="Schema:Product">` — назва, зображення, опис
2. Вкладений `itemscope` для `AggregateRating` (рейтинг + кількість відгуків)
3. Вкладений `itemscope` для `Offer` (ціна [UAH], availability [InStock])
4. Два `itemscope` для `Review` (відгуки з `reviewRating`, `author`, `reviewBody`)
5. Одночасно — JSON-LD для `BreadcrumbList` у `<head>`

::

::accordion-item{label="🔴 Рівень 3: Архітектура — Повне SEO-покриття сайту" icon="i-lucide-circle"}

Реалізуйте `<head>` та структуровані дані для онлайн-школи (3 типи сторінок):

**Головна сторінка:**

- `Organization` JSON-LD (з `contactPoint`, `sameAs`, `logo`)
- `WebSite` з `SearchAction` (сайтовий пошук у Google)
- OG type=`website`, Twitter Card `summary`

**Сторінка курсу:**

- `Course` з `hasCourseInstance`, `instructor`, `offers`
- `Product` з `AggregateRating` та 3 відгуками
- `FAQPage` з 5 питаннями
- `BreadcrumbList` (4 рівні)
- OG type=`product`, canonical, hreflang (uk/en/x-default)

**Сторінка статті:**

- `Article` з трьома форматами зображень
- `Person` для автора (з `sameAs` на GitHub та LinkedIn)
- `BreadcrumbList`
- `<meta name="robots">` з `max-snippet:160, max-image-preview:large`

Перевірте все через Google Rich Results Test.

## Підсумок. Від HTML до SEO-готового документа

Ви пройшли повний шлях вивчення HTML — від базової структури документа до технологій, що роблять ваш сайт зрозумілим для пошукових роботів і привабливим для користувачів будь-де.

::card-group

::card{title="Структура та текст" icon="i-heroicons-document-text"}
Ви знаєте анатомію HTML-документа, теги форматування тексту та семантику заголовків.

::

::card{title="Посилання та медіа" icon="i-heroicons-photo"}
Адаптивні зображення з `srcset`, відеоплеєр, `<picture>` для art direction.

::

::card{title="Форми та взаємодія" icon="i-heroicons-cursor-arrow-rays"}
Всі типи `<input>`, валідація, доступність та `autocomplete` для UX.

::

::card{title="Семантика та структура" icon="i-heroicons-building-office-2"}
`article`, `section`, `nav`, `dialog` — сторінки, які розуміють і люди, і роботи.

::

::card{title="Мультимедіа" icon="i-heroicons-play-circle"}
`<video>` з субтитрами, `<canvas>`, `<template>`, inline SVG та правильні `<script>`.

::

::card{title="SEO та мікророзмітка" icon="i-heroicons-rocket-launch"}
Open Graph, JSON-LD, Microdata — Google Rich Results та карти в соцмережах.

::

::
