## Що таке EDA (Exploratory Data Analysis)?

**Exploratory Data Analysis (EDA)** — це перший обов'язковий крок перед побудовою будь-якої ML-моделі. Це процес детального вивчення даних для розуміння їхньої структури, виявлення проблем та пошуку закономірностей.

### Ключові питання EDA:

::card-group

::card{title="📋 Структура" icon="i-lucide-list"}
- Які ознаки є в датасеті?
- Скільки рядків та стовпців?
- Які типи даних (числові, текстові)?
::

::card{title="❓ Проблеми" icon="i-lucide-alert-circle"}
- Чи є пропуски (NaN)?
- Чи є викиди (outliers)?
- Чи є дублікати рядків?
::

::card{title="🔗 Зв'язки" icon="i-lucide-git-branch"}
- Які ознаки корелюють з ціною?
- Які ознаки корелюють між собою?
- Чи є нелінійні залежності?
::

::

> Аналогія: EDA — це як медичний огляд перед операцією. Лікар має знати стан "пацієнта" (датасету): чи є "хвороби" (пропуски), чи все "на місці" (ознаки правильного типу), як працюють "органи" (взаємодія ознак).

::warning
**Типова помилка початківців:** відразу почати будувати модель, не проаналізувавши дані. Результат — погана якість, непередбачувані помилки, годинні втрати на налагодження.

**Правило:** витратьте 30-40% часу на EDA — це окупиться швидким та якісним моделюванням.
::

## Аналіз пропусків (Missing Values)

Пропуски — одна з найбільших проблем реальних датасетів. Давайте виявимо всі стовпці з пропусками та оцінимо їх масштаб.

::jupyter-cell{executionCount="5"}

```python
# Підрахунок пропусків для кожного стовпця
missing = df.isnull().sum()
missing = missing[missing > 0].sort_values(ascending=False)

# Відсоток пропусків
missing_percent = (missing / len(df)) * 100

# Об'єднати в DataFrame
missing_df = pd.DataFrame({
    'Стовпець': missing.index,
    'Пропусків': missing.values,
    'Відсоток': missing_percent.values
})

print(f"Стовпців з пропусками: {len(missing_df)}\n")
print(missing_df.head(10))
```

**Критичні спостереження:**

- **PoolQC** (якість басейну): 99.5% пропусків → майже ніхто не має басейну
- **MiscFeature** (додаткові зручності): 96.3% пропусків → сараї, тенісні корти тощо
- **Alley** (тип під'їзного провулка): 93.8% пропусків → більшість будинків без провулка
- **Fence** (наявність та якість огорожі): 80.8% пропусків
- **FireplaceQu** (якість каміна): 47.3% пропусків → у багатьох будинках взагалі немає каміна
- **LotFrontage** (лінійна довжина фасаду ділянки): 17.7% пропусків
- Характеристики гаража (**GarageType** — тип гаража, **GarageYrBlt** — рік побудови гаража, **GarageFinish** — стан внутрішнього оздоблення, **GarageQual** — якість гаража): по 5.5% (81 будинок взагалі не має гаража)

Ці пропуски — **не помилки**, а реальність: якщо у будинку немає басейну/огорожі/провулка/гаража, значення не заповнене. Але для ML-моделі `NaN` — це проблема.

**Стратегія:**
- Стовпці з >50% пропусків → видалити або заповнити спеціальним значенням "None"
- Стовпці з <20% пропусків → заповнити (imputation)

### Статистика та розподіл

::jupyter-cell{executionCount="7"}

```python
# Базова статистика
print("Статистика SalePrice:")
print(f"  Середня:  ${df['SalePrice'].mean():,.0f}")
print(f"  Медіана:  ${df['SalePrice'].median():,.0f}")
print(f"  Мінімум:  ${df['SalePrice'].min():,.0f}")
print(f"  Максимум: ${df['SalePrice'].max():,.0f}")
print(f"  Std:      ${df['SalePrice'].std():,.0f}")

# Skewness (асиметрія)
skewness = df['SalePrice'].skew()
print(f"\nSkewness: {skewness:.4f}")
if skewness > 0.5:
    print("  → Розподіл скошений вправо (right-skewed)")
    print("  → Більшість будинків дешевші, є кілька дорогих")
```
