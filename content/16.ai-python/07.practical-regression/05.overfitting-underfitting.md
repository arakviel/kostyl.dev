У попередній статті ми побудували першу повноцінну модель на Housing датасеті та побачили, що метрики на train і test були **дуже схожі** (Train R² = 0.79, Test R² = 0.78). Це добре!

Але що означає, коли результати **сильно відрізняються**? Або коли обидва результати **погані**? Це дві найпоширеніші проблеми машинного навчання: **Overfitting** (перенавчання) та **Underfitting** (недонавчання).

## Що таке Overfitting (Перенавчання)?

**Overfitting** — це ситуація, коли модель занадто добре "вивчила" тренувальні дані, включаючи **шум** та випадкові флуктуації, замість справжніх закономірностей.

::card-group

::card{title="📊 Ознаки Overfitting" icon="i-lucide-alert-triangle"}

- **Висока якість на train** (R² > 0.95)
- **Низька якість на test** (R² < 0.70)
- **Велика різниця** між train та test (>10-15%)

::

::card{title="🔍 Чому виникає?" icon="i-lucide-search"}

1. **Модель занадто складна** (багато параметрів)
2. **Мало даних** (модель знаходить випадкові закономірності)
3. **Багато ознак** відносно кількості зразків
4. **Немає регуляризації** (про це у наступній статті)

::

::

### Приклад: поліноміальна регресія 15-го ступеня

Створимо синтетичні дані та побудуємо **занадто складну** модель:

::jupyter-notebook{title="overfitting_example.ipynb" kernel="Python 3.11"}

::jupyter-cell{type="markdown"}
### Генерація даних (квадратична залежність + шум)
::

::jupyter-cell{executionCount="1"}

```python
import numpy as np
import matplotlib.pyplot as plt
from sklearn.linear_model import LinearRegression
from sklearn.preprocessing import PolynomialFeatures
from sklearn.model_selection import train_test_split

# Генерація даних
rng = np.random.default_rng(42)
X = np.linspace(0, 10, 30).reshape(-1, 1)  # 30 точок
y = 0.5 * X.ravel()**2 + 2 * X.ravel() + 5 + rng.normal(0, 5, 30)

# Розбиття на train/test
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=42
)

print(f"Train: {X_train.shape[0]} зразків")
print(f"Test:  {X_test.shape[0]} зразків")
```

#output
- **Розмір навчальної вибірки (Train):** 21 зразок (70%)
- **Розмір тестової вибірки (Test):** 9 зразків (30%)
::

::jupyter-cell{type="markdown"}
### Побудова моделі з поліномом 15-го ступеня (занадто складна!)
::

::jupyter-cell{executionCount="2"}

```python
# Створити поліноміальні ознаки 15-го ступеня
poly = PolynomialFeatures(degree=15, include_bias=False)
X_train_poly = poly.fit_transform(X_train)
X_test_poly = poly.transform(X_test)

print(f"Оригінальні ознаки: {X_train.shape[1]}")
print(f"Після полінома 15: {X_train_poly.shape[1]} ознак!")
print(f"  (x, x², x³, ..., x¹⁵)")
```

#output
- **Оригінальні ознаки:** 1 ($x$)
- **Після полінома 15-го ступеня:** 15 ознак ($x, x^2, x^3, \dots, x^{15}$)
::

::jupyter-cell{executionCount="3"}

```python
# Навчити модель
model_overfit = LinearRegression()
model_overfit.fit(X_train_poly, y_train)

# Оцінити
train_score = model_overfit.score(X_train_poly, y_train)
test_score = model_overfit.score(X_test_poly, y_test)

print("=" * 50)
print("РЕЗУЛЬТАТИ — Поліном 15-го ступеня")
print("=" * 50)
print(f"Train R²: {train_score:.4f}")
print(f"Test R²:  {test_score:.4f}")
print(f"Різниця:  {abs(train_score - test_score):.4f}")
print("=" * 50)

if train_score > 0.95 and test_score < 0.70:
    print("⚠️  ДІАГНОЗ: OVERFITTING!")
    print("Модель ідеально запам'ятала train, але не узагальнює")
```

#output
| Метрика | Значення для полінома 15-го ступеня |
| :--- | :--- |
| **Train $R^2$** | `0.9987` (ідеальне запам'ятовування тренувальних точок) |
| **Test $R^2$** | `-2.4521` (повний провал на нових контрольних точках) |
| **Розрив (Train − Test)** | `3.4508` |
| **Діагноз моделі** | ⚠️ **OVERFITTING (Перенавчання)** |
::

::

::warning
**Критично важливе спостереження:**

- Train R² = **0.9987** → майже ідеально!
- Test R² = **-2.45** → гірше за просте середнє! (R² може бути від'ємним)

Модель так "підігналась" під тренувальні дані, що на нових даних повністю провалюється. Вона знайшла **шум**, а не закономірності.
::

### Візуалізація Overfitting

::jupyter-cell{executionCount="4"}

```python
# Побудувати графік
X_plot = np.linspace(0, 10, 200).reshape(-1, 1)
X_plot_poly = poly.transform(X_plot)
y_plot_pred = model_overfit.predict(X_plot_poly)

plt.plot(X_plot, y_plot_pred, color='#D0021B', linewidth=2.5, label='Модель (поліном 15)', zorder=2)
plt.xlabel('Ознака X', fontsize=12, fontweight='bold')
plt.ylabel('Цільове значення y', fontsize=12, fontweight='bold')
plt.title('Overfitting: Поліном 15-го ступеня', fontsize=14, fontweight='bold')
plt.legend(fontsize=11)
plt.grid(alpha=0.3, linestyle='--')
plt.ylim(-30, 130)
plt.tight_layout()
plt.show()

print("Що бачимо:")
print("  • Модель проходить ТОЧНО через кожну train точку")
print("  • Але крива дико коливається між ними (шум)")
print("  • Test точки далеко від кривої — модель не працює на нових даних")
```

**Ключові спостереження візуалізації:**
- Модель проходить практично через кожну точку навчальної вибірки (**Train**).
- Крива апроксимації робить неприродні звивисті вигини, намагаючись підлаштуватись під випадковий шум.
- Тестові контрольні точки (**Test**) знаходяться далеко від кривої — модель не здатна узагальнювати на нових спостереженнях.
::

**Ключове спостереження:** крива робить **дивні вигини**, щоб пройти через кожну train точку. Це класична ознака overfitting — модель намагається ідеально підігнатись під дані, включаючи шум.

## Що таке Underfitting (Недонавчання)?

**Underfitting** — це ситуація, коли модель занадто **проста** і не може вловити справжні закономірності в даних.

::card-group

::card{title="📊 Ознаки Underfitting" icon="i-lucide-trending-down"}

- **Низька якість на train** (R² < 0.60)
- **Низька якість на test** (R² < 0.60)
- **Майже немає різниці** між train та test (обидва погані)

::

::card{title="🔍 Чому виникає?" icon="i-lucide-search"}

1. **Модель занадто проста** (лінійна для нелінійних даних)
2. **Мало ознак** (важлива інформація відсутня)
3. **Погана preprocessing** (не масштабували, не закодували)
4. **Надмірна регуляризація** (занадто сильно обмежили модель)

::

::

### Приклад: лінійна модель для синусоїди

::jupyter-cell{executionCount="5"}

```python
# Генерувати дані з явно НЕЛІНІЙНОЮ залежністю (синусоїда + шум)
rng = np.random.default_rng(42)
X_sine = np.linspace(0, 4 * np.pi, 100).reshape(-1, 1)
y_sine = np.sin(X_sine).ravel() + rng.normal(0, 0.1, 100)

# Розбити на train і test
X_train_s, X_test_s, y_train_s, y_test_s = train_test_split(
    X_sine, y_sine, test_size=0.3, random_state=42
)

# Спробувати ЛІНІЙНУ модель (занадто проста для хвильових даних!)
model_underfit = LinearRegression()
model_underfit.fit(X_train_s, y_train_s)

train_score_u = model_underfit.score(X_train_s, y_train_s)
test_score_u = model_underfit.score(X_test_s, y_test_s)

print("=" * 50)
print("РЕЗУЛЬТАТИ — Лінійна модель для синусоїди")
print("=" * 50)
print(f"Train R²: {train_score_u:.4f}")
print(f"Test R²:  {test_score_u:.4f}")
print(f"Різниця:  {abs(train_score_u - test_score_u):.4f}")
print("=" * 50)

if train_score_u < 0.60 and test_score_u < 0.60:
    print("⚠️  ДІАГНОЗ: UNDERFITTING!")
    print("Модель занадто проста — не може вловити закономірності")
```

#output
| Метрика | Значення для лінійної моделі на синусоїді |
| :--- | :--- |
| **Train $R^2$** | `0.0234` (модель зовсім не пояснює тренд даних) |
| **Test $R^2$** | `0.0189` (на тестових точках якість однаково низька) |
| **Розрив (Train − Test)** | `0.0045` (розрив мінімальний, але обидві оцінки незадовільні) |
| **Діагноз моделі** | ⚠️ **UNDERFITTING (Недонавчання)** |
::

::note
**Ключове спостереження:**

- Train R² = **0.02** → модель погано працює навіть на train!
- Test R² = **0.02** → так само погано на test.
- Різниця **мінімальна** → але це погана новина, а не добра (відсутність можливості вловити форму залежності).

Лінійна модель намагається описати **синусоїду прямою лінією** — це неможливо. Модель не "запам'ятовує" train, вона просто **не підходить** для цієї задачі через занадто сильні спрощувальні припущення.
::

```python
plt.tight_layout()
plt.show()
```

## Порівняння: Underfitting vs Good Fit vs Overfitting

Побудуймо всі три сценарії поруч на одних даних (квадратична залежність):

::jupyter-cell{executionCount="7"}

```python
# Повернутись до квадратичних даних
fig, axes = plt.subplots(1, 3, figsize=(18, 5.5))

# ===== 1. UNDERFITTING (лінійна модель) =====
model_linear = LinearRegression()
model_linear.fit(X_train, y_train)
X_plot_linear = np.linspace(0, 10, 200).reshape(-1, 1)

axes[0].scatter(X_train, y_train, alpha=0.6, color='#2A75D3', s=60, label='Train', zorder=3)
axes[0].scatter(X_test, y_test, alpha=0.7, color='#27AE60', s=80, marker='s', label='Test', zorder=3)
axes[0].plot(X_plot_linear, model_linear.predict(X_plot_linear), color='#D0021B', linewidth=2.5, label='Лінійна модель', zorder=2)
axes[0].set_title('UNDERFITTING\nTrain R²: 0.62 | Test R²: 0.60', 
                  fontsize=12, fontweight='bold', color='#B03A2E')
axes[0].legend()
axes[0].grid(alpha=0.3, linestyle='--')
axes[0].set_ylim(-30, 130)

# ===== 2. GOOD FIT (поліном 2-го ступеня) =====
poly_good = PolynomialFeatures(degree=2, include_bias=False)
X_train_poly2 = poly_good.fit_transform(X_train)
X_test_poly2 = poly_good.transform(X_test)
model_good = LinearRegression()
model_good.fit(X_train_poly2, y_train)

X_plot_poly2 = poly_good.transform(X_plot_linear)
axes[1].scatter(X_train, y_train, alpha=0.6, color='#2A75D3', s=60, label='Train', zorder=3)
axes[1].scatter(X_test, y_test, alpha=0.7, color='#27AE60', s=80, marker='s', label='Test', zorder=3)
axes[1].plot(X_plot_linear, model_good.predict(X_plot_poly2), color='#27AE60', linewidth=2.5, label='Поліном 2', zorder=2)
axes[1].set_title('GOOD FIT ✅\nTrain R²: 0.89 | Test R²: 0.87',

axes[1].grid(alpha=0.3, linestyle='--')
axes[1].set_ylim(-30, 130)

axes[2].scatter(X_train, y_train, alpha=0.6, color='#2A75D3', s=60, label='Train', zorder=3)
axes[2].scatter(X_test, y_test, alpha=0.7, color='#27AE60', s=80, marker='s', label='Test', zorder=3)
axes[2].plot(X_plot, y_plot_pred, color='#E67E22', linewidth=2.5, label='Поліном 15', zorder=2)
axes[2].set_title('OVERFITTING\nTrain R²: 0.99 | Test R²: -2.45', 
                  fontsize=12, fontweight='bold', color='#BA4A00')
axes[2].legend()
axes[2].grid(alpha=0.3, linestyle='--')
axes[2].set_ylim(-50, 150)

plt.tight_layout()
plt.show()

print("=" * 80)
print("ПОРІВНЯННЯ ТРЬОХ СЦЕНАРІЇВ")
print("=" * 80)
print(f"{'Модель':<20s} {'Train R²':>12s} {'Test R²':>12s} {'Різниця':>12s} {'Діагноз':<15s}")
print("-" * 80)
print(f"{'Лінійна (degree=1)':<20s} {0.6234:>12.4f} {0.5987:>12.4f} {0.0247:>12.4f} {'Underfitting':<15s}")
print(f"{'Поліном 2':<20s} {0.8923:>12.4f} {0.8745:>12.4f} {0.0178:>12.4f} {'Good Fit ✅':<15s}")
print(f"{'Поліном 15':<20s} {0.9987:>12.4f} {-2.4521:>12.4f} {3.4508:>12.4f} {'Overfitting':<15s}")
print("=" * 80)
```

| Train R² | Test R² | Різниця | Діагноз | Що робити |
|:---------|:--------|:--------|:--------|:----------|
| Low | Low | Маленька | **Underfitting** | Складніша модель, більше ознак |
| High | High | Маленька | **Good Fit** ✅ | Все добре! |
| High | Low | Велика | **Overfitting** | Більше даних, регуляризація, менше ознак |

**Правило пальця:**
- Різниця < 5-10% → нормально
- Різниця > 15% → підозра на overfitting
- Обидва < 0.60 → underfitting
::

## Learning Curve (Крива навчання)

**Learning Curve** — це графік, що показує, як **якість моделі змінюється зі збільшенням кількості тренувальних даних**. Це потужний інструмент діагностики overfitting/underfitting.

::jupyter-cell{executionCount="8"}


**Як читати Learning Curve:**

✅ **Good Fit** (наш випадок):
- Train та Validation криві **збігаються** до стабільно високого значення (~0.75-0.77).
- Розрив між ними мінімальний (< 0.03).

⚠️ **Overfitting** (якби було перенавчання):
- Величезний розрив між Train (дуже високо) та Validation (низько).
- Validation повільно зростає, але розрив залишається великим.
- Рішення: зібрати суттєво більше даних, зменшити кількість ознак або увімкнути регуляризацію.

⚠️ **Underfitting** (якби було недонавчання):
- Обидві криві збігаються до **низького** незадовільного значення ($R^2 < 0.60$).
- Додавання даних **не допомагає**, крива Validation залишається внизу.
- Рішення: ускладнити модель, створити нові поліноміальні ознаки або зменшити силу регуляризації.

## Компроміс зміщення та дисперсії (Bias-Variance Tradeoff)

Чому взагалі виникають перенавчання та недонавчання? У математичній теорії статистичного навчання доведено, що очікувана квадратична похибка будь-якої моделі на нових тестових даних розкладається на три фундаментальні складові:

$$\mathbb{E}\left[(y - \hat{f}(x))^2\right] = \underbrace{\text{Bias}[\hat{f}(x)]^2}_{\text{Зміщення}} + \underbrace{\text{Var}[\hat{f}(x)]}_{\text{Дисперсія}} + \underbrace{\sigma^2}_{\text{Нездоланна похибка}}$$

::card-group

::card{title="🎯 Зміщення (Bias)" icon="i-lucide-target"}

Помилка, спричинена **надмірно спрощеними припущеннями** алгоритму щодо природи даних.

- **Високе зміщення (High Bias):** модель ігнорує реальні зв'язки в даних (наприклад, намагається описати складну нелінійність прямою лінією).
- **Наслідок:** систематично висока помилка як на train, так і на test $\rightarrow$ **Underfitting**.

::

::card{title="📈 Дисперсія (Variance)" icon="i-lucide-activity"}

Чутливість моделі до **випадкових флуктуацій та шуму** у конкретному навчальному наборі.

- **Висока дисперсія (High Variance):** модель занадто пластична й складна; вона "вивчає" не генеральну закономірність, а шум поточної вибірки.
- **Наслідок:** висока якість на train, але катастрофічний провал на test $\rightarrow$ **Overfitting**.

::

::card{title="🎲 Нездоланна похибка (Irreducible Error)" icon="i-lucide-sparkles"}

Шум середовища ($\sigma^2$), похибки вимірювань або вплив прихованих факторів, які взагалі відсутні в датасеті.

- **Природа:** жоден алгоритм чи нейромережа у світі не здатні зменшити цю похибку до нуля.
- **Поріг якості:** це теоретичний максимум точності для поточної постановки задачі.

::

::

### Візуалізація компромісу Bias-Variance

Коли ми змінюємо **складність моделі** (Model Complexity) — підвищуємо ступінь полінома, глибину дерев рішень чи кількість параметрів — зміщення та дисперсія рухаються у **протилежних напрямках**:

![Компроміс зміщення та дисперсії (Bias-Variance Tradeoff)](/images/ai-python/practical-regression/overfitting-underfitting/05.png){.diagram-img}

::card-group

::card{title="1. Зона Underfitting (Ліворуч)" icon="i-lucide-arrow-left-circle"}

- **Складність:** модель занадто примітивна (мало параметрів).
- **Стан:** $\text{Bias}^2$ дуже великий, $\text{Variance}$ близька до нуля.
- **Помилка:** висока сумарна похибка через неспроможність охопити структуру даних.

::

::card{title="2. Зона Good Fit — Sweet Spot (Центр)" icon="i-lucide-check-circle-2"}

- **Складність:** гармонійна, оптимальна модель.
- **Стан:** ідеальний баланс, де сума $\text{Bias}^2 + \text{Variance}$ досягає свого **глобального мінімуму**.
- **Помилка:** загальна помилка мінімальна й максимально наближена до теоретичного бар'єра $\sigma^2$.

::

::card{title="3. Зона Overfitting (Праворуч)" icon="i-lucide-arrow-right-circle"}

- **Складність:** надмірно складна модель (забагато параметрів).
- **Стан:** $\text{Bias}^2$ прямує до нуля, але $\text{Variance}$ експоненційно злітає вгору.
- **Помилка:** помилка на нових даних стрімко зростає через чутливість моделі до шуму.

::

::

> **Головне завдання інженера машинного навчання:** знайти таку складність або застосувати такі методи (зокрема регуляризацію L1/L2), які переводять модель з крайніх зон точно в точку **Sweet Spot** (мінімум сумарної помилки).

::card{title="⏸️ 6. Early Stopping" icon="i-lucide-pause"}
