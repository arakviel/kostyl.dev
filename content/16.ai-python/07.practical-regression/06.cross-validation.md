У попередній статті ми навчились виявляти та діагностувати overfitting і underfitting — дві найпоширеніші проблеми машинного навчання. Але щоб правильно оцінити модель, недостатньо просто розбити дані на train і test один раз.

Чому? Тому що **одне розбиття — це лотерея**.

## Один train/test split — це лотерея

Уявімо експеримент: візьмемо одну і ту саму модель лінійної регресії та навчимо її на Housing датасеті **10 разів**, кожного разу з різним випадковим розбиттям train/test:

::jupyter-notebook{title="random_state_experiment.ipynb" kernel="Python 3.11"}

::jupyter-cell{type="markdown"}
### Експеримент: вплив випадковості на результат
::

::jupyter-cell{executionCount="1"}

```python
import pandas as pd
import numpy as np
from sklearn.linear_model import LinearRegression
from sklearn.model_selection import train_test_split

# Завантажити та підготувати дані Housing Prices
df = pd.read_csv('train.csv')

# Відбираємо ключові ознаки (з українськими перекладами)
features = [
    'OverallQual',   # Загальна якість матеріалів та оздоблення
    'GrLivArea',      # Житлова площа над рівнем землі (кв. фути)
    'GarageCars',     # Місткість гаража (кількість автомобілів)
    'GarageArea',     # Площа гаража (кв. фути)
    'TotalBsmtSF',    # Загальна площа підвалу (кв. фути)
    '1stFlrSF',       # Площа першого поверху (кв. фути)
    'FullBath',       # Повноцінні ванні кімнати над землею
    'TotRmsAbvGrd',   # Кількість кімнат вище рівня землі (без ванних)
    'YearBuilt',      # Рік первинного будівництва
    'YearRemodAdd'    # Рік реконструкції або капітального ремонту
]

X = df[features].fillna(df[features].median())
y = df['SalePrice']  # Ціна продажу ($) — цільова змінна

# Навчити модель 10 разів з різними random_state
scores = []

for seed in range(10):
    X_train, X_test, y_train, y_test = train_test_split(
        X, y, test_size=0.2, random_state=seed
    )
    
    model = LinearRegression()
    model.fit(X_train, y_train)
    
    test_score = model.score(X_test, y_test)
    scores.append(test_score)
    
    print(f"random_state={seed:2d} → Test R² = {test_score:.4f}")

print("\n" + "=" * 50)
print(f"R² мінімальний:  {min(scores):.4f}")
print(f"R² максимальний: {max(scores):.4f}")
print(f"Різниця:         {max(scores) - min(scores):.4f}")
print(f"Середнє:         {np.mean(scores):.4f}")
print(f"Std:             {np.std(scores):.4f}")
print("=" * 50)
```

## Проблема одного розбиття train/test

Чому один train/test split може бути **ненадійним**? Три основні ризики:

::card-group

::card{title="❌ Ризик 1: Невдалий розподіл" icon="i-lucide-alert-triangle"}

У test випадково потрапили **нерепрезентативні** зразки (наприклад, тільки дорогі будинки або тільки дешеві). Модель, навчена на іншому діапазоні цін, покаже гірший результат.

::

::card{title="❌ Ризик 2: Мала вибірка test" icon="i-lucide-minimize-2"}

20% від 1460 зразків = лише 292 будинки. Для статистично надійної оцінки це може бути замало, особливо якщо у датасеті є рідкісні категорії житла.

::

::card{title="❌ Ризик 3: Неможливо порівняти моделі" icon="i-lucide-git-compare"}

Одна модель може "випадково" виграти через щасливе розбиття. Інша модель, об'єктивно краща, може програти через "невдале" розбиття.

::

::

## Рішення: K-Fold Cross-Validation

**Крос-валідація (Cross-Validation)** — це метод оцінки моделі, який вирішує проблему залежності від одного випадкового розбиття. Замість одного train/test split ми створюємо **k розбиттів** і усереднюємо результати.

**Принцип роботи K-Fold Cross-Validation:**

1. Розбити весь датасет на **k рівних частин** (fold'ів)
2. Кожна частина по черзі стає **тестовою**, решта (k-1) частин — **тренувальною**
3. Навчити модель k разів, кожного разу на іншій комбінації train/test
4. Отримати **k оцінок** якості моделі
5. Обчислити **середнє** та **стандартне відхилення** цих оцінок

::note
**Ключові переваги крос-валідації:**

✅ **Кожен зразок використовується і для навчання, і для тестування** — жоден зразок не "витрачається" лише на test  
✅ **Надійніша оцінка** — середнє з k запусків стабільніше за один випадковий split  
✅ **Оцінка дисперсії моделі** — стандартне відхилення показує, наскільки стабільна модель  
✅ **Об'єктивне порівняння моделей** — випадковість розбиття не впливає на результат вибору  
::

## Візуалізація K-Fold (k=5)

Для наочності розглянемо 5-Fold Cross-Validation на схемі:

![Схема 5-Fold Cross-Validation](/images/ai-python/practical-regression/cross-validation/02.png){.diagram-img}

::tip
**Що означає k=5:**

- Датасет розбивається на **5 рівних частин** (по 20% кожна)
- Модель навчається **5 разів**:
  - Раз 1: train на частинах 2,3,4,5 → test на частині 1
  - Раз 2: train на частинах 1,3,4,5 → test на частині 2
  - Раз 3: train на частинах 1,2,4,5 → test на частині 3
  - Раз 4: train на частинах 1,2,3,5 → test на частині 4
  - Раз 5: train на частинах 1,2,3,4 → test на частині 5

**Кожен зразок:**
- Потрапляє у **test рівно 1 раз** (коли його fold обрано для тестування)
- Потрапляє у **train 4 рази** (у всіх інших ітераціях)

**Фінальна оцінка:** усереднюємо 5 результатів
::

## K-Fold Cross-Validation у scikit-learn

Scikit-learn надає зручну функцію `cross_val_score`, яка виконує всю роботу автоматично:

::jupyter-cell{executionCount="3"}

```python
from sklearn.model_selection import cross_val_score

# Створити модель
model = LinearRegression()

# Виконати 5-fold cross-validation
scores = cross_val_score(
    estimator=model,      # модель для оцінки
    X=X,                  # всі ознаки
    y=y,                  # всі цільові значення
    cv=5,                 # кількість fold'ів
    scoring='r2',         # метрика (R²)
    n_jobs=-1             # використати всі CPU ядра (паралельно)
)

print("Результати 5-Fold Cross-Validation:")
print("=" * 50)
print(f"R² по fold'ам:")
for i, score in enumerate(scores, 1):
    print(f"  Fold {i}: {score:.4f}")

print("\n" + "=" * 50)
print(f"Середнє R²:        {scores.mean():.4f}")
print(f"Стандартне відхил: {scores.std():.4f}")
print(f"95% довірчий інт.: [{scores.mean() - 2*scores.std():.4f}, {scores.mean() + 2*scores.std():.4f}]")
print("=" * 50)
```

### Параметри cross_val_score

| Параметр | Тип | Опис |
|:---------|:----|:-----|
| `estimator` | модель | Будь-яка модель з методами `.fit()` та `.predict()` (LinearRegression, Ridge, RandomForest, тощо) |
| `X` | array/DataFrame | Матриця ознак (весь датасет, без розбиття) |
| `y` | array/Series | Цільова змінна (весь датасет) |
| `cv` | int | Кількість fold'ів (типово 5). Можна також передати об'єкт KFold |
| `scoring` | str | Метрика оцінки (`'r2'`, `'neg_mean_absolute_error'`, тощо) |
| `n_jobs` | int | Кількість паралельних процесів (-1 = всі ядра) |

## Доступні метрики (scoring)

Параметр `scoring` визначає, за якою метрикою оцінювати модель. Для задач регресії доступні:

::card-group

::card{title="r2" icon="i-lucide-percent"}

**R² (коефіцієнт детермінації)**  
**Діапазон:** від -∞ до 1 (чим вище, тим краще)  
**Використання:** за замовчуванням для регресії, показує частку пояснюваної дисперсії

```python
scoring='r2'  # значення за замовчуванням
```

::

::card{title="neg_mean_absolute_error" icon="i-lucide-ruler"}

**MAE (середня абсолютна помилка)**  
**Діапазон:** від -∞ до 0 (чим ближче до 0, тим краще)  
**Використання:** коли потрібна інтерпретована помилка в одиницях цільової змінної

```python
scoring='neg_mean_absolute_error'
# Перетворити на позитивне: -scores.mean()
```

::

::card{title="neg_mean_squared_error" icon="i-lucide-square"}

**MSE (середня квадратична помилка)**  
**Діапазон:** від -∞ до 0 (чим ближче до 0, тим краще)  
**Використання:** коли великі помилки треба "карати" сильніше

```python
scoring='neg_mean_squared_error'
```

::

::card{title="neg_root_mean_squared_error" icon="i-lucide-triangle"}

**RMSE (корінь з MSE)**  
**Діапазон:** від -∞ до 0 (чим ближче до 0, тим краще)  
**Використання:** як MAE, але з більшим штрафом за викиди

```python
scoring='neg_root_mean_squared_error'
```

::

::

::warning
**Чому метрики MAE, MSE, RMSE негативні?**

Scikit-learn **максимізує** значення метрики `scoring`. Але MAE, MSE, RMSE — це **помилки**, які треба **мінімізувати**.

Щоб уніфікувати підхід (завжди максимізувати), sklearn використовує негативні значення:

- MAE = 25,000 → `neg_mean_absolute_error` = **-25,000**
- Менша помилка = більше негативне число = "краще" для максимізації

**Як повернути звичайне позитивне значення:**

```python
mae_scores = cross_val_score(model, X, y, cv=5, scoring='neg_mean_absolute_error')
mae_positive = -mae_scores.mean()  # Помножити на -1
print(f"MAE: ${mae_positive:,.2f}")
```
::

### Приклад використання різних метрик

::jupyter-cell{executionCount="4"}

```python
# Оцінити модель за трьома метриками одночасно
metrics = {
    'R²': 'r2',
    'MAE': 'neg_mean_absolute_error',
    'RMSE': 'neg_root_mean_squared_error'
}

print("=" * 60)
print("ОЦІНКА МОДЕЛІ ЗА РІЗНИМИ МЕТРИКАМИ (5-Fold CV)")
print("=" * 60)

for metric_name, scoring in metrics.items():
    scores = cross_val_score(
        model, X, y, cv=5, scoring=scoring, n_jobs=-1
    )
    
    # Для помилок перетворити на позитивні значення
    if 'neg' in scoring:
        mean_val = -scores.mean()
        std_val = scores.std()
        print(f"{metric_name:5s} = ${mean_val:>10,.2f} ± ${std_val:>8,.2f}")
    else:
        mean_val = scores.mean()
        std_val = scores.std()
        print(f"{metric_name:5s} = {mean_val:>12.4f} ± {std_val:>10.4f}")

print("=" * 60)
```

## Вибір кількості fold'ів (k)

Скільки fold'ів використовувати? Це баланс між **точністю оцінки** та **обчислювальною вартістю**:

| k | Train size | Test size | Переваги | Недоліки | Коли використовувати |
|:--|:-----------|:----------|:---------|:---------|:---------------------|
| **3** | ~67% | ~33% | Швидко | Менш надійна оцінка, велика дисперсія | Великі датасети (>10,000), швидкі експерименти |
| **5** ✅ | 80% | 20% | Баланс швидкості та точності | Стандарт | За замовчуванням для більшості задач |
| **10** | 90% | 10% | Більш надійна оцінка, менша дисперсія | Повільніше (10 моделей) | Коли важлива точність, фінальна оцінка |
| **n (LOO)** | ~100% | 1 зразок | Максимальне використання даних | Дуже повільно | Маленькі датасети (<100 зразків) |

::tip
**Рекомендації з вибору k:**

🚀 **Для швидких експериментів:** `cv=3` або `cv=5`  
📊 **Для фінальної оцінки:** `cv=10`  
💾 **Для маленьких датасетів (<500 зразків):** `cv=10` або навіть Leave-One-Out  
⚡ **Для величезних датасетів (>100,000):** `cv=3` (економія часу)  

**Золоте правило:** більший k → надійніша оцінка, але довше виконання.
::

### Leave-One-Out Cross-Validation (LOO)

**LOO** — це екстремальний випадок k-fold, коли k дорівнює кількості зразків (k = n). Кожен зразок по черзі стає тестовою вибіркою з 1 елемента:

::jupyter-cell{executionCount="5"}

```python
from sklearn.model_selection import LeaveOneOut

# Для демонстрації візьмемо лише перші 50 зразків (інакше дуже довго)
X_small = X.head(50)
y_small = y.head(50)

# Leave-One-Out Cross-Validation
loo = LeaveOneOut()

scores_loo = cross_val_score(
    model, X_small, y_small, cv=loo, scoring='r2', n_jobs=-1
)

print(f"Leave-One-Out Cross-Validation (n={len(X_small)} зразків)")
print(f"Кількість ітерацій: {loo.get_n_splits(X_small)}")
print(f"Середнє R²: {scores_loo.mean():.4f}")
print(f"Std: {scores_loo.std():.4f}")

print(f"\n⚠️ Для повного датасету (1460 зразків) це було б {1460} навчань моделі!")
```

**Leave-One-Out Cross-Validation ($n=50$ зразків):**

| Показник | Значення | Опис |
| :--- | :--- | :--- |
| **Кількість ітерацій (Splits)** | `50` | Окреме навчання моделі для кожного спостереження |
| **Середнє $R^2$** | `0.7834` | Усереднений коефіцієнт детермінації |
| **Стандартне відхилення (Std)** | `0.1823` | Висока дисперсія через розмір тестового фолду в $1$ об'єкт |

::

::note
**Коли використовувати LOO:**

✅ Датасет **дуже маленький** (<100 зразків), і кожен зразок на вагу золота  
✅ Модель **швидко навчається** (лінійна регресія, логістична регресія)  

❌ Датасет **середній або великий** — LOO стане надзвичайно повільним  
❌ Модель **повільна** (Random Forest, нейронні мережі) — час виконання неприйнятний  

Для Housing датасету (1460 зразків) LOO означає **1460 навчань моделі**. З k=5 це лише **5 навчань** → у **292 рази швидше**!
::

## Метод cross_validate — розширена версія

Функція `cross_validate` повертає не тільки test scores, але й **додаткову інформацію**: train scores, час навчання, час передбачення:

::jupyter-cell{executionCount="6"}

```python
from sklearn.model_selection import cross_validate

# Виконати розширену крос-валідацію
results = cross_validate(
    estimator=model,
    X=X,
    y=y,
    cv=5,
    scoring='r2',
    return_train_score=True,   # додатково повернути train scores
    n_jobs=-1
)

# Вивести результати
print("=" * 60)
print("РОЗШИРЕНА КРОС-ВАЛІДАЦІЯ (cross_validate)")
print("=" * 60)

print("\nTest R²:")
for i, score in enumerate(results['test_score'], 1):
    print(f"  Fold {i}: {score:.4f}")
print(f"\nСереднє:  {results['test_score'].mean():.4f} ± {results['test_score'].std():.4f}")

print("\nTrain R²:")
for i, score in enumerate(results['train_score'], 1):
    print(f"  Fold {i}: {score:.4f}")
print(f"\nСереднє:  {results['train_score'].mean():.4f} ± {results['train_score'].std():.4f}")

print("\nЧас виконання:")
print(f"  Навчання:    {results['fit_time'].sum():.3f}s (середнє {results['fit_time'].mean():.3f}s/fold)")
print(f"  Передбачення: {results['score_time'].sum():.3f}s (середнє {results['score_time'].mean():.3f}s/fold)")
print(f"  Загалом:     {results['fit_time'].sum() + results['score_time'].sum():.3f}s")

print("\n" + "=" * 60)

# Перевірка на overfitting
train_test_gap = results['train_score'].mean() - results['test_score'].mean()
print(f"Різниця Train vs Test: {train_test_gap:.4f}")

if train_test_gap > 0.10:
    print("⚠️  Велика різниця → підозра на overfitting")
elif train_test_gap < 0.05:
    print("✅ Маленька різниця → модель узагальнює добре")
else:
    print("📊 Помірна різниця → в межах норми")
```

## Порівняння: Train/Test Split vs Cross-Validation

Підсумуємо відмінності між двома підходами:

| Аспект | Train/Test Split (80/20) | K-Fold Cross-Validation (k=5) |
|:-------|:-------------------------|:------------------------------|
| **Кількість оцінок** | 1 (одне розбиття) | k (5 незалежних оцінок) |
| **Надійність** | Залежить від випадковості розбиття | Висока (усереднення k оцінок) |
| **Використання даних** | 80% train, 20% test (20% "втрачено") | ~100% (кожен зразок у test 1 раз, у train k-1 раз) |
| **Обчислювальна вартість** | Швидко (1 навчання моделі) | Повільно (k навчань моделі) |
| **Оцінка дисперсії** | Неможлива | Можлива (std показує стабільність) |
| **Коли використовувати** | Швидкі експерименти, попередня оцінка | Фінальна оцінка, порівняння моделей |

::note
**Правильний workflow роботи з даними:**

1. **Початковий розбиток:** весь датасет → 80% (train+validation) + 20% (holdout test)
2. **Розробка та вибір моделі:** на 80% використовувати **крос-валідацію** для:
   - Порівняння різних алгоритмів
   - Налаштування гіперпараметрів
   - Діагностики overfitting
3. **Фінальне навчання:** обрати найкращу модель та навчити на **всіх 80%**
4. **Остаточна оцінка:** один раз оцінити на **20% holdout test** → це остаточна оцінка для production

**Важливо:** holdout test **ніколи** не використовується під час розробки, інаке виникає data leakage!
::

---

## Stratified K-Fold для класифікації

Stratified K-Fold — це спеціальна версія крос-валідації для задач **класифікації** з незбалансованими класами.

::warning
**Проблема звичайного K-Fold у класифікації:**

Припустімо, у датасеті 90% зразків класу "0" та 10% класу "1" (незбалансовані класи).

При випадковому розбитті може трапитись ситуація:
- У Fold 1 потрапило **15% класу "1"**
- У Fold 2 потрапило **5% класу "1"**
- У Fold 3 **взагалі немає класу "1"** → модель не навчиться розпізнавати цей клас!

**Stratified K-Fold вирішує це:** гарантує, що у **кожному fold'і** буде **однакова пропорція** класів (90% "0" та 10% "1").
::

::jupyter-cell{executionCount="9"}

```python
from sklearn.model_selection import StratifiedKFold
from sklearn.datasets import make_classification

# Створити синтетичний незбалансований датасет для демонстрації
X_class, y_class = make_classification(
    n_samples=1000, 
    n_features=10, 
    n_informative=5,
    weights=[0.9, 0.1],  # 90% клас 0, 10% клас 1
    random_state=42
)

print(f"Розподіл класів:")
unique, counts = np.unique(y_class, return_counts=True)
for cls, count in zip(unique, counts):
    print(f"  Клас {cls}: {count} зразків ({count/len(y_class)*100:.1f}%)")

# Порівняти звичайний K-Fold та Stratified K-Fold
from sklearn.model_selection import KFold

print("\n" + "=" * 60)
print("ЗВИЧАЙНИЙ K-FOLD (може бути нерівномірний)")
print("=" * 60)

kf = KFold(n_splits=5, shuffle=True, random_state=42)

for i, (train_idx, test_idx) in enumerate(kf.split(X_class), 1):
    y_train_fold = y_class[train_idx]
    y_test_fold = y_class[test_idx]
    
    test_class1_pct = (y_test_fold == 1).sum() / len(y_test_fold) * 100
    print(f"Fold {i}: test має {test_class1_pct:.1f}% класу '1'")

print("\n" + "=" * 60)
print("STRATIFIED K-FOLD (завжди рівномірний)")
print("=" * 60)

skf = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)

for i, (train_idx, test_idx) in enumerate(skf.split(X_class, y_class), 1):
    y_train_fold = y_class[train_idx]
    y_test_fold = y_class[test_idx]
    
    test_class1_pct = (y_test_fold == 1).sum() / len(y_test_fold) * 100
    print(f"Fold {i}: test має {test_class1_pct:.1f}% класу '1'")
```

## Чи замінює CV потребу в окремому test set?

Це одне з найпоширеніших непорозумінь серед початківців у ML.

::warning
**Коротка відповідь: НІ!**

Крос-валідація **НЕ замінює** окремий holdout test set. Ось чому:

**CV використовується для:**
- ✅ Порівняння різних моделей та алгоритмів
- ✅ Налаштування гіперпараметрів (GridSearchCV, RandomizedSearchCV)
- ✅ Оцінки узагальнення під час **розробки**

**Окремий test set потрібен для:**
- ✅ **Фінальної** оцінки обраної моделі (один раз!)
- ✅ Симуляції **реальних нових даних**, які модель ніколи не бачила
- ✅ Уникнення **витоку інформації** (data leakage)

**Чому це важливо:**

Якщо ви порівнюєте 10 моделей через CV та обираєте найкращу, то **інформація з CV вже вплинула на вибір**. CV scores можуть бути трохи завищеними (оптимістичними).

Holdout test забезпечує **незалежну** оцінку після того, як всі рішення вже прийняті.
::

### Правильний workflow

![Схема правильного workflow валідації в машинному навчанні](/images/ai-python/practical-regression/cross-validation/05.png){.diagram-img}

```
                     Весь датасет (100%)
                            │
              ┌─────────────┴──────────────┐
              │                            │
        Train+Val (80%)            Holdout Test (20%)
              │                            │

              │
    ┌─────────┴─────────┐
    │   5-Fold CV       │
    │   на 80% даних    │
    └─────────┬─────────┘
              │
    ┌─────────▼──────────┐
    │ Порівняння моделей │
    │ Hyperparameter     │
    │ Tuning             │
    └─────────┬──────────┘
              │
    ┌─────────▼──────────┐
    │ Обрати найкращу    │
    │ модель             │
    └─────────┬──────────┘
              │
    ┌─────────▼──────────┐

    └─────────┬──────────┘

    ┌─────────▼──────────┐
```

::note
**Ключова ідея:**

- **CV на 80%** — це "внутрішній іспит" для вибору моделі
- **Holdout 20%** — це "зовнішній незалежний іспит", який визначає остаточну оцінку

Holdout test треба використати **лише один раз** після завершення всієї розробки. Якщо ви дивитесь на holdout під час розробки та приймаєте рішення на основі нього — це data leakage!
::

## Nested Cross-Validation для гіперпараметрів

**Nested Cross-Validation** — це двоє вкладених циклів крос-валідації:

- **Зовнішній CV (Outer Loop):** оцінка узагальнення моделі
- **Внутрішній CV (Inner Loop):** пошук оптимальних гіперпараметрів

Це найчесніша оцінка моделі, коли немає окремого holdout test або датасет маленький.

::jupyter-cell{executionCount="10"}

```python
from sklearn.model_selection import GridSearchCV

# Параметри для Ridge regression
param_grid = {
    'alpha': [0.1, 1.0, 10.0, 100.0]
}

# Внутрішній CV: GridSearch для вибору alpha
inner_cv = KFold(n_splits=3, shuffle=True, random_state=42)

grid_search = GridSearchCV(
    estimator=Ridge(),
    param_grid=param_grid,
    cv=inner_cv,        # внутрішній 3-fold
    scoring='r2',
    n_jobs=-1
)

# Зовнішній CV: оцінка узагальнення
outer_cv = KFold(n_splits=5, shuffle=True, random_state=42)

nested_scores = cross_val_score(
    estimator=grid_search,  # GridSearch як estimator
    X=X,
    y=y,
    cv=outer_cv,            # зовнішній 5-fold
    scoring='r2',
    n_jobs=-1
)

print("=" * 60)
print("NESTED CROSS-VALIDATION")
print("=" * 60)
print(f"Зовнішній CV: 5 fold'ів (оцінка узагальнення)")
print(f"Внутрішній CV: 3 fold'и (вибір alpha)")
print()
print(f"Загальна кількість навчань: {5 * 3 * len(param_grid['alpha'])} = {5*3*4}")
print(f"  (5 outer × 3 inner × 4 параметри)")
print()
print(f"Результати зовнішнього CV:")
for i, score in enumerate(nested_scores, 1):
    print(f"  Outer Fold {i}: R² = {score:.4f}")
print()
print(f"Фінальна оцінка: R² = {nested_scores.mean():.4f} ± {nested_scores.std():.4f}")
print("=" * 60)
```

| :--- | :--- | :--- |

::tip
**Nested CV:**

**Коли використовувати:**
- Маленькі датасети (<500 зразків), де неможливо виділити окремий holdout test
- Потрібна **максимально чесна** оцінка узагальнення з одночасним підбором гіперпараметрів
- Дослідницькі проєкти, де важлива наукова строгість

**Недоліки:**
- **Дуже повільно:** outer k × inner k × кількість параметрів
- У нашому прикладі: 5 × 3 × 4 = **60 навчань** моделі!

**Альтернатива:** якщо датасет достатньо великий (>1000 зразків), краще використовувати holdout test (80/20) + GridSearchCV з CV на train.
::

## Резюме

::card-group

::card{title="Cross-Validation" icon="i-lucide-repeat"}

Метод оцінки моделі на **k різних розбиттях** даних. Кожен зразок 1 раз у test, (k-1) разів у train. Усереднення k оцінок дає надійнішу оцінку узагальнення.

::

::card{title="K-Fold CV" icon="i-lucide-layers"}

Розбиття датасету на **k рівних частин** (fold'ів). Кожна частина по черзі стає тестовою. Стандартні значення: k=5 (баланс), k=10 (точність).

::

::card{title="cross_val_score" icon="i-lucide-code"}

Функція scikit-learn для швидкого виконання CV. Повертає масив з k оцінками. Параметри: `estimator`, `X`, `y`, `cv`, `scoring`, `n_jobs`.

::

::card{title="cross_validate" icon="i-lucide-code-2"}

Розширена версія `cross_val_score`. Повертає словник з train scores, test scores, часом навчання. Корисна для діагностики overfitting.

::

::card{title="Stratified K-Fold" icon="i-lucide-git-branch"}

Спеціальна версія для **класифікації** з незбалансованими класами. Гарантує однакову пропорцію класів у кожному fold'і. **Не застосовується** до регресії.

::

::card{title="Leave-One-Out (LOO)" icon="i-lucide-minimize"}

Екстремальний випадок: k = n (кожен зразок — окремий test fold). Для **маленьких датасетів** (<100 зразків). Дуже повільний для великих даних.

::

::card{title="Train/Test Split vs CV" icon="i-lucide-git-compare"}

Split: швидко, 1 оцінка, залежить від випадковості. CV: повільно, k оцінок, надійно. **CV не замінює holdout test** — потрібні обидва!

::

::card{title="Nested CV" icon="i-lucide-layers-2"}

Двоє вкладених циклів: зовнішній (оцінка узагальнення) + внутрішній (вибір гіперпараметрів). Найчесніша оцінка, але **дуже повільно**.

::

::card{title="Scoring Metrics" icon="i-lucide-bar-chart"}

Для регресії: `'r2'`, `'neg_mean_absolute_error'`, `'neg_mean_squared_error'`, `'neg_root_mean_squared_error'`. Негативні метрики (neg_*) перетворити на позитивні множенням на -1.

::

::card{title="Std (Стандартне відхилення)" icon="i-lucide-trending-up"}

Показує **стабільність** моделі. Маленький std = результат не залежить від fold'у (стабільна модель). Великий std = нестабільна (чутлива до даних).

::

::card{title="Правильний workflow" icon="i-lucide-workflow"}

1. Розбити: 80% (train+val) + 20% (holdout)  
2. CV на 80%: порівняти моделі  
3. Навчити найкращу на 80%  
4. Оцінити на 20% holdout (один раз!)

::

::card{title="Box Plot" icon="i-lucide-box"}

Візуалізація розподілу scores по fold'ам. Вузький ящик = стабільна модель. Широкий ящик = нестабільна. Медіана (червона лінія) vs середнє (точка).

::

::
