## Короткий зміст

### 1. Hook: Один експерт vs комітет експертів
- Проблема з попередньої статті: одне дерево нестабільне
- Аналогія: медична діагностика
  - Один лікар може помилитись (bias, особистий досвід)
  - Консиліум з 100 лікарів → голосування → надійніший діагноз
- Принцип "мудрості натовпу" (wisdom of the crowd)
- Random Forest = "комітет дерев рішень"

### 2. Ідея ансамблів у машинному навчанні
- **Ансамбль** — комбінація кількох моделей для покращення результату
- Два основні підходи:
  - **Bagging** (Bootstrap Aggregating) — паралельне навчання незалежних моделей
  - **Boosting** — послідовне навчання, де кожна модель виправляє помилки попередньої
- Random Forest використовує **Bagging**

### 3. Bagging (Bootstrap Aggregating) — детально

#### 3.1. Bootstrap вибірка
- Принцип: із тренувального набору з N зразків створюємо нову вибірку також із N зразків
- Вибірка **з поверненням** — один зразок може потрапити кілька разів
- Приклад: [1, 2, 3, 4, 5] → bootstrap → [1, 1, 3, 5, 5]
- В середньому кожна bootstrap вибірка містить ~63% унікальних зразків
- Решта 37% — "out-of-bag" (OOB) зразки, які можна використати для валідації

#### 3.2. Aggregating (агрегація передбачень)
- **Регресія:** середнє арифметичне передбачень усіх дерев
- **Класифікація:** голосування (мажоритарний клас)
- Формула: ŷ = (1/K) · Σ tree_k(x), де K — кількість дерев

#### 3.3. Чому Bagging працює?
- Кожне дерево "бачить" трохи різні дані → різні структури дерев
- Помилки окремих дерев **не корелюють** між собою
- При усередненні помилки частково **компенсують одна одну**
- Математика: Var(середнє) = Var(одиниця) / K → зменшення дисперсії

### 4. Random Forest: Bagging + випадковість ознак

#### 4.1. Додаткова випадковість — підмножина ознак
- Проблема "чистого" бегінгу: якщо одна ознака домінує, всі дерева будуть схожі
- Рішення Random Forest: на кожному розбитті розглядати лише **випадкову підмножину ознак**
- За замовчуванням: √n ознак для класифікації, n/3 для регресії
- Приклад: 20 ознак → кожне розбиття розглядає лише 7 випадкових ознак

#### 4.2. Алгоритм Random Forest (покроково)
1. Для кожного з K дерев:
   - Створити bootstrap вибірку з тренувальних даних
   - На кожному вузлі дерева:
     - Випадково вибрати m ознак з усіх n
     - Знайти найкраще розбиття серед цих m ознак
     - Розбити вузол
2. Фінальне передбачення: середнє (регресія) або голосування (класифікація)

#### 4.3. Діаграма PlantUML: архітектура Random Forest
- Тренувальні дані → K bootstrap вибірок → K дерев → агрегація → фінальне передбачення

### 5. RandomForestRegressor у scikit-learn

#### 5.1. Базове використання

```python
from sklearn.ensemble import RandomForestRegressor

model = RandomForestRegressor(

    max_depth=10,          # максимальна глибина кожного дерева
    max_features='sqrt',   # кількість ознак на розбитті
    random_state=42

model.fit(X_train, y_train)
predictions = model.predict(X_test)
```

### 6. Гіперпараметри Random Forest

#### n_estimators (кількість дерев)
- Більше дерев → краща якість, але повільніше навчання
- Зазвичай 100-500 достатньо
- Jupyter експеримент: графік R² vs n_estimators (10, 50, 100, 200, 500)

#### max_depth (глибина дерев)
- Контролює перенавчання окремих дерев
- Random Forest менш схильний до перенавчання, ніж одиночне дерево
- Можна дозволити None (повна глибина), але обережно

#### max_features (кількість ознак на розбитті)
- 'sqrt' — квадратний корінь (за замовчуванням для класифікації)
- 'log2' — логарифм за основою 2
- int або float — конкретне число або частка

#### min_samples_split, min_samples_leaf
- Ті самі параметри, що й у DecisionTree
- Контролюють складність окремих дерев

### 7. Feature Importance — важливість ознак

#### 7.1. Що таке feature importance?
- Метрика: "наскільки ознака корисна для передбачення?"
- Обчислюється через середній приріст якості (IG) при розбитті по цій ознаці
- Сума всіх важливостей = 1.0

#### 7.2. Доступ до важливості ознак
```python
importances = model.feature_importances_
feature_names = X.columns
```

#### 7.3. Візуалізація важливості
- Горизонтальний bar plot: топ-10 найважливіших ознак
- Jupyter notebook: аналіз важливості на Housing Prices
- Інтерпретація: чому "площа" найважливіша? Чому "колір стін" неважливий?

#### 7.4. Використання для відбору ознак
- Видалити ознаки з importance < 0.01 → спрощення моделі
- Ретренування на обраних ознаках → швидше навчання, схожа якість

### 8. Out-of-Bag (OOB) оцінка

#### 8.1. Що таке OOB?
- При створенні bootstrap вибірки ~37% зразків залишаються невикористаними
- Ці зразки можна використати як **вбудований валідаційний набір**
- Кожне дерево оцінюється на своїх OOB зразках

#### 8.2. Переваги OOB
- Не потрібно виділяти окремий test set для оцінки якості
- OOB score ≈ cross-validation score

#### 8.3. Використання в sklearn
```python
model = RandomForestRegressor(n_estimators=100, oob_score=True)
model.fit(X_train, y_train)
print(f"OOB Score: {model.oob_score_}")  # R² на OOB зразках
```

### 10. Переваги Random Forest

#### ✅ Висока якість передбачення
- Часто "працює з коробки" без тюнінгу
- Переможець багатьох Kaggle змагань (до епохи gradient boosting)

#### ✅ Стійкість до перенавчання
- Завдяки усередненню багатьох дерев

#### ✅ Автоматична обробка нелінійностей
- Як і одиночні дерева, але стабільніше

#### ✅ Feature importance
- Можна зрозуміти, які ознаки найважливіші

#### ✅ Не вимагає масштабування

### 11. Недоліки Random Forest

#### ❌ Повільне навчання та передбачення
- Потрібно тренувати K дерев → в K разів повільніше за одиночне дерево
- Передбачення теж повільніше (проходження через K дерев)

#### ❌ Великий розмір моделі
- 100 дерев × (структура + значення листків) → багато пам'яті

#### ❌ Втрата інтерпретабельності
- Неможливо "подивитись на модель" як на одне дерево
- Залишається feature importance, але не повна картина

#### ❌ Погана екстраполяція
- Передбачення обмежені діапазоном тренувальних даних
- Не може передбачити значення, більше за max у train

### 12. RandomForestClassifier — класифікація

### 13. Коли використовувати Random Forest?

#### ✅ Використовуйте Random Forest:
- Табличні дані (не зображення / не текст)
- Важлива якість передбачення, а не швидкість інференсу
- Маєте багато ознак, деякі з яких можуть бути нерелевантними
- Потрібна базова інтерпретабельність через feature importance

#### ❌ Не використовуйте Random Forest:
- Дуже великі датасети (мільйони рядків) → спробуйте XGBoost / LightGBM
- Потрібна максимальна інтерпретабельність → одиночне дерево або лінійна модель
- Критична швидкість інференсу (реал-тайм системи) → лінійні моделі
