## Короткий зміст

### 1. Hook: Паралель vs послідовність — два шляхи до точності
- Random Forest: 100 незалежних експертів голосують → усереднення думок
- Gradient Boosting: один експерт виправляє помилки іншого → послідовне вдосконалення
- Питання: який підхід кращий?
- Аналогія: RF = демократичне голосування, GB = редагування чернетки статті
- Анонс: Gradient Boosting — переможець більшості Kaggle змагань до 2017 року

### 2. Проблема Random Forest — мотивація для Boosting
- Random Forest усереднює **незалежні** помилки → зменшення дисперсії
- Але що, якщо помилки **не випадкові**, а систематичні?
- Приклад: RF недооцінює дорогі квартири (всі дерева помиляються в один бік)
- Ідея Boosting: фокусуватися на **складних випадках**, які попередні моделі не впорались

### 3. Градієнтний бустинг — теорія

#### 3.1. Принцип послідовного виправлення помилок
- Крок 1: Навчити просте дерево (baseline) → отримати передбачення ŷ₁
- Крок 2: Обчислити помилки (residuals): r₁ = y - ŷ₁
- Крок 3: Навчити друге дерево передбачати **залишки** r₁ → отримати ŷ₂
- Крок 4: Фінальне передбачення: ŷ = ŷ₁ + ŷ₂
- Повторити: навчити третє дерево на r₂ = r₁ - ŷ₂, і так далі

#### 3.2. Аналогія: написання есе
- Перша версія есе (дерево 1) — грубий чорновик, багато помилок
- Редагування (дерево 2) — виправлення найгрубіших помилок
- Полірування (дерево 3) — виправлення дрібних недоліків
- Кожна ітерація **фокусується на тому, що попередні пропустили**

#### 3.3. Формула ансамблю
- Gradient Boosting: F(x) = F₀ + η·h₁(x) + η·h₂(x) + ... + η·hₘ(x)
- F₀ — базове передбачення (середнє значення y)
- hₖ(x) — k-те дерево, навчене на залишках
- η — learning rate (коефіцієнт усадки, shrinkage)

#### 3.4. Чому "градієнтний"?
- Кожне нове дерево рухається в напрямку **негативного градієнта** функції втрат
- Математична аналогія з градієнтним спуском (з модуля 3.1)
- Залишки r = ∂L/∂ŷ — це градієнт MSE функції втрат
- Детальна математика — поза межами курсу, але концепція важлива

### 4. Алгоритм Gradient Boosting покроково (на прикладі)

#### Приклад: передбачення ціни 3 квартир

| Квартира | Площа | Реальна ціна (y) |
| :------: | :---: | :--------------: |
|    A     |  50   |      40000       |
|    B     |  80   |      65000       |
|    C     |  120  |      95000       |

**Ітерація 0 (baseline):**
- F₀ = mean(y) = 66667 (середнє значення)
- Помилки: rₐ = 40000 - 66667 = -26667, rᵦ = -1667, rᴄ = +28333

**Ітерація 1:**
- Навчити дерево h₁ передбачати залишки [−26667, −1667, +28333]
- Нехай h₁(A) = −20000, h₁(B) = −2000, h₁(C) = +22000
- Оновлення: F₁(x) = F₀ + η·h₁(x), де η = 0.1 (learning rate)
- F₁(A) = 66667 + 0.1×(−20000) = 64667
- Нові помилки: rₐ = 40000 - 64667 = −24667 (покращилось!)

**Ітерація 2:**
- Навчити h₂ на нових залишках
- Продовжити до збіжності або max iterations

### 5. Boosting vs Bagging — порівняльна таблиця

| Характеристика                  | Bagging (Random Forest)       | Boosting (Gradient Boosting) |
| :------------------------------ | :---------------------------- | :--------------------------- |
| Побудова моделей                | Паралельно, незалежно         | Послідовно, кожна від попередньої залежить |
| Навчальні дані                  | Bootstrap вибірка (з поверненням) | Зважені або залишки         |
| Мета                            | Зменшення дисперсії (variance) | Зменшення зміщення (bias)   |
| Ризик перенавчання              | Низький (усереднення)         | Високий (фокус на складних випадках) |
| Швидкість навчання              | Швидше (паралелізація)        | Повільніше (послідовність)  |
| Інтерпретабельність             | Низька (багато дерев)         | Низька (багато дерев)        |
| Якість на практиці              | Висока, стабільна             | Дуже висока, але потребує тюнінгу |

### 7. XGBoost — eXtreme Gradient Boosting

#### 7.1. Що таке XGBoost?
- Оптимізована бібліотека для градієнтного бустингу (розробка 2014 року, Tianqi Chen)
- **Не новий алгоритм**, а **швидша та потужніша реалізація** GB
- Переможець 80%+ Kaggle змагань у 2015-2017 роках
- Використовується у виробництві: Airbnb, Uber, Yandex

#### 7.2. Чим XGBoost кращий за sklearn GradientBoostingRegressor?

##### ✅ Регуляризація дерев
- sklearn: лише обмеження глибини
- XGBoost: L1 (alpha) та L2 (lambda) регуляризація на ваги листків
- Формула втрат: Loss = MSE + α·Σ|wᵢ| + λ·Σwᵢ²
- Менше перенавчання

##### ✅ Паралелізація
- sklearn: послідовна побудова дерев
- XGBoost: паралелізація **на рівні побудови одного дерева** (пошук розбиттів)
- Швидше навчання в 5-10 разів

##### ✅ Обробка пропусків (missing values)
- sklearn: вимагає заповнення пропусків (SimpleImputer)
- XGBoost: автоматично "вчиться" напрямку для пропусків під час побудови дерева

##### ✅ Вбудована крос-валідація
- Можливість моніторингу якості на валідаційному наборі під час тренування
- Early stopping — зупинка, якщо якість перестала покращуватись

### 8. Гіперпараметри Gradient Boosting / XGBoost

#### n_estimators (кількість дерев)
- Більше дерев → краща якість, але повільніше навчання та ризик перенавчання
- Зазвичай 100-500 для невеликих датасетів, 1000+ для великих
- Важливо комбінувати з learning_rate

#### learning_rate (η, коефіцієнт усадки)
- Контролює внесок кожного дерева: ŷ = ŷ + η·hₖ(x)
- Малий η (0.01-0.05) → повільна збіжність, потрібно більше дерев, але краще узагальнення
- Великий η (0.3-0.5) → швидка збіжність, менше дерев, але ризик перенавчання
- Золоте правило: η · n_estimators ≈ константа

#### max_depth (глибина дерев)
- GB зазвичай використовує **неглибокі дерева** (3-6 рівнів) — "weak learners"
- Глибокі дерева (10+) → ризик перенавчання
- Відмінність від RF: RF використовує глибокі дерева

#### subsample (підвибірка рядків)
- Випадкова частка рядків для навчання кожного дерева (наприклад, 0.8 = 80%)
- Додає випадковість → зменшує перенавчання
- Схоже на bootstrap у RF, але **без повернення**

#### colsample_bytree (підвибірка колонок)
- Випадкова частка ознак для навчання кожного дерева
- XGBoost має також `colsample_bylevel` (на кожному рівні) та `colsample_bynode` (на кожному вузлі)

#### reg_alpha, reg_lambda (регуляризація, тільки XGBoost)
- L1 (alpha) та L2 (lambda) регуляризація на ваги листків
- Працює як Lasso/Ridge для дерев

### 12. Коли використовувати Gradient Boosting vs Random Forest?

#### ✅ Використовуйте Gradient Boosting (XGBoost):
- **Kaggle змагання** — потрібна максимальна якість передбачення
- Табличні дані середнього розміру (10k-1M рядків)
- Є час на підбір гіперпараметрів
- Можна ризикувати перенавчанням (є валідаційний набір для контролю)

#### ✅ Використовуйте Random Forest:
- Потрібна **стабільна baseline модель** без тюнінгу
- Обмежений час на експерименти
- Датасет малий (< 10k рядків) — RF менш схильний до перенавчання
- Потрібна паралелізація навчання

#### ✅ Використовуйте лінійні моделі (Ridge/Lasso):
- Потрібна **інтерпретабельність**
- Дані мають лінійні залежності
- Критична швидкість інференсу (мільйони передбачень/секунду)

### 13. Альтернативи XGBoost — LightGBM та CatBoost

#### LightGBM (Microsoft, 2017)
- **Швидший** за XGBoost на великих датасетах (1M+ рядків)
- Використовує "листковий" (leaf-wise) алгоритм побудови дерев vs "рівневий" (level-wise) у XGBoost
- Менше пам'яті
- `from lightgbm import LGBMRegressor`

#### CatBoost (Yandex, 2017)
- **Автоматична обробка категоріальних ознак** (не потрібен OneHotEncoder)
- Вбудована боротьба з target leakage
- Повільніше навчання, але простіше у використанні
- `from catboost import CatBoostRegressor`

::note
У реальних проектах варто експериментувати з усіма трьома: XGBoost, LightGBM, CatBoost. Іноді один дає на 1-2% кращу якість за інші. Але для навчання достатньо опанувати XGBoost — принципи однакові.
::

Оптимізована реалізація GB. Регуляризація, паралелізація, обробка пропусків. Переможець Kaggle 2015-2017.
