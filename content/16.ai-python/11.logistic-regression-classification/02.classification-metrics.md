## Короткий зміст

### 1. Hook: Accuracy = 99%, але модель — катастрофа!

#### 1.1. Задача: виявлення рідкісної хвороби
- Датасет: 1000 пацієнтів, 10 хворих (1%), 990 здорових (99%)
- "Дурна" модель: завжди передбачає "здоровий"
- Accuracy = 990/1000 = **99%** — ніби чудово!
- Але: жодного хворого не виявлено — модель абсолютно марна

#### 1.2. Проблема незбалансованих класів (Imbalanced Dataset)
- Якщо один клас домінує (наприклад, 99% vs 1%), accuracy — оманлива метрика
- Потрібні метрики, які враховують **якість передбачення кожного класу окремо**

### 2. Confusion Matrix (Матриця плутанини) — основа всіх метрик

#### 2.1. Структура Confusion Matrix

|                      | **Передбачено: Позитив (1)** | **Передбачено: Негатив (0)** |
| :------------------- | :--------------------------: | :--------------------------: |
| **Реально: Позитив** |      True Positive (TP)      |     False Negative (FN)      |
| **Реально: Негатив** |     False Positive (FP)      |      True Negative (TN)      |

#### 2.2. Розшифровка термінів

##### True Positive (TP) — правильно знайдені позитивні
- Модель передбачила "1", і це правда
- Приклад: модель сказала "хворий", і пацієнт справді хворий

##### False Positive (FP) — хибна тривога (Type I Error)
- Модель передбачила "1", але насправді "0"
- Приклад: модель сказала "хворий", але пацієнт здоровий
- Аналогія: пожежна сигналізація спрацювала, але пожежі немає

##### False Negative (FN) — пропущена загроза (Type II Error)
- Модель передбачила "0", але насправді "1"
- Приклад: модель сказала "здоровий", але пацієнт хворий
- Аналогія: пожежна сигналізація **не спрацювала**, хоча пожежа є — найнебезпечніший випадок!

##### True Negative (TN) — правильно відхилені негативні
- Модель передбачила "0", і це правда
- Приклад: модель сказала "здоровий", і пацієнт дійсно здоровий

#### 2.3. Візуалізація Confusion Matrix у sklearn

```python
from sklearn.metrics import confusion_matrix, ConfusionMatrixDisplay
import matplotlib.pyplot as plt

cm = confusion_matrix(y_test, predictions)
disp = ConfusionMatrixDisplay(confusion_matrix=cm, display_labels=['Клас 0', 'Клас 1'])
disp.plot(cmap='Blues')
plt.title("Confusion Matrix")
plt.show()
```

### 3. Accuracy (Точність моделі) — базова метрика

#### 3.1. Формула
::math-formula
\text{Accuracy} = \frac{TP + TN}{TP + TN + FP + FN} = \frac{\text{Правильні передбачення}}{\text{Усі передбачення}}
::

#### 3.2. Інтерпретація
- "Яка частка передбачень була правильною?"
- Accuracy = 0.85 → 85% передбачень правильні

#### 3.3. Коли Accuracy працює добре?
- ✅ Класи **збалансовані** (приблизно 50/50 або 60/40)
- ✅ Помилки обох типів (FP та FN) **однаково критичні**

#### 3.4. Коли Accuracy оманлива?
- ❌ Класи **незбалансовані** (90/10, 99/1)
- ❌ Один тип помилки **набагато критичніший** за інший (медицина, безпека)

### 4. Precision (Точність позитивних передбачень)

#### 4.1. Формула
::math-formula
\text{Precision} = \frac{TP}{TP + FP} = \frac{\text{Правильні позитивні}}{\text{Усі передбачені позитивні}}
::

#### 4.2. Інтерпретація
- "З усіх, кого модель назвала **позитивними**, скільки **реально** позитивні?"
- Або: "Чи можна довіряти **сигналу тривоги** моделі?"

#### 4.3. Приклад: спам-фільтр
- Модель помітила 100 листів як "спам"
- Але 10 з них — важливі листи (FP = 10)
- Precision = 90 / 100 = **0.9** (90%)
- Висновок: 90% "спам"-позначок — справжній спам, 10% — помилка

#### 4.4. Коли важлива висока Precision?
- **Коли False Positive дорого коштує**
- Приклад 1: рекомендаційна система (не хочемо рекомендувати "сміття")
- Приклад 2: автоматична блокування акаунта (не хочемо блокувати невинних)

#### 4.5. Обчислення у sklearn
```python
from sklearn.metrics import precision_score

precision = precision_score(y_test, predictions)
print(f"Precision: {precision:.3f}")
```

### 5. Recall (Повнота, Чутливість, Sensitivity)

#### 5.1. Формула
::math-formula
\text{Recall} = \frac{TP}{TP + FN} = \frac{\text{Правильні позитивні}}{\text{Усі реальні позитивні}}
::

#### 5.2. Інтерпретація
- "З усіх **реально** позитивних, скільки модель **знайшла**?"
- Або: "Чи пропускає модель **реальні загрози**?"

#### 5.3. Приклад: медична діагностика раку
- Реально хворих на рак: 50 пацієнтів
- Модель виявила: 45 (TP = 45)
- Пропустила: 5 (FN = 5)
- Recall = 45 / 50 = **0.9** (90%)
- Висновок: модель знайшла 90% хворих, але **пропустила 10%** — це критично!

#### 5.4. Коли важливий високий Recall?
- **Коли False Negative дорого коштує** (пропущена загроза)
- Приклад 1: медична діагностика (краще перестрахуватись, ніж пропустити хвору людину)
- Приклад 2: виявлення шахрайства (краще перевірити зайвий раз, ніж пропустити злочин)
- Приклад 3: системи безпеки (краще хибна тривога, ніж пропущена загроза)

#### 5.5. Обчислення у sklearn
```python
from sklearn.metrics import recall_score

recall = recall_score(y_test, predictions)
print(f"Recall: {recall:.3f}")
```

### 6. Precision vs Recall Trade-off (Баланс точності та повноти)

#### 6.1. Проблема: не можна максимізувати обидві метрики одночасно
- Висока Precision → модель обережна, мало FP, але багато FN → **низький Recall**
- Високий Recall → модель агресивна, мало FN, але багато FP → **низька Precision**

#### 6.2. Візуалізація trade-off
- Порівняльна таблиця для різних порогів:

| Поріг | TP  | FP  | FN  | TN  | Precision | Recall |
| :---: | :-: | :-: | :-: | :-: | :-------: | :----: |
|  0.3  | 48  | 30  |  2  | 20  |   0.62    |  0.96  |
|  0.5  | 45  | 10  |  5  | 40  |   0.82    |  0.90  |
|  0.7  | 38  |  3  | 12  | 47  |   0.93    |  0.76  |

- Зниження порогу → більше "позитивних" передбачень → вищий Recall, нижча Precision

#### 6.3. Як обрати між Precision та Recall?
- **Медицина, безпека** → Recall важливіший (не пропустити хворого/загрозу)
- **Спам-фільтр, рекомендації** → Precision важливіший (не дратувати користувача хибними тривогами)
- **Баланс** → F1-score

#### 6.4. Jupyter notebook: експеримент з порогом
```python
# Змінюємо поріг класифікації
probs = model.predict_proba(X_test)[:, 1]
for threshold in [0.3, 0.5, 0.7]:
    predictions = (probs >= threshold).astype(int)
    precision = precision_score(y_test, predictions)
    recall = recall_score(y_test, predictions)
    print(f"Threshold {threshold}: Precision={precision:.2f}, Recall={recall:.2f}")
```

### 7. F1-score (Гармонійне середнє Precision та Recall)

#### 7.1. Формула
::math-formula
F_1 = 2 \cdot \frac{\text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}}
::

#### 7.2. Чому гармонійне середнє, а не арифметичне?
- Арифметичне середнє (Precision + Recall) / 2 дає однакову вагу обом метрикам
- Але якщо одна метрика **дуже низька**, це має сильно штрафувати F1
- Приклад: Precision = 1.0, Recall = 0.01
  - Арифметичне: (1.0 + 0.01) / 2 = 0.505 — начебто норма
  - Гармонійне (F1): 2 · (1.0 · 0.01) / (1.0 + 0.01) = **0.02** — реальний стан

#### 7.3. Коли використовувати F1-score?
- Коли потрібен **баланс** між Precision та Recall
- Коли класи **незбалансовані**, але обидва типи помилок (FP і FN) важливі

#### 7.4. Обчислення у sklearn
```python
from sklearn.metrics import f1_score

f1 = f1_score(y_test, predictions)
print(f"F1-score: {f1:.3f}")
```

### 8. Specificity (Специфічність) — рідше використовується

#### 8.1. Формула
::math-formula
\text{Specificity} = \frac{TN}{TN + FP} = \frac{\text{Правильні негативні}}{\text{Усі реальні негативні}}
::

#### 8.2. Інтерпретація
- "З усіх реально негативних, скільки модель правильно **відхилила**?"
- Протилежність Recall (який вимірює позитивні)

#### 8.3. Коли важлива?
- Рідше використовується у ML
- Важлива у медичних тестах (чи не помічає модель здорових як хворих)

### 10. ROC-AUC крива (Receiver Operating Characteristic)

#### 10.1. Що таке ROC крива?
- Графік залежності **True Positive Rate (Recall)** від **False Positive Rate** при різних порогах
- TPR = Recall = TP / (TP + FN)
- FPR = FP / (FP + TN) = 1 − Specificity
- Кожна точка на кривій — один поріг класифікації

#### 10.2. AUC (Area Under Curve) — площа під ROC кривою
- AUC = 1.0 → ідеальна модель (знаходить всі позитивні без жодної помилки)
- AUC = 0.5 → випадкове передбачення (як кидати монетку)
- AUC < 0.5 → модель гірша за випадкову (щось пішло не так!)
- Зазвичай AUC > 0.8 вважається гарною моделлю

#### 10.3. Візуалізація ROC кривої

```python
from sklearn.metrics import roc_curve, roc_auc_score
import matplotlib.pyplot as plt

probs = model.predict_proba(X_test)[:, 1]
fpr, tpr, thresholds = roc_curve(y_test, probs)
auc = roc_auc_score(y_test, probs)

plt.plot(fpr, tpr, label=f'AUC = {auc:.2f}')
plt.plot([0, 1], [0, 1], 'k--', label='Random')
plt.xlabel('False Positive Rate')
plt.ylabel('True Positive Rate (Recall)')
plt.title('ROC Curve')
plt.legend()
plt.show()
```

#### 10.4. Коли використовувати ROC-AUC?
- Коли потрібно порівняти **загальну якість** різних моделей
- Коли поріг класифікації ще не визначений
- AUC не залежить від балансу класів (на відміну від accuracy)

### 13. Threshold Tuning — налаштування порогу класифікації

#### 13.1. Чому не завжди 0.5?
- Стандартний поріг 0.5 оптимальний лише для **збалансованих класів**
- Для незбалансованих або при різній вартості помилок — треба налаштовувати

#### 13.2. Приклад: медична діагностика
- Хочемо Recall ≥ 0.99 (майже жодного пропущеного хворого)
- Знижуємо поріг до 0.3 → більше "позитивних" передбачень
- Precision впаде, але Recall зросте

#### 13.3. Jupyter notebook: пошук оптимального порогу
```python
probs = model.predict_proba(X_test)[:, 1]
best_threshold = 0.5
best_f1 = 0

for threshold in np.arange(0.1, 0.9, 0.05):
    preds = (probs >= threshold).astype(int)
    f1 = f1_score(y_test, preds)
    if f1 > best_f1:
        best_f1 = f1
        best_threshold = threshold

print(f"Оптимальний поріг: {best_threshold}, F1: {best_f1:.3f}")
```

### 14. Багатокласова класифікація — коротке згадування

#### 14.1. Метрики для мультикласової класифікації
- Confusion Matrix стає NxN (де N — кількість класів)
- Precision, Recall, F1 обчислюються **для кожного класу окремо**
- Macro-average: середнє арифметичне метрик усіх класів
- Weighted-average: зважене середнє (враховує кількість зразків у кожному класі)

#### 14.2. sklearn автоматично підтримує мультикласову класифікацію
```python
from sklearn.metrics import classification_report

# y_test та predictions можуть мати значення 0, 1, 2, ...
print(classification_report(y_test, predictions))
```
