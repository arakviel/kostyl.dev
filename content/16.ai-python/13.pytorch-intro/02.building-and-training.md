## Вступ: «Чистий» PyTorch vs nn.Module

У попередній статті ми навчилися обчислювати градієнти та реалізували просту лінійну регресію «з нуля» — вручну визначаючи параметри, forward pass та gradient descent loop. Це дало глибоке розуміння того, як працює навчання нейронних мереж.

Але уявіть, що потрібно побудувати мережу з 10 шарами, dropout, batch normalization та skip connections. Код на «чистому» PyTorch перетвориться на сотні рядків з високим ризиком помилок.

**Рішення:** модуль `torch.nn` — високорівневий API для побудови нейронних мереж.

::jupyter-notebook{title="pure_pytorch_vs_nn.ipynb"}

::jupyter-cell{type="markdown"}
### Підхід 1: "Чистий" PyTorch (вручну)
::

::jupyter-cell{executionCount="1"}

```python
import torch

# Вручну визначаємо параметри
w1 = torch.randn(10, 20, requires_grad=True)
b1 = torch.randn(20, requires_grad=True)
w2 = torch.randn(20, 1, requires_grad=True)
b2 = torch.randn(1, requires_grad=True)

# Forward pass вручну
def forward(X):
    h = X @ w1 + b1
    h = torch.relu(h)
    y = h @ w2 + b2
    return y

X = torch.randn(32, 10)
y_pred = forward(X)
print(f"Вихід: {y_pred.shape}")
```

#output
Вихід: torch.Size([32, 1])

::

::jupyter-cell{type="markdown"}
### Підхід 2: nn.Module (професійно)
::

::jupyter-cell{executionCount="2"}

```python
import torch
import torch.nn as nn

class SimpleNetwork(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = nn.Linear(10, 20)
        self.fc2 = nn.Linear(20, 1)
    
    def forward(self, X):
        h = torch.relu(self.fc1(X))
        y = self.fc2(h)
        return y

model = SimpleNetwork()
X = torch.randn(32, 10)
y_pred = model(X)
print(f"Вихід: {y_pred.shape}")
print(f"Кількість параметрів: {sum(p.numel() for p in model.parameters())}")
```

#output
Вихід: torch.Size([32, 1])
Кількість параметрів: 241

::

::

> **Аналогія:** «Чистий» PyTorch — це як збирати комп'ютер з окремих компонентів (процесор, пам'ять, материнська плата). `nn.Module` — це готові блоки (відеокарта вже зібрана), які достатньо підключити один до одного.

::tip
**Переваги nn.Module:**

- ✅ Автоматична реєстрація параметрів
- ✅ Методи `.parameters()`, `.state_dict()` для збереження
- ✅ Підтримка GPU через `.to(device)`
- ✅ Режими `.train()` та `.eval()`
- ✅ Вкладені модулі (композиція архітектур)
::

## 📋 Зміст статті

### Частина 1: Побудова нейронних мереж з nn.Module

#### 1.1. Вступ: "Чистий" PyTorch vs nn.Module
- Приклад лінійної моделі на тензорах + autograd (багато коду)
- Той самий приклад з nn.Module (5 рядків)
- Чому nn.Module — стандарт індустрії

#### 1.2. Анатомія nn.Module
- Два обов'язкові методи: `__init__` та `forward`
- Автоматична реєстрація параметрів
- `.parameters()`, `.named_parameters()`, `.state_dict()`
- `.children()` vs `.modules()` — різниця

#### 1.3. Основні шари (Layers)
- **`nn.Linear`** — повнозв'язний шар (формула y = Wx + b)
- **Функції активації:**
  - `nn.ReLU()`, `nn.LeakyReLU()`, `nn.ELU()`, `nn.GELU()`
  - Функціональні vs модульні (F.relu vs nn.ReLU)
- **Регуляризація:**
  - `nn.Dropout(p=0.3)` — випадкове вимикання нейронів
  - `nn.BatchNorm1d()` — нормалізація батча
- **Інші корисні шари:**
  - `nn.Embedding()` — для NLP (згадка, детально в Модулі 6)
  - `nn.Conv2d()`, `nn.MaxPool2d()` — для зображень (згадка, детально в Модулі 5)

#### 1.4. Три способи побудови моделей
- **Спосіб 1: Клас-наслідник nn.Module** (найгнучкіший)
  - Явне визначення шарів у `__init__`
  - Логіка forward проходу
- **Спосіб 2: nn.Sequential** (для простих архітектур)
  - Лінійна послідовність шарів
  - Без розгалужень та skip connections
- **Спосіб 3: nn.ModuleList + nn.ModuleDict** (для динамічних архітектур)
  - Список шарів змінної довжини
  - Словники шарів для розгалужень

#### 1.5. Поступове ускладнення архітектур
- **Рівень 1:** Проста MLP (3 шари, ReLU, Dropout)
- **Рівень 2:** Мережа з skip connections (ResNet-style)
- **Рівень 3:** Мережа з розгалуженнями (Inception-style, два шляхи → concat)
- Порівняння кількості параметрів

#### 1.6. Ініціалізація ваг
- Чому ініціалізація важлива (мертві нейрони, вибух градієнтів)
- **Xavier/Glorot initialization** — для tanh, sigmoid
- **He initialization** — для ReLU
- Кастомна ініціалізація через `.apply()`
- Приклад коду для різних ініціалізацій

#### 1.7. Практичні кейси побудови мереж
- **Кейс 1:** Переносимо NumPy MLP у PyTorch
- **Кейс 2:** Додаємо Batch Normalization
- **Кейс 3:** Експериментуємо з глибиною (3 vs 5 vs 10 шарів)

### Частина 2: Тренування моделей

#### 2.1. Анатомія Training Loop
- **6 обов'язкових кроків:**
  1. `optimizer.zero_grad()` — обнулити градієнти
  2. `predictions = model(X)` — forward pass
  3. `loss = criterion(predictions, y)` — обчислити втрати
  4. `loss.backward()` — backward pass
  5. `optimizer.step()` — оновити параметри
  6. Логування метрик
- Чому `zero_grad()` критичний (градієнти накопичуються)
- Gradient accumulation (для великих батчів, що не влазять у пам'ять)

#### 2.2. Функції втрат (Loss Functions)
- **Регресія:**
  - `nn.MSELoss()` — Mean Squared Error
  - `nn.L1Loss()` (MAE) — стійка до викидів
  - `nn.SmoothL1Loss()` (Huber Loss)
- **Бінарна класифікація:**
  - `nn.BCELoss()` — після Sigmoid
  - `nn.BCEWithLogitsLoss()` — без Sigmoid (стабільніше)
- **Багатокласова класифікація:**
  - `nn.CrossEntropyLoss()` — включає LogSoftmax (найпопулярніше)
  - `nn.NLLLoss()` — якщо Softmax вже застосовано
- Порівняльна таблиця та коли що використовувати

#### 2.3. Оптимізатори
- **SGD:**
  - Базовий варіант
  - З momentum (β=0.9)
  - Nesterov momentum
  - Weight decay (L2 regularization)
- **Adam та AdamW:**
  - Адаптивний learning rate
  - Різниця між Adam та AdamW (decoupled weight decay)
  - Типові гіперпараметри (β₁=0.9, β₂=0.999, ε=1e-8)
- **Інші оптимізатори:**
  - RMSprop — для RNN
  - Adagrad — рідко використовується
- Вибір learning rate (правило великого пальця)

#### 2.4. Train vs Validation Loop
- **Режими моделі:**
  - `model.train()` — увімкнути Dropout, BatchNorm у тренувальному режимі
  - `model.eval()` — вимкнути Dropout, заморозити BatchNorm
- **Validation loop:**
  - Без обчислення градієнтів (`with torch.no_grad()`)
  - Обчислення метрик на валідаційному наборі
- **Early Stopping:**
  - Моніторинг validation loss
  - Зупинка, якщо loss не покращується N епох (patience)
- **Model Checkpointing:**
  - Збереження найкращої моделі за validation loss
  - `torch.save(model.state_dict(), 'best_model.pt')`

#### 2.5. Метрики та моніторинг
- **Класифікація:**
  - Accuracy, Precision, Recall, F1-Score
  - Confusion Matrix
- **Регресія:**
  - R², MAE, RMSE
- Візуалізація:
  - Loss curves (train vs validation)
  - Accuracy curves
  - Виявлення перенавчання (train loss ↓, val loss ↑)

#### 2.6. Поступове ускладнення training loop
- **Рівень 1:** Базовий loop (без валідації, 10 епох)
- **Рівень 2:** Train + Validation split, логування метрик
- **Рівень 3:** Early stopping + model checkpointing
- **Рівень 4:** Learning rate scheduler + gradient clipping
  - `torch.optim.lr_scheduler.StepLR`, `ReduceLROnPlateau`
  - `torch.nn.utils.clip_grad_norm_()` — проти вибуху градієнтів

#### 2.7. Практичні кейси повного тренування
- **Кейс 1:** Класифікація Iris Dataset (3 класи, 4 ознаки)
  - Повний цикл: data → model → train → evaluate
  - Візуалізація loss curves
- **Кейс 2:** Регресія Boston Housing (передбачення ціни)
  - Метрики регресії (R², MAE)
  - Порівняння з sklearn LinearRegression
- **Кейс 3:** Виявлення перенавчання
  - Модель з 1000 параметрів на 100 прикладах
  - Боротьба через Dropout та weight decay

## Частина 1: Побудова нейронних мереж з nn.Module

### Анатомія nn.Module

Будь-яка модель у PyTorch має два обов'язкові методи:

1. **`__init__()`** — визначення архітектури (шари, параметри)
2. **`forward()`** — обчислення виходу (forward pass)

::jupyter-notebook{title="basic_nn_module.ipynb"}

::jupyter-cell{executionCount="1"}

```python
import torch
import torch.nn as nn

class MyFirstNetwork(nn.Module):
    def __init__(self, input_size, hidden_size, output_size):
        super().__init__()  # Обов'язково викликати конструктор батьківського класу!
        
        # Визначаємо шари
        self.fc1 = nn.Linear(input_size, hidden_size)
        self.relu = nn.ReLU()
        self.fc2 = nn.Linear(hidden_size, output_size)
    
    def forward(self, x):
        # Описуємо forward pass
        x = self.fc1(x)
        x = self.relu(x)
        x = self.fc2(x)
        return x

# Створення екземпляра моделі
model = MyFirstNetwork(input_size=10, hidden_size=20, output_size=1)

# Виклик моделі (автоматично викликає forward)
X = torch.randn(5, 10)  # батч з 5 прикладів
output = model(X)

print(f"Вхід: {X.shape}")
print(f"Вихід: {output.shape}")
```

#output
Вхід: torch.Size([5, 10])
Вихід: torch.Size([5, 1])

::

::

::note
**Чому викликати `super().__init__()`?**

Це ініціалізує внутрішні механізми PyTorch для відстеження параметрів, режимів тренування/eval та інших функцій. Без цього виклику модель не працюватиме коректно.
::

### Основні шари (Layers)

PyTorch надає готові реалізації найпопулярніших шарів:

#### nn.Linear — повнозв'язний шар

::jupyter-notebook{title="linear_layer.ipynb" executionCount="1"}

# Linear(in_features, out_features)

#### Функції активації

::jupyter-notebook{title="activations.ipynb"}

::jupyter-cell{executionCount="1"}

```python
import torch
import torch.nn as nn

x = torch.tensor([-2.0, -1.0, 0.0, 1.0, 2.0])

# ReLU: max(0, x)
relu = nn.ReLU()
print(f"ReLU: {relu(x)}")

# LeakyReLU: max(0.01x, x)
leaky_relu = nn.LeakyReLU(negative_slope=0.01)
print(f"LeakyReLU: {leaky_relu(x)}")

# Sigmoid: 1 / (1 + e^(-x))
sigmoid = nn.Sigmoid()
print(f"Sigmoid: {sigmoid(x)}")

# Tanh: (e^x - e^(-x)) / (e^x + e^(-x))
tanh = nn.Tanh()
print(f"Tanh: {tanh(x)}")
```

#output
ReLU: tensor([0., 0., 0., 1., 2.])
LeakyReLU: tensor([-0.0200, -0.0100,  0.0000,  1.0000,  2.0000])
Sigmoid: tensor([0.1192, 0.2689, 0.5000, 0.7311, 0.8808])
Tanh: tensor([-0.9640, -0.7616,  0.0000,  0.7616,  0.9640])

::

::

::tip
**Який активатор обрати?**

- **ReLU** — стандартний вибір для прихованих шарів (швидкий, ефективний)
- **LeakyReLU / ELU** — якщо проблема «мертвих нейронів»
- **Sigmoid** — для бінарної класифікації на виході
- **Tanh** — рідко використовується (в RNN)
- **Softmax** — для багатокласової класифікації на виході
::
