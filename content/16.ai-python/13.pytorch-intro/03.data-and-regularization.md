### Dataset — абстракція для даних

`torch.utils.data.Dataset` — це абстрактний клас, що визначає інтерфейс доступу до даних.

### Створення власного Dataset для табличних даних
::

::jupyter-cell{executionCount="1"}

```python
import torch
from torch.utils.data import Dataset
import pandas as pd

class CSVDataset(Dataset):
    """Dataset для завантаження даних з CSV файлу."""
    
    def __init__(self, csv_path, feature_columns, target_column):
        # Завантажуємо CSV (можна зробити ледачим для великих файлів)
        self.data = pd.read_csv(csv_path)
        self.feature_columns = feature_columns
        self.target_column = target_column
    
    def __len__(self):
        """Повертає кількість прикладів у датасеті."""
        return len(self.data)
    
    def __getitem__(self, idx):
        """Повертає один приклад за індексом."""
        # Вибираємо рядок
        row = self.data.iloc[idx]
        
        # Ознаки
        features = torch.tensor(
            row[self.feature_columns].values,
            dtype=torch.float32
        )
        
        # Мітка
        target = torch.tensor(
            row[self.target_column],
            dtype=torch.float32
        )
        
        return features, target

# Приклад використання (імітуємо CSV)
import io
csv_data = """age,income,score,purchased
25,50000,0.7,1
32,75000,0.9,1
45,60000,0.5,0
28,55000,0.6,0"""

# Зберігаємо у тимчасовий файл
with open('/tmp/data.csv', 'w') as f:
    f.write(csv_data)

dataset = CSVDataset(
    csv_path='/tmp/data.csv',
    feature_columns=['age', 'income', 'score'],
    target_column='purchased'
)

print(f"Розмір датасету: {len(dataset)}")
print(f"\nПерший приклад:")
features, target = dataset[0]
print(f"  Ознаки: {features}")
print(f"  Мітка: {target}")
```

#### Dataset для зображень

::jupyter-notebook{title="image_dataset.ipynb"}

::jupyter-cell{executionCount="1"}

```python
import torch
from torch.utils.data import Dataset
from PIL import Image
import os

class ImageFolderDataset(Dataset):
    """Dataset для завантаження зображень з папки."""
    
    def __init__(self, root_dir, transform=None):
        self.root_dir = root_dir
        self.transform = transform
        
        # Знаходимо всі зображення
        self.image_paths = []
        self.labels = []
        
        # Структура: root_dir/class_name/image.jpg
        for class_idx, class_name in enumerate(sorted(os.listdir(root_dir))):
            class_dir = os.path.join(root_dir, class_name)
            if not os.path.isdir(class_dir):
                continue
            
            for img_name in os.listdir(class_dir):
                if img_name.endswith(('.jpg', '.jpeg', '.png')):
                    self.image_paths.append(os.path.join(class_dir, img_name))
                    self.labels.append(class_idx)
    
    def __len__(self):
        return len(self.image_paths)
    
    def __getitem__(self, idx):
        # Завантажуємо зображення ЛИШЕ коли потрібно (lazy loading)
        img_path = self.image_paths[idx]
        image = Image.open(img_path).convert('RGB')
        label = self.labels[idx]
        
        # Застосовуємо трансформації (якщо є)
        if self.transform:
            image = self.transform(image)
        
        return image, label

# Демонстрація (без реального файлу)
print("ImageFolderDataset створено")
print("Приклад структури:")
print("  data/")
print("    cats/")
print("      cat1.jpg")
print("      cat2.jpg")
print("    dogs/")
print("      dog1.jpg")
print("      dog2.jpg")
```

### DataLoader — ітерація по батчах

`DataLoader` обгортає Dataset і надає зручний спосіб ітерації по батчах:

::jupyter-notebook{title="dataloader_basics.ipynb"}

::jupyter-cell{executionCount="1"}

```python
import torch
from torch.utils.data import TensorDataset, DataLoader

# Створюємо простий датасет
X = torch.randn(100, 10)
y = torch.randint(0, 2, (100,))

dataset = TensorDataset(X, y)

# DataLoader з різними параметрами
loader = DataLoader(
    dataset,
    batch_size=16,        # розмір батча
    shuffle=True,         # перемішувати перед кожною епохою
    num_workers=0,        # кількість процесів для завантаження (0 = головний процес)
    pin_memory=False,     # оптимізація для GPU
    drop_last=False       # відкинути неповний останній батч
)

print(f"Датасет: {len(dataset)} прикладів")
print(f"Батчів: {len(loader)}")
print(f"Розмір батча: {loader.batch_size}\n")

# Ітерація по батчах
for batch_idx, (batch_X, batch_y) in enumerate(loader):
    print(f"Батч {batch_idx + 1}: X={batch_X.shape}, y={batch_y.shape}")
    if batch_idx == 2:  # показуємо лише перші 3 батчі
        break
```

#### Ключові параметри DataLoader

::card-group

::card{title="📦 batch_size" icon="i-lucide-package"}

**Що робить:** Кількість прикладів у одному батчі

**Типові значення:**
- Малі моделі: 32-128
- Великі моделі: 8-32
- Transformers: 4-16

**Компроміс:** Більший батч → швидше, але більше пам'яті

::

::card{title="🔀 shuffle" icon="i-lucide-shuffle"}

**Що робить:** Перемішує дані перед кожною епохою

**Коли `True`:**
- Тренувальний набір (завжди!)
- Запобігає навчанню на порядку прикладів

**Коли `False`:**
- Валідаційний/тестовий набори
- Детермінований порядок для відтворюваності

::

::card{title="⚡ num_workers" icon="i-lucide-zap"}

**Що робить:** Кількість паралельних процесів для завантаження даних

**Рекомендації:**
- CPU: 2-8 (залежно від ядер)
- GPU: 4-8 (щоб GPU не чекав)
- `num_workers=0`: без паралелізму (для дебагу)

**Важливо:** На Windows можуть бути проблеми з `num_workers > 0`

::

::card{title="📌 pin_memory" icon="i-lucide-pin"}

**Що робить:** Виділяє пам'ять у pinned memory для швидшого CPU→GPU transfer

**Коли `True`:**
- Працюєте з GPU
- Прискорення ~10-20%

**Коли `False`:**
- Тільки CPU
- Дебаг (економія пам'яті)

### Частина 1: Ефективна робота з даними

#### 1.1. Вступ: Проблема великих датасетів
- Чому не можна завантажити весь датасет у RAM
- Приклад: ImageNet (1.2 млн зображень, ~150 GB)
- Рішення: ледаче завантаження (lazy loading) через DataLoader

#### 1.2. Dataset — абстракція для даних
- **Абстрактний клас `torch.utils.data.Dataset`**
- Два обов'язкові методи:
  - `__len__()` — повертає кількість прикладів
  - `__getitem__(idx)` — повертає один приклад за індексом
- Створення власного Dataset для табличних даних (CSV)
- Створення Dataset для зображень (папка з файлами)

#### 1.3. DataLoader — ітерація по батчах
- **Ключові параметри:**
  - `batch_size` — розмір батча
  - `shuffle` — перемішувати дані перед кожною епохою
  - `num_workers` — кількість процесів для завантаження (паралелізм)
  - `pin_memory` — оптимізація для GPU
  - `drop_last` — що робити з неповним останнім батчем
- **Collate function:**
  - Коли потрібна кастомна функція для об'єднання прикладів
  - Приклад: обробка послідовностей різної довжини (padding)

#### 1.4. Трансформації даних
- **Стандартизація (Standardization):**
  - Формула: z = (x - μ) / σ
  - Обчислення mean та std на тренувальному наборі
  - Застосування тих самих параметрів до валідації/тесту
- **Нормалізація (Min-Max Scaling):**
  - Формула: x_scaled = (x - min) / (max - min)
  - Коли використовувати vs стандартизація
- **Перетворення категоріальних ознак:**
  - Label Encoding (для цільової змінної)
  - One-Hot Encoding (для категоріальних ознак)
- **Data Augmentation (згадка):**
  - Для зображень: flip, rotate, crop (детально в Модулі 5)
  - Для тексту: synonym replacement (детально в Модулі 6)

#### 1.5. Train/Validation/Test Split
- **Підходи до розділення:**
  - `torch.utils.data.random_split()` — простий випадковий split
  - `sklearn.model_selection.train_test_split()` — з контролем random_state
  - Стратифікація для незбалансованих класів
- **Правильний порядок операцій:**
  1. Split на train/val/test
  2. Обчислити статистики (mean, std) **лише на train**
  3. Застосувати трансформації до всіх наборів
- Типові співвідношення: 70/15/15 або 80/10/10

#### 1.6. Практичні кейси Dataset та DataLoader
- **Кейс 1:** CSV датасет (Titanic)
  - Завантаження з pandas
  - Створення кастомного Dataset
  - Ітерація по батчах з DataLoader
- **Кейс 2:** Нестандартний формат даних
  - Dataset для кількох CSV файлів
  - Комбінування різних джерел даних
- **Кейс 3:** Оптимізація завантаження
  - Вплив `num_workers` на швидкість
  - Профілювання bottleneck'ів

### Частина 2: Техніки регуляризації

#### 2.1. Вступ: Проблема перенавчання
- **Симптоми:**
  - Train accuracy 99%, Test accuracy 60%
  - Train loss → 0, Val loss зростає
- **Причини:**
  - Модель занадто складна (багато параметрів)
  - Датасет занадто малий
  - Занадто довге тренування
- **Рішення:** регуляризація

#### 2.2. Dropout — випадкове вимикання нейронів
- **Принцип роботи:**
  - Під час тренування: випадково вимикає p% нейронів
  - Під час інференсу: всі нейрони активні, виходи масштабуються
- **Inverted Dropout:**
  - PyTorch автоматично масштабує у режимі тренування
  - Формула: y = y / (1 - p)
- **`nn.Dropout(p=0.3)`:**
  - Додається після шарів (зазвичай після активації)
  - Типові значення: p = 0.2–0.5
- **Коли застосовувати:**
  - ✅ Повнозв'язні шари (Fully Connected)
  - ⚠️ Згорткові шари (краще Batch Norm або Spatial Dropout)
  - ❌ Рекурентні шари (є спеціальний варіант — Variational Dropout)
- **Варіації:**
  - `nn.Dropout2d()` — для згорткових мереж
  - `nn.AlphaDropout()` — для SELU активації

#### 2.3. Batch Normalization — нормалізація батча
- **Проблема Internal Covariate Shift:**
  - Розподіл входів шару змінюється під час тренування
  - Уповільнює навчання та вимагає малого learning rate
- **Як працює Batch Normalization:**
  1. Нормалізація батча: (x - μ_batch) / √(σ²_batch + ε)
  2. Learnable параметри: γ (scale) та β (shift)
  3. Фінальний вихід: y = γ · x_norm + β
- **`nn.BatchNorm1d(num_features)`:**
  - Для 1D даних (табличні датасети, FC layers)
  - `nn.BatchNorm2d()` — для 2D (зображення, Conv layers)
- **Batch Norm у режимах train vs eval:**
  - Train: використовує статистики поточного батча, оновлює running mean/std
  - Eval: використовує збережені running mean/std
- **Де додавати Batch Norm:**
  - Варіант 1: після Linear/Conv, **перед** активацією
  - Варіант 2: після Linear/Conv, **після** активації
  - Варіант 1 рекомендується в оригінальній статті
- **Batch Norm + Dropout:**
  - Порядок: Linear → BatchNorm → Activation → Dropout
  - Або можна використовувати лише одне з них

#### 2.4. Weight Decay (L2 Regularization)
- **Принцип:**
  - Додає штраф за великі ваги до функції втрат
  - Формула: Loss_total = Loss + λ · Σ(w²)
- **Два способи реалізації:**
  - **Спосіб 1:** Додавання до функції втрат (явно)
  - **Спосіб 2:** Параметр `weight_decay` в оптимізаторі (рекомендовано)
- **Приклад:**
  ```python
  optimizer = torch.optim.Adam(model.parameters(), lr=0.001, weight_decay=1e-5)
  ```
- **Різниця між L1 та L2:**
  - L1 (Lasso): штраф за |w| → розріджені ваги (sparse)
  - L2 (Ridge): штраф за w² → малі ваги, але не нульові
- **Типові значення:** `weight_decay = 1e-4` до `1e-5`

#### 2.5. Інші техніки регуляризації (огляд)
- **Layer Normalization:**
  - Нормалізація по ознаках (не по батчу)
  - Використовується в Transformers
- **Group Normalization:**
  - Компроміс між Batch Norm та Layer Norm
  - Для малих батчів
- **Gradient Clipping:**
  - Обмеження норми градієнта
  - Проти вибуху градієнтів (особливо в RNN)
- **Data Augmentation:**
  - Згадка (детально в Модулях 5 та 6)

#### 2.6. Порівняльні експерименти
- **Експеримент 1:** Модель без регуляризації
  - Перенавчання на малому датасеті
- **Експеримент 2:** Модель з Dropout (p=0.3)
  - Покращення test accuracy
- **Експеримент 3:** Модель з Batch Normalization
  - Швидша збіжність
- **Експеримент 4:** Модель з Weight Decay
  - Згладжування ваг
- **Експеримент 5:** Комбінація всіх технік
  - Batch Norm + Dropout + Weight Decay
  - Найкращий результат

#### 2.7. Практичні рекомендації
- **Коли застосовувати кожну техніку:**
  - Dropout: якщо модель перенавчається на FC layers
  - Batch Norm: майже завжди (особливо для глибоких мереж)
  - Weight Decay: якщо ваги стають занадто великими
- **Порядок шарів:**
  - Рекомендований: Linear → BatchNorm → ReLU → Dropout
- **Гіперпараметри:**
  - Dropout: p = 0.2–0.5
  - Weight decay: 1e-5 до 1e-4
  - Batch Norm: α (momentum) = 0.1 (за замовчуванням)

### Dropout — випадкове вимикання нейронів

::jupyter-notebook{title="dropout.ipynb"}

::jupyter-cell{executionCount="1"}

```python
import torch
import torch.nn as nn

class NetworkWithDropout(nn.Module):
    def __init__(self, input_size, hidden_size, output_size, dropout_p=0.5):
        super().__init__()
        self.fc1 = nn.Linear(input_size, hidden_size)
        self.dropout1 = nn.Dropout(p=dropout_p)
        
        self.fc2 = nn.Linear(hidden_size, hidden_size)
        self.dropout2 = nn.Dropout(p=dropout_p)
        
        self.fc3 = nn.Linear(hidden_size, output_size)
    
    def forward(self, x):
        x = torch.relu(self.fc1(x))
        x = self.dropout1(x)  # Dropout після активації
        
        x = torch.relu(self.fc2(x))
        x = self.dropout2(x)
        
        x = self.fc3(x)
        return x

model = NetworkWithDropout(10, 128, 3, dropout_p=0.3)
X = torch.randn(5, 10)

# Режим train: dropout активний
model.train()
out_train = model(X)
print(f"Train mode (dropout ON): {out_train[0]}")

# Режим eval: dropout вимкнений
model.eval()
with torch.no_grad():
    out_eval = model(X)
print(f"Eval mode (dropout OFF): {out_eval[0]}")
```

#output
Train mode (dropout ON): tensor([ 0.3421, -1.2345,  0.7890], grad_fn=<SelectBackward0>)
Eval mode (dropout OFF): tensor([ 0.2341, -0.8543,  0.5432])

::

::

::tip
**Типові значення dropout:**

- `p=0.2`: легка регуляризація
- `p=0.3-0.5`: стандартний вибір для FC layers
- `p=0.6-0.8`: агресивна регуляризація (рідко)

**Де додавати:** Після активації у прихованих шарах. НЕ додавати на вихідному шарі!

### Batch Normalization

::jupyter-notebook{title="batch_normalization.ipynb"}

::jupyter-cell{executionCount="1"}

```python
import torch
import torch.nn as nn

class NetworkWithBatchNorm(nn.Module):
    def __init__(self, input_size, hidden_size, output_size):
        super().__init__()
        self.fc1 = nn.Linear(input_size, hidden_size)
        self.bn1 = nn.BatchNorm1d(hidden_size)
        
        self.fc2 = nn.Linear(hidden_size, hidden_size)
        self.bn2 = nn.BatchNorm1d(hidden_size)
        
        self.fc3 = nn.Linear(hidden_size, output_size)
    
    def forward(self, x):
        x = self.fc1(x)
        x = self.bn1(x)  # BatchNorm перед активацією
        x = torch.relu(x)
        
        x = self.fc2(x)
        x = self.bn2(x)
        x = torch.relu(x)
        
        x = self.fc3(x)
        return x

model = NetworkWithBatchNorm(10, 64, 3)
X = torch.randn(32, 10)

output = model(X)
print(f"Вихід: {output.shape}")
print(f"\nBatchNorm параметри (навчаються):")
print(f"  gamma (scale): {model.bn1.weight.shape}")
print(f"  beta (shift): {model.bn1.bias.shape}")
```

  gamma (scale): torch.Size([64])

::

::note
**Порядок шарів (два варіанти):**

**Варіант 1 (оригінальна стаття):**
```
Linear → BatchNorm → ReLU → Dropout
```

**Варіант 2 (популярний у практиці):**
```
Linear → ReLU → BatchNorm → Dropout
```

Обидва працюють, але варіант 1 рекомендується авторами Batch Normalization.

## Повний приклад: Боротьба з перенавчанням

::jupyter-notebook{title="full_regularization_example.ipynb"}

::jupyter-cell{type="markdown"}
### Порівняння: без регуляризації vs з регуляризацією
::

::jupyter-cell{executionCount="1"}

```python
import torch
import torch.nn as nn
import torch.optim as optim
from torch.utils.data import TensorDataset, DataLoader, random_split

# Генеруємо невеликий датасет (схильний до overfitting)
torch.manual_seed(42)
X = torch.randn(200, 20)
y = (X.sum(dim=1, keepdim=True) > 0).float()

dataset = TensorDataset(X, y)
train_ds, val_ds = random_split(dataset, [150, 50])

train_loader = DataLoader(train_ds, batch_size=16, shuffle=True)
val_loader = DataLoader(val_ds, batch_size=16, shuffle=False)

# Модель БЕЗ регуляризації
class PlainModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = nn.Linear(20, 128)
        self.fc2 = nn.Linear(128, 64)
        self.fc3 = nn.Linear(64, 1)
    
    def forward(self, x):
        x = torch.relu(self.fc1(x))
        x = torch.relu(self.fc2(x))
        x = self.fc3(x)
        return x

# Модель З регуляризацією
class RegularizedModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = nn.Linear(20, 128)
        self.bn1 = nn.BatchNorm1d(128)
        self.dropout1 = nn.Dropout(0.3)
        
        self.fc2 = nn.Linear(128, 64)
        self.bn2 = nn.BatchNorm1d(64)
        self.dropout2 = nn.Dropout(0.3)
        
        self.fc3 = nn.Linear(64, 1)
    
    def forward(self, x):
        x = self.fc1(x)
        x = self.bn1(x)
        x = torch.relu(x)
        x = self.dropout1(x)
        
        x = self.fc2(x)
        x = self.bn2(x)
        x = torch.relu(x)
        x = self.dropout2(x)
        
        x = self.fc3(x)
        return x

# Тренування обох моделей
def train_model(model, train_loader, val_loader, epochs=50, use_wd=False):
    criterion = nn.BCEWithLogitsLoss()
    if use_wd:
        optimizer = optim.AdamW(model.parameters(), lr=0.001, weight_decay=0.01)
    else:
        optimizer = optim.Adam(model.parameters(), lr=0.001)
    
    train_losses, val_losses = [], []
    
    for epoch in range(epochs):
        # Train
        model.train()
        train_loss = 0
        for X_batch, y_batch in train_loader:
            optimizer.zero_grad()
            output = model(X_batch)
            loss = criterion(output, y_batch)
            loss.backward()
            optimizer.step()
            train_loss += loss.item()
        
        # Validation
        model.eval()
        val_loss = 0
        with torch.no_grad():
            for X_batch, y_batch in val_loader:
                output = model(X_batch)
                loss = criterion(output, y_batch)
                val_loss += loss.item()
        
        train_losses.append(train_loss / len(train_loader))
        val_losses.append(val_loss / len(val_loader))
    
    return train_losses, val_losses

# Тренуємо обидві моделі
print("Тренування моделі БЕЗ регуляризації...")
plain_model = PlainModel()
plain_train, plain_val = train_model(plain_model, train_loader, val_loader)

print("Тренування моделі З регуляризацією...")
reg_model = RegularizedModel()
reg_train, reg_val = train_model(reg_model, train_loader, val_loader, use_wd=True)

print(f"\nРезультати:")
print(f"  Без регуляризації: Train={plain_train[-1]:.4f}, Val={plain_val[-1]:.4f}")
print(f"  З регуляризацією: Train={reg_train[-1]:.4f}, Val={reg_val[-1]:.4f}")
print(f"\n✓ Регуляризація зменшила розрив між train та val loss!")
```

  З регуляризацією: Train=0.1123, Val=0.1567

## Резюме

::card-group

::card{title="📦 Dataset & DataLoader" icon="i-lucide-database"}

- Dataset: `__len__()` + `__getitem__(idx)`
- DataLoader: батчування + shuffle + parallel loading
- `num_workers=4-8` для прискорення завантаження
- `pin_memory=True` для GPU

::

::card{title="🎨 Трансформації" icon="i-lucide-palette"}

- Стандартизація: `(x - mean) / std`
- Обчислювати статистики **лише на train**
- Застосовувати ті самі параметри до val/test
- Split: 70/15/15 або 80/10/10

::

::card{title="🛡️ Регуляризація" icon="i-lucide-shield"}

- **Dropout (p=0.3-0.5):** після активації
- **Batch Norm:** перед або після активації
- **Weight Decay (1e-4 до 1e-5):** в оптимізаторі
- Комбінуйте для найкращих результатів

::

::card{title="📊 Боротьба з overfitting" icon="i-lucide-trending-down"}

- Моніторити train vs val loss
- Early stopping (patience=3-10)
- Збільшити dropout
- Додати більше даних (augmentation)
- Зменшити складність моделі
