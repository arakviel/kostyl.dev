## 📋 Зміст статті

### Частина 1: GPU-прискорення

#### 1.1. Вступ: CPU vs GPU для Deep Learning
- **Порівняння швидкості:**
  - CPU: 10 хв/епоха
  - GPU: 30 сек/епоха (прискорення у 20×)
- Чому GPU швидший:
  - Тисячі ядер для паралельних обчислень
  - Оптимізовані для матричних операцій
  - Висока пропускна здатність пам'яті

#### 1.2. Переміщення на GPU
- **Перевірка доступності:**
  ```python
  torch.cuda.is_available()
  torch.cuda.device_count()
  torch.cuda.get_device_name(0)
  ```
- **Створення device object:**
  ```python
  device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')
  ```
- **Переміщення тензорів:**
  - `.to(device)` — універсальний метод
  - `.cuda()` — переміщення на GPU
  - `.cpu()` — повернення на CPU
- **Переміщення моделі:**
  ```python
  model = MyModel().to(device)
  ```
- **Важливо:** дані та модель мають бути на одному пристрої

#### 1.3. Multi-GPU Training (згадка)
- DataParallel vs DistributedDataParallel
- Коли потрібно (великі моделі, великі датасети)
- Детально буде в окремому курсі (поза межами цього модуля)

#### 1.4. Практичний кейс: тренування на CPU vs GPU
- Порівняльний бенчмарк
- Графік швидкості (секунд/епоха)
- Вимірювання споживання пам'яті

### Частина 2: Mixed Precision Training

#### 2.1. Проблема: обмеження пам'яті GPU
- Моделі стають все більшими (GPT-3: 175B параметрів)
- FP32 (float32): 4 байти на параметр
- Рішення: FP16 (float16) — 2 байти, вдвічі менше пам'яті

#### 2.2. Що таке Mixed Precision
- Комбінація FP16 та FP32
- FP16 для forward/backward (швидше, менше пам'яті)
- FP32 для оновлення ваг (точність)
- Автоматичне масштабування градієнтів (gradient scaling)

#### 2.3. PyTorch Automatic Mixed Precision (AMP)
- **`torch.cuda.amp.autocast()`:**
  - Контекстний менеджер для автоматичного кастингу
  - Обгортає forward pass
- **`torch.cuda.amp.GradScaler()`:**
  - Масштабування градієнтів проти underflow
  - Обгортає backward та optimizer.step()
- **Приклад коду:**
  ```python
  scaler = torch.cuda.amp.GradScaler()
  
  for epoch in range(num_epochs):
      optimizer.zero_grad()
      with torch.cuda.amp.autocast():
          predictions = model(X)
          loss = criterion(predictions, y)
      scaler.scale(loss).backward()
      scaler.step(optimizer)
      scaler.update()
  ```

#### 2.4. Переваги та обмеження
- **Переваги:**
  - ✅ Прискорення у 1.5–3× (залежно від GPU)
  - ✅ Економія пам'яті у 2×
  - ✅ Більші батчі → краща генералізація
- **Обмеження:**
  - ⚠️ Працює лише на NVIDIA GPU з Tensor Cores (від GTX 1660)
  - ⚠️ Деякі операції не підтримують FP16 (рідко)

#### 2.5. Практичний кейс
- Порівняння FP32 vs Mixed Precision
- Швидкість, споживання пам'яті, точність моделі

### Частина 3: Оптимізація та профілювання

#### 3.1. Оптимізація використання пам'яті GPU
- **`torch.no_grad()`** — вимкнути autograd для inference
- **`del` та `torch.cuda.empty_cache()`** — звільнення пам'яті
- **Gradient checkpointing:**
  - Компроміс: пам'ять ↔ час обчислень
  - Для дуже глибоких мереж
- **In-place операції:**
  - `.relu_()`, `.add_()` — економія пам'яті
  - Обережно: можуть порушити autograd

#### 3.2. Профілювання продуктивності
- **`torch.utils.benchmark.Timer`:**
  - Точне вимірювання часу виконання
  - Warmup iterations (перші виклики завжди повільніші)
- **CUDA Timing:**
  ```python
  start = torch.cuda.Event(enable_timing=True)
  end = torch.cuda.Event(enable_timing=True)
  start.record()
  # ... операції ...
  end.record()
  torch.cuda.synchronize()
  elapsed_time = start.elapsed_time(end)
  ```
- **PyTorch Profiler:**
  - `torch.profiler.profile()` — детальний аналіз
  - Візуалізація через TensorBoard

#### 3.3. Оптимізація DataLoader
- `pin_memory=True` — прискорення CPU → GPU transfers
- `num_workers` — оптимальна кількість (зазвичай 4–8)
- `prefetch_factor` — завантаження наперед
- `persistent_workers=True` — для довгих тренувань

- **Кейс 2:** Оптимізація DataLoader (до/після)

### Частина 4: Збереження та завантаження моделей

#### 4.1. Два способи збереження
- **Спосіб 1: state_dict (рекомендовано):**
  ```python
  torch.save(model.state_dict(), 'model_weights.pth')
  model.load_state_dict(torch.load('model_weights.pth'))
  ```
  - Зберігаються лише параметри (ваги + bias)
  - Потрібно спочатку створити екземпляр моделі
- **Спосіб 2: вся модель (не рекомендовано):**
  ```python
  torch.save(model, 'full_model.pth')
  model = torch.load('full_model.pth')
  ```
  - Зберігається через pickle
  - Проблеми з сумісністю версій PyTorch
  - Ризики безпеки при завантаженні з ненадійних джерел

#### 4.2. Checkpoint — збереження стану тренування
- **Що зберігати:**
  - Ваги моделі (`model.state_dict()`)
  - Стан оптимізатора (`optimizer.state_dict()`)
  - Номер епохи
  - Найкраща метрика (best_loss, best_accuracy)
  - Learning rate scheduler state (якщо є)
- **Приклад:**
  ```python
  checkpoint = {
      'epoch': epoch,
      'model_state_dict': model.state_dict(),
      'optimizer_state_dict': optimizer.state_dict(),
      'best_loss': best_loss
  }
  torch.save(checkpoint, 'checkpoint.pth')
  ```
- **Відновлення тренування:**
  ```python
  checkpoint = torch.load('checkpoint.pth')
  model.load_state_dict(checkpoint['model_state_dict'])
  optimizer.load_state_dict(checkpoint['optimizer_state_dict'])
  start_epoch = checkpoint['epoch'] + 1
  ```

### Частина 5: Deployment моделей

#### 5.1. TorchScript — компіляція моделі
- **Чому потрібно:**
  - Python повільний для inference
  - PyTorch модель залежить від Python runtime
  - TorchScript — незалежний формат (C++ runtime)
- **Два способи створення:**
  - **`torch.jit.trace()`** — для моделей без умовної логіки
    ```python
    traced_model = torch.jit.trace(model, example_input)
    traced_model.save('model_traced.pt')
    ```
  - **`torch.jit.script()`** — для моделей з if/for/while
    ```python
    scripted_model = torch.jit.script(model)
    scripted_model.save('model_scripted.pt')
    ```
- **Коли використовувати кожен:**
  - Trace: для простих feed-forward мереж
  - Script: для RNN, умовних розгалужень, циклів

#### 5.2. ONNX — міжплатформенний формат
- **Що таке ONNX:**
  - Open Neural Network Exchange
  - Формат для переносу моделей між фреймворками
  - PyTorch → ONNX → TensorFlow / TensorRT / CoreML
- **Експорт у ONNX:**
  ```python
  dummy_input = torch.randn(1, 3, 224, 224)
  torch.onnx.export(model, dummy_input, 'model.onnx',
                    input_names=['input'],
                    output_names=['output'])
  ```
- **Використання:**
  - Deployment на мобільних пристроях (CoreML, TensorFlow Lite)
  - Прискорення на NVIDIA GPU (TensorRT)
  - Запуск у браузері (ONNX.js)

#### 5.3. Inference оптимізація
- **Режим eval:**
  - Завжди `model.eval()` для inference
  - Вимикає Dropout, BatchNorm у тренувальному режимі
- **Batch inference:**
  - Обробка кількох прикладів одночасно
  - Амортизація overhead'у
- **Quantization (згадка):**
  - Зменшення precision (INT8 замість FP32)
  - Прискорення у 2–4×, менший розмір моделі
  - Детально в окремому курсі
