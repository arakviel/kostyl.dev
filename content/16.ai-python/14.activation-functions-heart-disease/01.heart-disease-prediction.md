## Математика функцій активації — чому похідна критична

Ми вже знаємо, що функції активації вносять нелінійність у нейронну мережу. Але для навчання мережі через градієнтний спуск нам потрібні **похідні** цих функцій. Саме похідні дозволяють обчислити, в якому напрямку та наскільки змінювати ваги, щоб зменшити помилку.

### Нагадування: ланцюгове правило диференціювання

Алгоритм зворотного поширення (backpropagation) базується на **ланцюговому правилі** з математичного аналізу. Якщо маємо композицію функцій:

::math-formula
y = f(g(x))
::

То похідна за :math-formula{tex="x" inline}:

::math-formula
\frac{\partial y}{\partial x} = \frac{\partial f}{\partial g} \cdot \frac{\partial g}{\partial x}
::

У нейронній мережі градієнт втрат по вазі :math-formula{tex="w" inline} обчислюється через ланцюг похідних від вихідного шару до вхідного. На кожному кроці ми множимо на похідну функції активації поточного нейрона.

::note
**Чому похідна функції активації важлива:**

Якщо похідна близька до нуля (як у сигмоїди для великих :math-formula{tex="|z|" inline}), то градієнт «зникає» — ваги попередніх шарів практично не оновлюються. Це проблема **vanishing gradients**.

Якщо похідна занадто велика, градієнт «вибухає» — ваги стрибають хаотично. Це проблема **exploding gradients**.

Ідеальна функція активації має стабільну, ненульову похідну в широкому діапазоні входів.
::

### Сигмоїда (Sigmoid) — похідна та проблеми

**Формула:**

::math-formula
\sigma(z) = \frac{1}{1 + e^{-z}}
::

**Похідна:**

Скористаємося правилом диференціювання частки та ланцюговим правилом:

::math-formula
\frac{d\sigma}{dz} = \frac{d}{dz} \left( \frac{1}{1 + e^{-z}} \right) = \frac{e^{-z}}{(1 + e^{-z})^2}
::

Можна показати, що це рівносильно елегантній формі:

::math-formula
\sigma'(z) = \sigma(z) \cdot (1 - \sigma(z))
::

**Докази:**

::math-formula
\sigma'(z) = \frac{e^{-z}}{(1 + e^{-z})^2} = \frac{1}{1 + e^{-z}} \cdot \frac{e^{-z}}{1 + e^{-z}} = \sigma(z) \cdot \left(1 - \frac{1}{1 + e^{-z}}\right) = \sigma(z) \cdot (1 - \sigma(z))
::

**Властивості похідної:**

::jupyter-notebook{title="sigmoid_derivative.ipynb" kernel="Python 3.11 (ipykernel)"}

::jupyter-cell{executionCount="1" executionTime="0.34s"}

```python
import numpy as np
import matplotlib.pyplot as plt

def sigmoid(z):
    return 1 / (1 + np.exp(-z))

def sigmoid_derivative(z):
    s = sigmoid(z)
    return s * (1 - s)

# Діапазон значень
z = np.linspace(-10, 10, 500)

# Візуалізація
fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(16, 6))

# Сигмоїда
ax1.plot(z, sigmoid(z), color='#3b82f6', linewidth=3, label='σ(z)')
ax1.axhline(0, color='gray', linestyle='--', alpha=0.3)
ax1.axhline(1, color='gray', linestyle='--', alpha=0.3)
ax1.axvline(0, color='gray', linestyle='--', alpha=0.3)
ax1.grid(alpha=0.3)
ax1.set_xlabel('z', fontsize=14)
ax1.set_ylabel('σ(z)', fontsize=14)
ax1.set_title('Функція Sigmoid', fontsize=16, fontweight='bold')
ax1.legend(fontsize=12)

# Похідна сигмоїди
ax2.plot(z, sigmoid_derivative(z), color='#ef4444', linewidth=3, label="σ'(z) = σ(z)·(1 - σ(z))")
ax2.axhline(0, color='gray', linestyle='--', alpha=0.3)
ax2.axvline(0, color='gray', linestyle='--', alpha=0.3)
ax2.fill_between(z, 0, sigmoid_derivative(z), alpha=0.2, color='#ef4444')

# Позначимо максимум похідної
max_val = sigmoid_derivative(0)
ax2.plot(0, max_val, 'o', color='#dc2626', markersize=12, label=f'Максимум: σ\'(0) = {max_val:.3f}')
ax2.annotate(f'Макс = {max_val:.3f}\nпри z=0', xy=(0, max_val), xytext=(2, max_val),
             arrowprops=dict(arrowstyle='->', color='#dc2626', lw=2),
             fontsize=12, color='#dc2626', fontweight='bold')

# Критичні зони
ax2.axvspan(-10, -5, alpha=0.15, color='yellow', label='Зони зникаючого градієнта')
ax2.axvspan(5, 10, alpha=0.15, color='yellow')
ax2.text(-7.5, 0.15, 'σ\'(z) ≈ 0', fontsize=11, ha='center', style='italic')
ax2.text(7.5, 0.15, 'σ\'(z) ≈ 0', fontsize=11, ha='center', style='italic')

ax2.grid(alpha=0.3)
ax2.set_xlabel('z', fontsize=14)
ax2.set_ylabel("σ'(z)", fontsize=14)
ax2.set_title('Похідна Sigmoid', fontsize=16, fontweight='bold')
ax2.legend(fontsize=11, loc='upper right')

plt.tight_layout()
plt.show()
```

### Гіперболічний тангенс (Tanh) — центрована альтернатива

**Формула:**

::math-formula
\tanh(z) = \frac{e^z - e^{-z}}{e^z + e^{-z}} = \frac{e^{2z} - 1}{e^{2z} + 1}
::

**Зв'язок із сигмоїдою:**

::math-formula
\tanh(z) = 2\sigma(2z) - 1
::

**Похідна:**

::math-formula
\tanh'(z) = 1 - \tanh^2(z)
::

**Доведення:**

::math-formula
\frac{d\tanh(z)}{dz} = \frac{d}{dz}\left(\frac{e^z - e^{-z}}{e^z + e^{-z}}\right) = \frac{(e^z + e^{-z})^2 - (e^z - e^{-z})^2}{(e^z + e^{-z})^2}
::

::math-formula
= \frac{4e^z \cdot e^{-z}}{(e^z + e^{-z})^2} = \frac{4}{(e^z + e^{-z})^2}
::

Підставляючи :math-formula{tex="\tanh(z)" inline}, отримуємо:

::math-formula
\tanh'(z) = 1 - \tanh^2(z)
::

**Властивості:**
- Діапазон виходу: :math-formula{tex="(-1, 1)" inline} — центрований навколо нуля
- Максимум похідної: :math-formula{tex="\tanh'(0) = 1" inline} — вчетверо більше, ніж у сигмоїди!
- Все одно страждає від зникаючих градієнтів для :math-formula{tex="|z| > 3" inline}

::tip
**Коли використовувати Tanh:**

Tanh краща за сигмоїду для прихованих шарів у неглибоких мережах (2–3 шари) завдяки центруванню навколо нуля. Але для глибоких мереж ReLU все одно перемагає.

Tanh часто використовується в рекурентних нейронних мережах (RNN, LSTM), де центроване представлення критично важливе для стабільності.
::

### ReLU (Rectified Linear Unit) — революційна простота

**Формула:**

::math-formula
\text{ReLU}(z) = \max(0, z) = \begin{cases}
z, & \text{якщо } z > 0 \\
0, & \text{якщо } z \leq 0
\end{cases}
::

**Похідна:**

::math-formula
\text{ReLU}'(z) = \begin{cases}
1, & \text{якщо } z > 0 \\
0, & \text{якщо } z \leq 0 \\
\text{не визначена}, & \text{якщо } z = 0
\end{cases}
::

На практиці в точці :math-formula{tex="z = 0" inline} приймають похідну рівною 0 або 1 (не має значення, бо ймовірність потрапити точно в нуль — нульова).



**Чому ReLU вирішує проблему зникаючих градієнтів:**

::jupyter-notebook{title="relu_properties.ipynb" kernel="Python 3.11 (ipykernel)"}

::jupyter-cell{executionCount="2"}

```python
import numpy as np
import matplotlib.pyplot as plt

def relu(z):
    return np.maximum(0, z)

def relu_derivative(z):
    return np.where(z > 0, 1, 0)

z = np.linspace(-5, 5, 500)

fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(16, 6))

# ReLU функція
ax1.plot(z, relu(z), color='#10b981', linewidth=3, label='ReLU(z)')
ax1.axhline(0, color='gray', linestyle='--', alpha=0.3)
ax1.axvline(0, color='gray', linestyle='--', alpha=0.3)
ax1.grid(alpha=0.3)
ax1.set_xlabel('z', fontsize=14)
ax1.set_ylabel('ReLU(z)', fontsize=14)
ax1.set_title('Функція ReLU', fontsize=16, fontweight='bold')
ax1.legend(fontsize=12)
ax1.fill_between(z[z > 0], 0, relu(z)[z > 0], alpha=0.2, color='#10b981')
ax1.text(2, 1, 'Активна зона\n(градієнт = 1)', fontsize=12, color='#059669', fontweight='bold')
ax1.text(-3, 1, 'Мертва зона\n(градієнт = 0)', fontsize=12, color='#6b7280', fontweight='bold')

# ReLU похідна
ax2.plot(z, relu_derivative(z), color='#f59e0b', linewidth=3, drawstyle='steps-post', label="ReLU'(z)")
ax2.axhline(0, color='gray', linestyle='--', alpha=0.3)
ax2.axhline(1, color='#10b981', linestyle='--', alpha=0.3, linewidth=2)
ax2.axvline(0, color='gray', linestyle='--', alpha=0.3)
ax2.grid(alpha=0.3)
ax2.set_xlabel('z', fontsize=14)
ax2.set_ylabel("ReLU'(z)", fontsize=14)
ax2.set_title('Похідна ReLU', fontsize=16, fontweight='bold')
ax2.legend(fontsize=12)
ax2.set_ylim(-0.2, 1.3)

# Позначення константного градієнта
ax2.annotate('Градієнт = 1 (константа!)\nНемає зникання', 
             xy=(3, 1), xytext=(2, 1.15),
             arrowprops=dict(arrowstyle='->', color='#10b981', lw=2),
             fontsize=12, color='#059669', fontweight='bold',
             bbox=dict(boxstyle='round,pad=0.5', facecolor='#d1fae5', edgecolor='#10b981'))

plt.tight_layout()
plt.show()
```

**Проблема: "мертві нейрони" (Dying ReLU):**

Якщо нейрон постійно отримує від'ємні входи, то:
1. Вихід завжди 0
2. Градієнт завжди 0
3. Ваги не оновлюються
4. Нейрон **назавжди "вмирає"**

Це відбувається при:
- Занадто високому learning rate (ваги «перестрибують» у від'ємну зону)
- Поганій ініціалізації ваг
- Дуже великих від'ємних bias

::note
**Як запобігти "мертвим нейронам":**

1. **Правильна ініціалізація ваг:** використовуйте **He initialization** (розроблено спеціально для ReLU):
   ::math-formula
   W \sim \mathcal{N}\left(0, \sqrt{\frac{2}{n_{\text{in}}}}\right)
   ::
   де :math-formula{tex="n_{\text{in}}" inline} — кількість вхідних нейронів.

2. **Помірний learning rate:** для Adam рекомендовано 0.001–0.01.

3. **Leaky ReLU або ELU:** варіанти ReLU, які не обнулюють градієнт для від'ємних значень.
::

### Leaky ReLU — вирішення проблеми мертвих нейронів

**Формула:**

::math-formula
\text{Leaky ReLU}(z) = \max(\alpha z, z), \quad \text{де } \alpha = 0.01
::

Або еквівалентно:

::math-formula
\text{Leaky ReLU}(z) = \begin{cases}
z, & \text{якщо } z > 0 \\
\alpha z, & \text{якщо } z \leq 0
\end{cases}
::

**Похідна:**

::math-formula
\text{Leaky ReLU}'(z) = \begin{cases}
1, & \text{якщо } z > 0 \\
\alpha, & \text{якщо } z \leq 0
\end{cases}
::

**Ключова відмінність:** для від'ємних значень градієнт не нульовий, а дорівнює :math-formula{tex="\alpha" inline} (зазвичай 0.01). Це дозволяє нейрону **продовжувати навчатися**, навіть якщо він тимчасово потрапив у від'ємну зону.

::jupyter-notebook{title="leaky_relu_comparison.ipynb" kernel="Python 3.11 (ipykernel)"}

::jupyter-cell{executionCount="3" executionTime="0.27s"}

```python
import numpy as np
import matplotlib.pyplot as plt

def relu(z):
    return np.maximum(0, z)

def leaky_relu(z, alpha=0.01):
    return np.where(z > 0, z, alpha * z)

z = np.linspace(-5, 5, 500)

plt.figure(figsize=(12, 7))
plt.plot(z, relu(z), color='#10b981', linewidth=3, label='ReLU', linestyle='--', alpha=0.7)
plt.plot(z, leaky_relu(z), color='#f59e0b', linewidth=3, label='Leaky ReLU (α=0.01)')

plt.axhline(0, color='gray', linestyle='--', alpha=0.3)
plt.axvline(0, color='gray', linestyle='--', alpha=0.3)
plt.grid(alpha=0.3)

# Позначення відмінностей
plt.fill_between(z[z < 0], 0, leaky_relu(z)[z < 0], alpha=0.3, color='#f59e0b', 
                 label='Зона відновлення (α·z)')
plt.annotate('ReLU: градієнт = 0\n(нейрон "вмирає")', 
             xy=(-3, 0), xytext=(-4, 1.5),
             arrowprops=dict(arrowstyle='->', color='#6b7280', lw=2),
             fontsize=11, color='#6b7280', fontweight='bold')
plt.annotate('Leaky ReLU: градієнт = 0.01\n(нейрон продовжує навчатися)', 
             xy=(-3, -0.03), xytext=(-4, -2),
             arrowprops=dict(arrowstyle='->', color='#f59e0b', lw=2),
             fontsize=11, color='#d97706', fontweight='bold',
             bbox=dict(boxstyle='round,pad=0.5', facecolor='#fef3c7', edgecolor='#f59e0b'))

plt.xlabel('z', fontsize=14)
plt.ylabel('Активація', fontsize=14)
```

::tip
**Коли використовувати Leaky ReLU:**

Якщо під час навчання ви спостерігаєте:
- Стагнацію loss після кількох епох
- Велику кількість нейронів із нульовою активацією (можна перевірити через `.weight.grad`)
- Втрату якості при збільшенні кількості шарів

Спробуйте замінити ReLU на Leaky ReLU. Емпірично це покращує збіжність у 10–15% випадків.
::

### Порівняльна таблиця функцій активації та їхніх похідних

| Функція     | Формула                       | Похідна                    | Максимум похідної | Зникаючі градієнти | Мертві нейрони | Рекомендація                |
| :---------- | :---------------------------- | :------------------------- | :---------------: | :----------------: | :------------: | :-------------------------- |
| **Sigmoid** | :math-formula{tex="\frac{1}{1+e^{-z}}" inline} | :math-formula{tex="\sigma(1-\sigma)" inline} |       0.25        |         ✅ Так          |       ❌ Ні       | Лише вихідний шар (бінарна) |
| **Tanh**    | :math-formula{tex="\frac{e^z-e^{-z}}{e^z+e^{-z}}" inline} | :math-formula{tex="1-\tanh^2" inline} |       1.0         |         ✅ Так          |       ❌ Ні       | RNN, неглибокі мережі       |
| **ReLU**    | :math-formula{tex="\max(0,z)" inline} | :math-formula{tex="[z>0]" inline} |       1.0         |         ❌ Ні          |      ✅ Так      | За замовчуванням (приховані)|
| **Leaky ReLU** | :math-formula{tex="\max(0.01z, z)" inline} | :math-formula{tex="[z>0] + 0.01[z\leq0]" inline} |       1.0         |         ❌ Ні          |       ❌ Ні       | Альтернатива ReLU           |

::tip
**Емпіричне правило вибору функції активації для нашої задачі серцевих захворювань:**

1. **Приховані шари:** ReLU (стандарт для глибоких мереж)
2. **Вихідний шар:** Sigmoid (бінарна класифікація: хвороба є/немає)
3. **Якщо виникають проблеми з ReLU:** спробувати Leaky ReLU з α=0.01

Саме цю конфігурацію ми використаємо при побудові нашої моделі.
::

## Датасет UCI Heart Disease — клінічні дані для діагностики

Завантажимо та проаналізуємо **UCI Heart Disease Dataset** — один із найвідоміших медичних датасетів у машинному навчанні.

### Опис датасету та клінічний контекст

**Джерело:** UCI Machine Learning Repository ([посилання](https://archive.ics.uci.edu/ml/datasets/heart+disease))

**Історія:** Датасет зібрано у 1988 році в чотирьох медичних закладах:
1. Cleveland Clinic Foundation (Огайо, США)
2. Hungarian Institute of Cardiology (Будапешт, Угорщина)
3. V.A. Medical Center (Лонг-Біч, Каліфорнія)
4. University Hospital (Цюрих, Швейцарія)

**Обсяг:** 303 пацієнти, 14 клінічних ознак.

**Цільова змінна:** наявність серцево-судинного захворювання (0 = немає, 1–4 = різні ступені). У нашій задачі спростимо до бінарної класифікації: **0 = здоровий**, **1 = хворий** (будь-який ступінь).

---

### Опис 14 клінічних ознак

::steps

### Крок 1: Демографічні та базові показники

1. **age** (вік) — вік пацієнта у роках (діапазон: 29–77)
   - Фізіологічне значення: з віком зростає ризик атеросклерозу та ослаблення серцевого м'яза

2. **sex** (стать) — 1 = чоловік, 0 = жінка
   - Клінічний факт: у чоловіків ризик інфаркту вищий у молодому віці; у жінок — після менопаузи

3. **cp** (chest pain type) — тип болю в грудях:
   - 0: Типова стенокардія (typical angina) — біль при фізичному навантаженні
   - 1: Атипова стенокардія (atypical angina)
   - 2: Біль, не пов'язаний із серцем (non-anginal pain)
   - 3: Безсимптомний (asymptomatic)

### Крок 2: Показники серцево-судинної системи

4. **trestbps** (resting blood pressure) — артеріальний тиск у стані спокою, мм рт. ст.
   - Норма: ~120 мм рт. ст.
   - Гіпертензія (>140) — фактор ризику інфаркту та інсульту

5. **chol** (serum cholesterol) — рівень холестерину в крові, мг/дл
   - Норма: <200 мг/дл
   - Високий холестерин (>240) — накопичення атеросклеротичних бляшок у судинах

6. **fbs** (fasting blood sugar > 120 mg/dl) — підвищений цукор крові натще
   - 1 = так (>120 мг/дл), 0 = ні
   - Діабет — сильний предиктор серцево-судинних захворювань

### Крок 3: Електрокардіограма (ЕКГ)

7. **restecg** (resting electrocardiographic results) — результати ЕКГ у стані спокою:
   - 0: Норма
   - 1: Аномалія ST-T хвилі (можлива ішемія)
   - 2: Гіпертрофія лівого шлуночка (ознака хронічного перевантаження серця)

8. **thalach** (maximum heart rate achieved) — максимальна частота серцевих скорочень при навантаженні
   - Норма: 220 - вік
   - Низьке значення може вказувати на слабкість серцевого м'яза

### Крок 4: Стрес-тест та ангіографія

9. **exang** (exercise induced angina) — стенокардія, спричинена фізичним навантаженням
   - 1 = так, 0 = ні
   - Сильний маркер ішемічної хвороби серця

10. **oldpeak** — депресія сегмента ST на ЕКГ, спричинена фізичним навантаженням (відносно спокою)
    - Вимірюється в мм
    - Значення >2 мм — ознака серйозної ішемії

11. **slope** — нахил піку сегмента ST при навантаженні:
    - 0: Підйом (upsloping) — норма
    - 1: Рівний (flat) — можлива ішемія
    - 2: Спуск (downsloping) — висока ймовірність ішемії

12. **ca** (number of major vessels colored by fluoroscopy) — кількість великих судин, виявлених при флюороскопії (0–3)
    - Більше судин із звуженням → вищий ризик

13. **thal** (thalassemia) — результат таласемії (вроджене захворювання крові):
    - 1: Норма
    - 2: Фіксований дефект
    - 3: Зворотний дефект

::

::note
**Клінічна інтерпретація ознак:**

Найбільш інформативні ознаки за медичною статистикою:
1. **cp** (тип болю в грудях) — пряма ознака стенокардії
2. **thalach** (максимальна ЧСС) — показник функціональної резервності серця
3. **oldpeak** та **slope** — об'єктивні показники ішемії при навантаженні
4. **ca** (кількість уражених судин) — анатомічний маркер атеросклерозу

Ці ознаки часто використовують кардіологи для прийняття рішення про направлення на коронарографію.
::

**Обґрунтування вибору:**

::steps

### Крок 1: Вхідний шар (13 нейронів)

Кожна з 13 клінічних ознак отримує окремий нейрон. **Обов'язкове масштабування** через StandardScaler, бо ознаки мають різні діапазони:
- `age`: 29–77 (роки)
- `chol`: 126–564 (мг/дл)
- `oldpeak`: 0–6.2 (мм депресії ST)

Без масштабування великі значення холестерину «задавлять» малі значення oldpeak.

### Крок 2: Прихований шар 1 (64 нейрони, ReLU)

Перший прихований шар має **найбільшу ємність** (64 нейрони). Його завдання:
- Знаходити **лінійні комбінації** вхідних ознак
- Виявляти **взаємодії між ознаками** (наприклад: високий вік + високий холестерин = підвищений ризик)

**Чому 64?** Емпіричне правило: 2–5× від кількості входів. Для 13 ознак → 26–65 нейронів. Обрано 64 (степінь двійки для оптимізації обчислень).

**Dropout 30%:** Під час навчання випадково «вимикаємо» 30% нейронів на кожній ітерації. Це запобігає **перенавчанню** — мережа не може покластися на один конкретний нейрон.

### Крок 3: Прихований шар 2 (32 нейрони, ReLU)

Другий шар має **вдвічі менше нейронів**. Це **звужуюча архітектура (bottleneck)** — мережа змушена **стискати інформацію**, відкидаючи шум і залишаючи лише найважливіше.

Аналогія: якщо перший шар виявив 64 різні комбінації ознак, другий шар обирає з них 32 найінформативніші клінічні **патерни** (наприклад: «кластер ішемічних ознак», «профіль гіпертензії»).

**Dropout 20%:** менше, ніж у першому шарі, бо мережа вже навчилася узагальнювати.

### Крок 4: Вихідний шар (1 нейрон, Sigmoid)

Один нейрон з активацією **Sigmoid** повертає ймовірність діагнозу:
- Вихід 0.1 → 10% ймовірність хвороби (низький ризик)
- Вихід 0.9 → 90% ймовірність хвороби (високий ризик)

**Поріг прийняття рішення:** зазвичай 0.5, але для медичних застосувань можна знизити до 0.3–0.4, щоб **не пропустити хворих** (краще зайва перестраховка, ніж пропущений інфаркт).

::

---

### Функція втрат та оптимізатор

**Binary Cross-Entropy Loss:**

Для бінарної класифікації використовуємо **логістичну функцію втрат** (Binary Cross-Entropy, BCE):

::math-formula
\mathcal{L}(y, \hat{y}) = -\frac{1}{N} \sum_{i=1}^{N} \left[ y_i \log(\hat{y}_i) + (1 - y_i) \log(1 - \hat{y}_i) \right]
::

Де:
- :math-formula{tex="y_i \in \{0, 1\}" inline} — справжній діагноз пацієнта :math-formula{tex="i" inline}
- :math-formula{tex="\hat{y}_i \in (0, 1)" inline} — передбачена ймовірність хвороби
- :math-formula{tex="N" inline} — кількість пацієнтів у батчі

**Інтуїція:** BCE **сильно штрафує** модель за впевнені неправильні передбачення:
- Якщо справжній діагноз :math-formula{tex="y=1" inline} (хворий), а модель передбачила :math-formula{tex="\hat{y}=0.01" inline} (майже впевнена, що здоровий), то :math-formula{tex="-\log(0.01) \approx 4.6" inline} — велика втрата
- Якщо :math-formula{tex="\hat{y}=0.99" inline} (правильно), то :math-formula{tex="-\log(0.99) \approx 0.01" inline} — мінімальна втрата

**Оптимізатор Adam:**

Використовуємо **Adam** (Adaptive Moment Estimation) — найпопулярніший оптимізатор для нейронних мереж:

::math-formula
\theta_{t+1} = \theta_t - \frac{\alpha}{\sqrt{\hat{v}_t} + \epsilon} \hat{m}_t
::

Де:
- :math-formula{tex="\hat{m}_t" inline} — експоненційне ковзне середнє градієнтів (**momentum**)
- :math-formula{tex="\hat{v}_t" inline} — експоненційне ковзне середнє квадратів градієнтів (**adaptive learning rate**)
- :math-formula{tex="\alpha" inline} — базовий learning rate (обираємо 0.001)

**Переваги Adam над звичайним SGD:**
1. **Автоматичне налаштування learning rate** для кожного параметра (для «повільних» ознак — більший крок, для «швидких» — менший)
2. **Momentum** — «розгойдує» оптимізацію через локальні мінімуми
3. **Не вимагає ручного налаштування** learning rate schedule

::tip
**Гіперпараметри для нашої моделі:**

- **Learning rate:** 0.001 (стандарт для Adam)
- **Batch size:** 32 (компроміс між стабільністю та швидкістю)
- **Epochs:** 200 (з early stopping — зупинимося раніше при перенавчанні)
- **Early stopping patience:** 20 (якщо валідаційна loss не покращується 20 епох — зупиняємо)

::

```python
class HeartDiseaseNet(nn.Module):
    """
    Нейронна мережа для передбачення серцево-судинних захворювань.
    
    Архітектура:
      - Вхід: 13 клінічних ознак
      - Прихований шар 1: 64 нейрони (ReLU + Dropout 30%)
      - Прихований шар 2: 32 нейрони (ReLU + Dropout 20%)
      - Вихід: 1 нейрон (Sigmoid) — ймовірність хвороби
    """
    
    def __init__(self, input_size=13, hidden1=64, hidden2=32, dropout1=0.3, dropout2=0.2):
        super(HeartDiseaseNet, self).__init__()
        
        # Прихований шар 1
        self.fc1 = nn.Linear(input_size, hidden1)
        self.relu1 = nn.ReLU()
        self.dropout1 = nn.Dropout(dropout1)
        
        # Прихований шар 2
        self.fc2 = nn.Linear(hidden1, hidden2)
        self.relu2 = nn.ReLU()
        self.dropout2 = nn.Dropout(dropout2)
        
        # Вихідний шар
        self.fc3 = nn.Linear(hidden2, 1)
        self.sigmoid = nn.Sigmoid()
        
    def forward(self, x):
        """Прямий прохід (forward propagation)"""
        # Шар 1
        x = self.fc1(x)
        x = self.relu1(x)
        x = self.dropout1(x)
        
        # Шар 2
        x = self.fc2(x)
        x = self.relu2(x)
        x = self.dropout2(x)
        
        # Вихідний шар
        x = self.fc3(x)
        x = self.sigmoid(x)
        
        return x

# Ініціалізація моделі
model = HeartDiseaseNet().to(device)
```

```python
def train_epoch(model, loader, criterion, optimizer, device):
    """Одна епоха навчання"""
    model.train()  # Режим навчання (dropout активний)
    total_loss = 0.0
    all_preds = []
    all_labels = []
    
    for X_batch, y_batch in loader:
        X_batch, y_batch = X_batch.to(device), y_batch.to(device)
        
        # Прямий прохід
        optimizer.zero_grad()
        outputs = model(X_batch)
        loss = criterion(outputs, y_batch)
        
        # Зворотний прохід та оновлення ваг
        loss.backward()
        optimizer.step()
        
        # Збір статистики
        total_loss += loss.item() * X_batch.size(0)
        preds = (outputs >= 0.5).float()
        all_preds.extend(preds.cpu().numpy())
        all_labels.extend(y_batch.cpu().numpy())
    
    avg_loss = total_loss / len(loader.dataset)
    accuracy = accuracy_score(all_labels, all_preds)
    return avg_loss, accuracy


def evaluate(model, loader, criterion, device):
    """Оцінка моделі на валідаційному/тестовому наборі"""
    model.eval()  # Режим оцінки (dropout вимкнений)
    total_loss = 0.0
    all_preds = []
    all_probs = []
    all_labels = []
    
    with torch.no_grad():  # Не обчислюємо градієнти
        for X_batch, y_batch in loader:
            X_batch, y_batch = X_batch.to(device), y_batch.to(device)
            
            outputs = model(X_batch)
            loss = criterion(outputs, y_batch)
            
            total_loss += loss.item() * X_batch.size(0)
            preds = (outputs >= 0.5).float()
            all_preds.extend(preds.cpu().numpy())
            all_probs.extend(outputs.cpu().numpy())
            all_labels.extend(y_batch.cpu().numpy())
    
    avg_loss = total_loss / len(loader.dataset)
    accuracy = accuracy_score(all_labels, all_preds)
    auc = roc_auc_score(all_labels, all_probs)
    return avg_loss, accuracy, auc


# Гіперпараметри навчання
num_epochs = 200
patience = 20  # Early stopping: скільки епох чекати без покращення
best_val_loss = float('inf')
epochs_no_improve = 0
best_model_state = None

# Історія метрик
history = {
    'train_loss': [],
    'train_acc': [],
    'val_loss': [],
    'val_acc': [],
    'val_auc': []
}

print("=" * 70)
print("ПОЧАТОК НАВЧАННЯ")
print("=" * 70)

for epoch in range(num_epochs):
    # Навчання
    train_loss, train_acc = train_epoch(model, train_loader, criterion, optimizer, device)
    
    # Валідація
    val_loss, val_acc, val_auc = evaluate(model, val_loader, criterion, device)
    
    # Збереження історії
    history['train_loss'].append(train_loss)
    history['train_acc'].append(train_acc)
    history['val_loss'].append(val_loss)
    history['val_acc'].append(val_acc)
    history['val_auc'].append(val_auc)
    
    # Early stopping
    if val_loss < best_val_loss:
        best_val_loss = val_loss
        epochs_no_improve = 0
        best_model_state = model.state_dict().copy()
        marker = "✅ Best"
    else:
        epochs_no_improve += 1
        marker = ""
    
    # Виведення прогресу кожні 10 епох
    if (epoch + 1) % 10 == 0 or epoch == 0:
        print(f"Epoch {epoch+1:3d}/{num_epochs} | "
              f"Train Loss: {train_loss:.4f} | Train Acc: {train_acc:.3f} | "
              f"Val Loss: {val_loss:.4f} | Val Acc: {val_acc:.3f} | Val AUC: {val_auc:.3f} {marker}")
    
    # Зупинка при перенавчанні
    if epochs_no_improve >= patience:
        print(f"\n⚠️ Early stopping на епосі {epoch+1}")
        print(f"   Валідаційна loss не покращувалася {patience} епох.")
        print(f"   Найкраща val_loss: {best_val_loss:.4f} на епосі {epoch+1-patience}")
        break

# Відновлення найкращої моделі
model.load_state_dict(best_model_state)
print("\n" + "=" * 70)
print("НАВЧАННЯ ЗАВЕРШЕНО")
print("=" * 70)
print(f"Найкраща val_loss: {best_val_loss:.4f}")
```

**False Negative (FN) — найнебезпечніший тип помилки в медицині:**
- Модель каже «здоровий», насправді пацієнт хворий
- Пацієнт не отримує лікування → прогресування хвороби → можливий інфаркт
- У нашій моделі FN = 2 з 21 хворого (9.5%) — прийнятний, але не ідеальний рівень

**False Positive (FP) — менш критична помилка:**
- Модель каже «хворий», насправді пацієнт здоровий
- Пацієнт проходить додаткове обстеження (стрес-тест, ЕКГ, можливо ангіографію)
- Психологічний стрес, але **життю не загрожує**

**Баланс у медицині:** часто налаштовують поріг прийняття рішення не 0.5, а 0.3–0.4, щоб **знизити FN за рахунок збільшення FP**. Краще зайвий раз перевірити здорову людину, ніж пропустити хвору.
::

```python
def predict_patient(model, scaler, patient_data, device):
    """
    Передбачення для одного пацієнта.
    
    Args:
        model: навчена модель PyTorch
        scaler: fitted StandardScaler
        patient_data: масив із 13 клінічними ознаками
        device: CPU або GPU
    
    Returns:
        Ймовірність хвороби (0–1)
    """
    model.eval()
    with torch.no_grad():
        # Масштабування
        patient_scaled = scaler.transform([patient_data])
        patient_tensor = torch.FloatTensor(patient_scaled).to(device)
        
        # Передбачення
        prob = model(patient_tensor).item()
    
    return prob

    3.5,  # oldpeak: сильна депресія ST (3.5 мм)
```

```python
# Навчання (скорочена версія — основний код аналогічний Heart Disease)
num_epochs = 150
patience = 20
best_val_loss = float('inf')
epochs_no_improve = 0

history = {'train_loss': [], 'val_loss': [], 'val_acc': [], 'val_auc': []}

print("Навчання моделі...\n")

for epoch in range(num_epochs):
    # Train
    model.train()
    train_loss = 0.0
    for X_batch, y_batch in train_loader:
        optimizer.zero_grad()
        outputs = model(X_batch)
        loss = criterion(outputs, y_batch)
        loss.backward()
        optimizer.step()
        train_loss += loss.item() * X_batch.size(0)
    
    train_loss /= len(train_loader.dataset)
    
    # Validation
    model.eval()
    val_loss = 0.0
    all_preds, all_probs, all_labels = [], [], []
    with torch.no_grad():
        for X_batch, y_batch in val_loader:
            outputs = model(X_batch)
            loss = criterion(outputs, y_batch)
            val_loss += loss.item() * X_batch.size(0)
            all_preds.extend((outputs >= 0.5).float().numpy())
            all_probs.extend(outputs.numpy())
            all_labels.extend(y_batch.numpy())
    
    val_loss /= len(val_loader.dataset)
    val_acc = accuracy_score(all_labels, all_preds)
    val_auc = roc_auc_score(all_labels, all_probs)
    
    history['train_loss'].append(train_loss)
    history['val_loss'].append(val_loss)
    history['val_acc'].append(val_acc)
    history['val_auc'].append(val_auc)
    
    # Early stopping
    if val_loss < best_val_loss:
        best_val_loss = val_loss
        epochs_no_improve = 0
        best_model_state = model.state_dict().copy()
        marker = "✅"
    else:
        epochs_no_improve += 1
        marker = ""
    
    if (epoch + 1) % 20 == 0 or epoch == 0:
        print(f"Epoch {epoch+1:3d} | Train: {train_loss:.4f} | Val: {val_loss:.4f} | Acc: {val_acc:.3f} | AUC: {val_auc:.3f} {marker}")
    
    if epochs_no_improve >= patience:
        print(f"\nEarly stopping на епосі {epoch+1}")
        break

model.load_state_dict(best_model_state)
print(f"\nНавчання завершено. Найкраща val_loss: {best_val_loss:.4f}")
```

**Етичні міркування AI у освіті:**

**Переваги:**
- ✅ Рання ідентифікація студентів у групі ризику
- ✅ Об'єктивна оцінка (не залежить від суб'єктивності вчителя)
- ✅ Масштабованість (можна аналізувати тисячі студентів щоденно)

**Ризики:**
- ⚠️ **Self-fulfilling prophecy:** якщо вчитель дізнається, що студент "у групі ризику", може підсвідомо приділяти йому менше уваги
- ⚠️ **Приватність:** хто має доступ до передбачень моделі?
- ⚠️ **Дискримінація:** якщо модель базується на соціально-економічних ознаках (освіта батьків, адреса), вона може увічнювати нерівність

**Рекомендації:**
1. Використовувати AI як **інструмент підтримки**, а не заміну вчителя
2. Передбачення мають бути **конфіденційними** (лише класний керівник + психолог)
3. Фокус на **позитивній інтервенції** (допомога, а не стигматизація)
4. Регулярний аудит моделі на предмет bias (дискримінація за статтю, етнічністю, соціальним статусом)

## Резюме ключових концепцій

::card-group

::card{title="Функції активації" icon="i-lucide-zap"}

- **Sigmoid:** лише для вихідного шару (бінарна класифікація)
- **Tanh:** RNN, неглибокі мережі
- **ReLU:** за замовчуванням для прихованих шарів (градієнт = 1 для z > 0)
- **Leaky ReLU:** якщо виникають мертві нейрони

::

::card{title="Попередня обробка даних" icon="i-lucide-database"}

- **StandardScaler:** обов'язково для нейронних мереж
- **Train/Val/Test split:** 70/15/15 зі stratify для балансу класів
- **Обережно з data leakage:** scaler.fit лише на train!

::

::card{title="Архітектура MLP" icon="i-lucide-layers"}

- Звужуюча структура: 64 → 32 → 1 (bottleneck)
- Dropout після кожного прихованого шару
- Sigmoid на виході для ймовірності

::

::card{title="Навчання та регуляризація" icon="i-lucide-trending-up"}

- **Optimizer:** Adam (lr=0.001)
- **Loss:** Binary Cross-Entropy
- **Early stopping:** patience=20 епох
- Dropout (30%, 20%) запобігає перенавчанню

::

::card{title="Оцінка якості" icon="i-lucide-bar-chart"}

- **AUC-ROC:** головна метрика (0.921 — відмінно!)
