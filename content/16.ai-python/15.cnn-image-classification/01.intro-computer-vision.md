# Вступ до комп'ютерного зору та проблеми Dense-мережі

::card-group

::card{title="🎯 Мета лекції" icon="i-lucide-target"}

- Зрозуміти, чому звичайні Dense-мережі неефективні для зображень
- Навчитися представляти зображення як тензори (багатовимірні масиви)
- Усвідомити проблему розмірності для зображень великого розміру
- Зрозуміти поняття локальності ознак у зображеннях

::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Dense-шар (повнозв'язний шар, Fully Connected):** шар, де кожен нейрон з'єднаний з кожним входом (у PyTorch — `nn.Linear`)
- **Тензор (Tensor):** багатовимірний масив чисел (1D — вектор, 2D — матриця, 3D — куб даних)
- **Канали зображення (Channels):** окремі компоненти кольору (1 для чорно-білого, 3 для RGB)
- **Локальність ознак (Spatial Locality):** ідея, що сусідні пікселі пов'язані між собою сильніше, ніж далекі
- **Інваріантність до зсуву (Translation Invariance):** здатність розпізнавати об'єкт незалежно від його позиції на зображенні

::

::

## Задача, яка мотивує

Уявіть, що ви хочете навчити комп'ютер розпізнавати рукописні цифри від 0 до 9. У вас є тисячі прикладів зображень розміром 28×28 пікселів, кожне зображення чорно-біле (тільки відтінки сірого).

**Перша ідея:** використати звичайну нейронну мережу з Модуля 4 і просто «розгорнути» зображення у вектор та подати на вхід.

::note
**Що означає слово «Dense».** У Модулі 4 ми будували мережі з шарів, де **кожен нейрон з'єднаний з кожним числом на вході**. Такі шари називають **повнозв'язними** (*fully connected*), а в бібліотеках і літературі їх часто називають **Dense-шарами** (англ. *dense* — «щільний»: зв'язків «щільно» — усі з усіма). У PyTorch це `nn.Linear`, у Keras — `Dense`. Далі в модулі ми скорочено говоритимемо «Dense-мережа», маючи на увазі саме такі мережі з Модуля 4 (MLP).
::

Але виникає декілька критичних проблем.

## Як комп'ютер бачить зображення

### Як зображення зберігається в пам'яті

Зображення — це **двовимірна сітка пікселів**. Кожен піксель має значення інтенсивності (для чорно-білого) або кілька значень (для кольорового).

### Справжня цифра: як виглядає «сімка» для комп'ютера

Сітка 5×5 з нулів і 255 — це іграшка. Подивимося на справжнє зображення з датасету **MNIST** — 70 000 рукописних цифр, на яких ми навчатимемо мережу в кінці модуля. Візьмемо одну з них і вивеземо не картинку, а те, що бачить програма, — числа.

::jupyter-notebook{title="mnist_digit_as_numbers.ipynb" kernel="Python 3.11"}

::jupyter-cell{executionCount="1"}

```python
from torchvision import datasets

mnist = datasets.MNIST(root="data", train=True, download=True)

image = mnist.data[101]      # тензор 28×28, значення 0…255
label = mnist.targets[101]   # правильна відповідь

print("Мітка:", label.item())
print("Форма:", tuple(image.shape), "| тип:", image.dtype)
print("Мінімум / максимум:", image.min().item(), "/", image.max().item())
print("\nФрагмент: рядки 8–10, стовпці 6–19")
print(image[8:11, 6:20])
```

### Форма тензора зображення

Зображення представляється як **тензор** з трьома вимірами: **(висота, ширина, канали)**.

| Тип зображення | Розміри тензора        | Приклад                  |
| :------------- | :--------------------- | :----------------------- |
| Чорно-біле     | `(height, width, 1)`   | `(28, 28, 1)` для MNIST  |
| RGB кольорове  | `(height, width, 3)`   | `(224, 224, 3)` для ImageNet |
| RGBA (з прозорістю) | `(height, width, 4)` | `(512, 512, 4)` для PNG з alpha-каналом |

Подивимося на це не на іграшкових квадратах, а на справжньому фото. У бібліотеці scikit-learn (яку ми використовували в Модулі 3) є кілька фотографій для експериментів. Візьмемо одну з них і витягнемо крихітну ділянку 4×4 пікселі з краю пелюстки.

::jupyter-notebook{title="rgb_representation.ipynb" executionCount="2"}

```python
from sklearn.datasets import load_sample_image

photo = load_sample_image("flower.jpg")
print("Форма фото:", photo.shape, "| тип:", photo.dtype)

# Ділянка 4×4 пікселі з краю пелюстки
patch = photo[222:226, 444:448]
print("Форма ділянки:", patch.shape)
print("Піксель (0, 0):", patch[0, 0], "→ [R, G, B]")
print("\nКанал R (червоний):")
print(patch[:, :, 0])
```

#output
```

Форма ділянки: (4, 4, 3)
Піксель (0, 0): [229 188 132] → [R, G, B]

Канал R (червоний):
[[229 207  86  12]
 [235 203  81  11]
 [231 192  77   2]
 [230 173  53   2]]
```

Фото має форму `(427, 640, 3)`: 427 рядків, 640 стовпців і 3 числа на кожен піксель. А наша ділянка — `(4, 4, 3)`, тобто **48 чисел** (4 · 4 · 3). Один піксель — це три числа `[R, G, B]`: скільки в ньому червоного, зеленого і синього. Якщо взяти з усіх пікселів лише перше число, вийде **канал R** — звичайна таблиця 4×4, така сама, як чорно-біле зображення. Таких таблиць три, і разом вони утворюють кольорову картинку.

## Проблема 1: Катастрофічне зростання кількості параметрів

Коли ми подаємо зображення на вхід Dense-мережі, нам потрібно **розгорнути** двовимірну (або тривимірну) структуру у **одновимірний вектор**.

### Приклад: MNIST (28×28 пікселів, чорно-біле)

::jupyter-notebook{title="mnist_flattening.ipynb" executionCount="3"}

```python
# Розмір зображення MNIST
height, width = 28, 28
channels = 1  # чорно-біле

# Кількість вхідних нейронів
input_size = height * width * channels
print(f"Розмір зображення: {height}×{width}×{channels}")
print(f"Кількість вхідних нейронів: {input_size}")

# Припустимо, перший прихований шар має 128 нейронів
hidden_size = 128
weights_count = input_size * hidden_size
print(f"\nКількість ваг між вхідним шаром та першим прихованим шаром:")
print(f"{input_size} × {hidden_size} = {weights_count:,} параметрів")
```

#output
```
Розмір зображення: 28×28×1
Кількість вхідних нейронів: 784

Кількість ваг між вхідним шаром та першим прихованим шаром:
784 × 128 = 100,352 параметрів
```
::

::tip
Для невеликих зображень MNIST (28×28) Dense-мережа ще може працювати. Але що станеться з великими зображеннями?
::

### Приклад: ImageNet (224×224 пікселів, RGB)

::jupyter-notebook{title="imagenet_flattening.ipynb" executionCount="4"}

```python
# Розмір зображення ImageNet
height, width = 224, 224
channels = 3  # RGB

# Кількість вхідних нейронів
input_size = height * width * channels
print(f"Розмір зображення: {height}×{width}×{channels}")
print(f"Кількість вхідних нейронів: {input_size:,}")

# Перший прихований шар з 512 нейронів
hidden_size = 512
weights_count = input_size * hidden_size
weights_mb = (weights_count * 4) / (1024 * 1024)  # 4 байти на float32

print(f"\nКількість ваг між вхідним шаром та першим прихованим шаром:")
print(f"{input_size:,} × {hidden_size} = {weights_count:,} параметрів")
print(f"Обсяг пам'яті (float32): {weights_mb:.1f} МБ")
```

#output
```
Розмір зображення: 224×224×3
Кількість вхідних нейронів: 150,528

Кількість ваг між вхідним шаром та першим прихованим шаром:
150,528 × 512 = 77,070,336 параметрів
Обсяг пам'яті (float32): 294.0 МБ
```
::

::warning
**77 мільйонів параметрів** тільки у **першому** шарі! Це призводить до:
- Величезного обсягу пам'яті (GPU швидко закінчиться)
- Повільного навчання (дуже багато обчислень)
- Високого ризику перенавчання (overfitting) — модель просто запам'ятає всі зображення
::

## Проблема 2: Втрата просторової структури

Коли ми розгортаємо зображення у вектор, **втрачається інформація про сусідство пікселів**.

### Локальність ознак

У зображеннях **сусідні пікселі пов'язані між собою**. Наприклад:
- Край об'єкта формується групою сусідніх пікселів з різкою зміною яскравості
- Текстура (хутро кота, дерево тканини) — це повторювані локальні патерни
- Око, ніс, вухо тварини — це **локальні структури**

Dense-мережа **не знає**, що піксель `(10, 10)` знаходиться поруч з пікселем `(10, 11)`. Для неї це просто два числа у векторі на позиціях `280` та `281` (для зображення 28×28).

## Проблема 3: Відсутність інваріантності до зсуву

Dense-мережа **не розуміє**, що об'єкт залишається тим самим об'єктом, якщо його зсунути на кілька пікселів.

### Приклад: цифра «3» у різних позиціях

Уявіть, що ми навчили Dense-мережу розпізнавати цифру «3», коли вона розташована **у центрі** зображення 28×28. Якщо ця ж цифра з'явиться **зміщеною на 5 пікселів вправо**, для Dense-мережі це **абсолютно інший вхідний вектор**.

Перевіримо це на справжній цифрі «3» з MNIST: зсунемо її на 5 пікселів вправо і порівняємо розгорнуті вектори.

::jupyter-notebook{title="translation_problem.ipynb" executionCount="5"}

```python
import numpy as np
from torchvision import datasets

mnist = datasets.MNIST(root="data", train=True, download=True)

image = mnist.data[12].numpy()        # цифра «3», 28×28
shifted = np.roll(image, 5, axis=1)   # та сама цифра, зсунута на 5 пікселів вправо

bright = image > 128                  # «яскраві» пікселі (штрих ручки)
bright_shifted = shifted > 128
same = (bright & bright_shifted).sum()

print("Мітка:", mnist.targets[12].item())
print("Яскравих пікселів у цифри:", bright.sum())
print(f"З них на тих самих позиціях вектора: {same} ({same / bright.sum():.0%})")

changed = (image.flatten() != shifted.flatten()).sum()
print(f"Позицій вектора, де значення змінилось: {changed} із {image.size}")
```

#output
```
Мітка: 3
Яскравих пікселів у цифри: 144
З них на тих самих позиціях вектора: 47 (33%)
Позицій вектора, де значення змінилось: 300 із 784
```
::

Розберемо результат. Для нас це **та сама цифра**, лише посунута вбік. А для Dense-мережі це майже інший вхід: із 144 яскравих пікселів лише 47 (третина) лежать на тих самих позиціях вектора, а значення змінилися на 300 із 784 позицій. Ваги, які мережа навчилася пов'язувати зі штрихами «3» в центрі, тепер стоять проти чорного фону, а нові штрихи потрапили на ваги, які ніколи їх не бачили.

## Що потрібно для роботи з зображеннями?

Підсумуємо проблеми Dense-мереж при роботі зі зображеннями:

::card-group

::card{title="❌ Проблема 1" icon="i-lucide-alert-triangle"}
**Величезна кількість параметрів**
Для зображень 224×224 у першому шарі — десятки мільйонів ваг
::

::card{title="❌ Проблема 2" icon="i-lucide-alert-triangle"}
**Втрата просторової структури**
Розгортання у вектор знищує інформацію про сусідство пікселів
::

::card{title="❌ Проблема 3" icon="i-lucide-alert-triangle"}
**Відсутність інваріантності**
Зсув об'єкта на кілька пікселів — це "новий" об'єкт для мережі
::

::

### Що ми не можемо собі дозволити

Подивимося на три проблеми разом. Усі вони виникають від одного: Dense-шар вважає кожен піксель окремою, ні з чим не пов'язаною ознакою і для кожного пікселя тримає власні ваги. Це як вчити людину впізнавати друга, показуючи їй не обличчя, а 784 окремі точки, перемішані в довільному порядку.

Зверніть увагу, що вирішувати ці проблеми «грубою силою» — більшою мережею чи більшим датасетом — безглуздо. Більша мережа означає ще більше параметрів, а більший датасет означає, що ми змушені показувати цифру у всіх можливих місцях. Тож потрібна принципово інша ідея.

Сформулюємо її як запитання, на яке дамо відповідь у наступній лекції:

::callout{icon="i-lucide-lightbulb" color="primary"}
**Чи можна навчити мережу шукати, наприклад, вертикальну риску в одному маленькому місці — і потім використовувати цей самий «детектор» в усіх інших місцях зображення?**
::

Якщо так, то нам не треба ні мільйонів ваг (детектор маленький), ні окремого навчання для кожної позиції (детектор той самий). І сусідні пікселі детектор бачитиме разом, як вони й лежать на картинці.

## Резюме

::card-group

::card{title="📌 Зображення як тензор" icon="i-lucide-layers"}
Зображення — це багатовимірний масив: `(висота, ширина, канали)`. Чорно-біле: 1 канал, RGB: 3 канали.
::

::card{title="📌 Проблема розмірності" icon="i-lucide-alert-circle"}
Для зображень 224×224×3 вхідний шар Dense-мережі має 150 528 нейронів. Перший прихований шар потребує десятків мільйонів параметрів.
::

::card{title="📌 Локальність ознак" icon="i-lucide-focus"}
Сусідні пікселі пов'язані між собою. Dense-мережа це ігнорує, розгортаючи зображення у вектор.
::

::card{title="📌 Інваріантність до зсуву" icon="i-lucide-move"}
Об'єкт залишається тим самим, якщо його зсунути. Dense-мережа цього не розуміє — потрібні тисячі прикладів для навчання.
::

::

---

**У наступній лекції** ми не просто покажемо готову формулу, а виведемо її самі: почнемо з одного нейрона-детектора, зламаємо його зсувом зображення і побачимо, що єдине розумне виправлення — це операція **згортки (convolution)**.
