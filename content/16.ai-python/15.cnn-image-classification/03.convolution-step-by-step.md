# Згортка крок за кроком

::card-group

::card{title="🎯 Мета лекції" icon="i-lucide-target"}

- Виконати згортку вручну на маленькому прикладі й отримати кожне число карти ознак самостійно
- Зрозуміти, що таке ядро, карта ознак і поле зору (receptive field)
- Вивести розмір результату :math-formula{tex="H - K + 1" inline} із простих міркувань
- Написати згортку на NumPy з нуля й перевірити її готовою функцією зі `scipy`

::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Ядро / фільтр (Kernel / Filter):** маленька таблиця ваг, яка ковзає по зображенню
- **Карта ознак (Feature Map):** таблиця результатів — по одному числу на кожну позицію ядра
- **Поле зору (Receptive Field):** ділянка входу, від якої залежить одне число карти ознак
- **Крос-кореляція (Cross-correlation):** точна назва того, що в бібліотеках глибокого навчання називають згорткою

::

::

## Від ідеї до механіки

У попередній лекції ми самі вивели ідею: один маленький детектор із ваг `[-1, 1, -1]` ковзає по картинці, а в кожній позиції ми множимо ділянку на ваги, додаємо добутки й записуємо результат у таблицю. Ми отримали карту відгуків і переконалися, що вона «знає», де стоїть штрих. Тоді нам було достатньо інтуїції.

Тепер зробимо те саме повільно й акуратно, щоб жодне число не залишилося «магією». Для цього нам потрібні чіткі домовленості: як позначати позиції, як рахувати кожне число й скільки чисел узагалі вийде. Після цієї лекції ви зможете виконати згортку на папері для будь-якого маленького прикладу й написати її в коді.

---

## Умови прикладу

Беремо ті самі ваги детектора, що й раніше, а картинку робимо трохи «живішою»: уже не просто нулі й одиниці, а яскравості від 0 до 5, і штрих не ідеально рівний. Так результат буде схожий на справжні дані.

![Вхід 5×5, ядро 3×3 та порожня карта ознак 3×3](/images/ai-python/cnn-image-classification/convolution-step-by-step/01.png){.diagram-img}

Домовимося про позначення, бо ми користуватимемося ними далі в усьому модулі:

- **Вхід** `I` (від *Input*) — таблиця 5×5. Елемент `I[i, j]` — це піксель у рядку `i` та стовпці `j`. Рахуємо з нуля, як у NumPy, а початок координат — лівий верхній кут.
- **Ядро** `K` (від *Kernel*) — таблиця 3×3 із вагами. У нашому прикладі це знайомий вертикальний детектор: `-1, 1, -1` у кожному рядку.
- **Карта ознак** `O` (від *Output*) — таблиця результатів. Поки що ми не знаємо її розміру, на малюнку праворуч показано 3×3, а чому саме так — з'ясуємо нижче.
- **Позиція ядра** `(i, j)` — це місце, де лежить **лівий верхній кут** ядра. Позиція `(0, 0)` означає, що ядро накриває рядки 0–2 та стовпці 0–2.

::note
Слова «ядро» (*kernel*) і «фільтр» (*filter*) у літературі означають те саме. Ми користуватимемося обома: «ядро» — коли говоримо про таблицю ваг, «фільтр» — коли говоримо про те, що вона робить із зображенням.
::

---

## Формула одного числа

Кожне число карти ознак `O[i, j]` рахується за однією й тією самою схемою: беремо ділянку входу 3×3, що починається в позиції `(i, j)`, множимо її елемент на елемент на ядро і додаємо всі дев'ять добутків. Запишемо це формулою:

::math-formula{tex="O[i, j] = \sum_{u=0}^{2} \sum_{v=0}^{2} I[i + u,\; j + v] \cdot K[u, v]"}
::

Не лякайтеся символу :math-formula{tex="\sum" inline} — це просто «додати все разом». Індекси `u` і `v` пробігають по ядру: `u` — по його рядках (0, 1, 2), `v` — по стовпцях (0, 1, 2). Вираз `I[i + u, j + v]` вибирає піксель входу, що лежить під елементом `K[u, v]`. Тобто формула каже: «для кожного з дев'яти елементів ядра візьми піксель під ним, помнож на вагу й додай до суми».

У NumPy це записується одним рядком, який ми використаємо весь модуль:

```python
O[i, j] = (I[i:i+3, j:j+3] * K).sum()
```

Зріз `I[i:i+3, j:j+3]` вирізає ділянку 3×3, знак `*` перемножує таблиці елемент на елемент (так звані *поелементні добутки*, ми бачили їх у модулі про тензори), а `.sum()` додає все.

## Крок 1. Ядро в позиції (0, 0)

Покладемо ядро на лівий верхній кут: його лівий верхній кут збігається з пікселем `I[0, 0]`. Ядро накриває рядки 0–2 та стовпці 0–2. Подивимося, що відбувається, у три дії.

![Згортка в позиції (0, 0): ділянка під ядром, ядро, поелементний добуток і сума −14](/images/ai-python/cnn-image-classification/convolution-step-by-step/02.png){.diagram-img}

::steps

### Вирізаємо ділянку під ядром
Беремо 9 пікселів, що лежать під ядром: це перші три рядки та перші три стовпці входу.

### Множимо елемент на елемент
Кожен піксель множимо на вагу, що лежить над ним. Верхній лівий: `0 · (−1) = 0`. Верхній середній: `1 · 1 = +1`. Верхній правий: `5 · (−1) = −5`. Так для всіх дев'яти клітинок.

### Додаємо всі добутки
`0 + 1 − 5 + 0 + 0 − 5 − 1 + 0 − 4 = −14`. Це число й стане першим елементом карти ознак `O[0, 0]`.

::

Перевіримо ручний розрахунок кодом. Спочатку створимо вхід і ядро, а потім виконаємо ті самі три дії.

::jupyter-notebook{title="convolution_step_by_step.ipynb" kernel="Python 3.11"}

::jupyter-cell{executionCount="1"}

```python
import numpy as np

I = np.array([
    [0, 1, 5, 0, 0],
    [0, 0, 5, 1, 0],
    [1, 0, 4, 0, 0],
    [0, 0, 5, 0, 1],
    [0, 1, 5, 0, 0],
])
K = np.array([
    [-1, 1, -1],
    [-1, 1, -1],
    [-1, 1, -1],
])

patch = I[0:3, 0:3]   # дія 1: ділянка під ядром
product = patch * K   # дія 2: добутки елемент на елемент
total = product.sum() # дія 3: сума

print("Ділянка:\n", patch)
print("\nДобутки:\n", product)
print("\nСума:", total)
```

#output
```
Ділянка:
 [[0 1 5]
 [0 0 5]
 [1 0 4]]

Добутки:
 [[ 0  1 -5]
 [ 0  0 -5]
 [-1  0 -4]]

Сума: -14
```
::

::

Код збігся з нашим ручним розрахунком: `−14`. Зверніть увагу на сенс цього числа: воно **дуже від'ємне**. Дивимося на ділянку: штрих (яскраві числа 5) лежить у її **правому** стовпці, тобто там, де вага `−1`. Ядро шукає штрих по центру, а тут він збоку, і ядро «протестує» сильним мінусом. Саме так, як ми бачили в попередній лекції.

## Крок 2. Зсуваємо ядро на один піксель вправо

Перше число готове. Тепер посунемо ядро на **один піксель** вправо: його лівий верхній кут стає в позицію `(0, 1)`. Тепер ядро накриває стовпці 1–3 (рядки ті самі — 0–2). Усе інше без змін: вирізаємо ділянку, множимо, додаємо.

![Згортка в позиції (0, 1): ядро зсунулося на один піксель вправо, сума +12](/images/ai-python/cnn-image-classification/convolution-step-by-step/03.png){.diagram-img}

Цього разу яскравий штрих (п'ятірки) потрапив у **середній** стовпець ділянки — саме туди, де ядро має вагу `+1`. Тому три «п'ятірки» дають `+5`, `+5`, `+4` у середньому стовпці, а по боках майже нічого не віднімається. Сума: `−1 + 5 + 0 + 0 + 5 − 1 + 0 + 4 + 0 = +12`.

::jupyter-notebook{title="second_position.ipynb" kernel="Python 3.11"}

::jupyter-cell{executionCount="2"}

```python
patch = I[0:3, 1:4]   # зсунули зріз на один стовпець вправо
print("Ділянка:\n", patch)
print("\nСума:", (patch * K).sum())
```

#output
```
Ділянка:
 [[1 5 0]
 [0 5 1]
 [0 4 0]]

Сума: 12
```
::

::

Порівняйте два результати. Для **тієї самої картинки** й **тих самих ваг** ми отримали `−14` і `+12`, бо різні ділянки картинки мають різну схожість на шаблон. Різниця між числами — це і є вся «інформація» карти ознак: вона розповідає, де шаблон збігся, а де ні.

::note
**А чому ядро зсувається саме на один піксель?** Це наш вибір, і він не єдиний. Можна зсуватися на 2 або 3 пікселі, тоді результат буде меншим і грубішим. Крок зсуву називають *stride* (англ. «крок»), і ми обговоримо його в окремій лекції. Поки що завжди рухаємося по одному пікселю.
::

## Крок 3. Проходимо всі позиції

Для кожної позиції відео показує три дії: ядро лягає на ділянку, виписуються добутки з сумою, сума потрапляє в карту ознак. Нічого нового, лише повторення вже знайомого. Запишемо цей обхід у коді двома вкладеними циклами:

::jupyter-notebook{title="all_positions.ipynb" kernel="Python 3.11"}

::jupyter-cell{executionCount="3"}

```python
O = np.zeros((3, 3), dtype=int)

for i in range(3):          # позиція ядра по рядках
    for j in range(3):      # позиція ядра по стовпцях
        O[i, j] = (I[i:i+3, j:j+3] * K).sum()

print(O)
```

#output
```
[[-14  12 -13]
 [-15  13 -14]
 [-14  13 -15]]
```
::

::

Дев'ять позицій — дев'ять чисел, які складаються в таблицю 3×3. Це і є **карта ознак**.

![Вхід, ядро та готова карта ознак: у середньому стовпці — додатні значення](/images/ai-python/cnn-image-classification/convolution-step-by-step/04.png){.diagram-img}

Прочитаємо результат, як вчилися в минулій лекції. Середній стовпець карти — це `+12`, `+13`, `+13`: усі додатні й найбільші. Саме там ядро накрило штрих центром. Лівий і правий стовпці — глибоко від'ємні (`−13 … −15`): там штрих лежить збоку від центру ядра. Карта ознак цілком «вказує» на положення вертикального штриха у вихідній картинці.

::tip
Подивіться на карту ознак як на **нове зображення**. Воно менше за вхідне (3×3 проти 5×5), але у ньому записано не яскравість пікселів, а відповідь на запитання «наскільки тут схоже на мій шаблон?». Саме тому на наступних шарах мережа працюватиме вже не з пікселями, а з такими картами.
::

Тепер напрошується запитання, яке ми поки що тільки відчули: чому вийшла таблиця саме **3×3**, а не 5×5? Це не випадковість, і зараз ми це виведемо.

## Скільки чисел вийде: розмір карти ознак

Нам потрібно зрозуміти, чому з входу 5×5 і ядра 3×3 вийшла карта 3×3. Рядки й стовпці тут працюють незалежно, тому достатньо розібратися з **однією віссю**, наприклад зі стовпцями.

Нехай вхід має ширину `H`, а ядро — ширину `K`. Позиція ядра `p` означає, що воно накриває стовпці від `p` до `p + K − 1`. Перша можлива позиція — `p = 0` (лівий край картинки). Ядро має повністю лежати на картинці, тому його правий край `p + K − 1` не може бути далі за останній стовпець `H − 1`. Звідси:

::math-formula{tex="p + K - 1 \le H - 1 \quad\Longrightarrow\quad p \le H - K"}
::

Позиції `p` — це цілі числа від `0` до `H − K` включно. Скільки їх? Від нуля до `H − K` лежить `H − K` кроків, а разом із нульовою позицією — на одиницю більше:

::math-formula{tex="W_{\text{out}} = H - K + 1"}
::

![Три позиції ядра шириною 3 на вході шириною 5: 5 − 3 + 1 = 3](/images/ai-python/cnn-image-classification/convolution-step-by-step/05.png){.diagram-img}

Перевіримо на нашому прикладі: :math-formula{tex="5 - 3 + 1 = 3" inline} позиції вздовж кожної осі, тобто :math-formula{tex="3 \times 3" inline} чисел. Збігається. Відео нижче показує, як кількість позицій змінюється зі збільшенням входу.

Для прямокутного входу і ядра формула діє окремо по кожній осі: вихід має розмір :math-formula{tex="(H - K_h + 1) \times (W - K_w + 1)" inline}. Для квадратних зображень і ядер вона зводиться до однієї. Порахуємо кілька випадків кодом, включно з реальним розміром MNIST.

::jupyter-notebook{title="output_size.ipynb" kernel="Python 3.11"}

::jupyter-cell{executionCount="4"}

```python
def output_size(h, w, k):
    """Розмір карти ознак для входу h×w і квадратного ядра k×k."""
    return h - k + 1, w - k + 1

print("5×5,   ядро 3×3:", output_size(5, 5, 3))
print("28×28, ядро 3×3:", output_size(28, 28, 3))
print("28×28, ядро 5×5:", output_size(28, 28, 5))

# Що буде, якщо застосовувати згортки 3×3 одну за одною?
size = 28
for layer in range(1, 4):
    size, _ = output_size(size, size, 3)
    print(f"після згортки №{layer}: {size}×{size}")
```

#output
```
5×5,   ядро 3×3: (3, 3)
28×28, ядро 3×3: (26, 26)
28×28, ядро 5×5: (24, 24)
після згортки №1: 26×26
після згортки №2: 24×24
після згортки №3: 22×22
```

::::accordion

:::accordion-item{label="❓ А що, якщо ядро більше за картинку?" icon="i-lucide-help-circle"}

Тоді `H − K + 1` стає нулем або від'ємним числом: жодної позиції, де ядро повністю лежить на картинці, немає, і карти ознак не існує. У бібліотеках це закінчується помилкою про некоректний розмір. Ядро має бути не більшим за вхід.

:::

:::accordion-item{label="❓ А що буде з ядром 1×1?" icon="i-lucide-help-circle"}

Формула дає `H − 1 + 1 = H`: розмір не змінюється. Ядро 1×1 — це одна вага, яка множить кожен піксель окремо. Ми повернемося до нього, коли говоритимемо про кольорові зображення.

:::

:::accordion-item{label="❓ Картинка стає меншою після кожної згортки. Це проблема?" icon="i-lucide-help-circle"}

Так, і ми це вже бачимо в коді вище: після трьох згорток 3×3 зображення 28×28 схудло до 22×22. Кожна згортка «з'їдає» по `K − 1` пікселів по кожній осі. До того ж пікселі на краях потрапляють під ядро значно рідше, ніж центральні. Як цьому зарадити, розберемо в окремій лекції.

:::

## Власна реалізація на NumPy

Ми вже записали обхід двома циклами для конкретного прикладу. Узагальнимо його у функцію, яка працює з будь-яким входом і ядром, і перевіримо її, порівнявши з готовою функцією з бібліотеки `scipy`.

::jupyter-notebook{title="conv2d_from_scratch.ipynb" kernel="Python 3.11"}

::jupyter-cell{executionCount="5"}

```python
def conv2d(image, kernel):
    """Згортка одноканального зображення з ядром (без доповнення країв, крок 1)."""
    h, w = image.shape
    kh, kw = kernel.shape
    out = np.zeros((h - kh + 1, w - kw + 1), dtype=image.dtype)

    for i in range(out.shape[0]):
        for j in range(out.shape[1]):
            out[i, j] = (image[i:i + kh, j:j + kw] * kernel).sum()
    return out

O = conv2d(I, K)
print(O)
```

#output
```
[[-14  12 -13]
 [-15  13 -14]
 [-14  13 -15]]
```

::jupyter-notebook{title="check_with_scipy.ipynb" executionCount="6"}

```python
from scipy.signal import correlate2d

reference = correlate2d(I, K, mode="valid")
print("Збігається зі scipy:", np.array_equal(O, reference))
```

#output
```

```

Параметр `mode="valid"` означає «лише ті позиції, де ядро повністю на картинці», тобто саме те, що рахує наша функція. Результати збіглися до останнього числа, отже функція працює правильно.

Цикли на Python для великих зображень повільні. Те саме можна зробити без циклів: `sliding_window_view` нарізає вхід на всі ділянки одразу, а потім один раз множить і додає.

::jupyter-notebook{title="vectorized_conv.ipynb" executionCount="7"}

```python
from numpy.lib.stride_tricks import sliding_window_view

windows = sliding_window_view(I, (3, 3))      # всі ділянки 3×3 одразу
print("Форма масиву ділянок:", windows.shape)

fast = (windows * K).sum(axis=(2, 3))         # множимо й додаємо по осях ділянки
print("Збігається з циклами:", np.array_equal(fast, O))
```

#output
```
Форма масиву ділянок: (3, 3, 3, 3)
Збігається з циклами: True
```
::

Форма `(3, 3, 3, 3)` читається так: перші дві цифри — позиція ядра `(i, j)`, останні дві — розмір ділянки 3×3. Тобто це 9 ділянок, по одній на кожну позицію. Для навчання ми й надалі користуватимемося простою версією з циклами, бо вона найкраще показує, що відбувається. Реальні бібліотеки, включно з PyTorch, використовують швидкі реалізації того самого обчислення.

## Маленька таємниця назви: це не зовсім згортка

У математиці **справжня згортка** (*convolution*) перед множенням перевертає ядро на 180° (читає його «задом наперед»). А те, що ми щойно робили, — без перевертання, — формально називається **крос-кореляцією** (*cross-correlation*). Проте в машинному навчанні (і в `nn.Conv2d` у PyTorch) операцію без перевертання звикли називати згорткою. Так склалося історично, і в цьому немає нічого страшного.

Чому це не заважає? Перевірмо на ядрі, яке *не* симетричне: вертикальному детекторі країв Собеля (його ми докладно розглянемо в наступній лекції). Для нього перевертання змінює результат.

::jupyter-notebook{title="cross_correlation.ipynb" executionCount="8"}

```python
from scipy.signal import convolve2d, correlate2d

K2 = np.array([
    [1, 0, -1],
    [2, 0, -2],
    [1, 0, -1],
])

print("Без перевертання (як у глибокому навчанні):")
print(correlate2d(I, K2, mode="valid"))
print("\nСправжня згортка (ядро перевертається):")
print(convolve2d(I, K2, mode="valid"))

flipped = K2[::-1, ::-1]   # перевернули ядро на 180°
print("\nЗбіг, якщо самим перевернути ядро:",
      np.array_equal(convolve2d(I, flipped, mode="valid"), correlate2d(I, K2, mode="valid")))
```

#output
```
Без перевертання (як у глибокому навчанні):
[[-18  -1  19]
 [-16  -1  17]
 [-18   1  17]]

Справжня згортка (ядро перевертається):
[[ 18   1 -19]
 [ 16   1 -17]
 [ 18  -1 -17]]

Збіг, якщо самим перевернути ядро: True
```
::

Результати різні (для цього ядра — з протилежними знаками), але якщо ядро перевернути самим, вони збігаються. Для нейромережі це не має значення: **ядро навчається**, тож мережа сама знайде потрібні ваги в тому вигляді, в якому вони потрібні. Чи перевертати ядро перед множенням, чи ні — мережа просто навчить собі «перевернуте» чи «неперевернуте» ядро. Тому в курсі ми кажемо «згортка», а в бібліотеках бачимо те, що математики назвали б крос-кореляцією.

## Що «бачить» одне число карти ознак

Подивіться ще раз на карту ознак. Кожне її число залежить **лише від ділянки 3×3** входу, а решту картинки воно «не знає». Ця ділянка називається **полем зору** (*receptive field*) цього числа.

![Клітинка (0, 1) карти ознак залежить лише від ділянки 3×3 входу](/images/ai-python/cnn-image-classification/convolution-step-by-step/06.png){.diagram-img}

На малюнку виділено клітинку `O[0, 1] = +12` і ділянку входу, від якої вона залежить: рядки 0–2, стовпці 1–3. Змінимо піксель поза цією ділянкою, наприклад `I[4, 0]`, — клітинка `O[0, 1]` не зміниться. Змінимо піксель усередині — зміниться. Саме це ми називали **локальними зв'язками** в попередній лекції: кожне число карти ознак пов'язане лише з маленьким сусідством, а не з усією картинкою.

Для одного шару поле зору дорівнює розміру ядра, тобто 3×3. Пізніше, коли ми складемо кілька шарів один за одним, воно зростатиме: другий шар бачитиме через перший ще ширшу область входу. Але про це вже в лекції про об'єднання шарів.

::::accordion

:::accordion-item{label="📋 Завдання 1: порахуйте вручну" icon="i-lucide-clipboard-list"}

Вхід 4×4 і ядро 2×2:

```python
I1 = np.array([[1, 2, 0, 1],
               [0, 1, 3, 0],
               [2, 0, 1, 1],
               [1, 1, 0, 2]])
K1 = np.array([[1,  0],
               [0, -1]])
```

Яким буде розмір карти ознак? Порахуйте вручну значення в позиції `(0, 0)`, а потім усю карту, і перевірте функцією `conv2d`.

:::

:::accordion-item{label="✅ Розв'язок" icon="i-lucide-check-circle"}

Розмір: `4 − 2 + 1 = 3` вздовж кожної осі, тобто 3×3. Значення в позиції `(0, 0)`: ділянка `[[1, 2], [0, 1]]`, ядро має ваги `+1` і `−1` по діагоналі, тому `1·1 + 2·0 + 0·0 + 1·(−1) = 0`.

```python
print(conv2d(I1, K1))
```

```
[[ 0 -1  0]
 [ 0  0  2]
 [ 1  0 -1]]
```

:::

:::accordion-item{label="📋 Завдання 2: скільки згорток вміщується?" icon="i-lucide-clipboard-list"}

Зображення 28×28. Скільки згорток 3×3 поспіль (кожна береться від результату попередньої) можна виконати, поки карта ознак ще існує? Яким буде її розмір наприкінці?

:::

:::accordion-item{label="✅ Розв'язок" icon="i-lucide-check-circle"}

Кожна згортка 3×3 зменшує розмір на 2. Після `n` згорток розмір дорівнює `28 − 2n` і має бути не меншим за 1: `28 − 2n ≥ 1`, тож `n ≤ 13`. Після 13 згорток карта має розмір 2×2; чотирнадцята була б неможливою (розмір 0).

:::

:::accordion-item{label="📋 Завдання 3: горизонтальний детектор" icon="i-lucide-clipboard-list"}

Як без нових ваг шукати **горизонтальний** штрих? Підказка: транспонуйте вхід і ядро (`I.T`, `K.T`). Перевірте, що результат — це транспонована карта ознак.

:::

:::accordion-item{label="✅ Розв'язок" icon="i-lucide-check-circle"}

```python
print(np.array_equal(conv2d(I.T, K.T), conv2d(I, K).T))
```

```
True
```

Транспонована картинка із транспонованим ядром дає транспоновану карту ознак. Ядро `K.T` має додатні ваги в середньому рядку, тобто шукає горизонтальний штрих, і повертає ту саму карту, лише повернуту.

## Резюме

::card-group

::card{title="📌 Формула одного числа" icon="i-lucide-sigma"}
Число карти ознак — це сума поелементних добутків ділянки входу й ядра. У NumPy: `(I[i:i+K, j:j+K] * K).sum()`.
::

::card{title="📌 Ковзання" icon="i-lucide-move-right"}
Ядро проходить усі позиції рядками, зліва направо й зверху вниз, на кожній рахуючи одне число. Усі числа складаються в карту ознак.
::

::card{title="📌 Розмір результату" icon="i-lucide-ruler"}
Вихід має розмір :math-formula{tex="(H - K + 1) \times (W - K + 1)" inline}. Без додаткових заходів карта ознак менша за вхід.
::

::card{title="📌 Поле зору" icon="i-lucide-focus"}
Кожне число карти ознак залежить лише від ділянки входу під ядром. Для одного шару це ділянка розміром із ядро.
::

::card{title="📌 Назва" icon="i-lucide-tag"}
У глибокому навчанні «згорткою» називають крос-кореляцію, тобто без перевертання ядра. Для навчених ядер це не має значення.
::

::
