# Padding і stride

::card-group

::card{title="🎯 Мета лекції" icon="i-lucide-target"}

- Побачити на числах, що звичайна згортка зменшує картинку й «недооцінює» її краї
- Зрозуміти, як рамка з нулів (padding) розв'язує обидві проблеми
- Зрозуміти, навіщо ядру крок зсуву (stride) і що він робить із результатом
- Користуватися загальною формулою розміру результату та перевірити її в PyTorch

::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Доповнення (Padding):** додаткова рамка пікселів навколо входу перед згорткою
- **Нульове доповнення (Zero padding):** рамка складається з нулів
- **Крок (Stride):** на скільки пікселів зсувається ядро між сусідніми позиціями
- **Valid / Same:** згортка без доповнення / згортка, що зберігає розмір

::

## Два питання, які ми відкладали

Ми вже кілька разів натрапляли на дві «незручності» згортки, але щоразу казали: «пізніше».

Перша: **картинка зменшується.** З входу 28×28 ми отримували карту 26×26. Якщо поставити кілька згорток підряд, розмір невпинно скорочується. Друга: **краї картинки лишаються осторонь.** У лекції 02 штрих у крайньому стовпці взагалі не давав максимального відгуку, бо ядро 3×3 не могло накрити його своїм центром.

Зараз ми розберемо обидві проблеми докладно, а потім додамо ще одне налаштування, яке працює «навпаки» — **крок зсуву**, який дозволяє зменшувати картинку навмисно й швидко. Після цієї лекції у нас буде повний набір параметрів однієї згорткової операції.

---

## Проблема 1: карта ознак стає все меншою

Згадаймо формулу з попередніх лекцій: для входу розміром `H` і ядра `K` результат має розмір `H − K + 1`. Для ядра 3×3 це означає, що кожна згортка забирає по **два пікселі** по кожній осі. Подивимося, що буде, якщо складати згортки підряд.

::jupyter-notebook{title="shrinking_maps.ipynb" kernel="Python 3.11"}

::jupyter-cell{executionCount="1"}

```python
import numpy as np
from scipy.signal import correlate2d

def conv(image, kernel):
    return correlate2d(image, kernel, mode="valid")   # звичайна згортка, без доповнення

I = np.array([
    [0, 1, 5, 0, 0],
    [0, 0, 5, 1, 0],
    [1, 0, 4, 0, 0],
    [0, 0, 5, 0, 1],
    [0, 1, 5, 0, 0],
])
K = np.array([[-1, 1, -1]] * 3)

size = 28
print("Вхід:", f"{size}×{size}")
for layer in range(1, 7):
    size = size - 3 + 1
    print(f"після згортки №{layer}: {size}×{size}")
```

#output
```

після згортки №1: 26×26
після згортки №2: 24×24
після згортки №3: 22×22
після згортки №4: 20×20
після згортки №5: 18×18
після згортки №6: 16×16
```

Це не лише незручність. Реальні мережі складаються з десятків згорток, а картинки в них часто невеликі: навіть із 28×28 після 13 згорток 3×3 лишиться 2×2, а після чотирнадцятої карти ознак не існуватиме взагалі. Якби ми хотіли вмістити більше шарів, нам довелося б брати все більші вхідні зображення. Було б корисно мати **ручку**, якою ми самі вирішуємо, зменшувати розмір чи ні.

## Проблема 2: пікселі на краях рахуються рідше

Друга проблема тонша. Давайте порахуємо, **скільки разів кожен піксель потрапляє під ядро** під час проходу. Для цього напишемо маленьку функцію: вона проходить усі позиції ядра й додає одиницю до кожного пікселя, який опинився під ним.

::jupyter-notebook{title="pixel_coverage.ipynb" executionCount="2"}

```python
def coverage(h, w, k):
    """Скільки разів кожен піксель входу h×w потрапляє під ядро k×k."""
    count = np.zeros((h, w), dtype=int)
    for i in range(h - k + 1):
        for j in range(w - k + 1):
            count[i:i + k, j:j + k] += 1    # усі пікселі під ядром отримують +1
    return count

print(coverage(7, 7, 3))
```

#output
```
[[1 2 3 3 3 2 1]
 [2 4 6 6 6 4 2]
 [3 6 9 9 9 6 3]
 [3 6 9 9 9 6 3]
 [3 6 9 9 9 6 3]
 [2 4 6 6 6 4 2]
 [1 2 3 3 3 2 1]]
```
::

Результат дуже показовий. **Центральний піксель потрапляє в дев'ять обчислень** (під кожне з дев'яти розміщень ядра, що його накривають), а **кутовий — лише в одне**. Пікселі вздовж країв — у 2–3 обчислення. Тобто інформація з країв і кутів впливає на результат у 9 разів слабше, ніж інформація з центру.

![Скільки разів піксель потрапляє під ядро 3×3: без доповнення (кут — 1, центр — 9) та з доповненням (кут — 4)](/images/ai-python/cnn-image-classification/padding-and-stride/01.png){.diagram-img}

Для цифр у центрі кадру це не критично. Але в загальному випадку об'єкт може лежати біля краю. Згадаймо лекцію 02, де ми шукали штрих. Поставимо його в **крайній лівий стовпець** і подивимося на карту відгуків ядра, яке шукає вертикальний штрих.

::jupyter-notebook{title="edge_stroke_problem.ipynb" executionCount="3"}

```python
edge_line = np.zeros((6, 6), dtype=int)
edge_line[:, 0] = 1                       # штрих у крайньому стовпці 0

result = conv(edge_line, K)
print(result)
print("Максимум:", result.max())
```

#output
```
[[-3  0  0  0]
 [-3  0  0  0]
 [-3  0  0  0]
 [-3  0  0  0]]
Максимум: 0
```
::

Штрих є, але карта його **не бачить**: максимальний відгук нуль, а штрих дав лише `−3` (на краю ділянки). Причина проста: щоб дати відгук `+3`, ядро має накрити штрих своїм центральним стовпцем, а центр ядра ніколи не може опинитися над стовпцем 0, бо ліворуч нього немає пікселів. Перший стовпець просто недосяжний для центру.

::tip
Ось дві проблеми, які насправді є двома проявами однієї причини: ядро має повністю лежати на картинці. Краї недоступні для центру ядра, а тому вони рахуються рідше, і саме тому розмір результату менший за вхід.
::

Звідси й рішення: якщо ядру бракує пікселів поза картинкою, **дамо йому ці пікселі**.

## Рішення для країв: доповнення (padding)

Ідея проста: **обведемо картинку рамкою з нулів** і лише потім виконаємо звичайну згортку. Нулі «дорисовують» пікселі, яких бракувало, і тепер центр ядра може стояти над будь-яким справжнім пікселем, навіть крайнім. Такий прийом називається **доповненням** (*padding*), а коли рамка складається з нулів — **нульовим доповненням** (*zero padding*). Параметр `P` — це товщина рамки в пікселях.

У NumPy рамку додає функція `np.pad`. Спробуємо на нашому прикладі 5×5 з рамкою товщиною 1.

::jupyter-notebook{title="zero_padding.ipynb" executionCount="4"}

```python
padded = np.pad(I, pad_width=1)       # рамка з нулів товщиною 1 пікселя
print("Розмір після доповнення:", padded.shape)
print(padded)

result = conv(padded, K)
print("\nРозмір результату:", result.shape)
print(result)
print("\nЦентр карти збігається зі старим результатом:",
      np.array_equal(result[1:-1, 1:-1], conv(I, K)))
```

#output

### Чи виправилася нерівність країв?

Перерахуємо покриття пікселів, тепер із рамкою. Для цього розширимо нашу функцію параметром `padding`.

::jupyter-notebook{title="coverage_with_padding.ipynb" executionCount="5"}

```python
def coverage(h, w, k, padding=0):
    size_h, size_w = h + 2 * padding, w + 2 * padding
    count = np.zeros((size_h, size_w), dtype=int)
    for i in range(size_h - k + 1):
        for j in range(size_w - k + 1):
            count[i:i + k, j:j + k] += 1
    return count[padding:padding + h, padding:padding + w]   # лишаємо лише справжні пікселі

print(coverage(7, 7, 3, padding=1))
```

#output
```
[[4 6 6 6 6 6 4]
 [6 9 9 9 9 9 6]
 [6 9 9 9 9 9 6]
 [6 9 9 9 9 9 6]
 [6 9 9 9 9 9 6]
 [6 9 9 9 9 9 6]
 [4 6 6 6 6 6 4]]
```
::

Тепер кут потрапляє під ядро **4 рази** замість одного, а край — 6 разів замість 2–3. Нерівність не зникла повністю (центр усе ще 9), але вона стала значно м'якшою. А що зі штрихом у крайньому стовпці? Подивимося.

### Скільки нулів потрібно, щоб розмір не змінювався

Підставимо рамку в формулу розміру. Після доповнення вхід має розмір `H + 2P` (рамка з обох боків), тому розмір результату:

::math-formula
H_{\text{out}} = (H + 2P) - K + 1
::

Ми хочемо, щоб він дорівнював `H`. Розв'яжемо відносно `P`:

::math-formula
H + 2P - K + 1 = H \quad\Longrightarrow\quad P = \frac{K - 1}{2}
::

Тож для ядра 3×3 потрібна рамка `P = 1`, для 5×5 — `P = 2`, для 7×7 — `P = 3`. Таке доповнення називають **same** (англ. «той самий» — розмір не змінюється), а згортку без доповнення — **valid** (англ. «допустима»: лише ті позиції, де ядро повністю лежить на картинці). Ці слова ви зустрінете в параметрах `scipy` (`mode="valid"`, `mode="same"`) і PyTorch (`padding="same"`).

::::accordion

:::accordion-item{label="❓ Чому ядра майже завжди мають непарний розмір (3×3, 5×5, 7×7)?" icon="i-lucide-help-circle"}

Бо в непарного ядра є **центральний піксель**: ядро симетрично дивиться на сусідів з усіх боків, а `P = (K − 1) / 2` — ціле число, тож рамка однакова з обох боків. Для парного ядра (наприклад 2×2) центру немає, і щоб зберегти розмір, довелося б додавати рамку нерівної товщини, наприклад з одного боку 1 піксель, з іншого 0. Тому на практиці беруть непарні розміри.

:::

:::accordion-item{label="❓ Чому рамка з нулів, а не з якихось інших чисел?" icon="i-lucide-help-circle"}

Нуль нейтральний: він нічого не додає до суми добутків (`0 · вага = 0`), тож рамка не вносить власного «візерунка». Для MNIST це ще й природно, бо фон там і так чорний (нуль). Існують інші варіанти: дзеркальне відбиття країв (`np.pad(I, 1, mode="reflect")`) або повторення крайніх пікселів (`mode="edge"`). У PyTorch їх вмикають параметром `padding_mode`. Але в більшості мереж використовують саме нулі, бо це просто і добре працює.

:::

::::

## Крок зсуву (stride): зменшуємо розмір навмисно

Тепер повернемося до першої проблеми, але подивимося на неї з іншого боку. Іноді зменшення картинки — це **бажаний** ефект. Мережі потрібно від детальних пікселів перейти до загальних ознак, а для цього зручно, щоб карти ставали меншими, і обчислень, і пам'яті — менше.

Досі ядро зсувалося на **один піксель**. Що буде, якщо зсувати його на **два**? Це і є **крок** (*stride*) — параметр `S`: на скільки пікселів ядро стрибає між сусідніми позиціями. Раніше ми мовчки брали `S = 1`. Тепер візьмемо `S = 2`: ядро стоїть у позиціях 0, 2, 4, … і пропускає позиції 1, 3, …

Подивімося на наш приклад 5×5. Позиції ядра по горизонталі: 0 та 2 (позиція 4 вже не поміщається, бо ядро виходить за межі). Те саме по вертикалі. Тобто результат матиме розмір 2×2. А які саме там числа? Позиції `(0, 0)`, `(0, 2)`, `(2, 0)`, `(2, 2)` — це вже знайомі нам клітинки звичайної карти. Тому результат кроку 2 дорівнює **кожній другій клітинці** карти для кроку 1.

::jupyter-notebook{title="stride_two.ipynb" executionCount="7"}

```python
full = conv(I, K)         # звичайна карта (крок 1), 3×3
stride2 = full[::2, ::2]  # кожна друга клітинка по рядках і стовпцях

print("Крок 1:\n", full)
print("\nКрок 2:\n", stride2)
```

```
 [-15  13 -14]
 [-14  13 -15]]

Крок 2:

 [-14 -15]]
```

Така сама логіка дає формулу кількості позицій. Позиції ядра — це `0, S, 2S, 3S, …`, і остання не може бути далі за `H − K`. Скільки таких позицій? Це кількість кроків по `S` у проміжку `H − K`, плюс нульова позиція. Вона має бути цілою, тому ділення округлюється вниз (позначимо дужками :math-formula{tex="\lfloor \cdot \rfloor" inline}):

::math-formula
\left\lfloor \frac{H - K}{S} \right\rfloor + 1
::

Перевірка: :math-formula{tex="\lfloor (5-3)/2 \rfloor + 1 = 2" inline} позиції вздовж осі. Збігається з тим, що ми бачили.

### Ціна кроку

Крок 2 прискорює обчислення вчетверо (маємо 4 числа замість 9), але платимо за це пропущеними позиціями. Якщо вузька ознака потрапить саме на пропущену позицію, ядро її не «побачить» у своєму центрі. Крок, більший за розмір ядра, залишав би цілі пікселі взагалі поза обчисленнями, тому на практиці `S` не перевищує `K`. Типові значення: `S = 1` (за замовчуванням) і `S = 2` (коли треба вдвічі зменшити карту).

---

## Загальна формула розміру

Тепер зберемо всі три параметри (розмір ядра `K`, доповнення `P` і крок `S`) в одну формулу. Спочатку рамка збільшує вхід до `H + 2P`, а потім ми рахуємо позиції з кроком `S`:

::math-formula
H_{\text{out}} = \left\lfloor \frac{H + 2P - K}{S} \right\rfloor + 1
::

Ця формула описує **всі** випадки, які ми розглянули: без доповнення й з кроком 1 вона дає `H − K + 1`, при `P = (K − 1) / 2` і `S = 1` — `H`, а з `S = 2` розмір майже вдвічі менший. Запишемо її як функцію й перевіримо на кількох реальних конфігураціях, включно з відомою початковою частиною нейромереж для фото (вхід 224×224, ядро 7×7, `P = 3`, `S = 2`).

::jupyter-notebook{title="output_size_formula.ipynb" executionCount="8"}

```python
def out_size(h, k, padding=0, stride=1):
    return (h + 2 * padding - k) // stride + 1      # // — ділення з округленням вниз

cases = [
    (28, 3, 0, 1),     # звичайна згортка
    (28, 3, 1, 1),     # same
    (28, 3, 1, 2),     # same + крок 2
    (28, 5, 2, 1),     # ядро 5×5, same
    (224, 7, 3, 2),    # початок багатьох мереж для фото
    (8, 3, 0, 2),      # ділиться не націло
]
for h, k, p, s in cases:
    print(f"H={h:>3}, K={k}, P={p}, S={s}  →  {out_size(h, k, p, s)}")
```

#output
```
H= 28, K=3, P=0, S=1  →  26
H= 28, K=3, P=1, S=1  →  28
H= 28, K=3, P=1, S=2  →  14
H= 28, K=5, P=2, S=1  →  28
H=224, K=7, P=3, S=2  →  112
H=  8, K=3, P=0, S=2  →  3
```
::

Формула округлює вниз, тож «зайві» пікселі просто лишаються поза розрахунком. Для `H = 8`, `K = 3`, `S = 2` ядро стоїть у позиціях 0, 2 і 4: воно накриває стовпці 0–2, 2–4 і 4–6. Наступна позиція 6 уже не помістилася б (потрібні стовпці 6–8, а картинка закінчується на 7), тому **останній стовпець 7 не бере участі в обчисленнях**. ## Власна згортка з усіма параметрами

Об'єднаємо все в одну функцію, розширивши `conv2d` із лекції 03 параметрами `padding` та `stride`. Додаємо лише два рядки: рамка нулів перед обходом і крок у позиціях.

::jupyter-notebook{title="conv2d_full.ipynb" executionCount="9"}

```python
def conv2d(image, kernel, padding=0, stride=1):
    if padding:
        image = np.pad(image, padding)             # рамка з нулів
    h, w = image.shape
    kh, kw = kernel.shape
    out_h = (h - kh) // stride + 1
    out_w = (w - kw) // stride + 1
    out = np.zeros((out_h, out_w), dtype=image.dtype)

    for i in range(out_h):
        for j in range(out_w):
            top, left = i * stride, j * stride     # позиція ядра з урахуванням кроку
            out[i, j] = (image[top:top + kh, left:left + kw] * kernel).sum()
    return out

print(conv2d(I, K, padding=1, stride=2))
```

#output
```
[[-1  8 -1]
 [ 1 13  0]
 [-1  9  1]]
```
::

Перевіримо нашу функцію з `nn.Conv2d` з PyTorch: підставимо в нього те саме ядро (без зсуву `bias`) і порівняємо результати для кількох комбінацій `padding` і `stride`.

::jupyter-notebook{title="check_with_pytorch.ipynb" executionCount="10"}

```python
import torch
import torch.nn as nn

def check(padding, stride):
    layer = nn.Conv2d(1, 1, kernel_size=3, padding=padding, stride=stride, bias=False)
    with torch.no_grad():
        layer.weight[:] = torch.tensor(K, dtype=torch.float32)       # кладемо наше ядро
    x = torch.tensor(I, dtype=torch.float32)[None, None]            # додали осі: [партія, канал, H, W]
    reference = layer(x)[0, 0].detach().numpy()
    ours = conv2d(I, K, padding, stride)
    return ours.shape, np.allclose(ours, reference)

for p, s in [(0, 1), (1, 1), (1, 2), (0, 2), (2, 1)]:
    print(f"padding={p}, stride={s}: {check(p, s)}")
```

#output
```
padding=0, stride=1: ((3, 3), True)
padding=1, stride=1: ((5, 5), True)
padding=1, stride=2: ((3, 3), True)
padding=0, stride=2: ((2, 2), True)
padding=2, stride=1: ((7, 7), True)
```
::

Результати збіглися в усіх п'яти випадках, тобто наша функція робить саме те, що й `nn.Conv2d`. Не лякайтеся рядка `[None, None]`: PyTorch очікує зображення у формі `[партія, канали, висота, ширина]`, і ми просто додали дві осі. Докладно про `nn.Conv2d` та цю форму поговоримо в одній із наступних лекцій. Поки що важливо, що параметри `padding` і `stride` там називаються так само, як у нас.

Подивимося ще на розміри, які повертає `nn.Conv2d` для MNIST, і порівняємо їх із формулою.

::jupyter-notebook{title="conv2d_shapes.ipynb" executionCount="11"}

## Практика

::::accordion

:::accordion-item{label="📋 Завдання 1: порахуйте розмір" icon="i-lucide-clipboard-list"}

Зображення 32×32. Яким буде розмір карти ознак, якщо:

1. ядро 5×5, `padding = 2`, `stride = 1`;
2. ядро 5×5, `padding = 0`, `stride = 2`?

:::

:::accordion-item{label="✅ Розв'язок" icon="i-lucide-check-circle"}

За формулою `⌊(H + 2P − K) / S⌋ + 1`:

1. `(32 + 4 − 5) / 1 + 1 = 32` — розмір зберігається (`P = (5 − 1) / 2 = 2`, тобто це «same»).
2. `⌊(32 − 5) / 2⌋ + 1 = ⌊13.5⌋ + 1 = 14`.

```python
print(out_size(32, 5, 2, 1), out_size(32, 5, 0, 2))   # 32 14
```

:::

:::accordion-item{label="📋 Завдання 2: який padding для ядра 7×7?" icon="i-lucide-clipboard-list"}

Яке `padding` потрібне ядру 7×7, щоб розмір не змінювався (при `stride = 1`)? А що буде з ядром 4×4?

:::

:::accordion-item{label="✅ Розв'язок" icon="i-lucide-check-circle"}

`P = (K − 1) / 2 = (7 − 1) / 2 = 3`. Для ядра 4×4 вийшло б `P = 1.5` — рамки напівтовщини не буває, тому симетричне доповнення зберегти розмір не дозволить. Саме тому ядра роблять непарними.

:::

:::accordion-item{label="📋 Завдання 3: з 28 до 7" icon="i-lucide-clipboard-list"}

Потрібно зменшити карту з 28×28 до 7×7, використовуючи ядро 3×3 з `padding = 1`. Знайдіть два способи: через дві згортки та через одну. Яка з них гірша і чому?

:::

:::accordion-item{label="✅ Розв'язок" icon="i-lucide-check-circle"}

**Дві згортки:** `stride = 2` на кожній: `28 → 14 → 7`.

**Одна згортка:** `stride = 4`: `⌊(28 + 2 − 3) / 4⌋ + 1 = ⌊6.75⌋ + 1 = 7`.

```python
print(out_size(out_size(28, 3, 1, 2), 3, 1, 2))   # 7
print(out_size(28, 3, 1, 4))                      # 7
```

Другий спосіб гірший: крок 4 більший за ядро (3), тому ядро «перестрибує» ціле сусідство між позиціями, і частина пікселів взагалі не потрапляє в обчислення. Дві згортки з кроком 2 переглядають усі пікселі, а ще й додають другу ознаку поверх першої.

:::

## Резюме

::card-group

::card{title="📌 Дві проблеми звичайної згортки" icon="i-lucide-alert-triangle"}
Карта ознак менша за вхід (на `K − 1` пікселів по осі), а краї рахуються рідше: кутовий піксель потрапляє під ядро 3×3 один раз, центральний — дев'ять.
::

::card{title="📌 Padding" icon="i-lucide-square-dashed"}
Рамка нулів товщиною `P` навколо входу. При `P = (K − 1) / 2` розмір зберігається (*same*), без рамки — *valid*. Краї стають доступними для центру ядра.
::

::card{title="📌 Stride" icon="i-lucide-move-right"}
Ядро зсувається на `S` пікселів. `S = 2` дає кожну другу клітинку й зменшує карту вдвічі. Крок не варто брати більшим за ядро.
::

::card{title="📌 Загальна формула" icon="i-lucide-sigma"}
:math-formula{tex="H_{\text{out}} = \lfloor (H + 2P - K) / S \rfloor + 1" inline}. Параметри `padding` і `stride` в `nn.Conv2d` працюють саме так.
::

::

**У наступній лекції** ми повернемося до питання, яке залишили наприкінці лекції про фільтри: хто вигадає ядра для розпізнавання котів? Ми побачимо, що ядро — це звичайні ваги, і спробуємо навчити його градієнтним спуском. Ми почнемо зі «сліпого» ядра з випадковими числами й за кілька сотень кроків побачимо, як воно саме стає детектором країв. Після цього ми познайомимося з шаром `nn.Conv2d`, який робить усе це для багатьох ядер одразу.
