# Ядро, що навчається

::card-group

::card{title="🎯 Мета лекції" icon="i-lucide-target"}

- Побачити згортку як нейрон із Модуля 4 (`w·x + b`) зі спільними вагами
- Навчити ядро градієнтним спуском і побачити, як із випадкових чисел виникає детектор країв
- Познайомитися з шаром `nn.Conv2d`: його параметрами, формою ваг і форми тензорів
- Зрозуміти, що означає `out_channels` і чому кілька ядер дають стос карт ознак

::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Зсув (Bias):** додатковий параметр нейрона, що додається до суми добутків
- **`nn.Conv2d`:** шар PyTorch, який зберігає ядра як навчані ваги
- **Вихідні канали (`out_channels`):** кількість ядер у шарі, тобто кількість карт ознак на виході
- **Форма `[N, C, H, W]`:** партія, канали, висота, ширина — формат вхідного тензора для `nn.Conv2d`

::

## Від готових ядер до навчених

У попередніх лекціях ми працювали з ядрами, які **ми самі** вигадали або взяли з підручника: вертикальний штрих, Собель, розмиття. Наприкінці лекції про фільтри ми поставили запитання: хто вигадає ядра для розпізнавання котів? І відповіли здогадом: ядро — це лише дев'ять чисел, а числа-ваги нейромережі ми вже вміємо навчати градієнтним спуском.

Тепер перевіримо цей здогад на практиці. Спершу покажемо, що згортка справді **є** нейроном із Модуля 4, а потім навчимо ядро з нуля. Ми візьмемо «сліпе» ядро з випадковими числами й подивимося, як воно за кілька сотень кроків саме перетворюється на Собеля.

---

## Згортка — це нейрон

Згадаймо нейрон із Модуля 4. Він бере кілька вхідних чисел, множить кожне на свою вагу, додає **зсув** (*bias*) і віддає результат:

::math-formula{tex="z = w_1 x_1 + w_2 x_2 + \dots + w_n x_n + b"}
::

Тепер подивимося на формулу однієї клітинки карти ознак із лекції 03 і додамо в неї ту саму константу `b`:

::math-formula{tex="O[i, j] = b + \sum_{u=0}^{2} \sum_{v=0}^{2} K[u, v] \cdot I[i + u,\; j + v]"}
::

Це **та сама формула**. Ділянка 3×3 — це дев'ять входів `x`, ядро — це дев'ять ваг `w`, а `b` — зсув. Ми навмисно не згадували `b` у попередніх лекціях, щоб не відволікатися, але в реальних шарах він завжди є. Перевіримо збіг на числах нашого прикладу:

::jupyter-notebook{title="conv_is_a_neuron.ipynb" kernel="Python 3.11"}

::jupyter-cell{executionCount="1"}

```python
import numpy as np

I = np.array([
    [0, 1, 5, 0, 0],
    [0, 0, 5, 1, 0],
    [1, 0, 4, 0, 0],
    [0, 0, 5, 0, 1],
    [0, 1, 5, 0, 0],
])
K = np.array([[-1, 1, -1]] * 3)

patch = I[0:3, 0:3]
w = K.flatten()          # 9 ваг нейрона
x = patch.flatten()      # 9 входів нейрона (ділянка, розгорнута в рядок)
b = 0.0                  # зсув (поки що нульовий)

print("Нейрон: w·x + b =", (w * x).sum() + b, "| згортка:", (patch * K).sum())
```

#output
```
Нейрон: w·x + b = -14.0 | згортка: -14
```
::

::

Результат збігається: **згортка в кожній позиції — це один нейрон**. Особливість лише одна, і ми її вже знаємо: нейрон один, а дивиться він у різні місця зображення, використовуючи одні й ті самі ваги. Саме це ми називали спільними вагами у лекції 02.

## Згортка як множення матриці на вектор

Є ще один погляд на згортку, який нам дуже знадобиться. Нейрон перемножує дев'ять входів на дев'ять ваг і додає. Нейронів, у яких ті самі ваги, — дев'ять (по одному на кожну позицію нашої карти 3×3). Складемо ділянки 3×3 для **всіх** позицій в таблицю: кожну ділянку розгорнемо в рядок із дев'яти чисел. Вийде матриця `9×9`: один рядок на позицію, один стовпець на піксель ділянки.

::jupyter-notebook{title="conv_as_matrix_product.ipynb" executionCount="2"}

```python
rows = [I[i:i + 3, j:j + 3].flatten() for i in range(3) for j in range(3)]
X_patches = np.array(rows)

print(X_patches.shape)
print((X_patches @ K.flatten()).reshape(3, 3))
```

#output
```
(9, 9)
[[-14  12 -13]
 [-15  13 -14]
 [-14  13 -15]]
```
::

Оператор `@` — це матричне множення: кожен рядок матриці множиться на вектор ваг, і виходить дев'ять чисел. Перескладемо їх у таблицю 3×3 — і ось уся карта ознак, ідентична результату з попередніх лекцій.

Навіщо нам цей погляд? Бо він показує, що відбувається під час навчання. Дев'ять стовпців матриці — це дев'ять **ознак** кожної позиції (значення дев'яти пікселів), результат — те, що ми хочемо передбачити, а ядро — вектор ваг, який множить ознаки. Це **лінійна регресія** з дев'ятьма ознаками, яку ви вже вивчали в Модулі 3.

::tip
Це дуже корисна думка: навчання ядра, по суті, — це та сама лінійна регресія з Модуля 3, тільки роль «рядків таблиці даних» грають усі ділянки всіх картинок. А градієнтний спуск ми вже вміємо застосовувати і до регресії, і до нейромереж.
::

## Шар nn.Conv2d: ядро як навчані ваги

У попередніх лекціях ми вже торкалися `nn.Conv2d` під час перевірки нашої функції. Тепер розберемо його докладно. Це шар PyTorch, який **зберігає ядро як ваги**, що навчаються, так само, як `nn.Linear` зберігає матрицю ваг повнозв'язного шару. Створимо найпростіший шар: один вхідний канал, одне ядро 3×3.

::jupyter-notebook{title="conv2d_anatomy.ipynb" executionCount="3"}

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

layer = nn.Conv2d(in_channels=1, out_channels=1, kernel_size=3)

print("weight:", tuple(layer.weight.shape))
print("bias:", tuple(layer.bias.shape))
print("параметрів:", sum(p.numel() for p in layer.parameters()))
print("weight навчається:", layer.weight.requires_grad)
```

#output
```
weight: (1, 1, 3, 3)
bias: (1,)
параметрів: 10
weight навчається: True
```
::

Розберемо кожен рядок виводу:

- **`weight` має форму `(1, 1, 3, 3)`.** Це чотири числа: `(вихідні канали, вхідні канали, висота ядра, ширина ядра)`. Ядро 3×3 — це останні дві цифри, а дві перші ми поки що не чіпаємо: у нас один канал на вході й одне ядро.
- **`bias` має форму `(1,)`:** по одному зсуву на кожне ядро.
- **Параметрів 10:** дев'ять ваг ядра та один зсув. Рівно стільки, скільки ми рахували для цілої карти ознак.
- **`requires_grad=True`:** PyTorch відстежуватиме градієнти ваг, і оптимізатор зможе їх оновлювати. Це механізм `autograd` із Модуля 4.

Щоб переконатися, що шар рахує те саме, що й наша згортка, покладемо в нього ядро з лекцій 02–03 й обнулимо зсув.

::jupyter-notebook{title="conv2d_with_our_kernel.ipynb" executionCount="4"}

```python
with torch.no_grad():
    layer.weight[:] = torch.tensor(K, dtype=torch.float32)   # кладемо наше ядро
    layer.bias.zero_()                                       # зсув = 0

x = torch.tensor(I, dtype=torch.float32)[None, None]         # форма [1, 1, 5, 5]
print(layer(x)[0, 0].detach())
```

#output
```
tensor([[-14.,  12., -13.],
        [-15.,  13., -14.],
        [-14.,  13., -15.]])
```
::

Знайома карта ознак. Про `[None, None]` скажемо слово: `nn.Conv2d` очікує вхід у формі **`[N, C, H, W]`**: `N` — кількість картинок у партії, `C` — кількість каналів, `H` і `W` — висота та ширина. Для однієї чорно-білої картинки `N = 1` і `C = 1`, тому ми додали дві зайві осі. Результат `[0, 0]` витягує з вихідного тензора єдину картинку з єдиним каналом.

## Навчаємо ядро: з випадкових чисел до Собеля

Тепер головний експеримент. Ми візьмемо шар зі **випадковими** вагами й навчимо його імітувати ядро Собеля X. Це навчальна демонстрація, і треба чесно сказати, як вона влаштована.

::note
**Що це за експеримент.** У справжній мережі ядро вчиться не імітувати чиєсь ядро, а допомагати правильно класифікувати зображення: сигнал помилки приходить із мітки («це «7», а мережа сказала «1»») і через усі шари доходить до ядра. У нашому спрощеному експерименті ми заздалегідь знаємо ідеальну відповідь (карту Собеля) і порівнюємо з нею вихід шару. Це дозволяє **побачити**, як саме змінюється ядро, не ускладнюючи картину цілою мережею. Механізм навчання при цьому той самий.
::

Задача виглядає так:

1. Беремо 64 цифри MNIST, це наші вхідні картинки.
2. Рахуємо для них карти Собеля X: це цільові відповіді.
3. Створюємо шар `nn.Conv2d` із випадковими вагами й навчаємо його, щоб його вихід збігався з цілями.
4. Міра розбіжності — середній квадрат різниці (*MSE*), з Модуля 3:

::math-formula{tex="L = \frac{1}{n} \sum \left( O_{\text{шар}} - O_{\text{ціль}} \right)^2"}
::

Спершу підготуємо дані. Зверніть увагу на форму `[64, 1, 28, 28]`: 64 картинки, по одному каналу.

::jupyter-notebook{title="learning_data.ipynb" executionCount="5"}

```python
from torchvision import datasets

mnist = datasets.MNIST(root="data", train=True, download=True)

X = (mnist.data[:64].float() / 255).unsqueeze(1)    # [64, 1, 28, 28]
print(X.shape)

sobel_x = torch.tensor([[-1, 0, 1],
                        [-2, 0, 2],
                        [-1, 0, 1]], dtype=torch.float32)
target = F.conv2d(X, sobel_x[None, None])           # цільові карти Собеля X
print(target.shape)
```

#output
```
torch.Size([64, 1, 28, 28])
torch.Size([64, 1, 26, 26])
```
::

Тепер навчальний цикл. Він знайомий з Модуля 4: прямий прохід, втрата, обнулення градієнтів, `backward`, крок оптимізатора. Нове лише те, що замість `nn.Linear` стоїть `nn.Conv2d`. Ми використаємо оптимізатор Adam зі швидкістю навчання `0.1` і 600 кроків.

::jupyter-notebook{title="training_loop.ipynb" executionCount="6"}

```python
torch.manual_seed(0)
layer = nn.Conv2d(1, 1, kernel_size=3, bias=False)     # випадкові ваги, без зсуву
optimizer = torch.optim.Adam(layer.parameters(), lr=0.1)

for step in range(601):
    loss = F.mse_loss(layer(X), target)    # порівнюємо вихід шару з ціллю
    optimizer.zero_grad()
    loss.backward()                        # градієнти для 9 ваг ядра
    optimizer.step()                       # крок градієнтного спуску
    if step in (0, 10, 30, 100, 300, 600):
        print(f"крок {step:>3}: втрата {loss.item():.3g}")

print(layer.weight.detach()[0, 0])
```

#output
```

крок 600: втрата 3.89e-14
```

## Той самий код навчає будь-яке ядро

Ми не вкладали в навчальний цикл жодних знань про краї. Він просто підганяє дев'ять чисел під заданий результат. Значить, якщо замінити ціль, він навчить **інше** ядро. Перевіримо на чотирьох цілях, які ми вже знаємо: два Собеля, розмиття й загострення. Оформимо цикл у функцію.

::jupyter-notebook{title="four_targets.ipynb" executionCount="7"}

```python
targets = {
    "Собель X":    [[-1, 0, 1], [-2, 0, 2], [-1, 0, 1]],
    "Собель Y":    [[-1, -2, -1], [0, 0, 0], [1, 2, 1]],
    "Розмиття":    [[1 / 9] * 3] * 3,
    "Загострення": [[0, -1, 0], [-1, 5, -1], [0, -1, 0]],
}

def train_kernel(kernel, steps=600):
    kernel = torch.tensor(kernel, dtype=torch.float32)
    goal = F.conv2d(X, kernel[None, None])
    torch.manual_seed(0)
    layer = nn.Conv2d(1, 1, kernel_size=3, bias=False)
    optimizer = torch.optim.Adam(layer.parameters(), lr=0.1)
    for _ in range(steps):
        loss = F.mse_loss(layer(X), goal)
        optimizer.zero_grad(); loss.backward(); optimizer.step()
    error = (layer.weight.detach()[0, 0] - kernel).abs().max().item()
    return error

for name, kernel in targets.items():
    print(f"{name:<12} похибка ядра: {train_kernel(kernel):.1e}")
```

#output
```
Собель X     похибка ядра: 7.2e-07
Собель Y     похибка ядра: 7.2e-07
Розмиття     похибка ядра: 2.2e-08
Загострення  похибка ядра: 1.9e-06
```
::

У всіх чотирьох випадках навчене ядро відрізняється від цілі менш ніж на `10⁻⁵`: код знайшов і Собеля, і розмиття з усіма дев'ятьма числами `0.11`, і загострення з п'ятіркою посередині. Те, що ядро нічого не знає про краї чи розмиття, не заважає: воно знає лише, яким має бути результат.

### Чому тут усе так «чисто»

Корисно зрозуміти, чому навчання пройшло гладко, і не вирішити помилково, що так буде завжди. У нашому експерименті цільова відповідь **теж отримана згорткою**, тобто існує точне ядро, яке дає нульову втрату. До того ж ядро входить у формулу лінійно, тож задача — це лінійна регресія з Модуля 3, у якій немає «пасток» (локальних мінімумів): градієнтний спуск гарантовано йде до ідеальної відповіді.

У справжній мережі все складніше. Там ціль — не карта ознак, а правильна відповідь на запитання «що на картинці?», ядер багато, між ними стоять нелінійності (ReLU), і ідеального ядра, яке дає нульову втрату, не існує. Тому навчені ядра справжніх мереж не такі «ідеальні» й охайні, як Собель, але принцип той самий: **ядра — це ваги, які градієнтний спуск підбирає так, щоб втрата зменшувалась**.

::::accordion

:::accordion-item{label="❓ Чому навчання працює, хоча ядро використовується у 676 позиціях одразу?" icon="i-lucide-help-circle"}

Градієнт для кожної ваги ядра — це **сума** внесків з усіх позицій, де ця вага використовувалась. PyTorch (`autograd`) додає їх автоматично. Тому ядро оновлюється з урахуванням усієї картинки, і кожна позиція «голосує» за те, як змінити вагу. Тому для кожної ваги ядра є дуже багато прикладів, на яких вона підстроюється: це одна з причин, чому ядра навчаються надійно.

:::

:::accordion-item{label="❓ А якщо взяти ядро більшого розміру, ніж потрібно?" icon="i-lucide-help-circle"}

Ядро саме обнулить зайве. Це можна перевірити в завданні 2 наприкінці лекції: якщо навчити ядро 5×5 імітувати Собеля 3×3, воно вивчить Собеля в центрі, а зовнішнє кільце заповнить нулями.

:::

## Багато ядер у одному шарі: out_channels

Одне ядро шукає одну ознаку: вертикальний край або розмиття. Але для розпізнавання цифр потрібно багато різних ознак: різні нахили ліній, кути, закруглення. Тому в реальному шарі ядер **кілька**, і кожне навчається шукати своє.

Кількість ядер у шарі задає параметр **`out_channels`** («вихідні канали»). Створимо шар із восьмома ядрами й подивимося, що змінилося.

::jupyter-notebook{title="eight_kernels.ipynb" executionCount="8"}

```python
torch.manual_seed(0)
layer8 = nn.Conv2d(in_channels=1, out_channels=8, kernel_size=3)

print("weight:", tuple(layer8.weight.shape), "| bias:", tuple(layer8.bias.shape))
print("параметрів:", sum(p.numel() for p in layer8.parameters()))

out = layer8(X[:5])                    # партія із 5 цифр
print("вихід:", tuple(out.shape))

dense = nn.Linear(784, 8 * 26 * 26)    # Dense-шар з такою самою кількістю виходів
print("Dense з тією ж кількістю виходів:", sum(p.numel() for p in dense.parameters()))
```

#output
```
weight: (8, 1, 3, 3) | bias: (8,)
параметрів: 80
вихід: (5, 8, 26, 26)
Dense з тією ж кількістю виходів: 4245280
```
::

Розберемо результат:

- **`weight` має форму `(8, 1, 3, 3)`:** вісім ядер 3×3, кожне для одного вхідного каналу. `bias` має вісім чисел, по одному на ядро.
- **Параметрів лише 80:** вісім ядер по дев'ять ваг і вісім зсувів (`8 · 9 + 8`).
- **Вихід має форму `(5, 8, 26, 26)`:** для кожної з п'яти картинок маємо **вісім** карт ознак по 26×26. Це ніби «зображення з вісьмома каналами».
- **Dense із тією ж кількістю виходів** (8 · 26 · 26 = 5408) потребував би понад **4,2 мільйона** параметрів. Це майже в 53 тисячі разів більше, ніж у `Conv2d`.

![Схема шару nn.Conv2d(1, 8, 3): вхід [N, 1, 28, 28], вісім ядер weight [8, 1, 3, 3], вихід [N, 8, 26, 26]](/images/ai-python/cnn-image-classification/learnable-kernels/06.png){.diagram-img}

![Кількість параметрів: Dense-шар із 5408 виходами має 4 245 280, а Conv2d(1, 8, 3) — 80](/images/ai-python/cnn-image-classification/learnable-kernels/07.png){.diagram-img}

Це і є розв'язання першої проблеми з початку модуля: параметрів потрібно не мільйони, а десятки, бо ядро ділить ваги між усіма позиціями.

Подивимося, як виглядають результати восьми ядер **до навчання**, на нашій цифрі «7». Ваги ініціалізовані випадково: PyTorch за замовчуванням вибирає їх рівномірно з діапазону :math-formula{tex="\pm 1/\sqrt{9} = \pm 0.33" inline} (дев'ять — це кількість ваг у ядрі). Тому в нас усі ваги на малюнку лежать у діапазоні `−0.33…0.33`.

![Вісім випадкових ядер та їхні карти ознак для цифри «7»: різні відгуки, але жодне ядро ні під що не налаштоване](/images/ai-python/cnn-image-classification/learnable-kernels/08.png){.diagram-img}

Карти не порожні: різні випадкові ядра вже дають різні відгуки. Одні нагадують розмиття цифри, інші виділяють краї певного напрямку. Але це **випадковість**, а не результат навчання: ядро 4 дає від'ємний відгук на штрихи, а ядро 3 — додатний, просто тому, що так випали числа. Фон теж не нульовий: ненульовий зсув `bias` зміщує всю карту на сталу величину. Під час навчання мережі кожне ядро знайде собі ознаку, яка допомагає класифікувати цифри.

```python
target5 = F.conv2d(X, sobel_x[None, None], padding=1)       # 28×28

optimizer = torch.optim.Adam(layer5.parameters(), lr=0.1)
for _ in range(800):
    loss = F.mse_loss(layer5(X), target5)
    optimizer.zero_grad(); loss.backward(); optimizer.step()
```

```python
for lr in (0.001, 0.1):
```

## Резюме

::card-group

::card{title="📌 Згортка — це нейрон" icon="i-lucide-brain"}
Кожна клітинка карти — це `w·x + b` з дев'яти пікселів ділянки. Нейрон один, ваги спільні для всіх позицій.
::

::card{title="📌 Ядро навчається" icon="i-lucide-trending-down"}
Ядро — це ваги `nn.Conv2d`. Градієнтний спуск перетворює випадкові числа на корисний детектор. Градієнт кожної ваги — сума внесків від усіх позицій.
::

::card{title="📌 Форми тензорів" icon="i-lucide-box"}
Вхід `[N, C, H, W]`, вага `[out, in, kh, kw]`, вихід `[N, out, H', W']`. Параметрів: `out · in · kh · kw + out`.
::

::card{title="📌 out_channels" icon="i-lucide-layers"}
Кілька ядер — кілька карт ознак на виході. `Conv2d(1, 8, 3)` має 80 параметрів, а Dense із тією ж кількістю виходів — понад 4,2 мільйона.
::

::

**У наступній лекції** ми розв'яжемо практичну проблему, яку створили самі: після шару з вісьмома ядрами в нас 8 карт по 26×26, тобто 5408 чисел замість 784. Точне положення ознаки зазвичай не потрібне, і важливо лише, що вона є десь поруч. Ми дізнаємося, як стискати карти ознак за допомогою **пулінгу** (*pooling*), і чому це робить мережу стійкішою до малих зсувів.
