# Пулінг і поле зору

::card-group

::card{title="🎯 Мета лекції" icon="i-lucide-target"}

- Зрозуміти, навіщо стискати карти ознак і що саме пулінг лишає від кожного вікна
- Порахувати max- та average-пулінг вручну й у PyTorch (`nn.MaxPool2d`, `nn.AvgPool2d`)
- Чесно оцінити, наскільки пулінг робить мережу стійкішою до зсуву
- Навчитися рахувати поле зору (receptive field) стеку шарів і побачити, чому пулінг так сильно його збільшує

::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Пулінг (Pooling):** стиснення карти ознак — із кожного вікна лишається одне число
- **Max-пулінг (Max pooling):** береться найбільше значення у вікні
- **Average-пулінг (Average pooling):** береться середнє значення у вікні
- **Поле зору (Receptive field):** ділянка входу, від якої залежить одне число на виході шару

::

::

## Скільки чисел ми вже маємо

Наприкінці попередньої лекції ми зробили шар `Conv2d(1, 8, 3)` і отримали вісім карт ознак по 26×26. Це `8 · 26 · 26 = 5408` чисел, тобто майже в сім разів більше, ніж у вихідній картинці 28×28 (784 числа). Якщо складати такі шари один за одним, чисел стане ще більше, а нам, навпаки, треба рухатися від «десятків тисяч пікселів» до короткої відповіді «це цифра 7».

Але є й друга, глибша причина. Згадаймо лекцію 02. Там ми помітили, що на запитання «є штрих десь на картинці?» відповідь не залежить від того, **де саме** він стоїть: достатньо подивитися на максимум карти. Для розпізнавання цифри точна позиція кожного краю з точністю до пікселя теж не потрібна. Важливо, що вертикальна лінія є *приблизно тут*. Було б добре мати прийом, який чесно викидає зайву точність позиції й одночасно зменшує кількість чисел. Саме це робить **пулінг**.

## Ідея: із кожного вікна лишаємо одне число

Розглянемо карту ознак 4×4 і поділимо її на чотири вікна 2×2 без перекриття. З кожного вікна лишимо **одне число**, і з чотирьох вікон отримаємо маленьку карту 2×2.

Яке саме число лишати? Найпоширеніший вибір — **найбільше** у вікні. Це **max-пулінг** (*max pooling*). Інший варіант — **середнє** значення вікна, тоді це **average-пулінг** (*average pooling*).

![Карта ознак 4×4, чотири вікна 2×2 та результати max- і average-пулінгу](/images/ai-python/cnn-image-classification/pooling/01.png){.diagram-img}

Подивимося, як це рахується. Напишемо функцію, яка ковзає вікном із кроком, що дорівнює розміру вікна (вікна не перекриваються), і рахує або максимум, або середнє.

::jupyter-notebook{title="pooling_by_hand.ipynb" kernel="Python 3.11"}

::jupyter-cell{executionCount="1"}

```python
import numpy as np

M = np.array([
    [1, 3, 2, 1],
    [4, 6, 5, 2],
    [7, 2, 9, 4],
    [1, 0, 3, 8],
])

def pool2d(x, size=2, mode="max"):
    h, w = x.shape
    out = np.zeros((h // size, w // size))
    for i in range(h // size):
        for j in range(w // size):
            window = x[i * size:(i + 1) * size, j * size:(j + 1) * size]
            out[i, j] = window.max() if mode == "max" else window.mean()
    return out

print("Max-пулінг:\n", pool2d(M, 2, "max"))
print("\nAverage-пулінг:\n", pool2d(M, 2, "mean"))
```

#output
```
Max-пулінг:
 [[6. 5.]
 [7. 9.]]

Average-пулінг:
 [[3.5 2.5]
 [2.5 6. ]]
```
::

::

Розберемо перше вікно (лівий верхній кут): у ньому числа `1, 3, 4, 6`. Максимум — `6`, середнє — `(1 + 3 + 4 + 6) / 4 = 3.5`. Те саме для решти вікон. Із 16 чисел лишилося 4, тобто карта стала **вдвічі меншою по кожній осі**.

### У пулінгу немає ваг

Порівняйте пулінг зі згорткою. Згортка множить числа на **ваги ядра**, а ваги навчаються. Пулінг лише бере максимум чи середнє, тобто **не має жодних параметрів, що навчаються**. Він не змінює кількості каналів: якщо на вході було 8 карт, то на виході теж 8, лише менших. Це проста й дешева операція, яку мережа використовує як «стискач» між згортками.

::note
Вікно пулінгу зазвичай має розмір 2×2 з кроком 2, як у нашому прикладі. Розмір результату рахується за знайомою формулою з попередньої лекції: `⌊(H − K) / S⌋ + 1`, де `K = 2` і `S = 2`. Для `H = 26` отримуємо `(26 − 2) / 2 + 1 = 13`.
::

## Max чи average: що краще

Вибір між максимумом і середнім залежить від того, яке запитання ми ставимо до вікна.

- **Max** відповідає на запитання «**чи є тут ознака?**». Якщо в якійсь клітинці вікна ядро знайшло край (великий відгук), цей відгук виживає. Це добре узгоджується з ReLU: після неї число означає «знайдено / не знайдено», а max лишає найсильніше «знайдено» у вікні.
- **Average** відповідає на запитання «**скільки ознаки в середньому?**». Один сильний відгук у вікні розмивається разом з нульовими сусідами.

У згорткових мережах для картинок майже завжди використовують max-пулінг: нас цікавить, чи знайдено ознаку, а не її середня «концентрація». Перевіримо різницю на справжній карті ознак.

## Пулінг справжньої карти ознак

Візьмемо вже знайому карту: цифра «7», ядро Собеля X і ReLU (ми зробили це в лекції про фільтри). Застосуємо до неї max- та average-пулінг 2×2.

::jupyter-notebook{title="pooling_real_map.ipynb" executionCount="2"}

```python
from scipy.signal import correlate2d
from torchvision import datasets

mnist = datasets.MNIST(root="data", train=True, download=True)
seven = mnist.data[101].numpy() / 255

sobel_x = np.array([[-1, 0, 1], [-2, 0, 2], [-1, 0, 1]])
feature_map = np.maximum(correlate2d(seven, sobel_x, mode="valid"), 0)    # Собель X + ReLU

max_pooled = pool2d(feature_map, 2, "max")
avg_pooled = pool2d(feature_map, 2, "mean")

print("Розміри:", feature_map.shape, "→", max_pooled.shape)
print("Ненульових клітинок:", (feature_map > 0).sum(), "→", (max_pooled > 0).sum())
print(f"Найсильніший відгук: {feature_map.max():.2f} → max {max_pooled.max():.2f}, average {avg_pooled.max():.2f}")
```

#output
```
Розміри: (26, 26) → (13, 13)
Ненульових клітинок: 130 → 45
Найсильніший відгук: 3.92 → max 3.92, average 3.19
```
::

Розберемо результат. Карта стала 13×13, тобто **чисел у чотири рази менше** (676 → 169), а ненульових клітинок із 130 лишилося 45, бо кілька сусідніх відгуків об'єдналися. Найсильніший відгук `3.92` після max-пулінгу **не змінився**, а після average-пулінгу впав до `3.19`: його розмило разом із сусідами.

## Пулінг і зсув: що він дає насправді

Ми казали, що пулінг робить мережу стійкішою до малих зсувів. Тепер перевіримо це на числах, а не на словах. Зсунемо цифру на кілька пікселів і порівняємо карти ознак із оригіналом, до пулінгу й після нього. Мірою схожості візьмемо **кореляцію** з Модуля 2: `1.0` означає однакові карти, а значення близькі до нуля — карти, що не мають нічого спільного.

::jupyter-notebook{title="pooling_and_shift.ipynb" executionCount="3"}

```python
def feature_map_of(image):
    return np.maximum(correlate2d(image, sobel_x, mode="valid"), 0)

def corr(a, b):
    return np.corrcoef(a.ravel(), b.ravel())[0, 1]

original = feature_map_of(seven)
original_pooled = pool2d(original, 2, "max")

for shift in range(5):
    moved = feature_map_of(np.roll(seven, shift, axis=1))     # зсув вправо на shift пікселів
    print(f"зсув {shift}: карта {corr(original, moved):.2f} | "
          f"після пулінгу {corr(original_pooled, pool2d(moved, 2, 'max')):.2f}")
```

#output
```
зсув 0: карта 1.00 | після пулінгу 1.00
зсув 1: карта 0.62 | після пулінгу 0.78
зсув 2: карта 0.11 | після пулінгу 0.39
зсув 3: карта -0.05 | після пулінгу 0.05
зсув 4: карта -0.06 | після пулінгу -0.09
```
::

Результат варто прочитати уважно, бо він чесний і не зовсім такий райдужний, як зазвичай пишуть:

- **На зсуві в 1 піксель пулінг допомагає помітно:** схожість карт зростає з `0.62` до `0.78`.
- **На зсуві у 2 пікселі допомога ще є, але слабша:** з `0.11` до `0.39`.
- **На зсуві у 3 і більше пікселів пулінг уже не рятує:** обидві карти майже не схожі на оригінал.

Тобто пулінг **пом'якшує** вплив зсуву на величину порядку розміру вікна, але **не робить мережу цілком стійкою** до зсуву. Одного пулінгу для повної стійкості мало, але разом зі спільними вагами ядер (карти зсуваються разом з об'єктом) і кількома шарами пулінгу ефект накопичується.

::::accordion

:::accordion-item{label="❓ Чому пулінг взагалі допомагає при зсуві?" icon="i-lucide-help-circle"}

Бо у вікні 2×2 максимум не залежить від того, у якій з чотирьох клітинок він стоїть. Якщо яскравий відгук посунувся на один піксель, але лишився всередині того самого вікна, вихід пулінгу не змінюється. Проблема виникає лише тоді, коли відгук перетинає межу між вікнами: тоді він переходить у сусіднє вікно, і вихід змінюється.

:::

:::accordion-item{label="❓ Чим пулінг відрізняється від згортки з кроком 2 (stride = 2)?" icon="i-lucide-help-circle"}

Обидва зменшують карту вдвічі, але по-різному. Згортка з кроком 2 множить на ваги, які **навчаються**, тож сама вирішує, що лишити. Пулінг — це фіксоване правило (максимум чи середнє), і ваг у нього немає. У класичних мережах для зображень використовують пулінг, а в багатьох сучасних замість нього ставлять згортку з кроком 2. У нашому курсі ми поки що користуватимемося пулінгом.

:::

## nn.MaxPool2d та nn.AvgPool2d у PyTorch

У PyTorch пулінг — це окремі шари. Створимо max-пулінг 2×2 й застосуємо до партії з п'яти картинок після шару з вісьмома ядрами (як у попередній лекції). Заодно перевіримо, що шар збігається з нашою функцією і що в нього справді немає параметрів.

::jupyter-notebook{title="pooling_in_pytorch.ipynb" executionCount="4"}

```python
import torch
import torch.nn as nn

maxpool = nn.MaxPool2d(kernel_size=2)       # крок за замовчуванням дорівнює розміру вікна
avgpool = nn.AvgPool2d(kernel_size=2)

feature_maps = torch.zeros(5, 8, 26, 26)    # 5 картинок, 8 карт ознак по 26×26
print("Вихід:", tuple(maxpool(feature_maps).shape))
print("Параметрів у пулінгу:", sum(p.numel() for p in maxpool.parameters()))

t = torch.tensor(M, dtype=torch.float32)[None, None]     # наша карта 4×4 у формі [1, 1, 4, 4]
print("\nmax:\n", maxpool(t)[0, 0].numpy())
print("average:\n", avgpool(t)[0, 0].numpy())
```

#output
```
Вихід: (5, 8, 13, 13)
Параметрів у пулінгу: 0

max:
 [[6. 5.]
 [7. 9.]]
average:
 [[3.5 2.5]
 [2.5 6. ]]
```
::

Результат збігається з нашою функцією, а розмір вийшов `[5, 8, 13, 13]`: партія та кількість каналів лишилися, а висота й ширина зменшилися вдвічі. Параметрів, як і обіцяли, нуль.

::tip
Що буде, якщо розмір не ділиться на вікно? Наприклад, 13×13 для вікна 2×2. За замовчуванням PyTorch округлює вниз і відкидає останній рядок і стовпець: `MaxPool2d(2)` дає з 13×13 розмір 6×6. Якщо потрібно не втрачати їх, є параметр `ceil_mode=True`, тоді вийде 7×7.
::

### Типовий блок: Conv → ReLU → Pool

Тепер ми можемо скласти звичну «цеглинку» згорткової мережі. Вона складається з трьох шарів підряд: згортка знаходить ознаки, ReLU залишає лише знайдене, пулінг стискає карти вдвічі. Під час проходу крізь два такі блоки подивимося, як змінюються форми тензорів.

::jupyter-notebook{title="conv_relu_pool_block.ipynb" executionCount="5"}

```python
x = torch.zeros(5, 1, 28, 28)

for name, layer in [
    ("Conv2d(1, 8, 3, padding=1)", nn.Conv2d(1, 8, 3, padding=1)),
    ("ReLU",                       nn.ReLU()),
    ("MaxPool2d(2)",               nn.MaxPool2d(2)),
    ("Conv2d(8, 8, 3, padding=1)", nn.Conv2d(8, 8, 3, padding=1)),
    ("ReLU",                       nn.ReLU()),
    ("MaxPool2d(2)",               nn.MaxPool2d(2)),
]:
    x = layer(x)
    print(f"{name:<28} → {tuple(x.shape)}")
```

#output
```
Conv2d(1, 8, 3, padding=1)   → (5, 8, 28, 28)
ReLU                         → (5, 8, 28, 28)
MaxPool2d(2)                 → (5, 8, 14, 14)
Conv2d(8, 8, 3, padding=1)   → (5, 8, 14, 14)
ReLU                         → (5, 8, 14, 14)
MaxPool2d(2)                 → (5, 8, 7, 7)
```
::

Тут ми використали `padding=1`, щоб згортка не зменшувала карту (лекція 05), а за зменшення відповідає лише пулінг: `28 → 14 → 7`. Зверніть увагу на другий `Conv2d(8, 8, …)`: його перший аргумент уже `8`, бо на вході тепер 8 карт, а не одна картинка. Як саме згортка працює з кількома вхідними каналами, ми розглянемо в окремій лекції; поки що достатньо бачити, що форми узгоджуються.

## Поле зору: як далеко «бачить» одне число

У лекції 03 ми ввели поняття **поля зору** (*receptive field*): це ділянка входу, від якої залежить одне число на виході шару. Для однієї згортки 3×3 воно дорівнює 3×3. Але що буде, якщо поставити шари один за одним?

Подумаймо спокійно. Одне число після другої згортки залежить від ділянки 3×3 карти ознак першої згортки. Кожне з цих дев'яти чисел, своєю чергою, залежить від ділянки 3×3 вхідного зображення. Ці ділянки частково перекриваються, але разом вони накривають область **5×5**. Тобто чим глибше шар, тим ширше його числа «бачать» зображення.

![Ділянка входу, від якої залежить одне число після кожного з п'яти шарів: 3, 4, 8, 10 і 18 пікселів](/images/ai-python/cnn-image-classification/pooling/04.png){.diagram-img}

### Формула поля зору

Щоб не перераховувати це вручну, виведемо правило. Для кожного шару нам потрібні два числа: його ядро `K` (розмір вікна) і крок `S`. Крім того, стежимо за двома величинами: **полем зору** `r` (на старті `1`, бо піксель бачить лише себе) і **кроком між сусідніми числами** `j` (скільки пікселів входу припадає на один зсув на карті; на старті `1`). Шар із розміром `K` і кроком `S` оновлює їх так:

::math-formula
r \leftarrow r + (K - 1) \cdot j, \qquad j \leftarrow j \cdot S
::

Перший вираз каже: ядро розміром `K` додає до поля зору ще `K − 1` сусідніх чисел, а відстань між сусідніми числами на вході дорівнює `j` пікселів. Другий — що крок `S > 1` робить сусідні числа дедалі «дальшими» одне від одного. Перевіримо в коді для стеку «Conv 3, Pool 2, Conv 3, Pool 2, Conv 3».

::jupyter-notebook{title="receptive_field.ipynb" executionCount="6"}

```python
def receptive_field(layers):
    """layers — список пар (розмір ядра, крок). Повертає поле зору після кожного шару."""
    r, jump = 1, 1
    history = []
    for kernel, stride in layers:
        r += (kernel - 1) * jump
        jump *= stride
        history.append(r)
    return history

conv3, pool2 = (3, 1), (2, 2)

print("Conv3, Pool2, Conv3, Pool2, Conv3:", receptive_field([conv3, pool2, conv3, pool2, conv3]))
print("Три Conv3 підряд:                 ", receptive_field([conv3] * 3))
print("Conv5, Pool2, Conv5:              ", receptive_field([(5, 1), pool2, (5, 1)]))
```

#output
```
Conv3, Pool2, Conv3, Pool2, Conv3: [3, 4, 8, 10, 18]
Три Conv3 підряд:                  [3, 5, 7]
Conv5, Pool2, Conv5:               [5, 6, 14]
```
::

Подивіться на перші два рядки. Три звичайні згортки дають поле зору лише `7×7`, а ті самі три згортки, між якими стоять два пулінги, — аж `18×18`, тобто майже всю цифру (28×28). **Пулінг додає до поля зору більше, ніж ще одна згортка**, бо після нього «один піксель» карти вже відповідає чотирьом пікселям входу.

### Перевіряємо формулу автоматичним диференціюванням

Формула виглядає переконливо, але добре було б переконатися на практиці. Ідея перевірки така: поле зору — це ті пікселі входу, від яких залежить вихідне число. А від яких пікселів воно залежить? Від тих, для яких градієнт `∂вихід/∂піксель` ненульовий. Тож зберемо стек, де у ядер усі ваги дорівнюють `1`, візьмемо одне вихідне число, запустимо `backward` і подивимося, у яких пікселях градієнт не нульовий.

::jupyter-notebook{title="receptive_field_check.ipynb" executionCount="7"}

```python
net = nn.Sequential(
    nn.Conv2d(1, 1, 3, bias=False), nn.AvgPool2d(2),
    nn.Conv2d(1, 1, 3, bias=False), nn.AvgPool2d(2),
    nn.Conv2d(1, 1, 3, bias=False),
)
for layer in net:
    if isinstance(layer, nn.Conv2d):
        nn.init.constant_(layer.weight, 1.0)         # усі ваги = 1

x = torch.zeros(1, 1, 28, 28, requires_grad=True)
y = net(x)
y[0, 0, 1, 1].backward()                             # беремо одне вихідне число

rows, cols = torch.nonzero(x.grad[0, 0]).T           # пікселі з ненульовим градієнтом
print("Вихід:", tuple(y.shape))
print(f"Рядки {rows.min().item()}–{rows.max().item()}, стовпці {cols.min().item()}–{cols.max().item()}")
print("Розмір ділянки:", (rows.max() - rows.min() + 1).item())
```

#output
```
Вихід: (1, 1, 3, 3)
Рядки 4–21, стовпці 4–21
Розмір ділянки: 18
```
::

Пікселі з ненульовим градієнтом утворюють квадрат 18×18 (рядки та стовпці 4–21), що **збігається з формулою**. Тут ми замість max-пулінгу взяли `AvgPool2d`, і на це є причина: у max-пулінгу градієнт іде лише до того єдиного елемента вікна, який виявився найбільшим, тож «ділянка залежності» залежала б від конкретних чисел. Це цікава особливість максимуму: він пропускає крізь себе тільки переможця. Детальніше її розберемо, коли дійдемо до навчання всієї мережі.

```
[[5. 3.]
 [3. 8.]]

 [1.5  5.75]]
```

:::accordion-item{label="📋 Завдання 2: розміри" icon="i-lucide-clipboard-list"}

Карта 28×28 тричі проходить `MaxPool2d(2)`. Які розміри вийдуть? А яким буде результат одного `MaxPool2d(3)` на 28×28?

:::

:::accordion-item{label="✅ Розв'язок" icon="i-lucide-check-circle"}

Три пулінги по 2: `28 → 14 → 7 → 3` (на останньому кроці 7 не ділиться на 2, і PyTorch відкидає зайвий рядок і стовпець). Один `MaxPool2d(3)`: `⌊(28 − 3) / 3⌋ + 1 = 9`, тож 9×9.

```python
x = torch.zeros(1, 1, 28, 28)
for _ in range(3):
    x = nn.MaxPool2d(2)(x)
    print(tuple(x.shape[2:]))
print(tuple(nn.MaxPool2d(3)(torch.zeros(1, 1, 28, 28)).shape[2:]))
```

```
(14, 14)
(7, 7)
(3, 3)
(9, 9)
```

:::

:::accordion-item{label="📋 Завдання 3: поле зору" icon="i-lucide-clipboard-list"}

Яке поле зору матиме стек «Conv 5×5, Pool 2×2, Conv 5×5»? А якби пулінг прибрали, залишивши дві згортки 5×5? Порахуйте за формулою `r ← r + (K − 1) · j`.

:::

:::accordion-item{label="✅ Розв'язок" icon="i-lucide-check-circle"}

Зі стеком: після `Conv 5`: `r = 1 + 4 · 1 = 5`, `j = 1`. Після `Pool 2`: `r = 5 + 1 · 1 = 6`, `j = 2`. Після другої `Conv 5`: `r = 6 + 4 · 2 = 14`. Без пулінгу: `r = 5`, потім `r = 5 + 4 · 1 = 9`.

```python
print(receptive_field([(5, 1), (2, 2), (5, 1)]))   # [5, 6, 14]
print(receptive_field([(5, 1), (5, 1)]))           # [5, 9]
```

Пулінг між згортками збільшив поле зору з 9 до 14 пікселів.

Пулінг пом'якшує вплив зсуву на величину порядку вікна (кореляція при зсуві на 1 піксель зростає з 0.62 до 0.78), але повної стійкості не дає.
::

::card{title="📌 Поле зору" icon="i-lucide-focus"}
Формула `r ← r + (K − 1) · j`, `j ← j · S`. Пулінг збільшує поле зору сильніше, ніж ще одна згортка: стек Conv3-Pool2-Conv3-Pool2-Conv3 бачить 18×18 із 28×28.
