# Багатоканальна згортка

::card-group

::card{title="🎯 Мета лекції" icon="i-lucide-target"}

- Навчитися рахувати параметри `nn.Conv2d` для довільних `in_channels`, `out_channels` і `kernel_size`

::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Ядро-куб (3D kernel):** ядро з розмірами `C × K × K`, де `C` — кількість вхідних каналів
- **Вхідні канали (`in_channels`):** кількість карт, які ядро бачить одночасно
- **Вихідні канали (`out_channels`):** кількість ядер у шарі (одне ядро — один вихідний канал)
- **Згортка 1×1:** ядро розміром 1×1, яке змішує канали в кожному пікселі окремо

::

## Скільки каналів бачить ядро

До цього моменту ядро було плоскою таблицею 3×3, а вхід мав один канал. Але в попередніх лекціях ми двічі натрапляли на ситуацію, коли каналів **більше**:

- **Кольорове фото** має три канали (R, G, B). Ми розкладали його на три таблиці в лекції 01 і для лекції про фільтри просто усереднили їх у сіре зображення, відклавши питання «як працювати з кольором прямо».
- **Вихід шару `Conv2d(1, 8, 3)`** — це вісім карт ознак. Наприкінці лекції про пулінг ми поставили другий шар `Conv2d(8, 8, 3)` і казали, що його перший аргумент `8` означає вісім вхідних каналів.

Тепер настав час відповісти, що це означає. Як ядро 3×3 працює, коли під ним не одна таблиця чисел, а три чи вісім? Чи застосовується воно до кожної карти окремо? І скільки карт тоді вийде на виході?

## Ідея: ядро отримує глибину

Відповідь проста, а її логіка випливає з того, що ми вже знаємо про нейрон. Нейрон бере **всі** свої входи, множить на ваги й додає. Якщо під ядром лежить ділянка 3×3 одного каналу, у нейрона 9 входів. Якщо під ним ділянка 3×3 у **трьох** каналах, у нейрона 27 входів (`3 · 3 · 3`), і ваг теж має бути 27.

Тому ядро для трьох вхідних каналів — це не плоска таблиця 3×3, а **«куб» 3×3×3**: по одній таблиці ваг на кожен канал. У кожній позиції ми беремо блок 3×3 зі **всіх** каналів, множимо його на куб ваг елемент на елемент і додаємо **всі 27 добутків в одне число**. Результат — один піксель карти ознак, незалежно від кількості вхідних каналів.

## Рахуємо вручну на реальній ділянці фото

Щоб не залишалося жодної «магії», пройдемо весь розрахунок на реальних даних. Візьмемо знайому ділянку 4×4 пікселі з краю пелюстки жоржини (її ми розкладали на канали в лекції 01) і ядро-куб, яке порівнює червоний із синім:

- шар для каналу **R**: усі ваги `+1`;
- шар для каналу **G**: усі ваги `0` (зелений нас не цікавить);
- шар для каналу **B**: усі ваги `−1`.

Сума по такому кубу дорівнює «сума червоного мінус сума синього» в ділянці 3×3: велике додатне число там, де переважає червоний (оранжеві пелюстки), і від'ємне, де переважає синій (тло). Це ядро-куб, виписане руками, без жодного навчання.

::jupyter-notebook{title="multichannel_by_hand.ipynb" kernel="Python 3.11"}

::jupyter-cell{executionCount="1"}

```python
import numpy as np
from sklearn.datasets import load_sample_image

photo = load_sample_image("flower.jpg")
patch = photo[222:226, 444:448].astype(int)       # (4, 4, 3): висота, ширина, канали
X = patch.transpose(2, 0, 1)                      # (3, 4, 4): канали першими
print("Форма ділянки (канали першими):", X.shape)

K = np.zeros((3, 3, 3), dtype=int)                # ядро-куб [канали, 3, 3]
K[0] = 1                                          # канал R: +1
K[2] = -1                                         # канал B: -1 (канал G лишається нулями)

block = X[:, 0:3, 0:3]                            # куб 3×3×3 у позиції (0, 0)
products = block * K
print("Суми по каналах:", products.sum(axis=(1, 2)))
print("Загальна сума:", products.sum())
```

#output
```
Форма ділянки (канали першими): (3, 4, 4)
Суми по каналах: [1541    0 -911]
Загальна сума: 630
```
::

::

Подивимося, що відбулося. Ми вирізали з усіх трьох каналів блок 3×3 і помножили його елемент на елемент на куб. Канал R дав `+1541` (багато червоного), G дав `0` (ваги нульові), B дав `−911` (відніманням синього). Всі три частинні суми додалися: `1541 + 0 − 911 = 630`. Саме це число стане першим пікселем карти ознак.

![Позиція (0, 0): для кожного каналу ділянка, шар ядра-куба, добуток і сума; разом +630](/images/ai-python/cnn-image-classification/multichannel-convolution/01.png){.diagram-img}

Тепер пройдемо ядром усі позиції. Ділянка 4×4 і ядро 3×3 дають карту 2×2 (за формулою `4 − 3 + 1 = 2`). Напишемо функцію для ядра-куба: це знайомий нам обхід, лише блок береться по всіх каналах.

::jupyter-notebook{title="conv_cube.ipynb" executionCount="2"}

```python
def conv_cube(x, k):
    """x: [канали, H, W], k: [канали, K, K] → карта ознак (одне число на позицію)."""
    _, h, w = x.shape
    kh = k.shape[1]
    out = np.zeros((h - kh + 1, w - kh + 1), dtype=int)
    for i in range(out.shape[0]):
        for j in range(out.shape[1]):
            out[i, j] = (x[:, i:i + kh, j:j + kh] * k).sum()    # множимо весь куб і додаємо все
    return out

O = conv_cube(X, K)
print(O)

for c, name in enumerate("RGB"):
    print(f"тільки {name}:", conv_cube(X[c:c + 1], K[c:c + 1]).tolist())

partial = sum(conv_cube(X[c:c + 1], K[c:c + 1]) for c in range(3))
print("Сума каналів збігається:", np.array_equal(O, partial))
```

#output
```
[[630 332]
 [586 304]]
тільки R: [[1541, 871], [1475, 794]]
тільки G: [[0, 0], [0, 0]]
тільки B: [[-911, -539], [-889, -490]]
Сума каналів збігається: True
```
::

Результат містить важливу думку: **згортка з кубом — це сума звичайних згорток кожного каналу окремою таблицею ваг**. Ми порахували три окремі карти (з кожного каналу своєю таблицею) і додали їх: вийшла та сама карта, що й при одному проході куба. Тобто багатоканальна згортка не вигадує нової операції, а лише додає до знайомої один крок: **складання результатів по каналах**.

### Формула

Запишемо те, що ми щойно робили, однією формулою. Для вхідних каналів `c = 0 … C − 1`:

::math-formula{tex="O[i, j] = b + \sum_{c=0}^{C-1} \sum_{u=0}^{K-1} \sum_{v=0}^{K-1} W[c, u, v] \cdot I[c,\; i + u,\; j + v]"}
::

Порівняйте з формулою з лекції 06. Додалася лише одна сума по каналах :math-formula{tex="c" inline}, а решта без змін. Один нейрон із :math-formula{tex="C \cdot K \cdot K" inline} входами й одним зсувом :math-formula{tex="b" inline}, який дивиться на різні ділянки з тими самими вагами.

## nn.Conv2d із кількома вхідними каналами

У PyTorch кількість вхідних каналів задає перший аргумент `in_channels`. Створимо шар для трьох каналів із одним ядром 3×3, покладемо в нього наш куб і перевіримо, що результат збігається з ручним розрахунком.

::jupyter-notebook{title="conv2d_three_channels.ipynb" executionCount="3"}

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

layer = nn.Conv2d(in_channels=3, out_channels=1, kernel_size=3)

with torch.no_grad():
    layer.weight[:] = torch.tensor(K, dtype=torch.float32)[None]    # [1, 3, 3, 3]
    layer.bias.zero_()

x = torch.tensor(X, dtype=torch.float32)[None]                       # [1, 3, 4, 4]
print(layer(x)[0, 0].detach().numpy())
```

#output
```
[[630. 332.]
 [586. 304.]]
```
::

Збіг із нашою `conv_cube`. Зверніть увагу на форму ваг: `[1, 3, 3, 3]`, тобто `[вихідні канали, вхідні канали, висота ядра, ширина ядра]`. Ми додали зайву вісь `[None]`, бо в шарі одне ядро-куб.

### Кілька ядер-кубів: out_channels

Одне ядро-куб шукає одну ознаку («оранжевість», вертикальний край тощо). Для різних ознак потрібні різні ядра, тому в шарі їх, як і раніше, кілька: параметр `out_channels`. Кожне ядро має **власний куб** ваг і дає **власну карту**. Усі карти складаються в стос.

::jupyter-notebook{title="conv2d_params.ipynb" executionCount="4"}

```python
layer = nn.Conv2d(3, 8, kernel_size=3)
print("weight:", tuple(layer.weight.shape), "| bias:", tuple(layer.bias.shape),
      "| параметрів:", sum(p.numel() for p in layer.parameters()))

for args in [(1, 8, 3), (3, 8, 3), (8, 8, 3), (8, 16, 3), (16, 32, 3), (3, 16, 5)]:
    n = sum(p.numel() for p in nn.Conv2d(*args).parameters())
    print(f"Conv2d{args}: {n}")
```

#output
```
weight: (8, 3, 3, 3) | bias: (8,) | параметрів: 224
Conv2d(1, 8, 3): 80
Conv2d(3, 8, 3): 224
Conv2d(8, 8, 3): 584
Conv2d(8, 16, 3): 1168
Conv2d(16, 32, 3): 4640
Conv2d(3, 16, 5): 1216
```
::

Розберемо найперший рядок: `weight` має форму `(8, 3, 3, 3)` — вісім ядер, кожне з трьох шарів по 3×3, тобто `8 · 27 = 216` ваг, плюс вісім зсувів. Разом 224. Із цього випливає загальна формула:

::math-formula{tex="\text{параметрів} = \underbrace{C_{\text{out}} \cdot C_{\text{in}} \cdot K \cdot K}_{\text{ваги}} + \underbrace{C_{\text{out}}}_{\text{зсуви}}"}
::

Перевірте її на інших рядках виводу. Для `Conv2d(8, 16, 3)`: `16 · 8 · 3 · 3 + 16 = 1152 + 16 = 1168`. Для `Conv2d(3, 16, 5)`: `16 · 3 · 5 · 5 + 16 = 1216`.

![nn.Conv2d(3, 8, 3): вхід [N, 3, H, W], вісім ядер-кубів weight [8, 3, 3, 3], вихід [N, 8, H′, W′]](/images/ai-python/cnn-image-classification/multichannel-convolution/04.png){.diagram-img}

![Кількість параметрів для шести шарів Conv2d за формулою out·in·K·K + out](/images/ai-python/cnn-image-classification/multichannel-convolution/07.png){.diagram-img}

::note
Зверніть увагу на дві речі. По-перше, кількість параметрів **не залежить від розміру картинки**: `Conv2d(3, 8, 3)` має ті самі 224 параметри на фото 28×28 і на фото 1000×1000. По-друге, вона росте разом із кількістю каналів: другий шар `Conv2d(8, 16, 3)` уже має 1168 параметрів, бо кожне з 16 ядер має шар для **кожної** з 8 вхідних карт.
::

## Кольорове фото крізь шар із двома ядрами

Подивимося, як це працює на цілому кольоровому фото. Зберемо шар `Conv2d(3, 2, 3)` із двома ядрами-кубами, які ми виписуємо вручну:

- **ядро 1** («оранжевість»): у шарі R ваги `+1/9`, у B — `−1/9`, у G — нулі. Результат: середнє червоного мінус середнє синього в ділянці 3×3.
- **ядро 2** (вертикальні краї): у кожному з трьох каналів стоїть Собель X, поділений на 3. Результат: край, знайдений по всіх каналах разом.

::jupyter-notebook{title="photo_through_two_kernels.ipynb" executionCount="5"}

```python
img = torch.tensor(photo.astype(np.float32) / 255).permute(2, 0, 1)[None]      # [1, 3, 427, 640]

weights = torch.zeros(2, 3, 3, 3)
weights[0, 0] = 1; weights[0, 2] = -1; weights[0] /= 9                         # ядро 1: R − B
sobel_x = torch.tensor([[-1, 0, 1], [-2, 0, 2], [-1, 0, 1]], dtype=torch.float32)
weights[1, :] = sobel_x / 3                                                    # ядро 2: Собель X у кожному каналі

layer = nn.Conv2d(3, 2, kernel_size=3, bias=False)
with torch.no_grad():
    layer.weight[:] = weights
out = layer(img).detach()

print("Форма входу:", tuple(img.shape))
print("Форма виходу:", tuple(out.shape))
print(f"Канал 1 (R − B): від {out[0, 0].min():.2f} до {out[0, 0].max():.2f}")
print(f"Канал 2 (краї):  від {out[0, 1].min():.2f} до {out[0, 1].max():.2f}")
print(f"Пікселів з R − B > 0.3: {(out[0, 0] > 0.3).float().mean():.0%}")
```

#output
```
Форма входу: (1, 3, 427, 640)
Форма виходу: (1, 2, 425, 638)
Канал 1 (R − B): від -0.46 до 0.91
Канал 2 (краї):  від -2.96 до 2.64
Пікселів з R − B > 0.3: 23%
```
::

Тут добре видно головну властивість багатоканальної згортки: **три вхідні канали, два вихідні**. Кількість вихідних каналів ми вибираємо самі (вона дорівнює кількості ядер), і вона ніяк не пов'язана з кількістю вхідних. Розмір `425×638` за звичною формулою: `427 − 3 + 1` і `640 − 3 + 1`.

![Кольорове фото й дві карти після Conv2d(3, 2, 3): R − B (оранжеві пелюстки) і вертикальні краї](/images/ai-python/cnn-image-classification/multichannel-convolution/05.png){.diagram-img}

На першій карті (зелене — додатне значення) оранжеві пелюстки яскраво відокремились від синьо-зеленого тла: саме такий результат ми й запрограмували ядром «червоне мінус синє». Друга карта — краї. Заради цього кольорового ядра ми не робили фото сірим: у сірому зображенні різниця між оранжевим і синім могла б зникнути, а ядро-куб бачить її напряму.

## Згортка 1×1: змішуємо канали в кожному пікселі

Є ще один цікавий випадок. Що буде, якщо взяти ядро розміром **1×1**? Спочатку здається, що це безглуздо: воно дивиться лише на один піксель. Але якщо каналів кілька, воно дивиться на **всі канали цього пікселя** і змішує їх із вагами. Ядро-куб тут має форму `C × 1 × 1`: просто `C` ваг на один піксель.

Покажемо на прикладі, який ми вже знаємо. Коли в лекції про фільтри ми робили фото сірим, ми просто усереднили канали. Стандартна формула яскравості дає кожному кольору свою вагу: `0.299 R + 0.587 G + 0.114 B` (око найчутливіше до зеленого). Це чиста згортка 1×1.

::jupyter-notebook{title="conv_1x1_gray.ipynb" executionCount="6"}

```python
gray_layer = nn.Conv2d(3, 1, kernel_size=1, bias=False)
with torch.no_grad():
    gray_layer.weight[:] = torch.tensor([0.299, 0.587, 0.114]).view(1, 3, 1, 1)

gray = gray_layer(img)[0, 0].detach()
manual = 0.299 * img[0, 0] + 0.587 * img[0, 1] + 0.114 * img[0, 2]

print("Форма:", tuple(gray.shape), "| збігається з ручною формулою:", torch.allclose(gray, manual, atol=1e-6))
print("Параметрів у Conv2d(3, 1, 1) із зсувом:", sum(p.numel() for p in nn.Conv2d(3, 1, 1).parameters()))
```

#output
```
Форма: (427, 640) | збігається з ручною формулою: True
Параметрів у Conv2d(3, 1, 1) із зсувом: 4
```
::

Розмір картинки не змінився (`427 × 640`): ядро 1×1 не зменшує карту, бо за формулою `H − 1 + 1 = H`. Змінилася лише кількість каналів: було три, стало один. Усього чотири параметри (три ваги й зсув).

![Три канали фото, помножені на ваги 0.299, 0.587 і 0.114, і їхня сума: сіре зображення](/images/ai-python/cnn-image-classification/multichannel-convolution/06.png){.diagram-img}

Згортку 1×1 використовують, щоб **змінювати кількість каналів** (стискати чи розширювати) і **змішувати** їх, не чіпаючи просторового розташування. Ми поки що її лише побачили, а детальніше повернемося до неї, коли дійдемо до глибоких архітектур.

## Стек шарів: каналів дедалі більше, картинка дедалі менша

Тепер ми можемо зрозуміти рядок `Conv2d(8, 16, 3)`, який з'явився в лекції про пулінг. Складемо два блоки «згортка → пулінг» і подивимося, як змінюються форми й скільки параметрів ми витратили.

::jupyter-notebook{title="two_blocks.ipynb" executionCount="7"}

```python
c1 = nn.Conv2d(1, 8, 3)
c2 = nn.Conv2d(8, 16, 3)

x = torch.zeros(1, 1, 28, 28)
for name, layer in [("Conv2d(1, 8, 3)", c1), ("MaxPool2d(2)", nn.MaxPool2d(2)),
                    ("Conv2d(8, 16, 3)", c2), ("MaxPool2d(2)", nn.MaxPool2d(2))]:
    x = layer(x)
    print(f"{name:<18} → {tuple(x.shape[1:])}")

print("Параметрів:", sum(p.numel() for m in (c1, c2) for p in m.parameters()))
print("weight 2-го шару:", tuple(c2.weight.shape))
```

#output
```
Conv2d(1, 8, 3)    → (8, 26, 26)
MaxPool2d(2)       → (8, 13, 13)
Conv2d(8, 16, 3)   → (16, 11, 11)
MaxPool2d(2)       → (16, 5, 5)
Параметрів: 1248
weight 2-го шару: (16, 8, 3, 3)
```
::

Подивіться на закономірність: з кожним блоком **карта зменшується** (28 → 26 → 13 → 11 → 5), а **каналів стає більше** (1 → 8 → 16). Загалом мережа ніби «обмінює» простір на смисл: пікселів стає все менше, зате на кожній позиції описано більше різних ознак. Усього на ці два шари пішло 1248 параметрів, тоді як один Dense-шар між картинкою 28×28 і всього 100 нейронами мав би 78 500.

Другий шар цікавий. Його вага має форму `(16, 8, 3, 3)`: кожне з 16 ядер має **вісім шарів по 3×3**, по одному на кожну карту першого шару. Тобто ядро другого шару бачить усі вісім карт ознак одночасно й може поєднувати їх: наприклад, скомбінувати «вертикальний край» і «горизонтальний край» у «кут». Які саме комбінації вигідні, вирішує навчання, а не ми.

::::accordion

:::accordion-item{label="❓ Чому на виході завжди один канал на ядро, а не по каналу на кожен вхідний?" icon="i-lucide-help-circle"}

Бо ядро-куб складає частинні суми всіх каналів в одне число: це і є «змішування» каналів. Якби результат лишався окремим для кожного вхідного каналу, канали ніколи б не взаємодіяли, і мережа не могла б порівнювати, наприклад, червоне із синім. Кількість вихідних каналів ми вибираємо самі (`out_channels`), і вона дорівнює кількості ядер.

:::

:::accordion-item{label="❓ Чи існує згортка, де кожен канал обробляється окремо?" icon="i-lucide-help-circle"}

Так, така згортка існує й називається *depthwise* («по глибині»). У ній кожен канал має власне плоске ядро, і результати не складаються. Вона зустрічається в легких мережах для телефонів, але в нашому курсі ми її не використовуватимемо. Для нас достатньо звичайної згортки з кубом.

:::

## Практика

::::accordion

:::accordion-item{label="📋 Завдання 1: порахуйте параметри" icon="i-lucide-clipboard-list"}

Скільки параметрів у `nn.Conv2d(3, 16, kernel_size=5)`? А якби це був `nn.Conv2d(16, 3, kernel_size=5)`? Яка формула?

:::

:::accordion-item{label="✅ Розв'язок" icon="i-lucide-check-circle"}

Для `(3, 16, 5)`: `16 · 3 · 5 · 5 + 16 = 1200 + 16 = 1216`. Для `(16, 3, 5)`: `3 · 16 · 5 · 5 + 3 = 1200 + 3 = 1203`. Ваг однакова кількість (добуток вхідних і вихідних каналів симетричний), відрізняється лише кількість зсувів: по одному на вихідний канал.

```python
print(sum(p.numel() for p in nn.Conv2d(3, 16, 5).parameters()))   # 1216
print(sum(p.numel() for p in nn.Conv2d(16, 3, 5).parameters()))   # 1203
```

:::

:::accordion-item{label="📋 Завдання 2: одне число вручну" icon="i-lucide-clipboard-list"}

Вхід має два канали розміром 2×2, а ядро-куб — два шари розміром 2×2 і зсув `b = 1`:

```python
x = torch.tensor([[[1., 2], [3, 4]],       # канал 0
                  [[0., 1], [1, 0]]])      # канал 1
k = torch.tensor([[[1., 0], [0, 1]],       # шар ядра для каналу 0
                  [[2., 2], [2, 2]]])      # шар ядра для каналу 1
```

Яке одне число вийде в карті ознак? Порахуйте вручну, а потім перевірте через `F.conv2d`.

:::

:::accordion-item{label="✅ Розв'язок" icon="i-lucide-check-circle"}

Канал 0: `1·1 + 2·0 + 3·0 + 4·1 = 5`. Канал 1: `(0 + 1 + 1 + 0) · 2 = 4`. Сума з зсувом: `5 + 4 + 1 = 10`. Розмір результату `2 − 2 + 1 = 1`, тобто одне число.

```python
print(F.conv2d(x[None], k[None], bias=torch.tensor([1.])))
```

```
tensor([[[[10.]]]])
```

:::

:::accordion-item{label="📋 Завдання 3: перестановка каналів" icon="i-lucide-clipboard-list"}

Придумайте згортку 1×1, яка міняє канали фото місцями (RGB → BGR). Яким має бути `weight` шару `Conv2d(3, 3, 1, bias=False)`? Перевірте, що результат збігається з `img[0].flip(0)`.

:::

:::accordion-item{label="✅ Розв'язок" icon="i-lucide-check-circle"}

Кожному вихідному каналу потрібно брати рівно один вхідний, тож матриця ваг `3×3` — це матриця перестановки: у кожному рядку одна одиниця.

```python
perm = torch.tensor([[0, 0, 1],       # новий канал 0 = старий канал 2 (B)
                     [0, 1, 0],       # новий канал 1 = старий канал 1 (G)
                     [1, 0, 0]], dtype=torch.float32).view(3, 3, 1, 1)

swap = nn.Conv2d(3, 3, kernel_size=1, bias=False)
with torch.no_grad():
    swap.weight[:] = perm

print("Канали розвернуто:", torch.equal(swap(img)[0], img[0].flip(0)))
```

```
Канали розвернуто: True
```

## Резюме

::card-group

::card{title="📌 Ядро-куб" icon="i-lucide-box"}
Для `C` вхідних каналів ядро має форму `C × K × K`. У кожній позиції весь блок множиться на куб і додається в одне число. Це сума звичайних згорток кожного каналу.
::

::card{title="📌 Вихідні канали" icon="i-lucide-layers"}
Кількість ядер у шарі дорівнює `out_channels`, і кожне дає свою карту. Кількість вихідних каналів не залежить від кількості вхідних.
::

::card{title="📌 Параметри" icon="i-lucide-calculator"}
`out · in · K · K + out`. Не залежать від розміру картинки: `Conv2d(3, 8, 3)` має 224 параметри на будь-якому фото.
::

::card{title="📌 Згортка 1×1" icon="i-lucide-square"}
Змішує канали в кожному пікселі, не змінюючи розмір карти. Наприклад, `Conv2d(3, 1, 1)` із вагами 0.299, 0.587, 0.114 робить фото сірим.
::

::
