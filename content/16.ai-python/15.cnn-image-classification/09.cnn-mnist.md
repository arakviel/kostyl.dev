## Усе, що потрібно, у нас уже є

Останні вісім лекцій ми збирали цеглинки по одній: згортку, ядра, що навчаються, `padding` і `stride`, пулінг, кілька каналів. Тепер настав час скласти з них повноцінну мережу й подивитися, чи справдиться те, що ми обіцяли на початку модуля: що вона працюватиме **краще** за повнозв'язну мережу з Модуля 4 і матиме **значно менше параметрів**.

План лекції простий. Спершу підготуємо дані й опишемо архітектуру. Потім навчимо дві мережі, CNN і звичайну повнозв'язну (MLP) як контрольну, на **однакових даних** з однаковим алгоритмом. Після цього перевіримо, що вийшло, і не лише за одним числом точності: розглянемо помилки, ядра, які мережа знайшла сама, і поведінку на зсунутих цифрах.

## Дані: MNIST

## Архітектура

Складемо мережу з уже знайомих шарів. Ідея така: спершу два блоки `Conv → ReLU → Pool` витягують із цифри ознаки, потім усі отримані карти розгортаються в один вектор, а останній повнозв'язний шар перетворює його на 10 чисел, по одному на кожну цифру.

![Архітектура CNN: два блоки Conv-ReLU-Pool, Flatten і Linear на 10 виходів; форми тензорів і кількість параметрів на кожному шарі](/images/ai-python/cnn-image-classification/cnn-mnist/02.png){.diagram-img}

Опишемо її як клас `nn.Module`, так само як ми робили в Модулі 4:

::jupyter-notebook{title="cnn_model.ipynb" executionCount="3"}

```python
class CNN(nn.Module):
    def __init__(self):
        super().__init__()
        self.conv1 = nn.Conv2d(1, 8, kernel_size=3, padding=1)     # 1 канал → 8 карт
        self.conv2 = nn.Conv2d(8, 16, kernel_size=3, padding=1)    # 8 карт → 16 карт
        self.pool = nn.MaxPool2d(2)                                # вдвічі менша карта
        self.fc = nn.Linear(16 * 7 * 7, 10)                        # 784 числа → 10 цифр

    def forward(self, x):
        x = self.pool(F.relu(self.conv1(x)))     # [N, 8, 14, 14]
        x = self.pool(F.relu(self.conv2(x)))     # [N, 16, 7, 7]
        return self.fc(x.flatten(1))             # [N, 784] → [N, 10]

torch.manual_seed(0)
model = CNN()
print("Вихід:", tuple(model(torch.zeros(5, 1, 28, 28)).shape))

for name, module in model.named_children():
    print(f"{name:<6} параметрів: {sum(p.numel() for p in module.parameters()):>5}")
print("Разом:", sum(p.numel() for p in model.parameters()))
```

#output
```
Вихід: (5, 10)
conv1  параметрів:    80
conv2  параметрів:  1168
pool   параметрів:     0
fc     параметрів:  7850
Разом: 9098
```
::

Розберемо цей код по шарах.

- **`conv1`:** 1 вхідний канал → 8 карт. `padding=1` зберігає розмір 28×28 (лекція 05). Параметрів `8 · 9 + 8 = 80`.
- **`pool`:** `MaxPool2d(2)` зменшує карти до 14×14 (лекція 07), параметрів немає.
- **`conv2`:** тепер на вході вже 8 карт, тому кожне з 16 ядер має вісім шарів по 3×3. Параметрів `16 · 8 · 9 + 16 = 1168` (лекція 08).
- **Другий `pool`:** карти 16 штук по 7×7.
- **`x.flatten(1)`:** розгортає кожен приклад із партії в один вектор, не чіпаючи вісь партії. Розмір `16 · 7 · 7 = 784`. Саме тому в останньому шарі `Linear(16 * 7 * 7, 10)`: число `784` не взялося з повітря, а випливає з форм попередніх шарів.
- **`fc`:** `784 · 10 + 10 = 7850` параметрів. Виходів десять: по одному на кожну цифру.

Загалом **9098 параметрів**, і найбільшу частину з них (7850, тобто 86%) займає останній повнозв'язний шар, а не згортки. Це типова картина: згортки економні, а шар, що збирає їхні відповіді, коштує дорожче.

::note
**Що таке «10 виходів».** Останній шар повертає 10 довільних чисел, які називають **логітами** (*logits*). Вони ще не є ймовірностями: можуть бути від'ємними й не додаються до одиниці. Щоб перетворити логіти на ймовірності, застосовують **softmax** (ми його вже бачили в Модулі 4). У нашій мережі softmax нарочито відсутній у `forward`: функція втрат `F.cross_entropy` рахує його всередині сама, так надійніше з чисельного погляду. Відповідь мережі — це цифра з найбільшим логітом (`argmax`).
::

### Контрольна група: повнозв'язна мережа

Щоб порівняння було чесним, нам потрібна мережа, з якою ми порівнюватимемо. Візьмемо звичайну повнозв'язну мережу з Модуля 4 (**MLP**, *multilayer perceptron*), яка просто розгортає картинку у вектор із 784 чисел і пропускає через два `Linear`-шари зі 128 нейронами у прихованому шарі.

::jupyter-notebook{title="mlp_baseline.ipynb" executionCount="4"}

```python
class MLP(nn.Module):
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(
            nn.Flatten(),
            nn.Linear(784, 128), nn.ReLU(),
            nn.Linear(128, 10),
        )

    def forward(self, x):
        return self.net(x)

torch.manual_seed(0)
mlp = MLP()
print("MLP параметрів:", sum(p.numel() for p in mlp.parameters()))
```

#output
```
MLP параметрів: 101770
```
::

У MLP **101 770** параметрів, що в 11 разів більше, ніж у CNN (9098). Перший шар `Linear(784, 128)` має `784 · 128 + 128 = 100 480` параметрів: це той самий «вибух», про який ми говорили в лекції 01, лише для маленького зображення. Ми спеціально не робимо MLP «слабким»: 128 прихованих нейронів — звична розумна конфігурація для MNIST.

## Навчання

Навчальний цикл ви знаєте з Модуля 4: для кожної партії рахуємо вихід, втрату, градієнти й робимо крок оптимізатора. Ми використаємо:

- **функцію втрат** `F.cross_entropy` (для класифікації на кілька класів, вона містить softmax);
- **оптимізатор** Adam зі швидкістю навчання `1e-3`;
- **10 епох**, тобто 10 повних проходів по 60 000 цифрах.

Після кожної епохи рахуватимемо точність на тестових даних. Оформимо все у дві функції: одна оцінює модель, друга навчає.

::jupyter-notebook{title="train_functions.ipynb" executionCount="5"}

```python
def evaluate(model, loader):
    model.eval()                       # режим оцінювання
    correct = 0
    with torch.no_grad():              # градієнти не потрібні
        for x, y in loader:
            correct += (model(x).argmax(1) == y).sum().item()
    return correct / len(loader.dataset)

def train(model, epochs=10, lr=1e-3, seed=0, verbose=True):
    loader = DataLoader(train_set, batch_size=64, shuffle=True,
                        generator=torch.Generator().manual_seed(seed))
    optimizer = torch.optim.Adam(model.parameters(), lr=lr)
    for epoch in range(1, epochs + 1):
        model.train()
        total = 0
        for x, y in loader:
            loss = F.cross_entropy(model(x), y)
            optimizer.zero_grad()
            loss.backward()
            optimizer.step()
            total += loss.item() * len(y)
        if verbose:
            print(f"Епоха {epoch:>2}: втрата {total / len(train_set):.4f}, "
                  f"точність на тесті {evaluate(model, test_loader):.2%}")
    return evaluate(model, test_loader)
```
::

Запустимо спочатку CNN, потім MLP. На ноутбуці одна епоха CNN займає близько 9 секунд, а MLP — близько 1,5 секунди.

### Що показали результати

Розберемо цей вивід, бо в ньому кілька важливих спостережень.

**1. CNN виграє майже з першої епохи.** Уже після першої епохи CNN дає `96.72%`, а MLP — лише `94.64%`. Наприкінці десятої епохи маємо `98.70%` проти `97.66%`. Тобто CNN робить майже вдвічі менше помилок: **130 проти 234** на 10 000 тестових цифр (порахуємо нижче). І це при тому, що в неї в 11 разів менше параметрів.

**2. Точність на тесті «стрибає» між епохами.** У CNN `98.82%` на 8-й епосі, `98.51%` на 9-й, `98.70%` на 10-й; у MLP `98.11%`, потім `97.49%`, потім `97.66%`. Це нормально: кожен крок Adam трохи змінює ваги, а на 10 000 цифр кілька змінених відповідей дають такі коливання. Звідси правило: **не вибирайте «найкращу епоху» за тестовими даними**. Якби ми вирішили, що результат MLP — це `98.11%` (найкраща епоха), то підгледіли б у тесті й завищили оцінку. Ми завжди беремо результат **останньої** епохи, наперед визначеної кількості.

**3. Втрата на навчальній вибірці й точність на тесті розходяться.** До 10-ї епохи в MLP втрата на навчанні **менша** (`0.0251`), ніж у CNN (`0.0326`), а на тесті MLP **гірша**. Тобто MLP краще підлаштувалася під навчальні цифри, але гірше узагальнює: це початок перенавчання (Модуль 3). Імовірно, річ у тому, що в CNN вбудовані припущення про зображення (локальність, спільні ваги), і мережі з такими обмеженнями важче «запам'ятати» окремі приклади, але напряму ми цього не перевіряли.

### Чи це не збіг? Три запуски

Одна пара чисел може виявитися випадковою: із іншою ініціалізацією результат був би інший. Щоб перевірити, чи перевага CNN стійка, навчимо кожну мережу ще двічі з іншими зернами (`seed = 1` та `2`). Ця клітинка працює кілька хвилин, бо навчає шість мереж.

::jupyter-notebook{title="three_seeds.ipynb" executionCount="7"}

```python
for name, cls in [("MLP", MLP), ("CNN", CNN)]:
    finals = []
    for seed in (0, 1, 2):
        torch.manual_seed(seed)
        finals.append(train(cls(), seed=seed, verbose=False))
    print(f"{name}: " + ", ".join(f"{a:.2%}" for a in finals) +
          f"  → середнє {sum(finals) / len(finals):.2%}")
```

## Де CNN помиляється

Точність `98.70%` звучить чудово, але вона ховає деталі. Подивимося, **які саме** цифри мережа плутає. Для цього зберемо всі відповіді на тестовій вибірці й побудуємо матрицю помилок: рядок — справжня цифра, стовпець — передбачена.

::jupyter-notebook{title="errors_analysis.ipynb" executionCount="8"}

```python
def predict_all(model):
    model.eval()
    out = []
    with torch.no_grad():
        for x, y in test_loader:
            out.append(model(x).argmax(1))
    return torch.cat(out)

truth = test_set.targets
pred = predict_all(model)
errors = (pred != truth).nonzero().flatten()
print("Помилок CNN:", len(errors), "із", len(test_set), "| MLP:", int((predict_all(mlp) != truth).sum()))

cm = torch.zeros(10, 10, dtype=torch.long)       # матриця помилок
for t, p in zip(truth, pred):
    cm[t, p] += 1

pairs = sorted([(cm[i, j].item(), i, j) for i in range(10) for j in range(10) if i != j], reverse=True)
for count, i, j in pairs[:5]:
    print(f"справжня {i} → передбачено {j}: {count} разів")
print("Перші помилки (індекси):", errors[:6].tolist())
```

Не варто очікувати, що вони будуть схожі на ідеальні ядра з підручника, і справді не схожі. Це чесна відповідь: **ядра оптимізовані під задачу, а не під людську інтуїцію**. Проте в них проглядається структура:

- У деяких ядер ваги мають чіткий знак по частинах: наприклад, у ядра 1 верхній рядок від'ємний (`−0.17, −0.63, −0.76`), а нижній додатний (`0.56, 0.77, 0.48`). Воно реагує на межу «темно зверху — світло знизу», тобто на горизонтальну межу.
- Ядро 8 майже все додатне: це ніби «детектор яскравості» (згладжене підсумовування).
- Ядро 2 має найрізкіші контрасти (від `−1.38` до `1.02`): діагональ із додатних і від'ємних ваг. Схоже, воно чутливе до косих структур, але це лише наше припущення з погляду на числа.
- У ядер різні зсуви `bias` (від `−0.01` до `+0.52`), і це теж навчені параметри.

Заради чесності: не варто ґрунтуватися на окремих ядрах, щоб стверджувати «тут мережа шукає краї». Із 72 ваг (`8 · 9`) і 8 зсувів складно за поглядом прочитати, що саме мережа «думає»: можна лише побачити, що вони різні й мають структуру. Корисніше дивитися на те, що вони **роблять** із цифрою.

## Мережа вдивляється в зсунуту цифру

Тепер перевіримо те, чим ми мотивували весь модуль: стійкість до зсуву. У лекції 01 ми показали, що для повнозв'язної мережі зсунута цифра — це «майже інший вхід». Чи допомогла згортка? Зсуватимемо **всі** 10 000 тестових цифр вправо на 0–6 пікселів (без обгортання) і подивимося, як змінюється точність обох мереж. Обидві навчені на звичайних, незсунутих цифрах.

::jupyter-notebook{title="shift_test.ipynb" executionCount="10"}

```python
X_test = torch.stack([test_set[i][0] for i in range(len(test_set))])    # усі тестові цифри [10000, 1, 28, 28]

def shift_images(x, s):
    y = torch.roll(x, s, dims=3)       # зсув вправо на s пікселів
    if s > 0:
        y[..., :s] = 0                 # без обгортання: ліві стовпці порожні
    return y

print("зсув | MLP     | CNN")
for s in range(7):
    xs = shift_images(X_test, s)
    print(f"{s:>4} | {(mlp(xs).argmax(1) == truth).float().mean():.2%} | {(model(xs).argmax(1) == truth).float().mean():.2%}")
```

#output
```
зсув | MLP     | CNN
   0 | 97.66% | 98.70%
   1 | 95.96% | 98.10%
   2 | 85.66% | 95.89%
   3 | 63.63% | 86.94%
   4 | 39.86% | 68.70%
   5 | 23.50% | 48.48%
   6 | 13.59% | 29.40%
```
::

Результат важливий, і його варто прочитати без прикрас.

- **CNN значно краща:** на зсуві 2 пікселі вона тримає `95.89%` проти `85.66%` в MLP, на зсуві 3 — `86.94%` проти `63.63%`.
- **Але повної стійкості немає.** На зсуві 4 пікселі CNN падає до `68.70%`, на 6 — до `29.40%`. Тобто вона сильно залежить від положення цифри теж, просто повільніше за MLP.
- **Чому так?** Згортка й пулінг справді пом'якшують зсув (лекція 07), але останній шар `Linear(784, 10)` має **окремі ваги для кожної позиції** на карті 7×7. Він навчився, що «саме тут на карті має бути верхня перекладина сімки», і коли цифра зсунулася далеко, ці очікування не виконуються.

Тож «згортка розв'язує проблему зсуву» — це правда лише частково: вона **зменшує** її, але не прибирає. Прийоми, які роблять мережу ще стійкішою (наприклад, показувати їй під час навчання зсунуті цифри або усереднювати відповіді по всій карті замість окремих ваг на кожну позицію), ми обговоримо пізніше.

## Як мережа «говорить» відповідь

Наостанок подивимося, що мережа видає для одного зображення. Візьмемо softmax від логітів і подивимося на три найімовірніші цифри для двох прикладів: першої тестової цифри «7» і першої помилки (тест №18, справжня цифра «3»).

::jupyter-notebook{title="predicted_probabilities.ipynb" executionCount="11"}

```python
with torch.no_grad():
    for idx in (0, errors[0].item()):
        p = model(X_test[idx][None]).softmax(1)[0]
        top = p.topk(3)
        print(f"тест №{idx} (істина {truth[idx].item()}):",
              ", ".join(f"{c.item()} — {v.item():.1%}" for v, c in zip(top.values, top.indices)))
```

#output
```
тест №0 (істина 7): 7 — 100.0%, 3 — 0.0%, 9 — 0.0%
тест №18 (істина 3): 8 — 92.7%, 5 — 5.5%, 3 — 1.8%
```
::

У першому випадку мережа каже «7» зі стовідсотковою впевненістю. У другому вона на `92.7%` впевнена, що це «8», і лише на `1.8%` бачить правильну відповідь «3». Тобто softmax-«впевненість» **не те саме, що ймовірність бути правим**: мережа може впевнено помилятись, особливо на цифрах, схожих на інші.

## Практика

::::accordion

:::accordion-item{label="📋 Завдання 1: порахуйте параметри ширшої мережі" icon="i-lucide-clipboard-list"}

Зробимо мережу ширшою: `Conv2d(1, 16, 3, padding=1)`, `MaxPool2d(2)`, `Conv2d(16, 32, 3, padding=1)`, `MaxPool2d(2)`, `Linear(32 * 7 * 7, 10)`. Скільки в ній параметрів? Порахуйте вручну, а потім перевірте кодом.

:::

:::accordion-item{label="✅ Розв'язок" icon="i-lucide-check-circle"}

Перша згортка: `16 · 1 · 9 + 16 = 160`. Друга: `32 · 16 · 9 + 32 = 4640`. Останній шар: вхід `32 · 7 · 7 = 1568`, тож `1568 · 10 + 10 = 15 690`. Разом `160 + 4640 + 15 690 = 20 490`.

```python
wide = nn.Sequential(
    nn.Conv2d(1, 16, 3, padding=1),
    nn.Conv2d(16, 32, 3, padding=1),
    nn.Linear(32 * 7 * 7, 10),
)
print(sum(p.numel() for p in wide.parameters()))
```

```
20490
```

Це все ще в 5 разів менше, ніж у MLP (101 770).

:::

:::accordion-item{label="📋 Завдання 2: без padding" icon="i-lucide-clipboard-list"}

Що зміниться, якщо в обох згортках прибрати `padding=1`? Які будуть розміри карт на кожному кроці, яким має бути вхід останнього `Linear` і скільки параметрів вийде?

:::

:::accordion-item{label="✅ Розв'язок" icon="i-lucide-check-circle"}

Без padding розмір рахується за формулою `H − K + 1`, а пулінг ділить на два з округленням вниз: `28 → 26 → 13 → 11 → 5`. Після другого пулінгу маємо 16 карт 5×5, отже вхід `Linear` дорівнює `16 · 5 · 5 = 400`. Параметри: `80 + 1168 + (400 · 10 + 10) = 80 + 1168 + 4010 = 5258`.

```python
x = torch.zeros(1, 1, 28, 28)
for layer in (nn.Conv2d(1, 8, 3), nn.MaxPool2d(2), nn.Conv2d(8, 16, 3), nn.MaxPool2d(2)):
    x = layer(x)
    print(tuple(x.shape[1:]))
```

```
(8, 26, 26)
(8, 13, 13)
(16, 11, 11)
(16, 5, 5)
```

Мережа вийшла ще компактнішою (5258 параметрів), але на краї картинки вона втратила частину інформації (лекція 05). Якби ми забули змінити `Linear(16 * 7 * 7, 10)` на `Linear(16 * 5 * 5, 10)`, PyTorch видав би помилку про невідповідність форм.

:::

:::accordion-item{label="📋 Завдання 3: де живуть параметри" icon="i-lucide-clipboard-list"}

Яку частку всіх параметрів нашої CNN (`model`) займає останній шар `fc`? Порахуйте кодом і поясніть, чому так.

:::

:::accordion-item{label="✅ Розв'язок" icon="i-lucide-check-circle"}

```python
fc_params = sum(p.numel() for p in model.fc.parameters())
```

Не вибирайте «кращу епоху» за тестом. Точність коливається між епохами. Менша втрата на навчанні в MLP при гіршій точності на тесті — ознака перенавчання.
::

::card{title="📌 Зсув" icon="i-lucide-move"}
CNN стійкіша до зсуву, ніж MLP (95.9% проти 85.7% на 2 пікселях), але не стійка повністю: на 6 пікселях лише 29.4%. Причина — позиційні ваги останнього `Linear`.

**У наступній лекції** ми перейдемо від чорно-білих цифр до **кольорових фотографій**. Ми візьмемо датасет CIFAR-10 (літаки, автомобілі, коти, собаки та ще шість класів на зображеннях 32×32×3), застосуємо ту саму ідею, що працювала для цифр, і побачимо, що задача набагато складніша: точність буде значно нижчою, а мережа почне **явно перенавчатись**. Це підведе нас до наступних тем: як будувати глибші мережі та як із перенавчанням боротися.
