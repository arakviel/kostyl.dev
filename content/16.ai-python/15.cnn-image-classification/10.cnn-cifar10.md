## Від цифр до фото

На цифрах MNIST ми побудували мережу з 9 098 параметрів і дістали майже **99%** точності. Виникає природне запитання: чи вдасться те саме на справжніх фотографіях? Спойлер: ні, і причина не в тому, що наша мережа «погана», а в тому, що **задача набагато складніша**.

Ця лекція завершує модуль. Ми візьмемо ідею, яка спрацювала для цифр, застосуємо її до кольорових фото й чесно подивимося, що з цього вийде: які результати, де мережа помиляється й чому. Відповіді підготують нас до наступних тем курсу.

## Дані: CIFAR-10

Датасет **CIFAR-10** складається з 60 000 кольорових фото розміром 32×32 пікселі у 10 класах. Із них 50 000 призначені для навчання, 10 000 — для перевірки. Класи рівномірні: по 6 000 фото кожного. Завантажимо його так само, як MNIST.

::jupyter-notebook{title="cifar_data.ipynb" kernel="Python 3.11"}

::jupyter-cell{executionCount="1"}

```python
import torch
import torch.nn as nn
import torch.nn.functional as F
from torch.utils.data import DataLoader
from torchvision import datasets, transforms

transform = transforms.ToTensor()      # фото → тензор [3, 32, 32], значення від 0 до 1

train_set = datasets.CIFAR10(root="data", train=True, download=True, transform=transform)
test_set = datasets.CIFAR10(root="data", train=False, download=True, transform=transform)

print("Навчальних:", len(train_set), "| тестових:", len(test_set))
print("Класи:", train_set.classes)

image, label = train_set[0]
print("Одне зображення:", tuple(image.shape), "| мітка:", label, "→", train_set.classes[label])
print(f"Значення пікселів: від {image.min():.1f} до {image.max():.1f}")
```

### Чому це складніше за цифри

Подивіться на кілька «котів» поруч із кількома «сімками». Усі сімки — це білий штрих на чорному тлі, і вони відрізняються лише почерком. А коти — це різні породи, пози, ракурси, освітлення, а ще різне тло: диван, трава, червона ковдра. Ознака «кіт» не зводиться до жодної простої форми, яку можна було б знайти одним ядром.

На додачу зображення дуже маленьке: 32×32 пікселі — це лише 1 024 пікселі на канал, і в цих пікселях дрібні деталі (вуха, очі, колеса) складаються з кількох точок. Навіть людині іноді важко розпізнати такі фото.

## Дві контрольні мережі

Почнемо з двох простих моделей, щоб мати з чим порівнювати.

**Перша — повнозв'язна мережа (MLP)** із Модуля 4: розгортає фото у вектор із `3 · 32 · 32 = 3072` чисел і пропускає через два шари.

**Друга — мала CNN**, яка є майже точною копією нашої мережі для MNIST: два блоки `Conv → ReLU → Pool`, а потім один `Linear`. Змінилося лише три речі: на вході три канали замість одного, розмір карти після двох пулінгів `8×8` (бо `32 → 16 → 8`) і, відповідно, `32 · 8 · 8 = 2048` входів в останньому шарі. Каналів ми взяли трохи більше (16 і 32), бо фото складніші за цифри.

::jupyter-notebook{title="cifar_baselines.ipynb" executionCount="2"}

```python
class MLP(nn.Module):
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(nn.Flatten(), nn.Linear(3072, 256), nn.ReLU(), nn.Linear(256, 10))

    def forward(self, x):
        return self.net(x)

class SmallCNN(nn.Module):
    def __init__(self):
        super().__init__()
        self.conv1 = nn.Conv2d(3, 16, kernel_size=3, padding=1)
        self.conv2 = nn.Conv2d(16, 32, kernel_size=3, padding=1)
        self.pool = nn.MaxPool2d(2)
        self.fc = nn.Linear(32 * 8 * 8, 10)

    def forward(self, x):
        x = self.pool(F.relu(self.conv1(x)))      # [N, 16, 16, 16]
        x = self.pool(F.relu(self.conv2(x)))      # [N, 32, 8, 8]
        return self.fc(x.flatten(1))

for name, cls in [("MLP", MLP), ("SmallCNN", SmallCNN)]:
    torch.manual_seed(0)
    model = cls()
    print(f"{name:<9} параметрів: {sum(p.numel() for p in model.parameters()):>7}")
```

Тепер потрібна функція навчання. Вона схожа на ту, що була в попередній лекції, але з двома доповненнями. По-перше, після кожної епохи ми рахуємо **і втрату, і точність** на тестових даних. По-друге, ми рахуємо точність і на частині **навчальних** даних (перших 10 000 фото): саме порівняння цих двох точностей покаже перенавчання.

::jupyter-notebook{title="cifar_training.ipynb" executionCount="3"}

```python
x_train10 = torch.stack([train_set[i][0] for i in range(10000)])    # частина навчальних фото
y_train10 = torch.tensor(train_set.targets[:10000])
x_test = torch.stack([test_set[i][0] for i in range(len(test_set))])
y_test = torch.tensor(test_set.targets)

def evaluate(model, x, y, batch=1000):
    model.eval()                                  # вимикає Dropout, якщо він є
    loss = correct = 0
    with torch.no_grad():
        for i in range(0, len(x), batch):
            out = model(x[i:i + batch])
            loss += F.cross_entropy(out, y[i:i + batch], reduction="sum").item()
            correct += (out.argmax(1) == y[i:i + batch]).sum().item()
    return loss / len(x), correct / len(x)

def train(model, epochs=12, lr=1e-3, seed=0, verbose=True):
    loader = DataLoader(train_set, batch_size=64, shuffle=True,
                        generator=torch.Generator().manual_seed(seed))
    optimizer = torch.optim.Adam(model.parameters(), lr=lr)
    for epoch in range(1, epochs + 1):
        model.train()
        total = 0
        for x, y in loader:
            loss = F.cross_entropy(model(x), y)
            optimizer.zero_grad()
            loss.backward()
            optimizer.step()
            total += loss.item() * len(y)
        train_acc = evaluate(model, x_train10, y_train10)[1]
        test_loss, test_acc = evaluate(model, x_test, y_test)
        if verbose:
            print(f"Епоха {epoch:>2}: втрата {total / len(train_set):.3f} | навчальні {train_acc:.1%} | "
                  f"тест {test_acc:.1%} (втрата {test_loss:.3f})")
    return train_acc, test_acc
```
::

Навчимо обидві контрольні мережі на 12 епох. MLP робить це за хвилину, мала CNN потребує близько 2–3 хвилин.

::jupyter-notebook{title="cifar_baselines_train.ipynb" executionCount="4"}

```python
for name, cls in [("MLP", MLP), ("SmallCNN", SmallCNN)]:
    torch.manual_seed(0)
    train_acc, test_acc = train(cls(), verbose=False)
    print(f"{name}: навчальні {train_acc:.1%}, тест {test_acc:.1%}")
```

Мала CNN дає **67,7%**, що значно краще, але **набагато гірше за 98,7% на цифрах** при майже тій самій архітектурі. Для порівняння: випадкове вгадування дало б 10%.

## Ширша й глибша мережа

Мала CNN упирається у власну ємність: 16 і 32 ядра — це мало, щоб описати ознаки десяти різних класів фото. Логічний крок — **збільшити мережу**: більше каналів і ще один блок `Conv → ReLU → Pool`. Додамо також проміжний повнозв'язний шар зі 128 нейронами перед виходом, щоб мережа могла комбінувати знайдені ознаки.

![Архітектура ширшої CNN: три блоки Conv-ReLU-Pool, Flatten, Linear(2048, 128) і Linear(128, 10); форми тензорів і параметри](/images/ai-python/cnn-image-classification/cnn-cifar10/03.png){.diagram-img}

::jupyter-notebook{title="wide_cnn.ipynb" executionCount="5"}

```python
class WideCNN(nn.Module):
    def __init__(self, dropout=0.0):
        super().__init__()
        self.conv1 = nn.Conv2d(3, 32, kernel_size=3, padding=1)
        self.conv2 = nn.Conv2d(32, 64, kernel_size=3, padding=1)
        self.conv3 = nn.Conv2d(64, 128, kernel_size=3, padding=1)
        self.pool = nn.MaxPool2d(2)
        self.fc1 = nn.Linear(128 * 4 * 4, 128)
        self.dropout = nn.Dropout(dropout)           # поки що dropout = 0, тобто вимкнений
        self.fc2 = nn.Linear(128, 10)

    def forward(self, x):
        x = self.pool(F.relu(self.conv1(x)))         # [N, 32, 16, 16]
        x = self.pool(F.relu(self.conv2(x)))         # [N, 64, 8, 8]
        x = self.pool(F.relu(self.conv3(x)))         # [N, 128, 4, 4]
        x = self.dropout(F.relu(self.fc1(x.flatten(1))))
        return self.fc2(x)

torch.manual_seed(0)
model = WideCNN()
for name, module in model.named_children():
    print(f"{name:<8} {sum(p.numel() for p in module.parameters()):>7}")
print("Разом:", sum(p.numel() for p in model.parameters()))
```

## Діагностика перенавчання

Подивіться на два стовпці виводу: «навчальні» і «тест». Вони ростуть разом лише перші 3–4 епохи. Далі навчальна точність продовжує зростати (з 70,5% до 89,3%), а тестова застигає на рівні 73–74,5%. Розрив між ними розкривається: на 3-й епосі він 3 п. п., на 8-й — 11,5 п. п., на 12-й — **16 п. п.**

Це класичне **перенавчання** (*overfitting*), яке ви знаєте з Модуля 3: мережа дедалі краще запам'ятовує навчальні фото й не стає кращою на нових. У нашому випадку вона навіть має чим запам'ятовувати: 356 810 параметрів на 50 000 фото.

Зверніть увагу на два цікавих моменти.

**Точність і втрата показують перенавчання по-різному.** Тестова **точність** майже не падає: вона коливається між 73% і 74,5%. А от тестова **втрата** після 8-ї епохи зростає від `0.770` до `0.929`. Чому? Втрата вимірює не лише «вгадав чи ні», а й **наскільки впевнено** мережа відповіла. Перенавчена мережа стає надто впевненою у відповідях, зокрема в помилкових, і втрата зростає, навіть якщо кількість правильних відповідей лишається приблизно тією самою. Тому дивитися лише на точність небезпечно: перенавчання вже триває, а точність цього ще не показує.

**Краща епоха за тестом — це підгляд.** Максимальна тестова точність (74,5%) була на 10-й епосі, а мінімальна втрата — на 8-й. Спокусливо сказати «зупинимось на епосі 10». Але ми вибирали б епоху **за тестовими даними**, тобто підлаштувалися б під них і завищили оцінку. У справжньому проєкті для таких рішень використовують окрему **валідаційну** вибірку (Модуль 3), а тестову не чіпають до самого кінця. У цій лекції ми, як і раніше, фіксуємо 12 епох заздалегідь і дивимося на останню.

## Перший засіб: Dropout

Один із засобів проти перенавчання ви вже знаєте з Модуля 4: **Dropout**. Під час навчання він випадково «вимикає» (обнуляє) частину нейронів шару, зокрема кожен із них із ймовірністю `p`. Мережа не може покладатися на конкретні нейрони і змушена навчитися надійніших, розподілених ознак. Під час оцінювання (`model.eval()`) Dropout вимикається, і мережа працює у повному складі.

Ми вже передбачили для нього місце: у `WideCNN` є параметр `dropout`. Поставимо `0.5` (вимикається половина нейронів після `fc1`, саме там, де сидить більшість параметрів) і навчимо ту саму мережу з тим самим зерном. Нічого іншого не змінюємо, щоб різницю дав лише Dropout.

::jupyter-notebook{title="wide_cnn_dropout.ipynb" executionCount="7"}

```python
torch.manual_seed(0)
wide_drop = WideCNN(dropout=0.5)
train(wide_drop)
```

### Чи це не випадковість? Три запуски

Один запуск нічого не доводить. Повторимо обидва експерименти ще з двома зернами (`seed = 1` і `2`). Ця клітинка найдовша: вона навчає шість мереж по 6 хвилин, тобто близько 35 хвилин.

::jupyter-notebook{title="wide_three_seeds.ipynb" executionCount="8"}

```python
for label, p in [("WideCNN", 0.0), ("WideCNN + Dropout", 0.5)]:
    tests, gaps = [], []
    for seed in (0, 1, 2):
        torch.manual_seed(seed)
        train_acc, test_acc = train(WideCNN(dropout=p), seed=seed, verbose=False)
        tests.append(test_acc)
        gaps.append((train_acc - test_acc) * 100)
    print(f"{label}: тест " + ", ".join(f"{a:.2%}" for a in tests) +
          f" → середнє {sum(tests) / len(tests):.2%}; розрив " +
          ", ".join(f"{g:.1f}" for g in gaps) + " п. п.")
```

#output
```
WideCNN: тест 73.28%, 73.49%, 74.73% → середнє 73.83%; розрив 16.0, 16.3, 16.6 п. п.
WideCNN + Dropout: тест 73.45%, 74.65%, 73.60% → середнє 73.90%; розрив 9.8, 10.0, 8.5 п. п.
```

Висновок із трьох запусків чіткий:

- **Точність: без різниці.** Середні `73,83%` і `73,90%` відрізняються на 0,07 п. п., а розкид між запусками одного варіанту (`73,28–74,73%`) набагато більший. Тобто Dropout не покращив точність.
- **Розрив: стабільно менший.** У всіх трьох запусках `8,5–10,0` п. п. із Dropout проти `16,0–16,6` без нього. Ефект на розрив стійкий і явний.

Тому чесна відповідь така: **Dropout зменшив перенавчання, але не збільшив точність** на цьому наборі й за 12 епох. Це важлива пересторога для будь-якого проєкту: засіб проти перенавчання не гарантує кращого результату. Зменшення розриву означає, що модель стала «чесніше» оцінювати себе, а не що вона стала розумнішою.

Ми не робили їх перебору, тож не варто робити з цього висновку «Dropout не допомагає». Висновок лише такий: за нашими налаштуваннями він розрив зменшив, а точність не покращив.

## Де мережа помиляється

73,5% — це в середньому. Подивимося, **які саме** класи мережа розпізнає легко, а які погано. Візьмемо модель із Dropout, зберемо її відповіді й порахуємо точність за кожним класом та найчастіші плутанини.

::jupyter-notebook{title="cifar_errors.ipynb" executionCount="9"}

```python
def predict_proba(model, x, batch=1000):
    model.eval()
    with torch.no_grad():
        return torch.cat([model(x[i:i + batch]).softmax(1) for i in range(0, len(x), batch)])

probs = predict_proba(wide_drop, x_test)
pred = probs.argmax(1)
errors = (pred != y_test).nonzero().flatten()
print("Помилок:", len(errors), "із", len(y_test))

cm = torch.zeros(10, 10, dtype=torch.long)           # матриця помилок
for t, p in zip(y_test, pred):
    cm[t, p] += 1

print("\nТочність за класами (від найгіршого):")
for i in sorted(range(10), key=lambda i: cm[i, i] / cm[i].sum()):
    print(f"  {names[i]:<11} {cm[i, i].item() / cm[i].sum().item():.1%}")

print()
pairs = sorted([(cm[i, j].item(), i, j) for i in range(10) for j in range(10) if i != j], reverse=True)
for count, i, j in pairs[:5]:
    print(f"справжній {names[i]} → передбачено {names[j]}: {count} разів")
```

## Чого цій мережі бракує

Підсумуємо, що ми побачили.

- Ширша CNN набагато краща за повнозв'язну: `73,3%` проти `45,7%`, і з утричі меншою кількістю параметрів.
- Проте `74%` — це далеко від `99%` на цифрах, і приблизно кожне четверте фото (26,5%) класифіковано неправильно.
- Мережа **перенавчається**: розрив між навчанням і тестом сягає 16 п. п., а тестова втрата після 8-ї епохи зростає.
- Dropout зменшує розрив, але точності не додає.
- Найгірше розпізнаються кіт, собака, птах і олень, особливо кіт (46,2%).

Звідси видно, куди рухатися далі. Мережі потрібно **більше різноманітності в навчальних даних** (щоб вона не запам'ятовувала конкретні фото), **стабільніше навчання** глибших мереж і **архітектури, які краще використовують глибину**. Саме про це йдеться в наступних темах курсу: аугментація даних (штучне створення нових фото з наявних: відображення, повороти, зсуви), нормалізація всередині мережі й глибокі архітектури з обхідними з'єднаннями (ResNet).

::tip
Ми зупинились на мережі зі 356 810 параметрами й 12 епохами, тому що цього достатньо, щоб побачити всі явища: складність задачі, перенавчання, обмеження Dropout. Покращення результату — окрема велика тема, і ми до неї дійдемо.

## Практика

::::accordion

:::accordion-item{label="📋 Завдання 1: менший прихований шар" icon="i-lucide-clipboard-list"}

Якщо в `WideCNN` замінити `fc1 = Linear(2048, 128)` на `Linear(2048, 64)` (і відповідно `fc2 = Linear(64, 10)`), скільки параметрів стане в мережі? Скільки з них у `fc1`?

:::

:::accordion-item{label="✅ Розв'язок" icon="i-lucide-check-circle"}

`fc1`: `2048 · 64 + 64 = 131 136`. `fc2`: `64 · 10 + 10 = 650`. Згортки без змін: `896 + 18 496 + 73 856 = 93 248`. Разом `93 248 + 131 136 + 650 = 225 034`.

Параметрів стало на 37% менше (було 356 810), бо найбільшу частину займає саме `fc1`.

:::

:::accordion-item{label="📋 Завдання 2: четвертий блок" icon="i-lucide-clipboard-list"}

Додамо до мережі четвертий блок `Conv2d(128, 256, 3, padding=1)` + `MaxPool2d(2)`. Яким стане розмір карти перед `Flatten`, яким буде вхід `fc1` і скільки параметрів у мережі? Куди зсунулася більшість параметрів?

:::

:::accordion-item{label="✅ Розв'язок" icon="i-lucide-check-circle"}

Після четвертого пулінгу карта стає `2×2` (`4 → 2`), каналів 256, тому вхід `fc1` дорівнює `256 · 2 · 2 = 1024`. Параметри: `conv4 = 256 · 128 · 9 + 256 = 295 168`, `fc1 = 1024 · 128 + 128 = 131 200`. Загалом `896 + 18 496 + 73 856 + 295 168 + 131 200 + 1290 = 520 906`.

Більшість параметрів тепер у згорткових шарах (особливо в `conv4`), а `fc1` скоротився вдвічі. Глибша мережа переносить «вагу» зі склеювального шару на згортки.

:::

:::accordion-item{label="📋 Завдання 3: що плутає кожен клас" icon="i-lucide-clipboard-list"}

Для кожного класу знайдіть, у який інший клас мережа помиляється найчастіше. Чи вони про щось говорять?

:::

:::accordion-item{label="✅ Розв'язок" icon="i-lucide-check-circle"}

```python
for i in range(10):
    row = cm[i].clone()
    row[i] = -1                              # виключаємо правильні відповіді
    j = int(row.argmax())
    print(f"{names[i]:<11} найчастіше → {names[j]:<10} ({cm[i, j].item()} із {cm[i].sum().item() - cm[i, i].item()} помилок)")
```

## Підсумок модуля

Пройдемо шлях модуля ще раз, бо він побудований на одній ідеї: **кожна нова деталь розв'язувала проблему, яку створила попередня**.

| Лекція | Проблема | Що з'явилося |
| :--- | :--- | :--- |
| 01. Комп'ютерний зір | Dense-мережа не годиться для картинок | Зображення як тензор, чотири проблеми |
| 02. Навіщо згортка | Як шукати ознаку будь-де на картинці | Локальні зв'язки й спільні ваги: згортка |
| 03. Згортка крок за кроком | Як це рахується | Ядро, карта ознак, `H − K + 1`, NumPy |
| 04. Фільтри | Що «бачить» ядро | Краї, розмиття, правило суми ваг |
| 05. Padding і stride | Карта зменшується, краї рахуються рідше | Рамка з нулів, крок, загальна формула |
| 06. Ядро, що навчається | Хто вигадає ядра | `nn.Conv2d`, навчання градієнтним спуском |
| 07. Пулінг | Забагато чисел, не потрібна точна позиція | Max/average-пулінг, поле зору |
| 08. Багатоканальна згортка | Колір і кілька карт на вході | Ядро-куб, `out_channels`, згортка 1×1 |
| 09. CNN для MNIST | Зібрати все разом | Повна мережа: 98,7% при 9 098 параметрах |
| 10. CNN для CIFAR-10 | Складніша задача | Перенавчання, Dropout, чесна оцінка |

**У наступних темах** ми розглянемо, як навчати глибші мережі стабільніше (нормалізація), як давати їм більше різноманітності (аугментація) і як будувати архітектури, що добре працюють на фото (ResNet).
