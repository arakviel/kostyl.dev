- Побачити, що робить `nn.Linear` за замовчуванням, і змінювати ініціалізацію через `nn.init`
- Розібрати Batch Normalization: формулу, `BatchNorm1d` проти `BatchNorm2d`, місце в блоці Conv → BN → ReLU
- Не плутати режими `train()` і `eval()` і розуміти, звідки в BatchNorm беруться `running_mean` та `running_var`

::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Ініціалізація ваг (Weight initialization):** вибір початкових значень ваг перед навчанням
- **Зникнення / вибух сигналу:** активації від шару до шару зменшуються до нуля або ростуть до величезних чисел
- **Ініціалізація Xavier (Glorot):** дисперсія ваг `2 / (n_in + n_out)`, добре для tanh
- **Ініціалізація He (Kaiming):** дисперсія ваг `2 / n_in`, добре для ReLU
- **Batch Normalization (BatchNorm):** шар, що нормалізує значення по батчу до середнього 0 і std 1, а потім масштабує їх навченими `γ` і `β`
- **Рухомі статистики (Running statistics):** згладжені середнє й дисперсія, які BatchNorm накопичує під час навчання й використовує в `eval()`

::

## Мережа, яка не хоче вчитися

У лекції 10 ми зробили CNN із трьома згортками, і вона вчилась без жодних ухищрень. Цікаво, що буде, якщо шарів стане більше? Залишимо тільки найпростіше: повнозв'язну мережу з **десяти** шарів на MNIST. Щоб вона навчалася, ми нічого не змінюємо: той самий `DataLoader`, той самий SGD зі швидкістю `0,05`.

Результат після трьох епох, зерно 0:

| Початкові ваги | Точність на тесті по епохах, % |
| :--- | :--- |
| Малі випадкові `N(0; 0,01)` | 11,35 → 11,35 → 11,35 |
| Налаштування `nn.Linear` за замовчуванням | 11,35 → 11,35 → 11,35 |
| Ініціалізація He (про неї далі) | 95,41 → 96,63 → 96,79 |

`11,35%` — це частка найпоширенішої цифри («1») у тестовому наборі: мережа просто вгадує один клас. Архітектура, дані, оптимізатор, швидкість навчання — усе однакове. Відрізняються тільки **числа, з яких мережа стартувала**. І це не питання «пощастило чи ні»: нижче ми побачимо, чому.

## Що відбувається з сигналом у глибині мережі

Розглянемо один нейрон шару без зсуву: `y = w₁x₁ + w₂x₂ + … + wₙxₙ`, де `n` — кількість входів. Припустимо, що ваги й входи незалежні, мають нульове середнє, а `Var` — дисперсія (середній квадрат відхилення від середнього). Тоді дисперсії доданків просто складаються:

::math-formula
\text{Var}(y) = n \cdot \text{Var}(w) \cdot \text{Var}(x)
::

Вся лекція в одному множнику `n · Var(w)`. Позначимо його `k`. Після кожного шару дисперсія сигналу множиться на `k`, після `L` шарів на `kᴸ`:

| Коефіцієнт `k = n · Var(w)` | Що з сигналом після багатьох шарів |
| :--- | :--- |
| `k < 1` | `kᴸ → 0`: сигнал **зникає**, усі нейрони глибоко в мережі виходять майже нульовими |
| `k > 1` | `kᴸ → ∞`: сигнал **вибухає**, числа стають величезними |
| `k ≈ 1` | сигнал зберігає масштаб, мережа «чує» вхід до самого кінця |

Цей самий множник діє й у зворотному напрямку: градієнт, що йде від виходу до входу, множиться на схожі коефіцієнти. Якщо сигнал зникає вперед, то зазвичай зникає й градієнт назад: перші шари майже не отримують сигналу, за яким можна вчитися.

### Експеримент: 30 шарів

Перевіримо формулу. Складемо стос із 30 лінійних шарів по 256 нейронів (без зсувів), подамо 512 випадкових векторів зі стандартним відхиленням 1 і дивитимемося на `std` активацій після кожного шару. Для цього напишемо ініціалізатор, який приймає назву схеми:

::jupyter-notebook{title="signal_depth.ipynb" kernel="Python 3.11 (ipykernel)"}

::jupyter-cell{type="markdown"}
Ініціалізатор і функція, що пропускає сигнал крізь 30 шарів із заданою активацією.
::

::jupyter-cell{executionCount="1"}
```python
import torch
import torch.nn as nn

def init_linear(layer, scheme):
    if scheme == "small":                       # N(0; 0,01)
        nn.init.normal_(layer.weight, 0, 0.01)
    elif scheme == "big":                       # N(0; 1)
        nn.init.normal_(layer.weight, 0, 1)
    elif scheme == "xavier":
        nn.init.xavier_normal_(layer.weight)
    elif scheme == "he":
        nn.init.kaiming_normal_(layer.weight, nonlinearity="relu")
    # "default": залишаємо те, що поставив сам nn.Linear

def signal_std(act, scheme, depth=30, width=256, seed=0):
    torch.manual_seed(seed)
    layers = []
    for _ in range(depth):
        layer = nn.Linear(width, width, bias=False)
        init_linear(layer, scheme)
        layers.append(layer)
    h = torch.randn(512, width, generator=torch.Generator().manual_seed(1))
    stds = []
    for layer in layers:
        h = act(layer(h))
        stds.append(h.std().item())
    return stds
```
::

::jupyter-cell{type="markdown"}
Подивимося на `std` після 1-го, 10-го і 30-го шару для ReLU.

```python
for scheme in ["big", "small", "default", "xavier", "he"]:

```

Тепер усю картину разом: ліворуч активація tanh, праворуч ReLU, по вертикалі `std` сигналу (шкала логарифмічна, кожна поділка — степінь десяти), по горизонталі номер шару.

![Std активацій після кожного з 30 шарів для п'яти способів ініціалізації та двох активацій](/images/ai-python/cnn-image-classification/init-batchnorm/01.png){.diagram-img}

Подивімося уважно на ReLU (праворуч):

- **`N(0; 1)`** (червона): `k = 256 · 1 ≫ 1`, і сигнал росте на порядок за шар: після 30 шарів `std ≈ 4·10³¹`. Для порівняння, найбільше число `float32` — близько `3·10³⁸`: ще кілька шарів, і мережа видала б `inf` та `nan`.
- **`N(0; 0,01)`** (жовта): `k = 256 · 0,0001 ≈ 0,026 ≪ 1`, і сигнал зникає: `4·10⁻²⁹` на тридцятому шарі.
- **За замовчуванням** (сіра) і **Xavier** (блакитна) теж ідуть униз, повільніше, але стабільно.
- **He** (зелена) тримається біля одиниці: `0,83`, `0,79`, `0,94`.

Із tanh історія інша. Велика ініціалізація не вибухає, а **насичує** нейрони: після `tanh` майже всі значення лежать біля `−1` або `+1` (гістограма нижче), `std = 0,974` на всіх шарах. Сигнал вижив, але похідна `tanh` у насиченій зоні близька до нуля, і градієнт через такі шари проходити не буде. Це наслідок форми `tanh`; ми його тут не вимірювали. З малими вагами tanh так само зникає (`1,3·10⁻²⁴` на 30-му шарі), а ось Xavier (`0,127`) і He (`0,557`) тримають сигнал на пристойному рівні, тоді як налаштування за замовчуванням дає `4,5·10⁻⁸`.

## Як вибрати дисперсію ваг

З формули `Var(y) = n · Var(w) · Var(x)` випливає рецепт: **підібрати `Var(w)` так, щоб `k = 1`**, тобто `Var(w) = 1 / n`. Є два нюанси, і з них з'являються дві відомі схеми.

### Xavier (Glorot)

Шар має `n_in` входів і `n_out` виходів. Умова `k = 1` для прямого проходу дає `Var(w) = 1 / n_in`. Для зворотного проходу градієнт «тече» через ті самі ваги в протилежний бік, і там аналогічна умова дає `Var(w) = 1 / n_out`. Компроміс між двома вимогами:

::math-formula
\text{Var}(w) = \frac{2}{n_{in} + n_{out}}
::

Це **ініціалізація Xavier** (за іменем автора Ксав'є Глоро; ще її називають Glorot). Виводилась вона для лінійних шарів і `tanh`. Для квадратного шару `256 × 256` вона дає `Var(w) = 2/512`, тобто `std = 0,0625`.

### He (Kaiming)

ReLU обнуляє всі від'ємні значення, тобто приблизно половину нейронів. Середній квадрат сигналу після нього вдвічі менший, і `k = 1` більше не тримає. Щоб компенсувати втрату половини, ваги роблять удвічі «дисперсійніші»:

::math-formula
\text{Var}(w) = \frac{2}{n_{in}}
::

Це **ініціалізація He** (Кайминг Хе, 2015). Для шару `256 × 256`: `std = √(2/256) = 0,0884`. Саме вона тримається біля одиниці на графіку вище.

Тепер зрозуміло, чому Xavier зі ReLU (блакитна лінія праворуч) іде вниз: вона розрахована на `k = 1` без втрат, а ReLU додає множник `½` на кожному шарі. За `std` це `√½ ≈ 0,71` за шар, а `0,71³⁰ ≈ 3·10⁻⁵`, і ми справді отримали `2,86·10⁻⁵`.

| Активація | Ініціалізація | `nn.init` |
| :--- | :--- | :--- |
| ReLU, LeakyReLU | He | `kaiming_normal_` / `kaiming_uniform_` |
| tanh, sigmoid | Xavier | `xavier_normal_` / `xavier_uniform_` |

### Що робить `nn.Linear`, якщо нічого не просити

Ми ніколи не ініціалізували ваги самі, а мережі навчалися. Тому що в `nn.Linear` і `nn.Conv2d` ініціалізація вже вбудована. Подивимося, яка:

::jupyter-notebook{title="default_init.ipynb" kernel="Python 3.11 (ipykernel)" executionCount="3" outputType="stdout"}

```python
torch.manual_seed(0)
layer = nn.Linear(256, 256)
print(f"std ваг за замовчуванням: {layer.weight.std().item():.4f}")
print(f"межі рівномірного розподілу: ±{layer.weight.abs().max().item():.4f}")
print(f"He для цього шару: {(2/256)**0.5:.4f}")
print(f"зсув: min {layer.bias.min().item():.3f}, max {layer.bias.max().item():.3f}")
```

#output
std ваг за замовчуванням: 0.0360
межі рівномірного розподілу: ±0.0625
He для цього шару: 0.0884
зсув: min -0.062, max 0.062
::

У PyTorch ваги `nn.Linear` беруться з **рівномірного** розподілу на відрізку `[−1/√n_in; 1/√n_in]`. Дисперсія такого розподілу дорівнює `(1/√n_in)² / 3 = 1 / (3 · n_in)`, тобто `k = n · Var(w) = 1/3`. Сигнал домножується приблизно на `1/3` за шар (за `std` на `√(1/3) ≈ 0,58`; з ReLU ще на `0,71`), і саме тому сіра лінія на графіку іде вниз. Для неглибоких мереж цього досить. Для десяти шарів уже мало, а для тридцяти — катастрофа.

### Як задати свою ініціалізацію

Функції з `torch.nn.init` змінюють тензор **на місці** (це видно по підкресленню в кінці назви). Щоб застосувати схему до всієї мережі, пишемо функцію для одного модуля й передаємо її в `model.apply`: метод обходить усі вкладені модулі.

::jupyter-notebook{title="init_apply.ipynb" kernel="Python 3.11 (ipykernel)" executionCount="4" outputType="stdout"}

```python
def init_weights(m):
    if isinstance(m, (nn.Linear, nn.Conv2d)):
        nn.init.kaiming_normal_(m.weight, nonlinearity="relu")
        nn.init.zeros_(m.bias)

model = nn.Sequential(nn.Linear(784, 256), nn.ReLU(),
                      nn.Linear(256, 256), nn.ReLU(),
                      nn.Linear(256, 10))
model.apply(init_weights)

for i in (0, 2, 4):
    w = model[i].weight
    print(f"шар {i}: std = {w.std().item():.4f}, очікувано {(2 / w.shape[1]) ** 0.5:.4f}, сума |зсувів| = {model[i].bias.abs().sum().item():.0f}")
```

#output
шар 0: std = 0.0505, очікувано 0.0505, сума |зсувів| = 0
шар 2: std = 0.0884, очікувано 0.0884, сума |зсувів| = 0
шар 4: std = 0.0873, очікувано 0.0884, сума |зсувів| = 0
::

Зсуви (bias) прийнято ставити в нуль: вони не множаться на вхід, тож їх масштаб не впливає на `k`. Для згорткового шару `n_in` у формулі — це `C_in · k_h · k_w` (кількість входів одного нейрона-ядра), `kaiming_normal_` порахує його сам.

::note
Скрізь вище ми писали `nn.init.kaiming_normal_(..., nonlinearity="relu")`. Параметр `nonlinearity` вибирає множник `2` для ReLU; для tanh краще `xavier_normal_`.
::

## Експеримент: десять шарів на MNIST

Повернімося до мережі, з якої ми почали: `784 → 256 → … → 256 → 10`, усього 10 лінійних шарів, ReLU між ними. Навчаємо три варіанти ініціалізації однаково: батч 64, 3 епохи, зерно 0.

::jupyter-notebook{title="deep_mlp.ipynb" kernel="Python 3.11 (ipykernel)"}

::jupyter-cell{executionCount="5"}
```python
def make_mlp(depth, scheme):
    layers = [nn.Flatten(), nn.Linear(784, 256), nn.ReLU()]
    for _ in range(depth - 2):
        layers += [nn.Linear(256, 256), nn.ReLU()]
    model = nn.Sequential(*layers, nn.Linear(256, 10))
    for m in model:
        if isinstance(m, nn.Linear):
            init_linear(m, scheme)            # та сама функція, що й вище
            if scheme != "default":
                nn.init.zeros_(m.bias)
    return model
```
::

::jupyter-cell{type="markdown"}
Навчальний цикл такий самий, як у лекціях 09–11. Єдине нове: на першому кроці запам'ятовуємо **норму градієнта** ваг кожного шару, щоб побачити, чи доходить сигнал до початку мережі.
::

::jupyter-cell{executionCount="6"}
```python
def train_mlp(scheme, opt_name, lr, epochs=3, seed=0):
    torch.manual_seed(seed)
    model = make_mlp(10, scheme)
    loader = DataLoader(train_set, batch_size=64, shuffle=True,
                        generator=torch.Generator().manual_seed(seed))
    opt = (torch.optim.Adam if opt_name == "adam" else torch.optim.SGD)(model.parameters(), lr=lr)
    first_grads = None
    for epoch in range(epochs):
        model.train()
        for step, (x, y) in enumerate(loader):
            loss = F.cross_entropy(model(x), y)
            opt.zero_grad(); loss.backward()
            if epoch == 0 and step == 0:
                first_grads = [m.weight.grad.norm().item() for m in model if isinstance(m, nn.Linear)]
            opt.step()
        # ... оцінка на тесті після кожної епохи
    return first_grads
```

Ліворуч видно, що втрата SGD з малими вагами та з вагами за замовчуванням лежить на рівні `2,30`: це `ln 10`, значення втрати при передбаченні «усі 10 класів рівноймовірні». Криві цих двох варіантів майже збігаються, сіра лежить зверху над жовтою. Посередині причина:

- З малими вагами норма градієнта **в усіх шарах** близько `3,5·10⁻⁹`. Крок SGD `lr · grad` змінює ваги на величини порядку `10⁻¹⁰`, тобто нічого.
- Із вагами за замовчуванням градієнт у першому шарі в `160` разів менший за градієнт в останньому: `4,4·10⁻⁴` проти `7,0·10⁻²`. Перші шари вчаться набагато повільніше за останні.
- З He градієнти в усіх шарах мають норму порядку `0,6–1,1`: сигнал дійшов до кожного шару.

Праворуч той самий експеримент з Adam (`lr = 0,001`) замість SGD. Adam нормує крок за величиною градієнта, тому на дуже малі градієнти йому все одно: він їх масштабує й навчання йде. Точність після третьої епохи: малі ваги `95,70%`, за замовчуванням `96,02%`, He `96,98%`. Тобто Adam **врятував** погані ваги, але He все одно виграє: у першу епоху вона дала `96,26%` проти `90,25%` у малих.

::warning
Висновок, що «SGD із вагами за замовчуванням не вчиться», коректний лише для цього експерименту: 10 шарів, `lr = 0,05`, 3 епохи. З більшою швидкістю навчання чи довшим навчанням мережа, найімовірніше, зрушила б з місця: ми цього не перевіряли. Метою було показати розкид градієнтів між шарами, а не побити рекорд.
::

## Batch Normalization: нормалізація всередині мережі

Хороші початкові ваги дають мережі правильний старт. Але ваги змінюються на кожному кроці, і масштаб значень на глибоких шарах може «попливти» вже під час навчання. У Модулі 3 ви бачили, що вхідні ознаки корисно масштабувати до середнього 0 і `std` 1: градієнтний спуск тоді йде рівніше. Ідея **Batch Normalization** (Іоффе й Сегеді, 2015): **робити те саме не лише на вході, а перед кожною активацією всередині мережі**, і навчити мережу керувати цим масштабом.

### Формула

Нехай шар видав значення `x` для кожного з `m` прикладів батча (для одного нейрона чи одного каналу). BatchNorm робить чотири кроки:

::math-formula
\mu_B = \frac{1}{m}\sum_{i=1}^{m} x_i \qquad \sigma_B^2 = \frac{1}{m}\sum_{i=1}^{m} (x_i - \mu_B)^2
::

::math-formula
\hat{x}_i = \frac{x_i - \mu_B}{\sqrt{\sigma_B^2 + \varepsilon}} \qquad y_i = \gamma \, \hat{x}_i + \beta
::

- `μ_B`, `σ²_B` — середнє й дисперсія **цього батча** для цього нейрона/каналу;
- `ε` (у PyTorch `1e-5`) — крихітне число, щоб не ділити на нуль, якщо дисперсія майже нульова;
- `x̂` — нормалізоване значення: середнє 0, `std` ≈ 1;
- `γ` (масштаб) і `β` (зсув) — **навчувані параметри**, по одній парі на нейрон/канал. Ініціалізуються як `γ = 1`, `β = 0`.

Навіщо `γ` і `β`, якщо ми щойно привели все до `N(0; 1)`? Бо «середнє 0, `std` 1» не обов'язково найкраще для наступного шару. Наприклад, сигмоїді потрібен діапазон ширший за `[−1; 1]`, а ReLU, можливо, вигідніший невеликий додатний зсув. З `γ` і `β` мережа **сама вирішує**, який масштаб їй потрібен, а в крайньому випадку може навіть відмінити нормалізацію (`γ = σ_B`, `β = μ_B` повернуть вихідні значення).

### BatchNorm1d і BatchNorm2d

Шар один, але для різних даних статистики потрібно рахувати по різних осях.

- **`BatchNorm1d(C)`** працює з тензором `(N, C)` (повнозв'язні шари): для кожної з `C` ознак `μ` і `σ²` рахуються по `N` прикладах батча.
- **`BatchNorm2d(C)`** працює з `(N, C, H, W)` (згорткові шари): для кожного з `C` **каналів** одна пара `(μ, σ²)` рахується по всіх `N` зображеннях і по всіх `H × W` позиціях. Так і має бути: усі позиції каналу отримані одним і тим самим ядром, тож це «та сама ознака» в різних місцях.

![BatchNorm1d усереднює по рядках матриці, BatchNorm2d по батчу й усіх позиціях кожного каналу](/images/ai-python/cnn-image-classification/init-batchnorm/04.png){.diagram-img}

## Де ставити BatchNorm і навіщо «зсув» у згортці

У CNN стандартний блок такий: **згортка → BatchNorm → ReLU**. Нормалізація стоїть між лінійною частиною й активацією, тому ReLU отримує значення з контрольованим масштабом. Один блок у коді:

```python
nn.Sequential(
    nn.Conv2d(32, 64, kernel_size=3, padding=1, bias=False),
    nn.BatchNorm2d(64),
    nn.ReLU(),
)
```

Помітили `bias=False`? Зсув згортки тут зайвий: BatchNorm віднімає середнє по батчу, і будь-яка константа, додана до всіх виходів каналу, одразу зникає, а замість неї працює навчуваний `β`. Тож зсув лише додає параметри, які нічого не змінюють. Для `Conv2d(3, 32, 3)` це `896` параметрів із зсувом проти `864` без нього, а сам `BatchNorm2d(32)` додає `64` навчуваних параметри (по `γ` і `β` на кожен з 32 каналів).

## Режими `train()` та `eval()`

Тут чекає найпідступніша частина BatchNorm. У формулі `μ_B` і `σ²_B` беруться з **поточного батча**. Під час навчання це нормально. Але коли ми передбачаємо клас для однієї фотографії, батчу немає, а якщо він є, відповідь на одне фото не повинна залежати від того, які ще фото потрапили в той самий батч. Тому BatchNorm влаштований у двох режимах:

| | `model.train()` | `model.eval()` |
| :--- | :--- | :--- |
| Звідки `μ` і `σ²` | з поточного батча | з накопичених `running_mean`, `running_var` |
| Оновлює `running_*` | так | ні |
| Результат залежить від інших прикладів у батчі | так | ні |

Накопичені статистики оновлюються на кожному кроці навчання як експоненційне ковзне середнє з `momentum = 0,1`:

::math-formula
\text{running\_mean} \leftarrow (1 - 0{,}1) \cdot \text{running\_mean} + 0{,}1 \cdot \mu_B
::

Те саме для `running_var` (з незміщеною дисперсією батча). Стартові значення `running_mean = 0`, `running_var = 1`. Тому після першого ж виклику `bn(x)` на нашому батчі з чотирьох прикладів вище `running_mean` дорівнював `0,1 · μ = [−0,020; 0,913; −0,306]`, а `running_var` — `0,9 + 0,1 · σ²` (незміщене).

Подивимося, як статистики «збігаються» до правди. Подаємо батчі по 64 приклади з відомими параметрами: `μ = [0; 10; −3]`, `σ² = [1; 25; 0,04]`.

::jupyter-notebook{title="running_stats.ipynb" kernel="Python 3.11 (ipykernel)"}

::jupyter-cell{executionCount="11" outputType="stdout"}
```python
torch.manual_seed(0)
scale = torch.tensor([1., 5., 0.2]); shift = torch.tensor([0., 10., -3.])
def batch(n): return torch.randn(n, 3) * scale + shift

bn = nn.BatchNorm1d(3)
bn(batch(64))
print("після 1 батча:    running_mean", bn.running_mean, " running_var", bn.running_var)
for _ in range(99):
    bn(batch(64))
print("після 100 батчів: running_mean", bn.running_mean, " running_var", bn.running_var)
print("справжні значення:        μ = [0, 10, -3],  σ² = [1, 25, 0.04]")
```

### Дві помилки, які трапляються постійно

::warning
**Забули `model.eval()` перед оцінкою.** Мережа лишається в режимі `train()`: BatchNorm рахує статистики по тестовому батчу та ще й псує `running_*` тестовими даними. Точність на тесті стає залежною від розміру тестового батча, а передбачення на одному прикладі просто падає з помилкою, яку ви щойно бачили. Усі наші функції `evaluate` з лекцій 09–11 мали `model.eval()` на початку: тепер ви знаєте, чому це було не декорацією.
::

::warning
**Забули повернутися до `model.train()`.** Після оцінки в кінці епохи `model.eval()` лишається увімкненим, і наступна епоха навчається зі статистиками BatchNorm, які вже не оновлюються, а Dropout (лекція 10) у режимі `eval()` взагалі нічого не вимикає: мережа втрачає регуляризацію. У нашому циклі `model.train()` стоїть на початку кожної епохи, і це саме та причина.
::

## Експеримент: глибока CNN на CIFAR-10 з BatchNorm і без

Час перевірити BatchNorm на справжній задачі. Візьмемо CIFAR-10 із лекції 10 і мережу глибшу за ту, що була там: **шість** згорток замість трьох, пара за парою перед кожним пулінгом (блоки по 32, 64 і 128 каналів). Дві версії відрізняються лише наявністю `BatchNorm2d` після кожної згортки:

::jupyter-notebook{title="deep_cnn_bn.ipynb" kernel="Python 3.11 (ipykernel)" executionCount="13" outputType="stdout"}

```python
def make_deep_cnn(bn):
    layers = []
    for k, (c_in, c_out) in enumerate(((3, 32), (32, 32), (32, 64), (64, 64), (64, 128), (128, 128))):
        layers.append(nn.Conv2d(c_in, c_out, 3, padding=1))
        if bn:
            layers.append(nn.BatchNorm2d(c_out))
        layers.append(nn.ReLU())
        if k % 2 == 1:
            layers.append(nn.MaxPool2d(2))
    return nn.Sequential(*layers, nn.Flatten(), nn.Linear(128 * 4 * 4, 128), nn.ReLU(), nn.Linear(128, 10))

print("без BatchNorm:", sum(p.numel() for p in make_deep_cnn(False).parameters()), "параметрів")
print("з BatchNorm:  ", sum(p.numel() for p in make_deep_cnn(True).parameters()), "параметрів")
```

#output
без BatchNorm: 550570 параметрів
з BatchNorm:   551466 параметрів
::

Тут ми залишили зсуви в згортках (`bias=True`): різниця у `896` параметрів складається з `2 · 448` навчуваних `γ` і `β`, тож порівняння чесне (практично однаковий розмір). Навчаємо Adam, батч 64, 8 епох, ваги за замовчуванням, **3 зерна** на кожну версію, швидкість навчання `0,001`. Кожна епоха триває близько `79` секунд на CPU з обома версіями: BatchNorm практично не додає часу.

| Без BatchNorm | 52,2% | 67,3% | **75,1%** (74,96 / 75,73 / 74,56) | 0,479 |
| З BatchNorm | 63,1% | 76,1% | **81,3%** (81,76 / 82,48 / 79,78) | 0,214 |

Різниця очевидна, і вона не випадкова: найгірше зерно з BatchNorm (`79,8%`) краще за найкраще зерно без нього (`75,7%`). Видно також, що BatchNorm навчає **швидше**: у третю епоху він уже на `76,1%`, а мережа без нього за всі 8 епох до цього рівня не дійшла (`75,1%`).

### Швидкість навчання в 10 разів більша

Права панель рисунка. З `lr = 0,01` мережа без BatchNorm **не вчиться взагалі**: `10,0%` у кожну з 8 епох, втрата застрягла на `2,304` (≈ `ln 10`). Та сама мережа з BatchNorm навчилась і дійшла до `78,1%` (один запуск, зерно 0). Тобто BatchNorm розширює діапазон `lr`, який «дозволений»: можна брати швидкості навчання, на яких звичайна мережа розсипається. Водночас при `lr = 0,01` він поступився швидкості `0,001`: `78,1%` проти `81,8%` у того ж зерна 0.

::note
З рисунка 06 не слід робити висновок «BatchNorm завжди краще». Ми порівняли лише дві мережі на одній задачі, з одним оптимізатором і 8 епохами. Також варто помітити: у версії з BatchNorm втрата на навчанні `0,214` вдвічі менша за втрату без нього, а втрата на тесті `0,62` проти `0,76` відрізняється менше. Розрив між навчанням і тестом у BatchNorm-версії більший: вона також швидше «заучує» тренувальні дані. Із цим ми будемо боротися в лекції 14 (аугментація).
::

### Що саме змінюється всередині

Подивимося на четверту згортку нашої мережі й виміряємо на **одних і тих самих** 512 тестових зображеннях, які значення вона видає в різні моменти навчання. Перший і другий графіки показують середнє та `std` перед ReLU.

![Гістограма виходу четвертої згортки до та після BatchNorm на кроці 1000](/images/ai-python/cnn-image-classification/init-batchnorm/05.png){.diagram-img}

Ліворуч «сирий» вихід згортки на кроці 1000: розподіл зсунутий у від'ємний бік (середнє `−1,12`) і розтягнутий (`std = 1,54`). Праворуч те саме після BatchNorm: центр на нулі, `std = 1,00`. ReLU отримує вхід, центрований на нулі, а не такий, більша частина якого лежить у від'ємній зоні й буде обнулена.

![Як змінюються середнє та std входу четвертого ReLU протягом навчання, з BatchNorm і без](/images/ai-python/cnn-image-classification/init-batchnorm/07.png){.diagram-img}

На останньому графіку видно протягом навчання (по горизонталі кроки, шкала логарифмічна):

- У мережі **без BatchNorm** (червона) вхід ReLU змінюється: `std` зростає з `0,03` на старті до `0,59` на кроці 6000, середнє зсувається від `−0,01` до `−0,48`. Наступні шари постійно мусять підлаштовуватись.
- У мережі **з BatchNorm** (зелена) вхід ReLU фактично нерухомий: середнє від `0,00` до `−0,30`, `std` від `1,00` до `0,98`. Пунктирна лінія показує, що відбувається **до** нормалізації: вихід згортки дрейфує (`std` від `0,38` до `2,27`, середнє до `−2,03`), але BatchNorm цей дрейф «з'їдає».

::note
Звичайне пояснення в підручниках: BatchNorm зменшує **внутрішній зсув коваріат** (internal covariate shift), тобто розподіл входів кожного шару не «пливе» під час навчання. Графік вище на перший погляд це підтверджує. Але **причинність ми не перевіряли**, а вона спірна: у статті Сантуркара та співавторів (2018) показано, що ефект BatchNorm зберігається, навіть якщо після BatchNorm навмисно додати випадковий шум, що знову розхитує розподіли, і що справжня причина швидшого навчання, найімовірніше, у **згладженому ландшафті втрати** (градієнти стають передбачуванішими, тому можна брати більший `lr`). Ми з вами вимірюємо результат (швидше, стабільніше, ширший діапазон `lr`), а пояснення лишається предметом досліджень.
::

## Практичні нюанси

- **Розмір батча.** BatchNorm рахує статистику по батчу, тому з дуже малими батчами (наприклад, 2 або 4) оцінки `μ_B` і `σ²_B` шумні, і якість падає. На батчах від 32 і більше проблем зазвичай немає. Якщо батч змушений бути малим, дивіться на LayerNorm: його ми розберемо в наступній лекції.
- **Dropout.** Dropout і BatchNorm в одному блоці дають суперечливі ефекти: Dropout змінює дисперсію сигналу під час навчання, а BatchNorm потім у режимі `eval()` використовує статистики, зібрані з іншою дисперсією. Практично: в згорткових мережах із BatchNorm Dropout часто просто не ставлять, а там, де ставлять, його кладуть біля самого виходу.
- **Збереження моделі.** `running_mean` і `running_var` лежать у `state_dict()` разом з вагами (ми це бачили: 33 числа на блок із 16 каналами, які не навчаються). Без них завантажена модель у режимі `eval()` нормалізуватиме неправильно.
- **Глибина.** У мережі з двома-трьома шарами (як у лекції 10) виграш від BatchNorm невеликий; помітним він стає, коли шарів шість і більше, як у нашому експерименті.

## Практика

::::accordion

:::accordion-item{label="📋 Завдання 1: порахуйте ініціалізацію" icon="i-lucide-clipboard-list"}

Обчисліть `std` ваг за схемою He для `nn.Linear(512, 128)` і `nn.Conv2d(64, 128, kernel_size=3)`, а також за схемою Xavier для `nn.Linear(512, 128)`. Потім перевірте кодом: створіть шари, ініціалізуйте й виміряйте `weight.std()`.

:::accordion-item{label="✅ Розв'язок" icon="i-lucide-check-circle"}

- He для `Linear(512, 128)`: `n_in = 512`, `std = √(2/512) = 0,0625`.
- He для `Conv2d(64, 128, 3)`: кожен нейрон-ядро бачить `n_in = C_in · k_h · k_w = 64 · 3 · 3 = 576` значень, `std = √(2/576) ≈ 0,0589`.
- Xavier для `Linear(512, 128)`: `Var = 2/(512 + 128) = 0,003125`, `std = √0,003125 ≈ 0,0559`.

::jupyter-notebook{title="init_check.ipynb" kernel="Python 3.11 (ipykernel)" executionCount="1" outputType="stdout"}

```python
import torch.nn as nn

lin = nn.Linear(512, 128); nn.init.kaiming_normal_(lin.weight, nonlinearity="relu")
print("He, Linear:  ", round(lin.weight.std().item(), 4))

lin = nn.Linear(512, 128); nn.init.xavier_normal_(lin.weight)
print("Xavier, Linear:", round(lin.weight.std().item(), 4))

conv = nn.Conv2d(64, 128, 3); nn.init.kaiming_normal_(conv.weight, nonlinearity="relu")
print("He, Conv2d:  ", round(conv.weight.std().item(), 4))
```

Xavier, Linear: 0.0558
He, Conv2d:   0.059

:::accordion-item{label="📋 Завдання 2: BatchNorm вручну" icon="i-lucide-clipboard-list"}

Один нейрон, батч із чотирьох значень `[2, 4, 6, 8]`, параметри `γ = 2`, `β = 1`, `ε` вважайте нулем. Порахуйте вихід BatchNorm у режимі навчання. Потім порахуйте, чому дорівнюватимуть `running_mean` і `running_var` після цього єдиного батча (початкові значення `0` і `1`, `momentum = 0,1`, дисперсія для `running_var` **незміщена**, тобто ділення на `m − 1`). Перевірте кодом.

:::

:::accordion-item{label="✅ Розв'язок" icon="i-lucide-check-circle"}

`μ = (2 + 4 + 6 + 8) / 4 = 5`. Дисперсія для нормалізації (ділення на `m = 4`): `(9 + 1 + 1 + 9) / 4 = 5`, тож `σ = √5 ≈ 2,236`. Нормалізовані значення `(x − 5) / 2,236`: `−1,342; −0,447; 0,447; 1,342`. Далі `y = 2 · x̂ + 1`: `−1,683; 0,106; 1,894; 3,683`.

Для `running_*`: `running_mean = 0,9 · 0 + 0,1 · 5 = 0,5`. Незміщена дисперсія `20 / 3 = 6,667`, тож `running_var = 0,9 · 1 + 0,1 · 6,667 = 1,567`.

::jupyter-notebook{title="bn_by_hand_task.ipynb" kernel="Python 3.11 (ipykernel)" executionCount="1" outputType="stdout"}

```python
import torch, torch.nn as nn

x = torch.tensor([[2.], [4.], [6.], [8.]])
bn = nn.BatchNorm1d(1)
bn.weight.data.fill_(2.); bn.bias.data.fill_(1.)
print(bn(x).flatten().tolist())
print(bn.running_mean.item(), bn.running_var.item())
```

## Резюме

::card-group

::card{title="📌 Ініціалізація" icon="i-lucide-sprout"}
Дисперсія сигналу множиться на `n · Var(w)` на кожному шарі. He (`2/n_in`) для ReLU, Xavier (`2/(n_in + n_out)`) для tanh. На 30 шарах ReLU He тримав `std` біля 1, а `N(0; 0,01)` скинув сигнал до `10⁻²⁹`.
::

::card{title="📌 BatchNorm" icon="i-lucide-align-center"}
`x̂ = (x − μ_B) / √(σ²_B + ε)`, потім `y = γ x̂ + β`. `BatchNorm1d` рахує статистики по батчу, `BatchNorm2d` по батчу й усіх `H × W`, окремо для кожного каналу. Блок: `Conv → BN → ReLU`, зсув у згортці зайвий.
::

::card{title="📌 train / eval" icon="i-lucide-toggle-left"}
У `train()` статистики з поточного батча, у `eval()` з накопичених `running_mean/var` (`momentum = 0,1`). Забули `eval()` перед оцінкою, і передбачення залежать від батча.
::

::card{title="📌 Результат" icon="i-lucide-trending-up"}
Глибока CNN на CIFAR-10: `75,1%` без BatchNorm проти `81,3%` з ним (3 зерна). З `lr = 0,01` без BatchNorm мережа не навчилась (`10%`), з ним дійшла до `78,1%`. Пояснення «чому» спірне, ефект виміряний.
::

::

**У наступній лекції** розберемо те, що BatchNorm не вміє: мережі з маленькими батчами, послідовності й трансформери. Це **LayerNorm**, яка нормалізує не по батчу, а по ознаках одного прикладу. А ще навчимось **обрізанню градієнтів** (gradient clipping), яке рятує навчання, коли градієнт раптом стає занадто великим.
