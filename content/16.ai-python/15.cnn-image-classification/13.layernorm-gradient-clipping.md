# LayerNorm і обрізання градієнтів

::card-group

::card{title="🎯 Мета лекції" icon="i-lucide-target"}

- Зрозуміти, чим LayerNorm відрізняється від BatchNorm і чому він не залежить від батча
- Перевірити формулу LayerNorm руками й дізнатися, що таке `GroupNorm(1, C)` для згорткових карт
- Побачити, як нормалізація «воскрешає» мережу, яка не навчалась у лекції 12
- Розібрати вибух градієнтів: що це, як його помітити по нормі градієнта і чому loss стає `nan`
- Користуватися `clip_grad_norm_` і розуміти, як вибрати `max_norm`

::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Layer Normalization (LayerNorm):** нормалізація кожного прикладу окремо по всіх його ознаках, без залежності від батча
- **Group Normalization (GroupNorm):** нормалізація по групах каналів одного прикладу; з однією групою це LayerNorm для карт ознак
- **Вибух градієнтів (Exploding gradients):** норма градієнта стрімко росте, ваги розлітаються, у втраті з'являється `inf` і `nan`
- **Норма градієнта (Gradient norm):** довжина вектора з усіх похідних усіх параметрів, `‖g‖`
- **Обрізання градієнтів (Gradient clipping):** якщо `‖g‖` перевищує поріг, градієнт масштабують до цього порогу

::

::

## Дві межі BatchNorm

У лекції 12 ми побачили, що BatchNorm дає мережі стабільність. Але в нього є дві особливості, які випливають із самої формули: статистики `μ_B` і `σ²_B` беруться **з батча**.

1. Відповідь для одного прикладу залежить від того, які ще приклади потрапили в батч. Через це ми потребували двох режимів і накопичених `running_mean`/`running_var`.
2. Для оцінки середнього й дисперсії потрібні кілька прикладів у батчі. З одним прикладом у режимі `train()` BatchNorm взагалі видає помилку (ми це бачили).

**Layer Normalization** (Ба, Кірос, Гінтон, 2016) прибирає обидві залежності одним рухом: статистики рахуються **по ознаках одного прикладу**, а не по батчу.

---

## LayerNorm: формула й осі

Для одного прикладу з `C` ознаками `x₁ … x_C`:

::math-formula
\mu = \frac{1}{C}\sum_{j=1}^{C} x_j \qquad \sigma^2 = \frac{1}{C}\sum_{j=1}^{C} (x_j - \mu)^2 \qquad y_j = \gamma_j \cdot \frac{x_j - \mu}{\sqrt{\sigma^2 + \varepsilon}} + \beta_j
::

Формула майже та сама, що в BatchNorm: віднімаємо середнє, ділимо на `std`, потім навчувані `γ` і `β`. Різниця тільки в тому, **по яких осях** рахуються `μ` і `σ²`.

![BatchNorm рахує статистику по стовпцю матриці (N, C), LayerNorm по рядку](/images/ai-python/cnn-image-classification/layernorm-clipping/01.png){.diagram-img}

Перевіримо вручну на тому самому батчі `4 × 3`, що й у лекції 12. Тільки тепер середнє і дисперсія рахуються **по рядках** (`dim=1`).

::jupyter-notebook{title="layernorm_by_hand.ipynb" kernel="Python 3.11 (ipykernel)"}

::jupyter-cell{executionCount="1" outputType="stdout"}
```python
import torch, torch.nn as nn
torch.set_printoptions(precision=3, sci_mode=False)

torch.manual_seed(1)
x = torch.randn(4, 3) * torch.tensor([1., 5., 0.2]) + torch.tensor([0., 10., -3.])

mu = x.mean(1, keepdim=True)
var = x.var(1, unbiased=False, keepdim=True)
x_hat = (x - mu) / torch.sqrt(var + 1e-5)

ln = nn.LayerNorm(3)
y = ln(x)
print("μ по рядках: ", mu.flatten())
print("σ² по рядках:", var.flatten())
print("вручну:\n", x_hat)
print("збігаються:", torch.allclose(x_hat, y, atol=1e-6))
print("середнє по рядках:", y.mean(1))
print("std по рядках:    ", y.std(1, unbiased=False))
```

Тепер кожен **рядок** має середнє 0 і `std` 1 (раніше це було в кожному стовпці). Зверніть увагу на побічний ефект: ознаки цього прикладу мали зовсім різні масштаби (`0`, `10`, `−3`), і після LayerNorm усі рядки стали майже однаковими: `[−0,4; 1,4; −1,0]`. LayerNorm зручний, коли ознаки одного шару «рівноправні» за змістом; тут ми навмисно склали стовпці різного масштабу, тому ефект яскравий.

### Головна властивість: незалежність від батча

Візьмемо один і той самий приклад `a` і покладемо його у два різні батчі: з «спокійними» сусідами і з сусідами іншого масштабу.

::jupyter-notebook{title="batch_independence.ipynb" kernel="Python 3.11 (ipykernel)" executionCount="2" outputType="stdout"}

```python
torch.manual_seed(0)
a = torch.randn(1, 3)
others1 = torch.randn(7, 3)
others2 = torch.randn(7, 3) * 5 + 3
b1 = torch.cat([a, others1]); b2 = torch.cat([a, others2])

bn, ln = nn.BatchNorm1d(3), nn.LayerNorm(3)
print("BatchNorm, приклад a у двох батчах:", bn(b1)[0], bn(b2)[0])
print("LayerNorm, приклад a у двох батчах:", ln(b1)[0], ln(b2)[0])
```

#output
BatchNorm, приклад a у двох батчах: tensor([ 1.704, -0.612, -2.126], grad_fn=<SelectBackward0>) tensor([-0.395, -0.914, -1.231], grad_fn=<SelectBackward0>)
LayerNorm, приклад a у двох батчах: tensor([ 1.219,  0.011, -1.230], grad_fn=<SelectBackward0>) tensor([ 1.219,  0.011, -1.230], grad_fn=<SelectBackward0>)
::

У режимі `train()` BatchNorm видав для одного й того самого прикладу зовсім різні числа залежно від сусідів. LayerNorm дав тотожний результат. Звідси три практичні наслідки:

- у LayerNorm **немає** `running_mean` і `running_var`: нічого накопичувати, у `eval()` він працює так само, як у `train()` (у `nn.LayerNorm(256)` лише `γ` і `β`, `512` параметрів і жодних буферів);
- він працює з батчем будь-якого розміру, навіть з одним прикладом;
- забути `model.eval()` для LayerNorm не так небезпечно (хоча для Dropout усе ще треба).

### LayerNorm для згорткових карт

Для тензора `(N, C, H, W)` природне узагальнення: нормалізувати кожне зображення окремо по всіх `C × H × W` значеннях. У PyTorch зручно це робить `GroupNorm(1, C)`: **GroupNorm** ділить канали на групи й нормалізує всередині кожної групи, а одна група означає «усі канали разом».

::jupyter-notebook{title="groupnorm_is_layernorm.ipynb" kernel="Python 3.11 (ipykernel)" executionCount="3" outputType="stdout"}

```python
torch.manual_seed(0)
f = torch.randn(2, 4, 3, 3)
gn = nn.GroupNorm(1, 4)
lnf = nn.LayerNorm([4, 3, 3])
print("GroupNorm(1, C) == LayerNorm([C, H, W]):", torch.allclose(gn(f), lnf(f), atol=1e-6))
o = gn(f)
print("середнє по (C, H, W):", o.mean((1, 2, 3)), " std:", o.std((1, 2, 3), unbiased=False))
```

#output
GroupNorm(1, C) == LayerNorm([C, H, W]): True
середнє по (C, H, W): tensor([0.000, 0.000], grad_fn=<MeanBackward1>)  std: tensor([1.000, 1.000], grad_fn=<StdBackward0>)
::

Відмінність у параметрах: `GroupNorm(1, C)` має `γ`, `β` по одному **на канал**, а `LayerNorm([C, H, W])`, `γ` і `β` на кожну позицію (`C·H·W` чисел) і вимагає знати розмір карти наперед. Тому в експериментах нижче для згорток ми беремо саме `GroupNorm(1, C)`.

## Експеримент 1: воскрешаємо мережу з лекції 12

У лекції 12 десятишарова мережа з вагами PyTorch за замовчуванням і SGD (`lr = 0,05`) тричі підряд показала `11,35%`: градієнти ледь доходили до перших шарів. Вставимо нормалізацію після кожного лінійного шару (перед ReLU), решту не чіпаємо: ті самі ваги за замовчуванням, той самий SGD, ті самі 3 епохи.

::jupyter-notebook{title="normalized_mlp.ipynb" kernel="Python 3.11 (ipykernel)"}

```python
def make_mlp(norm, depth=10):
    def block(c_in, c_out):
        layers = [nn.Linear(c_in, c_out)]
        if norm == "bn":
            layers.append(nn.BatchNorm1d(c_out))
        elif norm == "ln":
            layers.append(nn.LayerNorm(c_out))
        return layers + [nn.ReLU()]

    layers = [nn.Flatten()] + block(784, 256)
    for _ in range(depth - 2):
        layers += block(256, 256)
    return nn.Sequential(*layers, nn.Linear(256, 10))     # ваги за замовчуванням
```
::

## Експеримент 2: чи справді BatchNorm програє з малим батчем?

Типова порада: «BatchNorm погано працює з малими батчами, бо статистики шумні, тому беріть LayerNorm або GroupNorm». Перевіримо. Невелика CNN на MNIST (дві згортки по 16 і 32 канали, нормалізація після кожної), три варіанти: без нормалізації, `BatchNorm2d`, `GroupNorm(1, C)`. Розмір батча `B ∈ {2, 8, 32, 128}`, Adam з `lr = 0,001`, 2 епохи, по 3 зерна. Точність міряємо в режимі `eval()`.

::jupyter-notebook{title="norm_batch_size.ipynb" kernel="Python 3.11 (ipykernel)"}

```python
def norm_layer(kind, c):
    if kind == "bn":
        return nn.BatchNorm2d(c)
    if kind == "ln":
        return nn.GroupNorm(1, c)       # LayerNorm для карт ознак
    return nn.Identity()

def make_cnn(kind):
    return nn.Sequential(
        nn.Conv2d(1, 16, 3, padding=1), norm_layer(kind, 16), nn.ReLU(), nn.MaxPool2d(2),
        nn.Conv2d(16, 32, 3, padding=1), norm_layer(kind, 32), nn.ReLU(), nn.MaxPool2d(2),
        nn.Flatten(), nn.Linear(32 * 7 * 7, 10))
```
::

![Точність на тесті після двох епох залежно від розміру батча й нормалізації](/images/ai-python/cnn-image-classification/layernorm-clipping/02.png){.diagram-img}

| Розмір батча | Без нормалізації | BatchNorm | LayerNorm (`GroupNorm(1, C)`) |
| :--- | :--- | :--- | :--- |
| 2 | 98,48% | 98,60% | 98,71% |
| 8 | 98,62% | 98,60% | 98,67% |
| 32 | 98,43% | 98,25% | 98,62% |
| 128 | 97,95% | 98,30% | 98,33% |

Це **не** підтверджує поради про малі батчі: при `B = 2` BatchNorm не гірший за мережу без нормалізації. Усі відмінності між варіантами при `B ≤ 32` не більші за `0,4` в. п., а розкид між зернами (бліді точки на рисунку) такого ж порядку, тож відрізнити їх одне від одного ми не можемо. MNIST надто легкий, а мережа надто мала: тут мало що «ламається». Єдине, що помітне: при `B = 128` (за два проходи це лише `~940` кроків) мережа без нормалізації відстає, `97,95%`, тоді як обидві нормалізовані дають `~98,3%`.

Практичний висновок із цього експерименту скромніший, ніж в підручниках: **LayerNorm не гірший за BatchNorm і не залежить від батча**, а цінність цієї незалежності проявляється там, де вона справді потрібна (зображення великого розміру, де батч не вміщується в пам'ять; послідовності різної довжини). Цього ми тут не вимірювали.

::note
Час. На CPU 2 епохи при `B = 2` тривали: без нормалізації `76 с`, BatchNorm `86 с`, GroupNorm `85 с`. Нормалізація додає приблизно `12%` часу на такій маленькій мережі; при `B = 128` усі три варіанти займали `22–23 с`.
::

### Що вибрати

| Ситуація | Що брати |
| :--- | :--- |
| Згорткова мережа, батч ≥ 32, класифікація зображень | BatchNorm (стандарт, із запасом перевірений) |
| Батч дуже малий або змінний, або потрібна однакова поведінка в `train` і `eval` | LayerNorm / `GroupNorm` |
| Повнозв'язні блоки, де «ознаки» не просторові | LayerNorm працює, BatchNorm теж |

Для послідовностей (текст, звук) LayerNorm стандартний вибір; про послідовності ми поговоримо у відповідних модулях курсу.

## Вибух градієнтів

Нормалізація стабілізує значення, але не гарантує, що **градієнт** завжди буде невеликим. Достатньо одного невдалого батча або занадто великої швидкості навчання, і крок виявляється величезним: ваги вистрибують у область, де втрата ще більша, градієнт у наступному кроці ще більший, і так далі. Це **вибух градієнтів**.

Побачимо його вживу. Беремо мережу з лекції 12, яка не мала жодних проблем: 10 шарів, ініціалізація He, батч 64, SGD. Лише швидкість навчання велика: `lr = 1,0`. Нам потрібен лічильник «наскільки великий градієнт». Це **норма градієнта**: довжина вектора, складеного з похідних усіх параметрів:

::math-formula
\|g\| = \sqrt{\sum_{k} g_k^2}
::

У PyTorch її повертає сама функція обрізання, навіть якщо обрізати нічого не треба (з порогом `inf`). Запишемо норму на кожному кроці:

::jupyter-notebook{title="exploding_gradients.ipynb" kernel="Python 3.11 (ipykernel)" executionCount="4" outputType="stdout"}

```python
def make_he_mlp(depth=10):                  # 10 лінійних шарів + ReLU, як у лекції 12
    layers = [nn.Flatten(), nn.Linear(784, 256), nn.ReLU()]
    for _ in range(depth - 2):
        layers += [nn.Linear(256, 256), nn.ReLU()]
    model = nn.Sequential(*layers, nn.Linear(256, 10))
    for m in model:
        if isinstance(m, nn.Linear):
            nn.init.kaiming_normal_(m.weight, nonlinearity="relu")
            nn.init.zeros_(m.bias)
    return model

torch.manual_seed(0)
model = make_he_mlp()
loader = DataLoader(train_set, batch_size=64, shuffle=True, generator=torch.Generator().manual_seed(0))
opt = torch.optim.SGD(model.parameters(), lr=1.0)

for step, (x, y) in enumerate(loader):
    loss = F.cross_entropy(model(x), y)
    opt.zero_grad(); loss.backward()
    norm = torch.nn.utils.clip_grad_norm_(model.parameters(), float("inf"))   # лише міряємо
    print(f"крок {step}: loss = {loss.item():.4g}, ‖g‖ = {norm.item():.4g}")
    opt.step()
    if step == 5:
        break
```

#output
крок 0: loss = 2.301, ‖g‖ = 2.432
крок 1: loss = 11.93, ‖g‖ = 50.3
крок 2: loss = 2498, ‖g‖ = 8043
крок 3: loss = 4.311e+20, ‖g‖ = inf
крок 4: loss = nan, ‖g‖ = nan
крок 5: loss = nan, ‖g‖ = nan
::

Чотири кроки: `2,3 → 11,9 → 2498 → 4·10²⁰ → nan`. Градієнт на кроці 0 цілком звичайний (`‖g‖ = 2,4`), але крок `lr · g` з такою швидкістю виявився завеликим, наступний градієнт уже `50`, потім `8043`. Якщо дотягнути навчання до кінця епохи, результат на тесті буде `9,8%` (мережа з `nan` у вагах видає однакову відповідь на все), і так для всіх трьох зерен.

::warning
`nan` у втраті завжди означає, що навчання вже загинуло: усі ваги стали `nan`, і далі нічого не відновиться. Видно це зазвичай не одразу: у `tqdm` чи в логах рядок `loss = nan`. Тому в довгому навчанні варто виводити норму градієнта: вибух помітний на ній за кілька кроків **до** `nan`.
::

## Обрізання градієнтів

Ідея проста: **не дозволяти кроку бути довшим за поріг**. Нехай `‖g‖` — поточна норма градієнта, `c` — поріг (`max_norm`). Якщо `‖g‖ > c`, множимо весь градієнт на `c / ‖g‖`, інакше лишаємо як є:

::math-formula
g \leftarrow g \cdot \min\left(1, \frac{c}{\|g\|}\right)
::

Весь вектор масштабується одним числом, тож **напрямок не змінюється**, змінюється лише довжина. Перевіримо на градієнті двох параметрів: перший `[3; 4]`, другий `[12]`. Норма `√(9 + 16 + 144) = 13`.

::jupyter-notebook{title="clip_by_hand.ipynb" kernel="Python 3.11 (ipykernel)" executionCount="5" outputType="stdout"}

```python
p1 = nn.Parameter(torch.zeros(2)); p1.grad = torch.tensor([3., 4.])
p2 = nn.Parameter(torch.zeros(1)); p2.grad = torch.tensor([12.])

total = torch.nn.utils.clip_grad_norm_([p1, p2], max_norm=1.0)
print("норма до обрізання:", total.item())
print("після:", p1.grad.tolist(), p2.grad.tolist())
print("нова норма:", (p1.grad.pow(2).sum() + p2.grad.pow(2).sum()).sqrt().item())

q = nn.Parameter(torch.zeros(2)); q.grad = torch.tensor([0.3, 0.4])
t = torch.nn.utils.clip_grad_norm_([q], max_norm=1.0)
print("малий градієнт:", t.item(), q.grad.tolist())
```

#output
норма до обрізання: 13.0
після: [0.23076921701431274, 0.307692289352417] [0.923076868057251]
нова норма: 0.9999999403953552
малий градієнт: 0.5 [0.30000001192092896, 0.4000000059604645]
::

Усі компоненти поділені на `13`, нова норма дорівнює `1`. А коли градієнт малий (`‖g‖ = 0,5 < 1`), функція його не чіпає. Повертає вона **норму до обрізання**, і саме тому її зручно використовувати як вимірювач.

У PyTorch є і друга функція, `clip_grad_value_`: вона обрізає **кожну компоненту** окремо до `[−c; c]`. Ціна: напрямок змінюється.

![Обрізання за нормою зберігає напрямок, обрізання за значенням змінює його](/images/ai-python/cnn-image-classification/layernorm-clipping/06.png){.diagram-img}

Градієнт `(3; 4)` після `clip_grad_norm_` стає `(0,6; 0,8)` (той самий напрямок), а після `clip_grad_value_` — `(1; 1)` (інший напрямок). Для навчання майже завжди беруть `clip_grad_norm_`.

### Де викликати

Між `backward()` і `step()`:

```python
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
optimizer.step()
```

Перед `backward()` градієнтів ще нема, після `step()` вони вже використані. Порядок критичний.

## Експеримент 3: швидкість навчання проти обрізання

Тепер та сама мережа з обрізанням `max_norm = 1,0`. Для кожної з п'яти швидкостей навчання (`0,05 … 2,0`) і кожного з двох режимів (без обрізання/з ним) навчаємо 1 епоху з трьома зернами.

![Норма градієнта без обрізання, з обрізанням і втрата, lr = 1,0](/images/ai-python/cnn-image-classification/layernorm-clipping/04.png){.diagram-img}

Ліворуч уже знайомий вибух. У центрі той самий запуск **з обрізанням**: показана норма до обрізання (це те, що повертає функція), пунктир — поріг. Норми спочатку досягають `~20` і вже до кінця епохи падають до порядку одиниці; оптимізатор ніколи не бачить більше за `1`. Праворуч втрата плавно падає, точність на тесті `94,71%`.

![Точність після 1 епохи для швидкостей навчання 0,05 … 2,0 без обрізання та з ним](/images/ai-python/cnn-image-classification/layernorm-clipping/05.png){.diagram-img}

| `lr` | Без обрізання, середнє з 3 | З `max_norm = 1`, середнє з 3 | Частка кроків, де спрацювало обрізання |
| :--- | :--- | :--- | :--- |
| 0,05 | 93,4% | 91,9% | 100% |
| 0,2 | 88,6% | 93,6% | 99–100% |
| 0,5 | 38,1% (`nan` у 2 зернах із 3) | 93,8% | 93–95% |
| 1,0 | 9,8% (`nan` у 3 із 3) | 93,6% | 78–79% |
| 2,0 | 9,8% (`nan` у 3 із 3) | 49,3% | 41–58% |

Що тут видно:

- Без обрізання навчання лишається стабільним до `lr = 0,2`; на `0,5` два зерна із трьох падають у `nan` (одне на кроці 79, інше на кроці 5), на `1,0` і далі гинуть усі.
- З обрізанням мережа **переживає `lr` до `1,0` включно** і дає `93,6–93,8%`: майже рівно те, що дає найкраща безпечна швидкість без обрізання.
- Але **обрізання не робить будь-яку швидкість хорошою**: на `lr = 2,0` мережа не вмирає, проте навчається погано (`49,3%`, зерна `56,6 / 53,2 / 38,2`).
- На найменшій швидкості `lr = 0,05` обрізання навіть шкодить: `91,9%` проти `93,4%`. Причина в останньому стовпці: медіанна норма градієнта цієї мережі без обрізання `≈ 2,8`, тож поріг `1` спрацьовує **на кожному кроці**. Тоді обрізання перестає бути «запобіжником від рідкісних сплесків» і перетворюється на нормування кожного кроку до довжини `lr · 1`, що по суті зменшує ефективну швидкість в `~3` рази. (Різниця `1,5` в. п. при трьох зернах із розкидом `4–5` в. п. між ними не можна вважати надійною.)

### Як вибирати `max_norm`

Правильно не «поставити 1,0, бо так пишуть», а **подивитися на звичайну норму градієнта** у своєму навчанні: записати її на кількох сотнях кроків (так само, як ми робили вище), подивитися на медіану й на хвіст. Поріг має бути вищим за типове значення (щоб звичайні кроки не чіпати) і значно нижчим за викиди. Тоді обрізання спрацьовує лише на аномаліях. Якщо воно спрацьовує на `> 50%` кроків, це знак: або поріг замалий, або швидкість навчання занадто велика, і краще знизити її.

::note
Обрізання градієнтів ховає симптом, але не лікує причину. Перший варіант лікування вибуху: менша швидкість навчання, хороша ініціалізація (лекція 12), нормалізація. Обрізання, це страховка зверху, особливо корисна на довгих навчаннях і в рекурентних мережах, де вибух градієнтів трапляється найчастіше.
::

Загальна норма `√(9 + 16 + 144) = 13 > 5`, тож множник `5 / 13 ≈ 0,3846`. Нові градієнти: `[3 · 0,3846; 4 · 0,3846] = [1,154; 1,538]` і `[12 · 0,3846] = [4,615]`. Нова норма `5`.

:::accordion-item{label="📋 Завдання 3: оберіть поріг" icon="i-lucide-clipboard-list"}

Ви записали норми градієнта на шести кроках: `[0,8; 1,1; 0,9; 45; 1,0; 1,2]`. Чому поріг `max_norm = 1,0` поганий вибір? Який порядок порогу розумніший? У скільки разів буде зменшено крок із нормою `45`, якщо поставити поріг `5`?

:::

:::accordion-item{label="✅ Розв'язок" icon="i-lucide-check-circle"}

Медіана норм дорівнює `1,0`, тобто це типове значення. Поріг `1,0` зачепить половину звичайних кроків (`1,1`, `1,2`, а іноді й `1,0`), хоча вони цілком здорові, і перетворить обрізання на постійне нормування. Розумніший поріг кілька разів вищий за медіану, наприклад `3–5`: він пропустить усі звичайні кроки й спрацює тільки на сплеску `45`. З порогом `5` сплеск буде помножений на `5 / 45 ≈ 0,111`, тобто крок зменшиться у `9` разів.

## Резюме

::card-group

::card{title="📌 LayerNorm" icon="i-lucide-align-justify"}
Нормалізує кожен приклад по його ознаках: без залежності від батча, без `running_*`, однаково в `train()` і `eval()`. Для згорткових карт: `GroupNorm(1, C)`. У нашому експерименті на MNIST не гірший за BatchNorm при всіх розмірах батча.
::

::card{title="📌 Вибух градієнтів" icon="i-lucide-zap"}
`lr = 1,0`: норма градієнта `2,4 → 50 → 8043 → inf`, а потім `nan` у втраті за 4 кроки. Помітити можна по нормі градієнта, яку повертає `clip_grad_norm_`.
::

::card{title="📌 Gradient clipping" icon="i-lucide-scissors"}
`g ← g · min(1, c / ‖g‖)`: напрямок збережено, довжина обмежена. Викликається між `backward()` і `step()`. Поріг вибирають за звичайною нормою градієнта: якщо спрацьовує на більшості кроків, поріг замалий або `lr` завеликий.
::

::card{title="📌 Межі методу" icon="i-lucide-shield-alert"}
З обрізанням мережа пережила `lr` до `1,0` (93,6%), але на `lr = 2,0` навчилася погано (49,3%). Обрізання це страховка, а не заміна доброго `lr`.
::

::
