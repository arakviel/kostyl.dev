# Аугментація даних

::card-group

::card{title="🎯 Мета лекції" icon="i-lucide-target"}

- Зрозуміти, чому мережа перенавчається на малому наборі й чим тут допомагає аугментація
- Користуватися `torchvision.transforms`: `RandomHorizontalFlip`, `RandomCrop`, `RandomErasing`, `Compose`
- Розрізняти перетворення для навчання й для тесту
- Виміряти внесок кожної аугментації окремо й разом (3 зерна, CIFAR-10)
- Вирішувати, яка аугментація підходить задачі, а яка ламає мітки

::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Аугментація даних (Data Augmentation):** випадкові зміни навчальних прикладів, які не змінюють їхньої мітки
- **Інваріантність (Invariance):** властивість, коли відповідь не залежить від певної зміни (кіт лишається котом, якщо його відобразити)
- **Відображення (Horizontal flip):** дзеркальне відбиття ліворуч-праворуч
- **Випадковий зсув (Random crop with padding):** добавити по краях нулі й вирізати з розширеного зображення випадкове вікно початкового розміру
- **Вирізання (Random Erasing):** закрити випадковий прямокутник зображення нулями
- **Перенавчання (Overfitting):** мережа запам'ятовує навчальні приклади й гірше працює на нових

::

::

## Проблема, яку ми залишили в лекції 10

У лекції 10 ширша CNN на CIFAR-10 дійшла до `73,3%` на тесті, а навчальна точність тим часом росла до `89%`. Розрив досягав `16` п. п. Тепер ми можемо його побачити ще виразніше: повторимо навчання на 25 епох (та сама мережа з 356 810 параметрами, Adam, батч 64, три зерна).

| Мережа без аугментації | 1-ша епоха | 9-та епоха | 25-та епоха |
| :--- | :--- | :--- | :--- |
| Точність на тесті (середнє з 3) | 55% | **74,6%** (максимум) | 72,3% |
| Втрата на тесті | 1,25 | 0,78 (мінімум 0,77 на 7-й епосі) | **1,69** |
| Точність на навчанні (без збурень) | 56% | ~87% | **96,2%** |

Мережа майже ідеально запам'ятала `50 000` навчальних фото (`96%` на навчанні), але на нових фото стала гіршою, ніж була на 9-й епосі, а втрата на тесті зросла вдвічі від свого мінімуму. Це класичне **перенавчання**. Dropout у лекції 10 допоміг лише на 0,2 п. п.

Причина проста: `50 000` фото, а параметрів `356 810`. У мережі достатньо «пам'яті», щоб завчити кожне фото напам'ять, включно з випадковими деталями (наприклад, що «цей конкретний кіт сидить трохи лівіше»). Для справжнього розв'язання потрібні **нові приклади**, але фотографувати ще `50 000` котів ми не будемо. Є дешевший спосіб.

## Ідея: той самий кіт, інший кадр

Якщо відобразити фото кота дзеркально, це все ще кіт. Якщо зсунути його на два пікселі вбік, теж кіт. Наш мозок вважає ці фото «тим самим», а для мережі це **зовсім інший вектор пікселів** (ми бачили це в лекції 02: зсув змінює майже всі числа). Ми можемо використати це так: **кожного разу, коли мережа бере фото з набору, ми випадково його видозмінюємо**. На кожній епосі вона бачить трохи інший варіант того самого прикладу з тією самою міткою.

## Інструменти: `torchvision.transforms`

Перетворення в `torchvision` це маленькі об'єкти, які беруть зображення й повертають його змінену копію. `Compose` склеює їх у ланцюжок. Раніше в нас був лише `transforms.ToTensor()`; тепер ланцюжок довшає.

::jupyter-notebook{title="transforms_basics.ipynb" kernel="Python 3.11 (ipykernel)"}

::jupyter-cell{type="markdown"}
Візьмемо одне фото CIFAR-10 *без* перетворення (це PIL-зображення) і подивимося, що роблять окремі кроки.
::

::jupyter-cell{executionCount="1" outputType="stdout"}
```python
import torch
from torchvision import datasets, transforms as T

raw = datasets.CIFAR10("data", train=True, download=True)      # без transform: повертає PIL-зображення
img, label = raw[3]
print(type(img).__name__, img.size, "мітка:", label)

to_t = T.ToTensor()
x = to_t(img)

flip = T.RandomHorizontalFlip(p=1.0)                           # p=1: відображаємо завжди (для перевірки)
print("flip == x.flip(-1):", torch.equal(to_t(flip(img)), x.flip(-1)))
```

#output
Image (32, 32) мітка: 4
flip == x.flip(-1): True
::

::jupyter-cell{type="markdown"}
`RandomHorizontalFlip(p=0.5)` у навчанні відображає кожне фото з імовірністю `0,5`. Для перевірки ми поставили `p=1.0` і побачили, що результат дорівнює перевороту тензора за віссю ширини. Тепер зсув: `RandomCrop(32, padding=4)` обводить фото рамкою з нулів завширшки 4 пікселі, а потім вирізає з розширеної картинки випадкове вікно `32 × 32`.
::

::jupyter-cell{executionCount="2" outputType="stdout"}
```python
crop = T.RandomCrop(32, padding=4)
torch.manual_seed(0)
for k in range(3):
    c = to_t(crop(img))
    zero_rows = int((c.sum((0, 2)) == 0).sum())
    zero_cols = int((c.sum((0, 1)) == 0).sum())
    print(f"зсув {k}: форма {tuple(c.shape)}, порожніх рядків {zero_rows}, стовпців {zero_cols}, збігається з оригіналом: {torch.equal(c, x)}")
```

#output
зсув 0: форма (3, 32, 32), порожніх рядків 4, стовпців 4, збігається з оригіналом: False
зсув 1: форма (3, 32, 32), порожніх рядків 2, стовпців 2, збігається з оригіналом: False
зсув 2: форма (3, 32, 32), порожніх рядків 3, стовпців 2, збігається з оригіналом: False
::

::

Розмір не змінився, але з одного боку з'явилася чорна смуга, а об'єкт зсунувся. Кожен виклик дає інший зсув (до 4 пікселів у кожну сторону). Третє перетворення, `RandomErasing`, закриває випадковий прямокутник; воно працює вже **над тензором**, тому ставиться після `ToTensor()`.

### Для навчання й для тесту: різні ланцюжки

Ось ключове правило: **аугментація лише для навчання**. На тесті ми хочемо оцінити мережу на справжніх, не спотворених фото; випадковість там означала б, що одне й те саме фото щоразу дає різну оцінку.

::jupyter-notebook{title="train_test_transforms.ipynb" kernel="Python 3.11 (ipykernel)" executionCount="3" outputType="stdout"}

```python
train_tf = T.Compose([
    T.RandomCrop(32, padding=4),
    T.RandomHorizontalFlip(),
    T.ToTensor(),
])
test_tf = T.ToTensor()                                         # без випадковості

torch.manual_seed(1)
a, b = train_tf(img), train_tf(img)
print("два виклики train_tf дають однакове:", torch.equal(a, b))
print("test_tf детермінований:", torch.equal(test_tf(img), test_tf(img)))

er = T.RandomErasing(p=1.0, scale=(0.02, 0.2))
torch.manual_seed(2)
e = er(x.clone())
print("вирізано пікселів:", int(((e == 0).all(0)).sum()), "із 1024")
```

#output
два виклики train_tf дають однакове: False
test_tf детермінований: True
вирізано пікселів: 88 із 1024
::

Підключаються перетворення через параметр `transform` датасету, решта навчального коду з лекції 10 лишається такою самою:

```python
train_set = datasets.CIFAR10("data", train=True, download=True, transform=train_tf)
test_set = datasets.CIFAR10("data", train=False, download=True, transform=test_tf)
loader = DataLoader(train_set, batch_size=64, shuffle=True)
```

Перетворення виконуються **щоразу, коли датасет віддає приклад**, тобто в кожній епосі отримуємо інший варіант.

## Експеримент: що дає кожна аугментація

Беремо ту саму мережу (`WideCNN` з лекції 10, без Dropout), той самий Adam з `lr = 0,001` і батч 64. Змінюється лише `transform` навчального набору. П'ять варіантів по 25 епох, по 3 зерна кожен:

::jupyter-notebook{title="augmentation_ablation.ipynb" kernel="Python 3.11 (ipykernel)" executionCount="4"}

```python
CONFIGS = {
    "none":            [],
    "flip":            [T.RandomHorizontalFlip()],
    "crop":            [T.RandomCrop(32, padding=4)],
    "flip_crop":       [T.RandomCrop(32, padding=4), T.RandomHorizontalFlip()],
    "flip_crop_erase": [T.RandomCrop(32, padding=4), T.RandomHorizontalFlip()],   # + RandomErasing після ToTensor
}

def make_transform(name):
    ops = list(CONFIGS[name]) + [T.ToTensor()]
    if name == "flip_crop_erase":
        ops.append(T.RandomErasing(p=0.5))
    return T.Compose(ops)

# далі: DataLoader(train_set з цим transform), навчання як у лекції 10, 25 епох
# точність на навчанні міряємо на 10 000 фото БЕЗ аугментації, в режимі eval()
```
::

![Точність на тесті, втрата й розрив між навчанням та тестом: без аугментації та з відображенням і зсувом](/images/ai-python/cnn-image-classification/data-augmentation/02.png){.diagram-img}

Три панелі розповідають одну історію:

- **Точність (ліворуч).** Без аугментації (сіра) тестова крива припиняє зростати приблизно на 9-й епосі і трохи падає, а навчальна (пунктир) продовжує до `96%`. З аугментацією (зелена) тестова точність росте до 22-ї епохи й досягає `79,4%`, а навчальна точність скромніша: `83,7%`.
- **Втрата (посередині).** Без аугментації втрата на тесті після 7-ї епохи росте до `1,69`. З аугментацією втрата падає до `0,60` і лишається там.
- **Розрив (праворуч).** Без аугментації розрив між навчанням і тестом дорівнює `23,9` п. п., з нею `4,6`.

::note
Не лякайтеся того, що навчальна точність із аугментацією нижча (`83,7%` проти `96,2%`). Мережа вже не може завчити кожне фото, бо щоразу бачить його по-іншому. Це не погіршення, а прибрана можливість «списувати». Для оцінки якості модель дивиться саме на тест.
::

Ще одне зауваження. На 10-й епосі аугментація ще не виграє: `75,2%` проти `74,3%` без неї. Вона платить повільнішим навчанням і виправдовується лише на довгій дистанції. Тому з аугментацією епох потрібно більше.

### Внесок кожного перетворення

![Точність на тесті на 25-й епосі та розрив для п'яти варіантів аугментації](/images/ai-python/cnn-image-classification/data-augmentation/03.png){.diagram-img}

| Аугментація | Три зерна, тест після 25 епох | Середнє | Розрив навчання − тест |
| :--- | :--- | :--- | :--- |
| Без | 72,84 / 71,90 / 72,16 | **72,3%** | 23,9 п. п. |
| Відображення | 77,11 / 76,89 / 76,62 | **76,9%** | 15,7 п. п. |
| Зсув | 78,30 / 77,67 / 78,43 | **78,1%** | 7,3 п. п. |
| Відображення + зсув | 79,38 / 78,98 / 78,94 | **79,1%** | 4,6 п. п. |
| + вирізання | 78,25 / 76,84 / 79,07 | **78,1%** | 4,1 п. п. |

Що видно:

- Кожна з двох базових аугментацій дає багато: відображення `+4,6` п. п., зсув `+5,8` п. п. Разом `+6,8` п. п. (з `72,3%` до `79,1%`). Розкид між зернами в кожному з цих варіантів `≤ 0,8` п. п., тож ефект однозначний.
- **Вирізання не допомогло**: `78,1%` проти `79,1%` без нього, а розкид між зернами (`76,8 … 79,1`) більший за саму різницю. Тут вирізання лише додало шуму. Можливо, для маленьких `32 × 32` фото, де об'єкт займає майже весь кадр, закрита ділянка вилучає надто багато інформації, або нам потрібно навчати довше. Ми це не перевіряли. Вирізання не слід викидати на загал: на великих зображеннях і глибших мережах воно часто корисне, тут ми просто його ефекту не побачили.
- Розрив (`23,9 → 4,6`) скоротився в `5` разів, а тестова точність виросла на `6,8` п. п. 
- Час епохи не змінився: `28 с` без аугментації, `27–28 с` з нею. Для цих малих картинок перетворення практично безкоштовні.

### Кому допомогло

Подивимося на точність по класах у зерні 0: сіра смуга без аугментації, зелена з відображенням і зсувом.

![Точність по класах CIFAR-10 без аугментації й із відображенням та зсувом](/images/ai-python/cnn-image-classification/data-augmentation/04.png){.diagram-img}

Найбільше виграли **собака** (`+15,1` п. п.), **вантажівка** (`+11,1`) і **олень** (`+9,6`); майже не змінилися **літак** (`−0,7`) і **птах** (`+3,1`). Але це одне зерно, і різниці в один-два пункти можна не брати до уваги.

## Аугментація має зберігати мітку

Не кожна зміна зображення безпечна. Правило: **зміна не повинна перетворювати правильну мітку на неправильну**, і вона має бути схожою на ті варіації, які реально є в тестових даних. Для демонстрації візьмемо «погану» аугментацію: перевернути догори дриґом (`RandomVerticalFlip`) і повернути на випадковий кут до 90° (`RandomRotation(90)`). Рядок знизу на галереї вище показує, що вийшло: олень лежить на боці, автомобіль стоїть на даху.

![Тестова точність: без аугментації, з відображенням та зсувом і з поганою аугментацією](/images/ai-python/cnn-image-classification/data-augmentation/05.png){.diagram-img}

Результат поганої аугментації (зерно 0, 25 епох): `60,7%`, тобто **гірше, ніж без аугментації** (`72,8%` у того ж зерна) на `12` п. п. Мережа гарно навчилась розпізнавати перевернутих коней, а тестові коні стоять на ногах. Розрив між навчанням і тестом майже зник (`2,6` п. п.), але не тому, що вона стала узагальнювати краще: вона просто не змогла навчитись добре (навчальна точність лише `63,3%`).

Кілька правил на практиці:

| Задача | Що безпечно | Що небезпечно |
| :--- | :--- | :--- |
| Тварини, машини, пейзажі | відображення ліворуч-праворуч, невеликі зсуви, невелика зміна яскравості | переворот догори дриґом, поворот на великий кут |
| Цифри або літери | невеликі зсуви, легкі повороти (до ~15°) | відображення (`2` стане схожою на `5`, а `6` на `9` після повороту) |
| Медичні знімки | зазвичай невеликі зсуви й зміна яскравості, **залежить від лікаря** | відображення, якщо сторона тіла несе діагностичний сенс |

::warning
Більше аугментації не означає краще. Кожне перетворення вводить в тренувальні дані «розподіл», якого, можливо, немає у справжніх даних. Тестувати кожну аугментацію потрібно так само, як ми це зробили тут: порівняти точність на **не аугментованому** тесті.
::

::note
Додаткові перетворення для кольору: `ColorJitter` (яскравість, контраст, насиченість), `RandomRotation(15)` для невеликих поворотів, `RandomResizedCrop` для довільних кадрувань. Ми їх тут не міряли і не стверджуємо, що вони допоможуть на CIFAR-10; перевірити їх так само, як відображення, ви можете самі.

## Практика

::::accordion

:::accordion-item{label="📋 Завдання 1: порахуйте розмір поля" icon="i-lucide-clipboard-list"}

`RandomCrop(32, padding=4)` застосовано до фото `32 × 32`. Який розмір має зображення після додавання поля? Скільки різних позицій вікна можливо по горизонталі, по вертикалі й разом? Яка максимальна ширина «порожньої» (нульової) смуги, яка може з'явитися з одного боку?

:::

:::accordion-item{label="✅ Розв'язок" icon="i-lucide-check-circle"}

Після поля `32 + 2 · 4 = 40` пікселів з кожного боку, тобто `40 × 40`. Вікно `32 × 32` може стояти так, що його ліва межа починається з колонки `0, 1, …, 8`: це `40 − 32 + 1 = 9` позицій по горизонталі й стільки ж по вертикалі, тож `9 · 9 = 81` різний зсув (включно з нульовим). Якщо вікно доходить до краю поля, з одного боку з'являється нульова смуга завширшки `4` пікселі (як у нашому прикладі: «порожніх рядків 4»).

::jupyter-notebook{title="crop_positions.ipynb" kernel="Python 3.11 (ipykernel)" executionCount="1" outputType="stdout"}

```python
padded = 32 + 2 * 4
positions = padded - 32 + 1
print(padded, positions, positions ** 2)
```

#output
40 9 81
::

Пам'ятайте, що кожен зсув у цих `81` варіантів можна ще й відобразити (`× 2`), тобто з одного фото виходить `162` різні картинки до вирізання.

:::

:::accordion-item{label="📋 Завдання 2: що не так у цьому коді" icon="i-lucide-clipboard-list"}

Студент написав:

```python
tf = T.Compose([T.RandomCrop(32, padding=4), T.RandomHorizontalFlip(), T.ToTensor()])
train_set = datasets.CIFAR10("data", train=True, transform=tf)
test_set = datasets.CIFAR10("data", train=False, transform=tf)
```

Яка помилка? Як вона змінить результат оцінки і чому це погано?

:::

:::accordion-item{label="✅ Розв'язок" icon="i-lucide-check-circle"}

Для тесту використано той самий ланцюжок із випадковими перетвореннями. Тестові фото щоразу будуть дещо зсунуті й відображені, тож оцінка стане випадковою: два запуски `evaluate` на тих самих вагах дадуть різні числа. До того ж ми вимірюємо якість на спотворених фото, а не на справжніх. Правильно: `test_tf = T.ToTensor()` (без випадковості) для тесту.

::jupyter-notebook{title="test_noise.ipynb" kernel="Python 3.11 (ipykernel)" executionCount="1" outputType="stdout"}

```python
import torch
from torchvision import datasets, transforms as T

tf = T.Compose([T.RandomCrop(32, padding=4), T.RandomHorizontalFlip(), T.ToTensor()])
test_set = datasets.CIFAR10("data", train=False, download=True, transform=tf)
a = test_set[0][0]
b = test_set[0][0]
print("одне й те саме тестове фото двічі однакове?", torch.equal(a, b))
```

#output
одне й те саме тестове фото двічі однакове? False
::

(Вивід `False` може іноді бути `True`, якщо випадково обереться той самий зсув без відображення, але в більшості викликів він `False`.)

:::

:::accordion-item{label="📋 Завдання 3: оберіть аугментації" icon="i-lucide-clipboard-list"}

Для кожної задачі вирішіть, чи підходить відображення ліворуч-праворуч: (а) класифікація фото тварин; (б) розпізнавання рукописних цифр; (в) розпізнавання дорожніх знаків «поворот ліворуч»/«поворот праворуч». Поясніть.

:::

:::accordion-item{label="✅ Розв'язок" icon="i-lucide-check-circle"}

(а) Підходить: відображена тварина лишається тією самою твариною; саме це ми використали на CIFAR-10. (б) Не підходить: відображена цифра `2` схожа на `5`, а симетричних цифр, що збігаються з відображеними, замало, так що мітка ламається. (в) Категорично ні: відображення перетворює «поворот ліворуч» на «поворот праворуч», тобто мітка стає неправильною. Загальне правило: перетворення дозволене, лише якщо **мітка після нього залишається тією самою**.

:::
