## Перший крок навчання — чому початкові ваги критичні

У попередній статті ми опанували Mini-batch Gradient Descent та навчилися ефективно завантажувати дані через PyTorch DataLoader. Тепер наша модель готова до навчання: датасет розбито на батчі, оптимізатор налаштовано, функція втрат визначена. Залишилося натиснути «запуск» та спостерігати, як loss зменшується, а accuracy зростає.

Але перед першою ітерацією градієнтного спуску відбувається **критичний момент**, який часто залишається поза увагою початківців: **ініціалізація ваг**. Саме від того, з яких значень розпочне навчання модель, залежить:

::card-group

::card{title="🎯 Чи навчиться модель взагалі" icon="i-lucide-target"}

Погана ініціалізація може призвести до **dead network** — мережі, де всі нейрони обчислюють однакові значення, і градієнти не оновлюють ваги. Модель застрягає у початковій точці назавжди.

::

::card{title="⚡ Швидкість конвергенції" icon="i-lucide-zap"}

Правильна ініціалізація дозволяє використовувати **великий learning rate** (0.01-0.1 замість 0.0001), що прискорює навчання у **5-10 разів**. Різниця між 2 годинами та 20 годинами тренування.

::

::card{title="📊 Фінальна якість моделі" icon="i-lucide-trending-up"}

Глибокі мережі (10+ шарів) із поганою ініціалізацією часто застрягають у **погіршених локальних мінімумах**, досягаючи 70% accuracy там, де правильна ініціалізація дає 85%.

::

::

Уявіть альпініста, який збирається підкорити вершину. Якщо він стартує з підніжжя гори (правильна ініціалізація), шлях довгий, але досяжний. Якщо ж його телепортувати на дно глибокої ущелини (погана ініціалізація), він витратить весь час, намагаючись вибратися, і ніколи не досягне вершини.

::card-group

::card{title="🎯 Мета статті" icon="i-lucide-target"}

- Зрозуміти, чому нульова та константна ініціалізація не працюють (проблема симетрії)
- Дослідити наївний підхід випадкової ініціалізації та його недоліки
- Опанувати математику Xavier/Glorot ініціалізації для tanh/sigmoid активацій
- Вивчити He ініціалізацію, спеціально розроблену для ReLU
- Навчитися використовувати `nn.init` модуль PyTorch
- Провести експеримент на глибокій мережі, порівнюючи різні методи

::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Symmetry Breaking:** порушення симетрії — необхідність різних початкових ваг для різних нейронів
- **Vanishing/Exploding Gradients:** зникаючі/вибухаючі градієнти через неправильну дисперсію ваг
- **Xavier/Glorot Initialization:** ініціалізація для збереження дисперсії активацій у мережах з tanh/sigmoid
- **He Initialization:** модифікація Xavier для ReLU активацій (Kaiming He, 2015)
- **Fan-in / Fan-out:** кількість входів та виходів нейрона (використовується у формулах ініціалізації)

## Проблема 1: Нульова ініціалізація — мертва мережа

Найбільш інтуїтивний підхід: **ініціалізувати всі ваги нулями**. Логіка проста — модель «не знає нічого», тому почнемо з нуля, а градієнтний спуск сам знайде правильні значення. На жаль, це **фундаментально не працює**.

### Побудова простої двошарової мережі

Створимо мережу з двома прихованими шарами для класифікації MNIST. Спочатку ініціалізуємо всі ваги нулями.

::

::jupyter-cell{executionCount="1" executionTime="0.28s"}

```python
import torch
import torch.nn as nn
import torch.optim as optim
from torch.utils.data import DataLoader
from torchvision import datasets, transforms

# Простий MLP
class SimpleMLP(nn.Module):
    def __init__(self):
        super(SimpleMLP, self).__init__()
        self.fc1 = nn.Linear(784, 256)
        self.fc2 = nn.Linear(256, 128)
        self.fc3 = nn.Linear(128, 10)
        self.relu = nn.ReLU()
    
    def forward(self, x):
        x = x.view(x.size(0), -1)  # Flatten
        x = self.relu(self.fc1(x))
        x = self.relu(self.fc2(x))
        x = self.fc3(x)
        return x

# Створення моделі
device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')
model = SimpleMLP().to(device)

# Нульова ініціалізація всіх ваг
def init_weights_zero(m):
    if isinstance(m, nn.Linear):
        nn.init.constant_(m.weight, 0.0)
        nn.init.constant_(m.bias, 0.0)

model.apply(init_weights_zero)

# Перевірка ваг
print("🔍 Перевірка ваг після нульової ініціалізації:\n")
for name, param in model.named_parameters():
    if 'weight' in name:
        print(f"{name:20s} | Mean: {param.mean().item():.6f} | Std: {param.std().item():.6f}")
```

### Що відбувається під час backward pass?

Тепер спробуймо навчити таку модель та подивимося на градієнти:

::jupyter-cell{executionCount="3" executionTime="0.85s"}

```python
# Ініціалізуємо модель заново з нульовими вагами
model = SimpleMLP().to(device)
model.apply(init_weights_zero)

criterion = nn.CrossEntropyLoss()
optimizer = optim.SGD(model.parameters(), lr=0.01)

model.train()
images, labels = next(iter(train_loader))
images, labels = images.to(device), labels.to(device)

# Forward pass

loss = criterion(outputs, labels)

# Backward pass
optimizer.zero_grad()
loss.backward()

# Аналіз градієнтів
print("🔍 Аналіз градієнтів після backward pass:\n")
for name, param in model.named_parameters():
    if param.grad is not None and 'weight' in name:
        grad_mean = param.grad.mean().item()
        grad_std = param.grad.std().item()
        unique_grads = torch.unique(param.grad, dim=1 if param.grad.ndim > 1 else 0)
        
        print(f"{name:20s}")
        print(f"  Mean градієнта: {grad_mean:.8f}")
        print(f"  Std градієнта:  {grad_std:.8f}")
        print(f"  Унікальних рядків: {len(unique_grads)}")
        
        # Перевірка симетрії: чи всі рядки однакові?
        if param.grad.ndim == 2:
            first_row = param.grad[0]
            all_same = all(torch.allclose(param.grad[i], first_row) for i in range(min(5, param.grad.size(0))))
            print(f"  Симетрія: {'ВСІ РЯДКИ ІДЕНТИЧНІ ❌' if all_same else 'Рядки різні ✅'}")
        print()
```

### Математичне пояснення симетрії

Розглянемо, що відбувається у **першому прихованому шарі**. Нехай маємо :math-formula{tex="n" inline} нейронів, і всі ваги ініціалізовані нулями:

::math-formula
w_{ij}^{(1)} = 0 \quad \forall i, j
::

Для будь-якого входу :math-formula{tex="\mathbf{x}" inline}, активація :math-formula{tex="i" inline}-го нейрона:

::math-formula
z_i^{(1)} = \sum_{j=1}^{d} w_{ij}^{(1)} x_j + b_i^{(1)} = 0 + 0 = 0
::

Після функції активації (наприклад, ReLU):

::math-formula
a_i^{(1)} = \text{ReLU}(0) = 0
::

**Всі нейрони виводять нуль!** Тепер розглянемо градієнти під час backpropagation. Градієнт втрат по вазі :math-formula{tex="w_{ij}^{(1)}" inline} обчислюється як:

::math-formula
\frac{\partial L}{\partial w_{ij}^{(1)}} = \frac{\partial L}{\partial z_i^{(1)}} \cdot \frac{\partial z_i^{(1)}}{\partial w_{ij}^{(1)}} = \frac{\partial L}{\partial z_i^{(1)}} \cdot x_j
::

Оскільки всі :math-formula{tex="z_i^{(1)}" inline} однакові (нуль), то :math-formula{tex="\frac{\partial L}{\partial z_i^{(1)}}" inline} також однакові для всіх :math-formula{tex="i" inline}. Отже, **всі нейрони отримують однаковий градієнт** (з точністю до множника :math-formula{tex="x_j" inline}).

Після оновлення ваг:

::math-formula
w_{ij}^{(1)} \leftarrow 0 - \eta \cdot \delta \cdot x_j
::

Де :math-formula{tex="\delta" inline} — **однаковий для всіх нейронів**. Це означає, що після першого оновлення всі нейрони отримують **пропорційні ваги**, і симетрія зберігається на всіх наступних ітераціях!

::note
**Висновок:**

Нульова ініціалізація призводить до **повної симетрії нейронів** у кожному шарі. Вони обчислюють однакові значення, отримують однакові градієнти та оновлюються однаково. Фактично, мережа з 256 нейронами у прихованому шарі еквівалентна мережі з **одним нейроном**, помноженим на 256. Це величезна втрата виразності моделі.
::

## Проблема 2: Випадкова ініціалізація з великою дисперсією

Добре, нульова ініціалізація не працює. Очевидне рішення: **ініціалізувати ваги випадково** з нормального або рівномірного розподілу. Це порушить симетрію, і нейрони почнуть вчитися різних ознак.

Спробуймо наївний підхід: ініціалізувати ваги з :math-formula{tex="\mathcal{N}(0, 1)" inline} (стандартний нормальний розподіл).

::jupyter-notebook{title="naive_random_initialization.ipynb"}

::jupyter-cell{executionCount="1" executionTime="0.52s"}

```python
import numpy as np
import matplotlib.pyplot as plt

# Глибока мережа: 10 шарів
class DeepMLP(nn.Module):
    def __init__(self, input_size=784, hidden_size=256, num_layers=10, output_size=10):
        super(DeepMLP, self).__init__()
        layers = []
        
        # Перший шар
        layers.append(nn.Linear(input_size, hidden_size))
        layers.append(nn.ReLU())
        
        # Приховані шари
        for _ in range(num_layers - 2):
            layers.append(nn.Linear(hidden_size, hidden_size))
            layers.append(nn.ReLU())
        
        # Вихідний шар
        layers.append(nn.Linear(hidden_size, output_size))
        
        self.network = nn.Sequential(*layers)
        self.num_layers = num_layers
    
    def forward(self, x):
        x = x.view(x.size(0), -1)
        return self.network(x)

# Модель із наївною ініціалізацією
model = DeepMLP(num_layers=10).to(device)

def init_weights_naive(m):
    if isinstance(m, nn.Linear):
        # Наївна ініціалізація: N(0, 1)
        nn.init.normal_(m.weight, mean=0.0, std=1.0)
        nn.init.constant_(m.bias, 0.0)

model.apply(init_weights_naive)

print("✅ Модель створено: 10 шарів, наївна ініціалізація N(0, 1)")
print(f"   Загальна кількість параметрів: {sum(p.numel() for p in model.parameters()):,}")
```

### Математичне пояснення вибухаючих активацій

Розглянемо, що відбувається при проходженні сигналу через :math-formula{tex="L" inline} шарів. Активація :math-formula{tex="i" inline}-го шару:

::math-formula
\mathbf{a}^{(i)} = f(\mathbf{W}^{(i)} \mathbf{a}^{(i-1)} + \mathbf{b}^{(i)})
::

Де :math-formula{tex="f" inline} — функція активації (ReLU). Для спрощення аналізу припустимо, що всі bias нульові та ReLU не обнуляє нічого (оптимістичний сценарій). Тоді:

::math-formula
\mathbf{a}^{(i)} \approx \mathbf{W}^{(i)} \mathbf{a}^{(i-1)}
::

Після :math-formula{tex="L" inline} шарів:

::math-formula
\mathbf{a}^{(L)} \approx \mathbf{W}^{(L)} \mathbf{W}^{(L-1)} \cdots \mathbf{W}^{(1)} \mathbf{x}
::

Якщо ваги ініціалізовані з :math-formula{tex="\mathcal{N}(0, \sigma^2)" inline}, то дисперсія елементів :math-formula{tex="\mathbf{W}^{(i)} \mathbf{a}^{(i-1)}" inline} приблизно:

::math-formula
\text{Var}(\mathbf{W} \mathbf{a}) \approx n \cdot \sigma_w^2 \cdot \sigma_a^2
::

Де :math-formula{tex="n" inline} — розмір входу (кількість нейронів у попередньому шарі). Якщо :math-formula{tex="\sigma_w = 1" inline} та :math-formula{tex="n = 256" inline}, то після одного шару дисперсія зростає у **256 разів**! Після 10 шарів:

::math-formula
\sigma_a^{(10)} \approx \sigma_a^{(0)} \cdot (256)^{10} \approx 10^{24} \cdot \sigma_a^{(0)}
::

Значення стають астрономічними. З іншого боку, якщо :math-formula{tex="\sigma_w" inline} занадто мала (наприклад, 0.01), дисперсія **зменшується** експоненціально, і активації **зникають** (стають нулями).

::note
**Ключова інтуїція:**

Для стабільного проходження сигналу через глибоку мережу нам потрібно, щоб **дисперсія активацій залишалася приблизно постійною** від шару до шару. Це вимагає ретельного вибору дисперсії ініціалізації ваг.
::

## Розв'язання: Xavier (Glorot) ініціалізація

У 2010 році Xavier Glorot та Yoshua Bengio запропонували метод ініціалізації, який зберігає дисперсію активацій та градієнтів однаковою на всіх шарах. Цей метод тепер називається **Xavier initialization** або **Glorot initialization**.

### Математичне виведення

**Мета:** знайти таку дисперсію :math-formula{tex="\sigma_w^2" inline}, щоб дисперсія виходу шару дорівнювала дисперсії входу.

Розглянемо лінійний шар без bias:

::math-formula
z_i = \sum_{j=1}^{n_{\text{in}}} w_{ij} a_j
::

Припустимо:
1. Входи :math-formula{tex="a_j" inline} незалежні та мають нульове середнє: :math-formula{tex="E[a_j] = 0" inline}
2. Ваги :math-formula{tex="w_{ij}" inline} незалежні, мають нульове середнє: :math-formula{tex="E[w_{ij}] = 0" inline}
3. Входи та ваги взаємно незалежні

Тоді дисперсія :math-formula{tex="z_i" inline}:

::math-formula
\text{Var}(z_i) = \text{Var}\left(\sum_{j=1}^{n_{\text{in}}} w_{ij} a_j\right) = \sum_{j=1}^{n_{\text{in}}} \text{Var}(w_{ij} a_j)
::

Оскільки :math-formula{tex="w_{ij}" inline} та :math-formula{tex="a_j" inline} незалежні:

::math-formula
\text{Var}(w_{ij} a_j) = E[w_{ij}]^2 \text{Var}(a_j) + E[a_j]^2 \text{Var}(w_{ij}) + \text{Var}(w_{ij}) \text{Var}(a_j)
::

Оскільки середні нульові:

::math-formula
\text{Var}(w_{ij} a_j) = \text{Var}(w_{ij}) \text{Var}(a_j)
::

Отже:

::math-formula
\text{Var}(z_i) = \sum_{j=1}^{n_{\text{in}}} \text{Var}(w_{ij}) \text{Var}(a_j) = n_{\text{in}} \cdot \sigma_w^2 \cdot \sigma_a^2
::

**Умова збереження дисперсії (forward pass):**

Щоб :math-formula{tex="\text{Var}(z_i) = \text{Var}(a_j)" inline}, потрібно:

::math-formula
n_{\text{in}} \cdot \sigma_w^2 = 1 \quad \Rightarrow \quad \sigma_w^2 = \frac{1}{n_{\text{in}}}
::

**Умова збереження дисперсії (backward pass):**

Аналогічний аналіз для градієнтів показує, що для збереження дисперсії градієнтів при backpropagation потрібно:

::math-formula
n_{\text{out}} \cdot \sigma_w^2 = 1 \quad \Rightarrow \quad \sigma_w^2 = \frac{1}{n_{\text{out}}}
::

Де :math-formula{tex="n_{\text{out}}" inline} — кількість виходів шару (кількість нейронів у наступному шарі).

**Компроміс Xavier:**

Оскільки не можна одночасно задовольнити обидві умови (якщо :math-formula{tex="n_{\text{in}} \neq n_{\text{out}}" inline}), Glorot запропонував використовувати **середнє**:

::math-formula
\sigma_w^2 = \frac{2}{n_{\text{in}} + n_{\text{out}}}
::

### Формули Xavier ініціалізації

**Для рівномірного розподілу:**

::math-formula
w_{ij} \sim \mathcal{U}\left(-\sqrt{\frac{6}{n_{\text{in}} + n_{\text{out}}}}, \sqrt{\frac{6}{n_{\text{in}} + n_{\text{out}}}}\right)
::

**Для нормального розподілу:**

::math-formula
w_{ij} \sim \mathcal{N}\left(0, \frac{2}{n_{\text{in}} + n_{\text{out}}}\right)
::

::tip
**Коли використовувати Xavier:**

Xavier ініціалізація розроблялася для **sigmoid** та **tanh** активацій, які мають приблизно лінійну поведінку навколо нуля. Для цих функцій Xavier працює **чудово**.

Однак для **ReLU** Xavier дає **субоптимальні** результати, бо ReLU обнуляє половину входів, що порушує припущення виведення.
::

## He ініціалізація — спеціально для ReLU

У 2015 році Kaiming He зі співавторами опублікували статтю «Delving Deep into Rectifiers», де запропонували модифікацію Xavier ініціалізації для ReLU активацій. Ця ініціалізація тепер називається **He initialization** або **Kaiming initialization**.

### Проблема ReLU з Xavier

ReLU має властивість:

::math-formula
\text{ReLU}(z) = \max(0, z) = \begin{cases} z & \text{якщо } z > 0 \\ 0 & \text{якщо } z \leq 0 \end{cases}
::

Якщо вхід має симетричний розподіл навколо нуля (як після Xavier ініціалізації), ReLU **обнуляє приблизно половину** нейронів. Це означає, що **ефективна кількість нейронів** зменшується удвічі.

Розглянемо дисперсію після ReLU. Якщо :math-formula{tex="z \sim \mathcal{N}(0, \sigma_z^2)" inline}, то після ReLU:

::math-formula
\text{Var}(\text{ReLU}(z)) \approx \frac{1}{2} \sigma_z^2
::

Дисперсія **зменшується удвічі**! Щоб компенсувати це, He запропонував **подвоїти** дисперсію ваг.

### Формули He ініціалізації

**Для нормального розподілу:**

::math-formula
w_{ij} \sim \mathcal{N}\left(0, \frac{2}{n_{\text{in}}}\right)
::

**Для рівномірного розподілу:**

::math-formula
w_{ij} \sim \mathcal{U}\left(-\sqrt{\frac{6}{n_{\text{in}}}}, \sqrt{\frac{6}{n_{\text{in}}}}\right)
::

Зверніть увагу: He ініціалізація використовує **лише** :math-formula{tex="n_{\text{in}}" inline} (кількість входів), на відміну від Xavier, який усереднює :math-formula{tex="n_{\text{in}}" inline} та :math-formula{tex="n_{\text{out}}" inline}.

::note
**Варіанти He ініціалізації:**

PyTorch пропонує два режими:
- **`mode='fan_in'`** (за замовчуванням): використовує :math-formula{tex="n_{\text{in}}" inline} — оптимально для forward pass
- **`mode='fan_out'`**: використовує :math-formula{tex="n_{\text{out}}" inline} — може бути краще для деяких архітектур (наприклад, ResNet)

Для більшості задач `fan_in` працює чудово.
::

### Дефолтна ініціалізація у PyTorch

Якщо ви не вказуєте явно метод ініціалізації, PyTorch використовує **дефолтні** значення:

| Шар | Ваги (weights) | Bias |
|:----|:---------------|:-----|
| `nn.Linear` | `kaiming_uniform_` з `a=sqrt(5)` | Рівномірний на основі fan_in |
| `nn.Conv2d` | `kaiming_uniform_` з `a=sqrt(5)` | Рівномірний на основі fan_in |
| `nn.LSTM`, `nn.GRU` | Xavier uniform | Нулі |
| `nn.BatchNorm` | Одиниці (γ=1) | Нулі (β=0) |

::tip
**Практична рекомендація:**

Для більшості задач **дефолтна ініціалізація PyTorch працює чудово**. Явну ініціалізацію варто застосовувати лише у специфічних випадках:
- Дуже глибокі мережі (50+ шарів) — може знадобитися точніша He ініціалізація
- Нестандартні активації (Swish, GELU) — експериментувати з gain параметром
- Transfer learning — ініціалізація лише нових шарів, заморожені шари залишаються без змін
::

```python
from copy import deepcopy
import time

def train_model(model, train_loader, epochs=10, lr=0.01):
    """Навчання моделі та збереження метрик"""
    device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')
    model = model.to(device)
    criterion = nn.CrossEntropyLoss()
    optimizer = optim.SGD(model.parameters(), lr=lr, momentum=0.9)
    
    history = {
        'train_loss': [],
        'train_acc': [],
        'epoch_time': []
    }
    
    for epoch in range(epochs):
        start_time = time.time()
        model.train()
        running_loss = 0.0
        correct = 0
        total = 0
        
        for images, labels in train_loader:
            images, labels = images.to(device), labels.to(device)
            
            # Forward
            outputs = model(images)
            loss = criterion(outputs, labels)
            
            # Backward
            optimizer.zero_grad()
            loss.backward()
            
            # Перевірка на NaN у градієнтах
            has_nan = False
            for param in model.parameters():
                if param.grad is not None:
                    if torch.isnan(param.grad).any() or torch.isinf(param.grad).any():
                        has_nan = True
                        break
            
            if has_nan:
                print(f"   ⚠️ Епоха {epoch+1}: NaN/Inf у градієнтах, зупинка")
                history['train_loss'].append(float('nan'))
                history['train_acc'].append(0.0)
                history['epoch_time'].append(time.time() - start_time)
                return history
            
            optimizer.step()
            
            # Метрики
            running_loss += loss.item()
            _, predicted = outputs.max(1)
            total += labels.size(0)
            correct += predicted.eq(labels).sum().item()
        
        epoch_time = time.time() - start_time
        epoch_loss = running_loss / len(train_loader)
        epoch_acc = 100. * correct / total
        
        history['train_loss'].append(epoch_loss)
        history['train_acc'].append(epoch_acc)
        history['epoch_time'].append(epoch_time)
        
        if epoch % 2 == 0:
            print(f"   Епоха {epoch+1:2d}/{epochs}: Loss={epoch_loss:.4f}, Acc={epoch_acc:.2f}%")
    
    return history

# Функції ініціалізації
def init_zero(m):
    if isinstance(m, nn.Linear):
        init.constant_(m.weight, 0.0)
        init.constant_(m.bias, 0.0)

def init_naive(m):
    if isinstance(m, nn.Linear):
        init.normal_(m.weight, 0.0, 1.0)
        init.constant_(m.bias, 0.0)

def init_xavier(m):
    if isinstance(m, nn.Linear):
        init.xavier_uniform_(m.weight)
        init.constant_(m.bias, 0.0)

def init_he(m):
    if isinstance(m, nn.Linear):
        init.kaiming_normal_(m.weight, mode='fan_in', nonlinearity='relu')
        init.constant_(m.bias, 0.0)

# Експеримент
init_methods = {
    'Zero': init_zero,
    'Naive N(0,1)': init_naive,
    'Xavier': init_xavier,
    'He (Kaiming)': init_he
}

results = {}

print("🚀 Початок експерименту: 10-шарова MLP, 10 епох\n")

for name, init_fn in init_methods.items():
    print(f"📊 Навчання з ініціалізацією: {name}")
    
    # Створюємо нову модель
    torch.manual_seed(42)
    model = DeepMLP(num_layers=10)
    model.apply(init_fn)
    
    # Навчаємо
    history = train_model(model, train_loader, epochs=10, lr=0.01)
    results[name] = history
    
    final_acc = history['train_acc'][-1] if history['train_acc'] else 0.0
    print(f"   ✅ Завершено. Фінальна accuracy: {final_acc:.2f}%\n")

print("🎉 Експеримент завершено!")
```

## Висновки та практичні рекомендації

::::accordion

:::accordion-item{label="❓ Яку ініціалізацію використовувати для нової моделі?" icon="i-lucide-help-circle"}

**Загальне правило:**

1. **ReLU / Leaky ReLU / PReLU** → **He (Kaiming) initialization**
   ```python
   nn.init.kaiming_normal_(layer.weight, mode='fan_in', nonlinearity='relu')
   ```

2. **Tanh / Sigmoid** → **Xavier (Glorot) initialization**
   ```python
   nn.init.xavier_uniform_(layer.weight)
   ```

3. **GELU / Swish (для Transformers)** → **Xavier** або **He з меншим gain**

4. **Bias** → завжди **нулі**
   ```python
   nn.init.constant_(layer.bias, 0)
   ```

Для 95% задач: використовуйте **дефолтну ініціалізацію PyTorch** — вона вже оптимізована!

:::

:::accordion-item{label="❓ Що робити, якщо модель не навчається?" icon="i-lucide-help-circle"}

**Діагностика проблем ініціалізації:**

1. **Перевірте градієнти:** виведіть `.grad.mean()` та `.grad.std()` для кожного шару
   - Якщо градієнти < 1e-7 → **vanishing gradients** (зменшити std ваг або змінити активацію)
   - Якщо градієнти > 100 → **exploding gradients** (зменшити std ваг або gradient clipping)

2. **Візуалізуйте активації:** додайте hooks та збережіть розподіли активацій по шарах
   - Якщо всі активації ≈ 0 → проблема dead ReLU (зменшити std або використати Leaky ReLU)
   - Якщо активації → ∞ → вибухаючі активації (He ініціалізація занадто агресивна)

3. **Зменшіть learning rate** до 0.001 та спробуйте знову

:::

:::accordion-item{label="❓ Чи потрібна спеціальна ініціалізація для Batch Normalization?" icon="i-lucide-help-circle"}

**Короткаотповідь: НІ.**

Batch Normalization нормалізує активації кожного шару, тому вплив ініціалізації ваг значно менший. Однак:

- **γ (scale) параметр BN:** ініціалізується **одиницями** (за замовчуванням)
- **β (shift) параметр BN:** ініціалізується **нулями** (за замовчуванням)

Ці дефолтні значення оптимальні у 99% випадків. У наступній статті ми детально розглянемо Batch Normalization.

:::

:::accordion-item{label="❓ Як ініціалізувати лише нові шари при transfer learning?" icon="i-lucide-help-circle"}

**Приклад:** ви завантажили pretrained ResNet18 та додали свій класифікатор:

```python
import torchvision.models as models

# Завантажити pretrained модель
model = models.resnet18(pretrained=True)

# Замінити останній FC шар
num_features = model.fc.in_features
model.fc = nn.Linear(num_features, 10)  # 10 класів

# Ініціалізувати ЛИШЕ новий FC шар
nn.init.kaiming_normal_(model.fc.weight, mode='fan_in', nonlinearity='relu')
nn.init.constant_(model.fc.bias, 0)

# Pretrained шари залишаються без змін!
```

**Важливо:** НЕ застосовуйте `.apply(init_fn)` до всієї моделі — це перезапише pretrained ваги!

:::

::::

::tip
**Золоте правило ініціалізації:**

Для сучасних глибоких мереж з ReLU: **He (Kaiming) initialization + Batch Normalization = стабільне навчання**. У 90% випадків цього достатньо для успішної конвергенції.
::
