- Знати п'ять кроків, якими текст перетворюється на вхід для моделі, і в яких лекціях модуля вони розбираються.

::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **NLP (Natural Language Processing):** обробка природної мови — розділ ШІ, який працює з текстом і мовленням людини.
- **Природна мова (natural language):** мова, якою спілкуються люди, на відміну від мови програмування.
- **Омонім (homonym):** слово з однаковим написанням і різними значеннями («ключ»).
- **Словоформа (word form):** конкретна форма слова («бігав», «біжить»).
- **Кодова позиція (code point):** номер символа в таблиці Unicode.
- **Кодування (encoding):** правило запису кодових позицій у байтах; найпоширеніше — UTF-8.
- **Нормалізація (normalization):** приведення різних записів одного тексту до єдиного вигляду.

## Задача, яка мотивує

У магазину є тисячі відгуків, і потрібно автоматично відділити позитивні від негативних. Перше, що спадає на думку, — скласти списки слів. Позитивні: «чудовий», «задоволений», «чудово». Негативні: «жахлива», «поганий», «зламався». Відгук отримує мітку того списку, з якого в ньому більше слів.

::jupyter-notebook{title="rule_based_sentiment.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="1"}

```python
positive = {"чудовий", "задоволений", "чудово"}
negative = {"жахлива", "поганий", "зламався"}

def rule(text):
    words = [w.strip(",.!").lower() for w in text.split()]
    p = sum(w in positive for w in words)
    n = sum(w in negative for w in words)
    return "позитивний" if p > n else "негативний" if n > p else "невідомо"

reviews = [
    "Чудовий товар, дуже задоволений!",
    "Жахлива якість, гроші на вітер.",
    "Не можу сказати, що товар поганий.",
    "Товар не чудовий, а просто нормальний.",
    "Чудово! Чудово зламався вже за день.",
]
for r in reviews:
    print(f"{rule(r):<11} | {r}")
```

#output
```text
позитивний  | Чудовий товар, дуже задоволений!
негативний  | Жахлива якість, гроші на вітер.
негативний  | Не можу сказати, що товар поганий.
позитивний  | Товар не чудовий, а просто нормальний.
позитивний  | Чудово! Чудово зламався вже за день.
```

::

::

Правильно визначено два відгуки з п'яти. Помилки мають різні причини:

- У третьому відгуку слово «поганий» заперечене: загальний зміст позитивний, а правило бачить лише слово зі списку.
- У четвертому слово «чудовий» теж заперечене, тому зміст змінився на протилежний.
- У п'ятому іронічне «Чудово!» двічі перекрило єдине слово «зламався».

Слова самі по собі не несуть значення. Його задають **порядок слів, заперечення, контекст і тон**. Саме тому обробка природної мови виділена в окрему галузь: потрібні методи, які враховують ці чинники, а не списки слів.

## Що вміє NLP

**Обробка природної мови** (*Natural Language Processing, NLP*) розв'язує задачі, у яких вхід або вихід — текст. Незалежно від галузі, більшість із них зводиться до чотирьох типів.

![Чотири типи задач NLP: вхід і вихід кожної](/images/ai-python/natural-language-processing/text-as-data/01-nlp-tasks.png){.diagram-img}

::card-group

::card{title="Класифікація тексту" icon="i-lucide-tags"}
На вході текст, на виході мітка з фіксованого набору: тональність відгуку, тема новини, спам або не спам. Ця задача пройде крізь весь модуль, бо вона найпростіша для порівняння методів.
::

::card{title="Пошук сутностей" icon="i-lucide-search"}
Для кожного слова модель визначає, чи це ім'я, місто, дата, сума. Результат — розмітка тексту, а не одна мітка.
::

::card{title="Переклад і перефразування" icon="i-lucide-languages"}
На вході послідовність слів, на виході інша послідовність, довжина якої може відрізнятися.
::

::card{title="Відповіді на запитання" icon="i-lucide-message-circle-question"}
На вході запитання й текст, у якому шукають відповідь; на виході фрагмент тексту або нове речення.
::

::

У цьому модулі ми розв'яжемо перші задачі: **класифікацію** тексту на відгуках, а також підготуємо базу — вектори слів і архітектури, — на якій будуються переклад і відповіді на запитання. Задачі з довгим виходом (генерація тексту) торкнемося лише як ідеї, їх повноцінний розбір виходить за межі модуля.

::note
Мовлення (розпізнавання голосу, синтез) — окрема галузь: голос спершу перетворюють на текст, а далі застосовують ті самі методи. Ми працюємо лише з уже готовим письмовим текстом.
::

## Чому текст складніший за числа

Таблиця з Модуля 2 мала фіксовану структуру: однакова кількість стовпців, кожен із відомим типом. У тексту такої структури немає. Є п'ять властивостей, які ускладнюють роботу.

### Різна довжина

Відгук може складатися з одного слова або з тисячі. Модель із Модуля 4 приймає вектор **фіксованої** довжини, тому текст доведеться або обрізати й доповнювати, або обробляти по одному слову. Обидва підходи ми розглянемо далі.

### Одне слово, багато значень

**Омонім** — слово з однаковим написанням і різними значеннями. Слово «ключ» означає і металевий предмет для замка, і музичний знак, і джерело, і розгадку задачі. Значення визначає сусідні слова.

### Одне поняття, багато форм

Українська мова змінює слова за відмінками, родами, числами й часами. Для людини «бігти», «біг», «бігав» і «біжить» — одне поняття. Для програми, яка порівнює рядки, це чотири різні значення.

![Один омонім має кілька значень, одне поняття — кілька словоформ](/images/ai-python/natural-language-processing/text-as-data/02-word-forms.png){.diagram-img}

::jupyter-notebook{title="word_forms.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="2"}

```python
forms = ["бігти", "біг", "бігав", "біжить"]
for w in forms:
    print(f"{w:<8} == 'біг'  ->  {w == 'біг'}")

print("Відмінну" in "Відмінна якість")
```

#output
```text
бігти    == 'біг'  ->  False
біг      == 'біг'  ->  True
бігав    == 'біг'  ->  False
біжить   == 'біг'  ->  False
False
```

::

::

Пошук «Відмінну» не знаходить «Відмінна», хоча це те саме слово в іншому відмінку. Рядки порівнюються посимвольно, змісту програма не знає. Прийоми, які зводять форми до однієї (стеммінг і лемматизація), розбираються в лекції 03.

### Порядок слів змінює зміст

«Я не люблю каву» і «Я люблю каву» відрізняються одним словом, а зміст протилежний. «Собака вкусила чоловіка» і «Чоловік вкусив собаку» складаються з однакових слів. Якщо порахувати лише, які слова є в тексті, обидві пари стануть майже нерозрізненними. Цю проблему ми побачимо в лекції 05 і розв'яжемо в лекціях 12–16.

### Живе мовлення неакуратне

У реальних відгуках трапляються друкарські помилки («чудвий»), скорочення («норм»), сленг, змішування мов, емодзі й повтори («супеееер!!!»). Модель, навчена на охайних текстах, на таких даних працює гірше.

::tip
Прийом, який допомагає при проєктуванні: перед вибором методу прочитайте 20–30 реальних прикладів з вашого набору даних. Там майже завжди є різновид «неакуратності», про який ви не подумали.
::

## Як текст зберігається в пам'яті

Усі п'ять проблем вище стосуються змісту. Є ще одна, нижчого рівня: перш ніж обробляти текст, треба знати, **що саме лежить у рядку**. У Python 3 тип `str` — це послідовність символів Unicode, а не байтів.

### Символ, кодова позиція, байт

**Unicode** — таблиця, у якій кожному символу будь-якої мови присвоєно номер, **кодову позицію** (*code point*). Номер записують як `U+0457`. Функція `ord()` повертає цей номер, а `chr()` — символ за номером.

**Кодування** (*encoding*) визначає, як записати кодову позицію в байтах для файла чи мережі. Найпоширеніше кодування — **UTF-8**: символи з малим номером займають 1 байт, великим — до 4. Латинські літери записуються одним байтом, кириличні — двома, більшість емодзі — чотирма.

![Одна кодова позиція в UTF-8 займає від одного до чотирьох байтів](/images/ai-python/natural-language-processing/text-as-data/03-utf8-bytes.png){.diagram-img}

::jupyter-notebook{title="unicode_basics.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="3"}

```python
s = "Кіт"
print(len(s))
print([ord(c) for c in s])
print([hex(ord(c)) for c in s])
print(s.encode("utf-8"))
print(len(s.encode("utf-8")))
```

#output
```text
3
[1050, 1110, 1090]
['0x41a', '0x456', '0x442']
b'\xd0\x9a\xd1\x96\xd1\x82'
6
```

::

::

Рядок «Кіт» складається з трьох символів, кожен із яких має номер: 1050, 1110, 1090. У UTF-8 він займає шість байтів, по два на кожну кириличну літеру. Пояснення виходу:

- `len(s)` рахує **символи**, тому результат 3.
- `s.encode("utf-8")` перетворює рядок на послідовність **байтів** (тип `bytes`).
- `len(...)` від байтів показує розмір у пам'яті або у файлі: 6.

::jupyter-notebook{title="bytes_vs_chars.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="4"}

```python
for t in ["cat", "кіт", "€", "🐱"]:
    b = t.encode("utf-8")
    print(f"{t:<4} символів: {len(t)}  байтів: {len(b)}  {b}")
```

#output
```text
cat  символів: 3  байтів: 3  b'cat'
кіт  символів: 3  байтів: 6  b'\xd0\xba\xd1\x96\xd1\x82'
€    символів: 1  байтів: 3  b'\xe2\x82\xac'
🐱    символів: 1  байтів: 4  b'\xf0\x9f\x90\xb1'
```

::

::

::note
Якщо відкрити файл у неправильному кодуванні, замість тексту виходять «кракозябри», наприклад `ÐºÑ–Ñ‚` замість «кіт». Файл із даними треба відкривати з явним `encoding="utf-8"`: у Windows типове кодування може бути іншим, і код, що працює на вашому комп'ютері, зламається на чужому.
::

## Один текст — різні записи

Два рядки, які виглядають однаково на екрані, не зобов'язані бути рівними в Python. Це пастки, які псують підрахунок слів ще до початку аналізу.

### Складені й розкладені символи

Літеру «й» можна записати однією кодовою позицією `U+0439` або двома: «и» (`U+0438`) і знаком «бревіс» (`U+0306`). Друкований результат однаковий.

::jupyter-notebook{title="normalization.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="5"}

```python
import unicodedata

a = "й"            # одна кодова позиція
b = "й"      # «и» + знак «бревіс»

print(a, b)
print(len(a), len(b), a == b)

fixed = unicodedata.normalize("NFC", b)
print(len(fixed), fixed == a)
```

#output
```text
й й
1 2 False
1 True
```

::

::

Обидва рядки на екрані виглядають як «й», але мають різну довжину і не рівні. Функція `unicodedata.normalize("NFC", ...)` приводить текст до **складеної форми** (*NFC*), у якій кожному символу відповідає найкоротший запис. Скопійований із різних джерел текст (PDF, вебсторінка, месенджер) має змішані форми, тому нормалізацію виконують на вході, до будь-якого порівняння.

### Регістр

Метод `lower()` приводить текст до малих літер. Для порівняння без урахування регістру точніший метод `casefold()`: він враховує спеціальні випадки, як у німецькому «ß».

::jupyter-notebook{title="casefold.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="6"}

```python
print("ІВАН".lower() == "іван")
print("Straße".lower())
print("Straße".casefold())
```

#output
```text
True
straße
strasse
```

::

::

Для української мови `lower()` достатньо. `casefold()` потрібен, коли в наборі даних трапляються тексти різними мовами.

### Схожі символи з різних абеток

Українська «а» і латинська `a` виглядають однаково, але це різні символи.

::jupyter-notebook{title="homoglyphs.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="7"}

```python
lat, cyr = "a", "а"
print(lat == cyr)
print(hex(ord(lat)), hex(ord(cyr)))
```

#output
```text
False
0x61 0x430
```

::

::

Слово «кава», набране з латинською `a`, не знайдеться пошуком за словом, набраним кирилицею. Такі помилки трапляються в реальних відгуках, коли користувач перемикає розкладку посеред слова.

::warning
Нормалізація не розв'язує проблему схожих символів: `NFC` не перетворює латинську `a` на кириличну. Для таких даних потрібен окремий словник заміни, і його складають за результатами огляду самих даних.
::

## Шлях тексту до моделі

Після цієї лекції видно, що текст не можна «подати моделі як є». Його проводять через кілька кроків, і кожен із них забирає частину неоднозначності.

![Текст проходить п'ять етапів: від сирого рядка до результату моделі](/images/ai-python/natural-language-processing/text-as-data/04-text-pipeline.png){.diagram-img}

::steps

### Сирий текст
Рядок Unicode: може мати різні форми запису, зайві пробіли, регістр, пунктуацію. Ця лекція показала, звідки береться різноманітність записів.

### Очищення й токени
Текст нормалізують і розбивають на окремі одиниці — **токени**, найчастіше слова. Слова зводять до початкової форми й прибирають службові. Лекції 02–04.

### Числа
Кожне слово або весь текст перетворюють на вектор чисел. Починаємо з простого підрахунку слів (лекції 05–06), а потім переходимо до векторів, що зберігають зміст (лекції 07–10).

### Модель
На числах працює модель. Для послідовностей це рекурентні мережі (лекції 11–13), а потім архітектура Transformer (лекції 14–16).

### Результат
Мітка, розмітка або новий текст — залежно від задачі.

::

::tip
Кожен крок можна замінити без зміни інших, і саме тому модуль побудований «знизу вгору»: на кожному кроці ми покажемо, що саме не вдається попередньому, і візьмемо наступний.
::

Результат: `14 25`. У рядку 14 символів. Одинадцять літер кирилицею (6 у слові «Привіт» і 5 у слові «світе») займають по 2 байти, а кома, пробіл і знак оклику — по одному: 11 · 2 + 3 = 25.
