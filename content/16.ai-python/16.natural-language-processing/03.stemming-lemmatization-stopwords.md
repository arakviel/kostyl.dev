# Стеммінг, лемматизація та стоп-слова

::card-group

::card{title="🎯 Мета лекції" icon="i-lucide-target"}

- Пояснити, навіщо зводити різні форми слова до однієї, і порівняти два способи: стеммінг і лемматизацію.
- Застосувати `PorterStemmer`, `WordNetLemmatizer` (англійська) і `pymorphy3` (українська).
- Пояснити, чому лемматизації потрібна частина мови.
- Визначити, які слова називають стоп-словами, скільки місця вони займають у тексті і коли їх видаляти не можна.
- Скласти повний конвеєр попередньої обробки для української.

::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Стеммінг (stemming):** обрізання закінчень слова за правилами, без словника.
- **Корінь, основа (stem):** результат стеммінгу; не обов'язково існуюче слово.
- **Лемматизація (lemmatization):** зведення слова до початкової форми за словником із урахуванням частини мови.
- **Лема (lemma):** початкова форма слова: іменник в називному відмінку однини, дієслово в інфінітиві.
- **Частина мови (part of speech, POS):** іменник, дієслово, прикметник тощо.
- **Стоп-слова (stop words):** дуже часті службові слова («і», «в», «the», «is»).

## Задача, яка мотивує

У лекції 01 пошук слова «біг» не знайшов «бігав» і «біжить». Це проблема кожного розв'язку, де слова порівнюються як рядки: слова «кава», «каву», «кави» і «кавою» — чотири різні елементи, хоч означають одне й те саме.

Наслідки видно, коли рахують слова. Якщо в 1000 відгуках слово «кава» вжито в різних відмінках по 50 разів кожен, то модель побачить чотири рідкісних слова замість одного поширеного. Чим менше прикладів кожного слова, тим гірше модель його вивчає. Тому різні форми слова зводять до однієї.

Є два способи це зробити: швидкий і грубий (**стеммінг**) та повільніший і точніший (**лемматизація**).

---

## Стеммінг

**Стеммінг** відрізає від слова закінчення й суфікси за набором правил. Словника він не використовує, тому працює швидко, але результат — це **основа** (*stem*), яка не завжди є справжнім словом.

Найвідоміший алгоритм для англійської — стеммер Портера (*Porter stemmer*).

::jupyter-notebook{title="stemming.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="1"}

```python
from nltk.stem import PorterStemmer

stemmer = PorterStemmer()

for word in ["running", "connected", "studies", "university", "universe", "mice", "was"]:
    print(f"{word:<11} -> {stemmer.stem(word)}")
```

#output
```text
running     -> run
connected   -> connect
studies     -> studi
university  -> univers
universe    -> univers
mice        -> mice
was         -> wa
```

::

::

Результат показує сильні й слабкі сторони методу:

- `running` → `run` і `connected` → `connect`: правильно, форми зведено до кореня.
- `studies` → `studi`: основа не є словом, але для задач, де важливо лише збігатися, це не завадить.
- `university` і `universe` → `univers`: два різних поняття стали одним. Це помилка **надмірного зведення** (*over-stemming*).
- `mice` → `mice` і `was` → `wa`: нерегулярні форми стеммер не розуміє, бо правила працюють лише з закінченнями.

::note
Для української існують окремі стеммери, але вони менш поширені й менш точні, ніж лемматизатори; у цій лекції для української застосовуємо лемматизацію.
::

## Лемматизація

**Лемматизація** знаходить у словнику **лему** — початкову форму слова: іменник в називному відмінку однини, дієслово в інфінітиві. На відміну від стеммінгу, результат завжди існуюче слово, а нерегулярні форми («mice», «was») словник знає.

Ціна — потрібен словник і, як побачимо, знання частини мови.

::jupyter-notebook{title="lemmatization.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="2"}

```python
from nltk.stem import WordNetLemmatizer

lemmatizer = WordNetLemmatizer()

for word in ["studies", "university", "mice", "was", "better"]:
    print(f"{word:<11} -> {lemmatizer.lemmatize(word)}")
```

#output
```text
studies     -> study
university  -> university
mice        -> mouse
was         -> wa
better      -> better
```

::

::

Більшість слів оброблено краще, ніж у стеммінгу: `studies` → `study`, `mice` → `mouse`, а `university` не злилося з `universe`. Однак `was` залишилося як `wa`, а `better` не змінилося на `good`. Причина в тому, що метод `lemmatize` без додаткових параметрів вважає кожне слово **іменником**.

### Чому потрібна частина мови

Слово `was` — форма дієслова `be`, а не іменник. Лемматизатор потрібно повідомити про це параметром `pos` (*part of speech*): `"n"` — іменник, `"v"` — дієслово, `"a"` — прикметник, `"r"` — прислівник.

::jupyter-notebook{title="lemmatization_pos.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="3"}

```python
from nltk.stem import PorterStemmer, WordNetLemmatizer

stemmer, lemmatizer = PorterStemmer(), WordNetLemmatizer()

print(lemmatizer.lemmatize("was", pos="v"))
print(lemmatizer.lemmatize("running", pos="v"), lemmatizer.lemmatize("running", pos="n"))
print(lemmatizer.lemmatize("better", pos="a"))
print(lemmatizer.lemmatize("arguing", pos="v"), "|", stemmer.stem("arguing"))
```

#output
```text
be
run running
good
argue | argu
```

::

::

З правильною частиною мови `was` → `be`, `better` → `good`, `arguing` → `argue`. Слово `running` дає різні результати: як дієслово — `run`, як іменник («running» — біг як заняття) — `running`. Для одного слова без контексту правильної відповіді немає. Щоб автоматично визначати частину мови, потрібен додатковий крок: **розмітка частин мови** (*POS tagging*), який нам знадобиться рідко; у практиці цього модуля обходимося без нього.

::tip
Для порівняння на одному слові: **стеммінг** швидкий і не потребує словника, але помиляється в нерегулярних формах і створює штучні основи. **Лемматизація** повільніша, залежить від мови та словника, зате дає справжні слова. Вибір залежить від задачі: для пошуку за ключовими словами вистачає стеммінгу, для аналізу змісту краще лемматизація.
::

| Властивість | Стеммінг | Лемматизація |
| :---------- | :------- | :----------- |
| Принцип | відрізає закінчення за правилами | шукає слово в словнику |
| Результат | основа, іноді не слово (`studi`) | початкова форма (`study`) |
| Нерегулярні форми | не розуміє (`mice`, `was`) | розуміє (`mouse`, `be`) |
| Швидкість | швидко | повільніше |
| Потребує мовних даних | ні | так, словник і частину мови |

## Що це дає: розмір словника

Перевіримо ефект на даних. Бібліотека NLTK має набір із 2000 англомовних відгуків на фільми (докладніше про такі набори в лекції 04). Він містить 1 331 109 слів і 39 341 унікальне слово. Подивимося, на скільки зменшується кількість унікальних слів після кожного методу.

::jupyter-notebook{title="vocab_effect.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="4"}

```python
from nltk.corpus import movie_reviews
from nltk.stem import PorterStemmer, WordNetLemmatizer

words = [w for w in movie_reviews.words() if any(c.isalpha() for c in w)]
stemmer, lemmatizer = PorterStemmer(), WordNetLemmatizer()

print("без змін:        ", len(set(words)))
print("стеммінг:        ", len({stemmer.stem(w) for w in words}))
print("лема (іменники): ", len({lemmatizer.lemmatize(w) for w in words}))
print("лема (ім.+дієсл.):", len({lemmatizer.lemmatize(lemmatizer.lemmatize(w), pos="v") for w in words}))
```

#output
```text
без змін:         39341
стеммінг:         25832
лема (іменники):  34942
лема (ім.+дієсл.): 29570
```

::

::

![Кількість унікальних слів у 2000 відгуках: без змін 39 341, лемматизація 34 942 і 29 570, стеммінг 25 832](/images/ai-python/natural-language-processing/stemming-lemmatization-stopwords/02-vocab-reduction.png){.diagram-img}

Стеммінг скорочує словник на 34%, лемматизація лише іменників — на 11%, лемматизація іменників і дієслів — на 25%. Стеммінг скорочує словник найбільше, у тому числі через помилкові злиття на кшталт `university` і `universe` → `univers`. Лемматизація скорочує менше й не зливає різні поняття.

::note
Корпус `movie_reviews` вже записаний малими літерами, тому окремого кроку «нижній регістр» тут немає. У власних даних нижній регістр виконується до стеммінгу.
::

::jupyter-notebook{title="pymorphy_lemma.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="5"}

```python
import pymorphy3

morph = pymorphy3.MorphAnalyzer(lang="uk")

for word in ["бігти", "біжить", "бігав", "каву", "кави", "мишей", "людям", "книжками", "ходила"]:
    best = morph.parse(word)[0]
    print(f"{word:<9} -> {best.normal_form:<8} {best.tag.POS}")
```

#output
```text
бігти     -> бігти    VERB
біжить    -> бігти    VERB
бігав     -> бігати   VERB
каву      -> кава     NOUN
кави      -> кава     NOUN
мишей     -> миша     NOUN
людям     -> людина   NOUN
книжками  -> книжка   NOUN
ходила    -> ходити   VERB
```

::

::

Метод `morph.parse(word)` повертає список можливих розборів слова, відсортований за ймовірністю. Ми беремо перший (`[0]`). У кожному розборі є `normal_form` (лема) і `tag.POS` (частина мови). Бібліотека знайшла початкову форму навіть для «мишей» → «миша» і «людям» → «людина», бо знає нерегулярні форми зі словника.

Є два нюанси, які варто знати:

- **Вид дієслова.** «біжить» → «бігти», але «бігав» → «бігати»: словник трактує їх як різні дієслова (дієслова незавершеного виду руху). Слова «біг» і «бігав» все одно не збігаються після лемматизації, але кількість різних слів скоротилася.
- **Омоніми без контексту.** Слово «замок» має кілька розборів (споруда, пристрій, дієслово `замокти`). `parse` не бачить речення, тому обирає найімовірніший розбір за словником і може помилитися. Те саме обмеження ми бачили в англійській лемматизації слова `running`.

::warning
Лемматизатор не безпомилковий. Займенник «мені» бібліотека зводить до неіснуючої «мен»: словник не знає початкової форми «я» для цього відмінка. Результати лемматизації треба переглядати очима на вибірці, особливо для частих слів.
::

## Стоп-слова

**Стоп-слова** (*stop words*) — дуже часті службові слова, які майже не відрізняють один текст від іншого: прийменники, сполучники, займенники, допоміжні дієслова. Для англійської це `the`, `is`, `and`, `of`; для української — «і», «в», «на», «що».

NLTK має готовий список для англійської.

::jupyter-notebook{title="stopwords.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="6"}

```python
from nltk.corpus import stopwords

english = set(stopwords.words("english"))
print(len(english))
print(sorted(english)[:12])
```

#output
```text
198
['a', 'about', 'above', 'after', 'again', 'against', 'ain', 'all', 'am', 'an', 'and', 'any']
```

::

::

Скільки місця стоп-слова займають у реальному тексті, показує той самий набір із 2000 відгуків: **47,2% усіх слів** є стоп-словами. Водночас це лише 151 з 39 341 різних слів.

![Стоп-слова займають 47,2% токенів, але лише 0,4% словника](/images/ai-python/natural-language-processing/stemming-lemmatization-stopwords/03-stopwords-share.png){.diagram-img}

З цього випливає корисний висновок: видалення стоп-слів майже вдвічі скорочує обсяг тексту (менше обчислень), але словник майже не змінює. Чи покращує воно **якість** моделі, залежить від задачі.

### Коли видаляти не можна

Стандартний англійський список містить слова `not`, `no`, `nor`. Для тональності це найважливіші слова.

::jupyter-notebook{title="stopwords_danger.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="7"}

```python
text = "this is a very good movie and i really enjoyed the acting but the ending was not good"
tokens = text.split()
filtered = [t for t in tokens if t not in english]

print(len(tokens), "->", len(filtered))
print(filtered)
print("not" in english, "no" in english, "nor" in english)
```

#output
```text
18 -> 7
['good', 'movie', 'really', 'enjoyed', 'acting', 'ending', 'good']
True True True
```

::

::

![Після видалення стоп-слів зникло «not», і відгук із критикою фіналу став схожим на захоплений](/images/ai-python/natural-language-processing/stemming-lemmatization-stopwords/04-stopword-not.png){.diagram-img}

З 18 слів лишилося 7, і в них немає `not`. Відгук, у якому автор критикує фінал, тепер складається лише з позитивних слів. Це знову та ж проблема, що й у лекції 01 (заперечення), але вже створена самою попередньою обробкою.

::warning
Універсального списку стоп-слів немає. Готовий список — лише відправна точка: для аналізу тональності слова `not`, `no`, «не», «ні» зі списку прибирають. Для пошуку за темою (класифікація новин) вони можуть залишатися стоп-словами.
::

### Стоп-слова для української

У NLTK немає списку для української: у списку мов є російська, але не українська. Складемо власний невеликий список і навмисно не включимо в нього слова «не» і «ні».

::jupyter-notebook{title="stopwords_uk.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="8"}

```python
STOP_UK = {
    "і", "й", "та", "а", "але", "в", "у", "на", "з", "із", "до", "по", "за",
    "від", "для", "що", "це", "як", "я", "ти", "ви", "він", "вона", "воно",
    "ми", "вони", "цей", "той", "так", "же", "б", "би", "ж", "ось", "там",
    "тут", "мені", "мене", "мій", "моя", "моє",
}
print(len(STOP_UK))
print("не" in STOP_UK, "дуже" in STOP_UK)
```

#output
```text
41
False False
```

::

::

Слово «дуже» теж свідомо залишене: воно підсилює оцінку («дуже добре» проти «добре»). Для кожної нової задачі такий список переглядають і розширюють, виходячи з найчастіших слів у даних.

## Повний конвеєр для української

З'єднаємо всі кроки лекцій 01–03: нормалізація, токенізація, відкидання стоп-слів, лемматизація. Функція `tokenize_uk` — з лекції 02.

::jupyter-notebook{title="preprocess_uk.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="9"}

```python
import unicodedata
import pymorphy3
from nltk.tokenize import RegexpTokenizer

PATTERN = r"\d+(?:[.,]\d+)*|\w+(?:['’ʼ-]\w+)*"
morph = pymorphy3.MorphAnalyzer(lang="uk")

def tokenize_uk(text):
    text = unicodedata.normalize("NFC", text).casefold()
    return RegexpTokenizer(PATTERN).tokenize(text)

def lemma_uk(word):
    return morph.parse(word)[0].normal_form

def preprocess_uk(text, stop=STOP_UK):
    return [lemma_uk(w) for w in tokenize_uk(text) if w not in stop]

reviews = [
    "Я дуже люблю каву, але мені не подобаються ціни в цьому кафе.",
    "Замовили піци, піцу привезли холодною, а офіціанти ходили повільно.",
    "Мишей у підвалі більше не було, і ми дуже задоволені.",
]
for r in reviews:
    print(preprocess_uk(r))
```

Порядок кроків має значення: стоп-слова відкидаємо **до** лемматизації, бо «мені» після лемматизації стало б «мен», і зі списку воно вже не вилучилося б. У другому відгуку «піци» і «піцу» зведено до однієї «піца»: це саме те, чого не вдавалося досягти в лекції 01. Слово «не» залишилося, бо ми його свідомо не додали до стоп-слів.
