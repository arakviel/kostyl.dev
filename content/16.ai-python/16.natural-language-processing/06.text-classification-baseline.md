# Класифікація тексту — baseline на мішку слів

::card-group

::card{title="🎯 Мета лекції" icon="i-lucide-target"}

- Навчити класифікатор на мішку слів для задачі тональності відгуків.
- Порахувати precision, recall і F1-score для обох класів.
- Побудувати матрицю помилок і знайти приклади помилок.
- Знайти найвагоміші слова для позитивних і негативних відгуків.
- Виміряти, як розмір словника впливає на якість моделі.

::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Baseline (базовий еталон):** найпростіша модель, результат якої — точка відліку для складніших методів.
- **Precision (точність):** частка правильних серед усіх, кому модель присвоїла даний клас.
- **Recall (повнота):** частка знайдених серед усіх, хто насправді належить до класу.
- **F1-score:** гармонічне середнє precision і recall; єдина метрика для порівняння моделей.
- **Матриця помилок (confusion matrix):** таблиця, у якій рядки — справжні класи, стовпці — передбачені.
- **Коефіцієнт моделі (weight, coefficient):** число, яке множиться на ознаку; для лінійної моделі показує вплив слова.

::

## Задача, яка мотивує

У лекції 05 ми перевірили, що логістична регресія на мішку слів дає 83,8% точності на корпусі `movie_reviews`. Це лише одна цифра. Щоб зрозуміти, **де саме** модель помиляється, потрібні детальніші метрики: precision, recall, матриця помилок.

Друге питання: **які слова найважливіші** для кожного класу? Коефіцієнти лінійної моделі показують, наскільки кожне слово «тягне» текст до позитивного чи негативного класу. Це дозволяє зрозуміти, що саме модель навчилася.

Третє питання: чи вистачає 5000 слів, чи можна обмежитися меншим словником? Ми побудуємо графік якості від розміру словника й побачимо, де настає насичення.

## Підготовка даних і навчання моделі

Повторимо крок із лекції 05, але тепер детально: розділимо дані, навчимо модель, отримаємо передбачення.

::jupyter-notebook{title="train_baseline.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="1"}

```python
from nltk.corpus import movie_reviews
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import train_test_split

# Підготувати тексти й мітки
docs = [" ".join(movie_reviews.words(fid)) for fid in movie_reviews.fileids()]
labels = [1 if cat == "pos" else 0 for cat in movie_reviews.categories(movie_reviews.fileids())]

print(f"Усього документів: {len(docs)}")
print(f"Позитивних: {sum(labels)}, негативних: {len(labels) - sum(labels)}")

# Розділити на навчання й тест (80/20)
X_train_text, X_test_text, y_train, y_test = train_test_split(
    docs, labels, test_size=0.2, random_state=42, stratify=labels
)

print(f"\nНавчання: {len(X_train_text)}, тест: {len(X_test_text)}")
```

#output
```text
Усього документів: 2000
Позитивних: 1000, негативних: 1000
Навчання: 1600, тест: 400
```

::

::

Набір збалансований: 1000 позитивних і 1000 негативних. Параметр `stratify=labels` гарантує, що в навчанні й тесті співвідношення класів однакове (50/50). Це важливо, бо якби в тесті було 70% позитивних, точність 70% можна досягти, просто завжди повертаючи «позитивний».

::jupyter-notebook{title="vectorize_and_train.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="2"}

```python
# Побудувати мішок слів
vectorizer = CountVectorizer(max_features=5000, lowercase=True, token_pattern=r'\b[a-z]+\b')
X_train = vectorizer.fit_transform(X_train_text)
X_test = vectorizer.transform(X_test_text)

print(f"Розмір навчальної матриці: {X_train.shape}")
print(f"Розмір тестової матриці: {X_test.shape}")
print(f"Розрідженість (навчання): {(1 - X_train.nnz / (X_train.shape[0] * X_train.shape[1])) * 100:.2f}%")

# Навчити модель
model = LogisticRegression(max_iter=1000, random_state=42, C=1.0)
model.fit(X_train, y_train)

# Передбачити
y_pred = model.predict(X_test)

print(f"\nМодель навчена. Коефіцієнтів: {len(model.coef_[0])}")
```

#output
```text
Розмір навчальної матриці: (1600, 5000)
Розмір тестової матриці: (400, 5000)
Розрідженість (навчання): 98.92%

Модель навчена. Коефіцієнтів: 5000
```

::

::

Модель навчена на 1600 відгуках, кожен із яких представлений вектором із 5000 ознак. Параметр `C=1.0` контролює регуляризацію: менше `C` — сильніша регуляризація, модель простіша. Типово `C=1.0` працює добре.

::note
Метод `fit_transform` будує словник на **навчальних** даних і перетворює їх. Метод `transform` застосовує **той самий словник** до тесту. Якщо побудувати окремий словник для тесту, моделі побачать різні ознаки, і результат буде неправильним.
::

## Метрики: accuracy, precision, recall, F1

**Accuracy** (частка правильних відповідей) — найпростіша метрика, але вона приховує, **на якому класі** модель помиляється. Для збалансованих даних її вистачає, але для повноти картини рахують precision і recall для кожного класу.

**Precision** відповідає на питання: «З усіх, кого модель назвала позитивними, скільки насправді позитивні?» **Recall** відповідає: «З усіх позитивних скільки модель знайшла?»

::jupyter-notebook{title="metrics.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="3"}

```python
from sklearn.metrics import accuracy_score, precision_score, recall_score, f1_score, classification_report

acc = accuracy_score(y_test, y_pred)
prec = precision_score(y_test, y_pred, average='binary')
rec = recall_score(y_test, y_pred, average='binary')
f1 = f1_score(y_test, y_pred, average='binary')

print(f"Accuracy:  {acc:.3f}")
print(f"Precision: {prec:.3f}  (позитивний клас)")
print(f"Recall:    {rec:.3f}  (позитивний клас)")
print(f"F1-score:  {f1:.3f}")

print("\n" + "="*50)
print(classification_report(y_test, y_pred, target_names=["negative", "positive"], digits=3))
```

![Метрики класифікації: accuracy 83,8%, precision і recall збалансовані](/images/ai-python/natural-language-processing/text-classification-baseline/01-metrics-table.png){.diagram-img}

Модель збалансована: precision і recall для обох класів близькі (різниця 1–2%). Це означає, що помилки рівномірно розподілені між false positives (модель назвала позитивним негативний) і false negatives (модель назвала негативним позитивний).

**F1-score** — гармонічне середнє precision і recall:

::math-formula{tex="\text{F1} = 2 \cdot \frac{\text{precision} \cdot \text{recall}}{\text{precision} + \text{recall}}"}
::

Коли precision і recall однакові, F1 дорівнює їм. Коли вони різні, F1 ближче до меншого значення. F1 зручний, бо це одна цифра для порівняння моделей.

::tip
Для збалансованих даних accuracy майже дорівнює F1. Для незбалансованих (наприклад, 90% одного класу) accuracy може бути високою, навіть якщо модель нічого не навчилася, а F1 покаже справжню якість.
::

## Матриця помилок

**Матриця помилок** (*confusion matrix*) показує, скільки прикладів кожного класу модель передбачила як кожен клас. Рядки — справжні мітки, стовпці — передбачені.

::jupyter-notebook{title="confusion_matrix.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="4"}

```python
from sklearn.metrics import confusion_matrix
import numpy as np

cm = confusion_matrix(y_test, y_pred)
print("Матриця помилок:")
print("                Передбачено")
print("              Negative  Positive")
print(f"Справжнє Neg    {cm[0,0]:>3}       {cm[0,1]:>3}")
print(f"         Pos    {cm[1,0]:>3}       {cm[1,1]:>3}")

print(f"\nTrue Negatives:  {cm[0,0]}  (правильно негативні)")
print(f"False Positives: {cm[0,1]}  (помилково позитивні)")
print(f"False Negatives: {cm[1,0]}  (помилково негативні)")
print(f"True Positives:  {cm[1,1]}  (правильно позитивні)")

# Обчислення метрик із матриці
tn, fp, fn, tp = cm.ravel()
precision_manual = tp / (tp + fp)
recall_manual = tp / (tp + fn)
print(f"\nПеревірка: precision = {tp}/{tp + fp} = {precision_manual:.3f}")
print(f"           recall    = {tp}/{tp + fn} = {recall_manual:.3f}")
```

## Приклади помилок

Подивимося на кілька відгуків, які модель класифікувала неправильно. Це допомагає зрозуміти, **чому** модель помиляється.

::jupyter-cell{executionCount="5"}

# Знайти індекси false positives і false negatives
false_positives = [i for i, (true, pred) in enumerate(zip(y_test, y_pred)) if true == 0 and pred == 1]

print(f"False positives: {len(false_positives)}")

    print()

## Найвагоміші слова

Логістична регресія — лінійна модель. Для кожного слова є коефіцієнт *w*: якщо він позитивний, слово «тягне» до класу 1 (позитивний), якщо негативний — до класу 0 (негативний). Чим більше абсолютне значення, тим сильніший вплив.

::jupyter-notebook{title="feature_importance.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="6"}

```python
import numpy as np

# Коефіцієнти моделі
coef = model.coef_[0]
feature_names = vectorizer.get_feature_names_out()

# Топ-15 слів для кожного класу
top_positive = np.argsort(coef)[-15:][::-1]
top_negative = np.argsort(coef)[:15]

print("=== Найвагоміші для ПОЗИТИВНОГО класу ===")
for idx in top_positive:
    print(f"{feature_names[idx]:<15} {coef[idx]:>7.3f}")

print("\n=== Найвагоміші для НЕГАТИВНОГО класу ===")
for idx in top_negative:
    print(f"{feature_names[idx]:<15} {coef[idx]:>7.3f}")
```

## Вплив розміру словника

У лекції 05 ми бачили, що розрідженість зростає зі словником. Чи зростає **якість** моделі так само? Перевіримо: навчимо моделі з різним `max_features` і побудуємо графік.

::jupyter-notebook{title="vocab_size_effect.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="7"}

```python
from sklearn.metrics import f1_score

sizes = [500, 1000, 2000, 5000, 10000, 20000]
f1_scores_train = []
f1_scores_test = []

for size in sizes:
    vec = CountVectorizer(max_features=size, lowercase=True, token_pattern=r'\b[a-z]+\b')
    X_tr = vec.fit_transform(X_train_text)
    X_te = vec.transform(X_test_text)
    
    clf = LogisticRegression(max_iter=1000, random_state=42, C=1.0)
    clf.fit(X_tr, y_train)
    
    y_pred_tr = clf.predict(X_tr)
    y_pred_te = clf.predict(X_te)
    
    f1_tr = f1_score(y_train, y_pred_tr)
    f1_te = f1_score(y_test, y_pred_te)
    
    f1_scores_train.append(f1_tr)
    f1_scores_test.append(f1_te)
    
    print(f"Словник {size:>5}: train F1 = {f1_tr:.3f}, test F1 = {f1_te:.3f}")
```

На **навчанні** F1 зростає майже до 100%: зі словником у 20 тисяч слів модель майже ідеально запам'ятала навчальні дані. На **тесті** F1 зростає до ~5000 слів і далі не покращується. Це **перенавчання** (*overfitting*): модель запам'ятовує специфічні слова навчальних текстів, які не допомагають на нових.

Оптимальний розмір словника для цих даних — **2000–5000 слів**: далі якість не зростає, а модель стає повільнішою (більше ознак) і займає більше пам'яті. Для інших корпусів оптимум може бути іншим, тому таку криву будують для кожної нової задачі.

Корисно порівняти модель із «тупим» baseline: що, якби ми присвоювали мітки **випадково**? Для збалансованих даних випадкове присвоєння дає accuracy ≈50%.
