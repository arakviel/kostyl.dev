# Від one-hot до embeddings — щільні вектори слів

::card-group

::card{title="🎯 Мета лекції" icon="i-lucide-target"}

- Пояснити, чому one-hot вектори не зберігають схожість слів.
- Порівняти розріджені one-hot і щільні вектори (embeddings) за розміром і властивостями.
- Застосувати `nn.Embedding` у PyTorch для перетворення індексів слів на вектори.
- Обчислити косинусну подібність і пояснити, чому вона краща за евклідову відстань.
- Показати на іграшковому прикладі, як схожі слова мають близькі вектори.

::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **One-hot вектор:** представлення слова вектором довжини *V* (розмір словника), де одна позиція = 1, решта = 0.
- **Embedding (вектор слова):** щільний вектор довжини *d* (50–300), який зберігає зміст слова; схожі слова мають близькі вектори.
- **Щільний вектор (dense vector):** більшість елементів ненульові, на відміну від розрідженого.
- **Косинусна подібність (cosine similarity):** скалярний добуток нормалізованих векторів; вимірює кут між ними.
- **Lookup-таблиця (embedding matrix):** матриця *V* × *d*, де кожен рядок — вектор слова з індексом.

::

::

## Задача, яка мотивує

У лекції 06 мішок слів дав 83,8% точності. Це непогано, але модель не розуміє **схожості** слів: слова `excellent` і `great` мають різні індекси в словнику, і для моделі вони не пов'язані. Якщо в навчанні було багато відгуків зі словом `excellent`, а в тесті трапилося `superb`, модель не знає, що вони схожі.

Люди знають, що «чудовий», «прекрасний», «відмінний» — близькі за змістом. Чи можна **навчити** модель бачити цю схожість? Так, якщо представити кожне слово не one-hot вектором, а **щільним вектором**, який зберігає його зміст. Такі вектори називають **embeddings** (вкладення).

::jupyter-notebook{title="word_similarity_problem.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="1"}

```python
import numpy as np

# Словник
vocab = ["king", "queen", "man", "woman", "cat", "dog"]
word_to_idx = {w: i for i, w in enumerate(vocab)}

# One-hot вектори
def onehot(word, vocab_size):
    vec = np.zeros(vocab_size)
    vec[word_to_idx[word]] = 1
    return vec

king = onehot("king", len(vocab))
queen = onehot("queen", len(vocab))
cat = onehot("cat", len(vocab))

print("king:  ", king)
print("queen: ", queen)
print("cat:   ", cat)

# Відстань між словами (евклідова)
dist_king_queen = np.linalg.norm(king - queen)
dist_king_cat = np.linalg.norm(king - cat)

print(f"\nВідстань king–queen: {dist_king_queen:.3f}")
print(f"Відстань king–cat:   {dist_king_cat:.3f}")
```

#output
```text
king:   [1. 0. 0. 0. 0. 0.]
queen:  [0. 1. 0. 0. 0. 0.]
cat:    [0. 0. 0. 0. 1. 0.]

Відстань king–queen: 1.414
Відстань king–cat:   1.414
```

::

::

Відстань між `king` і `queen` така сама, як між `king` і `cat`. Для модели це означає, що `queen` не ближче до `king`, ніж `cat`. One-hot вектори **ортогональні**: скалярний добуток будь-яких двох дорівнює нулю, тому жодна пара слів не схожа на іншу.

Це фундаментальна межа one-hot кодування: воно не зберігає схожість. Рішення — навчити модель **щільні вектори**, у яких схожі слова мають близькі напрямки.

## Що таке embedding

**Embedding** (вкладення, вектор слова) — це щільний вектор **фіксованої довжини** *d*, який представляє слово. Типово *d* = 50–300, що значно менше за розмір словника *V* (тисячі). Кожна позиція вектора — це дійсне число, не обов'язково 0 або 1.

![Порівняння one-hot і embedding: one-hot має *V* = 10 000, лише одна 1; embedding має *d* = 100, усі числа ненульові](/images/ai-python/natural-language-processing/from-one-hot-to-embeddings/01-onehot-vs-embedding.png){.diagram-img}

| Властивість | One-hot | Embedding |
| :---------- | :------ | :-------- |
| Розмір вектора | *V* (5000–50000) | *d* (50–300) |
| Кількість ненульових | 1 | майже всі |
| Схожість слів | ні (усі ортогональні) | так (близькі вектори) |
| Навчається | ні (фіксовані) | так (параметри моделі) |

**Приклад іграшкових векторів** (для словника з лекції):

::jupyter-notebook{title="toy_embeddings.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="2"}

```python
import numpy as np

# Іграшкові вектори (2D для візуалізації)
embeddings = {
    "king":   np.array([0.8, 0.6]),
    "queen":  np.array([0.7, 0.7]),
    "man":    np.array([0.6, 0.3]),
    "woman":  np.array([0.5, 0.6]),
    "cat":    np.array([-0.3, 0.5]),
    "dog":    np.array([-0.2, 0.4]),
}

for word, vec in embeddings.items():
    print(f"{word:<6} {vec}")

# Відстань між словами (евклідова)
def euclidean(v1, v2):
    return np.linalg.norm(v1 - v2)

print(f"\nВідстань king–queen: {euclidean(embeddings['king'], embeddings['queen']):.3f}")
print(f"Відстань king–cat:   {euclidean(embeddings['king'], embeddings['cat']):.3f}")
print(f"Відстань cat–dog:    {euclidean(embeddings['cat'], embeddings['dog']):.3f}")
```

#output
```text
king   [0.8 0.6]
queen  [0.7 0.7]
man    [0.6 0.3]
woman  [0.5 0.6]
cat    [-0.3  0.5]
dog    [-0.2  0.4]

Відстань king–queen: 0.141
Відстань king–cat:   1.102
Відстань cat–dog:    0.141
```

::

::

Тепер відстань `king–queen` (0,141) **менша** за `king–cat` (1,102). Слова `king` і `queen` мають близькі вектори, бо вони близькі за змістом. Слова `cat` і `dog` теж близькі (0,141). Це саме те, що нам потрібно: **схожі слова мають близькі вектори**.

::note
Ці вектори складені вручну для демонстрації. У реальності їх **навчають** на великому корпусі, і модель сама знаходить, які слова схожі. Ми побачимо це в лекції 08.
::

## Косинусна подібність

Евклідова відстань має проблему: вона чутлива до **довжини** вектора. Два вектори можуть мати однаковий напрямок, але різну довжину, і відстань буде великою. Для векторів слів важливий **напрямок**, а не довжина.

**Косинусна подібність** (*cosine similarity*) вимірює **кут** між векторами:

::math-formula
---
formula: \cos(\theta) = \frac{\mathbf{u} \cdot \mathbf{v}}{\|\mathbf{u}\| \|\mathbf{v}\|}
---
::

де **u** · **v** — скалярний добуток, ‖**u**‖ і ‖**v**‖ — норми (довжини) векторів. Результат від –1 до 1:
- **1** — вектори однакового напрямку (кут 0°)
- **0** — вектори перпендикулярні (кут 90°)
- **–1** — вектори протилежного напрямку (кут 180°)

![Косинусна подібність як кут: 0° → 1, 90° → 0, 180° → –1](/images/ai-python/natural-language-processing/from-one-hot-to-embeddings/02-cosine-angle.png){.diagram-img}

::jupyter-notebook{title="cosine_similarity.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="3"}

```python
def cosine_similarity(v1, v2):
    return np.dot(v1, v2) / (np.linalg.norm(v1) * np.linalg.norm(v2))

# Обчислити для всіх пар
pairs = [("king", "queen"), ("king", "cat"), ("cat", "dog"), ("man", "woman")]

for w1, w2 in pairs:
    sim = cosine_similarity(embeddings[w1], embeddings[w2])
    print(f"{w1}–{w2:<6} косинус: {sim:>6.3f}")
```

#output
```text
king–queen  косинус:  0.983
king–cat    косинус:  0.063
cat–dog     косинус:  0.994
man–woman   косинус:  0.875
```

::

::

Косинус `king–queen` = 0,983 (майже 1) означає, що вектори майже однакового напрямку. Косинус `king–cat` = 0,063 (майже 0) означає, що вони перпендикулярні, тобто не схожі. Косинус `cat–dog` = 0,994 підтверджує, що ці слова дуже схожі.

::tip
Косинусна подібність стандартна для векторів слів. Вона не залежить від довжини, тому два вектори `[1, 1]` і `[10, 10]` мають косинус = 1, хоч евклідова відстань велика.
::

## nn.Embedding у PyTorch

У PyTorch `nn.Embedding` — це шар, який перетворює **індекс слова** на його **вектор**. Всередині це просто **lookup-таблиця**: матриця розміру *V* × *d*, де кожен рядок — вектор одного слова. Індекс слова — це номер рядка.

![Embedding як lookup-таблиця: індекс 14 → рядок 14 → вектор [0.23, –0.18, 0.91, ...]](/images/ai-python/natural-language-processing/from-one-hot-to-embeddings/03-embedding-lookup.png){.diagram-img}

::jupyter-notebook{title="nn_embedding.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="4"}

```python
import torch
import torch.nn as nn

# Створити embedding: словник 6 слів, вектори 4-вимірні
vocab_size = 6
embedding_dim = 4

embedding = nn.Embedding(num_embeddings=vocab_size, embedding_dim=embedding_dim)

print("Матриця embeddings (вага шару):")
print(embedding.weight)
print(f"\nРозмір: {embedding.weight.shape}")

# Перетворити індекси на вектори
indices = torch.tensor([0, 2, 5])  # king, man, dog
vectors = embedding(indices)

print(f"\nІндекси: {indices.tolist()}")
print(f"Вектори:\n{vectors}")
```

#output
```text
Матриця embeddings (вага шару):
tensor([[ 0.5414, -0.4149,  0.6793,  1.1827],
        [-0.8458,  0.5173, -1.2476, -1.2382],
        [ 1.1626, -1.0847, -1.1286, -1.6781],
        [-0.7698, -0.0345, -0.3986,  0.2169],
        [ 0.2448,  0.8280, -1.1404, -0.8075],
        [-0.4370, -0.0688, -1.0654,  1.3465]], requires_grad=True)

Розмір: torch.Size([6, 4])

Індекси: [0, 2, 5]
Вектори:
tensor([[ 0.5414, -0.4149,  0.6793,  1.1827],
        [ 1.1626, -1.0847, -1.1286, -1.6781],
        [-0.4370, -0.0688, -1.0654,  1.3465]], grad_fn=<EmbeddingBackward0>)
```

::

::

Матриця `embedding.weight` має розмір 6×4: 6 слів, кожне — вектор із 4 чисел. При виклику `embedding(indices)` PyTorch просто бере рядки з цими номерами. Це **диференційовна операція**: градієнти можуть пройти крізь неї, і вектори навчаться.

Початкові значення випадкові (ініціалізовані з нормального розподілу). Під час навчання модель змінює ці числа так, щоб схожі слова мали близькі вектори.

::note
Параметр `requires_grad=True` означає, що PyTorch відстежує градієнти для цієї матриці. Під час `backward()` вектори оновляться разом із рештою моделі.
::

## Порівняння розміру: one-hot проти embedding

Для словника з 10 тисяч слів one-hot вектор має 10 тисяч позицій. Embedding із *d* = 100 має лише 100. Економія пам'яті й обчислень величезна.

::jupyter-notebook{title="size_comparison.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="5"}

```python
vocab_size = 10_000
embedding_dim = 100
batch_size = 32
seq_length = 50  # Довжина речення

# One-hot: кожне слово — вектор vocab_size
onehot_size = batch_size * seq_length * vocab_size * 4  # 4 байти на float32
print(f"One-hot для батча: {onehot_size / 1024**2:.1f} МБ")

# Embedding: кожне слово — індекс (int64) → вектор embedding_dim
indices_size = batch_size * seq_length * 8  # 8 байтів на int64
embeddings_size = batch_size * seq_length * embedding_dim * 4  # 4 байти на float32
total = (indices_size + embeddings_size) / 1024**2

print(f"Індекси: {indices_size / 1024:.1f} КБ")
print(f"Вектори після embedding: {embeddings_size / 1024:.1f} КБ")
print(f"Разом: {total:.2f} МБ")
print(f"\nЕкономія: {onehot_size / (indices_size + embeddings_size):.1f}x")
```

#output
```text
One-hot для батча: 610.4 МБ
Індекси: 12.5 КБ
Вектори після embedding: 625.0 КБ
Разом: 0.62 МБ

Економія: 976.6x
```

::

::

Для батча з 32 речень по 50 слів one-hot займає **610 МБ**, а embedding лише **0,62 МБ** — майже **в тисячу разів менше**. Це дозволяє працювати з великими словниками й довгими текстами навіть на звичайних GPU.

::tip
У практиці індекси зберігають як `torch.long` (int64), а вектори — як `torch.float` (float32). Embedding шар автоматично перетворює індекси на вектори під час forward pass.
::

## Візуалізація векторів у 2D

Іграшкові вектори з початку лекції мали 2 виміри, тому їх можна намалювати на площині. Справжні вектори мають 50–300 вимірів, але ідея та сама: **схожі слова близькі в просторі**.

## Де береться навчена матриця embeddings

У цій лекції ми використали **випадкові** вектори. Вони не несуть реального змісту. Щоб отримати корисні вектори, їх потрібно **навчити** на великому корпусі. Є два способи:

::card-group

::card{title="Навчити з нуля" icon="i-lucide-zap"}
Додати `nn.Embedding` як перший шар моделі класифікації. Під час навчання вектори оновляться так, щоб мінімізувати loss. Цей підхід працює, якщо у вас багато даних (тисячі текстів).
::

::card{title="Використати готові" icon="i-lucide-download"}
Завантажити вектори, навчені на мільярдах слів (Word2Vec, GloVe, FastText). Ці вектори вже знають схожість слів. Їх можна використати як є або **дотренувати** (*fine-tune*) на ваших даних.
::

::

У лекції 08 ми навчимо вектори з нуля методом **Word2Vec**. У лекції 09 завантажимо готові вектори **GloVe** і перевіримо їхні властивості (аналогії, найближчі слова). У лекції 10 додамо їх до класифікатора замість мішка слів і порівняємо якість.

::note
Готові вектори навчені на загальних текстах (Вікіпедія, новини). Для специфічної галузі (медицина, право) краще навчити власні або дотренувати готові на вашому корпусі.
::

:::accordion-item{label="📋 Завдання 1: косинусна подібність вручну" icon="i-lucide-clipboard-list"}

Для векторів **u** = [3, 4] і **v** = [6, 8] обчисліть косинусну подібність вручну (на папері або в Python). Поясніть, чому результат дорівнює 1.

:::

:::accordion-item{label="✅ Розв'язок завдання 1" icon="i-lucide-check-circle"}

```python
import numpy as np

u = np.array([3, 4])
v = np.array([6, 8])

cos = np.dot(u, v) / (np.linalg.norm(u) * np.linalg.norm(v))
print(cos)  # 1.0
```

Результат = 1, бо вектори **v** = 2**u**: вони мають однаковий напрямок, лише різну довжину. Косинус вимірює напрямок, тому результат = 1 (кут 0°).

:::

:::accordion-item{label="📋 Завдання 2: embedding для невеликого словника" icon="i-lucide-clipboard-list"}

Створіть `nn.Embedding` для словника з 100 слів і вимірністю 10. Перетворіть тензор індексів `[5, 12, 99, 0]` на вектори. Виведіть розмір результату й переконайтеся, що це `(4, 10)`.

:::

:::accordion-item{label="✅ Розв'язок завдання 2" icon="i-lucide-check-circle"}

```python
import torch
import torch.nn as nn

embedding = nn.Embedding(num_embeddings=100, embedding_dim=10)
indices = torch.tensor([5, 12, 99, 0])
vectors = embedding(indices)

print(vectors.shape)  # torch.Size([4, 10])
print(vectors)
```

Кожен із чотирьох індексів перетворився на вектор довжини 10, тому вихід має розмір `(4, 10)`.

:::

target = embeddings["woman"]
similarities = {}

for word, vec in embeddings.items():

## Підсумок

::card-group

::card{title="📌 Головне" icon="i-lucide-check"}

- One-hot вектори не зберігають схожість: усі ортогональні, відстань між будь-якою парою однакова.
- Embedding — щільний вектор довжини *d* (50–300), який зберігає зміст слова; схожі слова мають близькі вектори.
- `nn.Embedding` у PyTorch — це lookup-таблиця *V* × *d*, яка перетворює індекси на вектори; це диференційовна операція.
- Косинусна подібність вимірює кут між векторами (від –1 до 1); вона не залежить від довжини, тому краща за евклідову відстань.
- Embedding економить пам'ять: для словника 10 тис. слів і *d* = 100 це майже в тисячу разів менше, ніж one-hot.
