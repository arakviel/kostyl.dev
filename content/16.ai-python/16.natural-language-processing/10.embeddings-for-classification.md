::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Усереднений вектор речення (sentence embedding):** середнє арифметичне векторів усіх слів у реченні.
- **OOV (Out-of-Vocabulary):** слова, яких немає у словнику попередньо навчених векторів.
- **Freezing embeddings:** використання попередньо навчених векторів без оновлення ваг під час тренування.
- **Fine-tuning embeddings:** дотренування векторів на цільовому корпусі (оновлення ваг).
- **Vocabulary size:** кількість слів у словнику (впливає на OOV rate і якість).

## Від мішка слів до векторів — що зміниться

У лекції 06 ми класифікували відгуки за допомогою **мішка слів**: кожне речення перетворювалося на розріджений вектор розміром *V* (словник), де кожна позиція — це кількість входжень слова. Логістична регресія навчилася вагам для кожного слова. На повному IMDB (25 тисяч відгуків для навчання й 25 тисяч для тесту) такий baseline дає 85,0% точності.

Проблема мішка слів: слова `excellent`, `great`, `superb` мають різні індекси, і модель не знає, що вони схожі. Якщо в навчанні було багато `excellent`, а в тесті з'явилося `superb`, модель не використає знання про схожість.

**Аналогія.** Мішок слів схожий на список покупок: «яйця — 2, молоко — 1». Якщо в тесті замість «молока» написано «кефір», список уже не збігається, хоч обидва — молочні продукти. Усереднений вектор схожий на **смак страви в цілому**: його складають усі інгредієнти, а схожі інгредієнти дають схожий смак.

Рішення: замінити мішок слів на **усереднений вектор embeddings**. Кожне слово представлене щільним вектором розміру *d* (50–300), де схожі слова мають близькі вектори. Речення стає вектором розміру *d* — середнім усіх слів.

![Порівняння підходів: мішок слів (розріджений вектор 10000, лише кілька 1) проти усередненого вектора (щільний вектор 100, усі числа ненульові)](/images/ai-python/natural-language-processing/embeddings-for-classification/01-bow-vs-embedding.png){.diagram-img}

На малюнку вище — речення «this movie is great»: мішок слів має 10 000 клітинок, із яких ненульові лише чотири, а усереднений вектор складається з кількох чисел, і всі вони несуть інформацію. Числа embedding на малюнку умовні, середнє пораховано за ними.

Переваги:

1. **Семантична інформація:** модель «розуміє», що `excellent` і `superb` схожі, бо їхні вектори близькі.
2. **Компактність:** вектор розміру 100 замість 10 000.
3. **Генералізація:** краще працює на тестових даних зі словами, рідкісними в навчанні.

Обмеження:

1. **Втрата порядку:** усереднення знищує інформацію про послідовність слів (*«not good»* і *«good not»* мають однаковий вектор).
2. **OOV слова:** якщо слово відсутнє у словнику GloVe, ігноруємо його або замінюємо на спеціальний токен `<UNK>`.

У лекціях 11–13 ми вирішимо проблему порядку за допомогою рекурентних мереж (RNN, LSTM), які обробляють слова послідовно.

## Усереднення векторів — як перетворити речення на вектор

Алгоритм простий:

1. Токенізуємо речення: *«This movie is excellent»* → `[this, movie, is, excellent]`.
2. Для кожного слова отримуємо вектор із GloVe (розмір 100).
3. Обчислюємо середнє арифметичне: *v*ᵣₑ꜀ₕₑₙₙᵧ = (*v*ₜₕᵢₛ + *v*ₘₒᵥᵢₑ + *v*ᵢₛ + *v*ₑₓ꜀ₑₗₗₑₙₜ) / 4.

Якщо слово відсутнє у словнику (OOV), ігноруємо його (не додаємо до суми, зменшуємо лічильник).

::jupyter-notebook{title="sentence_embedding.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="1"}

```python
import numpy as np
import gensim.downloader as api

# Завантажуємо GloVe
glove = api.load("glove-wiki-gigaword-100")

def sentence_to_vector(sentence, model):
    """Перетворює речення на вектор через усереднення embeddings."""
    words = sentence.lower().split()
    vectors = []
    
    for word in words:
        if word in model:
            vectors.append(model[word])
    
    if len(vectors) == 0:
        # Якщо всі слова OOV, повертаємо нульовий вектор
        return np.zeros(model.vector_size)
    
    return np.mean(vectors, axis=0)

# Тестуємо
sentences = [
    "This movie is excellent",
    "I loved this film",
    "Terrible waste of time",
    "Boring and predictable"
]

for sent in sentences:
    vec = sentence_to_vector(sent, glove)
    print(f"Речення: {sent:30s} → вектор розміру {len(vec)} (перші 5: {vec[:5]})")
```

Це застереження для всього розділу: усереднені вектори стирають різницю між реченнями, і тональність слабо видно навіть на трьох-чотирьох словах.

::tip
Функція `np.mean(vectors, axis=0)` обчислює середнє по рядках (кожна компонента вектора усереднюється окремо). Це еквівалентно `(v1 + v2 + ... + vN) / N`, але ефективніше для великих матриць.
::

## Класифікація на IMDB — навчання моделі

Навчимо логістичну регресію на усереднених векторах IMDB. Порівняємо результат із мішком слів (лекція 06).

::jupyter-notebook{title="imdb_embedding_classifier.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="3"}

```python
from datasets import load_dataset
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score, classification_report
import numpy as np

# Завантажуємо IMDB
ds = load_dataset("stanfordnlp/imdb")
print(f"Навчальна вибірка: {len(ds['train'])} відгуків")
print(f"Тестова вибірка: {len(ds['test'])} відгуків")

# Перетворюємо тексти на вектори (займе ~2 хвилини)
def texts_to_vectors(texts, model):
    vectors = []
    for text in texts:
        vec = sentence_to_vector(text, model)
        vectors.append(vec)
    return np.array(vectors)

print("\nПеретворення текстів на вектори...")
X_train = texts_to_vectors(ds['train']['text'], glove)
X_test = texts_to_vectors(ds['test']['text'], glove)
y_train = np.array(ds['train']['label'])
y_test = np.array(ds['test']['label'])

print(f"X_train: {X_train.shape} (25000 відгуків × 100 вимірів)")
print(f"X_test: {X_test.shape} (25000 відгуків × 100 вимірів)")
```

## Вплив розміру векторів — 50 vs 100 vs 300

GloVe доступний у чотирьох розмірах: 50, 100, 200, 300. Більший вектор зберігає більше інформації, але потребує більше пам'яті й часу навчання. Перевіримо вплив на точність.

::jupyter-notebook{title="embedding_size_comparison.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="5"}

```python
# Завантажуємо різні розміри GloVe
sizes = [50, 100, 300]
results = {}

for size in sizes:
    print(f"\n{'='*50}")
    print(f"Розмір вектора: {size}")
    print('='*50)
    
    # Завантажуємо модель
    model_name = f"glove-wiki-gigaword-{size}"
    glove_model = api.load(model_name)
    
    # Перетворюємо тексти (беремо випадкові 5000 для швидкості; IMDB відсортований
    # за міткою, тому зріз [:5000] містив би лише негативні відгуки)
    rng = np.random.RandomState(42)
    idx_train = rng.permutation(len(ds['train']))[:5000]
    idx_test = rng.permutation(len(ds['test']))[:5000]
    X_train_sub = texts_to_vectors([ds['train']['text'][i] for i in idx_train], glove_model)
    X_test_sub = texts_to_vectors([ds['test']['text'][i] for i in idx_test], glove_model)
    y_train_sub = y_train[idx_train]
    y_test_sub = y_test[idx_test]
    
    # Навчаємо
    clf_size = LogisticRegression(max_iter=300, C=1.0, random_state=42)
    clf_size.fit(X_train_sub, y_train_sub)
    
    # Оцінка
    y_pred = clf_size.predict(X_test_sub)
    acc = accuracy_score(y_test_sub, y_pred)
    results[size] = acc
    print(f"Точність: {acc:.3f} ({acc*100:.1f}%)")

print("\n" + "="*50)
print("Підсумок:")
for size, acc in results.items():
    print(f"  Розмір {size:3d}: {acc*100:.1f}%")
```

## OOV слова — що робити з невідомими словами

Словник GloVe містить 400 тисяч найчастіших слів англійської мови. Рідкісні слова (орфографічні помилки, неологізми, імена) можуть бути відсутніми. Це називається **OOV (Out-of-Vocabulary)** проблемою.

::jupyter-notebook{title="oov_analysis.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="6"}

```python
# Перевіримо OOV rate на IMDB
from collections import Counter

def count_oov(texts, model):
    """Обчислює кількість OOV слів."""
    total_words = 0
    oov_words = 0
    oov_counter = Counter()
    
    for text in texts:
        words = text.lower().split()
        for word in words:
            total_words += 1
            if word not in model:
                oov_words += 1
                oov_counter[word] += 1
    
    return total_words, oov_words, oov_counter

# Аналізуємо перші 1000 відгуків
total, oov, oov_list = count_oov(ds['train']['text'][:1000], glove)

print(f"Всього слів: {total:,}")
print(f"OOV слів: {oov:,} ({oov/total*100:.1f}%)")
print(f"\nТоп-10 OOV слів:")
for word, count in oov_list.most_common(10):
    print(f"  {word:20s} {count:>5,} разів")
```

Проблема: **16,7% слів відсутні** у словнику (на перших 1000 відгуках). Це не рідкісні слова: `split()` залишає розмітку й пунктуацію в токенах (`/><br`, `movie.`, `it.`) і не відокремлює апострофи (`it's`, `don't`).

Рішення:

1. **Очищення:** видалити `<br>`, розділити скорочення (`it's` → `it is`).
2. **Tokenізація:** використовувати `word_tokenize` замість `.split()` (він правильно обробляє пунктуацію).
3. **UNK токен:** замінити OOV слова на спеціальний вектор `<UNK>`, навчений на корпусі як «невідоме слово».
4. **Subword embeddings:** використовувати FastText (лекція 16), який будує вектори з частин слова (не потребує повного словника).

::jupyter-notebook{title="oov_cleanup.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="7"}

```python
import re
from nltk.tokenize import word_tokenize
import nltk
nltk.download("punkt_tab", quiet=True)

def clean_and_tokenize(text):
    """Очищення та токенізація."""
    # Видаляємо HTML теги
    text = re.sub(r'<br\s*/?>', ' ', text)
    # Видаляємо зайву пунктуацію
    text = re.sub(r'[^\w\s\']', ' ', text)
    # Токенізуємо
    tokens = word_tokenize(text.lower())
    return tokens

# Перевіряємо покращення
def count_oov_tokens(texts, model):
    total = 0
    oov = 0
    for text in texts:
        tokens = clean_and_tokenize(text)
        for token in tokens:
            total += 1
            if token not in model:
                oov += 1
    return total, oov

total_clean, oov_clean = count_oov_tokens(ds['train']['text'][:1000], glove)
print(f"Після очищення:")
print(f"  Всього токенів: {total_clean:,}")
print(f"  OOV токенів: {oov_clean:,} ({oov_clean/total_clean*100:.1f}%)")
print(f"  Покращення: {(oov/total - oov_clean/total_clean)*100:.1f}% менше OOV")
```

#output
```text

  Всього токенів: 237,722
```

## Freezing vs Fine-tuning — оновлювати вектори чи ні

Досі ми використовували попередньо навчені вектори GloVe **без змін** (freezing). Але можна **дотренувати** їх на цільовому корпусі (fine-tuning): оновлювати вектори під час навчання класифікатора.

Переваги fine-tuning:

- Вектори адаптуються до специфіки завдання (наприклад, слово `cool` у відгуках на фільми означає «класний», а в технічній документації — «холодний»).
- Рідкісні слова, які мають загальний вектор, отримують специфічний для домену.

Недоліки:

- Потребує нейронної мережі (логістична регресія не може оновлювати embeddings).
- Ризик перенавчання на малих датасетах (векторів 400 тисяч × 100 = 40 мільйонів параметрів).
- Повільніше навчання.

::jupyter-notebook{title="fine_tuning_embeddings.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="9"}

```python
import torch
import torch.nn as nn
from torch.utils.data import Dataset, DataLoader

# Створюємо словник (топ-10000 слів)
from collections import Counter

def build_vocab(texts, max_size=10000):
    word_counts = Counter()
    for text in texts:
        tokens = clean_and_tokenize(text)
        word_counts.update(tokens)
    
    # Топ слів
    vocab = {"<PAD>": 0, "<UNK>": 1}
    for word, _ in word_counts.most_common(max_size):
        vocab[word] = len(vocab)
    
    return vocab

vocab = build_vocab(ds['train']['text'])
print(f"Розмір словника: {len(vocab)} слів")

# Ініціалізуємо матрицю embeddings із GloVe
embedding_dim = 100
embedding_matrix = np.random.randn(len(vocab), embedding_dim) * 0.01

for word, idx in vocab.items():
    if word in glove:
        embedding_matrix[idx] = glove[word]

print(f"Матриця embeddings: {embedding_matrix.shape}")
print(f"Покриття словника: {sum(1 for w in vocab if w in glove) / len(vocab) * 100:.1f}%")
```

#output
```text

Матриця embeddings: (10002, 100)
Покриття словника: 99.9%
```

```python
# Модель із freezing
class SentimentClassifier(nn.Module):
    def __init__(self, embedding_matrix, freeze=True):
        super().__init__()
        vocab_size, embed_dim = embedding_matrix.shape
        
        # Embedding шар
        self.embedding = nn.Embedding(vocab_size, embed_dim)
        self.embedding.weight.data.copy_(torch.FloatTensor(embedding_matrix))
        
        # Freeze (не оновлювати градієнти)
        if freeze:
            self.embedding.weight.requires_grad = False
        
        # Класифікатор
        self.fc = nn.Linear(embed_dim, 1)
    
    def forward(self, x):
        # x: (batch_size, seq_len)
        embedded = self.embedding(x)  # (batch_size, seq_len, embed_dim)
        pooled = embedded.mean(dim=1)  # (batch_size, embed_dim) — усереднення
        logits = self.fc(pooled)  # (batch_size, 1)
        return logits.squeeze()

# Модель із frozen embeddings
model_frozen = SentimentClassifier(embedding_matrix, freeze=True)
trainable_params = sum(p.numel() for p in model_frozen.parameters() if p.requires_grad)
print(f"Модель (frozen): {trainable_params:,} параметрів для навчання")

# Модель із fine-tuning
model_finetuned = SentimentClassifier(embedding_matrix, freeze=False)
trainable_params = sum(p.numel() for p in model_finetuned.parameters() if p.requires_grad)
print(f"Модель (fine-tuned): {trainable_params:,} параметрів для навчання")
```

#output
```text
Модель (frozen): 101 параметрів для навчання
Модель (fine-tuned): 1,000,301 параметрів для навчання
```

::

::

Різниця величезна: frozen модель навчає лише 101 параметр (ваги класифікатора), а fine-tuned — мільйон (embeddings + класифікатор). На малих датасетах (< 5000 прикладів) fine-tuning ризикує перенавчитися. На великих (> 50 000) може дати +1–2% точності.

::tip
Компроміс: дотренувати лише **останній шар embeddings** або використовувати **низький learning rate** для embeddings (у 10 разів менший, ніж для класифікатора). Це дозволяє адаптувати вектори, не руйнуючи попередньо навчені знання.
::

## Обмеження усереднення — коли порядок важливий

Усереднення векторів — простий і швидкий метод, але він має фундаментальне обмеження: **втрата порядку слів**. Речення з однаковими словами, але різним змістом отримують однаковий вектор.

::jupyter-notebook{title="order_matters.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="11"}

```python
# Речення з протилежним змістом
sent1 = "not good"
sent2 = "good not"
sent3 = "good, not bad"
sent4 = "not bad, good"

vec1 = sentence_to_vector(sent1, glove)
vec2 = sentence_to_vector(sent2, glove)
vec3 = sentence_to_vector(sent3, glove)
vec4 = sentence_to_vector(sent4, glove)

print("Косинусна подібність (усереднення):")
print(f"  '{sent1}' ↔ '{sent2}': {cosine_similarity([vec1], [vec2])[0][0]:.3f}")
print(f"  '{sent3}' ↔ '{sent4}': {cosine_similarity([vec3], [vec4])[0][0]:.3f}")

# Ще складніший приклад
sent5 = "The movie is not terrible"
sent6 = "The movie is terrible"

vec5 = sentence_to_vector(sent5, glove)
vec6 = sentence_to_vector(sent6, glove)

print(f"\n  '{sent5}' ↔ '{sent6}': {cosine_similarity([vec5], [vec6])[0][0]:.3f}")
print("\nПроблема: слово 'not' змінює зміст, але усереднення не ловить це!")
```

#output
```text

  'not good' ↔ 'good not': 1.000
  'good, not bad' ↔ 'not bad, good': 0.938

  'The movie is not terrible' ↔ 'The movie is terrible': 0.988

Проблема: слово 'not' змінює зміст, але усереднення не ловить це!
```

::

**Аналогія.** Усереднення — як середня температура по палаті: якщо у кого температура 36 і 39, а в іншого 39 і 36, середнє те саме, хоч історії хвороби різні. Порядок «зник» разом із деталями. Те саме з анаграмами: слова «кіт» і «тік» складаються з тих самих літер, але мають різний зміст.

Речення *«not good»* і *«good not»* мають **ідентичні** вектори (косинус = 1,000), бо усереднення комутативне: (*v*ₙₒₜ + *v*₉ₒₒ) / 2 = (*v*₉ₒₒ + *v*ₙₒₜ) / 2. Речення *«The movie is not terrible»* (позитивне) і *«The movie is terrible»* (негативне) мають схожість 0,988 — майже однакові, хоча зміст протилежний.

- Часові зв'язки (*before*, *after*, *until*)

- Виявили обмеження усереднення (втрата порядку).

## Що далі

У лекції 11 перейдемо до **мовних моделей і послідовностей**. Дізнаємося, що таке мовна модель (Language Model), як передбачати наступне слово за попередніми, і чому це корисно для розуміння тексту. Введемо поняття **padding** (вирівнювання довжин), **батчів послідовностей** і підготуємо дані для рекурентних мереж (RNN), які обробляють слова по черзі, зберігаючи контекст.

У лекціях 12–13 навчимо **RNN і LSTM**, які вирішать проблему порядку слів. Модель зможе розрізняти *«not good»* і *«good»*, бо обробляватиме слова послідовно й «пам'ятатиме», що перед `good` було заперечення `not`.
