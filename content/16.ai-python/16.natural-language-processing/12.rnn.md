# Рекурентні нейронні мережі (RNN)

::card-group

::card{title="🎯 Мета лекції" icon="i-lucide-target"}

- Показати, чому усереднення embeddings не бачить порядку слів.
- Записати крок рекурентної мережі формулою й перевірити її на `nn.RNN`.
- Навчити класифікатор відгуків IMDB на RNN і порівняти його з усередненням.
- Уникнути пастки з padding за допомогою `pack_padded_sequence`.
- Виміряти зникнення градієнта на реальній мережі.

::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Прихований стан (hidden state):** вектор, який мережа передає з кроку на крок і в якому зберігає все прочитане.
- **Розгортка в часі (unrolling):** запис рекурентної мережі як ланцюжка однакових блоків, по одному на слово.
- **BPTT:** зворотне поширення помилки через усі кроки розгортки.
- **Зникнення градієнта (vanishing gradient):** градієнт, що з кожним кроком назад зменшується в рази й майже не доходить до початку речення.
- **Packing:** передача в мережу справжніх довжин, щоб вона не читала padding.

::

::

## Чому усереднення не вистачає

У лекції 10 речення перетворювалося на вектор усередненням embeddings слів. Сума не залежить від порядку доданків, тому «not good» і «good not» дають однаковий вектор. Перевіримо це на двох словах із випадковими embeddings:

::jupyter-notebook{title="order_matters.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="1"}

```python
import torch, torch.nn as nn

torch.manual_seed(0)
emb = nn.Embedding(4, 3)
a = torch.tensor([[1, 2]])   # «not good»
c = torch.tensor([[2, 1]])   # «good not»

print("усереднення однакове:", torch.allclose(emb(a).mean(1), emb(c).mean(1)))

rnn = nn.RNN(3, 4, batch_first=True)
print("RNN однакова:", torch.allclose(rnn(emb(a))[1], rnn(emb(c))[1]))
```

#output
```text
усереднення однакове: True
RNN однакова: False
```

::

::

Рекурентна мережа (*recurrent neural network*, RNN) читає слова по одному й після кожного слова оновлює свій **прихований стан**. Стан після «good» залежить від того, що було прочитано раніше, тому порядок слів змінює результат.

## Прихований стан і розгортка в часі

На кроці :math-formula{tex="t" inline} мережа отримує вектор слова :math-formula{tex="x_t" inline} і попередній стан :math-formula{tex="h_{t-1}" inline}, а повертає новий стан :math-formula{tex="h_t" inline}:

::math-formula
h_t = \tanh(W_x x_t + W_h h_{t-1} + b)
::

- :math-formula{tex="x_t" inline} — embedding поточного слова, розмір :math-formula{tex="d" inline};
- :math-formula{tex="h_t" inline} — прихований стан, розмір :math-formula{tex="h" inline}; початковий стан :math-formula{tex="h_0" inline} складається з нулів;
- :math-formula{tex="W_x" inline} (розмір :math-formula{tex="h \times d" inline}) і :math-formula{tex="W_h" inline} (розмір :math-formula{tex="h \times h" inline}) — матриці ваг, :math-formula{tex="b" inline} — зсув;
- :math-formula{tex="\tanh" inline} стискає кожне число стану до проміжку від −1 до 1.

Блок із петлею зручно розгорнути в ланцюжок: по одному блоку на слово. Усі блоки використовують **одні й ті самі** ваги :math-formula{tex="W_x, W_h, b" inline}. Тому кількість параметрів не залежить від довжини речення.

![Згорнута схема RNN з петлею та її розгортка на три слова: ті самі ваги на кожному кроці](/images/ai-python/natural-language-processing/rnn/01-unfolding.png){.diagram-img}

::note
Слово *recurrent* означає «повторюваний»: та сама операція застосовується на кожному кроці, а результат попереднього кроку подається на вхід наступного. Це не рекурсія: функція не викликає саму себе.
::

## nn.RNN у PyTorch

Модуль `nn.RNN` виконує всю розгортку за один виклик. Вхід — тензор `(batch, seq_len, embed_dim)`; параметр `batch_first=True` ставить розмір батча на перше місце, як у решті модуля. Модуль повертає два тензори: стани на **всіх** кроках (`output`) і стан на **останньому** кроці (`h_n`). Щоб переконатися, що це та сама формула, повторимо її вручну:

::jupyter-notebook{title="nn_rnn.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="1"}

```python
import torch, torch.nn as nn

torch.manual_seed(0)
x = torch.randn(2, 4, 10)            # (batch, seq_len, embed_dim)
rnn = nn.RNN(input_size=10, hidden_size=16, batch_first=True)
output, h_n = rnn(x)

print("output:", tuple(output.shape))
print("h_n:   ", tuple(h_n.shape))
print("останній крок == h_n:", torch.allclose(output[:, -1], h_n[0]))

# та сама формула вручну
W_x, W_h = rnn.weight_ih_l0, rnn.weight_hh_l0
b = rnn.bias_ih_l0 + rnn.bias_hh_l0
h = torch.zeros(2, 16)
for t in range(4):
    h = torch.tanh(x[:, t] @ W_x.T + h @ W_h.T + b)
print("ручний розрахунок збігається:", torch.allclose(h, h_n[0], atol=1e-6))
print("параметри:", {n: tuple(p.shape) for n, p in rnn.named_parameters()})
```

#output
```text
output: (2, 4, 16)
h_n:    (1, 2, 16)
останній крок == h_n: True
ручний розрахунок збігається: True
параметри: {'weight_ih_l0': (16, 10), 'weight_hh_l0': (16, 16), 'bias_ih_l0': (16,), 'bias_hh_l0': (16,)}
```

::

::

Розміри параметрів збігаються з формулою: `weight_ih_l0` — це :math-formula{tex="W_x" inline}, `weight_hh_l0` — :math-formula{tex="W_h" inline}. Зсув у PyTorch розбито на два (`bias_ih` і `bias_hh`); їхня сума дорівнює :math-formula{tex="b" inline}. Перший вимір `h_n` дорівнює кількості шарів і напрямків, у цьому прикладі це 1.

## Підготовка даних IMDB

Для порівняння моделей у лекціях 12–13 використовується один набір: 10 000 відгуків IMDB для навчання і 5 000 для тесту, вибраних випадково з фіксованим seed. Слова зводяться до нижнього регістру, словник складається з 10 000 найчастіших слів, відгуки обрізаються до 200 токенів і доповнюються нулями (`<pad>`, індекс 0). Це той самий padding, що в лекції 11.

::jupyter-notebook{title="imdb_prepare.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="1"}

```python
import re, random, collections, torch
from datasets import load_dataset

ds = load_dataset("stanfordnlp/imdb")
rnd = random.Random(42)

def take(split, n):
    idx = list(range(len(ds[split])))
    rnd.shuffle(idx)
    rows = [ds[split][i] for i in idx[:n]]
    return [r["text"] for r in rows], [r["label"] for r in rows]

train_texts, train_labels = take("train", 10000)
test_texts, test_labels = take("test", 5000)

def tokenize(text):
    text = re.sub(r"<br\s*/?>", " ", text.lower())
    return re.findall(r"[a-z']+|[!?]", text)

counts = collections.Counter(w for t in train_texts for w in tokenize(t))
itos = ["<pad>", "<unk>"] + [w for w, _ in counts.most_common(9998)]
stoi = {w: i for i, w in enumerate(itos)}

MAXLEN = 200
def encode(texts):
    X = torch.zeros(len(texts), MAXLEN, dtype=torch.long)
    lengths = torch.zeros(len(texts), dtype=torch.long)
    for i, t in enumerate(texts):
        ids = [stoi.get(w, 1) for w in tokenize(t)][:MAXLEN]
        X[i, :len(ids)] = torch.tensor(ids)
        lengths[i] = len(ids)
    return X, lengths

X_train, len_train = encode(train_texts)
X_test, len_test = encode(test_texts)
y_train, y_test = torch.tensor(train_labels), torch.tensor(test_labels)

print("train:", tuple(X_train.shape), "test:", tuple(X_test.shape))
print("словник:", len(itos), "слів")
print("середня довжина:", round(len_train.float().mean().item(), 1), "токенів")
print("відгуків із 200 токенів і більше:", (len_train == MAXLEN).sum().item())
print("частка позитивних:", round(y_train.float().mean().item(), 3))
```

#output
```text
train: (10000, 200) test: (5000, 200)
словник: 10000 слів
середня довжина: 159.2 токенів
відгуків із 200 токенів і більше: 4148
частка позитивних: 0.501
```

Окрім матриці індексів `X` зберігаються справжні довжини `lengths`. Вони потрібні для наступного кроку.

## Пастка з padding

Відгуки в батчі мають різну довжину, тому короткі доповнені нулями. Якщо подати такий батч у `nn.RNN` як є, мережа прочитає всі 200 позицій, зокрема й `<pad>`. Стан `h_n` буде взято після десятків «порожніх» кроків, і слова відгуку майже стерті. На схемі відгук «not good» дописано трьома `<pad>`:

Рішення — функція `pack_padded_sequence`. Вона отримує справжні довжини й змушує RNN для кожного відгуку зупинитися на його останньому слові. Праворуч на схемі — результат реального експерименту на цьому наборі (він наведений нижче): без packing мережа після шести епох залишається на рівні випадкового вгадування (50.0%), з packing досягає 68.0%.

## Класифікатор відгуків на RNN

Архітектура: embedding → RNN → останній прихований стан → лінійний шар із двома виходами (позитивний/негативний). Розмір embedding 64, прихованого стану 64. Для порівняння поруч стоїть модель із лекції 10: усереднення embeddings без урахування `<pad>`.

::jupyter-notebook{title="rnn_classifier.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="2"}

```python
import time
import torch.nn as nn
from torch.nn.utils.rnn import pack_padded_sequence

V = len(itos)

class AvgClassifier(nn.Module):
    def __init__(self):
        super().__init__()
        self.emb = nn.Embedding(V, 64, padding_idx=0)
        self.fc = nn.Linear(64, 2)

    def forward(self, x, lengths):
        mask = (x != 0).float().unsqueeze(-1)
        mean = (self.emb(x) * mask).sum(1) / lengths.clamp(min=1).unsqueeze(-1)
        return self.fc(mean)

class RNNClassifier(nn.Module):
    def __init__(self, hidden=64, packed=True):
        super().__init__()
        self.packed = packed
        self.emb = nn.Embedding(V, 64, padding_idx=0)
        self.rnn = nn.RNN(64, hidden, batch_first=True)
        self.fc = nn.Linear(hidden, 2)

    def forward(self, x, lengths):
        e = self.emb(x)
        if self.packed:
            e = pack_padded_sequence(e, lengths.clamp(min=1).cpu(),
                                     batch_first=True, enforce_sorted=False)
        _, h_n = self.rnn(e)
        return self.fc(h_n[-1])

def fit(model, epochs=6, batch_size=64, lr=2e-3):
    opt = torch.optim.Adam(model.parameters(), lr=lr)
    loss_fn = nn.CrossEntropyLoss()
    t0 = time.time()
    for epoch in range(epochs):
        model.train()
        perm = torch.randperm(len(X_train))
        total = 0.0
        for i in range(0, len(perm), batch_size):
            ix = perm[i:i + batch_size]
            opt.zero_grad()
            loss = loss_fn(model(X_train[ix], len_train[ix]), y_train[ix])
            loss.backward()
            nn.utils.clip_grad_norm_(model.parameters(), 1.0)
            opt.step()
            total += loss.item() * len(ix)
        model.eval()
        with torch.no_grad():
            correct = sum((model(X_test[i:i + 500], len_test[i:i + 500]).argmax(1)
                           == y_test[i:i + 500]).sum().item()
                          for i in range(0, len(X_test), 500))
        print(f"епоха {epoch + 1}: loss {total / len(X_train):.3f}, "
              f"accuracy {correct / len(X_test):.3f}")
    print(f"параметрів: {sum(p.numel() for p in model.parameters()):,}, "
          f"час: {time.time() - t0:.0f} с")

torch.manual_seed(0)
fit(AvgClassifier())
print()
fit(RNNClassifier())
```

Результат протилежний очікуваному: проста RNN не лише не перевершила усереднення, а й поступилася на 16,6 процентного пункту, працюючи при цьому в десятки разів довше. Імовірні причини:

1. Відгук довгий (у середньому 159 токенів). Слова, що визначають тональність («terrible», «brilliant»), часто стоять далеко від кінця, а градієнт до них не доходить (наступний розділ).
2. Усереднення оцінює кожне слово окремо, а для визначення тональності відгуку окремих слів на кшталт «awful» чи «excellent» значною мірою вистачає й без порядку.

Експеримент короткий: шість епох. Крива RNN ще не вийшла на плато, але розрив у 16,6 пункту не пояснюється нестачею одного-двох проходів.

::warning
Висновок: рекурентна модель не обов'язково краща за усереднення. На довгих відгуках і невеликому наборі простий baseline часто залишається сильнішим. Перевіряйте його першим.
::

## Backpropagation Through Time і зникнення градієнта

Навчання RNN — це звичайне зворотне поширення помилки по розгорнутому ланцюжку (*backpropagation through time*, BPTT). Помилку обчислюють на останньому стані, а потім розповсюджують назад: від :math-formula{tex="h_T" inline} до :math-formula{tex="h_{T-1}" inline}, далі до :math-formula{tex="h_{T-2}" inline} і так до першого слова. Градієнт для слова на відстані :math-formula{tex="k" inline} кроків від кінця містить добуток :math-formula{tex="k" inline} множників:

::math-formula
\frac{\partial h_T}{\partial h_{T-k}} = \prod_{j=T-k+1}^{T} \frac{\partial h_j}{\partial h_{j-1}}, \qquad \frac{\partial h_j}{\partial h_{j-1}} = \operatorname{diag}\!\big(1 - h_j^2\big)\, W_h
::

Якщо кожен множник у середньому менший за одиницю, добуток зменшується експоненційно: градієнт 0,9 у степені 100 уже становить близько 0,00003. Якщо множники більші за одиницю, градієнт натомість *вибухає*. Виміряємо це на RNN зі стартовими вагами: 30 випадкових послідовностей по 50 кроків, норма градієнта останнього стану за станом на відстані :math-formula{tex="k" inline} кроків назад.

![Норма градієнта на лог-шкалі: 8 на останньому кроці, 2·10⁻³ за 10 кроків до кінця, 3·10⁻¹⁰ за 30, 6·10⁻¹⁷ за 49](/images/ai-python/natural-language-processing/rnn/02-vanishing-gradient.png){.diagram-img}

Пряма на логарифмічній шкалі означає експоненційний спад. Вже на 10 кроків назад градієнт менший у тисячі разів, на 30 кроків — у десятки мільярдів, а на 49 дорівнює приблизно 10⁻¹⁶, тобто вага відповідного слова практично не впливає на навчання. Це і є зникнення градієнта: початок довгого відгуку мережа «не чує».

Наслідок для класифікатора відгуків: мережа вчиться на останніх десятках слів, а початок відгуку ігнорує.

### Що з цим можна робити

- **Обрізання градієнта (gradient clipping).** Якщо норма перевищує поріг, градієнт масштабується до порогу: `nn.utils.clip_grad_norm_(model.parameters(), 1.0)`. Це захищає від *вибуху* градієнта (одна величезна оновлена вага ламає навчання), але не лікує *зникнення*. Рядок уже є в навчальному циклі вище.
- **Ортогональна ініціалізація** `nn.init.orthogonal_(rnn.weight_hh_l0)` робить власні числа :math-formula{tex="W_h" inline} близькими до одиниці й сповільнює спад, але не прибирає його.
- **Вентилі.** Радикальне рішення — змінити саму архітектуру: додати шлях, яким градієнт проходить без множення на :math-formula{tex="W_h" inline} на кожному кроці. Це LSTM і GRU, їм присвячена наступна лекція.

## Варіанти використання RNN

Відрізняються лише тим, які стани беруться за вихід:

| Варіант | Що береться | Задача |
|---|---|---|
| Many-to-one | останній стан :math-formula{tex="h_T" inline} | класифікація відгуку, спам-фільтр |
| Many-to-many | стан :math-formula{tex="h_t" inline} на кожному кроці | мовна модель, розмітка частин мови |
| Двонапрямна (bidirectional) | стани двох ланцюжків, склеєні | розуміння тексту, коли відомий весь текст |

**Мовна модель** (лекція 11) передбачає на кожному кроці наступне слово. Під час навчання на вхід подають справжнє слово :math-formula{tex="w_t" inline}, а ціль — :math-formula{tex="w_{t+1}" inline}: це **teacher forcing**. На відміну від біграм, стан :math-formula{tex="h_t" inline} враховує все речення, а не лише останнє слово.

**Двонапрямна RNN** запускає два ланцюжки: зліва направо й справа наліво. Стан кожного слова — склейка обох, тому розмір виходу подвоюється:

::jupyter-notebook{title="bidirectional.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="1"}

```python
import torch, torch.nn as nn

torch.manual_seed(0)
x = torch.randn(2, 4, 10)
bi = nn.RNN(10, 16, batch_first=True, bidirectional=True)
output, h_n = bi(x)
print("output:", tuple(output.shape))
print("h_n:   ", tuple(h_n.shape))
```

#output
```text
output: (2, 4, 32)
h_n: (2, 2, 16)
```

::

::

`output` має розмір 32 = 2 × 16, а `h_n` містить два стани: для прямого й для зворотного напрямків. Для класифікатора їх склеюють: `torch.cat([h_n[0], h_n[1]], dim=1)`.

::warning
Двонапрямну RNN не можна використовувати для генерації тексту: зворотний ланцюжок читає слова, яких ще немає.
::

```python
class BiRNNClassifier(nn.Module):
    def __init__(self, hidden=64):
        super().__init__()
        self.emb = nn.Embedding(V, 64, padding_idx=0)
        self.rnn = nn.RNN(64, hidden, batch_first=True, bidirectional=True)
        self.fc = nn.Linear(hidden * 2, 2)

    def forward(self, x, lengths):
        e = pack_padded_sequence(self.emb(x), lengths.clamp(min=1).cpu(),
                                 batch_first=True, enforce_sorted=False)
        _, h_n = self.rnn(e)
        return self.fc(torch.cat([h_n[0], h_n[1]], dim=1))
```

Зворотний ланцюжок починає читання з кінця відгуку, тому початок відгуку для нього — це останні кроки. Чи дасть це приріст, залежить від запуску: перевірте самі.

:::accordion-item{label="📋 Завдання 3: виміряти градієнт самостійно" icon="i-lucide-clipboard-list"}

Замініть `nn.RNNCell` на `nn.GRUCell` у коді виміру градієнта (нижче) і порівняйте криві.

:::accordion-item{label="✅ Розв'язок 3" icon="i-lucide-check-circle"}

```python
import torch, torch.nn as nn

torch.manual_seed(0)
T, H, D = 50, 64, 64
cell = nn.RNNCell(D, H)             # для завдання замініть на nn.GRUCell(D, H)
acc = torch.zeros(T)
for _ in range(30):
    x = torch.randn(T, 1, D)
    h = torch.zeros(1, H)
    states = []
    for t in range(T):
        h = cell(x[t], h)
        h.retain_grad()             # зберегти градієнт проміжного стану
        states.append(h)
    states[-1].sum().backward()
    acc += torch.tensor([s.grad.norm().item() for s in states])
print((acc / 30)[[49, 39, 19, 0]])  # відстань 0, 10, 30, 49 кроків від кінця
```

## Підсумок

::card-group

::card{title="✅ Що ми дізналися" icon="i-lucide-check-circle"}

- RNN читає слова по черзі й оновлює прихований стан :math-formula{tex="h_t = \tanh(W_x x_t + W_h h_{t-1} + b)" inline}; ваги однакові на всіх кроках.
- `nn.RNN` повертає стани всіх кроків (`output`) і останній стан (`h_n`); формула збігається з ручним розрахунком.
- Без `pack_padded_sequence` мережа читає `<pad>`: accuracy 50.0% проти 68.0%.
- На 10 000 відгуків IMDB проста RNN (68.0%) поступилася усередненню embeddings (84.6%) і навчалася в десятки разів довше.
- Градієнт за 49 кроків зменшується від 8 до 6·10⁻¹⁷.

- Навчальний цикл із `clip_grad_norm_`.
- Вимір норми градієнта по кроках через `retain_grad`.

## Що далі

Зникнення градієнта лікується архітектурою. У наступній лекції LSTM додає окремий шлях для довгої пам'яті (*cell state*) і три вентилі, що керують ним, а GRU спрощує цю ідею до двох вентилів. На тому самому наборі IMDB порівняємо RNN, LSTM і GRU.
