# Лекція 13: LSTM і GRU

## Проблема, яку розв'язують LSTM і GRU

У [лекції 12](/16.ai-python/16.natural-language-processing/12.rnn) ми бачили, що звичайний RNN має **проблему зникнення градієнта**:

::math-formula{tex="\left\| \frac{\partial h_T}{\partial h_0} \right\| \leq \gamma^T, \quad \gamma < 1"}
::

Для послідовності з 50 токенів градієнт може зменшитися в **тисячі разів**, що робить навчання на довгих залежностях майже неможливим.

**Приклад**: Речення "The book that I bought last week at the store near my house **was** interesting" — RNN важко зв'язати "book" (однина) з "was" через 12 слів між ними.

::callout{type="warning" title="Що НЕ працює"}
Gradient clipping і orthogonal ініціалізація (лекція 12) допомагають, але не розв'язують проблему повністю. Потрібна **нова архітектура**.
::

---

## LSTM: Long Short-Term Memory

**LSTM** (запропонований Hochreiter & Schmidhuber, 1997) додає до RNN **механізм пам'яті** через **cell state** і **три вентилі (gates)**.

### Архітектура LSTM

![Схема LSTM з вентилями](/images/16.ai-python/16.natural-language-processing/13.lstm-gru/lstm-architecture.png)

**Основна ідея**: замість одного прихованого стану :math-formula{tex="h_t" inline}, LSTM має **два** стани:

- **Cell state** :math-formula{tex="C_t" inline} — "довгострокова пам'ять" (інформаційний конвеєр)
- **Hidden state** :math-formula{tex="h_t" inline} — "короткострокова пам'ять" (як в RNN)

**Три вентилі** контролюють потік інформації:

1. **Forget gate** :math-formula{tex="f_t" inline} — що забути з :math-formula{tex="C_{t-1}" inline}
2. **Input gate** :math-formula{tex="i_t" inline} — що додати до :math-formula{tex="C_t" inline}
3. **Output gate** :math-formula{tex="o_t" inline} — що вивести в :math-formula{tex="h_t" inline}

### Математика LSTM

На кожному кроці :math-formula{tex="t" inline} LSTM обчислює:

**1. Forget gate** (забувальний вентиль):

::math-formula{tex="f_t = \sigma(W_f [h_{t-1}, x_t] + b_f)"}
::

- :math-formula{tex="f_t \in [0, 1]^h" inline} — для кожного елемента cell state
- :math-formula{tex="\sigma" inline} — сигмоїда (виходить від 0 до 1)
- :math-formula{tex="f_t \approx 0" inline} → забути, :math-formula{tex="f_t \approx 1" inline} → зберегти

**2. Input gate** (вхідний вентиль):

::math-formula{tex="i_t = \sigma(W_i [h_{t-1}, x_t] + b_i)"}
::

::math-formula{tex="\tilde{C}_t = \tanh(W_C [h_{t-1}, x_t] + b_C)"}
::

- :math-formula{tex="i_t" inline} — наскільки важлива нова інформація
- :math-formula{tex="\tilde{C}_t" inline} — кандидат на додавання до cell state

**3. Оновлення cell state**:

::math-formula{tex="C_t = f_t \odot C_{t-1} + i_t \odot \tilde{C}_t"}
::

- :math-formula{tex="\odot" inline} — поелементне множення (Hadamard product)
- Забуваємо частину :math-formula{tex="C_{t-1}" inline} (множимо на :math-formula{tex="f_t" inline})
- Додаємо нову інформацію (множимо :math-formula{tex="\tilde{C}_t" inline} на :math-formula{tex="i_t" inline})

**4. Output gate** (вихідний вентиль):

::math-formula{tex="o_t = \sigma(W_o [h_{t-1}, x_t] + b_o)"}
::

::math-formula{tex="h_t = o_t \odot \tanh(C_t)"}
::

- :math-formula{tex="h_t" inline} — прихований стан (який йде далі і на вихід)

::callout{type="info" title="Позначення"}
- :math-formula{tex="[h_{t-1}, x_t]" inline} — конкатенація векторів :math-formula{tex="h_{t-1}" inline} і :math-formula{tex="x_t" inline}
- Якщо :math-formula{tex="h_{t-1} \in \mathbb{R}^h" inline} і :math-formula{tex="x_t \in \mathbb{R}^d" inline}, то :math-formula{tex="[h_{t-1}, x_t] \in \mathbb{R}^{h+d}" inline}
- Всі ваги :math-formula{tex="W_f, W_i, W_C, W_o \in \mathbb{R}^{h \times (h+d)}" inline}
::

## Як LSTM розв'язує проблему зникнення градієнта?

### Градієнт через cell state

Ключова відмінність: **cell state :math-formula{tex="C_t" inline} оновлюється адитивно** (додаванням), а не множенням:

::math-formula{tex="C_t = f_t \odot C_{t-1} + i_t \odot \tilde{C}_t"}
::

Градієнт :math-formula{tex="\frac{\partial C_t}{\partial C_{t-1}}" inline} має доданок:

::math-formula{tex="\frac{\partial C_t}{\partial C_{t-1}} = f_t + \ldots"}
::

Якщо :math-formula{tex="f_t \approx 1" inline} (вентиль відкритий), градієнт **тече без затухання**! 🎉

### Порівняння: RNN vs LSTM

| Архітектура | Оновлення стану | Градієнт через :math-formula{tex="T" inline} кроків |
|-------------|-----------------|---------------------------|
| **RNN** | :math-formula{tex="h_t = \tanh(W_h h_{t-1} + \ldots)" inline} | :math-formula{tex="\Vert \frac{\partial h_T}{\partial h_0} \Vert \leq \gamma^T" inline} (зникає) |
| **LSTM** | :math-formula{tex="C_t = f_t \odot C_{t-1} + i_t \odot \tilde{C}_t" inline} | Якщо :math-formula{tex="f_t \approx 1" inline}, градієнт зберігається |

**Візуалізація**:

![Градієнти: RNN vs LSTM](/images/16.ai-python/16.natural-language-processing/13.lstm-gru/gradient-flow.png)

LSTM може зберігати інформацію на **сотні кроків** назад!

## LSTM у PyTorch

PyTorch має готовий модуль `nn.LSTM`. Подивимося, як він працює:

::jupyter-notebook
```python
import torch
import torch.nn as nn

# Параметри
batch_size = 2
seq_len = 5
embed_dim = 10
hidden_dim = 16

# Приклад входу
x = torch.randn(batch_size, seq_len, embed_dim)

# Створюємо LSTM
lstm = nn.LSTM(input_size=embed_dim, hidden_size=hidden_dim, batch_first=True)

# Forward pass
output, (h_n, c_n) = lstm(x)

print(f"Вхід x: {x.shape}")
print(f"Виходи output: {output.shape}")  # (batch, seq_len, hidden_dim)
print(f"Останній h_n: {h_n.shape}")      # (1, batch, hidden_dim)
print(f"Останній c_n: {c_n.shape}")      # (1, batch, hidden_dim)
```

**Відмінності від nn.RNN**:

- `nn.LSTM` повертає **два** стани: `(h_n, c_n)`
  - `h_n` — hidden state (як в RNN)
  - `c_n` — **cell state** (нова річ!)
- `output[i, t, :]` = :math-formula{tex="h_t" inline} (не :math-formula{tex="C_t" inline}!)

::callout{type="info" title="Початкові стани"}
За замовчуванням :math-formula{tex="h_0 = \mathbf{0}" inline} і :math-formula{tex="C_0 = \mathbf{0}" inline}. 

Можна передати власні початкові стани:
```python
h_0 = torch.randn(1, batch_size, hidden_dim)
c_0 = torch.randn(1, batch_size, hidden_dim)
output, (h_n, c_n) = lstm(x, (h_0, c_0))
```
::

## Класифікація sentiment з LSTM

Повернемося до IMDB. Замінимо RNN на LSTM:

::jupyter-notebook
```python
import torch.nn as nn

class LSTMClassifier(nn.Module):
    def __init__(self, vocab_size, embed_dim, hidden_dim, num_classes, pad_idx):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_dim, padding_idx=pad_idx)
        self.lstm = nn.LSTM(embed_dim, hidden_dim, batch_first=True)
        self.fc = nn.Linear(hidden_dim, num_classes)
    
    def forward(self, x):
        # x: (batch, seq_len)
        embedded = self.embedding(x)  # (batch, seq_len, embed_dim)
        output, (h_n, c_n) = self.lstm(embedded)
        # Беремо останній hidden state
        last_hidden = h_n.squeeze(0)  # (batch, hidden_dim)
        logits = self.fc(last_hidden)
        return logits

# Приклад
vocab_size = 10000
model = LSTMClassifier(vocab_size, embed_dim=100, hidden_dim=128, num_classes=2, pad_idx=0)
print(model)
```

### Навчання на IMDB

::jupyter-notebook
```python
import torch
from torch.utils.data import DataLoader

# Використаємо датасет і collate_fn з лекції 12
# (припускаємо, що IMDBDataset і collate_fn вже визначені)

# Приклад даних (спрощений)
texts_train = [
    "this movie is absolutely fantastic and amazing",
    "terrible awful film waste of time",
    "great performance stunning visuals",
    "boring predictable not worth watching"
]
labels_train = [1, 0, 1, 0]

vocab = {"<pad>": 0, "<unk>": 1, "this": 2, "movie": 3, "is": 4, "absolutely": 5,
         "fantastic": 6, "and": 7, "amazing": 8, "terrible": 9, "awful": 10,
         "film": 11, "waste": 12, "of": 13, "time": 14, "great": 15, 
         "performance": 16, "stunning": 17, "visuals": 18, "boring": 19,
         "predictable": 20, "not": 21, "worth": 22, "watching": 23}

# Спрощений Dataset (як у лекції 12)
class SimpleDataset:
    def __init__(self, texts, labels, vocab):
        self.data = [([vocab.get(w, 1) for w in text.split()], label) 
                     for text, label in zip(texts, labels)]
    
    def __len__(self):
        return len(self.data)
    
    def __getitem__(self, idx):
        tokens, label = self.data[idx]
        return torch.tensor(tokens), torch.tensor(label)

def collate_fn(batch):
    texts, labels = zip(*batch)
    max_len = max(len(t) for t in texts)
    padded = torch.zeros(len(texts), max_len, dtype=torch.long)
    for i, t in enumerate(texts):
        padded[i, :len(t)] = t
    return padded, torch.stack(labels)

dataset = SimpleDataset(texts_train, labels_train, vocab)
loader = DataLoader(dataset, batch_size=2, collate_fn=collate_fn)

# Модель
model = LSTMClassifier(len(vocab), embed_dim=16, hidden_dim=32, num_classes=2, pad_idx=0)
criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(model.parameters(), lr=0.001)

# Навчання
model.train()
for epoch in range(10):
    total_loss = 0
    for texts, labels in loader:
        optimizer.zero_grad()
        logits = model(texts)
        loss = criterion(logits, labels)
        loss.backward()
        optimizer.step()
        total_loss += loss.item()
    if (epoch + 1) % 2 == 0:
        print(f"Epoch {epoch+1}, Loss: {total_loss/len(loader):.4f}")

# Тестування
model.eval()
test_text = "this movie is boring and terrible"
test_tokens = torch.tensor([[vocab.get(w, 1) for w in test_text.split()]])
with torch.no_grad():
    logits = model(test_tokens)
    pred = torch.argmax(logits, dim=1)
print(f"\nТекст: '{test_text}'")
print(f"Передбачення: {'positive' if pred.item() == 1 else 'negative'}")
```

| Модель | Test Accuracy | Кількість параметрів | Час епоха (GPU) |
|--------|---------------|---------------------|-----------------|
| **RNN** | 87.6% | 1.2M | 45 сек |
| **LSTM** | 89.8% | 3.8M | 72 сек |

**Висновок**: LSTM дає **+2.2% accuracy**, але потребує **втричі більше параметрів** (бо 3 вентилі + cell state) і працює повільніше.

::callout{type="success" title="Коли використовувати LSTM?"}
LSTM корисний для:

- **Довгих послідовностей** (>50 токенів)
- **Довгострокових залежностей** (інформація на початку впливає на кінець)
- **Складних паттернів** (наприклад, nested structures в коді)

Для коротких послідовностей (<20 токенів) звичайний RNN може бути достатнім.
::

## GRU: Gated Recurrent Unit

**GRU** (Cho et al., 2014) — спрощена версія LSTM з **двома вентилями** замість трьох.

### Архітектура GRU

![Схема GRU з вентилями](/images/16.ai-python/16.natural-language-processing/13.lstm-gru/gru-architecture.png)

**Основна ідея**: замість окремих :math-formula{tex="h_t" inline} і :math-formula{tex="C_t" inline}, GRU має **лише :math-formula{tex="h_t" inline}** (як RNN), але з вентилями.

**Два вентилі**:

1. **Reset gate** :math-formula{tex="r_t" inline} — скільки "забути" з :math-formula{tex="h_{t-1}" inline}
2. **Update gate** :math-formula{tex="z_t" inline} — як балансувати між старим :math-formula{tex="h_{t-1}" inline} і новим :math-formula{tex="\tilde{h}_t" inline}

### Математика GRU

**1. Update gate** (вентиль оновлення):

::math-formula{tex="z_t = \sigma(W_z [h_{t-1}, x_t] + b_z)"}
::

**2. Reset gate** (вентиль скидання):

::math-formula{tex="r_t = \sigma(W_r [h_{t-1}, x_t] + b_r)"}
::

**3. Кандидат на новий стан**:

::math-formula{tex="\tilde{h}_t = \tanh(W_h [r_t \odot h_{t-1}, x_t] + b_h)"}
::

- :math-formula{tex="r_t \odot h_{t-1}" inline} — "скидаємо" частину попереднього стану

**4. Фінальний стан**:

::math-formula{tex="h_t = (1 - z_t) \odot h_{t-1} + z_t \odot \tilde{h}_t"}
::

- :math-formula{tex="z_t" inline} контролює, скільки взяти від старого :math-formula{tex="h_{t-1}" inline} і скільки від нового :math-formula{tex="\tilde{h}_t" inline}
- Якщо :math-formula{tex="z_t \approx 0" inline} → зберігаємо :math-formula{tex="h_{t-1}" inline}
- Якщо :math-formula{tex="z_t \approx 1" inline} → беремо :math-formula{tex="\tilde{h}_t" inline}

::callout{type="info" title="Відмінності GRU від LSTM"}
| Параметр | LSTM | GRU |
|----------|------|-----|
| **Стани** | :math-formula{tex="h_t" inline} і :math-formula{tex="C_t" inline} (два) | Лише :math-formula{tex="h_t" inline} (один) |
| **Вентилі** | Forget, Input, Output (три) | Reset, Update (два) |
| **Параметри** | ~4× більше ніж RNN | ~3× більше ніж RNN |
| **Швидкість** | Повільніше | Швидше за LSTM |

GRU — це **компроміс** між RNN (простий, швидкий) і LSTM (потужний, повільний).
::

## Візуалізація вентилів (Gates)

Подивимося, як працюють вентилі LSTM на реальному прикладі.

::jupyter-notebook
```python
import torch
import torch.nn as nn
import matplotlib.pyplot as plt
import numpy as np

# Створимо LSTM і візуалізуємо вентилі
lstm = nn.LSTM(input_size=10, hidden_size=16, batch_first=True)
```

## Багатошарові LSTM/GRU

Можна **стакати** кілька LSTM/GRU шарів один на одного:

```
x → LSTM_1 → LSTM_2 → LSTM_3 → output
```

У PyTorch:

::jupyter-notebook
```python
# Двошаровий LSTM
lstm_stacked = nn.LSTM(
    input_size=100,
    hidden_size=128,
    num_layers=2,      # 2 шари!
    batch_first=True,
    dropout=0.3        # dropout між шарами
)

x = torch.randn(4, 10, 100)  # (batch, seq_len, embed_dim)
output, (h_n, c_n) = lstm_stacked(x)

print(f"Output: {output.shape}")  # (4, 10, 128)
print(f"h_n: {h_n.shape}")        # (2, 4, 128) — 2 шари!
print(f"c_n: {c_n.shape}")        # (2, 4, 128)
```

:::jupyter-cell
```json
{
  "output": {
    "type": "stream",
    "text": [
      "Output: torch.Size([4, 10, 128])\n",
      "h_n: torch.Size([2, 4, 128])\n",
      "c_n: torch.Size([2, 4, 128])\n"

  }
}
```
:::
::

**Переваги**:

- Більш складні паттерни (перший шар — низькорівневі фічі, другий — високорівневі)
- Краща accuracy на складних задачах

**Недоліки**:

- Більше параметрів → повільніше
- Більше ризик перенавчання (потрібен dropout)

::callout{type="warning" title="Коли використовувати багатошарові?"}
Багатошарові LSTM/GRU корисні для **дуже складних** задач (наприклад, машинний переклад, генерація тексту).

Для класифікації sentiment часто достатньо **1 шару**. Якщо 1 шар дає 89%, то 2 шари можуть дати 89.5% — невелике покращення за велику ціну.

```python
class BiLSTMClassifier(nn.Module):
    def __init__(self, vocab_size, embed_dim, hidden_dim, num_classes, pad_idx):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_dim, padding_idx=pad_idx)
        self.lstm = nn.LSTM(embed_dim, hidden_dim, batch_first=True, bidirectional=True)
        self.fc = nn.Linear(hidden_dim * 2, num_classes)  # *2 бо bidirectional
    
    def forward(self, x):
        embedded = self.embedding(x)
        output, (h_n, c_n) = self.lstm(embedded)
        # h_n: (2, batch, hidden_dim) — [forward, backward]
        h_fwd = h_n[0]
        h_bwd = h_n[1]
        h_combined = torch.cat([h_fwd, h_bwd], dim=1)
        logits = self.fc(h_combined)
        return logits

model_bi = BiLSTMClassifier(10000, embed_dim=100, hidden_dim=128, num_classes=2, pad_idx=0)
print(f"Параметри: {sum(p.numel() for p in model_bi.parameters()):,}")
```

:::accordion-item{title="Завдання 2: Візуалізація Cell State (★★★)"}

Візуалізуйте, як змінюється **cell state** :math-formula{tex="C_t" inline} LSTM протягом обробки речення.

**Підказки**:

1. Потрібно модифікувати forward pass, щоб зберігати всі :math-formula{tex="C_t" inline}
2. Застосуйте PCA до :math-formula{tex="(C_0, C_1, \ldots, C_n)" inline} → 2D
3. Намалюйте траєкторію (як у лекції 12 для :math-formula{tex="h_t" inline})

**Розв'язок**:

```python
import torch
import torch.nn as nn
from sklearn.decomposition import PCA
import matplotlib.pyplot as plt

# Візьмемо навчену LSTM модель
model_lstm = LSTMClassifier(len(vocab), embed_dim=16, hidden_dim=32, num_classes=2, pad_idx=0)
# (припускаємо, що модель навчена)

# Власний forward для збереження cell states
class LSTMWithStates(nn.Module):
    def __init__(self, lstm_model):
        super().__init__()
        self.embedding = lstm_model.embedding
        self.lstm = lstm_model.lstm
    
    def forward(self, x):
        embedded = self.embedding(x)
        batch_size, seq_len, _ = embedded.shape
        
        h_t = torch.zeros(1, batch_size, self.lstm.hidden_size)
        c_t = torch.zeros(1, batch_size, self.lstm.hidden_size)
        
        cell_states = [c_t.squeeze(0).detach().numpy()]
        
        for t in range(seq_len):
            x_t = embedded[:, t:t+1, :]
            _, (h_t, c_t) = self.lstm(x_t, (h_t, c_t))
            cell_states.append(c_t.squeeze(0).detach().numpy())
        
        return cell_states

# Візуалізація
model_with_states = LSTMWithStates(model_lstm)
text = "this movie was not good"
tokens_ids = [vocab.get(w, 1) for w in text.split()]
x = torch.tensor([tokens_ids])

with torch.no_grad():
    cell_states = model_with_states(x)

# PCA
cell_states_arr = np.array([cs[0] for cs in cell_states])  # (seq_len+1, hidden_dim)
pca = PCA(n_components=2)
coords_2d = pca.fit_transform(cell_states_arr)
```

:::accordion-item{title="Завдання 3: Peephole LSTM (★★★)"}

**Peephole connections** (Gers & Schmidhuber, 2000) — варіант LSTM, де вентилі мають доступ до :math-formula{tex="C_{t-1}" inline} (не лише :math-formula{tex="h_{t-1}" inline}).

Реалізуйте Peephole LSTM вручну (без `nn.LSTM`).

**Математика**:

::math-formula{tex="\begin{aligned} f_t &= \sigma(W_f [h_{t-1}, x_t] + W_{f,c} \odot C_{t-1} + b_f) \\ i_t &= \sigma(W_i [h_{t-1}, x_t] + W_{i,c} \odot C_{t-1} + b_i) \\ \tilde{C}_t &= \tanh(W_C [h_{t-1}, x_t] + b_C) \\ C_t &= f_t \odot C_{t-1} + i_t \odot \tilde{C}_t \\ o_t &= \sigma(W_o [h_{t-1}, x_t] + W_{o,c} \odot C_t + b_o) \\ h_t &= o_t \odot \tanh(C_t) \end{aligned}"}
::

**Розв'язок** (скорочений):

```python
class PeepholeLSTMCell(nn.Module):
    def __init__(self, input_size, hidden_size):
        super().__init__()
        self.hidden_size = hidden_size
        
        # Ваги для вентилів
        self.W_f = nn.Linear(input_size + hidden_size, hidden_size)
        self.W_i = nn.Linear(input_size + hidden_size, hidden_size)
        self.W_C = nn.Linear(input_size + hidden_size, hidden_size)
        self.W_o = nn.Linear(input_size + hidden_size, hidden_size)
        
        # Peephole weights (element-wise)
        self.W_fc = nn.Parameter(torch.randn(hidden_size))
        self.W_ic = nn.Parameter(torch.randn(hidden_size))
        self.W_oc = nn.Parameter(torch.randn(hidden_size))
    
    def forward(self, x_t, h_prev, C_prev):
        # x_t: (batch, input_size)
        # h_prev: (batch, hidden_size)
        # C_prev: (batch, hidden_size)
        
        combined = torch.cat([h_prev, x_t], dim=1)
        
        # Forget gate (з peephole)
        f_t = torch.sigmoid(self.W_f(combined) + self.W_fc * C_prev)
        
        # Input gate (з peephole)
        i_t = torch.sigmoid(self.W_i(combined) + self.W_ic * C_prev)
        
        # Candidate
        C_tilde = torch.tanh(self.W_C(combined))
        
        # Cell state
        C_t = f_t * C_prev + i_t * C_tilde
        
        # Output gate (з peephole на C_t!)
        o_t = torch.sigmoid(self.W_o(combined) + self.W_oc * C_t)
        
        # Hidden state
        h_t = o_t * torch.tanh(C_t)
        
        return h_t, C_t

# Тестування
peephole = PeepholeLSTMCell(input_size=10, hidden_size=16)
x = torch.randn(2, 10)
h = torch.zeros(2, 16)
C = torch.zeros(2, 16)

h_new, C_new = peephole(x, h, C)
print(f"h_new: {h_new.shape}, C_new: {C_new.shape}")
```

**Примітка**: На практиці Peephole LSTM рідко дає значне покращення, тому PyTorch не має вбудованої реалізації.

## Підсумок

::grid{cols=2}
  ::card{icon="lucide:brain-circuit"}
  **LSTM: Long Short-Term Memory**
  
  LSTM розв'язує проблему зникнення градієнта через **cell state :math-formula{tex="C_t" inline}** і **три вентилі**: forget gate (що забути), input gate (що додати), output gate (що вивести).
  ::

  ::card{icon="lucide:zap"}
  **GRU: Gated Recurrent Unit**
  
  GRU — спрощена версія LSTM з **двома вентилями** (reset, update) і **одним станом** :math-formula{tex="h_t" inline}. Швидше, менше параметрів, схожа accuracy.
  ::

  ::card{icon="lucide:trending-up"}
  **Градієнти**
  
  Cell state оновлюється **адитивно** (:math-formula{tex="C_t = f_t \odot C_{t-1} + \ldots" inline}), тому градієнт може текти без затухання на **сотні кроків**.
  ::

  ::card{icon="lucide:layers"}
  **Варіанти архітектур**
  
  - **Багатошарові** (num_layers>1): складніші паттерни
  - **Bidirectional**: контекст з обох боків
  - **Stacked + Bidirectional**: максимальна потужність
  ::
::
