# Лекція 14: Sequence-to-Sequence і Attention

## Мотивація: Від класифікації до генерації

У лекціях 12–13 ми використовували RNN/LSTM для **класифікації** (IMDB sentiment):

```
Вхідна послідовність → RNN/LSTM → Останній h_n → Linear → Клас
"This movie is great"                                      → positive
```

Але багато задач NLP вимагають **генерації послідовностей**:

- **Машинний переклад**: "Hello world" → "Привіт світ"
- **Підсумовування**: довга стаття → короткий резюме
- **Діалог**: питання → відповідь
- **Транскрипція**: аудіо → текст

Це задачі типу **sequence-to-sequence (seq2seq)**: вхідна послідовність → вихідна послідовність **різної довжини**.

::callout{type="info" title="Чим seq2seq відрізняється від класифікації?"}
| Задача | Вхід | Вихід | Приклад |
|--------|------|-------|---------|
| **Класифікація** | Послідовність | Один клас | "Great movie" → positive |
| **Seq2seq** | Послідовність | **Послідовність** | "Hello" → "Привіт" |

Ключова відмінність: довжина виходу **невідома заздалегідь** і може відрізнятися від входу.
::

## Encoder-Decoder архітектура

**Ідея**: розділити модель на дві частини:

1. **Encoder** — читає вхідну послідовність і кодує її в **контекстний вектор**
2. **Decoder** — генерує вихідну послідовність, використовуючи контекстний вектор

![Encoder-Decoder схема](/images/16.ai-python/16.natural-language-processing/14.seq2seq-attention/encoder-decoder-basic.png)

### Encoder (кодувальник)

Encoder — це LSTM (або GRU), який обробляє вхідну послідовність:

::math-formula{tex="h_1, h_2, \ldots, h_n = \text{LSTM}_{\text{enc}}(x_1, x_2, \ldots, x_n)"}
::

**Контекстний вектор** :math-formula{tex="c" inline} — це останній прихований стан encoder:

::math-formula{tex="c = h_n"}
::

Вектор :math-formula{tex="c" inline} містить "стиснуту" інформацію про весь вхід.

### Decoder (декодувальник)

Decoder — це інший LSTM, який генерує вихід **токен за токеном**:

::math-formula{tex="s_t = \text{LSTM}_{\text{dec}}(y_{t-1}, s_{t-1})"}
::

де:
- :math-formula{tex="s_t" inline} — прихований стан decoder на кроці :math-formula{tex="t" inline}
- :math-formula{tex="y_{t-1}" inline} — попередній згенерований токен (або `<SOS>` на початку)
- Початковий стан: :math-formula{tex="s_0 = c" inline} (контекстний вектор з encoder)

На кожному кроці decoder передбачає наступний токен:

::math-formula{tex="P(y_t | y_1, \ldots, y_{t-1}, x) = \text{softmax}(W s_t + b)"}
::

Генерація продовжується, доки модель не згенерує токен `<EOS>` (end of sequence).

## Приклад: Машинний переклад

Нехай ми перекладаємо "I am student" → "Я студент".

### Forward pass (training)

**Encoder**:
```
Вхід: ["I", "am", "student"]
  → Embeddings → LSTM_enc
  → h_1, h_2, h_3
Контекст: c = h_3
```

**Decoder** (з **teacher forcing** — подаємо справжні токени на вхід):
```
Крок 0: вхід = <SOS>,  стан = c   → передбачає "Я"
Крок 1: вхід = "Я",    стан = s_1 → передбачає "студент"
Крок 2: вхід = "студент", стан = s_2 → передбачає <EOS>
```

**Teacher forcing**: під час навчання на кроці :math-formula{tex="t" inline} ми подаємо **справжній** токен :math-formula{tex="y_t" inline} (з таргета), а не згенерований.

### Inference (генерація)

Під час inference ми **не знаємо** таргету, тому використовуємо **автореграсивну генерацію**:

```
Крок 0: вхід = <SOS> → генерує "Я"
Крок 1: вхід = "Я" (згенерований) → генерує "студент"
Крок 2: вхід = "студент" → генерує <EOS> → STOP
```

::jupyter-notebook
```python
import torch
import torch.nn as nn

# Простий Seq2Seq (без attention)
class Seq2Seq(nn.Module):
    def __init__(self, input_vocab_size, output_vocab_size, embed_dim, hidden_dim):
        super().__init__()
        self.encoder_emb = nn.Embedding(input_vocab_size, embed_dim)
        self.decoder_emb = nn.Embedding(output_vocab_size, embed_dim)
        
        self.encoder = nn.LSTM(embed_dim, hidden_dim, batch_first=True)
        self.decoder = nn.LSTM(embed_dim, hidden_dim, batch_first=True)
        
        self.fc = nn.Linear(hidden_dim, output_vocab_size)
    
    def forward(self, src, trg):
        # src: (batch, src_len)
        # trg: (batch, trg_len)
        
        # Encoder
        src_emb = self.encoder_emb(src)
        _, (h_n, c_n) = self.encoder(src_emb)  # h_n, c_n: (1, batch, hidden_dim)
        
        # Decoder (з teacher forcing)
        trg_emb = self.decoder_emb(trg)
        output, _ = self.decoder(trg_emb, (h_n, c_n))  # (batch, trg_len, hidden_dim)
        
        logits = self.fc(output)  # (batch, trg_len, output_vocab_size)
        return logits

# Приклад
model = Seq2Seq(input_vocab_size=5000, output_vocab_size=3000, embed_dim=128, hidden_dim=256)
src = torch.randint(0, 5000, (2, 6))  # 2 послідовності по 6 токенів
trg = torch.randint(0, 3000, (2, 4))  # таргети по 4 токени
logits = model(src, trg)
print(f"Вхід src: {src.shape}")
print(f"Таргет trg: {trg.shape}")
print(f"Вихід logits: {logits.shape}")
```

## Проблема вузького місця (Bottleneck Problem)

У базовому seq2seq **вся інформація** про вхідну послідовність стискається в **один вектор** :math-formula{tex="c" inline} (контекстний вектор).

![Bottleneck problem](/images/16.ai-python/16.natural-language-processing/14.seq2seq-attention/bottleneck-problem.png)

**Проблема**: для довгих послідовностей (>20-30 токенів) **один вектор не може зберегти всю інформацію**.

::callout{type="warning" title="Приклад bottleneck"}
Речення: "The conference that was originally scheduled for June but got postponed to September will be held in Kyiv"

Коли decoder генерує "Kyiv", йому потрібна інформація з **кінця** вхідного речення. Але вектор :math-formula{tex="c" inline} формується з останнього стану encoder, який може "забути" початок послідовності (проблема зникнення градієнта з лекції 12).
::

**Рішення**: механізм **уваги (attention)** — замість одного вектора :math-formula{tex="c" inline}, decoder має **доступ до всіх** :math-formula{tex="h_1, h_2, \ldots, h_n" inline} з encoder!

## Механізм уваги (Attention Mechanism)

**Основна ідея**: на кожному кроці декодування decoder "дивиться" (pays attention) на **різні частини** вхідної послідовності.

### Архітектура з увагою

![Seq2Seq з attention](/images/16.ai-python/16.natural-language-processing/14.seq2seq-attention/attention-architecture.png)

На кроці :math-formula{tex="t" inline} decoder обчислює:

1. **Контекстний вектор** :math-formula{tex="c_t" inline} як зважену суму всіх :math-formula{tex="h_i" inline} з encoder
2. **Вихід** :math-formula{tex="y_t" inline} на основі :math-formula{tex="c_t" inline} і :math-formula{tex="s_t" inline}

### Математика attention

**Крок 1**: Обчислюємо **оцінки (scores)** — наскільки релевантний кожен :math-formula{tex="h_i" inline} для поточного стану decoder :math-formula{tex="s_{t-1}" inline}:

::math-formula{tex="e_{t,i} = \text{score}(s_{t-1}, h_i)"}
::

Функція score може бути різною (ми розглянемо кілька варіантів нижче).

**Крок 2**: Нормалізуємо scores за допомогою **softmax** → отримуємо **attention weights**:

::math-formula{tex="\alpha_{t,i} = \frac{\exp(e_{t,i})}{\sum_{j=1}^{n} \exp(e_{t,j})}"}
::

де :math-formula{tex="\alpha_{t,i} \in [0, 1]" inline} і :math-formula{tex="\sum_{i=1}^{n} \alpha_{t,i} = 1" inline}.

**Крок 3**: Обчислюємо **контекстний вектор** як зважену суму:

::math-formula{tex="c_t = \sum_{i=1}^{n} \alpha_{t,i} \cdot h_i"}
::

**Крок 4**: Генеруємо вихід, комбінуючи :math-formula{tex="c_t" inline} і :math-formula{tex="s_t" inline}:

::math-formula{tex="\tilde{s}_t = \tanh(W_c [c_t; s_t] + b_c)"}
::

::math-formula{tex="y_t = \text{softmax}(W_o \tilde{s}_t + b_o)"}
::

::callout{type="info" title="Інтерпретація attention weights"}
:math-formula{tex="\alpha_{t,i}" inline} показує, **скільки уваги** decoder приділяє :math-formula{tex="i" inline}-му токену входу на кроці :math-formula{tex="t" inline}.

- Якщо :math-formula{tex="\alpha_{t,3} = 0.8" inline}, то decoder **фокусується** на 3-му токені входу
- Якщо всі :math-formula{tex="\alpha_{t,i} \approx 1/n" inline}, то увага **розподілена рівномірно** (як усереднення)
::

## Score functions (функції оцінки)

Існує кілька способів обчислити :math-formula{tex="\text{score}(s, h)" inline}:

### 1. Dot-product (скалярний добуток)

::math-formula{tex="\text{score}(s, h) = s^T h"}
::

**Переваги**: дуже швидко (одна операція)  
**Недоліки**: вимагає, щоб :math-formula{tex="s" inline} і :math-formula{tex="h" inline} мали однакову розмірність

### 2. Additive (Bahdanau attention)

::math-formula{tex="\text{score}(s, h) = v^T \tanh(W_s s + W_h h)"}
::

де :math-formula{tex="v, W_s, W_h" inline} — навчальні параметри.

**Переваги**: :math-formula{tex="s" inline} і :math-formula{tex="h" inline} можуть мати різні розмірності  
**Використання**: оригінальна стаття Bahdanau et al. (2015)

### 3. Scaled dot-product

::math-formula{tex="\text{score}(s, h) = \frac{s^T h}{\sqrt{d_k}}"}
::

де :math-formula{tex="d_k" inline} — розмірність векторів.

**Переваги**: стабільніше, ніж звичайний dot-product (використовується в Transformer, лекція 15)

## Seq2Seq з Attention у PyTorch

Реалізуємо повну модель з attention:

::jupyter-notebook
```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class AttentionLayer(nn.Module):
    def __init__(self, hidden_dim):
        super().__init__()
        # Additive attention (Bahdanau)
        self.W_s = nn.Linear(hidden_dim, hidden_dim)
        self.W_h = nn.Linear(hidden_dim, hidden_dim)
        self.v = nn.Linear(hidden_dim, 1)
    
    def forward(self, s, h_encoder):
        # s: (batch, hidden_dim) — поточний стан decoder
        # h_encoder: (batch, src_len, hidden_dim) — всі стани encoder
        
        batch_size, src_len, hidden_dim = h_encoder.shape
        
        # Розширюємо s до (batch, src_len, hidden_dim)
        s_expanded = s.unsqueeze(1).repeat(1, src_len, 1)
        
        # Обчислюємо scores
        scores = self.v(torch.tanh(self.W_s(s_expanded) + self.W_h(h_encoder)))
        # scores: (batch, src_len, 1)
        
        # Attention weights
        alpha = F.softmax(scores.squeeze(2), dim=1)  # (batch, src_len)
        
        # Контекстний вектор
        c_t = torch.bmm(alpha.unsqueeze(1), h_encoder).squeeze(1)
        # c_t: (batch, hidden_dim)
        
        return c_t, alpha

# Приклад
attention = AttentionLayer(hidden_dim=128)
s = torch.randn(2, 128)  # Decoder state
h_encoder = torch.randn(2, 6, 128)  # Encoder outputs (6 токенів)

c_t, alpha = attention(s, h_encoder)
print(f"Контекстний вектор c_t: {c_t.shape}")
print(f"Attention weights alpha: {alpha.shape}")
print(f"Сума alpha (має бути 1.0): {alpha.sum(dim=1)}")
```

### Повна модель Seq2Seq з Attention

::jupyter-notebook
```python
class Seq2SeqWithAttention(nn.Module):
    def __init__(self, input_vocab_size, output_vocab_size, embed_dim, hidden_dim):
        super().__init__()
        self.encoder_emb = nn.Embedding(input_vocab_size, embed_dim)
        self.decoder_emb = nn.Embedding(output_vocab_size, embed_dim)
        
        self.encoder = nn.LSTM(embed_dim, hidden_dim, batch_first=True)
        self.decoder = nn.LSTMCell(embed_dim, hidden_dim)  # LSTMCell для крок-за-кроком
        
        self.attention = AttentionLayer(hidden_dim)
        self.fc = nn.Linear(hidden_dim * 2, output_vocab_size)  # *2 бо [c_t; s_t]
    
    def forward(self, src, trg):
        # src: (batch, src_len)
        # trg: (batch, trg_len)
        
        batch_size = src.size(0)
        trg_len = trg.size(1)
        
        # Encoder
        src_emb = self.encoder_emb(src)
        h_encoder, (h_n, c_n) = self.encoder(src_emb)
        # h_encoder: (batch, src_len, hidden_dim)
        
        # Decoder початковий стан
        s_t = h_n.squeeze(0)  # (batch, hidden_dim)
        c_t_lstm = c_n.squeeze(0)
        
        outputs = []
        
        # Decoder крок за кроком
        for t in range(trg_len):
            # Вхід на кроці t
            trg_t = trg[:, t]  # (batch,)
            trg_emb_t = self.decoder_emb(trg_t)  # (batch, embed_dim)
            
            # Attention
            c_t, alpha = self.attention(s_t, h_encoder)
            
            # Decoder крок
            s_t, c_t_lstm = self.decoder(trg_emb_t, (s_t, c_t_lstm))
            
            # Комбінуємо context і decoder state
            combined = torch.cat([c_t, s_t], dim=1)  # (batch, hidden_dim*2)
            output_t = self.fc(combined)  # (batch, output_vocab_size)
            
            outputs.append(output_t.unsqueeze(1))
        
        outputs = torch.cat(outputs, dim=1)  # (batch, trg_len, output_vocab_size)
        return outputs

# Приклад
model_att = Seq2SeqWithAttention(5000, 3000, embed_dim=128, hidden_dim=256)
src = torch.randint(0, 5000, (2, 6))
trg = torch.randint(0, 3000, (2, 4))
logits = model_att(src, trg)
print(f"Вихід з attention: {logits.shape}")
print(f"Параметри: {sum(p.numel() for p in model_att.parameters()):,}")
```

## Query, Key, Value (Q/K/V) формалізм

Сучасне подання attention використовує термінологію **Query-Key-Value**:

- **Query** (:math-formula{tex="Q" inline}) — "що я шукаю?" (стан decoder :math-formula{tex="s_t" inline})
- **Key** (:math-formula{tex="K" inline}) — "що я маю?" (стани encoder :math-formula{tex="h_1, \ldots, h_n" inline})
- **Value** (:math-formula{tex="V" inline}) — "що я хочу отримати?" (теж :math-formula{tex="h_1, \ldots, h_n" inline}, але може бути трансформоване)

### Attention як lookup (пошук у словнику)

Уявіть словник:

```python
{
  "apple": "яблуко",
  "book": "книга",
  "cat": "кіт"
}
```

Коли ви шукаєте "apple" (query), ви порівнюєте його з ключами ("apple", "book", "cat") і отримуєте відповідне значення "яблуко".

Attention працює схожим чином, але **м'яко** (soft):

1. **Query** :math-formula{tex="q" inline} порівнюється з усіма **keys** :math-formula{tex="k_1, \ldots, k_n" inline}
2. Обчислюються **схожості** (scores): :math-formula{tex="e_i = q^T k_i" inline}
3. Нормалізація: :math-formula{tex="\alpha_i = \text{softmax}(e_i)" inline}
4. Вихід — зважена сума **values**: :math-formula{tex="\sum_i \alpha_i v_i" inline}

![Query-Key-Value](/images/16.ai-python/16.natural-language-processing/14.seq2seq-attention/qkv-illustration.png)

### Формула attention (загальний вигляд)

::math-formula{tex="\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{Q K^T}{\sqrt{d_k}}\right) V"}
::

де:
- :math-formula{tex="Q \in \mathbb{R}^{m \times d_k}" inline} — queries (m запитів)
- :math-formula{tex="K \in \mathbb{R}^{n \times d_k}" inline} — keys (n ключів)
- :math-formula{tex="V \in \mathbb{R}^{n \times d_v}" inline} — values (n значень)
- :math-formula{tex="d_k" inline} — розмірність ключів

**Результат**: :math-formula{tex="\mathbb{R}^{m \times d_v}" inline} — для кожного query отримуємо зважену суму values.

::jupyter-notebook
```python
import torch

def attention_qkv(Q, K, V):
    """
    Scaled dot-product attention
    """
    d_k = K.size(-1)
    
    # Scores: Q @ K^T
    scores = torch.matmul(Q, K.transpose(-2, -1)) / (d_k ** 0.5)
    
    # Attention weights
    alpha = torch.softmax(scores, dim=-1)
    
    # Weighted sum of values
    output = torch.matmul(alpha, V)
    
    return output, alpha

# Приклад
batch_size = 2
m = 3  # кількість queries (наприклад, 3 токени decoder)
n = 5  # кількість keys/values (наприклад, 5 токенів encoder)
d_k = 64
d_v = 64

Q = torch.randn(batch_size, m, d_k)
K = torch.randn(batch_size, n, d_k)
V = torch.randn(batch_size, n, d_v)

output, alpha = attention_qkv(Q, K, V)

print(f"Q: {Q.shape}")
print(f"K: {K.shape}")
print(f"V: {V.shape}")
print(f"Output: {output.shape}")
print(f"Attention weights alpha: {alpha.shape}")
print(f"Приклад alpha[0] (перший батч, перший query):")
print(alpha[0, 0])
print(f"Сума: {alpha[0, 0].sum()}")
```

::callout{type="info" title="Q/K/V у seq2seq"}
У класичному seq2seq з attention:

- **Query** = decoder state :math-formula{tex="s_t" inline}
- **Key** = encoder outputs :math-formula{tex="h_1, \ldots, h_n" inline}
- **Value** = encoder outputs :math-formula{tex="h_1, \ldots, h_n" inline} (ті самі)

У наступній лекції (Transformer) ми побачимо **self-attention**, де Q, K, V походять з **одного джерела**.

## Переваги Attention

| Проблема базового seq2seq | Як attention розв'язує |
|---------------------------|------------------------|
| **Bottleneck**: вся інформація в одному векторі :math-formula{tex="c" inline} | Decoder має доступ до **всіх** :math-formula{tex="h_i" inline} |
| **Довгі послідовності**: забування початку | Attention може "дивитися" на будь-який токен входу |
| **Вирівнювання** (alignment) невідоме | Attention weights показують вирівнювання автоматично |

**Емпіричні результати** (Bahdanau et al., 2015):

- На перекладі англійська→французька: **+5 BLEU** проти базового seq2seq
- Особливо великий виграш на **довгих реченнях** (>30 токенів)

:::accordion-item{title="Завдання 2: Реалізація Dot-Product Attention (★★☆)"}

Реалізуйте простий dot-product attention (без масштабування) і порівняйте з additive.

**Розв'язок**:

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class DotProductAttention(nn.Module):
    def forward(self, s, h_encoder):
        # s: (batch, hidden_dim)
        # h_encoder: (batch, src_len, hidden_dim)
        
        # Scores: s @ h_i^T для кожного i
        scores = torch.bmm(h_encoder, s.unsqueeze(2)).squeeze(2)
        # scores: (batch, src_len)
        
        # Attention weights
        alpha = F.softmax(scores, dim=1)
        
        # Context vector
        c_t = torch.bmm(alpha.unsqueeze(1), h_encoder).squeeze(1)
        
        return c_t, alpha

# Порівняння
dot_attn = DotProductAttention()
add_attn = AttentionLayer(hidden_dim=128)

s = torch.randn(2, 128)
h = torch.randn(2, 6, 128)

c_dot, alpha_dot = dot_attn(s, h)
c_add, alpha_add = add_attn(s, h)

print("Dot-product attention weights:", alpha_dot[0])
print("Additive attention weights:", alpha_add[0])
print(f"\nКореляція між alpha_dot і alpha_add: {torch.corrcoef(torch.stack([alpha_dot[0], alpha_add[0]]))[0, 1]:.3f}")
```

**Очікуваний результат**: Обидва методи дають схожі, але не ідентичні weights. Additive attention більш гнучкий (має навчальні параметри).

:::accordion-item{title="Завдання 3: Навчання Seq2Seq з Attention (★★★)"}

Навчіть просту модель seq2seq з attention на задачі "reverse sequence" (інвертування послідовності).

**Задача**: [1, 2, 3, 4] → [4, 3, 2, 1]

**Розв'язок** (скорочений):

```python
import torch
import torch.nn as nn
import torch.optim as optim

# Генеруємо датасет
def generate_data(num_samples=1000, seq_len=5, vocab_size=10):
    data = []
    for _ in range(num_samples):
        seq = torch.randint(1, vocab_size, (seq_len,))  # 0 зарезервовано для padding
        reversed_seq = seq.flip(0)
        data.append((seq, reversed_seq))
    return data

# Модель (використовуємо Seq2SeqWithAttention з вище)
model = Seq2SeqWithAttention(input_vocab_size=10, output_vocab_size=10, 
                              embed_dim=32, hidden_dim=64)
criterion = nn.CrossEntropyLoss()
optimizer = optim.Adam(model.parameters(), lr=0.001)

# Навчання
data = generate_data(num_samples=500, seq_len=6)
model.train()

for epoch in range(50):
    total_loss = 0
    for src, trg in data:
        src = src.unsqueeze(0)  # (1, seq_len)
        trg = trg.unsqueeze(0)
        
        optimizer.zero_grad()
        output = model(src, trg)  # (1, seq_len, vocab_size)
        
        loss = criterion(output.view(-1, 10), trg.view(-1))
        loss.backward()
        optimizer.step()
        
        total_loss += loss.item()
    
    if (epoch + 1) % 10 == 0:
        print(f"Epoch {epoch+1}, Loss: {total_loss/len(data):.4f}")

# Тестування
model.eval()
test_seq = torch.tensor([[1, 2, 3, 4, 5, 6]])
with torch.no_grad():
    output = model(test_seq, test_seq)  # На inference використовуємо greedy decoding
    pred = output.argmax(dim=-1)
print(f"Вхід: {test_seq[0].tolist()}")
print(f"Передбачення: {pred[0].tolist()}")
print(f"Очікується: {test_seq[0].flip(0).tolist()}")
```

**Очікуваний результат**: Після 50 епох модель має правильно інвертувати послідовності.

## Підсумок

::grid{cols=2}
  ::card{icon="lucide:arrow-left-right"}
  **Sequence-to-Sequence**
  
  Encoder-decoder архітектура для генерації послідовностей. Encoder кодує вхід в контекстний вектор :math-formula{tex="c" inline}, decoder генерує вихід крок за кроком.
  ::

  ::card{icon="lucide:focus"}
  **Attention Mechanism**
  
  Розв'язує проблему bottleneck: замість одного :math-formula{tex="c" inline}, decoder має доступ до **всіх** :math-formula{tex="h_i" inline} з encoder. На кожному кроці обчислюється зважена сума :math-formula{tex="c_t = \sum \alpha_{t,i} h_i" inline}.
  ::

  ::card{icon="lucide:key"}
  **Query-Key-Value**
  
  Сучасна формалізація attention: Query (що шукаємо), Key (з чим порівнюємо), Value (що отримуємо). Формула: :math-formula{tex="\text{Attention}(Q,K,V) = \text{softmax}(QK^T)V" inline}.
  ::

  ::card{icon="lucide:trending-up"}
  **Переваги**
  
  - **+5 BLEU** на машинному перекладі
  - Працює на **довгих послідовностях**
  - Attention weights показують **вирівнювання** (interpretability)
  ::
