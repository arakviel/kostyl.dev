::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Seq2seq (sequence-to-sequence):** модель, що перетворює одну послідовність на іншу, можливо іншої довжини.
- **Енкодер і декодер (encoder, decoder):** перший читає вхід у вектори, другий по одному слову генерує вихід.
- **Вузьке місце (bottleneck):** вектор фіксованого розміру, до якого енкодер стискає все речення.
- **Увага (attention):** зважена сума станів енкодера; ваги залежать від того, що зараз генерує декодер.
- **Query, Key, Value:** запит, ключі й значення; ключі порівнюються із запитом, а з значень складається відповідь.

## Від класифікації до генерації

У лекціях 12–13 рекурентна мережа читала відгук і видавала одну відповідь: «позитивний» або «негативний». Для перекладу, анотацій і відповідей на питання вихід — це теж послідовність, і її довжина не збігається з довжиною входу: речення «I am a student» (чотири слова) перекладається як «Я студент» (два).

Такі задачі називають **seq2seq**. Стандартна схема складається з двох рекурентних мереж.

## Encoder-decoder

**Енкодер** читає вхідне речення слово за словом, як у лекції 12. Його останній прихований стан — **контекстний вектор** :math-formula{tex="c" inline} — вважається стислим змістом усього речення.

**Декодер** отримує :math-formula{tex="c" inline} як початковий стан і генерує вихід по одному слову. Першим входом є службовий токен `<bos>` (*beginning of sequence*). На кожному кроці декодер видає розподіл імовірностей над словником, вибране слово стає входом наступного кроку, а генерація зупиняється, коли з'являється `<eos>` (*end of sequence*).

![Енкодер читає I am a student і стискає речення в контекст-вектор c; декодер по одному слову генерує Я, студент, eos](/images/ai-python/natural-language-processing/seq2seq-attention/01-encoder-decoder.png){.diagram-img}

Під час навчання й генерації декодер працює по-різному:

- **Навчання (teacher forcing).** На вхід кожного кроку подають **правильне** попереднє слово з навчального прикладу, незалежно від того, що модель передбачила. Це стабілізує навчання, бо одна помилка не руйнує решту речення.
- **Генерація (inference).** Правильних слів немає, тому на вхід йде **власне попереднє передбачення** моделі. Помилка на одному кроці впливає на всі наступні.

## Задача для експерименту: розвернути послідовність

Для чесної перевірки потрібна задача, у якій відома правильна відповідь і яку не можна розв'язати, дивлячись лише на кілька слів. Розворот послідовності цим вимогам відповідає: щоб вивести перший символ виходу, треба знати **останній** символ входу, а останній символ виходу вимагає **першого**. Модель має запам'ятати весь вхід. Дані генеруються випадково, тому нічого завантажувати не потрібно: дев'ять символів (позначимо їх цифрами від 0 до 8), довжина від 3 до 24.

## Вузьке місце

Побудуємо дві моделі: звичайну encoder-decoder (декодер стартує зі стану енкодера) і модель з увагою (її кроки описано нижче). Обидві мають GRU із 64 нейронами. Код цілком:

::jupyter-notebook{title="seq2seq_reverse.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="1"}

```python
import random, time
import torch, torch.nn as nn, torch.nn.functional as F

V, H, MAXL = 12, 64, 24          # 0 — pad, 1 — bos, 2 — eos, 3…11 — символи
PAD, BOS, EOS = 0, 1, 2

def make_batch(n, lo=3, hi=MAXL):
    seqs = [[random.randint(3, 11) for _ in range(random.randint(lo, hi))] for _ in range(n)]
    L = max(map(len, seqs))
    src = torch.zeros(n, L, dtype=torch.long)
    tgt = torch.zeros(n, L + 1, dtype=torch.long)
    for i, s in enumerate(seqs):
        src[i, :len(s)] = torch.tensor(s)
        tgt[i, :len(s) + 1] = torch.tensor(s[::-1] + [EOS])    # ціль — розвернута послідовність
    return src, tgt

class Seq2Seq(nn.Module):
    def __init__(self, attention):
        super().__init__()
        self.attention = attention
        self.emb_src = nn.Embedding(V, 32, padding_idx=PAD)
        self.emb_tgt = nn.Embedding(V, 32, padding_idx=PAD)
        self.encoder = nn.GRU(32, H, batch_first=True)
        self.decoder = nn.GRUCell(32 + (H if attention else 0), H)
        self.out = nn.Linear(H + (H if attention else 0), V)

    def start_state(self, enc_out, mask):
        # декодер стартує зі стану енкодера на останньому справжньому слові
        lengths = mask.sum(1)
        return enc_out[torch.arange(len(enc_out)), lengths - 1]

    def step(self, token, h, enc_out, mask):
        if not self.attention:
            h = self.decoder(self.emb_tgt(token), h)
            return self.out(h), h, None
        scores = (enc_out @ h.unsqueeze(-1)).squeeze(-1) / H ** 0.5   # запит · ключі
        scores = scores.masked_fill(~mask, -1e9)                      # pad не читаємо
        weights = F.softmax(scores, dim=-1)
        context = (weights.unsqueeze(-1) * enc_out).sum(1)            # Σ αᵢ·hᵢ
        h = self.decoder(torch.cat([self.emb_tgt(token), context], dim=1), h)
        return self.out(torch.cat([h, context], dim=1)), h, weights

    def forward(self, src, tgt):                       # навчання з teacher forcing
        enc_out, _ = self.encoder(self.emb_src(src))
        mask = src != PAD
        h = self.start_state(enc_out, mask)
        token = torch.full((len(src),), BOS)
        logits = []
        for t in range(tgt.size(1)):
            step_logits, h, _ = self.step(token, h, enc_out, mask)
            logits.append(step_logits)
            token = tgt[:, t]                          # на вхід — правильне слово
        return torch.stack(logits, dim=1)

    @torch.no_grad()
    def generate(self, src):                           # inference: власні передбачення
        enc_out, _ = self.encoder(self.emb_src(src))
        mask = src != PAD
        h = self.start_state(enc_out, mask)
        token = torch.full((len(src),), BOS)
        tokens, attn = [], []
        for _ in range(src.size(1) + 1):
            step_logits, h, w = self.step(token, h, enc_out, mask)
            token = step_logits.argmax(-1)
            tokens.append(token)
            attn.append(w)
        return torch.stack(tokens, 1), (torch.stack(attn, 1) if self.attention else None)
```

::jupyter-cell{executionCount="2"}

```python
def train(attention, steps=3000):
    model = Seq2Seq(attention)
    opt = torch.optim.Adam(model.parameters(), lr=3e-3)
    t0 = time.time()
    for step in range(steps):
        src, tgt = make_batch(64)
        loss = F.cross_entropy(model(src, tgt).reshape(-1, V), tgt.reshape(-1), ignore_index=PAD)
        opt.zero_grad(); loss.backward()
        nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        opt.step()
        if step % 1000 == 0 or step == steps - 1:
            print(f"  крок {step:4d}: loss {loss.item():.3f}")
    print(f"  параметрів: {sum(p.numel() for p in model.parameters()):,}, час: {time.time() - t0:.0f} с")
    return model

def exact_match(model, lo, hi, n=500):
    """Частка прикладів, відтворених без жодної помилки."""
    random.seed(123)
    src, tgt = make_batch(n, lo, hi)
    pred, _ = model.generate(src)
    ok = 0
    for i in range(n):
        gold = tgt[i][tgt[i] != PAD].tolist()
        p = pred[i].tolist()
        p = p[:p.index(EOS) + 1] if EOS in p else p
        ok += p == gold
    return ok / n

torch.manual_seed(0); random.seed(0)
results = {}
for attention in (False, True):
    print("з увагою" if attention else "без уваги")
    model = train(attention)
    results[attention] = {f"{lo}-{hi}": exact_match(model, lo, hi)
                          for lo, hi in [(3, 6), (7, 12), (13, 18), (19, 24)]}

print()
print("довжина  без уваги  з увагою")
for key in results[False]:
    print(f"{key:>7}  {results[False][key]:>8.1%}  {results[True][key]:>8.1%}")
```

## Механізм уваги

Ідея Bahdanau (2014): декодер не мусить обходитися одним вектором, адже енкодер видав стани :math-formula{tex="h_1, \ldots, h_n" inline} для **всіх** слів. На кожному кроці декодер може подивитися на всі стани й узяти з них те, що потрібно *саме зараз*. Для цього виконується чотири дії.

::steps

### Оцінка

Поточний стан декодера :math-formula{tex="s_t" inline} (**запит**) порівнюється з кожним станом енкодера :math-formula{tex="h_i" inline}: :math-formula{tex="e_{t,i} = s_t \cdot h_i / \sqrt{d}" inline}. Чим більше схожі вектори, тим більший скалярний добуток.

### Нормалізація

Оцінки перетворюються на ваги функцією softmax: :math-formula{tex="\alpha_{t,i} = \operatorname{softmax}(e_{t,\cdot})_i" inline}. Усі ваги додатні, їхня сума дорівнює 1.

### Зважена сума

Контекст кроку :math-formula{tex="t" inline} — це стани енкодера, зважені на :math-formula{tex="\alpha" inline}: :math-formula{tex="c_t = \sum_i \alpha_{t,i} h_i" inline}.

### Передбачення

Декодер оновлює стан зі входу та :math-formula{tex="c_t" inline} і видає розподіл над словником. Наступний крок знову порахує свої ваги.

::

Контекст тепер **свій для кожного кроку** й не обмежений одним вектором. Числовий приклад із чотирма словами «I am a student» (стани по три числа взято навмисно простими), де декодер генерує слово про «student»:

::jupyter-notebook{title="attention_by_hand.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="1"}

```python
import torch, torch.nn.functional as F

enc = torch.tensor([[1.0, 0.0, 0.0],    # I
                    [0.0, 1.0, 0.0],    # am
                    [0.5, 0.5, 0.0],    # a
                    [0.0, 0.2, 1.0]])   # student
query = torch.tensor([0.0, 0.3, 1.0])   # стан декодера

scores = enc @ query
weights = F.softmax(scores, dim=0)
context = weights @ enc
print("scores :", scores)
print("weights:", weights.round(decimals=3), "сума =", weights.sum().item())
print("context:", context.round(decimals=3))
```

weights: tensor([0.1560, 0.2110, 0.1820, 0.4510]) сума = 1.0

Запит найбільше схожий на стан слова «student» (скалярний добуток 1,06), тому вага 0,45 — найбільша. Інші слова теж вносять внесок, бо softmax не обнулює ваги, а лише розподіляє їх.

![Крок уваги: стан декодера порівнюється з h₁…h₄, softmax дає ваги 0,16, 0,21, 0,18, 0,45, контекст — зважена сума станів](/images/ai-python/natural-language-processing/seq2seq-attention/03-attention-step.png){.diagram-img}

### Способи оцінювати схожість

| Спосіб | Формула оцінки | Де використовується |
|---|---|---|
| Скалярний добуток (dot-product) | :math-formula{tex="s \cdot h" inline} | Luong, 2015 |
| Масштабований | :math-formula{tex="s \cdot h / \sqrt{d}" inline} | Transformer (наступна лекція) |
| Адитивний | :math-formula{tex="v^\top \tanh(W_1 s + W_2 h)" inline} | Bahdanau, 2014 |

Ділення на :math-formula{tex="\sqrt{d}" inline} зберігає масштаб: у векторах розміру :math-formula{tex="d" inline} скалярний добуток виростає разом із :math-formula{tex="d" inline}, softmax насичується, і майже вся вага опиняється на одному слові. У коді вище таке ділення вже є.

Вихід — точний розворот входу. На першому кроці декодер має вивести останній символ входу (0), і 85% ваги припадає на останню позицію. Далі вага «повзе» від кінця входу до початку: на п'ятому кроці найбільша вага (0,58) стоїть на п'ятій позиції входу (символ 8). Повна карта уваги цього прикладу:

![Карта уваги: рядки — символи виходу, стовпці — символи входу; значні ваги лежать на антидіагоналі](/images/ai-python/natural-language-processing/seq2seq-attention/04-attention-heatmap.png){.diagram-img}

Антидіагональ — це саме розворот: з кожним кроком вага зміщується на одну позицію входу ліворуч. Лінія зсунута приблизно на один крок: рядок першого символу й рядок другого обидва дивляться на кінець входу, бо запит будується зі стану, який уже врахував попередній виведений символ. Модель сама, без підказок про те, що це розворот, навчилася вирівнювати вихід із входом. У машинному перекладі такі карти показують, які слова вихідного речення відповідають яким словам входу; для споріднених мов вони близькі до діагоналі.

::note
Карта уваги корисна для налагодження, але не доводить причинності: вага 0,85 означає лише, що зі стану цього слова взято найбільше. Якщо навчання погане, карта виглядає розмитою, а не охайною.
::

## Query, Key, Value

У нашій моделі стани енкодера виконують дві ролі: за ними **порівнюють** запит (щоб отримати ваги) і з них **беруть** зміст (щоб скласти контекст). Зручно розділити ці ролі. Найближча аналогія — словник у Python, тільки з нечітким пошуком:

- **Query (запит)** — те, що шукаємо: стан декодера.
- **Key (ключ)** — мітка кожного запису, з якою запит порівнюється.
- **Value (значення)** — зміст запису, який повертається.

У звичайному словнику збігається рівно один ключ і повертається одне значення. У механізмі уваги збігаються **усі** ключі, кожен у своєму ступені, а відповідь — зважена сума значень:

::math-formula
\operatorname{Attention}(Q, K, V) = \operatorname{softmax}\!\left(\frac{Q K^\top}{\sqrt{d}}\right) V
::

У моделі вище ключі й значення — це одні й ті самі стани енкодера (`enc_out`), а запит — стан декодера. У Transformer (наступна лекція) запити, ключі й значення обчислюються з вхідних векторів трьома різними матрицями ваг, а запитом стає **будь-яке слово речення**, а не лише декодер.

## Практика

::::accordion

:::accordion-item{label="📋 Завдання 1: що буде без маски pad" icon="i-lucide-clipboard-list"}

У рядку `scores.masked_fill(~mask, -1e9)` pad-позиції отримують дуже малу оцінку. Видаліть цей рядок і повторіть навчання моделі з увагою. Як зміняться ваги й точність на коротких входах?

:::

:::accordion-item{label="✅ Розв'язок 1" icon="i-lucide-check-circle"}

Без маски softmax віддає частину ваги позиціям `<pad>`, де немає змісту: короткі приклади в одному батчі з довгими доповнені нулями. Наскільки це шкодить, показує лише експеримент: порівняйте таблицю точного збігу з результатом із маскою.

```python
# замість рядка з маскою
scores = (enc_out @ h.unsqueeze(-1)).squeeze(-1) / H ** 0.5
weights = F.softmax(scores, dim=-1)
```

:::

:::accordion-item{label="📋 Завдання 2: адитивна увага" icon="i-lucide-clipboard-list"}

Замініть скалярний добуток в оцінці на адитивну формулу Bahdanau :math-formula{tex="v^\top \tanh(W_1 s + W_2 h_i)" inline}.

:::

:::accordion-item{label="✅ Розв'язок 2" icon="i-lucide-check-circle"}

Потрібні три нові шари в конструкторі та інший розрахунок оцінок у `step`:

```python
# у __init__ (для attention=True)
self.W1 = nn.Linear(H, H, bias=False)    # для запиту s
self.W2 = nn.Linear(H, H, bias=False)    # для станів енкодера h_i
self.v = nn.Linear(H, 1, bias=False)

# у step, замість рядка зі скалярним добутком
scores = self.v(torch.tanh(self.W1(h).unsqueeze(1) + self.W2(enc_out))).squeeze(-1)
```

Решта (маска, softmax, контекст) без змін. Параметрів стає більше, ніж у скалярного добутку.

:::

:::accordion-item{label="📋 Завдання 3: прочитайте карту" icon="i-lucide-clipboard-list"}

На карті уваги вище на кроці 9 (`‹eos›`) найбільша вага стоїть на першому символі входу. Чому саме там?

:::

:::accordion-item{label="✅ Розв'язок 3" icon="i-lucide-check-circle"}

Розвернута послідовність закінчується першим символом входу. Перед виведенням `<eos>` запит спирається на стан, який щойно вивів останній символ, тобто перший символ входу, тому вага 0,56 лежить на першій позиції (0,28 — на другій). Це та сама зсунута на крок антидіагональ.

:::

## Підсумок

::card-group

::card{title="✅ Що ми дізналися" icon="i-lucide-check-circle"}

- Seq2seq складається з енкодера (читає вхід) і декодера (генерує вихід); навчається з teacher forcing, а генерує на власних передбаченнях.
- Один контекстний вектор — вузьке місце: точний збіг без уваги падає від 99.8% (3–6 символів) до 0.2% (19–24).
- Увага рахує для кожного кроку свої ваги над усіма станами енкодера; з увагою 87.6% найдовших послідовностей відтворюються точно.
- Карта уваги для розвороту має антидіагональ (зсунуту на крок): модель сама знайшла вирівнювання.
- Attention(Q, K, V) = softmax(QKᵀ/√d)·V: запит порівнюється з ключами, а відповідь складається зі значень.

## Що далі

Модель з увагою все ще містить рекурентні мережі: енкодер читає слова по черзі, тому навчання не розпаралелюється. Наступна лекція викидає рекурентність зовсім і залишає лише увагу. Кожне слово використовує її, щоб дивитися на всі інші слова того самого речення.
