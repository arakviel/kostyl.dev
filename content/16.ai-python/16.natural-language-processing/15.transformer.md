# Transformer — self-attention замість рекурентності

::card-group

::card{title="🎯 Мета лекції" icon="i-lucide-target"}

- Пояснити, чим self-attention відрізняється від уваги в seq2seq.
- Обчислити self-attention вручну й побачити, що рядки матриці ваг сумуються до 1.
- Показати, чому без позиційного кодування модель не бачить порядку слів.
- Скласти блок енкодера: багатоголова увага, залишкові з'єднання, нормалізація, FFN.
- Розрізняти маски (padding і причинну) та три варіанти Transformer: BERT, GPT, T5.

::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Self-attention:** кожне слово речення дивиться на всі слова того самого речення.
- **Multi-head attention:** кілька паралельних голів уваги, кожна зі своїми матрицями Q, K, V.
- **Позиційне кодування (positional encoding):** вектор позиції, який додається до embedding слова.
- **Residual connection і LayerNorm:** додавання входу блоку до його виходу та нормалізація.
- **Причинна маска (causal mask):** забороняє слову дивитися на наступні слова.

## Від уваги між мережами до уваги в самому реченні

У лекції 14 увага з'єднувала декодер із енкодером, а обидва лишалися рекурентними мережами. Це залишає дві проблеми.

- **Послідовність.** Стан :math-formula{tex="h_t" inline} залежить від :math-formula{tex="h_{t-1}" inline}, тому слова неможливо обробляти одночасно. Навчання на довгих текстах повільне.
- **Відстань.** Інформація від першого слова до сотого проходить сто кроків, і навіть вентилі не гарантують, що вона збережеться.

Стаття «Attention Is All You Need» (Vaswani та ін., 2017) прибрала рекурентність і залишила тільки увагу. Кожне слово напряму дивиться на кожне інше за один крок, а всі слова обробляються паралельно.

| | RNN / LSTM | Self-attention |
|---|---|---|
| Кроків між першим і останнім словом | n | 1 |
| Паралельна обробка слів | ні, по черзі | так, одним множенням матриць |
| Пам'ять на матрицю зв'язків | немає | n × n |
| Порядок слів | вбудований у читання | потрібне позиційне кодування |

Остання колонка таблиці — ціна: матриця n × n росте квадратично з довжиною тексту, а порядок слів доведеться додавати окремо.

## Self-attention

Self-attention — це та сама формула з лекції 14, але Q, K і V отримуються з **того самого** набору векторів :math-formula{tex="X" inline} (рядок на слово) трьома різними матрицями ваг:

::math-formula
Q = X W_Q,\quad K = X W_K,\quad V = X W_V,\qquad \operatorname{SelfAttn}(X) = \operatorname{softmax}\!\left(\frac{Q K^\top}{\sqrt{d_k}}\right) V
::

Кожне слово одночасно ставить запит («що мені потрібно знати про контекст?»), пропонує ключ («про що я можу розповісти?») і надає значення («ось мій зміст»).

![Схема self-attention: X множиться на Wq, Wk, Wv; QKᵀ ділиться на корінь з d, softmax дає матрицю A; A·V — вихід](/images/ai-python/natural-language-processing/transformer/02-qkv-flow.png){.diagram-img}

Проробимо це для чотирьох слів із випадковими векторами (розмір 8). Ваги випадкові, тому значення в матриці нічого не означають, але механіка та сама, що в реальній моделі:

::jupyter-notebook{title="self_attention.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="1"}

```python
import torch, math, torch.nn.functional as F

torch.manual_seed(1)
words = ["the", "cat", "sat", "down"]
d = 8
X = torch.randn(4, d)                                  # по одному вектору на слово
Wq, Wk, Wv = (torch.randn(d, d) / math.sqrt(d) for _ in range(3))

Q, K, Val = X @ Wq, X @ Wk, X @ Wv                    # Val, щоб не затерти V — розмір словника
scores = Q @ K.T / math.sqrt(d)                        # (4, 4): кожне слово з кожним
A = F.softmax(scores, dim=-1)                          # рядки — ваги, сума = 1
out = A @ Val                                          # нові вектори слів

print("A:\n", A.round(decimals=2))
print("рядки сумуються до 1:", A.sum(-1))
print("out:", tuple(out.shape))
```

#output
```text
A:
 tensor([[0.1000, 0.5200, 0.3600, 0.0200],
        [0.6000, 0.1900, 0.0900, 0.1300],
        [0.2600, 0.1400, 0.2400, 0.3600],
        [0.1200, 0.3100, 0.5500, 0.0200]])
рядки сумуються до 1: tensor([1.0000, 1.0000, 1.0000, 1.0000])
out: (4, 8)
```

::

::

Рядок `A[i]` показує, як слово `i` розподіляє увагу між усіма словами. Нова форма слова `i` — це суміш значень :math-formula{tex="V" inline} усіх слів із такими вагами. Розмір виходу не змінився (4 × 8): кожне слово лишається вектором, але тепер збагаченим контекстом.

На справжній моделі це можна побачити в готовому вигляді. Модель `bert-base-uncased` має 12 шарів по 12 голів. Для речення «the animal did not cross the street because it was too tired» виберемо голову, у якій слово `it` найсильніше дивиться на `animal`: шар 4, голова 11.

## Багатоголова увага

Одна голова дає один розподіл ваг: слово бачить контекст лише «під одним кутом». Займенникові потрібен антецедент, дієсловам — підмет і додаток, прикметникам — іменник. **Multi-head attention** запускає кілька голів паралельно. Вектор розміру :math-formula{tex="d" inline} ділиться на :math-formula{tex="h" inline} частин по :math-formula{tex="d/h" inline}, кожна голова має власні :math-formula{tex="W_Q, W_K, W_V" inline} і рахує свою увагу; результати склеюються й множаться на :math-formula{tex="W_O" inline}.

У PyTorch це готовий модуль `nn.MultiheadAttention`; для self-attention у нього тричі подається той самий тензор:

::jupyter-notebook{title="multihead.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="2"}

```python
import torch.nn as nn

mha = nn.MultiheadAttention(embed_dim=64, num_heads=4, batch_first=True)
x = torch.randn(2, 10, 64)                             # 2 речення по 10 слів
mha_out, mha_w = mha(x, x, x, average_attn_weights=False)
print("вихід:", tuple(mha_out.shape))
print("ваги уваги:", tuple(mha_w.shape), "(batch, голови, слово, слово)")
print("параметрів:", sum(p.numel() for p in mha.parameters()))
```

#output
```text
вихід: (2, 10, 64)
ваги уваги: (2, 4, 10, 10)
параметрів: 16640
```

::

::

Чотири голови по 16 вимірів рахують чотири незалежні матриці уваги 10 × 10. Кількість параметрів (16 640 = 4 матриці 64 × 64 плюс зсуви) не залежить від числа голів: голови лише по-різному ділять ті самі 64 виміри.

## Позиційне кодування

Self-attention обчислює суму з вагами, а сума не залежить від порядку. Переставимо слова вхідного речення й порівняємо виходи (код продовжує приклад вище):

::jupyter-notebook{title="no_position.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="3"}

```python
perm = [3, 1, 0, 2]                                    # інший порядок тих самих слів
Xp = X[perm]
Qp, Kp, Valp = Xp @ Wq, Xp @ Wk, Xp @ Wv
out_perm = F.softmax(Qp @ Kp.T / math.sqrt(d), -1) @ Valp
print("вихід лише переставився:", torch.allclose(out_perm, out[perm], atol=1e-5))
```

#output
```text
вихід лише переставився: True
```

::

::

Self-attention без додаткових засобів не відрізняє «собака вкусила чоловіка» від «чоловік вкусив собаку»: кожне слово отримає ті самі значення, змінюється лише їхній порядок у виході. Тому до embedding додається вектор позиції (**позиційне кодування**).

Оригінальна стаття використовує синуси й косинуси різних частот:

::math-formula
PE_{(pos,\,2i)} = \sin\!\left(\frac{pos}{10000^{2i/d}}\right), \qquad PE_{(pos,\,2i+1)} = \cos\!\left(\frac{pos}{10000^{2i/d}}\right)
::

Перші виміри змінюються швидко (період кількох позицій), останні повільно, тож кожна позиція має унікальний «відбиток», і зсув на фіксовану кількість позицій виражається лінійним перетворенням.

![Теплова карта позиційного кодування: 50 позицій × 64 виміри, швидкі хвилі зліва, повільні справа](/images/ai-python/natural-language-processing/transformer/03-positional-encoding.png){.diagram-img}

Альтернатива — навчані вектори позицій (як у BERT і GPT): окрема таблиця embedding за номером позиції. Вони не вимагають формули, але не працюють за межами довжини, на якій навчалися.

## Блок енкодера

Один шар енкодера складається з чотирьох частин:

1. **Multi-head self-attention** — слова обмінюються інформацією.
2. **Add & Norm** — до виходу додається вхід (*residual connection*), потім застосовується **LayerNorm**, нормалізація кожного вектора. Залишкове з'єднання дає градієнту пряму дорогу назад, як у LSTM шлях через cell state, а нормалізація стабілізує навчання.
3. **Feed-forward (FFN)** — два лінійні шари з нелінійністю між ними, що застосовуються до кожного слова **окремо**. Зазвичай середній шар у 4 рази ширший: :math-formula{tex="d \to 4d \to d" inline} (у нашому прикладі нижче для економії взято 128 = 2d). Увага змішує слова, а FFN обробляє кожне.
4. **Add & Norm** — те саме після FFN.

![Блок енкодера: self-attention, Add & Norm, FFN, Add & Norm із залишковими з'єднаннями; блок повторюється N разів](/images/ai-python/natural-language-processing/transformer/04-encoder-block.png){.diagram-img}

Такий блок повторюється N разів (6 в оригіналі, 12 у BERT-base). Вихід кожного шару — вектори тієї самої форми, тому шари можна складати як завгодно. У PyTorch блок — це `nn.TransformerEncoderLayer`, а його стек — `nn.TransformerEncoder`. Для розміру 64 з чотирма головами та FFN 128 один шар містить 33 472 параметри (з них 16 640 — увага).

## Маски

Матриця уваги «кожне з кожним» не завжди доречна. Використовуються дві маски; обидві працюють однаково: клітинки, які слід заборонити, перед softmax отримують :math-formula{tex="-\infty" inline}, тому після softmax їхня вага дорівнює нулю.

- **Маска padding.** Позиції `<pad>` не мають змісту, і на них не можна дивитися. У `nn.TransformerEncoder` вона передається як `src_key_padding_mask`.
- **Причинна маска (causal mask).** Під час навчання генерації слово `i` не має права бачити слова після `i`, інакше модель просто списуватиме відповідь. Маска залишає лише нижній трикутник.

![Дві матриці уваги для чотирьох слів: звичайна (енкодер) і з нульовим верхнім трикутником (декодер)](/images/ai-python/natural-language-processing/transformer/05-masks.png){.diagram-img}

На правій матриці слово «the» бачить лише себе (1,00), «cat» бачить «the» і себе, а нижній рядок «down» не змінений: він і так є останнім і бачить усе. Рядки як і раніше сумуються до 1, бо softmax виконується вже після маски.

## Три варіанти Transformer

Оригінальна архітектура призначалася для перекладу й мала енкодер і декодер. Згодом із неї взяли окремі половини:

| Варіант | Що береться | Увага | Приклади | Для чого |
|---|---|---|---|---|
| Лише енкодер | енкодер | двонапрямна, без причинної маски | BERT, RoBERTa, DistilBERT | класифікація, пошук, розмітка |
| Лише декодер | декодер | причинна маска | GPT, Claude, Llama | генерація тексту |
| Енкодер + декодер | обидва | двонапрямна в енкодері, причинна в декодері, cross-attention між ними | оригінальний Transformer, T5 | переклад, анотації |

Cross-attention у третьому варіанті — це механізм із лекції 14: запити беруться з декодера, ключі й значення з енкодера. Сучасні великі мовні моделі (ChatGPT та інші) — це «лише декодер», навчений передбачати наступне слово.

## Transformer на IMDB

Зберемо найменший варіант для класифікації відгуків: embedding, позиційне кодування, два шари `nn.TransformerEncoder` (4 голови, розмір 64) та усереднення виходів по справжніх словах. Дані й функція `fit` — із лекції 12.

::jupyter-notebook{title="transformer_classifier.ipynb" kernel="Python 3.13"}

::jupyter-cell{executionCount="4"}

```python
import math

def positional_encoding(length, d):
    pos = torch.arange(length).unsqueeze(1)
    i = torch.arange(0, d, 2)
    pe = torch.zeros(length, d)
    pe[:, 0::2] = torch.sin(pos / 10000 ** (i / d))
    pe[:, 1::2] = torch.cos(pos / 10000 ** (i / d))
    return pe

class TransformerClassifier(nn.Module):
    def __init__(self, d=64, heads=4, layers=2, use_position=True):
        super().__init__()
        self.use_position = use_position
        self.emb = nn.Embedding(V, d, padding_idx=0)
        self.register_buffer("pos", positional_encoding(MAXLEN, d))
        layer = nn.TransformerEncoderLayer(d, heads, dim_feedforward=128,
                                           dropout=0.1, batch_first=True)
        self.encoder = nn.TransformerEncoder(layer, layers)
        self.fc = nn.Linear(d, 2)

    def forward(self, x, lengths):
        is_pad = x == 0
        h = self.emb(x) * math.sqrt(self.emb.embedding_dim)
        if self.use_position:
            h = h + self.pos[:x.size(1)]
        h = self.encoder(h, src_key_padding_mask=is_pad)
        keep = (~is_pad).float().unsqueeze(-1)                 # усереднюємо лише справжні слова
        return self.fc((h * keep).sum(1) / keep.sum(1).clamp(min=1))

torch.manual_seed(0)
print("== з позиційним кодуванням")
fit(TransformerClassifier(), lr=1e-3)
print("== без позиційного кодування")
fit(TransformerClassifier(use_position=False), lr=1e-3)
```

- **Позиції майже не вплинули:** 78.5% з ними й 78.2% без них. Різниця менша за похибку тесту (близько ±0,6 пункта). Тональність відгуку здебільшого визначається самим набором слів, а не їхнім порядком. Як і в лекції 13, порядок важливіший у задачах перекладу й розмітки.
- **Transformer не обігнав усереднення (84.6%).** Два шари на 10 000 відгуків — замало: модель навчається з нуля й перенавчається вже на третій–п'ятій епосі (accuracy перестає рости, а loss падає). Transformer розкривається на великих даних і з попереднім навчанням. Саме цьому присвячена наступна лекція.
- **Швидкість.** Двошаровий Transformer навчався 97 с, GRU — 55 с: довжина 200 дає матрицю уваги 200 × 200 на кожну голову, а на CPU паралельність майже не допомагає. Виграш проявляється на GPU й на великих обсягах даних.

## Практика

::::accordion

:::accordion-item{label="📋 Завдання 1: розмір матриці уваги" icon="i-lucide-clipboard-list"}

Скільки чисел міститься в матриці ваг уваги для батча з 32 відгуків по 200 слів, якщо в шарі 4 голови? Скільки це в мегабайтах для `float32`?

:::

:::accordion-item{label="✅ Розв'язок 1" icon="i-lucide-check-circle"}

Форма `(32, 4, 200, 200)`: 32 × 4 × 200 × 200 = 5 120 000 чисел. По 4 байти: 20 480 000 байт, близько 20 МБ **на один шар**. При подвоєнні довжини пам'ять зростає вчетверо — через це довгі тексти потребують спеціальних оптимізацій.

:::

:::accordion-item{label="📋 Завдання 2: причинна маска вручну" icon="i-lucide-clipboard-list"}

Додайте до прикладу self-attention причинну маску й переконайтеся, що перший рядок має вигляд `[1, 0, 0, 0]`.

:::

:::accordion-item{label="✅ Розв'язок 2" icon="i-lucide-check-circle"}

Заборонені клітинки перед softmax отримують мінус нескінченність:

```python
mask = torch.tril(torch.ones(4, 4)).bool()             # нижній трикутник
A_causal = F.softmax(scores.masked_fill(~mask, float("-inf")), dim=-1)
print(A_causal.round(decimals=2))
```

Перший рядок буде `[1, 0, 0, 0]`: у першого слова єдиний дозволений сусід — воно саме. Останній рядок збігається з рядком без маски, бо останнє слово бачить усі попередні.

:::

:::accordion-item{label="📋 Завдання 3: позиційне кодування і відстань" icon="i-lucide-clipboard-list"}

Обчисліть скалярні добутки коду позиції 10 з кодами позицій 10, 11, 12, 20 та 40. Як добуток змінюється з відстанню? Що це говорить про кодування?

:::

:::accordion-item{label="✅ Розв'язок 3" icon="i-lucide-check-circle"}

```python
pe = positional_encoding(50, 64)
for j in (10, 11, 12, 20, 40):
    print(j, round((pe[10] @ pe[j]).item(), 2))
```

```text
10 32.0
11 30.92
12 28.3
20 21.05
40 17.07
```

Скалярний добуток кодів позицій 10 і 11 (30,92) більший, ніж позицій 10 і 40 (17,07): чим ближче позиції, тим схожіші їхні коди, і механізм уваги може це використати.

:::

## Підсумок

::card-group

::card{title="✅ Що ми дізналися" icon="i-lucide-check-circle"}

- Self-attention: Q, K, V із одного входу; кожне слово бачить усі слова за один крок; усі слова обробляються одночасно.
- Без позиційного кодування вихід лише переставляється разом зі входом, тобто порядок невидимий.
- Блок енкодера: multi-head attention → Add & Norm → FFN → Add & Norm; 33 472 параметри при d = 64.
- Маска padding закриває `<pad>`, причинна маска закриває наступні слова.
- BERT = енкодер, GPT = декодер, T5 = обидва.
- На 10 000 відгуків IMDB Transformer із нуля дав 78.5%, без позицій 78.2%, і поступився усередненню (84.6%).

::

::card{title="🔧 Практичні навички" icon="i-lucide-wrench"}

- Обчислення self-attention вручну.
- `nn.MultiheadAttention` і `nn.TransformerEncoder`.
- Побудова позиційного кодування й масок.
