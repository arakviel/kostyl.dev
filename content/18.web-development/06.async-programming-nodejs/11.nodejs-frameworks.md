# Порівняння Node.js фреймворків

## Короткий зміст

- Чому не писати на чистому http модулі
- Роль фреймворків (маршрутизація, middleware, валідація)
- **Express.js:** мінімалістичний, найпопулярніший
  - Переваги: простота, величезна спільнота, middleware екосистема
  - Недоліки: повільний, застарілий підхід, callback-based
  - Use case: прототипи, малі проєкти
- **Fastify:** швидкий, сучасний
  - Переваги: висока продуктивність, JSON Schema валідація, async/await
  - Недоліки: менша екосистема плагінів
  - Use case: high-load API
- **Koa.js:** від творців Express, модерніший
  - Переваги: async/await, мінімалізм, middleware через context
  - Недоліки: потребує більше налаштувань, менше готових рішень
  - Use case: кастомні рішення
- **Hapi.js:** корпоративний, конфігураційний
  - Переваги: вбудована валідація (Joi), безпека, плагіни
  - Недоліки: складність для простих задач, verbose
  - Use case: enterprise проєкти
- **NestJS:** Angular-подібний, TypeScript-first
  - Переваги: архітектура (modules, DI), scaffolding, підходить для великих проєктів
  - Недоліки: крива навчання, більш громіздкий
  - Use case: масштабні застосунки, команди
- Порівняльна таблиця (продуктивність, екосистема, складність)
- Benchmarks: req/sec для різних фреймворків
- Коли що обирати залежно від проєкту
