# Синхронізація з ефектами: хук `useEffect` та функції очищення

> 🔗 **Офіційний референс:** [Синхронізація з ефектами (Synchronizing with Effects)](https://uk.react.dev/learn/synchronizing-with-effects)

::card-group

::card{title="🎯 Мета лекції" icon="i-lucide-target"}

- Зрозуміти різницю між рендерінгом UI та побічними ефектами.
- Опанувати синтаксис хука `useEffect` та його три форми з різними масивами залежностей.
- Навчитися писати функції очищення для запобігання витокам пам'яті.
- Застосувати TypeScript для безпечної типізації асинхронних ефектів та підписок.

::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Ефект (_Effect_):** побічна дія, що синхронізує компонент із зовнішньою системою (API, таймер, браузерна подія).
- **Функція очищення (_Cleanup Function_):** функція, яку повертає ефект для скасування підписок, таймерів та з'єднань.
- **Масив залежностей (_Dependency Array_):** список реактивних значень, при зміні яких ефект перезапускається.
- **Strict Mode:** режим розробки React, що навмисно подвійно викликає ефекти для виявлення проблем очищення.

## Рендеринг проти побічних ефектів: фундаментальна різниця

До цього моменту ми працювали виключно з **чистою логікою рендерингу**: компоненти приймали пропси, обчислювали стан і повертали JSX-розмітку. Це була математично передбачувана система: одні й ті самі вхідні дані завжди давали однаковий результат без жодних змін зовнішнього світу.

Проте реальні застосунки повинні взаємодіяти з речами за межами React:

- Завантажувати дані з мережевого API.
- Підключатися до WebSocket-серверів для отримання оновлень у реальному часі.
- Змінювати заголовок документа `document.title`.
- Відстежувати події браузера (`scroll`, `resize`, `keydown`).
- Інтегруватися з картографічними бібліотеками, відеоплеєрами, графічними canvas.

Усі ці операції є **побічними ефектами** (_side effects_) — діями, що змінюють щось за межами обчислення розмітки. У React є чітке правило: **побічні ефекти не повинні виконуватися під час рендерингу**. Замість цього вони ізолюються у спеціальний хук `useEffect`, який виконується **після** того, як зміни вже застосовані до DOM.

::note
Назва `useEffect` часто вводить початківців в оману — здається, що це «хук для всього підряд». Насправді його точніше назвати **«хуком синхронізації з зовнішніми системами»** (_synchronization hook_). Якщо ваш код не виходить за межі React (наприклад, просто обчислює похідні дані з `state`), `useEffect` не потрібен.
::

## Анатомія `useEffect`: синтаксис та три форми масиву залежностей

Хук `useEffect` приймає два аргументи:

1. **Функцію ефекту (_setup function_)** — код, що виконає побічну дію.
2. **Масив залежностей (_dependency array_)** — список реактивних значень, при зміні яких ефект перезапускається.

Загальна сигнатура у TypeScript:

```tsx
useEffect(
  () => {
    // Код побічної дії (setup)
    return () => {
      // Опціональна функція очищення (cleanup)
    };
  },
  [dep1, dep2, ...] // Масив залежностей
);
```

Існує три фундаментальні форми `useEffect` залежно від масиву залежностей:

| Форма                              | Коли виконується            | Приклад використання                       |
| :--------------------------------- | :-------------------------- | :----------------------------------------- |
| `useEffect(() => { ... })`         | **Після кожного рендеру**   | Журналювання кожної зміни (рідко потрібно) |
| `useEffect(() => { ... }, [])`     | **Один раз при монтуванні** | Початкове завантаження даних, підписки     |
| `useEffect(() => { ... }, [a, b])` | **При зміні `a` або `b`**   | Синхронізація з prop/state                 |

::warning
Відсутність масиву залежностей (`useEffect(() => {...})` без другого аргументу) створює ефект, що виконується після **кожного** рендеру. Це призводить до каскадних оновлень та зациклень. Завжди явно вказуйте масив залежностей, навіть якщо він порожній.
::

## Перший ефект: змінюємо заголовок документа

Почнемо з найпростішого прикладу — зміни заголовка браузерної вкладки залежно від стану компонента:

```tsx
import { useState, useEffect } from 'react'

export function DocumentTitleExample() {
    const [count, setCount] = useState<number>(0)

    // Ефект синхронізує заголовок документа зі станом count
    useEffect(() => {
        document.title = `Ви натиснули ${count} разів`
    }, [count]) // Перезапускається щоразу, коли count змінюється

    return (
        <div>
            <p>Відкрийте заголовок вкладки браузера — він змінюється!</p>
            <p>Поточне значення: {count}</p>
            <button onClick={() => setCount(count + 1)}>+1</button>
            <button onClick={() => setCount(0)}>Скинути</button>
        </div>
    )
}
```

**Що тут відбувається:**

1. React рендерить компонент і оновлює DOM.
2. Браузер малює зміни на екрані (користувач бачить нове значення `count`).
3. **Після малювання** React викликає функцію ефекту, яка змінює `document.title`.
4. Коли `count` змінюється знову, React повторює цикл.

Ключовий момент: ефект виконується **асинхронно після рендерингу**, а не під час нього. Це гарантує, що користувач миттєво бачить оновлений інтерфейс, навіть якщо побічна дія займає час.

## Ефект із порожнім масивом залежностей: виконання один раз при монтуванні

Якщо передати порожній масив `[]` як другий аргумент, ефект виконається лише один раз — коли компонент вперше з'явиться на екрані. Це ідеально для:

- Початкового завантаження даних з API.
- Підписки на глобальні події (`window.resize`, `document.keydown`).
- Ініціалізації сторонніх бібліотек (карти, відеоплеєри).

```tsx
import { useState, useEffect } from 'react'

interface User {
    id: number
    name: string
    email: string
}

export function UserProfileLoader() {
    const [user, setUser] = useState<User | null>(null)
    const [isLoading, setIsLoading] = useState<boolean>(true)

    useEffect(() => {
        // Симулюємо мережевий запит
        const fetchUser = async () => {
            setIsLoading(true)
            // У реальному застосунку тут був би fetch('/api/user')
            await new Promise((resolve) => setTimeout(resolve, 1000))

            setUser({
                id: 1,
                name: 'Олександра Петренко',
                email: 'oleksandra@example.com',
            })
            setIsLoading(false)
        }

        fetchUser()
    }, []) // Порожній масив: виконується лише при монтуванні

    if (isLoading) {
        return <p>Завантаження профілю...</p>
    }

    if (!user) {
        return <p>Помилка завантаження даних</p>
    }

    return (
        <div>
            <h3>{user.name}</h3>
            <p>{user.email}</p>
        </div>
    )
}
```

::tip
Порожній масив залежностей `[]` означає «жодне реактивне значення не впливає на цей ефект». React виконає його один раз після першого рендеру і більше ніколи не торкнеться, доки компонент існує на екрані.
::

## Функція очищення: запобігання витокам пам'яті та завислим підпискам

Багато побічних ефектів створюють ресурси, які потрібно звільнити: таймери, мережеві з'єднання, підписки на події, інтервали. Якщо не очистити їх належним чином, виникають **витоки пам'яті** (_memory leaks_) — застосунок споживає все більше ресурсів, поки не сповільниться або не зависне.

Функція очищення (_cleanup function_) — це функція, яку ви **повертаєте** з ефекту. React викликає її у двох випадках:

1. **Перед повторним виконанням ефекту** (коли залежності змінилися).
2. **При остаточному розмонтуванні компонента** (видаленні з DOM).

### Приклад: таймер із автоматичним очищенням

Створимо секундомір, що оновлюється кожну секунду:

```tsx
import { useState, useEffect } from 'react'

export function LiveClock() {
    const [time, setTime] = useState<Date>(new Date())

    useEffect(() => {
        console.log('⏰ Запуск таймера')

        // Створюємо інтервал, що оновлює час кожну секунду
        const intervalId = setInterval(() => {
            setTime(new Date())
        }, 1000)

        // Функція очищення: зупиняємо інтервал
        return () => {
            console.log('🛑 Очищення таймера')
            clearInterval(intervalId)
        }
    }, []) // Порожній масив: створюємо інтервал лише один раз

    return (
        <div>
            <h3>Поточний час</h3>
            <p style={{ fontSize: '2rem', fontWeight: 'bold' }}>{time.toLocaleTimeString('uk-UA')}</p>
        </div>
    )
}
```

**Що відбувається при схованні компонента:**

1. Користувач натискає кнопку «Сховати годинник».
2. React видаляє компонент `LiveClock` з DOM (розмонтування).
3. **Перед розмонтуванням** React викликає функцію очищення: `clearInterval(intervalId)`.
4. Таймер зупиняється — більше не викликається `setTime` на неіснуючому компоненті.

::warning
Якщо забути написати функцію очищення, `setInterval` продовжуватиме працювати навіть після видалення компонента. Це призведе до спроб оновлення стану на розмонтованому компоненті — React видасть попередження у консолі: **"Can't perform a React state update on an unmounted component"**.

## Strict Mode та подвійне виконання ефектів у розробці

У файлі `main.tsx` (або `index.tsx`) ваш застосунок, ймовірно, обгорнутий у `<React.StrictMode>`:

```tsx
import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'
import App from './App'

createRoot(document.getElementById('root')!).render(
    <StrictMode>
        <App />
    </StrictMode>,
)
```

У режимі розробки (_development_) Strict Mode навмисно викликає кожен ефект **двічі поспіль**:

1. **Перший цикл:** `mount` → виконується ефект → `cleanup` → `unmount`
2. **Другий цикл:** `mount` → виконується ефект знову

Це схоже на те, ніби React швидко схований і показав компонент заново. Мета — виявити помилки, коли ваша функція очищення не нейтралізує побічну дію належним чином.

::note
**Чому це важливо:**
У реальному застосунку користувач може перейти на іншу сторінку (компонент розмонтується), потім повернутися назад (компонент змонтується знову). Якщо ваш ефект не має коректної функції очищення, при повторному монтуванні створяться дублюючі підписки, таймери або з'єднання.

Strict Mode симулює цю ситуацію під час розробки, щоб ви виявили проблему одразу, а не коли застосунок уже працює у продакшні.
::

Якщо у консолі ви бачите повідомлення `⏰ Запуск таймера` двічі поспіль — це нормально і відбувається лише в development. У production-збірці подвійне виконання автоматично відключається.

## Підписка на події браузера: відстеження розміру вікна

Коли компонент повинен реагувати на події, що відбуваються за межами React (прокручування, зміна розміру вікна, натискання клавіш), використовується підписка через `addEventListener`. Обов'язково видаляйте слухача у функції очищення через `removeEventListener`.

```tsx
import { useState, useEffect } from 'react'

interface WindowSize {
    width: number
    height: number
}

export function WindowSizeTracker() {
    const [windowSize, setWindowSize] = useState<WindowSize>({
        width: window.innerWidth,
        height: window.innerHeight,
    })

    useEffect(() => {
        const handleResize = (): void => {
            setWindowSize({
                width: window.innerWidth,
                height: window.innerHeight,
            })
        }

        // Підписуємося на подію зміни розміру вікна
        window.addEventListener('resize', handleResize)

        // Функція очищення: видаляємо слухача
        return () => {
            window.removeEventListener('resize', handleResize)
        }
    }, []) // Порожній масив: підписка створюється один раз

    return (
        <div>
            <h3>Розмір вікна браузера</h3>
            <p>Ширина: {windowSize.width}px</p>
```

## Асинхронні ефекти: завантаження даних із мережі

Однією з найпоширеніших задач `useEffect` є завантаження даних із API. Проте тут виникає підступна проблема: **функція ефекту не може бути `async`**. Це обмеження React — ефект повинен повертати або `undefined`, або функцію очищення, а не Promise.

Рішення: оголосити асинхронну функцію всередині ефекту та викликати її одразу.

```tsx
import { useState, useEffect } from 'react'

interface Post {
    id: number
    title: string
    body: string
}

export function PostLoader({ postId }: { postId: number }) {
    const [post, setPost] = useState<Post | null>(null)
    const [isLoading, setIsLoading] = useState<boolean>(true)
    const [error, setError] = useState<string | null>(null)

    useEffect(() => {
        // Оголошуємо async функцію всередині ефекту
        const fetchPost = async (): Promise<void> => {
            setIsLoading(true)
            setError(null)

            try {
                const response = await fetch(`https://jsonplaceholder.typicode.com/posts/${postId}`)

                if (!response.ok) {
                    throw new Error(`HTTP помилка: ${response.status}`)
                }

                const data: Post = await response.json()
                setPost(data)
            } catch (err) {
                setError(err instanceof Error ? err.message : 'Невідома помилка')
            } finally {
                setIsLoading(false)
            }
        }

        // Викликаємо функцію одразу
        fetchPost()
    }, [postId]) // Перезавантажуємо дані при зміні postId

    if (isLoading) {
        return <p>Завантаження публікації...</p>
    }

    if (error) {
        return <p style={{ color: '#ef4444' }}>Помилка: {error}</p>
    }

    if (!post) {
        return <p>Публікацію не знайдено</p>
    }

    return (
        <article>
            <h3>{post.title}</h3>
            <p>{post.body}</p>
        </article>
    )
}
```

```tsx
useEffect(() => {
    let ignore = false // Прапорець скасування

    const fetchPost = async () => {
        // ... виконуємо запит ...
        if (!ignore) {
            setPost(data) // Оновлюємо стан лише якщо не скасовано
        }
    }

    fetchPost()

    return () => {
        ignore = true // При зміні postId скасовуємо попередній запит
    }
}, [postId])
```

## Ефект із залежностями: синхронізація зі станом та пропсами

Коли ефект повинен перезапускатися у відповідь на зміну конкретних реактивних значень (стану або пропсів), ці значення вказуються у масиві залежностей. React порівнює їх із попередніми значеннями за допомогою `Object.is()` і перезапускає ефект, якщо хоча б одне змінилося.

```tsx
import { useState, useEffect } from 'react'

export function SearchLogger({ query }: { query: string }) {
    const [searchCount, setSearchCount] = useState<number>(0)

    useEffect(() => {
        if (query.trim() !== '') {
            console.log(`Пошуковий запит: "${query}"`)
            setSearchCount((prev) => prev + 1)
        }
    }, [query]) // Ефект залежить від пропса query

    return (
        <div>
            <p>
                Поточний запит: <strong>{query || '(порожньо)'}</strong>
            </p>
            <p>Кількість пошуків: {searchCount}</p>
        </div>
    )
}

export function SearchDemo() {
    const [inputValue, setInputValue] = useState<string>('')

    return (
        <div>
            <input
                type="text"
                value={inputValue}
                onChange={(e) => setInputValue(e.target.value)}
                placeholder="Введіть пошуковий запит..."
            />
            <SearchLogger query={inputValue} />
        </div>
    )
}
```

Кожного разу, коли значення `query` змінюється, React:

1. Викликає функцію очищення попереднього ефекту (якщо вона існує).
2. Виконує нову версію ефекту з актуальним значенням `query`.

::tip
**Коли додавати значення у залежності:**
Якщо ефект читає будь-яке реактивне значення (проп, стан або змінну, обчислену з них), це значення **обов'язково** має бути у масиві залежностей. Лінтер ESLint із правилом `react-hooks/exhaustive-deps` допоможе виявити забуті залежності автоматично.
::

## Типові помилки та антипатерни `useEffect`

### 1. Забута функція очищення для таймерів

```tsx
// ❌ Погано: інтервал ніколи не зупиняється
useEffect(() => {
    setInterval(() => {
        console.log('Tick')
    }, 1000)
}, [])

// ✅ Правильно: інтервал очищається при розмонтуванні
useEffect(() => {
    const id = setInterval(() => {
        console.log('Tick')
    }, 1000)

    return () => clearInterval(id)
}, [])
```

### 2. Відсутність масиву залежностей

```tsx
// ❌ Погано: ефект виконується після кожного рендеру
useEffect(() => {
    fetchData()
}) // Масив залежностей відсутній!

// ✅ Правильно: явно вказуємо порожній масив або залежності
useEffect(() => {
    fetchData()
}, [])
```

### 3. Неправильна залежність: об'єкт або масив

```tsx
// ❌ Погано: новий об'єкт створюється при кожному рендері
const options = { page: 1, limit: 10 }

useEffect(() => {
    fetchData(options)
}, [options]) // options — це щоразу новий об'єкт!

// ✅ Правильно: передавайте примітивні значення або useMemo
useEffect(() => {
    fetchData({ page: 1, limit: 10 })
}, []) // Або витягніть page і limit окремо у залежності
```

### 4. Async функція як тіло ефекту

```tsx
// ❌ Погано: useEffect не може повертати Promise
useEffect(async () => {
    const data = await fetchData()
    setData(data)
}, [])

// ✅ Правильно: оголосіть async функцію всередині
useEffect(() => {
    const loadData = async () => {
        const data = await fetchData()
        setData(data)
    }

    loadData()
}, [])
```

```tsx
import { useState, useEffect } from 'react'

export function OnlineStatus() {
    const [isOnline, setIsOnline] = useState<boolean>(navigator.onLine)

    useEffect(() => {
        const handleOnline = (): void => {
            setIsOnline(true)
        }

        const handleOffline = (): void => {
            setIsOnline(false)
        }

        window.addEventListener('online', handleOnline)
        window.addEventListener('offline', handleOffline)

        // Функція очищення: видаляємо обидва слухачі
        return () => {
            window.removeEventListener('online', handleOnline)
            window.removeEventListener('offline', handleOffline)
        }
    }, []) // Порожній масив: підписка створюється один раз

    return (
        <div
            style={{
                padding: '16px',
                borderRadius: '8px',
                backgroundColor: isOnline ? '#dcfce7' : '#fee2e2',
                color: isOnline ? '#166534' : '#991b1b',
                textAlign: 'center',
                fontWeight: '600',
            }}
        >
            <span
                style={{
                    display: 'inline-block',
                    width: '12px',
```

2. **Підписка на події:** `window.addEventListener` додає слухачів для подій `online` та `offline`, які спрацьовують при зміні мережевого стану.
3. **Оновлення стану:** Коли браузер виявляє зміну з'єднання, викликається відповідний обробник, що оновлює `isOnline`.

Створіть компонент `CountdownTimer`, який приймає проп `seconds` (початкова кількість секунд) і відраховує час до нуля. Коли таймер досягає нуля, покажіть повідомлення «Час вийшов!» і зупиніть відлік.

**Вимоги:**

- Використовуйте `setInterval` для зменшення лічильника кожну секунду.
- Зупиніть інтервал, коли лічильник досягне `0`.
- При зміні пропса `seconds` таймер має перезапуститися з новим значенням.
- Обов'язково очистіть інтервал у функції cleanup.

**Інтерфейс компонента:**

```tsx
interface CountdownTimerProps {
    seconds: number
}
```

:::

:::accordion-item{label="✅ Розв'язок завдання 2" icon="i-lucide-check-circle"}

```tsx
import { useState, useEffect } from 'react'

interface CountdownTimerProps {
    seconds: number
}

export function CountdownTimer({ seconds }: CountdownTimerProps) {
    const [timeLeft, setTimeLeft] = useState<number>(seconds)

    useEffect(() => {
        // Скидаємо таймер при зміні пропса seconds
        setTimeLeft(seconds)

        // Якщо час уже вийшов, не створюємо інтервал
        if (seconds <= 0) {
            return
        }

        const intervalId = setInterval(() => {
            setTimeLeft((prev) => {
                // Якщо лічильник досяг 1, наступний крок — 0, зупиняємо інтервал
                if (prev <= 1) {
                    clearInterval(intervalId)
                    return 0
                }
                return prev - 1
            })
        }, 1000)

        // Функція очищення: зупиняємо інтервал при розмонтуванні або зміні seconds
        return () => {
            clearInterval(intervalId)
        }
    }, [seconds]) // Перезапускаємо ефект при зміні початкового значення

    if (timeLeft === 0) {
        return (
            <div
                style={{
                    padding: '24px',
                    borderRadius: '12px',
                    background: '#fef3c7',
                    color: '#92400e',
                    textAlign: 'center',
                    fontSize: '20px',
                    fontWeight: '700',
                }}
            >
                ⏰ Час вийшов!
            </div>
        )
    }

    return (
        <div
            style={{
                padding: '24px',
                borderRadius: '12px',
                background: '#dbeafe',
                color: '#1e40af',
                textAlign: 'center',
            }}
        >
            <div style={{ fontSize: '48px', fontWeight: '700', marginBottom: '8px' }}>{timeLeft}</div>
            <div style={{ fontSize: '14px', color: '#64748b' }}>секунд до завершення</div>
        </div>
    )
}

// Приклад використання з кнопкою перезапуску
export function CountdownDemo() {
    const [duration, setDuration] = useState<number>(10)

    return (
        <div>
            <CountdownTimer seconds={duration} />
            <button
                onClick={() => setDuration(10)}
                style={{
                    marginTop: '16px',
                    padding: '10px 20px',
                    border: 'none',
                    borderRadius: '8px',
                    background: '#3b82f6',
                    color: 'white',
                    fontWeight: '600',
                    cursor: 'pointer',
                }}
            >
                Перезапустити
            </button>
        </div>
    )
}
```

**Покрокове пояснення:**

1. **Ініціалізація:** `timeLeft` отримує початкове значення з пропса `seconds`.
2. **Ефект із залежністю:** При зміні `seconds` ефект перезапускається, скидаючи таймер до нового значення.
3. **Функціональне оновлення:** `setTimeLeft((prev) => prev - 1)` гарантує, що ми завжди працюємо з найсвіжішим значенням лічильника.
4. **Умовна зупинка:** Коли `prev <= 1`, викликається `clearInterval(intervalId)` усередині колбека, зупиняючи відлік.
5. **Очищення:** Функція cleanup запускається при розмонтуванні або зміні `seconds`, видаляючи старий інтервал перед створенням нового.

::note
Виклик `clearInterval` усередині `setInterval` технічно працює, але елегантніший підхід — використати додатковий `useEffect`, що спостерігає за `timeLeft === 0` і зупиняє інтервал ззовні. Проте для навчальних цілей поточне рішення демонструє важливу концепцію: функція оновлення стану може містити побічну логіку.
::

:::accordion-item{label="📋 Завдання 3: Вимірювання часу перебування на сторінці" icon="i-lucide-clipboard-list"}

Створіть компонент `PageTimer`, який вимірює, скільки секунд користувач провів на поточній сторінці. Лічильник має починатися при монтуванні компонента і оновлюватися кожну секунду. При розмонтуванні компонента виведіть у консоль загальний час перебування.

**Вимоги:**

- Використовуйте `setInterval` для оновлення лічильника кожну секунду.
- У функції очищення виведіть `console.log` із загальним часом перебування.
- Формат виводу: `"Користувач провів на сторінці: X секунд"`.

:::

:::accordion-item{label="✅ Розв'язок завдання 3" icon="i-lucide-check-circle"}

```tsx
import { useState, useEffect, useRef } from 'react'

export function PageTimer() {
    const [elapsedSeconds, setElapsedSeconds] = useState<number>(0)
    const startTimeRef = useRef<number>(Date.now())

    useEffect(() => {
        const intervalId = setInterval(() => {
            setElapsedSeconds((prev) => prev + 1)
        }, 1000)

        // Функція очищення: виводимо загальний час у консоль
        return () => {
            clearInterval(intervalId)
            const totalTime = Math.floor((Date.now() - startTimeRef.current) / 1000)
            console.log(`Користувач провів на сторінці: ${totalTime} секунд`)
        }
    }, []) // Порожній масив: ефект створюється один раз

    const formatTime = (seconds: number): string => {
        const mins = Math.floor(seconds / 60)
        const secs = seconds % 60
        return `${mins.toString().padStart(2, '0')}:${secs.toString().padStart(2, '0')}`
    }

    return (
        <div
            style={{
                padding: '20px',
                borderRadius: '12px',
                background: '#f1f5f9',
                textAlign: 'center',
            }}
        >
            <div style={{ fontSize: '14px', color: '#64748b', marginBottom: '8px' }}>Час на сторінці</div>
            <div style={{ fontSize: '36px', fontWeight: '700', color: '#0f172a' }}>{formatTime(elapsedSeconds)}</div>
        </div>
    )
}
```

**Покрокове пояснення:**

1. **Референс стартового часу:** `useRef` зберігає мітку часу монтування компонента без перерендерів.
2. **Інтервал:** Кожну секунду збільшуємо `elapsedSeconds` на `1`.
3. **Функція очищення:** При розмонтуванні обчислюємо точний час через різницю `Date.now() - startTimeRef.current` (це точніше, ніж просто `elapsedSeconds`, оскільки `setInterval` може затримуватися).
4. **Формат часу:** Функція `formatTime` перетворює секунди у формат `MM:SS` для зручності.

::tip
Щоб перевірити виведення у консоль, додайте кнопку, що розмонтовує компонент:

```tsx
const [showTimer, setShowTimer] = useState(true)
return (
    <div>
        {showTimer && <PageTimer />}
        <button onClick={() => setShowTimer(false)}>Сховати таймер</button>
    </div>
)
```

При натисканні у консолі з'явиться повідомлення з точним часом перебування.

## Підсумок: коли та як використовувати `useEffect`

::card-group

::card{title="✅ Використовуйте useEffect для:" icon="i-lucide-check-circle"}

- **Підписок на події:** `window.addEventListener`, WebSocket, тощо.
- **Мережевих запитів:** завантаження даних з API при монтуванні або зміні параметрів.
- **Синхронізації з браузерним API:** `document.title`, `localStorage`, геолокація.
- **Інтеграції сторонніх бібліотек:** ініціалізація карт, графіків, відеоплеєрів.
- **Таймерів та інтервалів:** `setTimeout`, `setInterval`.

::

::card{title="❌ Не використовуйте useEffect для:" icon="i-lucide-x-circle"}

- **Трансформації даних для рендерингу:** обчислюйте похідні значення прямо під час рендеру або через `useMemo`.
- **Обробки подій користувача:** мережеві запити та зміни стану належать до обробників подій (`onClick`, `onSubmit`).
- **Ініціалізації стану:** використовуйте ліниву ініціалізацію `useState(() => computeInitial())`.
- **Сповіщення батьківського компонента:** викликайте колбеки з пропсів безпосередньо в обробниках подій.

::

::

::note
**Золоте правило `useEffect`:**
Якщо ваш код не виходить за межі React (не торкається DOM, мережі, таймерів або сторонніх бібліотек), швидше за все, вам не потрібен `useEffect`. Спочатку спробуйте вирішити задачу через звичайну логіку рендерингу.
::

## Довідкова таблиця: три форми `useEffect`

| Синтаксис                          | Коли виконується setup                  | Коли виконується cleanup                                                 | Приклад використання                   |
| :--------------------------------- | :-------------------------------------- | :----------------------------------------------------------------------- | :------------------------------------- |
| `useEffect(() => { ... })`         | Після кожного рендеру                   | Перед кожним повторним виконанням і при розмонтуванні                    | Журналювання змін (рідко потрібно)     |
| `useEffect(() => { ... }, [])`     | Один раз при монтуванні                 | Один раз при розмонтуванні                                               | Початкове завантаження даних, підписки |
| `useEffect(() => { ... }, [a, b])` | При монтуванні та при зміні `a` або `b` | Перед повторним виконанням (із попередніми `a`, `b`) і при розмонтуванні | Синхронізація з пропсами/станом        |

::warning
**Завжди вказуйте масив залежностей явно:**
Відсутність другого аргументу (`useEffect(() => {...})`) створює ефект, що запускається після кожного рендеру, включаючи ті, які спричинені самим ефектом. Це призводить до нескінченних циклів оновлення.

Використовуйте лінтер `eslint-plugin-react-hooks` із правилом `exhaustive-deps`, щоб автоматично виявляти забуті залежності.
::
