## React Router як бібліотека vs фреймворк

React Router v7 підтримує **два режими роботи**:

::steps

### Режим фреймворку (Framework Mode)

Повноцінний full-stack фреймворк із:
- Серверним рендерингом (SSR)
- Завантаженням даних на сервері (Server Loaders)
- Серверними діями (Server Actions)
- Автоматичним code-splitting
- Вбудованою збіркою та деплоєм

Цей режим конкурує з Next.js та Remix (насправді, React Router v7 — це еволюція Remix).

### Режим бібліотеки (Library Mode) — наш фокус

Класична клієнтська бібліотека маршрутизації для **існуючих React-застосунків**:
- Працює виключно на клієнті (без SSR)
- Інтегрується з будь-яким збирачем (Vite, Webpack, Parcel)
- Не нав'язує структуру проєкту
- Сумісна з будь-яким бекендом (REST API, GraphQL, WebSocket)

::

::note
**У цьому курсі ми вивчаємо React Router виключно як бібліотеку**, оскільки це найпоширеніший сценарій використання: клієнтський SPA-застосунок, що взаємодіє з незалежним бекенд-API. Режим фреймворку виходить за межі курсу.
::

## Перший крок: обгортання у BrowserRouter

`BrowserRouter` — це кореневий компонент React Router, що використовує **History API браузера** (методи `pushState`, `replaceState`, подія `popstate`) для синхронізації UI з URL без перезавантаження сторінки.

```tsx
// src/main.tsx
import React from "react";
import ReactDOM from "react-dom/client";
import { BrowserRouter } from "react-router";
import App from "./App";
import "./index.css";

ReactDOM.createRoot(document.getElementById("root")!).render(
  <React.StrictMode>
    <BrowserRouter>
      <App />
    </BrowserRouter>
  </React.StrictMode>
);
```

::note
**Чому саме у `main.tsx`, а не у `App.tsx`?**

`BrowserRouter` створює контекст маршрутизації, доступний для всіх дочірніх компонентів через React Context. Розміщення на найвищому рівні гарантує, що весь застосунок має доступ до хуків маршрутизації (`useNavigate`, `useParams`, `useLocation` тощо).
::

::warning
**Частая помилка:** обгортання `<App>` у `<BrowserRouter>` всередині самого компонента `App`. Це призведе до того, що хуки маршрутизації не працюватимуть поза компонентом `App`.

✅ **Правильно:** `<BrowserRouter>` у `main.tsx` на найвищому рівні.  
❌ **Неправильно:** `<BrowserRouter>` всередині `App.tsx`.
::

## Другий крок: визначення маршрутів

Тепер визначимо базові маршрути через компоненти `<Routes>` та `<Route>`.

```tsx
// src/App.tsx
import { Routes, Route } from "react-router";

function HomePage() {
  return (
    <div>
      <h1>Головна сторінка</h1>
      <p>Ласкаво просимо до нашого застосунку!</p>
    </div>
  );
}

function AboutPage() {
  return (
    <div>
      <h1>Про нас</h1>
      <p>Ми команда розробників, що створюють чудові SPA.</p>
    </div>
  );
}

function ContactPage() {
  return (
    <div>
      <h1>Контакти</h1>
      <p>Email: contact@example.com</p>
    </div>
  );
}

function App() {
  return (
    <Routes>
      <Route path="/" element={<HomePage />} />
      <Route path="/about" element={<AboutPage />} />
      <Route path="/contact" element={<ContactPage />} />
    </Routes>
  );
}

export default App;
```

::note
**Анатомія `<Route>`:**

- **`path`** — URL-шлях, що відповідає цьому маршруту (наприклад, `/`, `/about`, `/users/:id`).
- **`element`** — React-компонент, що рендериться, коли URL збігається з `path`.

React Router автоматично вибирає найбільш відповідний маршрут на основі поточного URL. Якщо URL `/about`, рендериться `<AboutPage />`.
::

## Третій крок: навігація через Link

Щоб переходити між сторінками без перезавантаження, використовуємо компонент `<Link>`:

```tsx
// src/App.tsx
import { Routes, Route, Link } from "react-router";

function Navigation() {
  return (
    <nav style={{ padding: "1rem", borderBottom: "1px solid #ccc" }}>
      <Link to="/" style={{ marginRight: "1rem" }}>
        Головна
      </Link>
      <Link to="/about" style={{ marginRight: "1rem" }}>
        Про нас
      </Link>
      <Link to="/contact">Контакти</Link>
    </nav>
  );
}

function HomePage() {
  return (
    <div>
      <h1>Головна сторінка</h1>
      <p>Ласкаво просимо до нашого застосунку!</p>
    </div>
  );
}

function AboutPage() {
  return (
    <div>
      <h1>Про нас</h1>
      <p>Ми команда розробників, що створюють чудові SPA.</p>
    </div>
  );
}

function ContactPage() {
  return (
    <div>
      <h1>Контакти</h1>
      <p>Email: contact@example.com</p>
    </div>
  );
}

function App() {
  return (
    <>
      <Navigation />
      <main style={{ padding: "1rem" }}>
        <Routes>
          <Route path="/" element={<HomePage />} />
          <Route path="/about" element={<AboutPage />} />
          <Route path="/contact" element={<ContactPage />} />
        </Routes>
      </main>
    </>
  );
}

export default App;
```

::tip
**Різниця між `<Link>` та `<a>`:**

- `<a href="/about">` — викликає **повне перезавантаження сторінки**, втрачається весь стан React, відбувається новий запит до сервера.
- `<Link to="/about">` — **клієнтська навігація**: React Router перехоплює клік, змінює URL через History API, React перерендерює компонент без перезавантаження сторінки.

Завжди використовуйте `<Link>` для внутрішньої навігації у SPA.
::

## Альтернативний синтаксис: Data Router API через `createBrowserRouter`

React Router v7 пропонує **два способи** визначення маршрутів:

1. **JSX-синтаксис** (який ми щойно розглянули) — через компоненти `<Routes>` та `<Route>`
2. **Об'єктний синтаксис** — через функцію `createBrowserRouter` та масив об'єктів маршрутів

Другий підхід називається **Data Router API** і надає додаткові можливості:

::steps

### Переваги Data Router API

- **Data Loaders** — завантаження даних до рендерингу компонента
- **Actions** — обробка форм на рівні маршруту
- **Error Boundaries** — обробка помилок на рівні маршруту
- **Lazy Loading** — динамічне завантаження компонентів
- **Централізована конфігурація** — всі маршрути в одному місці

### Базовий приклад з createBrowserRouter

```tsx
// src/main.tsx
import React from "react";
import ReactDOM from "react-dom/client";
import { createBrowserRouter, RouterProvider } from "react-router";
import "./index.css";

// Компоненти сторінок
function HomePage() {
  return (
    <div>
      <h1>Головна сторінка</h1>
      <p>Ласкаво просимо до нашого застосунку!</p>
    </div>
  );
}

function AboutPage() {
  return (
    <div>
      <h1>Про нас</h1>
      <p>Ми команда розробників, що створюють чудові SPA.</p>
    </div>
  );
}

function ContactPage() {
  return (
    <div>
      <h1>Контакти</h1>
      <p>Email: contact@example.com</p>
    </div>
  );
}

// Визначення маршрутів через масив об'єктів
const router = createBrowserRouter([
  {
    path: "/",
    element: <HomePage />,
  },
  {
    path: "/about",
    element: <AboutPage />,
  },
  {
    path: "/contact",
    element: <ContactPage />,
  },
]);

// Рендеринг застосунку
ReactDOM.createRoot(document.getElementById("root")!).render(
  <React.StrictMode>
    <RouterProvider router={router} />
  </React.StrictMode>
);
```

::

::note
**Ключові відмінності:**

| JSX-синтаксис (`<Routes>`) | Data Router API (`createBrowserRouter`) |
|---|---|
| `<BrowserRouter>` + `<Routes>` | `createBrowserRouter()` + `<RouterProvider>` |
| Маршрути визначаються в JSX | Маршрути визначаються в масиві об'єктів |
| Навігація та базовий роутинг | Додатково: loaders, actions, errorElement |
| Маршрути можуть бути розподілені по файлах | Централізована конфігурація |

**Який обрати?**
- Для простих SPA без завантаження даних — обидва підходи рівноцінні.
- Для складних застосунків із data fetching, формами, обробкою помилок — Data Router API краще.
::

### Додавання Layout та навігації

```tsx
// src/main.tsx
import React from "react";
import ReactDOM from "react-dom/client";
import { createBrowserRouter, RouterProvider, Link, Outlet } from "react-router";
import "./index.css";

// Layout компонент із навігацією
function RootLayout() {
  return (
    <>
      <nav style={{ padding: "1rem", borderBottom: "1px solid #ccc" }}>
        <Link to="/" style={{ marginRight: "1rem" }}>
          Головна
        </Link>
        <Link to="/about" style={{ marginRight: "1rem" }}>
          Про нас
        </Link>
        <Link to="/contact">Контакти</Link>
      </nav>
      <main style={{ padding: "1rem" }}>
        {/* Тут рендериться активний маршрут */}
        <Outlet />
      </main>
    </>
  );
}

function HomePage() {
  return (
    <div>
      <h1>Головна сторінка</h1>
      <p>Ласкаво просимо до нашого застосунку!</p>
    </div>
  );
}

function AboutPage() {
  return (
    <div>
      <h1>Про нас</h1>
      <p>Ми команда розробників, що створюють чудові SPA.</p>
    </div>
  );
}

function ContactPage() {
  return (
    <div>
      <h1>Контакти</h1>
      <p>Email: contact@example.com</p>
    </div>
  );
}

// Маршрути з Layout
const router = createBrowserRouter([
  {
    path: "/",
    element: <RootLayout />,
    children: [
      {
        index: true, // Еквівалент path: ""
        element: <HomePage />,
      },
      {
        path: "about",
        element: <AboutPage />,
      },
      {
        path: "contact",
        element: <ContactPage />,
      },
    ],
  },
]);

ReactDOM.createRoot(document.getElementById("root")!).render(
  <React.StrictMode>
    <RouterProvider router={router} />
  </React.StrictMode>
);
```

::tip
**Властивість `index: true`** еквівалентна `<Route index element={...} />` у JSX-синтаксисі. Це маршрут за замовчуванням, що рендериться за базового URL батьківського маршруту.
::

### Винесення конфігурації у окремий файл

Для великих застосунків рекомендується винести конфігурацію маршрутів у окремий файл:

```tsx
// src/router.tsx
import { createBrowserRouter } from "react-router";
import RootLayout from "./layouts/RootLayout";
import HomePage from "./pages/HomePage";
import AboutPage from "./pages/AboutPage";
import ContactPage from "./pages/ContactPage";

export const router = createBrowserRouter([
  {
    path: "/",
    element: <RootLayout />,
    children: [
      {
        index: true,
        element: <HomePage />,
      },
      {
        path: "about",
        element: <AboutPage />,
      },
      {
        path: "contact",
        element: <ContactPage />,
      },
    ],
  },
]);
```

```tsx
// src/main.tsx
import React from "react";
import ReactDOM from "react-dom/client";
import { RouterProvider } from "react-router";
import { router } from "./router";
import "./index.css";

ReactDOM.createRoot(document.getElementById("root")!).render(
  <React.StrictMode>
    <RouterProvider router={router} />
  </React.StrictMode>
);
```

::note
**Який синтаксис обрати для курсу?**

У наступних лекціях ми будемо **показувати обидва підходи**: спочатку JSX-синтаксис (оскільки він візуально наочніший для навчання), а потім еквівалент через `createBrowserRouter`.

Це допоможе вам:
- Зрозуміти концепції незалежно від синтаксису
- Вміти читати код в обох стилях
- Обрати підхід, що краще підходить для вашого проєкту
::

## Альтернатива BrowserRouter: HashRouter

Якщо ваш проєкт розгортається на статичному хостингу (GitHub Pages, Netlify) без налаштування серверних редиректів, можна використовувати `HashRouter`.

### JSX-синтаксис

```tsx
import { HashRouter } from "react-router";

ReactDOM.createRoot(document.getElementById("root")!).render(
  <React.StrictMode>
    <HashRouter>
      <App />
    </HashRouter>
  </React.StrictMode>
);
```

### Data Router API

```tsx
import { createHashRouter, RouterProvider } from "react-router";

const router = createHashRouter([
  {
    path: "/",
    element: <HomePage />,
  },
  {
    path: "/about",
    element: <AboutPage />,
  },
]);

ReactDOM.createRoot(document.getElementById("root")!).render(
  <React.StrictMode>
    <RouterProvider router={router} />
  </React.StrictMode>
);
```

`HashRouter` використовує **hash-частину URL** (після `#`):

- `https://example.com/#/about`
- `https://example.com/#/users/123`

::note
**Відмінності:**

| BrowserRouter | HashRouter |
|---|---|
| `/about`, `/users/123` | `/#/about`, `/#/users/123` |
| Потребує серверної конфігурації для SPA | Працює без серверної конфігурації |
| Чистіші URL, краще для SEO | URL містять `#`, гірше для SEO |

**Рекомендація:** використовуйте `BrowserRouter` завжди, коли це можливо. `HashRouter` — лише для обмежених середовищ без доступу до серверної конфігурації.
::

```tsx
      <p>Ми команда розробників, що створюють чудові SPA.</p>
    </div>
  );
}

function ServicesPage() {
  return (
    <div>
      <h1>Наші послуги</h1>
      <ul>
        <li>Веб-розробка</li>
        <li>Мобільні додатки</li>
        <li>Консалтинг</li>
        <li>UI/UX дизайн</li>
      </ul>
    </div>
  );
}

function ContactPage() {
  return (
    <div>
      <h1>Контакти</h1>
      <p>Email: contact@example.com</p>
    </div>
  );
}

function App() {
  return (
    <>
      <Navigation />
      <main style={{ padding: "1rem" }}>
        <Routes>
          <Route path="/" element={<HomePage />} />
          <Route path="/about" element={<AboutPage />} />
          <Route path="/services" element={<ServicesPage />} />
          <Route path="/contact" element={<ContactPage />} />
        </Routes>
      </main>
    </>
  );
}

export default App;
```

**Перевірка:**

1. Запустіть `npm run dev`.
2. Натисніть на посилання "Послуги" — URL зміниться на `/services`, відобразиться список послуг.
3. Натисніть "Назад" у браузері — ви повернетесь на попередню сторінку.
4. Оновіть сторінку на `/services` — якщо dev-сервер Vite налаштований правильно, сторінка завантажиться без 404 (Vite автоматично обробляє це у режимі розробки).
