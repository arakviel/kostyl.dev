## Чому React Router v7?

Односторінкові застосунки (SPA) відображають різний контент залежно від URL **без повного перезавантаження сторінки**. React Router синхронізує URL із компонентами, надаючи:

::steps

### Декларативну маршрутизацію

Замість імперативного `window.location.href = "/about"` описуєте відображення URL на компоненти через JSX:

```tsx
<Routes>
  <Route path="/" element={<HomePage />} />
  <Route path="/about" element={<AboutPage />} />
</Routes>
```

### Вкладені маршрути

Ієрархічна структура маршрутів із спільними Layout-компонентами:

```tsx
<Route path="/dashboard" element={<DashboardLayout />}>
  <Route path="profile" element={<Profile />} />
  <Route path="settings" element={<Settings />} />
</Route>
```

### Динамічні параметри

Один маршрут для тисяч сторінок:

```tsx
<Route path="/users/:userId" element={<UserProfile />} />
```

### Інтеграція з History API

Підтримка кнопок "Назад" та "Вперед" браузера, збереження стану навігації, програмні переходи.

## Режим бібліотеки vs режим фреймворку

React Router v7 підтримує два режими:

| Режим | Призначення | Можливості |
|---|---|---|
| **Library Mode** (наш фокус) | Клієнтська маршрутизація для існуючих React-застосунків | Навігація, параметри URL, вкладені маршрути, ErrorBoundary |
| **Framework Mode** | Full-stack фреймворк (аналог Next.js/Remix) | SSR, Server Loaders, Server Actions, автоматичний code-splitting |

::note
**У цьому курсі ми вивчаємо виключно Library Mode** — клієнтську бібліотеку маршрутизації без серверних можливостей. Це найпоширеніший сценарій для SPA-застосунків із незалежним бекенд-API.
::

## Ключові концепції та патерни

::steps

### Декларативне відображення URL на компоненти

React Router не використовує імперативні виклики (`router.navigate()`). Замість цього визначаєте дерево маршрутів декларативно через JSX, а React Router автоматично обирає відповідний компонент на основі поточного URL.

### Односпрямований потік даних

URL → Маршрут → Компонент → UI. Зміна URL викликає ререндер відповідних компонентів, але компоненти **не змінюють URL напряму** — вони використовують `<Link>` або `useNavigate()` для делегування навігації React Router.

### Композиція через вкладеність

Складні макети будуються через вкладені маршрути замість ручного рендерингу умовних компонентів. Кожен рівень вкладеності додає свій сегмент до URL та свій Layout до UI.

### Типобезпека через TypeScript

Всі хуки React Router підтримують дженерики для типізації параметрів, стану локації та пошукових параметрів. Це забезпечує автодоповнення та перевірку типів на етапі компіляції.

## Порівняння з альтернативами

| Критерій | React Router v7 | TanStack Router | Wouter |
|---|---|---|---|
| **Популярність** | Стандарт де-факто | Швидко зростає | Нішова |
| **Розмір бандлу** | ~10 KB | ~12 KB | ~1.5 KB |
| **TypeScript** | Добра підтримка | Відмінна (type-safe) | Базова |
| **API** | Компоненти + хуки | Об'єктна конфігурація | Мінімалістичний |
| **Data Loading** | Ручний (fetch у компонентах) | Вбудований | Відсутній |
| **Framework Mode** | Так (SSR, RSC) | Ні | Ні |

::tip
**Коли обирати React Router:**

- Найбільша екосистема та комьюніті.
- Велика кількість навчальних матеріалів та прикладів.
- Плавна міграція з попередніх версій (v5 → v6 → v7).
- Можливість еволюціонувати у full-stack фреймворк (Framework Mode) за потреби.

**Коли розглянути TanStack Router:**

- Потреба у type-safe маршрутизації з автоматичним виведенням типів.
- Вбудоване завантаження даних із підтримкою Suspense.
- Проєкт вже використовує інші бібліотеки TanStack (Query, Table).

**Коли використовувати Wouter:**

- Мікросервіси або мікрофронтенди з жорстким обмеженням бандлу.
- Дуже прості застосунки з 3–5 маршрутами.
