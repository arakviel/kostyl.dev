# Серверний стан: RTK Query та TanStack Query

::card-group

::card{title="🎯 Мета теми" icon="i-lucide-target"}

- Зрозуміти різницю між клієнтським та серверним станом.
- Опанувати RTK Query для автоматичного кешування та інвалідації через теги.
- Навчитися використовувати TanStack Query для складних сценаріїв синхронізації.
- Реалізувати оптимістичні оновлення та фонову ревалідацію даних.
- Порівняти підходи та обрати оптимальний інструмент для конкретних задач.

::

::card{title="🔑 Ключові терміни" icon="i-lucide-key"}

- **Server State:** дані, що зберігаються на сервері та синхронізуються з клієнтом (на відміну від client state).
- **Cache Invalidation:** механізм позначення даних як застарілих, що призводить до автоматичного перезапиту.
- **Stale-While-Revalidate:** стратегія кешування, де застарілі дані показуються миттєво, а фоновий запит оновлює їх.
- **Optimistic Updates:** оновлення UI перед отриманням відповіді від сервера для миттєвого відчуття реакції.

::

## Клієнтський vs серверний стан: фундаментальна різниця

Після вивчення Redux та Context API може здатися, що будь-який глобальний стан управляється однаково. Але існує критична різниця між **клієнтським** та **серверним** станом, яка вимагає різних підходів:

::code-group

```tsx [Клієнтський стан — повний контроль]
// Стан, що повністю контролюється клієнтом
interface UIState {
  sidebarOpen: boolean;        // Відкрита/закрита бічна панель
  theme: "light" | "dark";     // Тема інтерфейсу
  currentTab: number;          // Активна вкладка
  modalVisible: boolean;       // Видимість модального вікна
}

// Джерело правди — клієнт
// Ніхто інший не може змінити це
const [sidebarOpen, setSidebarOpen] = useState(false);
```

```tsx [Серверний стан — синхронізація з джерелом]
// Стан, що зберігається на сервері
interface ServerData {
  users: User[];               // Може змінитися іншими користувачами
  posts: Post[];               // Може оновлюватися фоново
  notifications: Notification[]; // Може з'являтися у реальному часі
  profile: UserProfile;        // Може змінитися в іншій вкладці
}

// Джерело правди — сервер
// Клієнт має лише КОПІЮ, яка може застаріти
const { data: users, isStale } = useQuery("users", fetchUsers);
```

::

**Проблеми управління серверним станом через Redux/Context:**

1. **Кешування:** потрібно вручну зберігати дані, щоб уникнути повторних запитів.
2. **Інвалідація:** складно визначити, коли дані застаріли та потребують оновлення.
3. **Дедуплікація:** кілька компонентів можуть одночасно запитувати ті самі дані.
4. **Фонове оновлення:** немає механізму автоматичної синхронізації при поверненні на вкладку.
5. **Оптимістичні оновлення:** складна логіка rollback при помилках сервера.

::tip
**Правило розподілу стану:**
- **Клієнтський стан** → `useState`, `useReducer`, Context API, Redux
- **Серверний стан** → RTK Query, TanStack Query, SWR

Не змішуйте їх у одному сховищі — це призводить до складної логіки синхронізації та багів.
::

## RTK Query: серверний стан у екосистемі Redux

**RTK Query** — це офіційна бібліотека data fetching від команди Redux Toolkit. Вона інтегрується з Redux store, але повністю автоматизує управління серверним станом: кешування, дедуплікацію, фонове оновлення та інвалідацію.

### Встановлення та налаштування

RTK Query вже входить у пакет `@reduxjs/toolkit`:

```bash
# Якщо ви вже встановили RTK — нічого додаткового не потрібно
npm install @reduxjs/toolkit react-redux
```

### Створення API slice через createApi

```tsx
// src/store/api/usersApi.ts
import { createApi, fetchBaseQuery } from "@reduxjs/toolkit/query/react";

export interface User {
  id: number;
  name: string;
  email: string;
  phone: string;
}

export interface CreateUserDTO {
  name: string;
  email: string;
  phone: string;
}

export const usersApi = createApi({
  reducerPath: "usersApi", // Ключ у Redux store

  baseQuery: fetchBaseQuery({
    baseUrl: "https://jsonplaceholder.typicode.com",
    prepareHeaders: (headers) => {
      // Додаємо токен автентифікації до кожного запиту
      const token = localStorage.getItem("authToken");
      if (token) {
        headers.set("Authorization", `Bearer ${token}`);
      }
      return headers;
    },
  }),

  // Теги для інвалідації кешу
  tagTypes: ["User"],

  endpoints: (builder) => ({
    // Query — для отримання даних (GET)
    getUsers: builder.query<User[], void>({
      query: () => "/users",
      // Позначаємо, які теги надає цей запит
      providesTags: (result) =>
        result
          ? [
              ...result.map(({ id }) => ({ type: "User" as const, id })),
              { type: "User", id: "LIST" },
            ]
          : [{ type: "User", id: "LIST" }],
    }),

    getUserById: builder.query<User, number>({
      query: (id) => `/users/${id}`,
      providesTags: (result, error, id) => [{ type: "User", id }],
    }),

    // Mutation — для зміни даних (POST, PUT, PATCH, DELETE)
    createUser: builder.mutation<User, CreateUserDTO>({
      query: (body) => ({
        url: "/users",
        method: "POST",
        body,
      }),
      // Інвалідуємо список після створення
      invalidatesTags: [{ type: "User", id: "LIST" }],
    }),

    updateUser: builder.mutation<User, { id: number; data: Partial<CreateUserDTO> }>({
      query: ({ id, data }) => ({
        url: `/users/${id}`,
        method: "PATCH",
        body: data,
      }),
      // Інвалідуємо конкретного користувача
      invalidatesTags: (result, error, { id }) => [{ type: "User", id }],
    }),

    deleteUser: builder.mutation<void, number>({
      query: (id) => ({
        url: `/users/${id}`,
        method: "DELETE",
      }),
      // Інвалідуємо і конкретного користувача, і список
      invalidatesTags: (result, error, id) => [
        { type: "User", id },
        { type: "User", id: "LIST" },
      ],
    }),
  }),
});

// Автоматично згенеровані хуки — один для кожного endpoint
export const {
  useGetUsersQuery,
  useGetUserByIdQuery,
  useCreateUserMutation,
  useUpdateUserMutation,
  useDeleteUserMutation,
} = usersApi;
```

::note
**Як працює система тегів:**
- `providesTags` — позначає, які дані повертає запит (наприклад, "User з id=5" та "LIST усіх User").
- `invalidatesTags` — позначає, які теги застаріли після мутації.
- RTK Query автоматично перезапускає всі query, що мають інвалідовані теги.

Це елегантне рішення проблеми «коли оновлювати кеш» без ручного відстеження залежностей.
::

### Підключення до Redux store

```tsx
// src/store/index.ts
import { configureStore } from "@reduxjs/toolkit";
import { usersApi } from "./api/usersApi";

export const store = configureStore({
  reducer: {
    // Додаємо RTK Query reducer
    [usersApi.reducerPath]: usersApi.reducer,
    // ...інші звичайні slices
  },

  // Додаємо RTK Query middleware для кешування та синхронізації
  middleware: (getDefaultMiddleware) =>
    getDefaultMiddleware().concat(usersApi.middleware),
});

export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;
```

```tsx
// src/main.tsx
import { Provider } from "react-redux";
import { store } from "./store";
import App from "./App";

ReactDOM.createRoot(document.getElementById("root")!).render(
  <Provider store={store}>
    <App />
  </Provider>
);
```

## Використання RTK Query у компонентах

### Query hooks: автоматичне завантаження даних

```tsx
// src/components/UserList.tsx
import { useGetUsersQuery, useDeleteUserMutation } from "../store/api/usersApi";

function UserList() {
  // Автоматично запускається при монтуванні компонента
  const {
    data: users,
    isLoading,
    isError,
    error,
    isFetching,  // true при фоновому оновленні
    refetch,     // Ручне оновлення
  } = useGetUsersQuery();

  const [deleteUser, { isLoading: isDeleting }] = useDeleteUserMutation();

  if (isLoading) return <p>Початкове завантаження...</p>;
  if (isError) return <p className="error">Помилка: {JSON.stringify(error)}</p>;

  return (
    <div className="user-list">
      <header>
        <h2>Користувачі</h2>
        <button onClick={refetch} disabled={isFetching}>
          {isFetching ? "Оновлення..." : "🔄 Оновити"}
        </button>
      </header>

      <ul>
        {users?.map((user) => (
          <li key={user.id}>
            <span>{user.name}</span>
            <span>{user.email}</span>
            <button
              onClick={() => deleteUser(user.id)}
              disabled={isDeleting}
            >
              Видалити
            </button>
          </li>
        ))}
      </ul>
    </div>
  );
}

export default UserList;
```

::tip
**Різниця між `isLoading` та `isFetching`:**
- `isLoading` — `true` лише при **першому** завантаженні (коли даних ще немає).
- `isFetching` — `true` при **будь-якому** запиті (включаючи фонове оновлення).

Це дозволяє показувати skeleton при першому завантаженні та лише індикатор оновлення при рефрешах.
::

### Mutation hooks: зміна даних з автоматичною інвалідацією

```tsx
// src/components/CreateUserForm.tsx
import { useState } from "react";
import { useCreateUserMutation } from "../store/api/usersApi";

function CreateUserForm() {
  const [formData, setFormData] = useState({ name: "", email: "", phone: "" });
  const [createUser, { isLoading, isSuccess, isError, error }] = useCreateUserMutation();

  async function handleSubmit(e: React.FormEvent) {
    e.preventDefault();

    try {
      await createUser(formData).unwrap(); // .unwrap() кидає помилку при rejected
      setFormData({ name: "", email: "", phone: "" });
      alert("Користувача створено!");
    } catch (err) {
      console.error("Помилка створення:", err);
    }
  }

  return (
    <form onSubmit={handleSubmit}>
      <h2>Новий користувач</h2>

      {isSuccess && <p className="success">✅ Користувача успішно додано!</p>}
      {isError && <p className="error">❌ Помилка: {JSON.stringify(error)}</p>}

      <input
        type="text"
        placeholder="Ім'я"
        value={formData.name}
        onChange={(e) => setFormData({ ...formData, name: e.target.value })}
        required
      />

      <input
        type="email"
        placeholder="Email"
        value={formData.email}
        onChange={(e) => setFormData({ ...formData, email: e.target.value })}
        required
      />

      <input
        type="tel"
        placeholder="Телефон"
        value={formData.phone}
        onChange={(e) => setFormData({ ...formData, phone: e.target.value })}
        required
      />

      <button type="submit" disabled={isLoading}>
        {isLoading ? "Створення..." : "Створити"}
      </button>
    </form>
  );
}

export default CreateUserForm;
```

::note
Після виклику `createUser()` RTK Query автоматично:
1. Відправляє POST-запит на сервер.
2. Інвалідує теги `{ type: "User", id: "LIST" }` (згідно з `invalidatesTags`).
3. Перезапускає всі активні `useGetUsersQuery()` у всіх компонентах.
4. Компоненти з `UserList` автоматично отримують свіжі дані без ручного `refetch()`.
::

### Умовні запити: skip та polling

```tsx
function UserDetail({ userId }: { userId: number | null }) {
  // Запит НЕ виконується, якщо userId === null
  const { data: user, isLoading } = useGetUserByIdQuery(userId!, {
    skip: userId === null, // Умовне пропускання запиту
  });

  if (userId === null) return <p>Виберіть користувача</p>;
  if (isLoading) return <p>Завантаження...</p>;
  if (!user) return <p>Користувача не знайдено</p>;

  return (
    <div className="user-detail">
      <h2>{user.name}</h2>
      <p>Email: {user.email}</p>
      <p>Телефон: {user.phone}</p>
    </div>
  );
}
```

```tsx
function RealtimeNotifications() {
  // Polling — повторний запит кожні 5 секунд
  const { data: notifications } = useGetNotificationsQuery(undefined, {
    pollingInterval: 5000, // мс
  });

  return (
    <div className="notifications">
      <h3>Сповіщення (оновлюються автоматично)</h3>
      <ul>
        {notifications?.map((notif) => (
          <li key={notif.id}>{notif.message}</li>
        ))}
      </ul>
    </div>
  );
}
```

## TanStack Query (React Query): гнучкіша альтернатива

**TanStack Query** (колишня React Query) — це бібліотека серверного стану, яка **не прив'язана до Redux** і надає більше гнучкості у складних сценаріях: пагінація, нескінченний скрол, паралельні запити, оптимістичні оновлення.

### Встановлення

::tabs
::tabs-item{label="npm"}
```bash
npm install @tanstack/react-query
```
::
::tabs-item{label="pnpm"}
```bash
pnpm add @tanstack/react-query
```
::
::

### Налаштування QueryClient

```tsx
// src/main.tsx
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";
import { ReactQueryDevtools } from "@tanstack/react-query-devtools";
import App from "./App";

// Створюємо клієнт з налаштуваннями кешування
const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 1000 * 60 * 5, // 5 хвилин — дані вважаються свіжими
      gcTime: 1000 * 60 * 10,   // 10 хвилин — час зберігання у кеші
      retry: 3,                  // Кількість повторів при помилці
      refetchOnWindowFocus: true, // Оновлення при поверненні на вкладку
    },
  },
});

ReactDOM.createRoot(document.getElementById("root")!).render(
  <QueryClientProvider client={queryClient}>
    <App />
    {/* DevTools для інспекції запитів та кешу */}
    <ReactQueryDevtools initialIsOpen={false} />
  </QueryClientProvider>
);
```

::tip
**Ключові налаштування TanStack Query:**
- `staleTime` — як довго дані вважаються свіжими (не потребують оновлення).
- `gcTime` (garbage collection time) — як довго зберігати неактивні дані у кеші.
- `refetchOnWindowFocus` — автоматично оновлювати дані при поверненні на вкладку браузера.
::

## useQuery: отримання даних з автоматичним кешуванням

```tsx
// src/hooks/useUsers.ts
import { useQuery } from "@tanstack/react-query";
import axios from "axios";

interface User {
  id: number;
  name: string;
  email: string;
}

async function fetchUsers(): Promise<User[]> {
  const { data } = await axios.get("https://jsonplaceholder.typicode.com/users");
  return data;
}

export function useUsers() {
  return useQuery({
    queryKey: ["users"], // Унікальний ключ для кешу
    queryFn: fetchUsers, // Функція завантаження
  });
}
```

```tsx
// src/components/UserList.tsx
import { useUsers } from "../hooks/useUsers";

function UserList() {
  const {
    data: users,
    isLoading,
    isError,
    error,
    isFetching,
    refetch,
  } = useUsers();

  if (isLoading) return <p>Завантаження...</p>;
  if (isError) return <p>Помилка: {error.message}</p>;

  return (
    <div>
      <button onClick={() => refetch()}>
        {isFetching ? "Оновлення..." : "Оновити"}
      </button>

      <ul>
        {users?.map((user) => (
          <li key={user.id}>{user.name}</li>
        ))}
      </ul>
    </div>
  );
}
```

::note
**Query Key** — це масив, який однозначно ідентифікує запит. TanStack Query використовує його для:
- Кешування результатів (різні ключі = різні кеші).
- Інвалідації даних (`queryClient.invalidateQueries(["users"])`).
- Залежних запитів (`["user", userId]` — різний кеш для кожного `userId`).
::

### Динамічні query keys для параметризованих запитів

```tsx
// src/hooks/useUser.ts
import { useQuery } from "@tanstack/react-query";
import axios from "axios";

async function fetchUser(id: number): Promise<User> {
  const { data } = await axios.get(`https://jsonplaceholder.typicode.com/users/${id}`);
  return data;
}

export function useUser(userId: number) {
  return useQuery({
    queryKey: ["user", userId], // Різний кеш для кожного userId
    queryFn: () => fetchUser(userId),
    enabled: userId > 0, // Не виконувати запит, якщо userId невалідний
  });
}
```

```tsx
function UserProfile({ userId }: { userId: number }) {
  const { data: user, isLoading } = useUser(userId);

  if (isLoading) return <p>Завантаження профілю...</p>;
  if (!user) return <p>Користувача не знайдено</p>;

  return (
    <div>
      <h2>{user.name}</h2>
      <p>{user.email}</p>
    </div>
  );
}
```

## useMutation: зміна даних з інвалідацією кешу

```tsx
// src/hooks/useCreateUser.ts
import { useMutation, useQueryClient } from "@tanstack/react-query";
import axios from "axios";

interface CreateUserDTO {
  name: string;
  email: string;
  phone: string;
}

async function createUser(userData: CreateUserDTO): Promise<User> {
  const { data } = await axios.post("https://jsonplaceholder.typicode.com/users", userData);
  return data;
}

export function useCreateUser() {
  const queryClient = useQueryClient();

  return useMutation({
    mutationFn: createUser,

    // Успішне виконання — інвалідуємо кеш списку користувачів
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ["users"] });
    },

    // Можна додати оптимістичне оновлення (розглянемо далі)
  });
}
```

```tsx
// src/components/CreateUserForm.tsx
import { useState } from "react";
import { useCreateUser } from "../hooks/useCreateUser";

function CreateUserForm() {
  const [formData, setFormData] = useState({ name: "", email: "", phone: "" });
  const { mutate, isPending, isSuccess, isError, error } = useCreateUser();

  function handleSubmit(e: React.FormEvent) {
    e.preventDefault();

    mutate(formData, {
      onSuccess: () => {
        setFormData({ name: "", email: "", phone: "" });
        alert("Користувача створено!");
      },
      onError: (err) => {
        console.error("Помилка:", err);
      },
    });
  }

  return (
    <form onSubmit={handleSubmit}>
      <h2>Новий користувач</h2>

      {isSuccess && <p className="success">✅ Створено успішно!</p>}
      {isError && <p className="error">❌ Помилка: {error.message}</p>}

      <input
        type="text"
        placeholder="Ім'я"
        value={formData.name}
        onChange={(e) => setFormData({ ...formData, name: e.target.value })}
      />

      <input
        type="email"
        placeholder="Email"
        value={formData.email}
        onChange={(e) => setFormData({ ...formData, email: e.target.value })}
      />

      <button type="submit" disabled={isPending}>
        {isPending ? "Створення..." : "Створити"}
      </button>
    </form>
  );
}
```

::warning
У TanStack Query v5 `isLoading` у мутаціях перейменовано на `isPending`. Це зроблено для уніфікації термінології та уникнення плутанини з `isLoading` у queries.

## Оптимістичні оновлення: миттєвий відчуття реакції

**Optimistic Updates** — це техніка, коли UI оновлюється **до** отримання відповіді від сервера. Якщо запит успішний — все гаразд. Якщо помилка — зміни відкочуються (*rollback*).

### Оптимістичне видалення у TanStack Query

```tsx
// src/hooks/useDeleteUser.ts
import { useMutation, useQueryClient } from "@tanstack/react-query";
import axios from "axios";

async function deleteUser(id: number): Promise<void> {
  await axios.delete(`https://jsonplaceholder.typicode.com/users/${id}`);
}

export function useDeleteUser() {
  const queryClient = useQueryClient();

  return useMutation({
    mutationFn: deleteUser,

    // Оптимістичне оновлення ПЕРЕД відправкою запиту
    onMutate: async (deletedId) => {
      // 1. Скасовуємо всі фонові запити для користувачів
      await queryClient.cancelQueries({ queryKey: ["users"] });

      // 2. Зберігаємо попередній стан для rollback
      const previousUsers = queryClient.getQueryData<User[]>(["users"]);

      // 3. Оптимістично видаляємо користувача з кешу
      queryClient.setQueryData<User[]>(["users"], (old) =>
        old ? old.filter((user) => user.id !== deletedId) : []
      );

      // Повертаємо контекст для rollback
      return { previousUsers };
    },

    // Rollback при помилці
    onError: (err, deletedId, context) => {
      queryClient.setQueryData(["users"], context?.previousUsers);
      alert("Помилка видалення: " + err.message);
    },

    // Синхронізація з сервером при успіху
    onSettled: () => {
      queryClient.invalidateQueries({ queryKey: ["users"] });
    },
  });
}
```

```tsx
function UserList() {
  const { data: users } = useUsers();
  const { mutate: deleteUser } = useDeleteUser();

  return (
    <ul>
      {users?.map((user) => (
        <li key={user.id}>
          {user.name}
          {/* Користувач зникає МИТТЄВО при кліку */}
          <button onClick={() => deleteUser(user.id)}>Видалити</button>
        </li>
      ))}
    </ul>
  );
}
```

::tip
**Lifecycle оптимістичного оновлення:**
1. `onMutate` — виконується **до** запиту: оновлює UI оптимістично, зберігає snapshot для rollback.
2. Запит відправляється на сервер (користувач бачить миттєвий результат).
3. `onSuccess` або `onError` — обробка результату.
4. `onSettled` — виконується **завжди** (успіх чи помилка): синхронізація з сервером через інвалідацію.
::

### Offset-based пагінація (skip/take)

```tsx
// src/hooks/useUsers.ts

import axios from "axios";

interface PaginatedResponse {
  users: User[];
  total: number;
}

async function fetchUsers(page: number, pageSize: number): Promise<PaginatedResponse> {
  const { data, headers } = await axios.get("https://api.example.com/users", {
    params: {
      _page: page,
      _limit: pageSize,
    },
  });

  return {
    users: data,
    total: parseInt(headers["x-total-count"] || "0", 10),
  };
}

export function useUsersPaginated(page: number, pageSize: number = 10) {
  return useQuery({
    queryKey: ["users", "paginated", page, pageSize],
    queryFn: () => fetchUsers(page, pageSize),
    placeholderData: (previousData) => previousData, // Показуємо старі дані під час завантаження нових
  });
}
```

## RTK Query vs TanStack Query: детальне порівняння

| Критерій                          | RTK Query                                      | TanStack Query                                    |
| --------------------------------- | ---------------------------------------------- | ------------------------------------------------- |
| **Інтеграція з Redux**            | Повна (частина Redux store)                    | Незалежна (власний кеш)                           |
| **Розмір бандлу**                 | ~10 КБ (+ Redux Toolkit)                       | ~12 КБ (без залежностей)                          |
| **Налаштування**                  | Середнє (createApi, endpoints)                 | Легке (QueryClient + хуки)                        |
| **Автоматичні хуки**              | Генеруються для кожного endpoint               | Ручне створення (useQuery, useMutation)           |
| **Інвалідація кешу**              | Теги (providesTags / invalidatesTags)          | Ручна (queryClient.invalidateQueries)             |
| **Оптимістичні оновлення**        | Підтримка через onQueryStarted                 | Вбудована підтримка (onMutate)                    |
| **Нескінченний скрол**            | Потребує ручної реалізації                     | Вбудований useInfiniteQuery                       |
| **Prefetching**                   | Підтримується                                  | Підтримується                                     |
| **WebSocket / SSE**               | Потребує додаткових middleware                 | Інтеграція через custom hooks                     |
| **TypeScript типізація**          | Відмінна (автоматичні типи endpoint)           | Відмінна (generic types для queries/mutations)    |
| **DevTools**                      | Redux DevTools                                 | React Query DevTools (окремий пакет)              |
| **Фонова ревалідація**            | Так (refetchOnMountOrArgChange)                | Так (refetchOnWindowFocus, staleTime)             |
| **Pagination**                    | Ручна реалізація                               | Вбудована підтримка (useInfiniteQuery)            |
| **Коли використовувати**          | Проєкт вже на Redux, багато client state       | Немає Redux, складна пагінація, WebSocket         |

::tip
**Рекомендації вибору:**

**Обирайте RTK Query**, якщо:
- Проєкт вже використовує Redux Toolkit для client state.
- Потрібна єдина екосистема (один DevTools, один store).
- API простий (стандартний REST без складних сценаріїв).

**Обирайте TanStack Query**, якщо:
- Не використовуєте Redux (або плануєте мігрувати з нього).
- Потрібні складні сценарії: нескінченний скрол, WebSocket, GraphQL.
- Критична швидкість розробки (менше boilerplate для endpoint).
::

## Best Practices серверного стану

::card-group

::card{title="✅ Розділяйте client та server state" icon="i-lucide-check-circle"}

Не зберігайте серверні дані у Redux/Context — використовуйте RTK Query або TanStack Query. Залиште Redux для UI-стану (модальні вікна, вкладки, форми).

::

::card{title="✅ Налаштуйте staleTime розумно" icon="i-lucide-check-circle"}

- `staleTime: 0` (за замовчуванням) — дані застарівають миттєво, перезапит при кожному рендері.
- `staleTime: 1000 * 60 * 5` (5 хвилин) — дані залишаються свіжими 5 хвилин.
- Для статичних даних (країни, категорії) — `staleTime: Infinity`.

::

::card{title="✅ Використовуйте точні query keys" icon="i-lucide-check-circle"}

```tsx
// ❌ Погано — конфлікти ключів

// ✅ Добре — чітка ієрархія
```

::card{title="✅ Prefetching для передбачуваних дій" icon="i-lucide-check-circle"}

::card{title="⚠️ Не змішуйте sources of truth" icon="i-lucide-alert-triangle"}

Не дублюйте серверні дані у Redux — це створює проблеми синхронізації. Єдине джерело правди для серверних даних — RTK Query / TanStack Query кеш.

::card{title="⚠️ Обережно з оптимістичними оновленнями" icon="i-lucide-alert-triangle"}

Оптимістичні оновлення ускладнюють логіку. Використовуйте їх лише для критичних UX-моментів (видалення, toggling). Для простих форм достатньо звичайної інвалідації.

## Питання для самоконтролю

::::accordion

:::accordion-item{label="❓ Чому серверний стан не варто зберігати у Redux?" icon="i-lucide-help-circle"}

Серверний стан має **зовнішнє джерело правди** (сервер), яке може змінюватися незалежно від клієнта. Зберігання його у Redux створює кілька проблем:

1. **Складна синхронізація:** потрібно вручну відстежувати, коли дані застаріли та оновлювати їх.
2. **Дедуплікація запитів:** кілька компонентів можуть одночасно запитувати ті самі дані — потрібен механізм об'єднання запитів.
3. **Фонова ревалідація:** при поверненні на вкладку дані можуть бути застарілими — потрібен автоматичний refetch.
4. **Кешування:** потрібно вручну реалізовувати TTL (time-to-live), garbage collection застарілих даних.

RTK Query та TanStack Query вирішують всі ці проблеми автоматично, звільняючи розробника від написання сотень рядків boilerplate-коду.

:::

:::accordion-item{label="❓ Як працює система тегів у RTK Query?" icon="i-lucide-help-circle"}

Система тегів у RTK Query — це механізм **декларативної інвалідації кешу**:

1. **`providesTags`** — позначає, які дані **надає** запит (query).
   - Приклад: `getUsers` надає теги `[{ type: "User", id: "LIST" }, { type: "User", id: 1 }, ...]`.

2. **`invalidatesTags`** — позначає, які теги **застаріли** після мутації.
   - Приклад: `deleteUser(5)` інвалідує теги `[{ type: "User", id: 5 }, { type: "User", id: "LIST" }]`.

3. **Автоматична ревалідація:** RTK Query перезапускає всі активні query, що мають інвалідовані теги.

**Приклад:**
- Компонент A викликає `useGetUsersQuery()` — отримує дані та теги `[User:LIST]`.
- Компонент B викликає `deleteUser(5)` — інвалідує теги `[User:5, User:LIST]`.
- RTK Query бачить, що компонент A має тег `User:LIST` → автоматично перезапускає запит.
- Компонент A отримує свіжі дані без ручного `refetch()`.

:::

:::accordion-item{label="❓ Що таке staleTime та gcTime у TanStack Query?" icon="i-lucide-help-circle"}

**`staleTime`** (*stale — застарілий*) — це час, протягом якого дані вважаються **свіжими** і не потребують оновлення:

- `staleTime: 0` (за замовчуванням) — дані застарівають миттєво. При кожному рендері компонента TanStack Query перевіряє, чи потрібен refetch.
- `staleTime: 1000 * 60 * 5` — дані свіжі 5 хвилин. Протягом цього часу компонент отримує дані з кешу без мережевих запитів.
- `staleTime: Infinity` — дані ніколи не застарівають (для статичних даних: країни, категорії).

**`gcTime`** (*garbage collection time*) — це час, протягом якого **неактивні** дані зберігаються у кеші після того, як останній компонент-споживач розмонтувався:

- `gcTime: 1000 * 60 * 5` (за замовчуванням) — якщо жоден компонент не використовує дані 5 хвилин, вони видаляються з кешу.
- `gcTime: Infinity` — дані ніколи не видаляються (обережно — витік пам'яті у SPA).

**Взаємодія:**
- `staleTime` контролює **коли** потрібен refetch.
- `gcTime` контролює **коли** видалити дані з пам'яті.

:::

```tsx
// src/store/api/postsApi.ts — RTK Query для постів
import { createApi, fetchBaseQuery } from "@reduxjs/toolkit/query/react";

export interface Post {
  id: number;
  title: string;
  body: string;
  userId: number;
}

export const postsApi = createApi({
  reducerPath: "postsApi",
  baseQuery: fetchBaseQuery({
    baseUrl: "https://jsonplaceholder.typicode.com",
  }),
  tagTypes: ["Post"],
  endpoints: (builder) => ({
    getPosts: builder.query<Post[], void>({
      query: () => "/posts?_limit=10",
      providesTags: (result) =>
        result
          ? [
              ...result.map(({ id }) => ({ type: "Post" as const, id })),
              { type: "Post", id: "LIST" },
            ]
          : [{ type: "Post", id: "LIST" }],
    }),

    getPostById: builder.query<Post, number>({
      query: (id) => `/posts/${id}`,
      providesTags: (result, error, id) => [{ type: "Post", id }],
    }),

    createPost: builder.mutation<Post, Omit<Post, "id">>({
      query: (body) => ({
        url: "/posts",
        method: "POST",
        body,
      }),
      invalidatesTags: [{ type: "Post", id: "LIST" }],
    }),

    deletePost: builder.mutation<void, number>({
      query: (id) => ({
        url: `/posts/${id}`,
        method: "DELETE",
      }),
      invalidatesTags: (result, error, id) => [
        { type: "Post", id },
        { type: "Post", id: "LIST" },
      ],
    }),
  }),
});

export const {
  useGetPostsQuery,
  useGetPostByIdQuery,
  useCreatePostMutation,
  useDeletePostMutation,
} = postsApi;
```

```tsx
import axios from "axios";

interface Comment {
  id: number;
  postId: number;
  name: string;
  email: string;
  body: string;
}

async function fetchComments(postId: number): Promise<Comment[]> {
  const { data } = await axios.get(
    `https://jsonplaceholder.typicode.com/posts/${postId}/comments`
  );
  return data;
}

export function useComments(postId: number, enabled: boolean = true) {
  return useQuery({
    queryKey: ["comments", postId],
    queryFn: () => fetchComments(postId),
    enabled, // Завантаження лише якщо пост завантажено
  });
}
```

```tsx
// src/components/PostDetail.tsx
import { useGetPostByIdQuery } from "../store/api/postsApi";
import { useComments } from "../hooks/useComments";

function PostDetail({ postId }: { postId: number }) {
  // RTK Query для поста
  const { data: post, isLoading: postLoading } = useGetPostByIdQuery(postId);

  // TanStack Query для коментарів (залежить від поста)
  const { data: comments, isLoading: commentsLoading } = useComments(postId, !!post);

  if (postLoading) return <p>Завантаження поста...</p>;
  if (!post) return <p>Пост не знайдено</p>;

  return (
    <article className="post-detail">
      <h1>{post.title}</h1>
      <p>{post.body}</p>

      <section className="comments">
        <h2>Коментарі</h2>
        {commentsLoading ? (
          <p>Завантаження коментарів...</p>
        ) : (
          <ul>
            {comments?.map((comment) => (
              <li key={comment.id}>
                <strong>{comment.name}</strong> ({comment.email})
                <p>{comment.body}</p>
              </li>
            ))}
          </ul>
        )}
      </section>
    </article>
  );
}

export default PostDetail;
```

```tsx
// src/components/PostList.tsx
import { useGetPostsQuery, useDeletePostMutation } from "../store/api/postsApi";

function PostList() {
  const { data: posts, isLoading, isFetching } = useGetPostsQuery();
  const [deletePost] = useDeletePostMutation();

  if (isLoading) return <p>Завантаження постів...</p>;

  return (
    <div className="post-list">
      <header>
        <h1>Блог</h1>
        {isFetching && <span className="badge">Оновлення...</span>}
      </header>

      <ul>
        {posts?.map((post) => (
          <li key={post.id}>
            <h3>{post.title}</h3>
            <p>{post.body.substring(0, 100)}...</p>
            <button onClick={() => deletePost(post.id)}>Видалити</button>
          </li>
        ))}
      </ul>
    </div>
  );
}

export default PostList;
```

**Ключові моменти реалізації:**

1. **Гібридний підхід:** RTK Query для основних CRUD-операцій, TanStack Query для складніших сценаріїв (залежні запити, коментарі).
2. **Автоматична інвалідація:** після видалення поста RTK Query автоматично оновлює список.
3. **Залежні запити:** коментарі завантажуються лише якщо пост успішно завантажено (`enabled: !!post`).
4. **Індикація стану:** `isFetching` показує фонове оновлення, `isLoading` — початкове завантаження.
