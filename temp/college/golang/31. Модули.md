## Модули

Последнее обновление: 15.06.2025

Модуль в языке Go представляет коллекцию пакетов, который имеет встроенное версионирование и который можно опубликовать для использования в других проектах. Применение модулей в Go имеет ряд преимуществ:

-   Изоляция зависимостей: Каждый модуль управляет своими зависимостями независимо, что позволяет избежать конфликтов версий между разными проектами на одном компьютере.
    
-   Воспроизводимые сборки: Файлы `go.mod` (файл конфигурации модуля) и `go.sum` (содержит криптографические контрольные суммы для проверки целостности зависимостей), которые входят в состав модуля, гарантируют, что любой, кто клонирует ваш репозиторий, сможет собрать проект с теми же версиями зависимостей, что и у вас.
    
-   Упрощенное управление версиями: Модули позволяют легко указывать минимальные требуемые версии зависимостей, а также использовать псевдонимы для различных версий или даже заменять модули локальными версиями для разработки.
    
-   Децентрализованная разработка: Go может загружать зависимости из различных источников, включая системы контроля версий, таких как GitHub.
    

### Файлы go.mod и go.sum

-   go.mod: Этот файл объявляет путь к модулю, версию Go, используемую в проекте, и список всех зависимостей с их минимальными требуемыми версиями.
    
-   go.sum: Содержит криптографические хеши содержимого всех зависимостей. Это обеспечивает безопасность и воспроизводимость, гарантируя, что загруженные модули не были подделаны.
    

### Основные операции с модулями Go

Рассмотрим основные операции работы с модулями:

-   Инициализация модуля. Чтобы превратить проект (каталог) в модуль, в корневом каталоге проекта надо выполнить команду:
    
    ```
    go mod init [имя_модуля]
    ```
    
    `[имя_модуля]` является произвольным, но обычно соответствует пути к репозиторию для проекта (например, `github.com/имя_пользователя/название_проекта`).
    
-   Добавление зависимостей. При импорте новых пакетов в код программы и запуске команд go build или go test, Go автоматически добавит все необходимые зависимости в файл **go.mod**. Но также можно добавить зависимость вручную с помощью команды:
    
    ```
    go get [путь_к_пакету]@[версия]
    ```
    
-   Удаление неиспользуемых зависимостей. Со временем в вашем go.mod могут накопиться неиспользуемые зависимости. Их можно удалить командой:
    
    ```
    go mod tidy
    ```
    
    Эта команда также добавит недостающие зависимости.
    
-   Обновление зависимостей. Для обновления всех зависимостей до последних минорных или патч-версий (сохраняя мажорную версию), применяется команда:
    
    ```
    go get -u
    ```
    
    Для обновления до конкретной версии:
    
    ```
    go get [путь_к_пакету]@latest
    ```
    

## Создание модуля

Для создания модуля применяется команда go mod init, которой передается имя модуля. Посмотрим на примере. Сначала определим папку, где будет располагаться наш модуль. Пусть, к примеру это будет папка hello. Перейдем в терминале/командной строке к этой папке. Допустим, наш модуль будет называться также, как и папка - hello. Для его создания выполним команду `go mod init hello`:

```
eugene@Eugene:/workspace/go$ cd hello
eugene@Eugene:/workspace/go/hello$ go mod init hello
go: creating new go.mod: module hello
eugene@Eugene:/workspace/go/hello$ 
```

После выполнения этой команды в папке появится файл go.mod - это файл конфигурации проекта/модуля на Go. По умолчанию он будет иметь содержимое типа следующего:

|1
|---|
2
3|`module hello`
`go` `1.24.4`|

Первая строка с директивой module определяет путь к модулю (в нашем случае это название модуля) - "hello". Вторая строка определяет используемую для модуля версию go - в данном случае 1.24.4

Кроме пути к модулю и версии go этот файл может содержать и другую информацию, например, информацию об используемых зависимостях и т.д.

Далее создадим в этой же папке модуля новый файл main.go со следующим кодом:

|1
|---|
2
3
4
5
6
7|`package` `main`
`import` `"fmt"`
`func` `main() {`
    `fmt.Println(``"Hello METANIT.COM"``)`
`}`|

Для запуска проекта мы можем использовать стандартный подход, который применялся для запуска файла на Go - с помощью команды go run:

```
eugene@Eugene:/workspace/go/hello$ go run main.go
Hello METANIT.COM
eugene@Eugene:/workspace/go/hello$ 
```

Однако в случае с модулями мы можем сократить команду запуска - вместо названия скрипта написать точку:

```
eugene@Eugene:/workspace/go/hello$ go run .
Hello METANIT.COM
eugene@Eugene:/workspace/go/hello$ 
```

То же самое касается построения проекта: для построения из модуля исполняемого приложения с помощью команды **go build** вместо названия файлов мы можем точку:

```
eugene@Eugene:/workspace/go/hello$ go build .
```

В итоге создается исполняемый файл, который по умолчанию называется по имени модуля.

### Создание модуля для проекта в Git

Если наш проект будет использовать Git и располагаться где-то во репозитории, то обычно в качестве имени модуля используется URL репозитория. Например:

```
go mod init github.com/your-username/your-project
```

## Несколько файлов в одном пакете модуля

Использование модулей упрощает организацию и управление проектами. Например, если проект состоит из нескольких файлов, то без использования модулей нам надо при компиляции передать все эти файлы крманде запуска/построения проекта. С модулями же нам достаточно указать точку. Например, определим в папке проекта два файла:

-   main.go
    
-   hello.go
    

В файле hello.go для теста определим функцию для вывода сообщения на консоль:

|1
|---|
2
3
4
5
6
7|`package` `main`
`import` `"fmt"`
`func` `say_hello() {`
    `fmt.Println(``"Hello World"``)`
`}`|

Данный файл с определением функции say\_hello принадлежит пакету main, потому что вначале файла мы указали инструкцию `package main`.

В файле main.go используем функцию say\_hello для вывода сообщения на консоль:

|1
|---|
2
3
4
5
6|`package` `main`
`func` `main() {`
    `say_hello()`
`}`|

Данный файл также принадлежит пакету main. Файлов может и быть и больше. Теперь запустим нашу программу из двух файлов. Для этого выполним следующую команду:

```
eugene@Eugene:/workspace/go$ go run .
Hello World
eugene@Eugene:/workspace/go$ 
```
