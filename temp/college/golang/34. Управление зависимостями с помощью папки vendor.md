---
Последнее обновление: 15.06.2025

В Go, как и в любом другом современном языке программирования, существует механизм управления зависимостями — сторонними библиотеками (пакетами), которые используются в вашем проекте. Одним из механизмов управления зависимостями в языке Go является использование папки vendor. Применение этой папки позволяет создавать полностью самодостаточные проекты, изолированные от изменений во внешних репозиториях.

## Зачем нужна папка vendor

Папка `vendor` представляет каталог в корневой папке проекта, в котором хранятся точные копии исходного кода всех зависимостей. Когда вы собираете или запускаете проект, утилита Go (начиная с версии 1.6) в первую очередь ищет необходимые пакеты в этой папке, и только потом в глобальном кеше модулей ($GOPATH/pkg/mod).

Основные преимущества использования `vendor`:

-   Воспроизводимость сборок: проект всегда будет собираться с одними и теми же версиями зависимостей, даже если их авторы внесут изменения или удалят свои репозитории.
    
-   Работа в офлайн-режиме: так как весь необходимый код располагается локально, можно продолжать разработку и сборку проекта без доступа к интернету.
    
-   Контроль и аудит: полный контроль над кодом зависимостей, можно проводить его аудит на безопасность и даже вносить исправления при необходимости.
    
-   Упрощение CI/CD: процессы непрерывной интеграции и развертывания становятся проще и быстрее, так как не требуют скачивания зависимостей из сети на каждом шаге.
    

## Как использовать vendor

Современный и рекомендуемый способ управления зависимостями в Go представляет использование модулей. Они позволяют легко интегрировать механизм работы с каталогом `vendor`. Рассмотрим поэтапно.

### Шаг 1: Инициализация модуля

Сначала создадим где-нибудь в файловой системе для нашего проекта новую папку, которая будет называться, например, "myapp". В консоли перейдем в эту папку и инициализируем в ней Go-модуль с помощью следующей команды:

```
go mod init myapp
```

После этого в текущей папке будет создан файл **go.mod** примерно со следующим содержимым:

|1
|---|
2
3|`module myapp`
`go` `1.24.4`|

### Шаг 2: Добавление зависимостей

Зависимости добавляются в проект как обычно с помощью команды **go get**. Например, добавим в проект библиотеку "rsc.io/quote", которая предназначена для целей тестирования и вывода случайных цитат. Для этого выполним в консоли следующую команду:

```
go get rsc.io/quote
```

Полный консольный вывод:

```
eugene@Eugene:/workspace/go/myapp$ go get rsc.io/quote
go: added golang.org/x/text v0.0.0-20170915032832-14c0d48ead0c
go: added rsc.io/quote v1.5.2
go: added rsc.io/sampler v1.3.0
eugene@Eugene:/workspace/go/myapp$ 
```

После этого в файле `go.mod` появится запись о новой зависимости, и также в папке проекта появится файл `go.sum` с контрольной суммой загруженной библиотеки.

Теперь создадим файл **main.go** в корневой папке проекта и напишем код, который будет использовать пакет `rsc.io/quote`:

Пакеты из внешнего модуля подключаются также, как и другие пакеты с помощью директивы import.

В данном случае вызывается функция quote.Hello() из пакета "rsc.io/quote", которая возвращает некоторое сообщение (точнее строку "Hello World"). А функция `quote.Go()` возвращает цитату про Go.

### Шаг 4: Создание папки vendor

Теперь, чтобы "завендорить" (скопировать) все зависимости из глобального кеша в локальную папку `vendor`, выполним команду:

```
go mod vendor
```

Эта команда создаст папку `vendor` в корне проекта. При создании папки `vendor` Go скопирует в нее исходный код всех пакетов, перечисленных в `go.mod`. Также будет создан файл `vendor/modules.txt` с метаданными о версиях "завендоренных" модулей. Например, он может выглядеть следующим образом:

### Шаг 5: Сборка проекта с использованием `vendor`

Начиная с Go 1.14, если в проекте присутствует папка `vendor`, то команды `go build`, `go run` и другие команды сборки автоматически используют ее по умолчанию. Никаких дополнительных флагов не требуется. Если вы хотите явно указать компилятору использовать `vendor`, вы можете использовать флаг `-mod=vendor`:

```
go run . -mod=vendor
go build -mod=vendor
```

Это может быть полезно для старых версий Go или для того, чтобы убедиться, что сборка не обращается к сети.

Например, запустим приложение на выполнение:

```
eugene@Eugene:/workspace/go/hello$ go run .
Hello, world.
Don't communicate by sharing memory, share memory by communicating.
eugene@Eugene:/workspace/go/hello$ 
```

### Возможные проблемы

Если мы создаем папку `vendor` до определения кода приложения (в примере выше это файл **main.go**), то мы можем получить предупреждение `"all" matched no packages`

```
eugene@Eugene:/workspace/go/helloapp$ go mod vendor
go: warning: "all" matched no packages
eugene@Eugene:/workspace/go/helloapp$ 
```

В этом предупреждении "all" — это специальный шаблон в командах Go, который означает "все пакеты, находящиеся в текущем модуле". А "matched no packages" означает, что Go не нашел ни одного такого пакета. То есть Go не нашел ни одного файла `.go` с исходным кодом, где бы использовался импорт загруженных библиотек.

В этом случае мы можем сначала определить исходный код программы, а затем повторно запустить команду **go mod vendor**

## Некоторые частые вопросы при работе с папкой vendor

#### Стоит ли коммитить папку vendor в Git?

Если вкратце, то да, если вы разрабатываете приложение (конечный бинарный файл), и нет, если вы разрабатываете библиотеку.

-   Для приложений: Коммит папки `vendor` в систему контроля версий (например, Git) гарантирует максимальную воспроизводимость. Любой разработчик, склонировав репозиторий, получит те же самые зависимости без необходимости их скачивать. Это также упрощает сборку в CI/CD системах. Основной минус — увеличение размера репозитория.
    
-   Для библиотек: Коммитить `vendor` не рекомендуется, так как это может привести к конфликтам зависимостей в проектах, которые будут использовать вашу библиотеку. Лучше позволить конечному приложению самому решать, какие версии зависимостей использовать.
    

#### Как обновить зависимости?

Процесс обновления зависимостей при использовании `vendor` выглядит следующим образом:

1.  Обновите нужную зависимость с помощью `go get`:
    
    ```
    go get -u rsc.io/quote
    ```
    
2.  Приведите файлы `go.mod` и `go.sum` в соответствие с новой версией библиотеки с помощью команды:
    
    ```
    go mod tidy
    ```
    
3.  Обновите содержимое папки `vendor` в соответствии с `go.mod`:
    
    ```
    go mod vendor
    ```
    
4.  Если вы коммитите `vendor`, закоммитьте изменения в `go.mod`, `go.sum` и папке `vendor`.
