## Параллельное программирование. Горутины

Последнее обновление: 22.06.2025

Параллелизм представляет чрезвычайно важную функциональность языка Go, которая позволяет выполнять несколько задач одновременно, позволяя разработчикам создавать высокоэффективные и отзывчивые приложения. В Golang основу модели параллелизма образуют такие конструкции как **горутины**.

**Горутины** (**goroutine**) представляют параллельные операции, которые могут выполняться независимо от функции, в которой они запущены. Главная особенность горутин состоит в том, что они могут выполняться параллельно. То есть на многоядерных архитектурах есть возможность выполнять отдельные горутины на отдельных ядрах процессора, тем самым горутины будут выполняться паралелльно, и программа завершится быстрее.

Каждая горутина, как правило, представляет вызов функции, и последовательно выполняет все свои инструкции. Все горутины запускаются в одном и том же адресном пространстве в любой программе Go. С горутинами размер стека увеличивается и уменьшается в соответствии с потребностями программы. Когда мы запускаем программу на Go, мы уже работаем как минимум с одной горутиной, которая представлена функцией main. Эта функция последовательно выполняет все инструкции, которые определены внутри нее. Как только компилятор достигает конца функции `main`, он завершает все созданные горутины.

Для определения горутин применяется оператор go, который ставится перед вызовом функции:

|1|`go` `вызов_функции`|
|---|---|

В цикле последовательно запускаются шесть горутин с помощью вызова `go sum(i)`. То есть фактически это обычный вызов функции с оператором **go**.

Однако вместо суммы первых n чисел на консоли при вызове программы мы можем увидеть только строку "The End":

```
The End
```

"Можем увидеть" означает, что поведение программы в данном случае недетерминировано. Например, вывод может быть и таким:

```
2 - 3
1 - 1
4 - 10
The End
5 - 15
```

Почему так происходит? После вызова `go sum(i)` функция main запускает горутину, которая начинает выполняться в своем контексте, независимо от функции main. То есть фактически main и sum выполняются параллельно. Однако главной горутиной является вызов функции main. И если завершается выполнение этой функции, то завершается и выполнение всей программы. Поскольку вызовы функции sum представляют горутины, то функция main не ждет их завершения и после их запуска продолжает свое выполнение. Какие-то горутины могут завершиться раньше функции main, и соответственно мы сможем увидеть на консоли их результат. Но может сложиться ситуация, что функция main выполнится раньше вызовов функции sum. Поэтому мы можем не увидеть на консоли суммуы чисел.

Например, горутина `go sum(2)` запускается до `go sum(5)`, однако может завершиться после.

### Пакет time

Встроенный пакет **time** в Go определяет функциональность, которая может помочь при работе с потоками. В частности, этот пакет определяет функцию time.Sleep(), которая приостанавливает выполнение горутины на определенное время (в миллисекундах). Например, в примерах выше для ожидания выполнения всех горутин применялся хак с функцией `fmt.Scanln()`, которая ожидает ввода пользователя. ### Горутины на нескольких ядрах

В языке Go мы можем зафиксировать количество ядер процессора для запуска горутин в программе. Существуют различные способы запуска горутин на нескольких ядрах системы. Go предоставляет переменную окружения **GOMAXPROCS**, которая определяет количество ядер, используемых в программе. Эта переменная берет на себя управление во время выполнения в программе Go. Значением по умолчанию этой переменной является количество ядер, доступных в системе. Система определяет при запуске в соответствии с запущенной операционной системой.
