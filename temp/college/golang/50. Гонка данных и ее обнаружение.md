## Гонка данных и ее обнаружение

Последнее обновление: 23.06.2025

Гонка данных (data race) представляет ситуацию, когда два или несколько потоков одновременно обращаются к одному и тому же участку памяти и выполняют по крайней мере одну операцию записи. Например:

Здесь у нас есть две горутины в виде функции update\_value, которые обращаются к одному и тому же значению переменной для обновления ее значения. И в зависимости от порядка выполнения горутин результат может различаться. Например, он может быть следующим:

```
Goroutine 2 starts
Goroutine 2 changes the value
23
Goroutine 1 starts
23
```

Здесь видно, что горутина 2 сначала считала и проверила значение переменной value, а затем изменила его. Потом горутина 1 считала и проверила значение value. Поскольку значение переменной уже не равно 22, то оно не изменяется. Это собственно тот порядок выполнения, который предпочтителен - одна горутина проверяет и изменяет значение, а другая горутина считывает уже измененное значение.

Однако это недетерминированное поведение. Вполне может быть так, что одна горутина проверит значение value, но не успеет изменить его. И тут же это значение считает вторая горутина. В итоге мы получим что-тио наподобие:

```
Goroutine 2 starts
Goroutine 1 starts
Goroutine 1 changes the value
23
Goroutine 2 changes the value
24
```

Таким образом, мы можем получить гонку данных, когда в программе одновременно выполняются два или несколько потоков, которые конкурируют за одни и те же ресурсы (в нашем случае переменная value).

### Проверка на гонку данных

Не всегда бывает легко отследить гонки данных в программе, особенно в больших приложениях. Но язык Go предоставляет для этого специальные инструменты, которые отслеживают все операции, связанные со статическим/динамическим доступом к памяти, а также то, как и когда в программе осуществляется доступ к памяти. Динамическое отслеживание выполняется для несинхронизированного доступа к общим переменным. Если в программе возникает состояние гонки из-за гонки данных, то Go выводит предупреждение. Чтобы включить детектор гонки в программе, во время выполнения программы применяется флаг `-race`:

```
go run –race имя_программы

go build –race имя_программы
```

Таким образом, детектор Go подсветил нам потенциальную проблему, которая может вылиться в гонку данных. В то же время рекомендуется использовать детектор гонок только в случае необходимости, так как он потребляет в десять раз больше ресурсов процессора и памяти. Также можно сказать, что при параллелизме обмен данными между горутинами должен быть должным образом синхронизирован, чтобы избежать таких ошибочных условий.
