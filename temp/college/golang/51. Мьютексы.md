## Мьютексы

Последнее обновление: 23.06.2025

Мьютексы позволяют разграничить доступ к некоторым общим ресурсам, гарантируя, что только одна горутина имеет к ним доступ в определенный момент времени. И пока одна горутина не освободит общий ресурс, другая горутина не может с ним работать.

На уровне кода мьютекс представляет тип sync.Mutex, который определен в пакете sync. Для блокирования доступа к общему разделяемому ресурсу у мьютекса вызывается метод Lock(), а для разблокировки доступа - метод Unlock().

Несмотря на то, что в каждой горутине значение counter сбрасывается к 0, а затем увеличивается до 5, мы видим, что несколько горутин после сброса переменной работают совсем с другим значением. То есть при запуске горутин каждая из них получает значение переменной counter и начинает с ней работать. Пока одна горутина еще не закончила работу с counter в цикле, с этой же переменной начинает работать и другая горутина. То есть к одному и тому же разделяемому общему ресурсу - переменной counter одновременно работают сразу несколько горутин. Это может привести к некорректным результатам, как в данном случае.

Теперь функция work принимает указатель на мьютекс. С помощью вызова `mutex.Lock()` мьютекс блокируется данной горутиной. Это значит, что к последующему коду имеет доступ только та горутина, которая первая заблокировала мьютекс. Остальные горутины ждут пока, мьютекс освободится.

Далее горутина сбрасывает значение переменной counter к нулю и затем в цикле последовательно увеличивает его. В конце, когда все действия с общим ресурсом уже выполнены, горутина освобождает мьютекс с помощью вызова `mutex.Unlock()`. Ожидающие горутины получают сигнал, что мьютекс освободился, и одна из горутин блокирует мьютекс и начинает выполнять действия с переменной counter. ### RWMutex

Горутина может только считывать данные, либо только изменять их. При выполнении операции записи совместное использование данных несколькими горутинами не допускается, тогда как при операции чтения несколько горутин могут считывать одни и те же данные без каких-либо проблем. Go предоставляет специальный мьютекс для чтения/записи - структуру **sync.RWMutex**, которая содержит различные поля для отслеживания доступа к памяти несколькими потоками. **sync.RWMutex** реализует несколько методов для блокировки/разблокировки:

-   **RLock()**: используется для получения блокировки на чтение. Несколько читателей могут получить эту блокировку в одной программе. Блокировка на чтение не привязан к определенному потоку.
    
-   **RUnlock()**: освобождает полученную одну блокировку на чтение.
    
-   **Lock()**: блокирует мьютекс для записи. Доступен только для одного потока за раз. Если другой поток получает блокировку для целей чтения/записи, Lock блокируется до тех пор, пока блокировка не станет доступной для получения.
    
-   **Unlock()**: снимает блокировку на запись. При выполнении Unlock без получения блокировки мы получим ошибку во время выполнения.

55|`package` `main`
`import` `(`
    `"fmt"`
    `"sync"`
`)`
`type` `Map_struct` `struct``{`
    `values` `map``[``int``]` `int`
    `sync.RWMutex`
`}`
`var` `wg sync.WaitGroup`
`func` `(map_data *Map_struct) update_map(keyval` `int``){`
    `map_data.Lock()`    
    `map_data.values[keyval] = keyval * 10` 
    `map_data.Unlock()`  
    `wg.Done()`      
`}`
`func` `(map_data *Map_struct) read_map(){`
    `map_data.RLock()`       
    `val := map_data.values`
    `map_data.RUnlock()`    
    `fmt.Println(val)`
    `wg.Done()`      
`}`
`func` `main(){`
    `my_map := Map_struct{values:make(``map``[``int``]``int``)}`
    `wg.Add(2*5)`      
    `for` `n:= 1; n <= 5; n++{`
        `go` `my_map.update_map(n)`
        `go` `my_map.read_map()`
    `}`
    `wg.Wait()` 
`}`|

Здесь мы создаем структуру `Map_struct`, которая имеет два поля - values и объект **RWMutex**. Встраивание объекта **RWMutex** позволяет получить доступ к нескольким методам для values. В функции main инициализируем структуру и в цикле вызываем две горутины. Горутина read\_map считывает значения из values, а горутина update\_map изменяет values. Горутина read\_map с помощью вызова `RLock()` устанавливает блокировку для выполнения операции чтения, а после считывания данных values снимает блокировку с помощью `RUnlock`. Горутина update\_map получает блокировку для операции записи, а после обновления values снимает блокировку с помощью метода `Unlock()`. Возможный консольный вывод программы (недетерминирован):

```
map[]
map[1:10]
map[1:10 2:20]
map[1:10 2:20 3:30]
map[1:10 2:20 3:30 4:40]
```
