## Изоморфная обработка ошибок

Последнее обновление: 24.06.2025

При выполнении программы могут возникать ошибки, соответственно обработка ошибок при разработке программы играет большую роль. В языке Go ошибки обрабатываются либо с помощью возвращаемых значений, либо через механиз panic. В этой статье рассмотрим первый способ.

Обработка ошибок с помощью возвращаемых значений на примере открытия несуществующего файла:

`func` `main(){`
    `file, err := os.Open(``"./content.txt"``)`
    `fmt.Println(``"file :"``, file)`
    `fmt.Println(``"error:"``, err)`
`}`|

Здесь для примера мы используем встроенную функцию `os.Open()` из модуля **os**. Эта функция принимает путь к открываемому файлу и возвращает два значения: открытый файл (file) и информацию об ошибке (err). Если файл был успешно открыт, то переменная file будет содержать некоторый дескриптор открытого файла для операций с ним, а переменная `err` будет равна `nil`, то есть ошибка отсутствует. Но если файла не существует, или при его открытии возникли ошибки, то переменная `file` будет равна `nil`, а переменная `err` будет содержать информацию об ошибке.

Так, в данном случае в функцию передается путь "./content.txt", и если в текущей папке нет файла "content.txt", то мы получим ошибку:

```
eugene@Eugene: go/hello$ go run main.go
file : <nil>
error: open ./content.txt: no such file or directory
eugene@Eugene: go/hello$
```

Если же мы передадим путь к существующему файлу (например, к файлу исполняемого скрипта Go):

|1
|---|
2
3|`file, err := os.Open(``"./main.go"``)`
`fmt.Println(``"file :"``, file)`
`fmt.Println(``"error:"``, err)`|

Тогда ошибки не будет

```
eugene@Eugene: go/hello$ go run main.go
file : &{0xc00007e1e0}
error: <nil>
eugene@Eugene: go/hello$
```

Подобный механизм уведомления об ошибках через возвращаемые значения можно практиковать и у себя в программах. Рассмотрим на примере функции факториала. Как известно факториал числа n представляет произведение всех чисел от 1 до n включительно. Соответственно, если n будет меньше 1, то должна быть ошибка. `import`  `"fmt"`
`func` `factorial(n` `int``) (``int``,` `interface``{}){`
    `if``(n < 0){`
        `return` `0,` `"Недопустимое число. Должно быть больше 0"`
    `}`

    `fmt.Println(``"Error:"``, err)`

Рассмотрим основные моменты. Прежде всего посмотрим на функцию факториала - она возвращает два значения:

|1|`func` `factorial(n` `int``) (``int``,` `interface``{}){`|
|---|---|

Первое значение типа int представляет результат, а второе возвращаемое значение теоретически может представлять любой объект, поэтому в качестве его типа указан анонимный интерфейс `interface{}`, который соответствует произвольному объекту. Стоит отметить, что для ошибок в Go есть собственный тип, который можно использовать вместо анонимного интерфейса, но пока посмотрим на общую картину.

В начале функции проверяем значение параметра. И если передано некорректное число - меньше 0, то в качестве результата возвращаем число 0 (недопустимое значение факториала) и сообщение об ошибке (интерфейсу `interface{}` соответствуют все объекты в том числе и строки):

|1
|---|
2
3|`if``(n < 0){`
    `return` `0,` `"Недопустимое число. Должно быть больше 0"`
`}`|

Если передано корректное число, то вычисляем факториал числа и в качестве ошибки возвращаем `nil`:

|1
|---|

    `result *= i`
`}`

Далее в функции main два раза вызываем эту функции передевая в нее валидные и невалидные значения. В первом случае передается валидное число 5:

|1
|---|

`fmt.Println(``"Factorial:"``, fact)`    
`fmt.Println(``"Error:"``, err)`|

Во втором случае передается некорректное число -5, поэтому переменная err будет хранить информацию об ошибке:

|1
|---|
2
3|`fact, err := factorial(-5)`
`fmt.Println(``"Factorial:"``, fact)`    
`fmt.Println(``"Error:"``, err)`|

Проверив переменную err на `nil`, мы можем узнать, есть ли ошибка или нет.

Это общий механизм, где, конечно, конкретная логика и возвращаемые типы могут отличаться в зависимости от наших потребностей, но в общем случае возвращаются два значения, где одно из них представляет информацию об ошибке, а второе - собственно результат функции.
