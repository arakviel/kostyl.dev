## 2. МЕТА ТА ЗАВДАННЯ ДИСЦИПЛІНИ

**Предметом вивчення** навчальної дисципліни є теоретичні засади, мережеві протоколи, архітектурні патерни, інженерні підходи та практичні засоби проєктування, розроблення, оптимізації, захисту, тестування й розгортання клієнт-серверних застосувань, розподілених мережевих сервісів та бекенд-систем мовою Go, здатних ефективно взаємодіяти з різноманітними типами клієнтських платформ (десктопні, мобільні, веб- та консольні застосунки).

### 2.1. Мета викладання навчальної дисципліни
**Метою викладання навчальної дисципліни «Розробка застосувань клієнт-серверної архітектури» є:** формування у здобувачів освіти системи фундаментальних теоретичних знань і стійких практичних навичок, необхідних для вирішення комплексних задач повного життєвого циклу проєктування, низькорівневої та високорівневої реалізації, оптимізації, верифікації, безпеки та розгортання надійної серверної частини клієнт-серверних застосувань та розподілених сервісів промислового рівня мовою **Go (Golang)** із використанням сучасного інструментарію та здатністю взаємодіяти з різноманітними типами клієнтських платформ (десктопні, мобільні, веб- та консольні застосунки).

### 2.2. Основні завдання вивчення дисципліни
**Основними завданнями вивчення дисципліни «Розробка застосувань клієнт-серверної архітектури» є вивчення основ, засвоєння та використання на практиці:**
- функціонування комп’ютерних мереж, сокетного API Берклі, стеку протоколів TCP і IP, низькорівневої датаграмної передачі по UDP та створення багатопотокових мережевих серверів;
- методів взаємодії гетерогенних клієнтів і серверів, керуючих заголовків та механізмів збереження стану (cookies, сесії, токени);
- мови системного програмування Go (Golang): системи статичної типізації, моделі пам'яті (Escape Analysis), покажчиків та парадигми конкурентності CSP (горутини, канали, примітиви синхронізації `sync`);
- архітектурних засад побудови модульних серверних систем за принципами Clean Architecture, конвеєрів Middleware та ручного впровадження залежностей (Dependency Injection);
- розробки стандартизованих RESTful API на базі стандартного пакета `net/http`, маршрутизатора Chi та вебфреймворку Gin (Model Binding, конвеєри валідації DTO через теги);
- взаємодії з реляційною СУБД PostgreSQL через прямий оптимізований SQL (`pgx`/`sqlx`), технології об'єктно-реляційного відображення (ORM `GORM`), використання патерну Repository, транзакцій та міграцій;
- впровадження механізмів автентифікації на основі JWT токенів (Access/Refresh flow), криптографічного захисту каналів зв'язку засобами TLS 1.3 та взаємної автентифікації (mTLS);
- організації комунікації у реальному часі через WebSocket (RFC 6455) та Server-Sent Events (SSE), а також черг асинхронної обробки фонових задач на базі RabbitMQ (AMQP) та протоколу MQTT;
- проєктування контрактів бінарної серіалізації Protocol Buffers та високоефективної міжсервісної взаємодії на основі gRPC;
- організації роздачі адаптивного потокового мультимедіа (HLS/DASH) та технології однорангового прямого зв'язку WebRTC;
- автоматизованого тестування HTTP-шару, документування програмних інтерфейсів за стандартом OpenAPI і Swagger, структурованого логування (`log/slog`), експорту метрик для Prometheus та контейнеризації додатків засобами Docker.

### 2.3. Результати навчання
У результаті вивчення навчальної дисципліни студент повинен:
- **РН1.** Застосовувати знання про багаторівневі клієнт-серверні моделі, парадигми мережевої взаємодії та життєвий цикл програмного забезпечення для створення масштабованих мережевих систем.
- **РН2.** Розробляти багатопотокові сокетні сервери та клієнтські модулі на базі протоколів TCP і UDP з кастомними протоколами прикладного рівня мовою Go.
- **РН3.** Реалізовувати архітектурно зрілі серверні сервіси та стандартизовані REST API з використанням стандартної бібліотеки Go, маршрутизатора Chi та фреймворку Gin.
- **РН4.** Забезпечувати інтероперабельність серверної частини з гетерогенними клієнтами (десктопними додатками на JavaFX / WPF / Avalonia, мобільними клієнтами на React Native та CLI-інтерфейсами).
- **РН5.** Проєктувати структури збереження даних у реляційній СУБД PostgreSQL, реалізовувати операції вибірки й маніпуляції даними за допомогою прямого SQL (`pgx`), транзакцій, міграцій та технологій ORM (`GORM`).
- **РН6.** Забезпечувати криптографічний захист каналів зв'язку (TLS 1.3, mTLS), впроваджувати надійні механізми автентифікації (JWT токени) та захищати мережеві інтерфейси від типових вразливостей.
- **РН7.** Інтегрувати механізми комунікації в реальному часі (WebSockets, SSE), потокового медіа (HLS), прямого зв'язку (WebRTC) та асинхронної обробки черг повідомлень (RabbitMQ, MQTT).
- **РН8.** Проєктувати та розробляти високопродуктивні інтерфейси міжсервісної взаємодії на базі протоколу gRPC та бінарних контрактів Protocol Buffers.
- **РН9.** Проводити модульне та інтеграційне тестування мережевого й HTTP-шару застосунків, виконувати профілювання швидкодії та витоків пам'яті (`pprof`).
- **РН10.** Оформляти інтерактивну технічну документацію до програмних інтерфейсів (API) за стандартами OpenAPI і Swagger.
- **РН11.** Розгортати скомпільовані клієнт-серверні застосунки у контейнеризованих середовищах Docker із застосуванням багатоетапного складання (Multi-stage Builds) та налаштуванням моніторингу (Prometheus, slog).
- **РН12.** Презентувати та захищати результати розробки клієнт-серверних комплексів, аргументовано обґрунтовуючи архітектурні, технологічні та безпекові рішення.

### 2.4. Компетентності

#### Інтегральна компетентність:
Здатність розв'язувати складні спеціалізовані завдання та практичні проблеми у галузі програмної інженерії при проєктуванні, розробці, інтеграції та супроводі масштабованих клієнт-серверних систем і мережевих сервісів.

#### Загальні компетентності (ЗК):
- **ЗК 1.** Здатність до абстрактного мислення, системного аналізу та синтезу мережевих архітектур.
- **ЗК 2.** Здатність застосовувати набуті знання у практичних ситуаціях системного та мережевого програмування.
- **ЗК 3.** Здатність до пошуку, оброблення та аналізу технічної інформації (специфікації RFC, стандарти консорціумів).
- **ЗК 4.** Здатність приймати обґрунтовані інженерні рішення при виборі мережевих протоколів та інструментів розробки.

#### Спеціальні (фахові) компетентності (СК):
- **СК 1.** Здатність проєктувати та реалізовувати надійні, високопродуктивні клієнт-серверні застосунки мовою Go з використанням моделі конкурентності CSP.
- **СК 2.** Здатність працювати з низькорівневим сокетним API (TCP, UDP), проєктувати кастомні бінарні та текстові протоколи обміну.
- **СК 3.** Здатність конфігурувати криптографічний захист каналів передачі даних (TLS/mTLS) та керувати сертифікатами X.509.
- **СК 4.** Здатність проєктувати стандартизовані RESTful та RPC API, забезпечуючи інтероперабельність із гетерогенними клієнтами (Desktop, Mobile, CLI).
- **СК 5.** Здатність реалізовувати шарувату архітектуру (Clean Architecture) із забезпеченням слабкої зв'язності компонентів.
- **СК 6.** Здатність ефективно працювати з реляційними базами даних як на рівні оптимізованого SQL (`pgx`), так і за допомогою ORM (`GORM`).
- **СК 7.** Здатність створювати системи реального часу (WebSockets, SSE), потокового медіа (HLS) та P2P комунікацій (WebRTC).
- **СК 8.** Здатність проєктувати асинхронні розподілені системи з використанням брокерів повідомлень (AMQP/RabbitMQ, MQTT).
- **СК 9.** Здатність здійснювати моніторинг, структуроване логування та контейнеризацію нативних Go-застосунків.

## 3. ПРОГРАМА НАВЧАЛЬНОЇ ДИСЦИПЛІНИ

### Розділ 1. Основи Go, низькорівневе мережеве програмування, транспортні протоколи та HTTP

**Тема 1. Архітектура клієнт-серверних систем та основи Go**  
Парадигма клієнт-серверної архітектури. Багаторівневі моделі (2-Tier, 3-Tier, N-Tier). Гетерогенність клієнтів: тонкі та товсті клієнти, десктопні платформи (JavaFX, WPF, Avalonia), мобільні клієнти (React Native), вебклієнти та термінальні утиліти (CLI). Мережева модель OSI та стек TCP/IP, адресація, порти та сокети. Філософія та екосистема Go, порівняння Go vs Java (пам'ять, GC, відсутність JVM, швидкість холодного старту). Інструментарій CLI (`go build`, `go run`, `go test`), робота з Go Modules (`go.mod`, `go.sum`).

**Тема 2. Система типів та модель пам'яті мови Go**  
Базові типи даних, константи, змінні. Модель пам'яті: стек та купа, механізм аналізу втечі (Escape Analysis). Покажчики та адресна арифметика. Структури (`struct`), теги полів (`struct tags`), композиція та вбудовування структур замість спадкування. Зрізи (`slice`) та карти (`map`). Функції як об'єкти першого класу, замикання, керування ресурсами через `defer`. Явна обробка помилок через значення `error` vs виключення у Java, функції `panic` та `recover`.

**Тема 3. Інтерфейси та модель конкурентності мови Go**  
Інтерфейси у Go: принципи качиної типізації (Duck Typing) та неявна реалізація, порожній інтерфейс `any`, приведення типів (Type Assertions, Type Switches). Парадигма конкурентності: модель CSP (Communicating Sequential Processes) vs модель спільної пам'яті. Горутини (Goroutines) та планувальник GMP. Канали (`chan`), оператор `select`. Примітиви синхронізації пакета `sync` (`Mutex`, `RWMutex`, `WaitGroup`, `Once`) та атомарні операції `sync/atomic`. Пакет `context`: життєвий цикл запитів, таймаути та скасування операцій.

**Тема 4. Сокетне програмування та протокол TCP у Go**  
Мережеві сокети Берклі (Berkeley Sockets API). Протокол TCP: характеристики, життєвий цикл TCP-сесії (3-Way Handshake, завершення з'єднання). Пакет `net`: функції `net.Listen`, `net.Dial`, інтерфейси `net.Conn`, `net.Listener`. Архітектура сервера з моделлю «горутина на кожне з'єднання». Потокове введення/виведення (`io.Reader`, `io.Writer`, пакет `bufio`). Проєктування кастомних протоколів прикладного рівня (розділювачі, довжина повідомлення, TLV). Плавне завершення роботи сервера (Graceful Shutdown) та обробка сигналів ОС.

**Тема 5. Протокол UDP та датаграмна передача даних**  
Характеристики протоколу UDP, робота без з'єднання та гарантій доставки. Пакет `net`: `net.ListenPacket`, `net.DialUDP`, інтерфейс `net.PacketConn`. Режими адресації: Unicast, Broadcast, Multicast (протокол IGMP, мультикаст-групи). Сфери застосування UDP: телеметрія, метрики, потокове відео, ігрові мережеві сервери. Проєктування надійних протоколів поверх UDP (концепція RUDP, порядкові номери, підтвердження ACK/NACK, ковзне вікно).

**Тема 6. Криптографічний захист каналів зв'язку та протокол TLS**  
Криптографічні основи: симетричне та асиметричне шифрування, геш-функції, цифрові підписи. Протокол TLS: специфікація TLS 1.3, фази рукостискання, захист від атак Man-in-the-Middle. Інфраструктура відкритих ключів (PKI), сертифікати стандарту X.509, центри сертифікації (CA). Пакет `crypto/tls`: створення TLS-сервера та клієнта. Взаємна автентифікація (mTLS) та верифікація сертифікатів клієнта, реалізація моделі Zero Trust.

**Тема 7. Прикладні мережеві протоколи DNS та SMTP**  
Протокол DNS: ієрархія простору імен, формати DNS-повідомлень, типи записів (A, AAAA, CNAME, MX, TXT, SRV). Резолвінг у Go за допомогою `net.Resolver`. Протокол SMTP (RFC 5321): архітектура електронної пошти, сеанс зв'язку, команди та коди відповідей. Формат повідомлень MIME (RFC 2045), багатокомпонентні листи (Multipart/alternative, Multipart/mixed), вкладення файлів та Base64. Захист пошти (STARTTLS, SPF, DKIM, DMARC) та надсилання листів через пакет `net/smtp`.

**Тема 8. Протокол HTTP та стандартний вебсервер Go**  
Еволюція протоколу HTTP (HTTP/1.1, HTTP/2, HTTP/3 QUIC). Анатомія HTTP-запитів та відповідей: стартовий рядок, методи (GET, POST, PUT, PATCH, DELETE), статус-коди, керуючі заголовки, ідемпотентність. Стандартний пакет `net/http`: інтерфейс `http.Handler`, роутер `http.ServeMux`. Створення кастомного `http.Server`, конфігурація таймаутів та TLS. Обробка параметрів, заголовків та потокового тіла запиту.

**Тема 9. Проєктування REST API та маршрутизація засобами Chi**  
Архітектурний стиль REST: обмеження, проєктування ресурсних URI, статус-коди, пагінація та фільтрація. Маршрутизатор `go-chi/chi`: дерево маршрутів Radix Tree, параметри шляху (`chi.URLParam`), суб-роутери та монтування маршрутів. Серіалізація та десеріалізація JSON (`encoding/json`). Формування стандартизованих відповідей (RFC 7807 Problem Details). Взаємодія з різними типами клієнтів (Desktop, Mobile, CLI).

### Розділ 2. Бекенд-архітектура, фреймворк Gin, бази даних та розподілені комунікації

**Тема 10. Шарувата архітектура та конвеєри обробки запитів**  
Патерн Middleware у Go: конвеєр обробки запитів, ланцюжки обробників. Реалізація Middleware для логування, Panic Recovery, CORS та обмеження частоти запитів (Rate Limiting). Принципи Clean Architecture: рівень домену (Domain), репозиторіїв (Repository), бізнес-логіки (UseCase) та HTTP-доставки (Delivery/Handler). Ручне впровадження залежностей (Dependency Injection) через фабричні конструктори. Модульне тестування HTTP-шару засобами `net/http/httptest`.

**Тема 11. Архітектура та маршрутизація фреймворку Gin**  
Архітектура вебфреймворку Gin: двигун `gin.Engine`, дерево маршрутів HttpRouter, пул контекстів. Центральна сутність `gin.Context`: читання параметрів маршруту, query-параметрів, форм та заголовків. Рендеринг відповідей (JSON, XML, ProtoBuf, PureJSON). Групування маршрутів за допомогою `RouterGroup`. Створення кастомних Middleware у Gin: керування потоком (`c.Next()`, `c.Abort()`) та контекстні змінні (`c.Set()`, `c.Get()`).

**Тема 12. Валідація даних, безпека та документування у Gin**  
Зв'язування даних (Model Binding: `ShouldBindJSON`, `ShouldBindQuery`, `ShouldBindUri`). Декларативна валідація за допомогою тегів структури `binding` (`go-playground/validator`). Обробка багатокомпонентних запитів (Multipart) та завантаження файлів. Автентифікація на базі токенів JWT (структура токена, генерація, перевірка через JWT Middleware, ротація Access/Refresh токенів). Автоматична генерація інтерактивної документації Swagger / OpenAPI 3.0 за допомогою `swaggo/swag` та `gin-swagger`.

**Тема 13. Взаємодія з реляційними СУБД та технології ORM**  
Підключення до реляційної СУБД PostgreSQL: інтерфейс `database/sql`, керування пулом з'єднань. Робота з чистим SQL через драйвер `pgx` та `sqlx`: параметризовані запити, транзакції, сканування в структури. Версіонування схеми БД за допомогою `golang-migrate`. ORM-підхід з бібліотекою `GORM`: моделі, теги колонок, зв'язки (1:1, 1:N, N:M), жадібне завантаження `Preload`, хуки життєвого циклу. Порівняння підходів Raw SQL vs ORM.

**Тема 14. Потокова передача даних та протокол WebSocket**  
Технології доставки даних у реальному часі. Протокол Server-Sent Events (SSE): HTTP-стрімінг, MIME-тип `text/event-stream`, інтерфейс `http.Flusher`, підключення десктопних і мобільних клієнтів. Протокол WebSocket (RFC 6455): встановлення з'єднання (HTTP Upgrade Handshake), фрейми, маскування, Ping/Pong перевірка живості. Реалізація WebSocket-сервера в Go на базі `gorilla/websocket`: горутини читання/запису, патерн Hub, керування кімнатами та броадкаст через канали.

**Тема 15. Міжсервісна взаємодія на основі протоколу gRPC**  
Концепція віддаленого виклику процедур (RPC) vs REST. Формат бінарної серіалізації Protocol Buffers (Protobuf v3): синтаксис файлів `.proto`, типи повідомлень, компілятор `protoc` та кодогенерація. Транспорт HTTP/2 у gRPC. Типи викликів: Unary, Server Streaming, Client Streaming, Bidirectional Streaming. Реалізація сервісів, gRPC-інтерцептори для автентифікації та логування, генерація клієнтських стабів для Go, C#, Java та мобільних платформ.

**Тема 16. Асинхронний обмін повідомленнями та протоколи черг**  
Парадигма асинхронного обміну повідомленнями: Work Queues, Publish/Subscribe, Topic-based Routing. Протокол AMQP 0-9-1 та брокер RabbitMQ: Producers, Exchanges, Queues, Bindings, підтвердження (ACK/NACK), черги Dead Letter, клієнтська бібліотека `amqp091-go`. Протокол MQTT: легковагий обмін повідомленнями для IoT та мобільних пристроїв, топіки, рівні якості обслуговування (QoS 0, 1, 2), Keep-Alive, Last Will and Testament, робота з Eclipse Paho Go-клієнтом.

**Тема 17. Протоколи потокового медіа та технологія WebRTC**  
Принципи передачі потокового медіаконтенту по HTTP. Протокол HTTP Live Streaming (HLS, RFC 8216): файли маніфестів (`.m3u8`), сегменти відео (`.ts`/fMP4), протокол DASH (`.mpd`), адаптивний бітрейт (ABR), організація роздачі відео у Go, взаємодія з FFmpeg. Концепція P2P комунікації. Архітектура WebRTC: сигналізація (Signaling), протокол SDP (Offer/Answer), проходження NAT (STUN, TURN, ICE). Бібліотека `Pion WebRTC` у Go: потокове відео/аудіо та канали передачі даних DataChannels.

**Тема 18. Моніторинг, безпека та контейнеризація застосунків**  
Три стовпи спостережуваності: структуроване логування (пакет `log/slog`), збір метрик для Prometheus (Counter, Gauge, Histogram), Health Checks. Безпека серверних інтерфейсів: хешування паролів (`bcrypt`), захисні HTTP-заголовки, запобігання XSS, CSRF та ін'єкціям. Контейнеризація Go-застосунків: патерн багатоетапного складання (Multi-stage Build Dockerfile), створення мінімальних безпечних образів на базі `scratch`/`alpine`, запуск від імені non-root користувача.

## 7. ФОРМИ ТА МЕТОДИ НАВЧАННЯ

### 7.1. Методи навчання
- **Інформаційно-ілюстративні лекції** з мультимедійними презентаціями та інтерактивними схемами архітектур.
- **Метод Live-Coding**: демонстрація викладачем розробки мережевих протоколів, налагодження сокетних з'єднань, роботи з Wireshark, Postman та gRPC GUI у реальному часі.
- **Проблемно-орієнтоване навчання (PBL)**: постановка реальних інженерних задач (наприклад, оптимізація високого навантаження, усунення стану гонитви (Race Condition), забезпечення стійкості до розривів мережі).
- **Практичні лабораторні роботи**: виконання індивідуальних завдань на комп'ютерах з написанням чистого коду та підключенням реальних клієнтів (Desktop, Mobile, CLI).
- **Code Review**: колективний та індивідуальний аналіз коду студентів із коментарями щодо ідіоматичності стилю Go (Effective Go).

### 7.2. Форми контролю
- **Поточний контроль:** оцінювання виконання та захисту кожної практичної роботи, перевірка репозиторіїв з кодом, опитування за ключовими темами.
- **Модульний контроль:** проведення 2 модульних контрольних робіт (МКР-1 на 5-му практичному занятті, МКР-2 на 10-му практичному занятті).
- **Підсумковий контроль:** екзамен або диференційований залік за результатами роботи в семестрі (рейтингова оцінка).

### Модуль 1. Основи Go, низькорівневе мережеве програмування, транспортні протоколи та HTTP

1. Парадигма клієнт-серверної архітектури: багаторівневі моделі (2-Tier, 3-Tier, N-Tier) та концепція гетерогенності клієнтів (Desktop, Mobile, Web, CLI).
2. Філософія та архітектурні особливості платформи Go у порівнянні з Java/C#: компіляція у нативний код, модель керування пам'яттю, робота з Go Modules.
3. *Практичне завдання:* Написати Go-код для ініціалізації структури конфігурації сервера та зчитування параметрів запуску через змінні оточення (`os.Getenv`) та прапорці CLI (`flag`).
4. Модель пам'яті Go: розподіл даних між стеком і купою, робота механізму Escape Analysis та покажчики.
5. Структури, композиція та явне опрацювання помилок у Go: порівняння типу `error` з ієрархією виключень (Exceptions) у класичному ООП.
6. *Практичне завдання:* Оголосити структуру з тегами полів та реалізувати користувацький тип помилки (імплементація інтерфейсу `error`), який містить HTTP-код та опис помилки.
7. Інтерфейси у мові Go: принципи качиної типізації (Duck Typing), неявна реалізація, порожній інтерфейс `any` та операції приведення типів (Type Assertions).
8. Модель конкурентності CSP: концепція горутин, планувальник GMP, канали та примітиви синхронізації пакета `sync`.
9. *Практичне завдання:* Реалізувати патерн Worker Pool на горутинах та буферизованих каналах для паралельної обробки списку задач із контролем таймауту через `context.WithTimeout`.
10. Берклі сокети та протокол TCP: характеристики, життєвий цикл TCP-сесії (триетапне рукостискання 3-Way Handshake) та завершення з'єднання.
11. Організація багатопотокового TCP-сервера у Go: пакет `net`, патерн «горутина на підключення», робота з `bufio` та реалізація Graceful Shutdown.
12. *Практичне завдання:* Написати фрагмент TCP-сервера на Go (`net.Listen`), який приймає текстові повідомлення від клієнта до розділювача `\n` та повертає ехо-відповідь.
13. Протокол UDP: характеристики, робота без встановлення з'єднання, режими адресації (Unicast, Broadcast, Multicast) та сфери практичного застосування.
14. Концепція Reliable UDP (RUDP): способи гарантування доставки, нумерація пакетів, механізми ACK/NACK та керування ковзним вікном поверх UDP.
15. *Практичне завдання:* Реалізувати UDP-сервер для збору телеметрії на базі `net.ListenPacket` із читанням датаграм у фіксований буфер байтів.
16. Криптографічний захист каналів зв'язку: основи асиметричного шифрування, інфраструктура відкритих ключів (PKI) та стандарти сертифікатів X.509.
17. Протокол TLS 1.3: фази рукостискання, захист від атак Man-in-the-Middle та механізм взаємної автентифікації клієнта і сервера (mTLS).
18. *Практичне завдання:* Написати конфігурацію `tls.Config` у Go для встановлення TLS-з'єднання з обов'язковою верифікацією клієнтського сертифіката через пул кореневих сертифікатів (Root CA).
19. Протокол DNS: ієрархічна структура простору імен, типи записів (A, AAAA, CNAME, MX, TXT, SRV) та програмний резолвінг у Go через `net.Resolver`.
20. Протокол SMTP: архітектура транспорту електронної пошти, формат повідомлень MIME, багатокомпонентні листи (Multipart) та механізми захисту (SPF, DKIM, DMARC).
21. *Практичне завдання:* Написати функцію на Go для формування та надсилання електронного листа з HTML-розміткою через протокол SMTP з автентифікацією (`smtp.PlainAuth`) та STARTTLS.
22. Еволюція протоколу HTTP (HTTP/1.1, HTTP/2, HTTP/3): мультиплексування, бінарні фрейми, заголовки HPACK/QPACK та транспорт QUIC.
23. Стандартний HTTP-сервер Go: інтерфейс `http.Handler`, механізм маршрутизації `http.ServeMux`, робота з `http.Request` та `http.ResponseWriter`.
24. *Практичне завдання:* Реалізувати базовий HTTP-обробник на чистому `net/http`, який зчитує JSON-тіло запиту, проводить його десеріалізацію та повертає статус-код 201 із JSON-відповіддю.
25. Архітектурні принципи та обмеження REST: структурування ресурсних URI, семантика методів та статус-коди відповідей.
26. Маршрутизатор `go-chi/chi`: деревоподібний роутинг Radix Tree, робота з URL-параметрами та суб-роутерами (`r.Route`).
27. *Практичне завдання:* Написати групу маршрутів Chi для сутності `/api/v1/articles` із підтримкою отримання сутності за URL-ідентифікатором (`chi.URLParam`) та повернення стандартизованої помилки 404 (RFC 7807).

43. Концепція віддаленого виклику процедур (RPC) у порівнянні з REST: двійкова серіалізація Protocol Buffers, версіонування схем та генерація коду.

45. *Практичне завдання:* Скласти файл `.proto` для сервісу замовлень з Unary-методом створення замовлення та Streaming-методом отримання потоку статусів замовлення.
46. Парадигма асинхронного обміну повідомленнями: шаблони черг завдань (Work Queues), Publish/Subscribe та маршрутизація повідомлень.
47. Протокол AMQP 0-9-1 та брокер RabbitMQ (Exchanges, Queues, Routing Keys, підтвердження ACK/NACK). Протокол MQTT для мобільних та IoT-клієнтів (топіки, рівні QoS).

49. Протоколи передачі потокового мультимедіа: HTTP Live Streaming (HLS) та DASH, структура маніфестів (`.m3u8`), сегментація відео (`.ts`) та адаптивний бітрейт (ABR).
50. Архітектура технології WebRTC: механізм сигналізації, протокол SDP (Offer/Answer), подолання NAT (STUN/TURN/ICE) та канали передачі даних (DataChannels).
51. *Практичне завдання:* Реалізувати HTTP-обробник на Go для роздачі сегментів HLS-відео з коректним MIME-типом `video/MP2T` та заголовками кешування.

* **Лекція 13. Взаємодія з реляційними СУБД та технології ORM (2 год)**  
  1. Підключення до PostgreSQL: `database/sql`, пул з'єднань. 2. Чистий SQL через `pgx` / `sqlx`: параметризовані запити, транзакції, сканування в структури. 3. Версіонування схеми БД через `golang-migrate`. 4. ORM `GORM`: моделі, теги, зв'язки (1:1, 1:N, N:M), `Preload`, хуки. 5. Raw SQL vs ORM.

* **Лекція 14. Потокова передача даних та протокол WebSocket (2 год)**  
  1. Технології реального часу. 2. Server-Sent Events (SSE): HTTP-стрімінг, `text/event-stream`, `http.Flusher`. 3. Протокол WebSocket (RFC 6455): HTTP Upgrade, фрейми, Ping/Pong. 4. WebSocket-сервер у Go (`gorilla/websocket`): горутини читання/запису, патерн Hub, кімнати, броадкаст через канали.

* **Лекція 15. Міжсервісна взаємодія на основі протоколу gRPC (2 год)**  
  1. Концепція RPC vs REST. 2. Двійкова серіалізація Protocol Buffers (Protobuf v3): синтаксис `.proto`, компілятор `protoc`. 3. Транспорт HTTP/2. 4. Патерни викликів: Unary, Server Streaming, Client Streaming, Bidirectional Streaming. 5. Інтерцептори та клієнтські стаби (Go, C#, Java, Mobile).

* **Лекція 16. Асинхронний обмін повідомленнями та протоколи черг (2 год)**  
  1. Парадигми асинхронного обміну: Work Queues, Pub/Sub, Topics. 2. Протокол AMQP 0-9-1 та RabbitMQ: Exchanges, Queues, Bindings, ACK/NACK, Dead Letter Queues, бібліотека `amqp091-go`. 3. Протокол MQTT: архітектура для IoT/Mobile, топіки, рівні QoS (0, 1, 2), Keep-Alive, LWT, бібліотека Eclipse Paho.

* **Лекція 17. Протоколи потокового медіа та технологія WebRTC (2 год)**  
  1. Стрімінг медіаконтенту по HTTP. 2. HTTP Live Streaming (HLS): маніфести `.m3u8`, сегменти `.ts`, DASH (`.mpd`), адаптивний бітрейт (ABR), сервер роздачі в Go, FFmpeg. 3. WebRTC: архітектура P2P, сигналізація, SDP Offer/Answer, NAT Traversal (STUN, TURN, ICE). 4. Бібліотека `Pion WebRTC`: медіа-треки та канали даних DataChannels.

* **Лекція 18. Моніторинг, безпека та контейнеризація застосунків (2 год)**  
  1. Три стовпи спостережуваності: структуроване логування (`log/slog`), збір метрик для Prometheus, Health Checks. 2. Безпека: хешування паролів (`bcrypt`), захисні HTTP-заголовки, XSS, CSRF, ін'єкції. 3. Контейнеризація: Multi-stage Build Dockerfile, мінімальні образи `scratch`/`alpine`, non-root користувач.
