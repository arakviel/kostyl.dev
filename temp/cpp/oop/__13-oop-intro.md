## 1. Вступ та передумови виникнення ООП

Напишемо програму для обчислення середнього значення балів студентів. Для зберігання потрібних даних створимо структуру `Student`, елементами якої будуть ПІБ студента і масив його оцінок.

### Процедурний (структурний) підхід

```cpp
// Обчислити середню оцінку студента
#include <iostream>
#include <iomanip>
#include <conio.h>
#include <windows.h>

using namespace std;

// максимальна довжина імені
const int maxNameLength = 20;

// кількість оцінок
const int markCount = 3;

// визначення структури даних
// ---------------------------------------------
// Студент
struct Student
{
    // ПІБ
    char name[maxNameLength];

    // оцінки
    int marks[markCount];
};
// ---------------------------------------------
// кінець визначення структури даних

// функції опрацювання структури даних
// ---------------------------------------------
// заповнення даних про студента
void initStudent(Student& student, const char* name, const int marks[])
{
    strcpy_s(student.name, maxNameLength, name);
    for (int i = 0; i < markCount; i++)
    {
        student.marks[i] = marks[i];
    }
}

// обчислення середньої оцінки
double averMark(Student student)
{
    double sum = 0;
    for (int i = 0; i < markCount; i++)
    {
        sum += student.marks[i];
    }
    return sum / markCount;
}

// виведення даних про студента
void printStudent(Student student)
{
    cout << student.name << endl;
    cout << "Оцінки: ";
    for (int i = 0; i < markCount; i++)
    {
        cout << setw(4) << student.marks[i];
    }
    cout << endl;
}
// ---------------------------------------------
// кінець списку функцій опрацювання структури даних

int main()
{
    SetConsoleCP(1251);
    SetConsoleOutputCP(1251);

    cout << "Успішність студента." << endl << endl;
    Student student;
    const char* studentName{ "Петренко А.О." };
    int studentMarks[]{ 4, 4, 3 };

    initStudent(student, studentName, studentMarks);
    printStudent(student);

    cout << "Середній бал: "
         << fixed << setprecision(2)
         << averMark(student) << endl;

    _getch();
    return 0;
}
```

### Проблематика процедурного коду

Задачу вирішено. Але довелося написати і використати декілька функцій з довгими іменами і довгими списками параметрів.

А тепер уявіть, що необхідно розширити можливості програми:
- Додати в структуру додаткові елементи;
- Значно розширити список функцій;
- Написання такої програми, а головне — її налагодження, пошук і виправлення помилок, буде важкою і невдячною працею.

Чи можна зробити простіше і зручніше?  
**Можна.** Існує підхід до розроблення програм — **об'єктно-орієнтоване програмування (ООП)**, за якого значно поліпшується і процес розроблення, і отриманий у результаті код.

---

### Об'єктно-орієнтована версія

```cpp
// Обчислити середній бал студента
#include <iostream>
#include <iomanip>
#include <conio.h>
#include <windows.h>

using namespace std;

// максимальна довжина імені
const int maxNameLength = 20;

// кількість оцінок
const int markCount = 3;

// визначення класу
// ---------------------------------------------
// Студент
class Student
{
    // ПІБ
    char name[maxNameLength];

    // оцінки
    int marks[markCount];

public:
    // конструктор: створення об'єкта Студент
    Student(const char* name, const int* marks)
    {
        strcpy_s(Student::name, maxNameLength, name);
        for (int i = 0; i < markCount; i++)
        {
            Student::marks[i] = marks[i];
        }
    }

    // обчислення середнього бала
    double getAverage()
    {
        double sum = 0;
        for (int i = 0; i < markCount; i++)
        {
            sum += marks[i];
        }
        return sum / markCount;
    }

    // вивід даних про студента
    void print()
    {
        cout << name << endl;
        cout << "Оцінки: ";
        for (int i = 0; i < markCount; i++)
        {
            cout << setw(4) << marks[i];
        }
        cout << endl;
    }

    // вивід середнього бала
    void printAverage()
    {
        cout << " Середній бал: "
             << fixed << setprecision(2)
             << getAverage() << endl;
    }
};
// ---------------------------------------------
// кінець визначення класу

int main()
{
    SetConsoleCP(1251);
    SetConsoleOutputCP(1251);

    cout << "Успішність студента." << endl << endl;

    // виклик конструктора класу:
    // створення об'єкта
    Student student{ "Петренко А.О.", new int[3]{ 4, 4, 3 } };

    // виклик методу класу:
    // робота з даними об'єкта
    student.print();
    student.printAverage();

    _getch();
    return 0;
}
```

### У чому різниця між структурним та об'єктно-орієнтованим варіантом?

Замість окремо існуючих елементів програми:
- структура `Student`;
- функції для її опрацювання (`initStudent`, `averMark`, `printStudent`);

У нас тепер є:
- **клас `Student`**, який описує (об'єднує в собі) і структуру даних, і функції їхнього опрацювання;
- на основі цього класу створюється **об'єкт `student`**, у якому містяться дані конкретного студента і який керує цими даними за допомогою методів класу (`student.print()`, `student.printAverage()`).

## 2. Історія та етапи розвитку C++

> *«Якщо ви вважаєте, що С++ важка мова, спробуйте вивчити англійську.»*  
> — **Б’ярн Страуструп**

- **1972 рік**: Деніс Рітчі в Bell Labs створив мову програмування **C**. Інші мови (Fortran, COBOL, Basic, Pascal) розроблялися вченими для вчених або викладачами для студентів. C була придумана програмістом для програмістів. Програми виходили короткими і дуже швидкими. C стала головною мовою системного програмування (ОС, компілятори, СУБД).
- **1980 рік**: Групою дослідників на чолі з Аланом Кейєм реалізовано мову **Smalltalk**, ідеї ООП почали підкорювати світ.
- **1983 рік**: Б’ярн Страуструп (Bell Labs) доповнив мову C класами та об'єктами, отримавши назву **C++**. Мова стала новим стандартом для складних системних продуктів (зокрема, Windows до Windows XP включно писалася на C++).

### Переваги та недоліки C++

| Переваги | Недоліки |
| :--- | :--- |
| **Висока сумісність з C** (використання десятиліть коду) | **Складність мови** (потрібно вчитися довго і ґрунтовно) |
| **Мультипарадигменність** (процедурне, ООП, шаблони, макроси) | **Легкість помилок**, які важко виявити через орієнтацію на максимальну продуктивність і низькорівневий доступ |
| **Кросплатформність** (Windows, Unix тощо) | |
| **Максимальна ефективність** (швидкість і контроль пам'яті) | |
| **Робота на рівні «заліза»** (пам'ять, адреси, порти) | |

### Еволюція та стандарти C++

1. **Нові Сі-подібні мови**: На основі C++ з'явилися мови зі спрощеним вивченням і більшою безпекою (C#, Java, PHP, Perl, Swift).
2. **Стандартизація C++**:
   - **1985**: перший опис мови;
   - **1989**: C++ 2.0;
   - **1998 (C++98)**: перший офіційний ISO стандарт;
   - **2003 (C++03)**: мінорні виправлення;
   - **2011 (C++11)**: революційне оновлення «сучасного C++»;
   - **2014 (C++14), 2017 (C++17)**: планові оновлення кожні 3 роки;
   - **2020 (C++20), 2023 (C++23)**: модулі, концепти, корутини тощо.

## 3. Криза процедурного підходу і виникнення ООП

> *«Складність програмних об'єктів більше залежить від їхніх розмірів, ніж, можливо, для будь-яких інших створюваних людиною конструкцій, оскільки ніякі дві їхні частини не схожі між собою.»*  
> — **Фредерік Брукс**

> *«Простота — чудова властивість, але потрібні великі зусилля, щоб її досягти, і гарна освіта для того, щоб гідно її оцінити.»*  
> — **Едсгер Дейкстра**

Коли комп'ютери стали потужними, обсяг програм зріс у тисячі разів і виникла **криза процедурного програмування**:
- У великій програмі зв'язки між сотнями функцій і глобальними змінними стають хаотичними.
- Дослідження IBM (1994): 68% програмних проектів відставали від графіка, перевищення бюджету досягало 65%.
- Дослідження The Standish Group (2014, >8000 проектів): лише 16.2% успішних проектів, 31.1% повних провалів, 52.7% частково успішних/невдалих.

### Як ООП вирішує цю проблему

ООП розбиває загальний хаотичний простір на **окремі «кімнати» (класи)**:
- Внутрішні об'єкти кімнати зв'язані переважно між собою.
- Кількість зв'язків для $N$ функцій у процедурній системі приблизно дорівнює $N \times N = 100 \times 100 = 10\,000$.
- Якщо розбити на 10 класів по 10 функцій: зв'язки всередині класів $10 \times (10 \times 10) + 10 \times 10$ (між класами) $= 1\,100$. Складність падає практично на порядок (у ~10 разів).

### Порівняння процедурного та об'єктно-орієнтованого мислення

| Підхід | Процедурний (C) | Об'єктно-орієнтований (C++) |
| :--- | :--- | :--- |
| **Головна основа** | Функції (алгоритми) | Дані (сутності, моделі реального світу) |
| **План проєктування** | Спочатку визначаються функції, а дані підганяються під них | Спочатку визначаються об'єкти та зв'язки між ними, а потім методи їхньої поведінки |

**Приклад проєктування «Філія комп'ютерної академії»:**
- **Процедурний підхід (від завдань):**
  1. Вести набір студентів;
  2. Складати розклад;
  3. Стежити за успішністю та оплатою;
  4. Розраховувати зарплату;
  *(і лише потім шукаємо, які дані для цього потрібні).*
- **Об'єктно-орієнтований підхід (від об'єктів):**
  1. Студенти;
  2. Викладачі;
  3. Заняття;
  4. Бюджет філії;
  *(методи логічно прив'язуються до об'єктів: `Заняття.СкластиРозклад()`, `Студенти.СтежитиЗаУспішністю()`).*

## 4. Три основні принципи ООП

### 1. Інкапсуляція (Encapsulation)

> *«Omnia mea mecum porto» (Все своє ношу з собою)* — **Цицерон**  
> *«Частіше ставте собі запитання: "Що мені приховати?" — і ви здивуєтесь, скільки проблем проєктування виростуть у вас на очах.»* — **Стівен Макконнелл**

**Інкапсуляція** (від лат. «в капсулі / в ящику») — це:
1. Тісне поєднання даних та методів роботи з ними всередині одного класу.
2. Приховування внутрішньої структури даних та деталей реалізації від зовнішнього світу (data hiding).

**Аналогія з телефоном:**
- Раніше (початок XX ст.): зв'язок через телефоністку на комутаторі або дисковий набір.
- Сучасний смартфон: ми просто натискаємо кнопку виклику або контакт; уся колосальна апаратна і мережева складність надійно схована всередині корпусу.

**Аналогія з біологічною клітиною:**  
Клітина взаємодіє з іншими клітинами через мембрану як єдине ціле, зберігаючи всередині складний і автономний внутрішній устрій.

**У програмуванні:**
- **Креслення** = **Клас** (опис того, як влаштований тип даних).
- **Виріб/деталь** = **Об'єкт (екземпляр класу)** (конкретний представник з власними значеннями).
- Об'єкти спілкуються між собою **виключно через публічний інтерфейс (методи)**, не втручаючись у внутрішню структуру даних один одного.

---

### 2. Наслідування (Inheritance)

> *«Якщо я бачив далі інших, це тому, що стояв на плечах гігантів.»* — **Ісаак Ньютон**  
> *«Більшість ідей засновані на минулих ідеях.»* — **Алан Кей**

**Наслідування** — це механізм, за якого один клас переймає структуру та поведінку іншого класу (базового):
- **Базовий клас** (батьківський, суперклас, надклас) — містить загальні властивості й методи.
- **Похідний клас** (дочірній, підклас, спадкоємець) — успадковує все від базового і додає власні унікальні риси.

**Приклади з життя:**
- Написання резюме на базі готового шаблону.
- Випуск нової лінійки автомобілів автоконцерном на базі існуючої успішної платформи.

**Приклад у програмуванні:**  
Моделювання транспортних засобів:
- Базовий клас: `Транспорт` (швидкість, маса, методи `рухатися()`, `заправитися()`).
- Похідні класи: `Автомобіль`, `Мотоцикл`, `Літак` (перевикористовують спільну логіку, реалізуючи лише власну специфіку).

---

### 3. Поліморфізм (Polymorphism)

**Поліморфізм** (від грецьк. «багатоформність / різноманітність») — властивість, яка дозволяє використовувати одне й те саме ім'я методу для вирішення схожих за змістом, але технічно різних задач.

**Сенс поліморфізму — економія понять.**
- У житті дія «відкрити ключем» однаково зрозуміла для дверей квартири, домофона, автомобіля чи криптографічного ключа до файлу.
- У програмуванні метод `Транспорт.Завантажити()`:
  - для об'єкта `Мотоцикл` здійснює посадку мотоцикліста;
  - для `Автомобіль` — посадку водія і пасажирів у салон;
  - для `Літак` — посадку екіпажу, пасажирів і розміщення вантажу в багажному відсіку.

## 5. Класи та методи в C++

### Порівняння структури `struct` та класу `class`

У C++ структури та класи мають дуже схожі можливості, але використовуються за різним призначенням:

#### Традиційна структура (лише дані)
```cpp
struct DateStruct
{
    int day;
    int month;
    int year;
};

// Зовнішня функція для виведення
void print(DateStruct &date)
{
    std::cout << date.day << "/" << date.month << "/" << date.year;
}

int main()
{
    DateStruct today { 12, 11, 2018 }; // uniform-ініціалізація
    today.day = 18;                    // доступ через оператор вибору (.)
    print(today);
    return 0;
}
```

#### Визначення класу `class`
```cpp
class DateClass
{
public:
    int m_day;
    int m_month;
    int m_year;

    // Метод (функція-член класу)
    void print()
    {
        std::cout << m_day << "/" << m_month << "/" << m_year;
    }
};
```

Використання об'єкта класу:
```cpp
#include <iostream>

class DateClass
{
public:
    int m_day;
    int m_month;
    int m_year;

    void print()
    {
        std::cout << m_day << "/" << m_month << "/" << m_year;
    }
};

int main()
{
    DateClass today { 12, 11, 2018 };

    today.m_day = 18; // доступ до змінної-члена
    today.print();    // виклик методу класу

    return 0;
}
```
**Результат:**
```text
18/11/2018
```

---

### Неявний об'єкт (`implicit object`) та префікс `m_`

- У зовнішню функцію `print(DateStruct &date)` ми змушені явно передавати екземпляр у параметрах.
- При виклику методу `today.print()` компілятор знає, що метод прив'язаний до об'єкта `today`.
  - `m_day` інтерпретується як `today.m_day`;
  - `m_month` — як `today.m_month`;
  - `m_year` — як `today.m_year`.
  Пов'язаний об'єкт неявно передається всередину методу.

#### Навіщо використовувати префікс `m_`?
1. Одразу видно, що змінна є полем (member) класу, а не локальною змінною або аргументом методу.
2. Відомо, де шукати її оголошення: у визначенні самого класу, а не всередині поточної функції.

> **Правило:** Імена класів прийнято писати з великої літери (`DateClass`, `Student`, `Employee`).

### Порядок визначення методів класу

На відміну від звичайних C-функцій, **порядок визначення методів усередині класу не має значення**: методи можуть вільно викликати один одного незалежно від того, хто вище оголошений у коді класу.

```cpp
#include <iostream>
#include <string>

class Employee
{
public:
    std::string m_name;
    int m_id;
    double m_wage;

    // Метод виводу інформації про працівника на екран
    void print()
    {
        std::cout << "Name: " << m_name << "\nId: " << m_id << "\nWage: $" << m_wage << '\n';
    }
};

int main()
{
    // Визначаємо двох працівників
    Employee john{ "John", 5, 30.00 };
    Employee max{ "Max", 6, 32.75 };

    // Виводимо інформацію про працівників на екран
    john.print();
    std::cout << std::endl;
    max.print();

    return 0;
}
```

**Результат роботи програми:**
```text
Name: John
Id: 5
Wage: $30

Name: Max
Id: 6
Wage: $32.75
```

### Різниця між `struct` та `class` у C++

- У мові C структури зберігали лише змінні.
- Б'ярн Страуструп у C++ надав структурам можливість також мати методи.
- **Єдина синтаксична різниця**: за замовчуванням у `struct` всі члени є `public`, а в `class` — `private`.

> **Золоте правило:**  
> - Використовуйте `struct` виключно для простих контейнерів даних (Plain Old Data), де немає логіки чи інваріантів.  
> - Використовуйте `class` для повноцінних об'єктів, які об'єднують дані та логіку (методи), контролюють доступ та інкапсулюють стан.

### Стандартна бібліотека C++ (STL) побудована на класах

Усі звичні типи — `std::string`, `std::vector`, `std::array` — це повноцінні класи зі своїми методами:

```cpp
#include <string>
#include <array>
#include <vector>
#include <iostream>

int main()
{
    std::string s { "Hello, world!" };  // екземпляр класу string
    std::array<int, 3> a { 7, 8, 9 };    // екземпляр класу array
    std::vector<double> v { 1.5, 2.6, 3.7 }; // екземпляр класу vector

    std::cout << "length: " << s.length() << '\n'; // виклик методу класу

    return 0;
}
```

### Завдання №1: Клас `Numbers`

Створіть клас `Numbers`, який містить два цілих числа:
- Дві змінні-члени (`m_first`, `m_second`).
- Метод `set()`, який дозволяє присвоювати значення цим змінним.
- Метод `print()`, який виводить значення змінних у форматі `Numbers(a, b)`.

#### Вимоги до `main()`:
```cpp
int main()
{
    Numbers n1;
    n1.set(3, 3); // ініціалізуємо об'єкт n1 значеннями 3 і 3

    Numbers n2{ 4, 4 }; // ініціалізуємо об'єкт n2 значеннями 4 і 4

}
```

```text
Numbers(3, 3)
Numbers(4, 4)
```

### Рішення завдання №1

```cpp
#include <iostream>

class Numbers
{
public:
    int m_first;
    int m_second;

    void set(int first, int second)
    {
        m_first = first;
        m_second = second;
    }

    void print()
    {
        std::cout << "Numbers(" << m_first << ", " << m_second << ")\n";
    }
};

int main()
{
    Numbers n1;
    n1.set(3, 3);

    Numbers n2{ 4, 4 };

    n1.print();
    n2.print();

    return 0;
}
```

#### Контрольне запитання:
> **Чому для `Numbers` повинен використовуватися саме клас, а не структура?**  
> *Відповідь:* Сутність `Numbers` містить не лише дані, але й пов'язані методи поведінки (`set()` та `print()`). Відповідно до правил проєктування C++, типи, що інкапсулюють стан разом із функціями для його опрацювання, мають бути оголошені через ключове слово `class`.
