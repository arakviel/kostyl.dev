## 1. Методичні принципи (наскрізні)

0. **Легкість тексту, глибина у відео.** Текст лекції — рівня старих слайдів (`temp/python/core/lesson_N/*_presentation.md`) з короткими «правдами», 300–450 рядків, стиль сухо і по суті (скіл `college-lectures`, розділ 1.2). Механізми (біти й байти, 30-бітні «цифри» `int`, IEEE 754, хеш-таблиці, UTF-8, дескриптор файлу) у тексті — 1–2 абзаци і одна картинка; повний розбір, числа й анімація — у відео [М]. Відео-механізми з планів уроків не скорочуємо.

1. **Нотаційна машина (notional machine).** З першого уроку студент має модель «що робить інтерпретатор»: імена → посилання → об'єкти в пам'яті, кадри стеку викликів. Кожна нова тема додає шар до тієї самої картинки, а не вводить нову метафору.
2. **Спрощувати можна, брехати — ні.** Якщо щось спрощуємо, позначаємо це явно (`::note` «Спрощення: …, детальніше в уроці N»). Метафори з «коробкою» не використовуємо — у Python це хибна модель.
3. **PRIMM:** Predict → Run → Investigate → Modify → Make. Перед кожним лістингом студент спершу передбачає вивід.
4. **Розібраний приклад → приклад із пропусками → самостійна задача** (worked → faded → independent).
5. **Полювання на хибні уявлення.** У кожному уроці 1–3 типові хибні уявлення, які навмисно ламаємо: передбачення, «несподіваний» результат, пояснення.
6. **Активне пригадування:** урок починається з 3–5 питань «пригадай» з попередніх уроків, а приблизно кожні 4 уроки повторюємо пройдене по спіралі.
7. **Трасування коду** (таблиці стану, `::code-trace`) вважаємо окремою навичкою, а не бонусом.
8. **Помилки — це навчальний матеріал.** Traceback читаємо з першого уроку. У Python 3.15 вивід кольоровий, а підказки стали кращими.

### Візуальна мова (однакова в усіх відео та `::code-trace`)

> Картинки в статті — окремо, matplotlib (див. «Слоти» вище), у світлому стилі скіла `college-lectures`. Візуальна мова нижче стосується лише відео й `::code-trace`.
- **Простір імен** (зліва): таблиця з іменами (`globals` / кадр функції).
- **Купа об'єктів** (справа): кожен об'єкт — плашка з заголовком `type | id | refcount` і значенням.
- **Стрілка** = посилання. Присвоєння = перемальована стрілка, а не «покласти значення».
- **Стек кадрів** (з уроку функцій): кадри складаються вертикально і зникають при `return`.
- **Редактор / термінал** для [К]: одна тема оформлення, один шрифт (JetBrains Mono).
- Кольори: імена — cyan, об'єкти — emerald, незмінні (immutable) — сірий замок, помилки/винятки — amber/red.

## 5. Інтерактивний трасувальник коду `::code-trace` (новий компонент)

Покрокове виконання коду у стилі Python Tutor, у тій самій візуальній мові, що й відео. Відео *пояснює*, а трасувальник дає студенту *самому прокрутити* виконання на іншому прикладі.

- **Як працює:** кадри виконання генеруються **заздалегідь** скриптом (`tools/code-trace/trace.py` на `sys.settrace`: рядок, кадри, імена → id, купа об'єктів з типом/значенням/refcount, stdout) у JSON. Vue-компонент лише програє цей JSON, тому Python у браузері не потрібен і результат завжди правдивий, бо його отримано з CPython 3.15. Той самий JSON може бути джерелом даних для сцен [М].
- **UI:** код із підсвіченим поточним рядком · кнопки ⏮ ◀ ▶ ⏭ і повзунок · зліва стек кадрів з іменами, справа купа об'єктів, стрілки-посилання · панель stdout · незмінні об'єкти з «замком».
- **Режим «передбач»:** на позначених кроках компонент зупиняється і питає «куди тепер вкаже стрілка?» або «що виведе?».
- **Синтаксис у статті (чернетка):** `::code-trace{src="/traces/python-core/03-aliasing.json"}`. Код береться з того самого JSON.
- **Наявні компоненти:** `MemoryView` (hex-дамп) і `DebuggerView` (таблиця locals) статичні. `MemoryView` лишається для уроків 00, 02 і 08 (байти, UTF-8), а новий компонент — окремий.
- **Де:** усі відео з позначкою `→ trace` (уроки 03, 06, 09, 11, 12, 13, 14).
