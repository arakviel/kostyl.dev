# Урок 1 (основи Python) — практичний ноутбук для Colab

## Що тут є

Папка `lesson_1_practice/` містить усе, що пов'язано з практичним ноутбуком:

| Файл | Що це |
| :--- | :--- |
| `01_python_basics_practice.ipynb` | **Ноутбук для студентів.** 22 практичні завдання + бліц + підсумкова самоперевірка по 8 блоках. |
| `build_practice_notebook.py` | Генератор ноутбука (правте код → перегенеруйте). |
| `validate_practice_notebook.py` | Автотест: проганяє «розв'язану» версію (має дати 8/8 ✅) і «порожню» (має дати 0/8 ❌). |
| `README_lesson1_practice.md` | Цей файл: інструкції для викладача та студентів. |

> Презентація уроку (`lesson_1_presentation.md`, `.html` та тека `lesson_1_presentation/` з ілюстраціями) лежить на один рівень вище — вона не змінювалася.

## Як роздати 16 копій (2 хвилини)

1. Завантажте `01_python_basics_practice.ipynb` у **Google Drive** (перетягніть файл у вікно Drive).
2. Задайте доступ: **права «перегляд»** для групи/курсу — і всі зможуть відкрити файл.
3. Дайте студентам посилання на файл із теки Drive і одну інструкцію:

> Відкрийте файл у Colab → **File → Save a copy in Drive** → перейменуйте копію на `ПІБ_lesson1.ipynb` → працюйте у своїй копії.

Кожен студент отримує **свою ідентичну копію** — ваш оригінал не постраждає.

> Якщо Colab відкриє файл лише «в режимі читання» — це нормально: студент все одно робить `Save a copy in Drive`, і далі працює у своєму файлі.

## Як зібрати й перевірити 16 робіт

Оберайте один із двох способів (або обидва):

**Спосіб А — спільна тека Drive (зручно для перегляду)**
1. Створіть теку `Python_core_lesson1` у своєму Drive і дайте студентам права на редагування.
2. Попросіть: перемістити копію ноутбука в цю теку й натиснути **Ctrl+S / Cmd+S**.
3. Ви бачите 16 файлів; відкриваєте будь-який — і одразу видно код студента та збережені результати всіх клітинок, включно з підсумковою таблицею.

**Спосіб Б — «Share» (резервний, нічого переміщати не треба)**
Студент натискає **Share → Add collaborator → ваш Gmail**. Вам приходить лист із посиланням на його ноутбук — можна відкрити й перевірити.

### Як оцінювати
Відкрийте файл студента → прокрутіть до **«Блок 9. Фінальна перевірка»** → там таблиця:

## Як перегенерувати / перевірити ноутбук локально

```bash
python3 lesson_1_practice/build_practice_notebook.py     # перегенерувати .ipynb з коду
python3 lesson_1_practice/validate_practice_notebook.py  # автотест: має надрукувати 8/8 ✅
```

`validate_practice_notebook.py` підставляє правильні відповіді в усі TODO-клітинки та проганяє ноутбук через `nbclient` — тобто перевіряє, що **кожна перевірка проходить з правильним розв'язком**, а порожня версія коректно повідомляє «❌ Спершу виконайте клітинку із завданням».

## 🚫 Як повністю вимкнути ШІ-підказки в VS Code (обов'язково)

Практикум виконується самостійно. Нижче — інструкція, яку можна розіслати студентам дослівно.

### Спосіб 1 (найпростіший, VS Code 1.104 і новіші)

Одне налаштування вимикає і ховає **всі** вбудовані ШІ-функції VS Code (чат, інлайн-підказки, next edit suggestions) і водночас **вимикає розширення Copilot**, якщо вони встановлені:

1. `Ctrl + Shift + P` (на macOS — `Cmd + Shift + P`) → введіть `Preferences: Open User Settings (JSON)` → Enter.
2. Додайте в `settings.json`:

```json
{
    "chat.disableAIFeatures": true
}
```

> Або без JSON: `Ctrl + ,` → у пошуку напишіть `disable ai features` → поставте галочку **Disable AI features in VS Code**.

### Спосіб 2 (якщо хочете вимкнути все окремо й дрібніше)

```json
{
    "chat.disableAIFeatures": true,
    "editor.inlineSuggest.enabled": false,
    "github.copilot.enable": { "*": false },
    "github.copilot.chat.enable": false,
    "github.copilot.nextEditSuggestions.enabled": false,
    "chat.commandCenter.enabled": false,
    "inlineChat.enableV2": false,
    "workbench.settings.showAISearchToggle": false
}
```

| Налаштування | Що вимикає |
| :--- | :--- |
| `chat.disableAIFeatures` | усі вбудовані ШІ-функції VS Code + розширення Copilot |
| `editor.inlineSuggest.enabled` | «сірі» підказки під курсором (autocomplete Copilot) |
| `github.copilot.enable: {"*": false}` | Copilot для всіх мов (Python, Markdown,…) |
| `github.copilot.chat.enable` | чат-панель Copilot |
| `github.copilot.nextEditSuggestions.enabled` | next edit suggestions (NES) |
| `chat.commandCenter.enabled` | кнопка чату у шапці вікна |
| `inlineChat.enableV2` | вбудований inline chat (Ctrl+I) |
| `workbench.settings.showAISearchToggle` | пошук по налаштуваннях через ШІ |

### Спосіб 3 (найнадійніший — прибрати розширення)

`Ctrl + Shift + X` ( або `Cmd + Shift + X`) → знайти й **Uninstall**:

* `GitHub Copilot`
* `GitHub Copilot Chat`
* інші ШІ-розширення, якщо є: `Codeium` / `Windsurf`, `Continue`, `Tabnine`, `Cline`, `Roo Code`, `Amazon Q Developer`

Додатково: `Ctrl + Shift + P` → `GitHub: Sign out` — щоб VS Code не підключався до Copilot через ваш GitHub-акаунт.

### Як перевірити, що все вимкнено

* у правому нижньому куті **немає іконки Copilot**;
* у редакторі **не з'являються** сірі підказки під час набору;
* у шапці вікна **немає** кнопки чату / піктограми Copilot;
* `Ctrl + ,` → пошук `disable ai features` → галочка стоїть.

### Уточнення

* **IntelliSense** (автодоповнення назв змінних, функцій, аргументів) — це **не ШІ**, а звичайна підказка редактора. Зазвичай її не вимикають. Якщо хочеться прибрати й її:
  ```json
  "editor.quickSuggestions": { "other": "off", "comments": "off", "strings": "off" },
  "editor.suggestOnTriggerCharacters": false,
  "editor.parameterHints.enabled": false,
  "editor.hover.enabled": false
  ```
* **У Google Colab** ШІ-функції обмежені (напр. «Ask AI» / Gemini у контекстному меню клітинки). Якщо ними користуєтесь — не використовуйте їх для розв'язання завдань цього практикуму.

## Як влаштована перевірка

Клітинка-перевірка йде одразу під завданням і перевіряє саме його:

* ✅ `ТЗ-4 виконано правильно!` — все добре;
* ❌ `AssertionError` з поясненням — що саме не так (наприклад, «Очікувалось 22, а зараз None»).

**Готове рішення** кожного завдання — у розгорнутому блоці 💡 (`<details>`) у кінці кожного блоку: студент не бачить відповіді, не відкривши блок.

Наприкінці ноутбука є клітинка **«🔍 ФІНАЛЬНА ПЕРЕВІРКА»** — вона виконує перевірку всіх блоків одразу і друкує підсумкову таблицю:

```
========================================================================
ПІДСУМКОВА ПЕРЕВІРКА — Урок 1: Основи Python
========================================================================
✅  Блок 1 — print(), sep та end
❌  Блок 4 — арифметичні оператори
       → ТЗ-11: неправильні обчислення
...
========================================================================
Пройдено блоків: 7 з 8
========================================================================
```

Це і є «звіт» студента: одна клітинка, яку можна запускати будь-коли.

| 7 | Підсумкові задачі | ТЗ-20 … ТЗ-22 |

## Технічні рішення, які варто знати

* **`%%capture`** — магічний рядок IPython, який «записує» вивід `print()` у змінну (`cap1.stdout`). Без нього `assert` не бачить надруковане, а перевіряти треба саме `sep`/`end`. Побічний ефект: `%%capture` **ховає** вивід із клітинки — тому в клітинках перевірки вивід друкується назад у рамці («👀 Ось що ви надрукували:»), а в описі блоку 1 є підказка, як тимчасово закоментувати `%%capture`, щоб бачити результат одразу.
* **`set_inputs(...)` / `reset_inputs()`** — хелпери, які підміняють `input()` на заготовлені відповіді. Студент пише звичайний `input(...)` — перевірка працює автоматично, без ручного вводу.
* **`_need(...)`** — перевіряє, що змінна студента існує, і видає зрозумілу підказку замість `NameError`.
* **Готове рішення** кожного завдання — у розгорнутому блоці 💡 (`<details>`), тож студент не бачить відповіді, не відкривши блок.
* **Клітинки-перевірки** йдуть одразу під завданням (видимі), у фінальній таблиці — підсумок по 8 блоках.
* **У TODO-коментарях немає відповідей** — там лише опис кроку («запитайте сторону, перетворіть на float, піднесіть до степеня 2»), а значення/вирази лежать у таблиці завдання над клітинкою. Студент не може «розкоментувати рядок і здати порожню роботу».
* **Числові відповіді прибрано й з завдань** (напр. у ТЗ-11 прибрано колонку «очікуваний результат», у ТЗ-18/20/21 — підсумкові числа): студент має обчислити сам, а не «звірити».

## Що НЕ виходить за межі уроку (за вашим проханням тримати scope)

У студентських завданнях немає: `if`, `for`, списків, кортежів, f-рядків, методів рядків, власних функцій (`def`), роботи з файлами. Тільки те, що є в `lesson_1_presentation.md`.
