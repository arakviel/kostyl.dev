### Рівень 1: "Лаборант" (Lab Assistant)

_Ціль: Навчитися створювати та імпортувати прості модулі, розуміти `__name__` та базову роботу з `venv`._

**Завдання 1.1: Математичний переселенець**

- **Дано:** Один файл `main.py`, в якому написані функції `add(a, b)`, `subtract(a, b)` і код, що їх викликає.
- **Завдання:**

1. Створити новий файл `calc_utils.py`.
2. Перенести функції `add` та `subtract` туди.
3. У `main.py` імпортувати ці функції двома способами:

- Через `import calc_utils` (виклик `calc_utils.add`).
- Через `from calc_utils import subtract` (прямий виклик `subtract`).

4. Запустити `main.py` і переконатися, що все працює.

- **Що тренуємо:** Створення модулів, синтаксис `import`, `from ... import`.

**Завдання 1.2: Охоронець входу (`__main__`)**

- **Дано:** Файл `greeter.py` з функцією `say_hello()` та викликом `say_hello()` в самому кінці файлу (на глобальному рівні).
- **Завдання:**

1. Створити файл `app.py` і написати там `import greeter`.
2. Запустити `app.py`. Ти побачиш, що привітання виводиться, хоча ми функцію не викликали (вона спрацювала при імпорті). Це погано.
3. Виправити `greeter.py`: огорнути виклик функції в умову `if __name__ == "__main__":`.
4. Знову запустити `app.py` — тиша (правильно). Запустити `greeter.py` напряму — привітання є (правильно).

- **Що тренуємо:** Конструкція `if __name__ == "__main__":`, запобігання побічним ефектам при імпорті.

**Завдання 1.3: Ізолятор (Перший venv)**

- **Дано:** Термінал/Консоль.
- **Завдання:**

1. Створити нову папку `my_first_env`.
2. Створити в ній віртуальне середовище: `python -m venv .venv`.
3. Активувати середовище (Windows: `.venv\Scripts\activate`, Mac/Linux: `source .venv/bin/activate`).
4. Переконатися, що воно активне (з'явився напис `(.venv)`).
5. Встановити бібліотеку `requests`: `pip install requests`.
6. Перевірити список встановлених пакетів: `pip list`.

- **Що тренуємо:** Модуль `venv`, команди активації, `pip install`, `pip list`.

### Рівень 2: "Логіст пакетів" (Package Logistician)

_Ціль: Робота з пакетами (`__init__.py`), керування залежностями та конфліктами імен._

**Завдання 2.1: Сортувальний центр (Пакети)**

- **Дано:** Проект з купою файлів в корені: `user_login.py`, `user_register.py`, `db_connect.py`, `db_migrate.py`, `main.py`.
- **Завдання:**

1. Створити структуру пакетів: папку `auth` і папку `database`.
2. Перемістити файли `user_*.py` в папку `auth`, а `db_*.py` в папку `database`.
3. Створити порожні файли `__init__.py` в обох папках.
4. У `main.py` виправити імпорти, щоб вони виглядали як `from auth.user_login import login`.

- **Що тренуємо:** Структура директорій, перетворення папки в пакет, `Dot-notation` в імпортах.

**Завдання 2.2: Клонування середовища (`requirements.txt`)**

- **Дано:** Віртуальне середовище з попередніх завдань, де встановлено `requests`.
- **Завдання:**

1. Зберегти список залежностей у файл: `pip freeze > requirements.txt`.
2. Деактивувати та **видалити** папку `.venv`. (Імітуємо, що ми скачали проект на новий комп'ютер).
3. Створити нове віртуальне середовище `.venv_new` та активувати його.
4. Встановити всі залежності однією командою з файлу: `pip install -r requirements.txt`.
5. Перевірити `pip list` — `requests` має бути на місці.

- **Що тренуємо:** `pip freeze`, файл `requirements.txt`, відновлення середовища.

**Завдання 2.3: Прихований експорт (`__init__` facade)**

- **Дано:** Пакет `geometry`, в якому є файли `circle.py` (з функцією `area`) і `square.py` (з функцією `area`).
- **Завдання:**

1. Зараз у `main.py` доводиться писати довго: `from geometry.circle import area as circle_area`.
2. Налаштувати `geometry/__init__.py` так, щоб він імпортував функції з під-модулів.
3. Зробити так, щоб у `main.py` можна було написати: `from geometry import circle_area, square_area` (попередньо давши їм унікальні імена або аліаси всередині `__init__.py`).

- **Що тренуємо:** Просунута робота з `__init__.py`, створення зручного API пакету.

### Рівень 3: "Архітектор систем" (System Architect)

_Ціль: Створення складної структури, вирішення проблем циклічних імпортів, використання сторонніх бібліотек у власних модулях._

**Завдання 3.1: Пастка циклу (Circular Import)**

- **Дано:** Два файли.
- `game.py`: імпортує `player` і створює гру.
- `player.py`: імпортує `game`, щоб перевірити статус гри.
- Це викликає помилку `ImportError` при запуску.

- **Завдання:**

1. Відтворити цю помилку.
2. Вирішити проблему архітектурно: створити третій модуль `config.py` або `state.py`.
3. Перенести спільні дані (статус гри) туди.
4. Імпортувати `config` і в `game.py`, і в `player.py`.

- **Що тренуємо:** Розуміння, як Python виконує імпорти, вирішення архітектурних помилок, рефакторинг.

**Завдання 3.2: ASCII-Art Генератор (Wrapper)**

- **Дано:** Порожній проект.
- **Завдання:**

1. Створити віртуальне середовище, встановити бібліотеку `art` (`pip install art`).
2. Створити пакет `creative_tools`.
3. Всередині створити модуль `banner.py`. Він має імпортувати бібліотеку `art`, але надавати власну спрощену функцію `make_banner(text)`, яка повертає гарний ASCII-текст.
4. У `main.py` імпортувати ТІЛЬКИ свою функцію `make_banner` і використати її.
   _Мета:_ Головний файл не повинен знати про бібліотеку `art`, він спілкується тільки з твоїм модулем.

- **Що тренуємо:** Інкапсуляція сторонніх залежностей, патерн "Фасад" (Facade) через модулі.

**Завдання 3.3: Професійний "Setup"**

- **Дано:** Потреба створити шаблон для майбутнього веб-сервісу.
- **Завдання:**

1. Створити структуру папок:

```text
project_root/
├── .venv/            (ігнорується git)
├── src/              (вихідний код)
│   ├── app/          (головний пакет)
│   │   ├── __init__.py
│   │   └── main.py
│   └── utils/
├── requirements.txt
└── run.py            (скрипт запуску)

```

2. `run.py` повинен додавати папку `src` у `sys.path` (якщо потрібно) і запускати функцію з `src.app.main`.
3. Продемонструвати запуск проекту через команду `python run.py`, знаходячись у корені.

- **Що тренуємо:** Маніпуляції з `sys.path`, професійна структура проекту, розділення коду та точок входу.

---

Зверни увагу в завданні 3.3 на `sys.path`. Часто новачки не розуміють, чому Python не бачить їхні модулі, якщо вони лежать у вкладених папках. Це завдання навчить тебе контролювати "зону видимості" інтерпретатора. Успіхів!
